# Visible content

## Title bar
«Цикл агента: plan → act → check → iterate»

## Body
[Inline-define, 16pt italic]
*Агент — архитектура, где модель не делает один проход, а работает в цикле, сама динамически определяя последовательность шагов.*

[Замкнутый цикл 4 шага, Ocean rounded boxes, стрелки по часовой + возврат]

**Plan** → формулирует следующий шаг
*режим отказа: близорукий / зацикленный план (не видит накопленной стоимости)*

→ **Act** → вызывает инструмент (function calling)
*режим отказа: инструмент падает / тормозит, а ветки на это нет*

→ **Check** → достигнута ли цель, корректен ли результат  *(gold-акцент)*
*валидация против ВНЕШНЕГО критерия — не самооценка модели (callback s07)*

→ **Iterate** → цикл повторяется
*режим отказа: нет внешнего лимита на итерации / стоимость / время → петля*

⟲ возврат к Plan — **повторяется**

[Sub-caption, низ, 12pt italic]
*Паттерны цикла (ReAct, Reflexion, Plan-and-Execute) — в главе. Проектировать агента = проектировать защиту на каждом из 4 шагов.*

## Speaker notes

Теперь есть всё для следующей ступени. Один вызов умеет рассуждать; RAG достаёт знание; function calling дотягивается до внешних систем; MCP стандартизует подключение. Агент — архитектура, в которой модель не делает один проход, а работает в цикле: планирует шаг, действует — вызывает инструмент, наблюдает результат, проверяет, достигнута ли цель, и итерирует, сама динамически определяя последовательность. Каноническая формулировка — планируй, действуй, проверяй, повторяй; это паттерн ReAct, чередование рассуждения и действий, а Reflexion добавляет явную самооценку после неудачи. Это «другой AI» по сравнению с одним вызовом: там модель отвечала один раз, здесь — управляет процессом из многих шагов.

Разберём цикл по шагам, потому что каждый шаг — место конкретного режима отказа. Plan: модель формулирует шаг исходя из цели и истории; режим отказа — близорукий или зацикленный план, модель не видит накопленную стоимость и время. Act: вызывается инструмент; режим отказа — инструмент падает или возвращает ошибку, и если плана на это нет, начинается петля. Check: оценивается результат; режим отказа — проверки нет или она сводится к самооценке модели. Iterate: цикл повторяется; режим отказа — нет внешнего лимита на итерации, стоимость или время. «Агент» — не одна абстракция, а четыре шага, каждый со своим способом сломаться; проектировать агента значит проектировать защиту на каждом из четырёх.

Подчеркну элемент, несущий основную сквозную нагрузку курса, — шаг check. И здесь возвращается урок про верность рассуждения ребром: проверка не должна быть «модель сама себя спросила и сама себе ответила, что всё хорошо». Самооценка подвержена той же unfaithfulness, что мы видели на слайде про предел chain-of-thought — это иллюзия контроля: объяснение «я проверил» порождается тем же сэмплингом, что и сам ответ. Надёжная проверка — валидация против внешнего критерия: схема, тест, проверка инвариантов, сверка с источником истины, а в значимых решениях — человек-валидатор. Без внешнего check цикл агента — петля, которая уверенно идёт не туда. Это прямой мост к провалам агентов.
