# Когда аргумент решения нужно брать вне текста клиента

## Assertion

Граница проходит не по тому, кто принимает решение, а по тому, откуда взялось каждое число, которое в это решение идёт.

## Visual

> **Критерий.** Перенос решения в код защищает порядок шагов: какой узел выполнится и по какому условию. Аргументы, которые в это решение подставляются, он не защищает. Число, пришедшее из текста, который читала модель, сверяют с независимым источником либо берут оттуда сразу.

| Когда нужно | Когда не нужно |
|---|---|
| Решение что-то меняет вовне: деньги ушли, документ отправлен, заявка закрыта без человека | Шаг только готовит текст, а исполняет его человек, который этот текст прочитает |
| У значения есть источник истины вне текста клиента: таблица заказов, система оплат, отдельное поле формы | Такого источника нет по природе задачи — тему обращения не из чего взять, кроме слов обратившегося |
| Цена неверного решения отложенная: расхождение всплывает при сверке, когда отменять поздно | Ошибку видно сразу и она отменяема — заявку можно переоформить тем же днём |
| Форму обращения можно менять: она наша, а не чужое письмо или чат | Обращение приходит каналом, который мы не держим; тогда извлекать из текста придётся, и защищать надо иначе |

> **Предел приёма, названный прямо.** Отдельное поле убирает подмену, а не ошибку. Клиент по-прежнему может вписать в него неверное число — просто теперь это обычная неверно заполненная заявка, которую видно сверкой с заказом, а не подмена аргумента внутри решения.

> **Про «пусть человек подтверждает каждую».** По реальной телеметрии одного крупного поставщика подтверждается около **93%** запросов на подтверждение, и чем больше их видит человек, тем меньше внимания достаётся каждому. Рутинная галочка — ещё один слой, не замена структурной защите.

> **Чем кончается то же самое при разном устройстве.** Два публично разобранных случая порчи ответа — чат-бот продавца машин, согласившийся на сделку за доллар, и бот службы доставки, обругавший собственную компанию, — не привели ни к одной сделке: у них не было технического доступа никуда, кроме текста. Два случая с реальным каналом исполнения — автоматическая подгрузка документа по ссылке и уход приватных данных из рабочего мессенджера по клику — обошлись компаниям дорого. Разница не в модели, а в том, у какого шага было настоящее полномочие.

> **Четвёртая строка оси закрыта.** «Решение уже в коде — значит, модель больше не может его обойти»: ход процесса код держит, и подменить ветку текстом не вышло ни разу. Аргумент для этого хода пришёл из заявки, и его подменили.

## Speaker notes

Собираем кейс в формулировку, которую можно унести и приложить к своему процессу.

Критерий такой. Перенос решения в код защищает порядок шагов: какой узел выполнится, по какому условию, с какой веткой. Это настоящая защита, и наш прогон её подтвердил — подменить ветку напрямую не вышло ни разу. Чего этот перенос не делает: он никак не защищает значения, которые в решение подставляются. Если число пришло из текста, который читала модель, его нужно либо сверять с независимым источником, либо брать оттуда сразу.

Теперь границы, обе стороны прямо.

Делать так нужно, когда решение что-то меняет вовне — деньги ушли, документ отправлен, заявка закрыта без человека. Когда у значения есть источник истины вне текста клиента: таблица заказов, система оплат, отдельное поле. Когда цена ошибки отложенная и всплывает при сверке, а не в день заявки. И когда форму обращения можно менять, потому что она наша.

Не нужно — и это не формальная оговорка. Если шаг только готовит текст, а исполняет человек, который этот текст прочитает, подменять там нечего: решение принимает он. Если источника истины вне текста нет по природе задачи — тему обращения не из чего взять, кроме слов обратившегося. Если ошибка видна сразу и отменяема. И если обращение приходит каналом, который мы не держим, — тогда извлекать из текста придётся, и защищаться надо другим способом.

Предел самого приёма. Отдельное поле убирает подмену, а не ошибку. Клиент может вписать в него неверное число — но это уже обычная неверно заполненная заявка, которую ловит сверка с заказом.

Про частое предложение «пусть человек подтверждает каждую». Телеметрия крупного поставщика: подтверждается около девяноста трёх процентов запросов на подтверждение, и чем их больше, тем меньше внимания достаётся каждому. Это слой, а не замена.

И четыре публичных случая рядом. Два бота наговорили лишнего — продали машину за доллар, обругали собственную компанию — и не стоили никому ничего: доступа никуда, кроме текста, у них не было. Два других имели настоящий канал исполнения, и обошлись компаниям дорого. Разница была не в модели, а в том, у какого шага было полномочие.
