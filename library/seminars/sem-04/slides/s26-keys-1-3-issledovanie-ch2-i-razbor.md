# Ни одна структура не измерила пользу — разбор

## Assertion

Ни одно из двух контролируемых измерений не нашло, что распределение документации улучшает результат — поэтому канал выбирается по доставке и цене, а не по обещанной пользе: знание про функцию идёт в код, про класс файлов — в правило с шаблоном путей, про проект — в корневой файл указателями.

## Visual

| Источник | Тезис | Сила доказательства |
|---|---|---|
| McMillan, arXiv:2605.10039 — 1650 сессий Claude Code | Ни одна из 4 структурных переменных конфиг-файла (включая противоречия между соседними уровнями) не дала значимого эффекта после поправки на множественность; для размера и противоречий байесовский фактор — свидетельство ОТСУТСТВИЯ эффекта | Сильное и контринтуитивное: единственное контролируемое исследование именно структуры конфиг-файлов не подтверждает пользы разбиения |
| Khatri, arXiv:2607.27250 — 288 прогонов, 2 агента, 3 репозитория, скрытые эталонные тесты | Три режима: файла нет / файл в каждом ходу / раздельные документы для подгрузки по требованию. Claude: 53,3 — 55,6 — 55,6%. Codex: 58,8 — 56,9 — 52,9%, то есть без файла лучше. Значимости нет (p=1,00 и p=0,66). Задачи проваливались на мастерстве реализации, а не на нехватке знания о репозитории | Сильное по замыслу, слабое по мощности: авторы сами пишут, что на 15–17 задачах различимый эффект больше 30 п.п. |
| Vasilopoulos, arXiv:2602.20478 — 283 сессии, один разработчик, 108 тыс. строк | Единственная работа, где свод построен целиком: постоянно загружаемое ядро + специалисты по областям + 34 документа по требованию через поисковый индекс; инфраструктура — 24,2% строк проекта | Слабое как доказательство пользы: один человек, один проект, без контрольной группы; автор прямо пишет, что это не контролируемый эксперимент |
| Он же, про режим отказа | «Агенты доверяют документации абсолютно, и устаревшие спецификации вызывают тихие отказы». Поддержание свода — 1–2 часа в неделю; устаревание названо главным режимом отказа | Прямое наблюдение владельца системы — и единственное, что мы знаем про цену свода |

**Честно про пробел — четыре оговорки:**

1. Ни одно измерение не показало, что распределение документации улучшает результат. Канал выбирается не по обещанной пользе, а по доставке и цене.
2. «Не нашли эффекта» — не «эффекта нет»: у Khatri мощности хватило бы только на эффект больше 30 п.п., у McMillan байесовский фактор говорит об отсутствии эффекта для двух переменных из четырёх.
3. Гарантия комментария в коде выведена из механизма, а не измерена: если агент читает файл кусками или прыгает к символу через языковой сервер, шапка файла может не попасть в контекст. Отсюда практическое следствие — держать комментарий рядом с самой функцией, а не только в шапке файла.
4. Правило с шаблоном путей — тоже условная загрузка, а не гарантия, и у самого шаблона есть свои грабли: документированный случай — неэкранированная `[` делает шаблон невалидным, он не совпадает ни с чем, и правило молча не срабатывает.

**Разбор пяти карточек зала:**

| Вариант | Где работает | Почему здесь рано — и что вместо |
|---|---|---|
| «Вложенный файл в самой папке» | Нигде гарантированно | Единственный вариант без гарантии во всех четырёх инструментах. Обещание даёт стандарт, а не инструмент |
| «Правило с объявленным шаблоном путей» | Когда у класса файлов есть конвенция, ненужная в остальных сессиях | Правильный механизм — но не на нашем репозитории: конвенция `tests/` помещается в две строки, и новый механизм дороже двух строк |
| **«Комментарий рядом с кодом»** | **Всегда — для знания про конкретный код** | **Часть целевого ответа.** Единственный канал, где доставка следует из механизма, а не из настройки. Деталь про повторную отправку идёт сюда |
| **«Отдельный документ плюс указатель в корневом файле»** | **Когда документ уже есть и его есть кому поддерживать** | **Часть целевого ответа — и ответ на «где живёт свод».** Свод — не отдельный файл, который надо найти: это оглавление в том единственном файле, что грузится при старте. У нас указывать пока не на что |
| «Дописать в корневой файл» | Когда знание нужно в каждой сессии | Для конвенции `tests/` — presence paradox: строка про объект страницы стоит контекста и в сессиях, где тесты не трогают |

**Gold-плашка на уровне целевого ответа — правило трёх адресов:**

> «Знание про одну функцию — рядом с ней, в код. Знание про класс файлов — в правило с объявленным шаблоном путей. Знание про весь проект — в корневой файл, коротко, и указателями, а не содержанием. Единственное место, куда знание класть не надо, — вложенный файл инструкций в подпапке: это единственный из пяти каналов, у которого нет гарантии ни в одном инструменте.»

## Speaker notes

«Теперь неудобная часть. Два контролируемых измерения проверяли, помогает ли всё это вообще. Первое — тысяча шестьсот пятьдесят сессий, четыре структурных переменных конфиг-файла: значимого эффекта нет ни у одной. Второе, свежее, — двести восемьдесят восемь прогонов на двух агентах и трёх репозиториях, три режима: файла нет, файл в каждом ходу, раздельные документы для подгрузки по требованию. У Claude все три в пределах двух процентных пунктов. У Codex вариант "файла нет" оказался лучшим. Значимости нет. А разбор провалов показал, что задачи падали на мастерстве реализации, не на нехватке знания о репозитории.

Оговорку авторы делают сами, и мы её повторим: на пятнадцати задачах различимый эффект — больше тридцати процентных пунктов. Эффект в десять они бы не увидели. "Не нашли" — не "нет".

Что из этого следует практически. Канал доставки мы выбираем не потому, что кто-то доказал его пользу — никто не доказал. Мы выбираем по двум вещам, которые знаем точно: доходит ли текст и сколько он стоит в сессиях, где не нужен. Отсюда правило трёх адресов. Знание про одну функцию — рядом с ней, в код: единственный канал, где доставка следует из механизма. Знание про класс файлов — в правило с объявленным шаблоном путей. Знание про весь проект — в корневой файл, коротко.

И ответ на вопрос, который обычно повисает: где живёт свод. Свод — не отдельный документ, который агент должен найти. Свод — это оглавление в том единственном файле, который грузится при старте: одна строка на документ, где лежит и когда туда идти. Всё остальное — "у нас есть вики, посмотри там" — это надежда, а не канал доставки.

Цену этого свода мы тоже знаем, из единственной работы, где его построили целиком: час-два в неделю на поддержание, и главный режим отказа — устаревание. Дословно: агенты доверяют документации абсолютно, и устаревшие спецификации дают тихие отказы. Это опыт одного разработчика на одном проекте, без контрольной группы, — но других цифр про цену свода у нас нет.»
