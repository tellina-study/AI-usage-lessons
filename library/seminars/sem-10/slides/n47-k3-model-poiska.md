# Структура замера: третья группа и модель поиска

## Assertion

Нейтральная группа — ни разрыв, ни точное совпадение; модель поиска по смыслу та же, что уже считала Кейс 1.

## Visual

| Группа | Сколько | Пример вопроса | Ожидаемый ответ | Почему эта группа |
|---|---|---|---|---|
| Нейтральные | 18 | «Чем был обмен по бартеру в торговле?» | Единственной доступной формой торговли | Класс выделен по отсутствию общего числа с текстом — степень лексического сходства тут значения не имеет. Группа нейтральная: ни разрыв, ни точное совпадение, хотя внутри неё есть и вопросы, лексически близкие к тексту |

> **Поиск по смыслу считает `text-embedding-3-small` через OpenRouter** — та же модель эмбеддинга, что уже работала в Кейсе 1 этого занятия, косинусное сходство со всеми 500 документами, без порога отсечения. Метрика для всех вариантов одна — recall@1 и recall@3 (нашёлся ли верный документ первым или среди первых трёх) и средний ранг верного документа по эталонной разметке SberQuAD. **Результатов на этом кадре нет — дальше смотрим, что получилось.**

## Speaker notes

Третья группа — восемнадцать нейтральных вопросов, где нет общего с текстом числа, которое решало бы вопрос в пользу точного совпадения, вроде вопроса про бартерный обмен в торговле: класс выделен по отсутствию числового совпадения — степень лексического сходства тут значения не имеет. Внутри него есть и вопросы, лексически близкие к тексту не меньше, чем вопросы из группы точного совпадения. Эта группа нужна именно затем, чтобы два предыдущих класса не выглядели единственными: на практике значительная часть реальных вопросов обратившегося не попадает чётко ни в «точное совпадение», ни в «лексический разрыв», и честный замер обязан это отразить — подгонять корпус под удобную картину нельзя.

Поиск по смыслу в этом замере считает модель `text-embedding-3-small` через OpenRouter — та же самая модель эмбеддинга, что уже работала в первом кейсе сегодняшнего занятия. Ничего нового заводить не пришлось: тот же вызов, та же модель, другой корпус и другие вопросы.

Сравнение — косинусное сходство эмбеддинга вопроса со всеми пятьюстами эмбеддингами корпуса, без какого-либо порога отсечения: ранжируются все документы, заранее никого не фильтруют. Это важно для честности замера: модель должна найти верный документ среди всех пятисот — без предварительного отбора в сотню кандидатов.

Метрика для всех трёх вариантов поиска одна и та же: recall@1 и recall@3 — нашёлся ли верный документ первым или хотя бы среди первых трёх, — и средний ранг верного документа в полной выдаче по пятистам документам, по эталонной разметке SberQuAD. Общая метрика на всех вариантах — условие честного сравнения: если бы у каждого варианта была своя метрика, сравнивать числа между собой было бы нечестно.

На этом кадре результатов пока нет ни одного — структура теста названа целиком, дальше идёт сам свод.
