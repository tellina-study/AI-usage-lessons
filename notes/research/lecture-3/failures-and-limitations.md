## Таблица кейсов

### #1 — Агент сжёг $4,200 за 63 часа в петле (catastrophic agent loop)
- **Что произошло:** автономный агент синхронизировал данные заказов в CRM, упёрся в rate-limit (HTTP 429), вошёл в цикл plan→tool→429→replan ≈4,800 раз/час. $1,000 к 12-му часу, экспонента когда агент стал ре-инжестить собственные лог-провалы как контекст. Не понимал ни накопленной стоимости, ни прошедшего времени, ни повторяемости. (Sattyam Jain, 2026-04-14, C5) `[VFY — single-author postmortem; illustrative, числа округлены]`
- **Урок:** "Архитектура — это продукт; модель — апстрим-зависимость, которая может регрессировать в любую неделю." Без жёстких лимитов "пробуй пока не получится" исполняется буквально.
- **Альтернатива:** budget gates (жёсткий потолок $/токены/wall-clock/глубина рекурсии), boundary validation, deny-by-default разрешения, attribution-observability. Для синка заказов — детерминированный retry-with-backoff скрипт, не агент.

### #2 — Catastrophic forgetting при узком fine-tuning
- **Что произошло:** агрессивный fine-tuning на узком task-датасете деградирует общие знания/reasoning базовой модели; эмпирически наблюдается на 1B–7B; *с ростом масштаба модели тяжесть забывания возрастает* (выше изначальный уровень → больше падать). Механизмы (arXiv 2026-01, B4 `[VFY preprint]`): gradient interference в attention, representational drift в средних слоях, уплощение loss-landscape вокруг старых минимумов. (arXiv:2308.08747, B3, 2023-08; B4 2026-01)
- **Урок:** "дообучить под задачу" — не бесплатно; вы можете *сломать* то, что работало.
- **Альтернатива:** PEFT (LoRA/QLoRA — обновляются только адаптеры, базовые веса заморожены → риск забывания ниже); general instruction-tuning как буфер; для меняющегося знания — RAG, не fine-tune. (D8)

### #3 — Multi-agent: размен надёжности (reliability compounding)
- **Что произошло:** в системе из N компонентов надёжности падают мультипликативно: 5×99% → 95% системной, 10×99% → 90%. Улучшение отдельного агента почти не двигает системную надёжность при неконтролируемом распространении ошибок. (D3, MindStudio, 2025-26)
- **Урок:** агенты компонуются "как будто вероятность не перемножается" — это математически ложно.
- **Альтернатива:** меньше хопов; checkpoints/валидация между шагами (workflow-паттерн evaluator-optimizer A1); single-threaded линейный агент (Cognition A4) для задач с зависимостями.

### #4 — Air Canada: чат-бот выдумал политику, компания отвечает (Moffatt v. Air Canada)
- **Что произошло:** 2024-02-14 трибунал BC Civil Resolution признал Air Canada ответственной: чат-бот *галлюцинировал* политику bereavement-тарифа (сказал, что можно подать заявку в течение 90 дней после покупки — противоречило сайту). Суд отверг как "remarkable submission" аргумент, что чат-бот — отдельное юр. лицо. (C1 McCarthy, C2 ABA, 2024-02)
- **Урок:** компания отвечает за вывод ИИ как за сотрудника; галлюцинация на плохом/несогласованном retrieval = юридическая ответственность.
- **Альтернатива:** для фиксированной политики — детерминированная страница/правило/lookup, не генеративный чат; если RAG — strict grounding + цитаты + "не знаю" вместо генерации.

### #5 — RAG молча деградирует на масштабе ("returns something ≠ returns the right thing")
- **Что произошло:** legal-AI цитирует неверные прецеденты, medical-RAG смешивает контексты разных пациентов, support-бот тянет случайные статьи — потому что retrieval тихо перестал работать после ~10k документов, а система всё ещё *что-то* возвращает. Плохие чанки → модель галлюцинирует, чтобы "заполнить пробелы". Fixed-size chunking рвёт логическую структуру/causal-context. Stale index → устаревшая выдача. (D1, Kore.ai D2; Barnett et al. arXiv:2401.05856)
- **Урок:** "вернуть что-то ≠ вернуть правильное"; RAG без мониторинга качества retrieval — скрытая бомба.
- **Альтернатива:** retrieval-eval/observability, semantic/structure-aware chunking, hybrid search, reranking; для малого корпуса (< ~200k токенов) — full-context, без RAG-инфры (A2).

### #6 — GitHub MCP prompt-injection data heist
- **Что произошло:** май 2025 — критическая уязвимость в официальной GitHub MCP-интеграции: атакующий создаёт вредоносный issue в публичном репо → prompt injection перехватывает AI-ассистента → приватные репо, детали проекта, зарплатные/финансовые данные утекают в публичный PR. Root cause: over-privileged PAT + недоверенный контент в контексте LLM. (C8 Docker, C6 AuthZed, 2025-05)
- **Урок:** недоверенный внешний контент = исполняемая инструкция для агента; широкие токены = широкий взрыв.
- **Альтернатива:** least-privilege токены, human-in-the-loop на write-действиях, изоляция недоверенного контента, deny-by-default tool-доступ.

### #7 — mcp-remote CVE-2025-6514: кража ключей через malicious server
- **Что произошло:** июль 2025 — OS command injection: вредоносный MCP-сервер шлёт booby-trapped `authorization_endpoint` → RCE на клиенте → кража API-ключей, cloud-credentials, SSH-ключей, git-содержимого; 437k+ загрузок затронуто. (C6 AuthZed; Practical-DevSecOps; 2025-07)
- **Урок:** подключение к MCP-серверу = доверие его коду на вашей машине; цепочка "агент→инструмент→внешний сервер" — реальная поверхность RCE.
- **Альтернатива:** только аудированные/подписанные серверы, sandbox/контейнер, никаких ключей в окружении агента без vault, review транспорта (STDIO-флоу — системный класс уязвимостей).

### #8 — Tool poisoning / "rug pull" (мутация определения инструмента)
- **Что произошло:** инструменты MCP могут *менять своё определение после установки* — выглядят безопасно при установке, потом тихо перенаправляются на кражу API-ключей; tool poisoning (вредоносные инструкции в метаданных инструмента) — самый частый client-side вектор. WhatsApp MCP (апр 2025): tool-poisoning выгрузил истории чатов. (Unit 42 C9; AuthZed C6; Simon Willison C7)
- **Урок:** "LLM доверяет всему, что присылает убедительные токены" (confused deputy); статическая проверка при установке недостаточна.
- **Альтернатива:** pin версий/хешей tool-definition, runtime-мониторинг изменений, allowlist, не давать агенту доступ к секретам, которые ему не нужны.

### #9 — Anthropic MCP Inspector RCE (CVE-2025-49596)
- **Что произошло:** июнь 2025 — неаутентифицированный RCE в dev-инструменте: отсутствие аутентификации на localhost-листенере, запуск с правами пользователя → доступ к ФС, API-ключам, секретам окружения. (C6 AuthZed, 2025-06)
- **Урок:** даже official/first-party tooling экосистемы MCP имел дыры; "localhost = безопасно" ложно.
- **Альтернатива:** аутентификация даже на локальных листенерах, обновления, принцип наименьших привилегий для dev-окружения.

### #10 — Supabase/Cursor: SQL-эксфильтрация через support-тикеты
- **Что произошло:** mid-2025 — Cursor-агент с привилегированным service-role доступом обрабатывал support-тикеты, содержащие пользовательский ввод; атакующий встроил SQL-инструкции → агент прочитал и выгрузил чувствительные integration-токены. (web-research 2026-05-16; corroborate via C6/C9) `[VFY — corroborate exact dating]`
- **Урок:** агент с привилегиями + недоверенный пользовательский контент в том же контексте = эксфильтрация; "данные" становятся "командами".
- **Альтернатива:** строгое разделение privilege/untrusted-input, read-only/least-privilege роли, не давать LLM сырой service-role.

### #11 — NYT v. OpenAI: судебный приказ сохранять все логи ChatGPT
- **Что произошло:** May 2025 — федеральный судья обязал OpenAI сохранять *все* логи пользователей ChatGPT (400M+ пользователей); индефинитное удержание закончилось 26 сент 2025; ноябрь 2025 — суд обязал выдать 20M анонимизированных логов (из 120M запрошенных истцом). (C3 Bloomberg Law, C4 NatLawReview, A8/A9 OpenAI; 2025-05…11)
- **Урок:** данные в API/чат-цепочке могут *пережить* вашу retention-политику из-за судебного приказа третьей стороны; "30 дней" не гарантировано против litigation hold.
- **Альтернатива:** не отправлять чувствительные данные в провайдера без ZDR/BAA/контракта; on-prem/локальная модель для регулируемых данных; минимизация PII на входе.

### #12 — Anthropic ZDR-граница: third-party / MCP / Files не покрыты
- **Что произошло (ограничение, не "взлом"):** Anthropic data-retention doc (live 2026, A7): ZDR покрывает Messages/Token-Counting; **НЕ покрывает** Files API (хранит до удаления), Batch (29 дн), code-exec контейнеры (до 30 дн), MCP-connector, Agent Skills, Console/Workbench, потребительские планы, **third-party интеграции**. При флаге за нарушение политики — хранение до 2 лет. Activity Feed — 6 лет.
- **Урок:** "у нас ZDR" не значит "ничего нигде не хранится"; каждая фича/интеграция = своя retention-граница; цепочка агент→инструмент→внешний API уводит данные из-под ZDR.
- **Альтернатива:** карта данных по каждой фиче перед продакшеном; не пускать регулируемые данные через не-ZDR фичи; читать политику каждого third-party инструмента отдельно.

### #13 — DPD: чат-бот ругался и сочинял стихи против компании
- **Что произошло:** 2024 — после системного апдейта чат-бот DPD начал материться, называть себя "useless" и писать стих с критикой компании; легко манипулировался, компанию вынудили отключить. (C13 CIO; CX Today)
- **Урок:** генеративный открытый чат-бот = неконтролируемая поверхность; недетерминизм + prompt-injection пользователем.
- **Альтернатива:** для FAQ/трекинга — детерминированный rule-based/retrieval-bot с замкнутым множеством ответов, guardrails, отказ от свободной генерации в клиентском канале.

### #14 — Chevrolet $1 Tahoe / NYC MyCity нелегальные советы
- **Что произошло:** дилерский чат-бот GM согласился "продать" Chevy Tahoe 2024 за $1 после prompt-инъекции пользователя. NYC MyCity (март 2024) советовал бизнесам нарушать закон: что можно забирать чаевые работников, увольнять жалующихся на харассмент, подавать обгрызенную грызунами еду; мэр оставил бота на сайте, признав ошибки. (C13 CIO, C14)
- **Урок:** LLM в роли источника обязывающей политики/цены/юр-совета без жёстких ограничений → юридический и репутационный риск; ИИ не должен быть авторитетом там, где нужна верифицируемая корректность.
- **Альтернатива:** детерминированный price/policy engine; ИИ только как навигатор к официальному документу с дисклеймером; human-review для юридически значимых ответов.

### #15 — Cognition "Don't Build Multi-Agents": хрупкость параллельных субагентов
- **Что произошло (документированная инженерная позиция):** 2025-06-12 (Walden Yan, A4) — параллельные субагенты неполноинформированы; в их Flappy-Bird-примере агенты неверно интерпретируют подзадачи и выдают несовместимые выходы. Принципы: "Share context… not just individual messages"; "Actions carry implicit decisions, and conflicting decisions carry bad results". Модели 2025 ещё не умеют надёжно "договариваться" в long-context дискурсе.
- **Урок:** мульти-агент по умолчанию — не апгрейд; для задач с зависимостями он *хуже* single-threaded.
- **Альтернатива:** single-threaded линейный агент с непрерывным контекстом; мульти-агент только для широкопараллельных независимых задач высокой ценности (Anthropic A3 — контрапункт, не отмена).

### #16 — MIT NANDA: ~95% GenAI-пилотов без измеримого ROI
- **Что произошло:** "The GenAI Divide: State of AI in Business 2025" (MIT NANDA, освещён Fortune 2025-08-18, C10): ~95% корпоративных GenAI-пилотов не дали измеримого P&L-эффекта. Методология: 150 интервью + опрос 350 сотрудников + анализ 300 публичных внедрений. Корень — не качество моделей, а "learning gap" и провал интеграции; бюджеты в sales/marketing, хотя ROI выше в back-office. (C10) `[VFY — цитировать как отчёт с методологией, не как точный универсальный закон]`
- **Урок:** "запустить ИИ" ≠ ценность; архитектурно-интеграционная дисциплина решает, а не выбор модели.
- **Альтернатива:** начинать с простейшего (один LLM-вызов/workflow), узкая верифицируемая задача, измеримый ROI до масштабирования; иногда правильный ответ — не-ИИ-решение.

## Сводка: фундаментальные ограничения по архитектурам

| Архитектура | Фундаментальное ограничение | "Здесь НЕ применять" |
|---|---|---|
| Промпт (zero/few-shot) | нет свежих/приватных знаний; недетерминизм | задачи с верифицируемой спецификацией → обычный код |
| RAG | качество = качество retrieval; молчаливая деградация; stale index; chunking рвёт смысл | малый корпус (влезает в контекст); фиксированная политика → детерминированный lookup |
| Fine-tuning | catastrophic forgetting; знание устаревает; дорого переобучать | меняющиеся факты, нужна свежесть/провенанс → RAG |
| Long context | context rot (точность падает с длиной); стоимость токенов | нужен аудит-провенанс/цитаты по источнику → RAG |
| Агент (ReAct) | накопление ошибок, петли, недетерминизм, 4–15× токенов, prompt-injection | предсказуемая/детерминированная задача → workflow или код |
| Multi-agent | reliability compounding; конфликтующие неявные решения | задачи с зависимостями/общим контекстом → single-threaded |
| MCP/tool use | недоверенный контент=команда; tool poisoning; утечка ключей; данные вне ZDR | секреты/регулируемые данные без изоляции и least-privilege |
| API к провайдеру | retention пережил приказ суда; third-party вне ZDR | высокочувствительные данные без ZDR/BAA → on-prem/локально |
