# Файл, который можно склонировать

## Assertion

Готовый барьер — одна запись в файле настроек: матчер на команды оболочки, четыре шага в команде и урезанный с шестисот секунд до десяти таймаут; файл под контролем версий, поэтому в свежем клоне работает сам.

## Visual

```json
{
  "$comment": "… пояснение автора, на исполнение не влияет …",
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",                                  ← 1
        "hooks": [
          {
            "type": "command",
            "command": "jq -r '.tool_input.command' | { read -r cmd;   ← 2
                 if echo \"$cmd\" | grep -qE '(^|[;&|]\\s*)git\\s+commit\\b'; then
                   if ! git rev-parse --is-inside-work-tree …; then    ← 3
                     … permissionDecision: \"ask\"  + причина …
                   fi
                   branch=$(git symbolic-ref --short HEAD …)           ← 4
                   if [ \"$branch\" = \"main\" ] || [ \"$branch\" = \"master\" ]; then
                     … permissionDecision: \"deny\" + причина …
                   fi
                 fi; }",
            "timeout": 10                                   ← 5
          }
        ]
      }
    ]
  }
}
```

> **1** матчер на команды оболочки · **2** достать команду из нагрузки · **3** это вообще репозиторий? · **4** имя ветки · **5** таймаут, урезанный с 600 секунд до 10

> На пустом репозитории без коммитов: `git rev-parse --abbrev-ref HEAD` → код **128**. `git symbolic-ref --short HEAD` → ветка и код **0**. Тот же репозиторий, обе подряд.

## Speaker notes

Вот он целиком. Пять номеров — ровно те места, которые вы назвали.

Матчер на команды оболочки. Достать команду из нагрузки. Проверка «это вообще репозиторий» — если нет, хук печатает вопрос, а не молчание. Имя ветки. И таймаут: десять секунд там, где по умолчанию шестьсот. Автор урезал его в шестьдесят раз, и причина всплывёт в третьем кейсе.

Поле с пояснением сверху свёрнуто — длинная заметка автора, она не исполняется.

Теперь сноска, она важнее, чем выглядит. Привычная команда определения ветки на репозитории без единого коммита падает с кодом сто двадцать восемь. Менее привычная отдаёт имя ветки и ноль — тот же репозиторий, обе подряд.

Почему это не вопрос вкуса: упавшая проверка ничего не блокирует, она просто не срабатывает — а снаружи это выглядит точно так же, как успешно пройденная. Выбрали команду, у которой нет состояния тихого отказа.

Файл под контролем версий: склонировали — барьер уже стоит.
