# Два слова про RAG

## Assertion

Поиск по базе знаний подкладывает нужные фрагменты в контекст модели перед ответом

## Visual

Горизонтальная схема из четырёх шагов: «вопрос пользователя» → «поиск
релевантных фрагментов в базе» → «фрагменты в контекст модели» → «модель
генерирует ответ». Подпись внизу: «подробно — Лекция 3».

## Speaker notes

Прежде чем перейти к следующему кейсу, два слова про RAG — эта
аббревиатура вам сейчас понадобится, и дальше в занятии будет всплывать
ещё не раз. Устроено это так: вопрос пользователя → система ищет
релевантные фрагменты в базе знаний → найденные фрагменты подкладываются
в контекст модели → модель генерирует ответ на основе вопроса и
найденного. RAG нужен, когда база знаний большая, меняется во времени, и
весь её объём физически не помещается в один запрос к модели — то есть
модель физически не может «прочитать» всё сразу, ей нужно заранее найти
только релевантный кусок. Как устроен поиск внутри — векторные
представления, индексация — подробно разберём на Лекции 3, сегодня нам
достаточно этой интуиции, чтобы узнавать архитектуру, когда она нужна, а
не изобретать её заново каждый раз с нуля.
