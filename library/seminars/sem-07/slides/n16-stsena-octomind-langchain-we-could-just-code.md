# «We could just code»

## Assertion

Octomind строила тестирующих агентов на LangChain до середины 2024 года. Когда абстракции фреймворка перестали помогать и начали мешать, команда вынесла его целиком и заменила прямыми вызовами API — «мы могли просто написать код».

## Visual

| | Прямой вызов API | LangChain |
|---|---|---|
| Пример: перевести слово на другой язык | 1 класс, 1 вызов функции | 3 класса, 4 вызова |
| Новые понятия на том же действии | 0 | 3 — шаблон промпта, парсер вывода, «цепочка» (переопределяет `\|` самого Python) |
| Наблюдение за состоянием агента между шагами | доступно напрямую | `AgentExecutor` непрозрачен — не предоставляет способа |

> Решение команды: вынести фреймворк целиком, заменить прямыми вызовами API и обычным кодом. **«We could just code»** — «мы могли просто написать код».

> Обсуждение на Hacker News (20 июня 2024): **480 очков, 297 комментариев**. Один из самых поддержанных — независимо подтвердил тот же опыт на трёх разных компаниях: «стоит сделать что-то чуть более оригинальное — и приходится проходить сквозь пять слоёв абстракции, чтобы поменять одну мелкую деталь».

## Speaker notes

Octomind — компания, чьи агенты на основе нескольких больших языковых моделей автоматически создают и исправляют сквозные (end-to-end) тесты, написанные на Playwright, популярном инструменте для автоматизации браузера. До середины 2024 года эта агентская система строилась на фреймворке LangChain: решение, которое в 2023 году выглядело разумным — у LangChain был большой набор готовых компонентов и прямое обещание «пройти путь от идеи до работающего кода за один вечер».

На первых порах фреймворк действительно помогал: простые требования команды совпадали с тем, для чего LangChain был рассчитан. Но по мере того как требования становились более специфичными — в частности, понадобился способ извне наблюдать за внутренним состоянием агента между шагами, — высокоуровневые абстракции фреймворка перестали помогать и начали мешать. Простой пример из самого разбираемого поста показывает масштаб разницы: перевод одного слова на другой язык прямым вызовом API модели — это один класс и один вызов функции; та же самая задача через LangChain — уже три класса и четыре вызова, с появлением трёх новых понятий (шаблон промпта, парсер вывода, «цепочка», переопределяющая оператор `|` самого языка Python), ничего не добавляющих к результату по существу. На собственной практике команда обнаружила, что фреймворк не предоставляет способа извне наблюдать за состоянием агента, и это заставило сузить собственную реализацию до того, что LangChain умел показать наружу, вместо того чтобы построить систему, которая была нужна изначально.

Решение команды — вынести фреймворк целиком и заменить его прямыми вызовами API модели и обычным кодом вокруг него: условиями, циклами, обработкой текста. Итоговая формулировка авторов поста короткая и прямая: «We could just code» — «мы могли просто написать код».

Публикация получила широкий резонанс: обсуждение на Hacker News (20 июня 2024) собрало 480 очков и 297 комментариев. Один из самых поддержанных комментариев независимо подтвердил ту же картину на опыте трёх разных компаний автора комментария: «стоит сделать что-то чуть более оригинальное — и приходится проходить сквозь пять слоёв абстракции, чтобы поменять одну мелкую деталь». Другой участник того же обсуждения назвал собственный `AgentExecutor` LangChain «непрозрачным» — ровно тем свойством, которое новый на тот момент инструмент из той же экосистемы, LangGraph, создавался специально, чтобы заменить.
