# Годы original-реестра: извлечение из razmetka и перепроверка динамики файла 14

> **Источник чисел.** Извлечение — `extract_year_candidates.py` (regex-кандидаты из строк
> `razmetka/lec-NN.md`) + `year_decisions.py` (ручное ревью каждого кандидата) +
> `build_original_years.py` (сборка CSV с валидацией). Динамика —
> `analyze_dynamics_original.py` по пересобранному `reestr-reshenij-combined.csv`.
> Формула успешности — формула B линии. Ячейки со знаменателем <10 помечены ⚠.

## §0. Задача и место в линии

Владелец курса, посмотрев графики `chart-dyn-*` файла 14 (построены только на 248
verified-строках — единственном датасете с колонкой `year`): «так добавь и пересчитай!
в исходниках же есть годы». Это файл про то, что получилось: явные годы извлечены из
первоисточника канонического реестра для 213 из 421 кейсов (50,6%), и динамика файла 14
перепроверена на втором, независимо датированном корпусе. Сам `reestr-reshenij.csv` **не
изменён** — годы живут в аддитивном `reestr-reshenij-original-years.csv`, который
`build_combined.py` теперь подхватывает в колонку `year` combined-файла: 461 строка из 669
с непустым годом (213 original + все 248 verified); у остальных 208 original год пуст, как
раньше — обратная совместимость, verified не тронут.

## §1. Методология извлечения — граница и правила

**Граница источника.** Для каждого кейса текст **ровно одной строки-таблицы**
`razmetka/lec-NN.md` (все её ячейки), найденной по `source_file` + `source_locator` — тех же
полей, которыми собирался сам реестр. Сопоставление: 421/421 строк найдено однозначно
(0 unmatched, 0 multi-match; `extract_year_candidates.py`). Главы `chapter*.md`, файлы
`lec-NN-os4.md`, внешние знания и память модели **не использовались**; год публикации лекции
как прокси — не использовался.

**Процедура.** (1) Regex-кандидаты `19xx/20xx` в тексте строки — 397 кандидатов в 221 кейсе;
у 200 кейсов кандидатов нет вовсе → `absent` автоматически. (2) Ручное ревью каждого
кандидата с контекстом ±70 символов (`year_candidates_review.txt`): принят год, **привязанный
к записанному в реестре исходу** кейса; отклонены false positives. (3) Сборка CSV с
программной валидацией: каждый принятый год обязан буквально входить в кандидаты своей
строки (решение не может «придумать» год), множество решений равно множеству кейсов с
кандидатами — ни одного неразобранного.

**Правило нескольких годов / диапазонов** (`year_confidence=range`, 38 строк из 213):
выбран год, якорённый к исходу — конец диапазона для кульминации провала/признания
(GE Predix 2011–2020 → 2020, «продана по частям»), начало — для длящегося успеха «с года X»
(Brynjolfsson rollout ноя 2020 – май 2021 → 2020), последний названный год — для оценки
состояния «к году Y» (Tesla Optimus «с 2021 до 2026 без промышленного масштаба» → 2026).
Это отличается от более грубого правила verified-реестра «первый год диапазона» — и
задокументировано здесь именно потому, что отличается. Остальные 175 строк — `explicit`
(один год, явно привязанный к исходу).

**Отклонено явно, не молча** (8 кейсов, у которых ВСЕ кандидаты — false positives; полный
список с причинами — `REJECTED` в `year_decisions.py`): «~1974 разработчика» (размер выборки,
L04-033), «HB 8752-2023» (номер стандарта, L06-027), «в 1981 году» (исторический контрпример
той же технологии, не год кейса, L07-021), roadmap-даты «план на 2026–2027» / «запуск не
раньше 2027» / «заявлен на 2026» / «анонсирована на 1кв.2025, не развёрнуто» (L09-017,
L09-028, L14-004, L11-038), «Krige 1951, Mockus 1989…» (даты происхождения классического
метода, L15-008). Внутри принятых кейсов отклонялись также: целевые годы («30 000/год к
2028» у L11-012), годы основания компаний при наличии года исхода (FarmWise «с 2016» при
wind-down 2025), версии моделей и счётчики («2000+ увольнений» у L13-014).

**Результат:** `reestr-reshenij-original-years.csv` — 421 строка, колонки
`id, year, year_confidence (explicit/range/absent), year_quote (буквальная цитата из
razmetka), source_file, source_locator`. Покрытие 213/421 = **50,6%** (175 explicit + 38
range + 208 absent, из них 8 — с отклонёнными кандидатами).

## §2. Смещение выборки с годом — главное, что надо знать до чтения трендов

Выборка «у кейса есть явный год» — **не случайная**. Три разреза (из
`build_original_years.py`):

| Разрез | Покрытие годом |
|---|---|
| провалы | **98/137 = 71,5%** |
| успехи | 52/108 = 48,1% |
| частичные | 33/86 = 38,4% |
| неопределённые | 30/90 = 33,3% |

Механизм очевиден из материала: провал — это датируемое **событие** (инцидент, банкротство,
отзыв, суд), успех — часто недатируемое **состояние** («рутинная эксплуатация», «тысячи
клиентов», вендорская метрика без даты). Следствие в числах: B всего original — 44,1%,
датированной подвыборки — **34,7%**, недатированной — **58,9%**; доля провалов 46,0% против
18,8%. График (правая панель): `assets/chart-dyn-orig-vs-verified-by-year.png`.

Разброс по лекциям — 23,1% (lec-07) … 92,6% (lec-15); по классам — 25,5% (classical-ml —
зрелые недатированные деплойменты) … 70,6% (sensor-fusion). То есть датированная подвыборка
смещена одновременно по исходу, по индустрии и по классу метода. **Любая абсолютная ставка
на этой подвыборке занижена конструкцией; читать можно только сравнения внутри подвыборки,
и то с осторожностью.**

Распределение по годам: хвост 1981–2021 — 41 строка (13 лет, по 1–11), окно 2022–2026 —
172 строки с пиком **2025 (69)** и 2026 (38). Пик на 2025, а не 2024 как у verified —
материал курса писался в 2025–2026 и честно отражает recency своих источников.

## §3. Динамика на original-с-годом против verified (окно 2022–2026)

График: `assets/chart-dyn-orig-vs-verified-by-year.png` (левая панель). Таблица D1:

| год | original-с-годом B | verified B |
|---|---|---|
| 2022 | 25,0% (3/12, n=16) | 42,4% (14/33) |
| 2023 | 33,3% (5/15, n=18) | 39,3% (22/56) |
| 2024 | 26,1% (6/23, n=31) | 53,2% (33/62) |
| 2025 | 34,0% (17/50, n=69) | 52,2% (24/46) |
| 2026 ⚠ | 29,4% (5/17, n=38) | 62,5% (15/24) — оба: год неполный |

### 3.1. Рост B по годам — НЕ подтверждается на original-с-годом

Ряд original-с-годом **плоский**: 25–34% без направления (2022 → 2026: +4,4 п.п. с
немонотонными качелями), против роста verified с ~40% до ~53–62%. Честная интерпретация —
**не** «рост опровергнут», а «второй корпус не может его ни подтвердить, ни опровергнуть»:
датированная подвыборка original структурно смещена к провалам (§2), и степень этого смещения
сама может меняться по годам (свежие годы материала курса датируются через июльские-2025
инциденты агентов, старые успехи — не датируются вовсе). Уточнение к файлу 14 §1: статус
вывода «ставка успеха растёт» понижается с «виден сквозь выравнивание» до **«виден только в
verified; второй датированный корпус не воспроизводит и не опровергает (non-random
подвыборка)»**.

### 3.2. Сдвиг границы high — направление подтверждается, величина нет

B на `axis1_level=high` (original-с-годом): 2022–23 — **0/10 (0,0%)**; 2024–25 — **3/20
(15,0%)**. Направление то же, что у verified (11,8% → 59,4%, файл 14 §2): высокая
неопределённость со временем становится менее фатальной — теперь это видно в **двух**
независимо датированных корпусах. Величина прыжка радикально различается (15% против 59%),
на тонких годовых ячейках (⚠ везде кроме 2025), поэтому вывод: **направление — в обоих,
величина — не установлена**. Уточнение к файлу 14 §2: сигнал усилен по направлению, но его
размер следует цитировать только по verified с оговоркой.

### 3.3. «Провал ↔ без гейта» — реплицируется и здесь, ещё жёстче

Доля провалов без гейта (no + not-applicable) по годам, original-с-годом без Лекции 15
(n=188): **100,0% → 100,0% → 93,3% → 93,5% → 100,0%** (2022→2026). У verified было 80–100%
со средним ~87%. Два датированных корпуса согласны: связка «провал случается там, где гейта
нет» не дрейфует во времени — это самый устойчивый динамический результат всей линии
(подтверждение файла 14 §4 вторым корпусом).

### 3.4. Big-AI по годам — корпуса прямо противоречат друг другу

Original-с-годом, 2025: big-AI B = **4,5% (1/22)** против 60,9% у остальных классов;
verified, 2025: big-AI B = **52,9% (9/17)**. Это не шум тонких ячеек (оба знаменателя ≥17) —
это лобовое противоречие. Механизм виден по составу: материал курса (лекции 4, 14) строит
2025-й на задокументированных инцидентах агентного кодинга (Replit, Amazon Q, Kiro, Cloudflare
— все лето–зима 2025), и правило ≥30% провального контента толкает туда же; verified под
квотой 10/10 набирал сбалансированно. Уточнение к файлу 14 §3 и файлу 12 §3: **уровень
успешности big-AI в 2025–2026 — величина, о которой два корпуса этой линии не согласны даже
по порядку**; вывод «big-AI улучшается внутри себя» остаётся только verified-наблюдением.
(Расхождение по agentic-llm 25,0%/56,2% из файла 12 §3 — часть этой же картины.)

### 3.5. Extreme — мёртв и во втором датированном корпусе

9 из 10 original-кейсов уровня `extreme` получили год (2020–2026): **0 успехов** — 7
провалов + 2 частичных. Вместе с verified (0 успехов, n=7, все годы) — экстремальная неопределённость
остаётся зоной без единого датированного успеха в обоих корпусах, во всех годах.

### 3.6. Хвост 1981–2021 (41 строка)

Вне окна трендов, но сам по себе содержателен: B хвоста — 48,5% (16/33), т.е. старые
датированные кейсы курса — наполовину катастрофы-иллюстрации (Hyatt 1981, Gimli 1983, MCO
1999, Knight 2012, Uber Tempe 2018), наполовину зрелые успехи (AEGIS 2016, ORION 2015,
X5/Tesco 2017–2020). Это педагогический отбор, не временной ряд — 13 лет по 1–11 строк.

## §4. Что изменилось в статусах выводов файла 14

| Вывод файла 14 | Было (только verified) | Стало (два датированных корпуса) |
|---|---|---|
| Ставка успеха растёт по годам (§1) | рост ~40% → 53–62% | **только verified**: original-с-годом плоский (25–34%), но подвыборка non-random — не подтверждает и не опровергает (§3.1) |
| High становится успешнее (§2) | 11,8% → 59,4% | **направление — в обоих** (original: 0% → 15%), величина не установлена (§3.2) |
| «Провал ↔ без гейта» стабильна (§4) | ~87% все годы | **в обоих**: original-с-годом 93–100% все годы — самый устойчивый динамический результат линии (§3.3) |
| Big-AI улучшается внутри себя (§3) | 18,2% → 52,9% | **корпуса противоречат**: original-с-годом 2025 = 4,5% против verified 52,9% — не разрешимо этими данными (§3.4) |
| Extreme мёртв во все годы (§2) | 0 успехов, n=7 | **в обоих**: + 9 датированных original, 0 успехов, 2020–2026 (§3.5) |

## §5. Ограничения этого извлечения

1. **Смещение «датируются провалы»** (§2) — главное; оно не чинится большим n, это свойство
   того, как материал курса датирует события.
2. **Single-rater ревью годов** — 221 решение принято одним проходом этой сессии; правило
   диапазонов (§1) содержит суждение (конец/начало/состояние), другая реализация даст другие
   годы у части из 38 range-строк.
3. **Граница «только строка razmetka»** режет в обе стороны: год, который есть в главе
   лекции, но не попал в ячейку разметки, здесь отсутствует честно — покрытие можно поднять
   только расширением границы источника, что было бы другой методологией.
4. **2026 неполон** в обоих корпусах (сбор 2026-11-20); у original-с-годом 2026 вдобавок
   13/38 строк — `undetermined` (свежие нерешённые кейсы).
5. Правило диапазонов этого файла ≠ правило verified («первый год») — при сравнении корпусов
   по конкретному кейсу это может давать ±1–2 года; на бакетах-годах эффект мал, но не нулевой.

## §6. Артефакты

- `reestr-reshenij-original-years.csv` — 421 строка, годы + confidence + цитаты (аддитивный).
- `extract_year_candidates.py` — кандидаты с контекстом (его вывод
  `year_candidates_review.txt` воспроизводится запуском скрипта и в репозиторий не коммитится).
- `year_decisions.py` — все 213 принятых решений + 8 отклонений, с цитатами и причинами.
- `build_original_years.py` — сборка CSV с валидацией; печатает покрытие и bias-разрезы.
- `build_combined.py` — расширен: подхватывает годы original в combined (669 строк, 213+248
  с годом; поведение без файла годов — прежнее).
- `analyze_dynamics_original.py` — таблицы D1–D6 этого файла.
- `assets/chart-dyn-orig-vs-verified-by-year.png` — B по годам в двух корпусах + смещение
  исходов датированной подвыборки.
