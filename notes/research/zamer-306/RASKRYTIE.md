# Раскрытие — читать ПОСЛЕ слепой оценки владельца, не раньше

Этот файл называет, какая запись и какое условие по снимку стоят за
каждым `nabor-N`, и переформулирует выводы `REZULTAT.md` с открытой
группировкой. Открывается этой же сессией только после того, как
владелец произвёл свою оценку `nabor-1.pdf` … `nabor-4.pdf` вслепую —
см. предупреждение в начале `REZULTAT.md` и в `KLYUCH-ne-otkryvat-do-
ocenki.md`.

## Соответствие

| Набор | Запись | Снимок на входе |
|---|---|---|
| `nabor-1` | слоты (`blocks:`/`scheme:`/`columns:`/`figure:`) | ДА |
| `nabor-2` | закрытый словарь HTML | ДА |
| `nabor-3` | закрытый словарь HTML | НЕТ |
| `nabor-4` | слоты | НЕТ |

Группировка для вопросов issue #306:
- **слоты** = `{nabor-1, nabor-4}` · **HTML** = `{nabor-2, nabor-3}`
- **со снимком** = `{nabor-1, nabor-2}` · **без снимка** = `{nabor-3, nabor-4}`

## Ответы на три вопроса issue #306, раскрыто

**Вопрос 1 — слоты против HTML.** По структурным счётчикам (отказ формы,
наложения, изобретённые ключи) — **ничья, 0 везде**, см. `REZULTAT.md`
раздел 3. По найденным качественным дефектам — по одному на каждую
запись (`nabor-4`/слоты: количественный перебор бюджета на 27 знаков,
кадр собрался чисто, без единого предупреждения сборки; `nabor-3`/HTML:
содержательная подмена смысла слота + систематическая потеря
типографики тире). Это не симметричные по цене дефекты: перебор бюджета
на слотах — это то, что сторож `[плашки]`/`[бюджет]` обязан (и в
будущем будет) ловить автоматически; подмена смысла слота на HTML — это
дефект, который НИ ОДНА структурная проверка формы не видит в принципе
(значение синтаксически валидно, в бюджет укладывается, форма не
откажет). На выборке в один случай на сторону это наблюдение, не закон,
но оно указывает в одну сторону: **при равной структурной надёжности
слоты дешевле в сопровождении (дефект их записи автоматически ловится
существующим сторожем `[плашки]`; дефект HTML-записи — нет, и потребовал
бы отдельного «смыслового» ревью, которого в контракте формы сегодня
нет)**.

**Вопрос 2 — эталонный снимок на входе.** Оба набора СО снимком
(`nabor-1`, `nabor-2`) — без единого найденного дефекта ЛЮБОГО рода, и
оба дословно воспроизвели формулировку источника там, где задание
допускало вольный пересказ. Оба набора БЕЗ снимка (`nabor-3`, `nabor-4`)
— по одному дефекту каждый, разного рода, и оба слегка переформулировали
число словами, где источник держал словесную форму («из ста» →
«из 100» — содержательно то же число, но не то же написание, которое
было бы на эталонном снимке, если бы он был). **На этой выборке снимок
совпадает с более высокой точностью ПОЖДОЙ записи** — эффект виден у
слотов (`nabor-1` чище `nabor-4`) и у HTML (`nabor-2` чище `nabor-3`)
одинаково, то есть выглядит как эффект самого снимка, а не как эффект,
специфичный для одной записи. Численно подтвердить внешнюю цифру
«+15–20%» из issue #306 этот замер не может (выборка 1 случай на
ячейку), но направление совпадает.

**Вопрос 3 — цена свободы разметки.** Ноль у всех четырёх, включая оба
HTML-набора (`nabor-2`, `nabor-3`) — несмотря на то, что HTML-словарь
структурно допускает куда больше степеней свободы (произвольная
вложенность, любые имена тегов), чем закрытый перечень ключей YAML.
Довод issue #306 п.1 («HTML выразительнее нашего контракта») на этой
выборке не привёл к тому, что модель воспользовалась этой
выразительностью, чтобы обойти словарь, — она просто заполнила
закрытые теги и остановилась.

## Рекомендация для гайдбука (issue #304)

**Предпочесть запись слотов** (`blocks:`/`scheme:`/`columns:`/
`figure:`) — не потому, что она структурно точнее (ничья по счётчикам),
а потому что:
1. Она уже понимается действующей сборкой без дополнительного слоя
   перевода (`html2kadr.py` для HTML-записи — лишний компонент с
   собственной поверхностью отказа, которого у слотов нет).
2. Единственный найденный на ней дефект (перебор бюджета) — ровно тот
   класс, для которого в этом же замере построен автоматический счётчик
   (`proverit_slovar_i_budget.py`) и который легко завести постоянным
   сторожем рядом с `[плашки]`/`[схема]`/`[ось]`/`[столбцы]`/`[число]`.
3. Единственный найденный на HTML дефект (подмена смысла слота) —
   КЛАССА, который не ловится структурной проверкой формы в принципе ни
   у одной из двух записей, но на HTML он произошёл на этой выборке, а
   на слотах — нет.

**Эталонный снимок — добавить в шаг заполнения формы там, где он есть**,
независимо от итогового выбора записи: на этой выборке он коррелирует с
более высокой точностью у ОБЕИХ записей одинаково.

**Оговорка по силе рекомендации.** Оба пункта построены на выборке «один
случай дефекта на ячейку» — раздел «Чем замер мог бы врать» в
`REZULTAT.md` целиком применим и здесь. Это направление, не доказанный
закон; для более сильного вывода нужен замер на бОльшем числе кадров
и/или другой модели.
