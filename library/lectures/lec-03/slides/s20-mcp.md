# Visible content

## Title bar
«MCP: стандарт подключения — не гарантия доверия»

## Body
[Слева — что решает MCP]
**MCP (Model Context Protocol)** — «USB-C для инструментов LLM»
N моделей × M инструментов = N×M интеграций → MCP: **N+M**
Открыт Anthropic 11/2024, принят OpenAI и Google в 2025

[Справа — масштаб критически]
Каталоги — «до **90 000** серверов», но реально запускаемых — лишь **≈10 000 ≈ 11%**
Остальное — дубли, битые, заглушки; и даже рабочие **не проверены на безопасность**

[Плашка — поворот доверия]
30+ CVE за 60 дней (**≈43%** — command injection); path traversal у **82%** из 2 614 просканированных реализаций

[Gold callout, низ]
**Стандартизация подключения не означает безопасность подключаемого — и усугубляет проблему доверия.** Удобство подключения — не аргумент за подключение.

## Speaker notes

Разведём два вопроса, которые легко слить. Function calling решает, как модель формулирует вызов инструмента. MCP решает другой вопрос — как инструмент к модели физически подключается. До конца 2024 года каждый вендор и каждая интеграция решали это по-своему, и это давало комбинаторный взрыв несовместимых интеграций. MCP — Model Context Protocol — открытый стандарт единого способа подключать инструменты к LLM-приложениям. Арифметика проста: при N моделях и M инструментах прямые интеграции дают N×M пар; MCP сводит это к N+M, потому что каждый инструмент один раз становится сервером, каждая модель — клиентом. Прижившаяся метафора — «USB-C для инструментов LLM»: один разъём вместо набора несовместимых. Anthropic открыла протокол в ноябре 2024, OpenAI приняла в марте 2025, Google — в апреле 2025; это де-факто отраслевой стандарт, и подключение инструмента из «проекта на неделю» превратилось в «операцию на минуты».

Но масштаб экосистемы надо читать критически, потому что «сырой» размер каталога вводит в заблуждение. Официальный реестр на середину 2026 содержит порядка 9 400–9 700 серверов, сторонние каталоги считают десятки тысяч. Три знаменателя снимают эйфорию. Первый: обновлённый скан всех примерно 10 700 серверов показал, что около 25% непригодны — и авторы называют это полом, а не потолком, потому что часть за auth-стеной вообще не удалось протестировать. Второй: «запускается» не равно «решает задачу» — на бенчмарке MCP-Universe с реальными серверами лучшая модель дала 43,7% успешных задач, то есть проваливает больше половины. Третий: безопасность не проверена вовсе.

И вот критический инженерный поворот, который легко пропустить за удобством: стандартизация подключения не означает безопасность подключаемого — более того, усугубляет проблему доверия. Ровно та лёгкость, с которой MCP подключает инструмент, означает, что каждый подключённый инструмент — это код, запускаемый в вашем окружении, и описание, которое попадает в контекст модели и может быть носителем инъекции. Масштаб измерим: за одно 60-дневное окно в начале 2026 против MCP-серверов зарегистрировано 30+ CVE, около 43% из них — паттерны command injection; независимые сканы находили path traversal у 82% из 2 614 проверенных реализаций. База: это доли просканированных серверов, но выборки в тысячи делают картину репрезентативной. «Подключить за минуту» и «доверять подключённому» — два разных вопроса; MCP решил первый и сделал второй острее. Зафиксируем принцип: удобство подключения — не аргумент за подключение; аргумент — требование задачи и приемлемость новой границы доверия. Полный разбор атак MCP — в разделе про безопасность агента.
