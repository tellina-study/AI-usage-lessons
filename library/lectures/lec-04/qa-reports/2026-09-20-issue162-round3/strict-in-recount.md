Категория **in** для этой задачи включает явное расширение, которое использует сам текст этих двух частей («честная граница практики с уроком» — cм. §3.3e «когда git не подходит»), поверх 4 категорий из CLAUDE.md (провал+урок / фундаментальное ограничение / критерий «AI не нужен» / сравнение с альтернативой).

Правило классификации применялось **одинаково к обеим частям**: абзац засчитывается in только если **бо́льшая часть** его содержания организована вокруг провала/ограничения/критерия/альтернативы — не абзац, где механика/листинг вендоров занимает основной объём, а урок — одно предложение в конце (это partial→out). Отдельно стоящий абзац "Суждение (устойчивый паттерн / вендорский хайп)", целиком построенный вокруг разоблачения конкретного overclaim (например §5.4, §5.2 Части 4; §3.4 «Anthropic уравнен» Части 3) — засчитан in; абзац, где anti-hype-фраза — просто финальное предложение поверх вендор-ландшафта (например §3.3b skills-кросс-вендорность, §5.4 «вторичный блок — инструменты» Части 4) — засчитан out.
