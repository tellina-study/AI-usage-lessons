# Панель узла механической проверки: код со списком приёмов

## Assertion

Узел смотрит на оборот речи заявки по шаблону текста — одна строка кода на каждое известное семейство приёма.

## Visual

> Панель узла Code: массив `PRIEMY`, пары «название приёма, шаблон текста». Девять строк видны без прокрутки, ещё двенадцать — за нижним краем кадра, из полных 21 (число — из описания замера).

## Speaker notes

Это настоящая панель узла, который на прошлом кадре мы назвали механической проверкой, — код, который видит заявку раньше решающей модели.

Сверху — стандартные вкладки n8n: Parameters и Settings. Режим запуска — «на каждый элемент»: функция выполняется один раз для каждой заявки из очереди. Язык — JavaScript, обычный код, без обращения к какой-либо модели.

Тело функции открывает массив `PRIEMY`. Каждая строка этого массива — пара: человеческое название приёма и регулярное выражение, которое его ищет. В коде это называется регулярным выражением — шаблон текста, который одним правилом ловит целый класс похожих формулировок приёма.

На экране, без прокрутки, видно девять таких строк подряд. Первая ищет прямую инъекцию — обороты вида «забудь инструкции» в разных формулировках. Дальше — требование игнорировать правило или проверку, инструкция пропустить проверку, две разные поддельные системные пометки: одна оформлена квадратной скобкой, другая словом «системное» внутри обычного текста. Дальше — упоминание режима отладки или теста, инструкция, набранная латиницей вместо русского текста, и два варианта переопределения формата ответа: через слово «decision» и через просьбу ответить строго определённым образом.

Массив на этом не заканчивается — он просто обрезан нижним краем экрана. Полный список, по которому написан узел, — двадцать один шаблон на разные семейства приёмов; на кадре видна меньше половины, остальные двенадцать строк идут ниже и требуют прокрутки, которой здесь нет.

Как работает сам узел, видно по его месту в схеме. Для каждой заявки код проходит список приёмов по очереди и сравнивает текст заявки с каждым шаблоном. Совпал хотя бы один — заявка уходит менеджеру напрямую, решающая модель эту заявку не видит вовсе. Не совпал ни один шаблон из двадцати одного — заявка идёт дальше, к модели, обычным путём.

Понимания смысла заявки здесь нет вовсе. Узел сравнивает её текст с готовым списком оборотов речи — и ровно этим ограничен: формулировка манипуляции, которой в списке нет, пройдёт мимо него незамеченной, сколько бы смысла в ней ни было. Чем это оборачивается на реальном корпусе из 64 заявок, мы увидим на такте результата.
