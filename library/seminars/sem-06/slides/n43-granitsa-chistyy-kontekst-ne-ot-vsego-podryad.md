# Чистый контекст — не от всего подряд

## Assertion

Роль по умолчанию наследует описания всех подключённых серверов вызвавшей сессии — даже тех, что её задаче не нужны. Фокус работает для репозитория, но не сам собой для серверов.

## Visual

> **«Subagents inherit every MCP tool definition from the parent session, which can fill their context window before the first turn. Disable MCP servers you are not using before spawning subagents.»** — документация харнесса об устранении ошибок.

> Это третья полоса со схемы базы — «описания подключённых серверов». В контекст роли она переезжает целиком. Для нашего поиска по лимиту участников: если в сессии подключены трекер задач и сервер документации из прошлого раздела занятия, роль, которой нужно прочитать сорок файлов кода, получает их описания бесплатно.

**Фокус из прошлых двух слайдов — про содержимое репозитория. За тем, что подключено серверами, следят отдельно: тем же списком инструментов роли, который стоит пятым блоком на одностраничнике ступени.**

## Speaker notes

Контекст роли чище вашего, но не чист от всего подряд. Свой промпт и свежее начало она получает — и вместе с ними, по умолчанию, описания всех подключённых серверов целиком, даже тех, что её задаче не нужны. Это третья полоса нашей схемы — она наследуется.

Дословно из документации по устранению ошибок: роли наследуют каждое описание инструмента из вызвавшей сессии, и это может заполнить их контекст ещё до первого шага — отключайте серверы, которыми не пользуетесь, прежде чем заводить роли.

Фокус работает для содержимого репозитория. За подключёнными серверами следят отдельно — тем же списком прав, который стоит пятым блоком на одностраничнике.

Если спросят, почему это не противоречит прошлым слайдам: не противоречит, оба про один контракт. Этот называет то, что входит в контракт дополнительно и по умолчанию, помимо желания автора роли. Экономия контекста остаётся, просто считается с этой оговоркой.

Если спросят, сколько это стоит: цифру зал уже видел в прошлом блоке занятия, там постоянная плата за подключённые серверы измерена в токенах и в доле контекста. Здесь важно другое: эта плата вносится ещё раз, отдельно, в контекст каждой заведённой роли.

Если спросят, можно ли подключить сервер только роли, не трогая сессию: можно, и это обратный приём той же механики. Роль умеет объявить нужный ей сервер у себя — он поднимается на её старте и отключается на её завершении, а контекст вызвавшей сессии его описаний не видит вовсе. Для тяжёлого сервера, нужного одной задаче, это дешевле, чем держать его подключённым всю сессию.

Если спросят, относится ли то же к хукам и скиллам: механика у них своя, и сегодня мы её не разбираем. Здесь достаточно одного: отключение ненужных серверов — осознанный ход перед заведением роли. Разовая уборка в начале дня его не заменяет, потому что сессия обрастает серверами по ходу работы.
