# Case 2. Duplicate Check

## Assertion

One and the same person sometimes writes about the same question twice, in different words. There's no need to run the whole chain from scratch on a repeat request if the answer already exists.

## Visual

> "Isn't this the same question he wrote in two hours ago?"

## Speaker notes

We closed the first case: the notification to the coordinator is now assembled by substituting values, not composed by the model on every run. The second case starts from a different need, but one just as ordinary for a training center.

Course requests are handled by an administrator, and many messages from different people pass through her in a day. Sometimes the same person writes about the same question twice: forgot they'd already asked, didn't see the answer, decided to remind in different words. The reason doesn't matter to us. What matters is that the chain we're building shouldn't react to a repeat request every time as if it were seeing it for the first time.

The line on screen isn't from an abstract client — it's from the person reading the requests on the other end: the administrator, who sees the incoming stream all day and has to decide in a second whether this is a new question or one she's already dealt with. The difference from the first case is where the need grows from: there, the discomfort was the client's, getting a dry or uneven notification text; here the discomfort is the administrator's — and, no less, the client's own, who has every right to expect he won't be asked again about something he just explained.

So far it looks like a minor interface detail: so what, the question came in twice. But behind every repeat run stands the whole chain again — logging the request, assembling the notification, the model's work on the earlier steps. If the repeat isn't stopped at the entrance, all of that work gets redone for a question that already has an answer. It's cheaper to stop the repeat at the entrance than to run it through the whole chain and sort it out after the fact.

Today the task isn't whether the check is needed — it obviously is — but what to build it from. And, as we'll see further on, two different tools are in play by price: one almost free, the other noticeably more expensive. The question isn't which one to pick as the only one, but how to order them.
