# Big Idea + Keystone (моя formulation после чтения)

- **Big Idea:** Современная производственная автоматизация — это не «AI заменяет людей», а **многоуровневая шкала, на которой AI занимает разные роли в зависимости от ступени**; инженер ценится умением определить правильную ступень и **отказать неподходящему AI**, заменив его более правильным инструментом (MPC, формальная верификация, метрология+GD&T+SPC, RCM).
- **A0–A3 ladder:** A0 — AI наблюдает (vision QC, PdM); A1 — AI советует (MES advisory, alarm prediction, PLC Copilot); A2 — AI замыкает петлю в безопасной зоне (Yokogawa FKDPP); A3 — AI действует автономно (Toyota Digit, BMW Leipzig — единицы кейсов в 2026). Шкала — наша адаптация SAE J3016/ISO 22989, не индустриальная норма.
- **Digital twin as bridge:** Двойник — не «3D-визуализация», а двусторонняя петля physical ↔ digital по Kritzinger 2018. Архитектурно мост между A1 и A2 — без twin как safe sandbox обучение RL невозможно (либо опасно на железе, либо застрял на A1). Это **новая грань** Лекции 12 относительно Лекции 11.

# Что понял (5 takeaways)

1. **Шкала A0–A3 ортогональна ISA-95.** Один AI-агент может физически жить на ISA-95 L2 (диспетчерская) и при этом быть на A1 (советует, не замыкает). Сначала путало, но §0.1 disambiguation отлично спасает.
2. **75% twin-проектов проваливаются из-за слоя данных, не из-за модели.** Кейс Southeast Asian Port ($12M / 18 мес / списан) — это не «AI плох», это **«красивый Unity-3D без подключённых датчиков»**. Я как студент уношу: «3D-визуализация — last, data layer — first».
3. **Generic LLM на PLC структурно невозможен.** Пример MOV %M99999 в S7-1500 убедителен: ChatGPT не знает архитектурного предела M-области (65535), генерирует синтаксически валидный код, PLC уходит в STOP, производственная линия встаёт. Это конкретный концентрат failure-bucket.
4. **MPC vs RL — default для известной физики = MPC.** Это меняет моё интуитивное мышление: я был склонен «RL современнее, поэтому лучше». Теперь понимаю — MPC даёт **доказуемые гарантии устойчивости через Ляпунова**, регуляторно совместим, зрелые библиотеки 50+ лет; RL для известной физики = over-engineering.
5. **A3 в 2026 — почти исключительно логистика, не управление.** Toyota Digit, BMW Leipzig — внутрицеховая логистика. Никто публично не дал AI полномочия дозировать активный компонент в фарме или открыть предохранительный клапан. Это правильно формирует ожидания на горизонт 5–10 лет.

# Failure cases — выношу lessons?

Все пять документированных провалов **рассказаны так, что я выношу lesson**:

1. **Southeast Asian Port** ($12M/18 мес/списан) → **Lesson: data layer first, visualization last.** Это самый запоминающийся кейс главы. Конкретные цифры + конкретные причины (фрагментированные данные, плохое качество, отсутствие clear use case) + явная связь с шестью структурными причинами §1.4 + объяснение «3D-визуализация без слоя данных = музей, не twin». **Pedagogically полноценный failure-case.**

2. **ChatGPT MOV %M99999 на S7-1500** → **Lesson: generic LLM не знает архитектурных пределов конкретного контроллера; purpose-built tools обучены на верифицированных PLC-программах.** Самый яркий концентрат failure главы. Конкретный пример кода + объяснение архитектурного несоответствия + сравнение 35% vs 85% точность generic vs purpose-built. **Сильный failure-case.**

3. **Гипотетический FKDPP без mitigation в §4.4 (T=300°C → T=315°C через surface fouling)** → **Lesson: sim-to-real gap реален; mitigation три уровня (domain randomization + fine-tuning + runtime monitors) обязательны.** «Гипотетический» формат немного слабее реального кейса, но конкретика (300 vs 315°C, 10% excursion) делает урок осязаемым. **Хороший failure-case с явным mitigation.**

4. **Каскад срабатываний 1% × 10 000 = 100 годных отвергнуто** → **Lesson: на массовой линии FP rate доминирует над FN rate; ROC-tuning + trust ramping обязательны.** Простая арифметика, очень убедительная. Плюс психология (signal fatigue, alarm fatigue) для глубины. **Сильный конкретный failure-case.**

5. **Gartner 40% agentic AI cancelled by 2027 + MIT Sloan 95% GenAI pilots fail by 2025** → **Lesson: индустриальные baseline ожидания должны учитывать failure rate; 5 вопросов вендору §5.4.** Это не «случай», это **statistical reality**. Использовано как контекст, а не как narrative cas. Работает.

**Worked example фарма+FDA** (§5.3) — это **тоже failure-case по сути** (verdict «AI не подходит для batch release»). См. separate section ниже.

**Failure-bucket purity (strict-in):** оцениваю **>>30% — возможно ~50%+** содержания главы посвящено провалам / ограничениям / альтернативам / критериям «не применять». Структурно это сделано через §5 (целая большая глава — «10 критериев когда AI не подходит» — это самый большой раздел) + §2.4 (где vision/PdM не применимы) + §3.4 (provals generic LLM на PLC) + §4.4 (sim-to-real gap) + §4.5 (три блокера A3) + §1.4–§1.5 (provals 75% + Southeast Asian Port). **Fundamental mission курса выполнена** через chapter.

# Альтернативы AI — actionable?

**Да, мне как студенту понятно, когда что выбирать.** Это благодаря decision-tree подходу в §5.2 + конкретным альтернативам для каждого критерия. Я могу сейчас сформулировать:

| Задача | AI или не AI |
|---|---|
| Safety-critical аварийная защита | Hardwired PLC + формальная верификация (TLA+/SPIN/Coq/SCADE) + IEC 61508 SIL 2/3 |
| Процесс с известной физикой (например, нагрев печи Q4 в Q&A) | MPC — доминирует, гарантии устойчивости |
| Tight tolerances ±0,001 мм | Метрология (КИМ, лазерные интерферометры) + GD&T + SPC |
| Rare events MTBF >1 года | Physics-based simulation + RCM (Nowlan-Heap 1978) |
| Generic PLC code | Purpose-built tools (PLC Copilot) + engineer-in-loop OR classical engineer + симулятор |
| FDA batch release decision | Human-in-loop QA + statistical batch sampling (USP testing) |
| ATEX Zone 0 environment | ATEX-сертифицированные датчики в Zone 0 + удалённая обработка edge AI в Zone 2 |
| Дешёвая операция, низкая стоимость ошибки человека | Не внедрять AI; обучение операторов |

**Это actionable knowledge.** Через decision tree §5.2 я могу пройти 5 категорий и оценить любую задачу. Worked example §5.3 (фарма) дополнительно показывает, как делать gap-анализ конкретного процесса.

**Что можно усилить (P2):** в §5.2 на каждый критерий есть «альтернатива», но **редко есть конкретная стоимость / время / зрелость альтернативы**. Например, для критерия 1 «hardwired PLC + формальная верификация» — это $200K? $2M? 6 месяцев? 2 года? Студенту полезно было бы знать порядок. Сейчас приходится догадываться. **Recommendation: добавить порядковую оценку стоимости / времени каждой не-AI альтернативы.**

**Параллель с Waymo (geo-fenced) и Tesla FSD (всё ещё L2)** в §4.5.3 — очень помогает интуитивно. SAE J3016 шкала за 10 лет показала те же блокеры — это закрепляет мой ментальный model.

# Worked example фарма+FDA §5.3

**Мне абсолютно ясно**, что AI не подходит для batch release и **какая альтернатива**.

- Gap-анализ конкретный: AI ±0,5% vs FDA ±0,1% = **5× не в пользу AI**. AI accuracy 90% = 10% случаев неверно = неприемлемо для безопасности пациента.
- Двухслойная архитектура (AI advisory на process design + human-in-loop QA + statistical batch sampling для release) — **actionable alternative**, не «не делайте AI вообще».
- Cross-reference на Pfizer Vox 2024-2025 (внутренняя GenAI как рекомендательная система на AWS Bedrock + SageMaker) — реальный пример того, как делают правильно.
- **Уточнение «что значит AI accuracy ±0,5% точно»** (стандартное отклонение, не критический максимум; tails распределения дают единичные outliers до 5%) — **крайне полезное уточнение**, я бы как студент мог запутаться без него.
- **Extension на RTRT (Real-Time Release Testing)** — показывает, что границы регуляторики динамичны, FDA постепенно принимает PAT + chemometric calibration с PLS/PCR (не AI), и AI как **расширение** RTRT — пилотная фаза 2026.

**Это образцовый worked example в учебнике** — конкретно, gap-quantified, action-oriented.

# Где «уже знаю»

- **§2.1 Vision QC** — basics классификации/сегментации на PCB, ROC-кривые, FP/FN trade-offs. Это покрыто в моём курсе ML. Можно было бы **глубже**: какие конкретные архитектуры (YOLOv8? RetinaNet? - **§4.1 closed-loop control basics (термостат)** — это уровень school physics. Можно глубже: PID-control, autotuning, gain scheduling. §4.5 / §6.2 их упоминают.

**Recommendation: эти места можно проходить быстрее, экономя время на §5 и §4 advanced stuff (FKDPP, sim-to-real, CIRL).**
