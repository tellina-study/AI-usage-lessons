# What Carries Over from Last Session

## Assertion

The S9 process answers the requester itself, checks its own answer, decides refunds by a rule in code, keeps a format, reads a photo. One thing it doesn't do: it can't handle a knowledge base bigger than a dozen items.

## Visual

The process you left last session with could do five things: answer the requester instead of staying silent; check its own answer before sending it; decide the refund amount by a rule written in code instead of letting the model guess; answer in one stable format on every call; and, if a photo is attached to the request, read it instead of just saving it as an attachment.

> **The question S9 ended on, verbatim: "At what size and volatility does the knowledge base make 'everything in the prompt' stop being reasonable?"**

Olga's training center doesn't stand still: something is added to the base every week — a new regulation, an updated FAQ, a breakdown of another disputed case. S9's ten items are the base's state at the moment the process launched; from there it grows.

## Speaker notes

Today's session starts from the same training-center process the previous seminar ended on, plus the five refinements we worked through there. The process answers the requester itself when the question falls within what the knowledge base covers. It checks its own answer before sending it, as a separate step, instead of trusting the model's self-report. The refund amount is decided by a rule written in code; there is no free decision left to the model here. The answer arrives in one stable format on every call. And if a photo is attached to the request — say, a scan of a form or a receipt — the process can read it and understand what's written on it.

These five refinements are enough for this breakdown to move forward: we take them as a given, without rebuilding or re-verifying them. The full, combined file of the repository's state after S9 doesn't exist yet in this working tree — it's being prepared on a separate branch, and merging it isn't part of today's task. So we don't reconstruct the exact look of the input screen; we take exactly what the previous session already fixed in words.

And this is exactly the question that, per the arc's plan, the previous session is supposed to end on: at what size and volatility does "everything in the prompt" stop being reasonable for the knowledge base. This isn't rhetoric, and it isn't a metaphor for the next session — it's exactly where today's breakdown begins.

The training center doesn't stand still. Every week the base gains a new regulation, an updated FAQ item, a breakdown of another disputed case from the last cohort. The ten items we worked with last session are the base's state at the moment the process launched; from there it changes. The question S9 ended on stops being hypothetical the moment the base actually starts growing — and that's exactly where today's breakdown begins.
