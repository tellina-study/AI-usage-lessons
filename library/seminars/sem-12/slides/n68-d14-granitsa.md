# Когда какой способ нужен — и когда ни один из трёх

## Assertion

Слова — когда запрос совпадает с записью; смысл — когда меняется формулировка; картинка — когда деталь не записана; и ни один из трёх не решает «тот же файл?» — для этого в занятии есть другой, дешевле и детерминированный способ.

## Visual

| Способ | Когда нужен | Когда не нужен |
|---|---|---|
| По словам | запрос совпадает с лексикой описаний; нужна скорость и объяснимость без модели | запрос другими словами или про незаписанную деталь |
| По смыслу | пересказ другими словами; описания разнородны по лексике | корпус мелкий и однородный по жанру — опоры для границы меньше, чем у слов |
| По картинке | описание не называет искомую деталь вовсе; описаний может не быть | текст на изображении — вся информативность в печатном тексте, не в общем виде |
| Гибрид | смесь классов запроса на одном архиве | один класс известен заранее — одиночная ветка дешевле и не хуже |

> **Граница масштаба.** 40 фотографий здесь ищутся перебором каждой. На миллионе снимков перебор не работает — нужен приближённый поиск соседей; это граница масштаба, названная, не разобранная в этом кейсе.

> **Это не задача «тот же файл?»** Точный повтор файла решает **кейс C** этого занятия перцептивным хэшем — дешевле и детерминированно. Три способа кейса D не закрывают все задачи поиска по картинкам — они закрывают поиск по запросу, не сличение дублей.

## Speaker notes

Граница — прямой формой: не «стоит учитывать, что применимость ограничена», а когда конкретно каждый способ нужен и когда не нужен. Поиск по словам нужен, когда запрос Ольги совпадает с лексикой описаний, — он быстрый, бесплатный и объяснимый, и не нужен, когда формулировка другая или деталь не записана. Поиск по смыслу нужен там, где описания разнородны и пересказ другими словами — обычное дело; на архиве Ольги, где описания однородны по жанру, у него меньше опоры для границы, чем у простого поиска по словам, — измеренная на этом занятии находка, не абстрактное предупреждение. Поиск по вектору картинки нужен, когда описание не называет искомую деталь вовсе или описаний может не быть в принципе, и не нужен там, где вся информативность — в печатном тексте: контроль на документах это прямо показал. Гибрид нужен, когда к архиву приходит смесь классов запроса и неизвестно заранее, какой класс следующий; если класс известен — одиночная, более дешёвая ветка не хуже.

Отдельно — граница масштаба: сорок фотографий архива здесь ищутся прямым перебором каждой против каждой. На архиве в миллион снимков перебор физически не успевает, и нужен приближённый поиск по соседям — это названная граница, не разобранная здесь задача.

И последняя, обязательная строка — чтобы с занятия не унесли лишний вывод. Кейс D не решает «тот же самый файл уже есть в архиве?» — ни один из трёх способов поиска не для этого. Эту задачу в сегодняшнем занятии решает кейс C перцептивным хэшем: дешевле любого вызова модели и детерминированно, одно и то же сравнение всегда даёт одно и то же число. Три способа кейса D закрывают поиск по запросу — находят то, что похоже или подходит по смыслу, не сличают, один ли это файл побайтово.
