# Контрпример: `✓ Connected`, но не работает

## Assertion

«Подключён» — не то же самое, что «работает»: claude mcp list показывал ✓ Connected, пока сервер этого же курса был фактически недоступен.

## Visual

Карточка-цитата с моноширинным блоком, дословно из `notes/mcp-limitations.md`, запись `[#49]`: «Server: workspace-mcp. Symptom: Все вызовы возвращают `ACTION REQUIRED: Google Authentication Needed`, хотя `claude mcp list` показывает сервер как `✓ Connected`. Root cause: OAuth-приложение в Google Cloud Console находится в Testing publishing status — в этом режиме refresh_token автоматически отзывается через 7 дней неактивности». Ниже — компактная приписка: второй, независимый инцидент того же сервера (запись `[#86]`) — `claude mcp list` показывает уже `✗ Failed to connect`, регрессия транзитивной зависимости `aiofile` 3.10.0.

## Speaker notes

Это не гипотетический риск, а реальная запись из журнала известных ограничений этого же курса, `notes/mcp-limitations.md`. Сервер `workspace-mcp` — тот же, что даёт доступ к Google Docs, Sheets, Slides. В какой-то момент все вызовы к нему стали возвращать «требуется аутентификация Google», при этом `claude mcp list` продолжал честно показывать зелёную галочку — сервер подключён. Причина оказалась не в самом сервере, а в конфигурации OAuth-приложения в Google Cloud Console: оно осталось в тестовом статусе публикации, а в этом режиме refresh-токен отзывается автоматически через семь дней неактивности. Формально подключение существует, канал открыт, но токен на другом конце уже истёк — и агент об этом ничего не знает, пока не попробует реально что-то сделать.

Второй, независимый случай того же сервера — прямо противоположный симптом: `claude mcp list` показывает уже явную ошибку подключения, потому что транзитивная зависимость `aiofile` версии 3.10.0 не была зафиксирована и получила регрессию при обновлении.

Вывод один и тот же в обоих случаях, но особенно ценен первый: статус в интерфейсе — это не источник истины о работоспособности сервера, это источник истины только о факте самого подключения на транспортном уровне. Проверять нужно оба слоя отдельно — и что `claude mcp list` показывает подключение, и что панель `/mcp` реально перечисляет рабочие инструменты, а не ноль при формально зелёном статусе.

Перенесите этот урок на GitHub-сервер из нашего сценария: подключить его командой и увидеть зелёную галочку — необходимое, но не достаточное условие. Прежде чем полагаться на сервер в реальной работе, стоит один раз явно попросить его сделать что-то простое и проверяемое — например, вывести список открытых issue — и убедиться, что ответ реальный, а не ошибка авторизации, спрятанная за формально зелёным статусом подключения.
