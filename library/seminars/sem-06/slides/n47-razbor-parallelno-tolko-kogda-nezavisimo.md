# Параллельно — только когда независимо

## Assertion

Третья карточка — целевая без оговорок: сначала проверить, что задачи действительно не зависят друг от друга, и только потом запускать параллельный вызов роли на каждую.

## Visual

| Вариант | Что делает | Что не делает / ограничение |
|---|---|---|
| ничего не менять — по одной | простой, предсказуемый порядок | время ожидания складывается — три проверки по очереди всегда займут втрое больше, чем одна |
| объединить три правки в одно задание | один вызов, одна формулировка | роль должна держать в голове три независимых диффа сразу — находки одной правки легче спутать с другой |
| сначала проверить зависимость, потом отдельный вызов роли на каждую задачу параллельно | отделяет случай, где параллелить безопасно, от случая, где нет, и даёт каждой независимой задаче свой контекст — итоги приходят почти одновременно | работает только когда проверка подтвердила независимость — иначе роли увидят разные версии одного и того же кода; сама проверка ничего не ускоряет, экономит время только распараллеливание, которое идёт следом |
| параллелить всегда, по умолчанию | экономит время там, где правки и так независимы | там, где шаг одной роли должен видеть вывод другой, параллельный запуск оставляет у каждой роли свою, частично устаревшую картину вместо общего результата |

> **Вывод.** Третья карточка — целевая без оговорок, двумя шагами сразу: сначала проверить условие независимости, потом запустить параллельный вызов роли на каждую задачу. Пропустить первый шаг и оставить только второй — с равной вероятностью либо сэкономит время, либо создаст рассогласование.

## Speaker notes

Ничего не менять — простой, предсказуемый порядок, но время ожидания складывается: три проверки по очереди всегда займут втрое больше, чем одна. Объединить три правки в одно задание — один вызов, одна формулировка, но роль должна держать в голове три независимых диффа сразу, и находки одной правки легче спутать с другой. Сначала проверить зависимость, потом отдельный вызов роли на каждую задачу параллельно — это один приём в два шага, не два конкурирующих варианта: проверка отделяет безопасный случай от небезопасного, а сам параллельный запуск даёт каждой правке свой контекст и итоги почти одновременно — но работает только когда проверка подтвердила независимость, иначе роли увидят разные версии одного и того же кода. Параллелить всегда, по умолчанию — экономит время там, где правки и так независимы, но там, где шаг одной роли должен видеть вывод другой, параллельный запуск оставляет у каждой роли свою, частично устаревшую картину вместо общего результата.

Вывод: третья карточка — целевая без оговорок, и в ней два шага сразу, не один.

Если спросят, что будет, если проверка зависимости пройдена, а дальше всё равно что-то не сошлось: именно это разбираем дальше в этом же кейсе — задачи могут быть независимыми по названию и всё равно оставить промежуток, за который не отвечает ни одна из ролей.
