# Отчёт: круг правок владельца — кейс 3 блока MCP

## По замечаниям

**1. «Нет разбора MCP — что это такое и как работает».** Не моя зона: базовый разбор MCP
(section_divider/base_and_edge) живёт в кейсе 1 (n05–n15), к моей зоне не относится.

**2. «В первом кейсе — выбор API / MCP-удалённый / свой MCP-сервер».** Не моя зона: это
развилка кейса 1.

**3. «Кейсы и вопросы не читаемы, надо упрощать» — относится напрямую.** Проверил все 8
слайдов зоны по настоящим PNG (`rendered/snapshots/iter-25.png` … `iter-32.png`). Пять слайдов
(`n25`, `n26`, `n27`, `n29`, `n30`) уже проходили пятисекундную проверку — не трогал, чтобы не
расходовать бюджет без нужды. Два слайда были стеной текста и правились:

- **`n28`** (разбор пяти карточек, форма А7) — все 15 ячеек таблицы были полными предложениями
  (до 25 слов на ячейку, читались не с одного взгляда по строке). Сжал каждую ячейку до короткой
  фразы (6–10 слов), смысл и база утверждения сохранены дословно — форма «вариант · где
  работает · ограничения» и вывод отдельной строкой не тронуты (правило А7). Таблица теперь
  читается по строке за один проход, не по абзацу.
- **`n31`** (три слоя провала) — таблица «что произошло · база сравнения» держала два столбца
  полными абзацами (до 55 слов на ячейку: три инцидента описывались как три отдельных рассказа).
  Это именно тот случай, который владелец выделил отдельно в задании («кейсы с анализом работы и
  контролем — отличный, но не читаемые»). Свёл к таблице «слой · что подменилось · цифра»:
  общая колонка называет канал подмены одной фразой для всех трёх слоёв (юникод в описании →
  поведение сервера после проверки → код уже одобренного пакета при обновлении), на экране
  остаётся только число (8 из 8, 3 вызова, ≈1,5 недели) и источник. Абзацы с разбором (почему 0
  ложных срабатываний исключает фильтр, почему порог именно три вызова, почему обновление —
  обычное действие) перенесены в заметки, где они частично уже были — на экране не потеряны по
  смыслу, но и не загромождают его.

**4. «Одностраничники по субагентам и MCP».** Не моя зона — одностраничник MCP (если решат
делать отдельный) не входит в диапазон `n25–n32`; мой диапазон уже начинается с развилки
третьего кейса, не с одностраничника блока.

**5. «Кейсы с анализом работы и контролем — не читаемые, упрощать» — относится напрямую,
см. п.3 выше.** Та же правка (`n28`, `n31`) закрывает оба пункта: это одно требование, не два
разных.

**6. «Больше кейсов и рассмотрений на границы применимости» — относится напрямую.** Слайд
границы (`n32`) раньше отвечал только на один вопрос («когда достаточно периодического
внимания»), второй столбец нёс один пункт («не нужно никогда — полагаться на одобрили один
раз…»). Расширил правый столбец до трёх явных пунктов, по материалу механики (`rework/section-1-
mcp-part1b.md` §A.3.5, уже раскрытому на `n29`), без новых фактов:
  - когда одной дисциплины (версия + перечитывание) мало — нужна аннотация
    `requiresUserInteraction` у автора сервера;
  - **прямой ответ на «что делать, если автор сервера её не поставил»**: технического
    принуждения к повторному одобрению тогда не существует вовсе, держит только дисциплина
    версии и перечитывания — и для такого уровня чувствительности её объективно недостаточно;
  - где черта, за которой автоматизацию шага убирают вовсе: если и дисциплины, и аннотации не
    хватает для чувствительности действия — шаг передают человеку.

  Заметки получили соответствующее раскрытие («Дальше — три уточнения этой границы»).

## Что сокращено ради бюджета

- `n28`: вывод-директива под таблицей не менялся (уже короткий), но из ячеек убраны
  повторяющиеся служебные слова («работает, если…», «большинство клиентов, включая наш»,
  «каким его сменил бы злоумышленник» в двух местах) — смысл остался, многословность ушла.
- `n31`: столбец «база сравнения» (интерпретация каждого факта) убран с экрана целиком,
  перенесён в заметки — на слайде он не читался с одного взгляда, а для устной подачи
  интерпретация работает лучше, чем для чтения с проектора.
