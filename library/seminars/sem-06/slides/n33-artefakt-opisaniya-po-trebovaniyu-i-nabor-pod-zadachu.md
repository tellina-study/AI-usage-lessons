# Описания — по требованию. Набор — под задачу

## Assertion

Четыре строки решения: у сервера в проектном файле нет флага принудительной загрузки описаний, отложенная загрузка в окружении не выключена, серверу передаются только нужные наборы инструментов, а свой набор серверов он держит в личной области.

## Visual

- `.mcp.json`: у сервера снят `alwaysLoad: true` — описания его инструментов приходят по требованию. Флаг оставляют одному инструменту, который нужен на каждом шаге, и записывают рядом, почему.
- Окружение проекта: `ENABLE_TOOL_SEARCH` не выставлен в `false`. Пороговое значение вида `auto:10` — компромисс: пока определения занимают меньше названной доли контекста, они грузятся сразу.
- Команда запуска сервера: только нужные наборы инструментов — `--toolsets repos,issues` вместо полного набора. Проверяйте флаги по текущей версии сервера: у официального сервера GitHub режим выдачи наборов по требованию был и снят в мае 2026.
- Личная область подключения: серверы под свою работу — там. Общий проектный файл остаётся командным, и чужие три сервера из него никто не выбрасывает.

> Проектный файл говорит, что подключено у всех. Личная область — что подключено у вас. Режим загрузки описаний решает, во что это обходится до первого вопроса.

## Speaker notes

Четыре строки решения, и первые две — проверка; настройки они не меняют.

Первая. В файле подключения `.mcp.json` у двух серверов снят `alwaysLoad: true`: описания их инструментов снова приходят по требованию. Флаг имеет законное применение, и совсем его запрещать неразумно — инструмент, который нужен буквально на каждом шаге, дешевле описать один раз при старте, чем подтягивать его схему перед каждым обращением. Поэтому флаг оставляют одному такому инструменту и рядом записывают, какому и почему. Исключение без записанной причины через месяц неотличимо от случайной строки, и следующий человек либо снесёт его вслепую, либо побоится тронуть.

Вторая. В окружении проекта `ENABLE_TOOL_SEARCH` не выставлен в `false`. Это проверка одного значения, и она стоит минуты. Пороговое значение вида `auto:10` — осмысленный компромисс для тех, кому важна скорость первого обращения: пока определения занимают меньше названной доли контекста, они грузятся сразу, а при достижении порога уходят в отсрочку.

Третья строка живёт на стороне самого сервера. В команде запуска передаются только нужные наборы инструментов: `--toolsets repos,issues` вместо полного набора. Официальный сервер GitHub объясняет назначение этого флага своими словами: включение только нужных наборов помогает модели с выбором инструмента и уменьшает размер контекста. Сервер, который умеет отдавать свои инструменты наборами, снимает часть платы раньше, чем она дойдёт до клиента.

Здесь же — оговорка о свежести флагов, и это проверенный случай с номером запроса правок и датой. У того же сервера GitHub существовал режим выдачи наборов по требованию: флаг `--dynamic-toolsets`, переменная окружения `GITHUB_DYNAMIC_TOOLSETS` и три служебных инструмента для перечисления и включения наборов. В описании версии 1.0.0 слово `dynamic` встречается одиннадцать раз; начиная с версии 1.1.0 — ни разу, и в коде его тоже нет. Удалён режим одним запросом на внесение правок в мае 2026 года: двадцать четыре файла, пятьдесят одна строка добавлена, девятьсот сорок две удалены. Причина, названная автором, — долг по поддержке и то, что режим работал только локально, удалённый сервер его никогда не предлагал. Вывода «идея не работает» в запросе нет, и приписывать его нельзя.

Урок из этой оговорки общий, и он про обычную судьбу флага. Поиск по-прежнему выдаёт страницу прежней версии, она читается как действующая инструкция, и отличить её от действующей по виду невозможно. Проверяется это одним способом: открыть описание текущей версии сервера и найти флаг там.

Четвёртая строка — единственная, которая требует работы. Серверы под свою личную работу переносятся в личную область подключения: тот же файл настроек пользователя, который разбирался, когда выбирали, куда положить ключ. Проектный файл остаётся командным, и чужие серверы из него никто не выбрасывает. Держать всё в проектном файле проще, пока наборы у всех совпадают; как только работа расходится, общий файл берёт с каждого плату за все работы сразу — ровно то, что произошло в сцене.

В сцене всё было устроено наоборот: флаг стоял, поставил его один человек, а платил каждый, кто открывал сессию.
