# Три части описания и пять шагов тела

## Assertion

Описание собирается из трёх частей — что делает, когда использовать, когда НЕ использовать — и становится реальной формулировкой из репозитория; тело же зал назвал сам минуту назад.

## Visual

| Часть описания | Что она решает | Как звучит у нас |
|---|---|---|
| что делает | попадёт ли скилл в кандидаты вообще | деплоит лендинг signup-landing на прод: сборка, тест формы, публикация, проверка адреса |
| когда использовать | совпадут ли слова с теми, что реально звучат в запросе | используй, когда просят задеплоить, выкатить или опубликовать сайт |
| когда НЕ использовать | не сработает ли там, где он не нужен | не для обычных правок кода без деплоя |

```
# deploy
1. Собрать: npm run build  (код выхода должен быть 0)
2. Прогнать smoke-тест формы: npx playwright test  (должен быть зелёным)
3. Опубликовать: wrangler pages deploy dist --project-name signup-landing
4. Открыть прод-URL, отправить форму с валидными данными — заявка должна дойти
5. Записать в .tasks/active/YYYY-MM-DD-описание.md: что задеплоено, когда, чем
```

## Speaker notes

«Собираем из трёх частей. Что делает — от неё зависит, попадёт ли скилл в кандидаты вообще. Когда использовать — здесь решается, совпадут ли ваши слова с теми, что реально звучат в запросе. Когда НЕ использовать — эту часть почти никто не называет сам, и именно она отличает описание, которое работает, от описания, которое работает слишком хорошо.

Приём для запоминания: описание — это поисковый запрос вашего будущего «я», забывшего детали через полгода.

Тело вы назвали сами минуту назад. Новый здесь только последний шаг — он вернётся на ступени про процесс.»
