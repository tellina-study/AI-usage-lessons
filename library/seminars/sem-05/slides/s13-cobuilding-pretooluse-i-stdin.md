# Три вопроса — три фрагмента конфигурации

## Assertion

Первые три решения хука: проверка до вызова, условие — только команды оболочки, источник знания о команде — JSON на стандартном вводе.

## Visual

**Вопрос 1.** «Проверять до вызова инструмента или после?» → до. Фиксируется:
```
"PreToolUse"
```

**Вопрос 2.** «Вешаем условие на все инструменты или на один?» → на один, на команды оболочки. Фиксируется:
```
"matcher": "Bash"
```

**Вопрос 3.** «Откуда хук узнаёт, какая команда сейчас выполнится?» → движок передаёт описание вызова в виде JSON через стандартный ввод. Фиксируется:
```
jq -r '.tool_input.command'
```

## Speaker notes

Первые два вопроса — почти разминка: до вызова, не после — фиксируем `PreToolUse`; на один инструмент, не на все — фиксируем `matcher: Bash`. Шире условие срабатывания — больше ложных срабатываний и выше цена ошибки в самой проверке, к этому вопрос ещё вернётся в разборе провалов.

Третий вопрос зал обычно не угадывает: хук получает описание вызова целиком, в виде JSON, через стандартный ввод, и вытаскивает из него нужное поле через `jq`. Это общий приём для любого хука на `PreToolUse` — распаковать описание события, а не разбирать произвольный текст, который к нему как-то попал.

Три фрагмента уже собраны, но конфигурации ещё не хватает главного — что делать с полученной командой и что возвращать в ответ. Это следующий слайд, два оставшихся вопроса, и один из них с настоящим сюрпризом: привычная команда для определения ветки здесь работает не так, как ожидается.
