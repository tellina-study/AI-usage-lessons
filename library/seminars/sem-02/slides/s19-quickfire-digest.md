# Еженедельный дайджест

## Assertion

RAG — это про поиск по большой, меняющейся базе на произвольный запрос, а не про «у нас много источников» само по себе.

## Visual

Постановка: «Нужен еженедельный дайджест по рабочим чатам и почте команды — что обсуждали, что решили». Ниже — двухколоночный разбор: левая колонка «Агент — нужен» (обход нескольких источников по расписанию, многошаговая задача с обращением к внешним системам), правая колонка «RAG — не нужен» (источники обходятся напрямую по расписанию, не по произвольному запросу пользователя к большой базе; суммаризация — один вызов модели после сбора). Внизу урок: «RAG ≠ «у нас много источников»».

## Speaker notes

Быстрый кейс: нужен еженедельный дайджест по рабочим чатам и почте команды — что обсуждали, что решили.

Вопрос в зал: какая архитектура здесь нужна?

Здесь ожидайте частую ошибку — часть аудитории скажет «RAG, потому что много источников». Разбор: агент, или конвейер, нужен — кто-то должен обойти несколько источников, чаты и почту, и собрать материал, это многошаговая задача с обращением к внешним системам. А RAG не нужен: источники обходятся напрямую по расписанию, а не по произвольному запросу пользователя к большой базе; после сбора материала суммаризация делается одним вызовом модели.

Урок для явного проговаривания: RAG — это про поиск по большой, меняющейся базе на произвольный запрос пользователя, а не про «у нас много источников данных» само по себе. Спутать эти два признака — частая практическая ошибка.

### Self-check
1. В чём именно разница между «обойти несколько источников по расписанию» и «искать по большой базе на запрос пользователя» — почему первое не требует RAG?
2. Приведите контрпример: измените постановку дайджеста так, чтобы RAG действительно понадобился.
