# Блок 4. Промежуточная сборка оси (5 мин, 3 слайда)

Блок продолжает занятие сразу после того, как на ступени 5 (MCP) легла третья строка оси. Он не
подводит итог занятия — до итога ещё два раздела следующего занятия. Он делает ровно три вещи:
показывает три заполненные строки, показывает, во что они превратили репозиторий, и возвращает
зал к вопросу открытия — частично, ровно настолько, насколько сегодня было материала.

## A. План раздела

### A.0. Раскадровка (3 слайда, 5 мин)

|---|---|---|---|---|
| 1 | z5-1 | `recap_table` | 2,0 | Ось: три заполненные строки из пяти + явное «две остаются» |

**Тон.** Это контрольная точка, а не развязка: ни синтеза «3:3 vs что-то ещё», ни тезисов на
вынос, ни афоризма в рамке. Тот материал закрывает занятие 6, не дублируется здесь.

### A.1. z5-1 — ось: три строки из пяти

**Заголовок:** «Ось занятия: три строки закрыты».

Та же таблица, что была показана пустой на открытии (`section-0-otkrytie.md` §A.4) — теперь с
тремя заполненными строками. Формулировки сведены дословно из строк оси, сданных каждым разделом,
сокращены под ширину ячейки без изменения смысла.

| Ступень | Предотвращаем / решаем | Интуиция говорила | Проверка показала |
|---|---|---|---|
| Хук | Решаем — правило уже нарушено | «Поставили хук — коммит в `main` закрыт» | Барьер обходится синтаксически пятью воспроизведёнными способами против ровно этого паттерна — и не видит человека, печатающего `git commit` в отдельном терминале |
| Скилл | Решаем — по сигналу перегрузки файла инструкций процедурой, нужной не всегда | «Содержание скилла — вот что важно, описание — деталь, можно дописать позже» | Без точного описания-триггера скилл не сработает вообще — модель выбирает по описанию, не по содержимому; разовое одобрение даёт постоянные права на исполнение кода |
| MCP | Смешанная: подключение — решаем, по сигналу; дисциплина минимальных прав — предотвращаем, день 0 | «Одобрил один раз, права выдал — вопрос решён; зелёный статус значит работает» | Права вычёркиваются, а не выдаются; одобрение не окончательно — 8 из 8 попыток сокрытия доставили инструкцию модели, 0 из 8 потребовали повторного одобрения; зелёный статус — утверждение о транспорте, не о работе |
| Субагент | | | |
| Процесс | | | |

**Строка под таблицей (дословно, единственная подпись слайда):** «Три строки закрыты. Две
остаются — их заполняет следующее занятие.»

### A.4. Доля strict-in этого раздела

Раздел — мостовой, как открытие (`section-0-otkrytie.md` §A.8, 16,7%). Полностью in-bucket
контента здесь нет: слайд z5-1 — таблица уже прозвучавших в разделах 1–3 находок (сами находки
учтены в долю своих разделов), слайд z5-2 — дерево репозитория, слайд z5-3 — открытый вопрос без
разбора провала. 0 из 5,0 минут = **0%**. Это ожидаемо: раздел не вводит нового провала или
границы, он сводит уже прозвучавшее, и основной бюджет провалов несут разделы 1–3 (33,3%, 42% и
доля раздела 3 — см. соответствующие файлы), не мостовые блоки.

### B.2. z5-1 — ось: три строки

**Речь фасилитатора (дословно, ≈180 слов):**

> «Вот та же таблица, которую мы открывали пустой в начале занятия. Три строки из пяти — три
> сегодняшние ступени.
>
> Хук: интуиция говорила — поставили, значит закрыли. Проверка показала — закрыли ровно один
> паттерн одной команды, и барьер не видит человека, который набирает `git commit` в соседнем
> терминале.
>
> Скилл: интуиция говорила — важно, что внутри файла. Проверка показала — важно, что в описании:
> без точного триггера содержание не имеет значения, оно просто не загрузится.
>
> Доступ наружу: интуиция говорила — одобрил один раз, зелёный статус, вопрос закрыт. Проверка
> показала — статус про транспорт, не про работу, а одобрение инструмента не окончательно.

> Две строки внизу пустые — субагент и процесс. Не потому, что про них нечего сказать: потому что
> мы до них ещё не дошли. Их заполнит следующее занятие.»
