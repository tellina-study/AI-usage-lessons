# Файл, который открывается сам

## Assertion

Собранный SKILL.md — реальный файл в репозитории; одновременно файл инструкций худеет обратно до сорока строк, а скилл проверяется в обе стороны — срабатывает, когда нужно, и молчит, когда не нужно.

## Visual

```
.claude/skills/deploy/SKILL.md
---
name: deploy
description: Деплоит лендинг signup-landing на прод — сборка, smoke-тест формы,
  публикация, проверка прод-URL. Используй, когда пользователь просит задеплоить,
  выкатить или опубликовать сайт — не для обычных правок кода без деплоя.
---
# deploy
1. Собрать: npm run build  (код выхода должен быть 0)
2. Прогнать smoke-тест формы: npx playwright test  (должен быть зелёным)
3. Опубликовать: wrangler pages deploy dist --project-name signup-landing
4. Открыть прод-URL, отправить форму с валидными данными — заявка должна дойти
5. Записать в .tasks/active/YYYY-MM-DD-описание.md: что задеплоено, когда, чем
```

- Одновременно: те же сорок строк вырезаются из файла инструкций, он возвращается к сорока.
- Проверка положительная: в новой сессии просим «задеплой сайт» — скилл должен открыться сам.
- Проверка отрицательная, её пропускают: «поправь отступ в вёрстке» — открываться не должен.

## Speaker notes

«Вот файл целиком, в репозитории он лежит по пути .claude/skills/deploy/SKILL.md. Фронтматтер — имя и описание из трёх частей. Тело — пять шагов.

И одновременно вот что происходит с файлом инструкций: восемьдесят строк уходят обратно до сорока, тех же, с которыми мы начали, — с разделами этикета и хука, но без процедуры деплоя, она вырезана целиком. Это не опция. Если процедура осталась в двух местах, налог никуда не делся, а к нему добавился риск, что копии разойдутся.

Как проверить, что это реально сработало, а не просто выглядит правильно? Первая проверка очевидная: в новой сессии просим задеплоить сайт — скилл должен открыться сам. Вторая, та, которую почти всегда пропускают: просим поправить отступ в вёрстке. Скилл открываться не должен. Если открылся — описание слишком широкое, и вы купили себе лишнее срабатывание в каждой второй сессии. Скилл проверяется в обе стороны: срабатывает, когда надо, и молчит, когда не надо.»
