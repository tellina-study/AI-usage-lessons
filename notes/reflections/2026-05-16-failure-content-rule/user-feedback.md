## Паттерны (как работать с этим пользователем)

1. **Строгие правила + явная owner-дискреция для фундамента.**
   Хочет жёсткое ENFORCED-правило, но с правом владельца снять его для теоретических/вводных лекций. Миссия (научить суждению) — это **дух**, а не слепые 30% везде.
   → При предложении governance-правил сразу включать явный документированный escape hatch и спрашивать про классы-исключения. → memory.

2. **Решительное исполнение, чекпойнты только на настоящих forks.**
   Терсные команды: «запускай», «1 b», «2 да», «все в main», «сведи все в одну ветку», «1 пуш 2 удали», «мерж», «рефлексируй и закрывай». Уважать короткие директивы; держать crisp decision-таблицы; не переспрашивать там, где есть разумный дефолт.

3. **Surface, не auto-decide, для того, что я не создавал.**
   lec-02 backup, ahead-ветки #51/#52 — я не удалял молча, вынес решение → пользователь выбрал (push #51/#52, delete backup). Это правильное поведение, продолжать.

4. **Deferral пересматривается.**
   «оставляем как есть» по lec-02 → позже «наведи порядок, всё синхронизируй». Не трактовать отложенное как закрытое; держать в поле зрения.

5. **Изоляция риска ценится.**
   Поправка #82 отдельным issue/branch/PR, не в #79; правки через worktree без порчи локального состояния; мерж только по явной команде. Пользователь это принял без правок.
