# Итоговый файл — тринадцать строк

## Assertion

Итоговый файл — тринадцать строк: критерий готово, гейт-предупреждение, честная оговорка предела; `AGENTS.md` — симлинк на тот же файл.

## Visual

```
# CLAUDE.md

signup-landing: статический лендинг с формой заявки на демо-урок. Готово = `npm run build`
завершается кодом 0, `npx playwright test` зелёный, форма реально отправляет заявку на проде.

## Safety / scope boundaries

- Никогда не запускать деплой на прод без явного запроса.

## Build, test, verify

- To verify a change actually works (not just compiles): открыть `dist/index.html` после сборки,
  вручную отправить форму с заполненными и с пустыми полями.
```

Три факта справа:

- Файл грузится в начало **каждой** сессии целиком (официальный ориентир объёма — до 200 строк, наш итог — 13).
- `@`-импорты организуют файл, но не экономят контекст — импортированное всё равно грузится целиком.
- `AGENTS.md` заведён как симлинк на тот же файл (`ln -s CLAUDE.md AGENTS.md`) — один источник правды для разных движков. Острый край: `cp -R` без `-P` на macOS разыменовывает симлинк во вторую реальную копию молча — копировать через `cp -a`, `git clone` или `git archive`.

## Speaker notes

«Вот итоговый файл — тринадцать строк, не абзац на триста. Критерий готово записан явно: сборка кодом 0, тест зелёный, и форма реально отправляет заявку на проде — то самое требование, которое в начале занятия никто не назвал. Гейт-предупреждение про прод. И честная оговорка предела вместо "Build/Test/Run locally" — эти три строки просто дублировали `package.json`, мы их вычеркнули.

Файл грузится в начало каждой сессии целиком, `@`-импорты его организуют, но не экономят контекст. `AGENTS.md` — симлинк на тот же файл, один источник правды; но осторожно с `cp -R` без `-P` на macOS — он разыменовывает симлинк молча, во вторую реальную копию.»

Мостик к кейсу 1.3: «Мы записали то, что знали заранее и уже один раз проверили на практике — правда, зная, что у текста есть потолок. Файл вырос с нуля до пары содержательных абзацев. Следующий вопрос — практический: репозиторий растёт, появляются подпапки со своими правилами. Стоит ли раскладывать этот же файл по ним?»
