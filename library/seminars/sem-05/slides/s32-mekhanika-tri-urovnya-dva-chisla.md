# Три уровня — и два числа за первый

## Assertion

Три уровня раскрытия официально задокументированы, но у первого уровня — цена метаданных — два разных числа в двух разных документах, и стоит показать оба, а не выбрать одно.

## Visual

| Уровень | Когда грузится | Куда попадает |
|---|---|---|
| 1. Метаданные | всегда, при старте сессии | системный промпт — имя и описание |
| 2. Тело | только после срабатывания | сообщение в истории диалога; повторно не перечитывается |
| 3. Вложения и код | по обращению из тела | файл — целиком при чтении; скрипт — не код, только его вывод |

**Цена уровня 1 — источники расходятся.** Общая спецификация: ≈100 токенов на один скилл, независимо от того, сработает он или нет. Документация Claude Code этого числа не повторяет — описывает бюджет: единый листинг всех скиллов до 1% контекстного окна целиком, а при переполнении — обрезку описаний, начиная с тех скиллов, что реже всего вызывались. Отдельно — жёсткий потолок 1536 символов на одну запись (описание + `when_to_use`).

Прямого подтверждения, что это один и тот же механизм на двух уровнях детализации, не нашлось — честный пробел.

**Иллюстрация, не измерение.** 13 установленных скиллов × ≈100 токенов ≈ 1300 токенов на весь листинг. Бюджет для окна 200 000 токенов ≈ 2000 токенов (1%). При таком масштабе обрезка не наступает.

## Speaker notes

Скилл готов, обе проверки прошли. Следующий вопрос — не «работает ли», а «сколько это стоит, пока скилл не сработал». Три уровня, и они официально описаны — но у первого уровня два разных числа в двух разных документах, и стоит показать оба, а не выбрать одно.

Уровень первый — имя и описание, всегда в системном промпте, для любого установленного скилла, сработал он в этой сессии или нет. Уровень второй — тело файла, попадает в переписку только после того, как модель решила, что описание совпало с запросом, и больше не перечитывается на следующих ходах. Уровень третий — вложенные файлы и скрипты, по обращению из тела; и здесь тонкость: код скрипта в контекст не попадает вообще, даже когда скрипт реально исполняется, — исполняется он через bash, а в контекст возвращается только то, что он напечатал.

Теперь про цену первого уровня. Общая спецификация Agent Skills называет число: около ста токенов на один скилл. Документация Claude Code это число не повторяет — она описывает бюджет: весь список имён и описаний размером до одного процента контекстного окна целиком, а при переполнении — обрезку отдельных описаний, начиная с тех скиллов, что реже всего вызывались. Отдельно от бюджета — жёсткий потолок на одну запись, тысяча пятьсот тридцать шесть символов, описание вместе с полем `when_to_use`.

Прямого подтверждения, что это одно и то же правило на двух уровнях детализации, найти не удалось — это честно оставлено как пробел, не сглажено до одной цифры. Для практики разница невелика: оба источника согласны, что дёшево, пока скилл не выбран, а второй точнее говорит, кого урезают первым — те скиллы, что ещё ни разу не сработали. Иллюстрация, не измерение: тринадцать установленных скиллов, по первой оценке, — около тысячи трёхсот токенов на весь список при старте любой сессии; бюджет по второй оценке для окна в двести тысяч — около двух тысяч. При таком масштабе обрезка не наступает.
