# ЗАГЛУШКА: проверка таблицы в три колонки

## Assertion

Проверка приёма `answer_breakdown_table` на таблице в три колонки — рабочей форме разбора карточек, которая на настоящей деке повторяется минимум на шести слайдах.

## Visual

| Решение | Где оно работает — конкретные случаи | Ограничения |
|---|---|---|
| заглушка-решение один — это не содержание занятия, а проверка ширины первой колонки на тексте среднего объёма | заглушка показывает, как ведёт себя колонка при тексте в одну-две строки: граница между короткой и длинной записью видна по переносу слов, а не по выдумыванию кейса | ограничение заглушки: она не измеряет вёрстку реальной формулировки, только проверяет, что столбец шириной около трети слайда не схлопывается в единый символ на строку |
| заглушка-решение два — вторая строка держит тот же объём текста, чтобы проверить, что высота строки считается по самой длинной ячейке строки, а не по первой колонке | вторая колонка второй строки умышленно короче первой колонки, чтобы проверить, что короткая ячейка не тянет высоту вниз за собой — высота строки задаётся максимумом по всем трём ячейкам одной строки | — |
| заглушка-решение три — третья строка проверяет сжатие кегля на максимально длинной ячейке среди всех трёх строк таблицы, нарочно набранной с запасом по знакам | третья колонка короче, чтобы проверить несимметричное распределение длины текста между тремя ячейками одной строки — ровно тот случай, который ломает наивный расчёт высоты по одной ячейке | ограничение: заглушка не проверяет жирную строку-целевой ответ (правило «вся строка жирным — золотая подсветка») — это отдельная, не связанная с шириной колонок проверка |

## Speaker notes

Это техническая заметка смоук-слайда, а не речь лектора. Слайд проверяет приём `answer_breakdown_table` на таблице в три колонки — ровно ту форму, в которой на настоящей деке разбираются ответы на вопрос занятия минимум на шести слайдах (например, разбор пяти решений кейса MCP или разбор границы между ролью субагента и координатором). Три строки заглушки набраны заведомо неравномерно по длине ячеек внутри строки и между строками, чтобы проверить два разных механизма верстки одновременно: во-первых, что высота строки таблицы считается по самой длинной ячейке именно этой строки, а не усредняется и не берётся по первой колонке; во-вторых, что при недостатке места включается лестница подгонки кегля, а не молчаливое переполнение за рамку. Задача по заданию — проверить, что таблица такого устройства при ширине слайда около 1024 точек не переполняется и не обрезает текст, и ровно это здесь проверяется на синтетическом, заведомо избыточном по объёму тексте.
