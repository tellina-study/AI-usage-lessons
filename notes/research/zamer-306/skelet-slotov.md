# Скелет слотов — запись, которую понимает настоящая сборка (issue #306)

Для каждого из пяти кадров — скелет файла кадра в формате, который читает
`tools/presentation-build/deckkit/slidefile.py` (frontmatter YAML + тело).
Поля `blocks:` / `scheme:` / `columns:` / `figure:` — закрытые контракты
ядра (`plates.py` / `scheme.py` / `axis.py` / `columns.py` / `figure.py`).
Любой ключ вне перечня, который ядро читает, называется предупреждением
`[схема]`/`[плашки]`/`[столбцы]`/`[число]`/`[ось]` и не рисуется молча.

**Бюджеты знаков** выведены прогоном через настоящую меру текста
(`deckkit.metrics`) для геометрии лекции 7 (`MX=0.55"`, `FULL_W=12,233"`,
палитра `Liberation Sans`). Методика — ниже после всех пяти скелетов.
Заполнитель может уложиться туже бюджета; превышение бюджета — это
превышение того предела, на котором форма либо откажет своим тегом
(явный числовой предел в коде), либо подберёт кегль мельче того, что
заложено в бюджет (мягкий предел, посчитанный на ХУДШЕМ по вместимости
кегле формы).

## кадр-1 — полоса плашек (`blocks:`)

```yaml
blocks:
  - {label: "<ПОДПИСЬ-1, обязательна>", value: "<ЗНАЧЕНИЕ-1, обязательно>", note: "<ОГОВОРКА-1, необязательна>"}
  - {label: "<ПОДПИСЬ-2>", value: "<ЗНАЧЕНИЕ-2>", note: "<ОГОВОРКА-2>", key: true}   # ключевая плашка — ОДНА на кадр
  - {label: "<ПОДПИСЬ-3>", value: "<ЗНАЧЕНИЕ-3>", note: "<ОГОВОРКА-3>"}
  - {label: "<ПОДПИСЬ-4>", value: "<ЗНАЧЕНИЕ-4>", note: "<ОГОВОРКА-4>"}
```

Не больше 4 плашек в ряд (пятая уходит во второй ряд ценой высоты тела).
`key: true` — ровно на той плашке, чьё число названо в задании как
главное; без явного `key` золото достаётся последней плашке с цифрой.

Бюджет на СЛОТ (один из четырёх):
- `label` — ≤ 55 знаков (капитель, 2 строки, 12 пт, ширина плашки в ряду из 4 ≈ 2,62")
- `value` — ≤ 48 знаков, если это число (2 строки на нижнем из подбираемых кеглей, 13 пт); ≤ 72 знаков, если это словесная величина (3 строки)
- `note` — ≤ 85 знаков (3 строки, 12 пт курсивом)

## кадр-2 — ось с засечками (`scheme: kind: shkala`)

```yaml
scheme:
  kind: shkala
  unit: "<ЕДИНИЦА ОДНА НА ВСЮ ОСЬ, обязательна>"
  caption: "<ПОДПИСЬ ПОД ОСЬЮ, необязательна>"
  marks:
    - {value: <ЧИСЛО-1>, label: "<ПОДПИСЬ-1>"}
    - {value: <ЧИСЛО-2>, label: "<ПОДПИСЬ-2>"}
    - {value: <ЧИСЛО-3>, label: "<ПОДПИСЬ-3>", key: true}
```

От 2 до 5 засечек; у каждой засечки — ОДНА и та же единица и одна база
(разные базы форма отвергает тегом `[ось]`). `key: true` — на засечке,
названной в задании ключевой.

Бюджет на СЛОТ:
- `label` засечки — ≤ 48 знаков при 3 засечках на оси (одна строка, 12 пт, дорожка подписи делит ширину кадра на число засечек: 4,08" при трёх), ≤ 37 при четырёх, ≤ 29 при пяти
- `unit` (+ `base`, если есть) — ≤ 134 знаков (одна строка, 12 пт полужирным, во всю ширину кадра)
- `caption` — ≤ 145 знаков (одна строка, 12 пт курсивом, во всю ширину)

## кадр-3 — два столбца (`columns:`)

```yaml
columns:
  left:  {head: "<ЗАГОЛОВОК ЛЕВОГО СТОЛБЦА>", items: ["<ПУНКТ-1>", "<ПУНКТ-2>", "<ПУНКТ-3>", "<ПУНКТ-4>"]}
  right: {head: "<ЗАГОЛОВОК ПРАВОГО СТОЛБЦА>", items: ["<ПУНКТ-1>", "<ПУНКТ-2>", "<ПУНКТ-3>", "<ПУНКТ-4>"]}
```

Число пунктов в обоих столбцах ОБЯЗАНО совпадать — столбцы читаются
построчными парами (сторож `[пары]`). Кадр нужен типу `comparison`.

Бюджет на СЛОТ (столбец занимает половину ширины кадра за вычетом
просвета — 5,95" ширины, 5,59" внутри):
- `head` — ≤ 97 знаков (2 строки, 14 пт полужирным)
- один пункт `items` — ориентир ≤ 110 знаков (при 4 пунктах в столбце: предел высоты столбца 3,40", пол кегля перечня 9 пт, 15 строк на весь столбец / 4 пункта ≈ 3-4 строки на пункт на нижнем кегле; выше нижнего кегля бюджет меньше строк, но шире кегль — здесь взят НИЖНИЙ кегль как безопасная оценка, см. методику)

## кадр-4 — схема рядами (`scheme:`, без `kind`)

```yaml
scheme:
  caption: "<ПОДПИСЬ ПОД СХЕМОЙ, необязательна>"
  arrows: true          # явно: есть порядок (стрелки)
  rows:
    - label: "<ПОДПИСЬ РЯДА-1, необязательна>"
      steps: ["<ШАГ-1>", "<ШАГ-2>", "<ШАГ-3>", "<ШАГ-4>"]
    - label: "<ПОДПИСЬ РЯДА-2>"
      steps: ["<ШАГ-5>", "<ШАГ-6>", "<ШАГ-7>"]
      arrows: <true|false — ЯВНО, своё для этого ряда>
```

Не больше 4 шагов в ряду, не больше 3 рядов. `arrows` — ОБЯЗАН быть
объявлен явно на каждом ряду, где порядок — не то же самое, что в
соседнем ряду: стрелка утверждает «сначала одно, потом другое», и по
умолчанию (без явного ключа) сборка это ТОЛЬКО называет предупреждением,
не решает сама.

Бюджет на СЛОТ:
- один `step` в ряду из 4 (со стрелками) — ≤ 81 знака (3 строки, нижний кегль 12 пт, бокс ≈ 2,44" внутренней ширины)
- один `step` в ряду из 3 (с подписью ряда) — ≤ 84 знаков (3 строки, 12 пт, бокс ≈ шире на подпись слева)
- `label` ряда — ориентир ≤ 33 знаков (2 строки, 12 пт, колонка подписи 1,70")
- `caption` — ≤ 145 знаков (1 строка, 12 пт курсивом, во всю ширину) либо ≤ 285 (2 строки)

## кадр-5 — кадр одного числа (`figure:`)

```yaml
figure:
  value: "<ВЕЛИЧИНА, обязательна>"
  unit:  "<ЧТО ЭТО ЗА ВЕЛИЧИНА, необязательна>"
  base:  "<БАЗА, обязательна по смыслу — без базы `[число]` откажет>"
  note:  "<ОГОВОРКА, необязательна>"
```

Бюджет на СЛОТ:
- `value` — ЖЁСТКИЙ предел кода: ≤ 16 знаков (`figure.FigureStyle.max_val_chars`); длиннее — это уже не число, а фраза, форма откажет тегом `[число]`
- `unit` — ориентир ≤ 202 знака (2 строки, 16 пт, во всю ширину кадра минус поля)
- `base` — ориентир ≤ 233 знака (2 строки, 14 пт); база ОБЯЗАНА содержать вторую величину либо слово сравнения («против», «из», «от», «без», «вместо» …) — иначе форма откажет: это не поле, а содержание
- `note` — ориентир ≤ 250 знаков (2 строки, 12 пт курсивом)

## Методика вывода бюджетов (не придумано — прогон)

Все числа получены прогоном `deckkit.metrics.n_lines` / `text_w` по
настоящим файлам шрифта (`Liberation Sans`, то же начертание, которым
дека набирается) на геометрии лекции 7 (`FULL_W = 13,333" − 2×0,55" =
12,233"`). Для каждого слота:

1. Взята ширина, которую форма реально отводит слоту (`plates._plate_rows`,
   `scheme._step_iw`, `columns.draw_columns`, `axis.lane_w`, `figure._iw`)
   — те же формулы, которыми меряется высота (`*_h`) и рисуется слот.
2. Взят ХУДШИЙ (самый мелкий из допустимых) кегль слота — там, где кегль
   подбирается в диапазоне (плашка, схема, столбец): нижняя граница
   диапазона. Нижний кегль даёт МЕНЬШЕ знаков в строке, но ДОПУСКАЕТ
   больше строк до жёсткого предела — поэтому он даёт безопасную (не
   оптимистичную) оценку количества знаков, которое форма гарантированно
   не завалит.
3. Взят жёсткий предел строк слота (`value_rows_digit`/`value_rows_word`
   у плашки, `step_rows` у схемы, `note_rows` у плашки; у слотов без
   жёсткого предела строк — 1-2 строки practического ориентира, явно
   помечено словом «ориентир», не «предел»).
4. Строка-кандидат растится словами реального русского текста (не
   повторением одной буквы: на кириллице это завышает бюджет — буквы
   разной ширины) до тех пор, пока `n_lines(кандидат, кегль, ширина)`
   не превышает предел строк; длина последнего влезшего кандидата — и
   есть бюджет.

Там, где в коде стоит ЯВНОЕ числовое ограничение («не больше 16 знаков»
у `figure.value`, «не больше 4 шагов в ряду», «не больше 5 засечек»,
«не больше 4 плашек в ряд», «не больше 3 рядов схемы») — это ЖЁСТКИЙ
предел формы, нарушение — гарантированный отказ тегом. Бюджеты знаков на
текстовые слоты — МЯГКИЙ предел: превышение не обязательно даёт отказ
(кегль может подобраться мельче), но мельчайший допустимый кегль формы —
это уже дно, годное к сравнению «уложился / не уложился».
