# Поднять n8n у себя

Два адресата: **ведущий** — чтобы показать живой холст на занятии, и **студент** — чтобы
прогнать дома файл сценария, который выдали на занятии.

## Чего ожидать по времени и месту

- Установка — 10–20 минут, в основном скачивание.
- Около 1 ГБ на диске.
- Интернет нужен на установку и на вызовы модели; сам n8n работает локально.

## Вариант 1 — Docker (рекомендуемый самим n8n)

Если на машине есть Docker с плагином `docker compose` версии 2:

```
curl -fsSL https://get.n8n.io | sh
```

Скрипт создаёт папку `n8n`, пишет `compose.yml` и `.env` с уникальными секретами,
скачивает образ и запускает. Повторный запуск безопасен.

## Вариант 2 — npm, без Docker

**Нужен Node.js версии 24 или новее.** Это не опечатка и не перестраховка: страница
документации n8n всё ещё пишет «20.19–24», но в самом пакете `n8n@2.42.6` стоит
`engines: {"node": ">=24.0.0"}`. На Node 20 установка выдаёт предупреждение и дальше
может не запуститься.

```
node --version          # должно быть v24 или выше
npm install -g n8n
n8n
```

Открыть `http://localhost:5678`.

**Предупреждение на будущее:** установка через npm объявлена устаревшей начиная с n8n 3.0,
и 3.0 вообще не публикует запускаемый пакет в npm. Пока актуальна ветка 2.x, способ
работает; как выйдет 3.0 — только Docker.

## Первый запуск

1. Открывается `http://localhost:5678`.
2. n8n просит завести учётную запись владельца инстанса. Это локальная учётка, наружу
   ничего не уходит.
3. Дальше — пустой список сценариев.

Лицензионный ключ не нужен. Без него работает **Community edition** — бессрочно и
бесплатно. Если ввести почту в **Settings → Usage and plan → Unlock**, бесплатно
добавятся папки и **отладчик (Debug in editor)** — для разбора прошедших прогонов удобно,
но для занятия не обязательно.

## Импорт файла сценария

Файлы занятий лежат в репозитории курса, по одному на занятие.

- **Workflow menu → Import from File** — выбрать `.json`.
- Либо открыть файл текстом, скопировать всё, и вставить на пустой холст (`Ctrl/Cmd + V`).

**Учётные данные в файле не передаются** — это защита, а не недоработка. После импорта
узлы, которым нужен ключ (модель, почта), будут помечены; ключ вписывается свой.

## Что понадобится для вызовов модели

Один из двух путей:

- **Ключ стороннего провайдера** (OpenAI, Anthropic и прочие) — вписывается в учётные
  данные соответствующего узла.
- **Локальная модель через Ollama** — ключ не нужен вовсе, в учётных данных указывается
  только адрес инстанса. Если n8n и Ollama в разных контейнерах, адрес —
  `http://host.docker.internal:11434` (Linux требует флага `--add-host`); если обе
  программы на хосте — `http://localhost:11434`. При ошибке `ECONNREFUSED ::1:11434`
  заменить `localhost` на `127.0.0.1`: включён IPv6, а Ollama слушает IPv4.

## Если показываете на занятии

- Поднимать **на петле** (`localhost`), наружу не открывать. На машине с публичным
  адресом открытый n8n без HTTPS — это открытый n8n в интернете.
- Прогон показывать **ручным запуском**: расписание на занятии ждать нечего.
- Держать в уме: **ручной прогон потребляет больше памяти**, чем автоматический, потому
  что n8n копирует данные для отображения в интерфейсе.
- Сценарий автосохраняется в черновик постоянно. В продакшен он уходит отдельным
  действием **Publish**. Продакшен-исполнения идут по опубликованной версии, а не по тому,
  что сейчас на экране. Слова «активировать» в n8n 2.x больше нет.

## Перед тем как отдать студентам свой файл

Прочитать его глазами. Секреты учётных данных не экспортируются, но **имена и
идентификаторы остаются**, а узлы HTTP Request, собранные импортом из cURL, могут
содержать заголовки аутентификации прямо в параметрах узла.
