# Skill vs always-on инструкция vs ссылочный файл vs slash-команда vs hook vs MCP — вердикт для владельца курса

**Date:** 2026-10-02 · **Access date:** 2026-10-02 · **Issue:** #217

> Разметка типа доказательства обязательна везде: **ИЗМЕРЕНО** / **документация вендора** /
> **vendor-утверждение об эффекте** / **народная практика**. Первоисточники — `01-mechanics.md`,
> `02-empirics-instruction-following.md`, `03-failures-and-security.md`, `sources.md`,
> собственный мини-эксперимент — `04-own-experiment.md`.

---

## 1. Ответ одной фразой

Текст процедуры, положенный в Skill, в always-on-файл (всегда активный инструктивный файл,
загружаемый целиком каждую сессию) или в ссылочный файл «читай по требованию» — **один и тот же
текст**; разница не в тексте, а в трёх независимых свойствах механизма его доставки: **когда** он
физически попадает в контекст модели (всегда при старте / по срабатыванию / только если модель
сама решит прочитать), **кто принимает решение о его применении** (модель — вероятностно; человек —
явной командой; код харнесса — детерминированно всегда) и **что платится постоянно**, в каждом
запросе сессии, независимо от того, применилась ли инструкция. Выбор формы — это выбор точки
отказа и цены, не выбор формулировки.

## 2. Механика разницы — три оси по каждому способу

(Источник раздела — `01-mechanics.md`; номера параграфов указаны инлайн.)

### 2.1 Когда контент попадает в контекст

| Способ | Когда |
|---|---|
| Skill (метаданные) | Всегда, при старте сессии — но это только `name`+`description`, не тело (§1.2) |
| Skill (тело) | По срабатыванию — модель сама вызывает чтение `SKILL.md`, когда решит, что skill релевантен (§1.2-1.3) |
| always-on `CLAUDE.md`/`AGENTS.md` | Всегда, целиком, при старте сессии — для файлов выше рабочей директории; в поддиректориях — по факту обращения к файлу (§2.1-2.2) |
| `@path`-импорт | Всегда — код харнесса разворачивает его при старте, синхронно с файлом-источником (§2.4, §3) |
| Ссылочный файл прозой («читай X») | Только если модель сама решит вызвать инструмент чтения — нет структурной точки принятия решения (§3) |
| Slash-команда | Никогда автоматически — только по явному вводу `/name` человеком (§4.2) |
| Hook | Код хука — никогда «в контексте» (внешний процесс); его stdout — только для подмножества событий (§5.3) |
| MCP-инструмент (без tool search, механизма отложенного поиска схем инструментов) | Полная схема — всегда, каждый инструмент каждого сервера (§6.2) |
| MCP-инструмент (tool search) | Имя + server instructions — всегда; полная схема — по запросу модели (§6.3) |
| Субагент | Своё изолированное окно; в основной контекст — только финальная сводка (§7) |

### 2.2 Кто решает применить

- **Модель, вероятностно** — Skill (сопоставление `description` с запросом, §1.3), ссылочный файл
  прозой (решение вызвать инструмент чтения, §3), MCP-инструмент (вызвать ли конкретный, §6.1).
- **Человек, явной командой** — slash-команда (§4.2); Skill с `disable-model-invocation: true`
  переходит в этот же режим (§1.3).
- **Код харнесса, детерминированно, всегда** — hook при совпадении событие+matcher (§5.2);
  `@path`-импорт при старте сессии (§2.4). Это единственная строка таблицы, где применение не
  зависит от того, что «решит» модель — сам вендор формулирует это разграничение явно: «To block
  an action regardless of what Claude decides, use a PreToolUse hook instead» (§2.3, документация
  вендора).
- **Никто — грузится безусловно** — always-on CLAUDE.md/AGENTS.md целиком; но это не то же самое,
  что «гарантия применения»: файл присутствует безусловно, а вот последует ли модель написанному —
  решает модель (§2.3).

### 2.3 Что платится постоянно

Ключевые опоры механики: тело Skill **не** в контексте, пока не сработал, — в этом его экономика
(§1.2, документация вендора); `@path`-импорт **не снижает** стоимость токенов — документация прямо
пишет: «Imports help you organize a long file but don't reduce its context cost, because imported
files also load at launch» (§2.4, документация вендора) — то есть это организационный приём, не
механизм отложенной загрузки; always-on файл — 100% текста на каждый запрос всей сессии, без
вариантов (§2.2); slash-команда (старый формат) — 0 токенов, пока не вызвана (§4.4); hook — 0
токенов, если не возвращает вывод (§5.4); MCP-инструмент без tool search — полная схема на каждый
запрос, растёт линейно с числом серверов (§6.2); с tool search — имя+server instructions в покое,
цена подгрузки схемы — только при реальном поиске (§6.3).

## 3. Что об этом ИЗМЕРЕНО, а что нет

(Источник — `02-empirics-instruction-following.md`.)

**Главный честный результат: прямого контролируемого сравнения «Skill vs always-on vs ссылочный
файл» на одной и той же задаче в опубликованной литературе НЕ НАЙДЕНО.** Это не методическая
небрежность поиска — область эмпирически не покрыта (02-empirics §0, §2.1). Собственный
мини-эксперимент (`04-own-experiment.md`) частично закрывает именно этот пробел — с жёсткими
оговорками по размеру выборки (см. §8 там).

Что измерено по соседним вопросам:

- **Gloaguen et al., arXiv:2602.11988 (ETH Zürich)** — наличие AGENTS.md/CLAUDE.md само по себе в
  среднем **не улучшает** success rate на SWE-задачах; LLM-сгенерированные файлы дают −0,5%
  (SWE-bench Lite) и −2% (AGENTbench) к success rate; developer-written дают +4% в среднем; рост
  стоимости инференса на 20–23% (число шагов +2,45…+3,92). **ИЗМЕРЕНО**, confidence H.
- **McMillan, arXiv:2605.10039** — ни один из 4 структурных параметров CLAUDE.md (размер 25–500
  строк, позиция инструкции, архитектура, наличие конфликтующего файла) не дал детектируемого
  эффекта на соблюдение простой конвенции (affirmative null, Bayes factor 0,05–0,10 для
  size/conflict). Но **внутри одной сессии** каждая следующая функция снижает шанс соблюдения на
  ~5,6% (OR≈0,944/шаг) — затухание по ходу работы агента, не по структуре файла. **ИЗМЕРЕНО**,
  confidence M.
- **SEQUOR/Laban (arXiv:2605.06353, arXiv:2505.06120)** — деградация соблюдения правил в
  многоходовом диалоге: >11% просадка к 50-му ходу при одном правиле, >38% при нескольких
  одновременных, >40–63% при последовательно добавляемых; независимо — средняя просадка качества
  39% при переходе с одного хода на диалог из многих. **ИЗМЕРЕНО**, confidence H, два независимых
  домена сходятся в одном направлении.
- **IFScale, arXiv:2507.11538** — лучшие фронтир-модели 2025 г. достигают ~68% точности при 500
  одновременных инструкциях в одном промпте; primacy-bias (ранние инструкции выполняются лучше) с
  пиком смещения ~150–200 инструкций. **ИЗМЕРЕНО**, confidence H.
- **«Lost in the Middle», arXiv:2307.03172** и **Chroma «Context Rot»** — измеряют **поиск факта по
  позиции в контексте**, НЕ соблюдение процедуры. Перенос «правило посреди файла не сработает» на
  инструкции — **экстраполяция**, не измеренный факт (02-empirics §2.3, §3 последняя строка). Это
  главная ловушка темы — не цитировать как прямое доказательство для процедурных правил.
- **SkillsBench, arXiv:2602.12670** — curated (отобранные) Agent Skills поднимают pass rate с
  33,9% до 50,5% (**+16,6 п.п.**, база — 18 конфигураций модель×харнесс, 87 задач/8 доменов).
  **ИЗМЕРЕНО**, confidence H, независимо.
- **SWE-Skills-Bench, arXiv:2603.15401** — на 49 реальных публичных skills «как есть» (не
  курированных) — у **39 из 49 (≈80%)** эффект нулевой; средний прирост +1,2%; расход токенов — до
  **+451%** при неизменном pass rate; у 7 — выигрыш до +30%, у 3 — проигрыш до −10%. **ИЗМЕРЕНО**,
  confidence H, независимо, скептический дизайн. Расхождение с SkillsBench — не противоречие:
  разница между «куратор подобрал skill под задачу» и «случайный skill из каталога».
- **Собственный мини-эксперимент (`04-own-experiment.md`)** — при явном упоминании процедуры в
  задаче все 4 способа подачи дали потолок 5/5 (различие только в цене: раздутый файл +31,8…+35,5%
  токенов к минимальному указателю при идентичном результате); без упоминания — ссылочный файл дал
  0/5 на обеих независимых темах (молчаливое, бинарное несрабатывание), остальные три — 5/5.
  **ИЗМЕРЕНО** (собственный мини-эксперимент, n=2 на плечо, одна модель — см. жёсткие ограничения в
  исходном файле).

## 5. Критерий выбора одной строкой

**Операционное правило — через цену пропуска** (что происходит, если процедура молча не
применится): если молчаливый пропуск недопустим — хук (код) или явный человеческий вызов, а НЕ
документ; если процедура ситуативная — skill; если это короткий инвариант, окрашивающий каждое
решение, — короткий always-on; если это длинный справочник, нужный редко — ссылочный файл, но
только с указателем из always-on-слоя и никогда как единственная гарантия.

**Чек-лист (4–6 вопросов) перед тем, как оформить процедуру:**

1. Если эту процедуру молча пропустят — это допустимо, или это сломает что-то важное? → Если
   недопустимо: хук или явный вызов человеком. Документ любого вида — не вариант.
2. Нужна она в БОЛЬШИНСТВЕ задач сессии, или в узком, ситуативном подмножестве? → Большинство —
   always-on (коротко). Подмножество — Skill или ссылочный файл, не always-on.
3. Задача, где она нужна, САМА называет процедуру явно («оформи по конвенции X»), или должна
   сработать по смыслу без упоминания? → Называет явно — ссылочный файл годится (в собственном
   эксперименте сработал 5/5). Не называет — нужен Skill (вероятностный, но с точкой решения в
   контексте) или always-on, не ссылочный файл (в эксперименте — 0/5 без упоминания).
4. Это процедура/знание («как делать»), или возможность действовать на внешнюю систему
   («что можно сделать»)? → Знание — Skill/CLAUDE.md. Возможность — MCP-инструмент.
5. Источник артефакта (skill, hook, MCP-сервер) — я сам, Anthropic напрямую, или внешний
   маркетплейс/чужой репозиторий? → Внешний источник + сильная гарантия исполнения (особенно hook)
   — построчный аудит обязателен ПЕРЕД подключением (см. §7).
6. Задача выполняется оркестратором напрямую, или делегируется субагенту? → Делегируется —
   не полагаться на auto-invocation skill внутри субагента; называть skill явно текстом промпта.

## 6. Что из популярных советов данными НЕ подтверждается

| Популярный совет | Что ИМЕННО известно | Чего не хватает |
|---|---|---|
| «Skill надёжнее, чем раздел в CLAUDE.md» | Прямого измерения «Skill vs always-on на одной процедуре» нет (02-empirics §2.1). Есть Skills vs БЕЗ Skills (SkillsBench +16,6 п.п. на curated; SWE-Skills-Bench — 39/49 публичных нулевой эффект) и структура-CLAUDE.md vs структура-CLAUDE.md (McMillan — null). Между механизмами сравнения нет | Контролируемый эксперимент «тот же текст, Skill vs always-on vs ссылочный файл», на серьёзной выборке и не одной модели |
| «Короче CLAUDE.md — лучше соблюдается» | Vendor-утверждение об эффекте: «Bloated CLAUDE.md files cause Claude to ignore your actual instructions» (документация вендора, качественно). McMillan — размер файла 25–500 строк эффекта на простую конвенцию НЕ дал (affirmative null, M). Для Skills — SkillsBench: компактные (≤3 модуля) обгоняют большие бандлы | Числовая кривая «строк → % соблюдения» для процедурных (не тривиальных) правил не найдена ни у вендора, ни в академических работах |
| «Агент прочитает файл, если попросить» | В собственном эксперименте — 0/2 (B на E2 и E3) без прямого напоминания в задаче; 2/2 при напоминании. Формального измерения вероятности «пропуска» в литературе нет (02-empirics, 03-failures §2.2) | Контролируемая оценка частоты несрабатывания на большей выборке/моделях; наш n=2 — направление, не частота |
| «Положи правило в начало файла» | IFScale — primacy-bias ПОДТВЕРЖДЁН, но ТОЛЬКО среди множества ОДНОВРЕМЕННЫХ инструкций в одном промпте (пик смещения ~150–200), не про позицию правила в структуре отдельного файла по ходу диалога | Путается с «Lost in the Middle» (поиск факта по позиции) — это другой предмет измерения, не перенос без оговорок |
| «Системный промпт всегда приоритетнее пользовательского» | ИЗМЕРЕНО — ОПРОВЕРГНУТО для немодифицированных моделей: Mu et al. (arXiv:2502.12197) — системные guardrails часто проигрывают прямому конфликту с сообщением пользователя (качественно подтверждено; точные % по моделям не подтверждены первичным текстом, не цитировать). OpenAI Instruction Hierarchy — специальный fine-tuning именно ПРОТИВ этой проблемы, что косвенно подтверждает её серьёзность для необученных моделей | Независимая репликация с полными числами по моделям; найденные конкретные проценты (17–32%, Qwen2.5-Coder 60%/2%/0%) — unverifiable, использовать нельзя |
| «Больше навыков/инструментов — лучше» | ИЗМЕРЕНО — ОПРОВЕРГНУТО: SWE-Skills-Bench — токены растут до +451% без выигрыша в pass rate на 39/49 публичных skills; RAG-MCP — точность выбора инструмента падает с 43,13% до 13,62% (база — рост каталога тулз без retrieval-слоя); фокусный набор 4 тулз даёт ~95% верного выбора против ~71% на 46 тулзах (разница 24 п.п.) | Порог «30–50 инструментов, после которого падает точность», приписываемый внутреннему гайду Anthropic — не найден в первичном документе, только во вторичных блогах (`[VFY-day-of]`) |

## 7. Безопасность как часть выбора

(Источник — `03-failures-and-security.md`.)

Каждый подгружаемый артефакт — поверхность атаки, и это касается не только MCP:

- **arXiv:2601.10338** — эмпирическое исследование **31 132** уникальных Agent Skills (после
  фильтрации качества, из 42 447 изначально собранных с двух маркетплейсов): **26,1%** содержат
  хотя бы один из 14 паттернов уязвимости по 4 категориям; **5,2%** показывают паттерны,
  указывающие на умышленную злонамеренность, а не небрежность автора. **security-research**,
  эмпирическое измерение на выборке.
- **Rules File Backdoor (Pillar Security, 2025)** — скрытые Unicode-символы в файлах конвенций
  (`.cursor/rules`, аналог CLAUDE.md/AGENTS.md по классу файла), невидимые человеку-рецензенту,
  читаемые моделью; PoC — молчаливое внедрение внешнего `<script>`-тега при безобидном запросе.
  CVE не присвоен — оба вендора назвали это проблемой конфигурации пользователя. **документированный
  инцидент**.
- **CVE-2025-59536 (CVSS 8,7)** — злонамеренный `.claude/settings.json` в клонированном
  репозитории регистрирует hook на `SessionStart`; команда исполняется **до того, как отрисовался
  диалог доверия/апрува**, с правами локального пользователя. **документированный инцидент (CVE,
  патч выпущен)**.

**Парадокс, который нужно проговорить явно:** гарантия исполнения hook — заявленное главное
преимущество этого механизма (§2.2 — «код исполняет, модель не уговаривают») — работает **и на
атакующего**: детерминизм не различает «доверенный автор репозитория» и «атакующий, подсунувший
settings.json» — оба исполняются одинаково надёжно. Это прямое следствие той же механики, что
делает hook привлекательным для guardrails.

**Правило:** чем сильнее гарантия исполнения артефакта (hook > `@import`/slash-команда > Skill с
исполняемым кодом > просто текст always-on), тем строже должно быть доверие к источнику этого
артефакта перед подключением. Источник «я сам» или «Anthropic напрямую» — вендор явно
рекомендует именно это как границу доверия («Use Skills only from trusted sources: those you
created yourself or obtained from Anthropic», документация вендора). Любой внешний
маркетплейс/форк/клонированный репозиторий, несущий конфигурацию с сильной гарантией исполнения —
требует построчного аудита (включая проверку на скрытый Unicode) перед первым запуском, не после.
