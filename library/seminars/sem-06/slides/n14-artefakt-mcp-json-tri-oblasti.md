# Собранный файл: что значит каждая строка

## Assertion

Итог разговора — файл из четырёх строк существа: имя сервера, чем он запускается, что запускается, откуда берётся ключ. Вне файла, но не менее важно — какие права у этого ключа: один репозиторий, не вся учётная запись.

## Visual

```json
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": {
        "GITHUB_PERSONAL_ACCESS_TOKEN": "${GITHUB_PAT}"
      }
    }
  }
}
```

`mcpServers` — корень: список всех серверов, объявленных в этой области.
`"github"` — имя сервера; под этим именем агент будет называть его инструменты: `mcp__github__…`.
`"command": "npx"` — чем запускается сервер.
`"args"` — что именно запускается: конкретный пакет сервера.
`"env"` — переменные окружения для запущенного процесса; значение — подстановка `${GITHUB_PAT}`, не сам секрет текстом.

> Это полная версия шаблона, который на одностраничнике (n08) был показан фрагментом. Права токена — один репозиторий, не вся учётная запись — собраны на предыдущем экране и в файл не входят: их задаёт сервис, где создан токен, не эта конфигурация.

## Speaker notes

Итог разговора — файл из четырёх строк существа. Разберём каждую.

`mcpServers` — корень: список всех серверов, которые объявлены в этой области видимости. `"github"` — имя сервера: именно под этим именем агент дальше будет вызывать его инструменты, вида `mcp__github__…`. `"command": "npx"` — чем запускается: конкретная программа-лаунчер. `"args"` — что запускается: пакет самого сервера. И `"env"` — переменные окружения для процесса: значение здесь — подстановка `${GITHUB_PAT}`, сам секрет в файле не лежит текстом.

Это полная версия того же шаблона, который уже мелькал фрагментом на одностраничнике в начале кейса — там он был первым знакомством, здесь — разбор построчно. Права этого ключа — один репозиторий, не вся учётная запись — в файл не входят вообще: их задаёт сервис, где токен создавался, не эта конфигурация.

Эта практика остаётся целевым решением раздела, не подтверждённым коммитом ни в этом проекте, ни в репозитории курса — слайд показывает разбираемый пример, не обещает «склонируй и повтори».

Честное предложение в сторону: эта команда запускает на вашей машине живой процесс. Если он упадёт посреди сессии — сам он не перезапустится, нужна новая сессия. Полный разбор, что при этом видно и как это заметить, — в следующем кейсе этого занятия.

Если спросят про сам файл подробнее: он лежит в корне репозитория, видят его все, кто клонирует проект; личная и общая личная области живут в отдельном файле вне репозитория, туда секреты из кода не попадают просто потому, что файл физически не в дереве git.

Если спросят про схему приоритета ниже: ступени `local` и `user` обе подписаны файлом `~/.claude.json` — это не два одинаковых адреса и не ошибка на экране. Это один физический файл, но две разные записи внутри него: `local` — под записью именно этого проекта, `user` — под общим ключом `mcpServers`. При конфликте имён это разные по весу записи, несмотря на общий файл.

Если спросят, что будет, если изменить область уже подключённого сервера: это та же запись, просто переписанная в другое место — сами права токена при этом не меняются, их меняют на стороне сервиса, где токен создавался.

Если спросят, почему именно этот список из трёх областей, а не произвольные: это ровно то, что физически умеет продукт — три жёстко заданных места, не произвольная настройка.

Если спросят про честный пробел ещё раз: этот конкретный файл — целевое решение, собранное из более раннего захвата демо-репозитория; в текущей ветке его нет, и тот же файл отсутствует в репозитории курса. Проверка этого кейса — на доказательной базе исследования, не на живом коммите; это касается и двух следующих кейсов этого блока — у них общий этот пробел.
