## Фазы (последовательно, каждая — отдельный gate)

### Фаза 1. Single source of truth в репо

**Цель:** иметь один YAML, из которого выводятся оба Google Doc'а в будущем (skill `update-formal-doc` потом).

**Артефакты:**
- `catalog/manifests/course.yaml` — модули (3 шт.) + лекции (17) + семинары (17) + LO + competencies (ПКС-4/5/11) + часы.
- `catalog/manifests/lectures.yaml` — расширить с 1 до 17 записей (синк с course.yaml).
- `catalog/manifests/seminars.yaml` — новый, 17 записей.
- `templates/seminar-outline.md` — шаблон семинара (по аналогии с lecture-outline).
- `templates/module-card.md` — шаблон модуля.
- Онтология (`ontology/schema.ttl`): добавить класс `Module`, связь `belongs_to_module` (Lecture, Seminar → Module).
- Обновить `wiki/index.md` (Course Structure блок) — отразить 3 модуля.
- `CLAUDE.md`: добавить раздел «Структура курса» (модули → лекции/семинары → LO) и правило, что `course.yaml` — single source of truth.

**Подход:** делает subagent (Plan/general-purpose) по подробному ТЗ, я только ревьюю.

### Фаза 2. Семинары — содержание

**Цель:** для каждой из 17 лекций — описание соответствующего семинара.

**Формат семинара:**
- Тема (привязана к лекции).
- Краткое описание (что делаем 75 мин).
- LO (которые отрабатываем).
- Формат: кейс / разбор / промптинг / опрос / групповой анализ / мини-проект (выбираем под лекцию).
- Спец. семинары: С1 финальный (8) → Рубежный контроль 1; С12 → РК2; С17 → итоговая защита/РК3.

**Подход:** subagent пишет 17 черновиков семинаров на основе Doc #1 + course.yaml. Я ревьюю.
