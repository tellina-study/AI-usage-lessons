# Чем занятие кончается

## Assertion

Из шести сегодняшних кейсов опору несут два; остальные четыре — документированное исследование, которое одной командой не воспроизвести.

## Visual

| Кейс | Опора | Проверяется чем |
|---|---|---|
| MCP — данных нет в репозитории | нет | целевое решение, коммита нет ни в демо-репозитории, ни в репозитории курса |
| MCP — подключён, агент не ходит | есть | `claude mcp list` / `/mcp` — статусы, два тайм-аута, вживую на занятии |
| MCP — описания инструментов занимают контекст | нет | числа документации и инженерных блогов; замера на занятии не делаем |
| Субагент — чтение уходит в контекст роли | нет | требует подготовленного параллельного прогона, не воспроизводится на занятии |
| Субагент — вторая роль, промежуток | нет | утверждение исследования (MAST); ни одна из двух опор занятия его не демонстрирует |
| Субагент — исполнители в одной папке | есть | `git worktree list` — у себя; и три столкновения в журнале репозитория, открытого на занятии |

> «Под частью сегодняшних карточек лежит команда, которую можно выполнить и получить ответ. Под другой частью — нет, и это названо прямо: необъявленный пробел стоил бы дороже объявленного.»

> «Отсюда вы уносите один вопрос к своей работе: чего ей не хватает — того, чего внутри нет вовсе, или места, занятого чтением? Первое приносят внутрь, второе выносят наружу.»

## Speaker notes


Последний экран занятия делает две вещи: честно разделяет сегодняшний материал по тому, чем его можно проверить, и отдаёт вопрос, которым выбирают ход у себя.

Из шести случаев занятия опору несут два.

Статус сервера — второй случай блока MCP. Проверяется прямо на вашей машине: `claude mcp list` печатает список подключённых серверов и их состояние, `/mcp` показывает то же изнутри сессии, и там видно, что «подключён» отвечает за поднятый процесс и ни за что больше. Доказательством реальной работы сервера остаётся явный именованный вызов, видимый в выводе. Два тайм-аута из этого разбора смотрятся вживую, на занятии.

Исполнители в одной папке — третий случай блока субагента. `git worktree list` печатает, сколько отдельных копий репозитория у вас есть и на каком каталоге стоит каждая; отсюда и видно, сколько сессий делят один каталог. На этом же счёте курс поймал сам себя: его собирают несколькими сессиями в одной рабочей копии, и в журнале записаны три столкновения — пустой PDF при коде возврата ноль, ошибка сборки от чтения посреди чужой записи и около двух часов на восстановление ветки. Во всех трёх привычные признаки успеха сошлись. Журнал, в котором эти случаи записаны, открыт.

Под остальными четырьмя командой, которую можно выполнить здесь и сейчас, опоры нет, и это сказано прямо. У первого случая блока MCP решение целевое, коммита у него нет ни в демонстрационном репозитории, ни в репозитории курса. Числа по занятому контексту взяты из документации протокола и инженерных блогов — замера на занятии не делаем. Выигрыш делегированного чтения требует подготовленного параллельного прогона, который в аудитории не поставишь. Рассогласование между исполнителями держится на измерении по 1600+ трассам мультиагентных систем, где оно отвечает за 37% провалов, и ни одна из двух опор занятия этого не демонстрирует. Проверяемость здесь другого рода: читается первоисточник, команда не выполняется. Четыре клетки без команды — разница в природе материала, и недосмотра за ней нет.

Результат занятия измеряется не количеством файлов. Результат — вопрос, которым выбирают ход, и цена, названная у каждого из двух. Проверяемость — половина этого результата: про часть материала можно задать вопрос и получить ответ командой, про другую часть пока нет, и необъявленный пробел стоил бы дороже объявленного.

И последнее, то, ради чего всё шло. Два механизма разобраны; с собой стоит унести вопрос, которым между ними выбирают. Завтра, когда ваша работа перестанет помещаться агенту: чего ей не хватает — того, чего внутри нет вовсе, или места, занятого чтением? Первое приносят внутрь, второе выносят наружу. Разработчик, с чьих двух промахов занятие начиналось, различает эти случаи сам — и это весь ответ на вопрос, прозвучавший второй раз экраном раньше.

Это вопрос, и заданием он не становится. Отвечать на него никому не нужно, присылать ответ некуда, на следующем занятии он не спрашивается: перенос на свой репозиторий — работа отдельного занятия, и начинать её с невыполненного задания было бы нечестно.
