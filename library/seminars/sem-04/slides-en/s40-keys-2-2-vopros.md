# How to reorganize the decision log

## Assertion

A decision log that has outgrown itself and a lost link between two records is a reason to choose how to reorganize it, not to start a new one.

## Visual

The question verbatim, in a gold frame:

> "DECISIONS.md has grown, and it already contains a decision that overrides part of an earlier decision — without a single link between them. Choose how to reorganize this file — from the cards below — so that the agent quickly finds the decision it needs and sees the links between decisions, instead of scrolling a linear log from the beginning. Justify your choice."

Below it — five option cards:

`leave it as is — just grep it` · `split it into separate files with links` · `install a graph/vector memory system` · `set up one shared SUMMARY.md, rewritten in full` · `the agent will find it itself by searching the repository`

There is not a single number on the slide, no breakdown table and no target answer — they are on the next slide.

## Speaker notes

The wording verbatim. The facilitator reads out the question and the five cards, takes 2 responses from the room — and gives no numbers on this slide: the evidence comes on the next one.

The answer "I'll install a graph memory system" is not taken apart here: it is recorded out loud on the same footing as the rest, and the comment comes on the next slide.
