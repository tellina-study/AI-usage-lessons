# Как превратить число в решение

## Assertion

Четыре способа решить, что делать с числом похожести — у каждого свой довод.

## Visual

> **Похожесть вернулась числом 0,74. Как решить «тот же документ или другой»?**

`порог по умолчанию из документации` · `порог, подобранный на своих данных` · `два порога с полосой неопределённости` · `список кандидатов без вердикта`

## Speaker notes

Четыре действия, и у каждого свой довод. Порог по умолчанию — берётся число прямо из примера в документации модели или библиотеки, один раз, без проверки на собственных данных: работа начинается сразу, отдельный замер не нужен.

Порог, подобранный по собственному распределению — распределение похожести считается по своим парам, как в предыдущем кейсе этого занятия, и порог ставится так, чтобы разделить уже известные примеры «тот же / другой» как можно лучше. Это учитывает реальные данные архива — не чужой пример из чужой документации.

Два порога с полосой неопределённости между ними — ниже нижнего порога система уверенно отвечает «другой», выше верхнего — уверенно «тот же», а всё, что лежит между двумя порогами, не разрешается автоматически: такую пару передают человеку. Этот вариант не заставляет одно число делать работу, для которой данных может быть недостаточно, и честно называет область, где однозначного ответа нет.

Список кандидатов без вердикта — система вообще не произносит «тот же» или «другой»: она отдаёт ранжированный список похожих документов, а решение целиком остаётся за человеком. Этот вариант снимает с модели саму задачу опознания и перекладывает её на того, кто смотрит список.

Пятнадцать секунд на голосование. Прежде чем выбирать, стоит держать в голове: чем меньше автоматики в решении, тем дороже по времени каждая отдельная пара документов: это компромисс, бесплатных улучшений среди них нет. Какой из четырёх вариантов что в итоге даёт на собственном распределении похожести архива — разбирается следующим тактом, числами замера, не предположением.
