# Что делает каждое действие

## Assertion

Три действия из четырёх не решают эту конкретную задачу; решает её подстановка значений в готовую форму.

## Visual

| Действие | Что делает | Чего не делает |
|---|---|---|
| **подставить значения в готовую форму** | ровно наш случай: сообщение с одной формой, в которую подставляются только значения полей, без вызова модели | не меняется сам, если позже форма сообщения потребует реальной вариативности — тогда её придётся переписывать руками на каждый новый случай |
| **дать модели сочинять текст с тоном** | работает, когда тон, язык или длина должны реально меняться от заявки к заявке | для нашего сообщения — не тот случай: текст не требует интерпретации, только сборки из уже известных значений |
| **в любом случае доверить это модели** | действительно выдаёт естественный язык на выходе | не работает как общее правило: шаблон тоже выдаёт естественный язык читателю — разница не в том, похож ли результат на язык, а в том, кто придумывает его форму |
| **усилить модель при росте получателей** | усиливает модель | не относится к задаче: число получателей не связано с вариативностью контента — одно и то же шаблонное сообщение рассылается любому числу адресатов без модели |

> **Поворот.** Разница между решениями — не в том, выглядит ли результат естественным языком. Шаблон тоже выдаёт язык, который читает человек. Разница в том, кто придумывает форму сообщения: человек один раз заранее — это шаблон, или модель на каждый отдельный прогон — это генерация.

## Speaker notes

Разбираем по порядку, и сразу главное: ни одно из четырёх действий не глупое само по себе, но только одно отвечает на вопрос, который мы задали.

Подставить значения в готовую форму — это ровно наш случай. У сообщения одна форма: «новая заявка от такого-то, тема такая-то». Меняются только значения внутри неё, модель вызывать не нужно вовсе. Из ограничений: если форма сообщения со временем начнёт требовать реальной вариативности — разные языки, разная степень подробности — шаблон придётся переписывать руками на каждый новый случай. Это тоже цена, просто не денежная, а инженерная.

Дать модели сочинять текст с тоном на каждый прогон — рабочее решение, но не для этой задачи. Оно подходит, когда тон, язык или длина сообщения действительно должны меняться от случая к случаю. Для нашего сообщения это не так: текст не требует интерпретации, его нужно просто собрать из уже известных значений.

В любом случае доверить это модели, потому что на выходе естественный язык, — рассуждение, которое ломается на одном наблюдении. Шаблон тоже выдаёт естественный язык, который читает человек. Дело не в том, похож ли результат на язык, а в том, кто придумывает форму этого языка: человек один раз, заранее, — это шаблон; модель каждый раз заново — это генерация. Похожесть результата на язык не говорит, какой путь к нему привёл.

Усилить модель при росте числа получателей — действие, которое отвечает не на тот вопрос. Число получателей не связано с тем, насколько вариативен контент сообщения. Одно и то же шаблонное сообщение можно рассылать любому числу адресатов, и модель для этого не нужна.

Поворот, который стоит здесь унести: смотреть не на то, выглядит ли результат языком, а на то, кто придумывает его форму. Это и есть граница между форматированием и генерацией — переходим к решению.
