# Обошли, промолчал, или просто не увидел

## Assertion

Хук может отказать тихо даже написанный правильно, может приехать с чужим репозиторием уже скомпрометированным, и в любом случае не видит человека, который набрал команду в обход агента — сработал не значит принудил.

## Visual

**1. Конфигурация — чужой исполняемый код.** Задокументированная уязвимость подделки служебного файла git worktree заставляет харнесс считать папку доверенной и выполнить хуки из чужого `settings.json` **без диалога доверия вообще** (CVSS 7,7–8,8).

**2. Тихий отказ — по силе тишины:**
- Сломан весь файл целиком → в интерактивной сессии **не тихо**, диалог виден сразу
- Опечатка в одной записи (имя события, регистр, matcher) → тихо всегда, только через `doctor`
- Таймаут → тихое разрешение
- Узкий matcher (`Edit|Write`) при вызове `Bash` вместо правки → не режим виноват, а ширина условия
- Хук во frontmatter субагента может не сработать вовсе при идентичном хуке в общих настройках

**3. Человек и субагент.** `PreToolUse` — событие жизни **агента**; человек в отдельном терминале для харнесса не существует. Хуки уровня настроек срабатывают и внутри субагента — но зафиксированы два независимых случая, где `deny` вынесен, а команда всё равно выполнилась.

> «Когда гейт не срабатывает, не происходит ничего — а именно так выглядит и успешно пройденный гейт.»

## Speaker notes

Первое: конфигурация — исполняемый код, который приезжает вместе с чужим репозиторием. Задокументированная уязвимость подделывает служебный файл git worktree так, что харнесс решает — папка уже доверена, — и выполняет чужие хуки без единого диалога доверия; в более ранней версии той же проблемы диалог хотя бы появлялся, просто хуки успевали отработать раньше.

Второе: хук может отказать тихо, даже написанный правильно, — и тут две разные тишины, не одна. Сломан весь файл — в интерактивной сессии не тихо совсем, диалог виден сразу. Сломана одна запись — тихо всегда, никакого сигнала кроме отладочного лога. К этой же категории — режим без подтверждений, который повышает шанс вызова команды оболочки вместо выделенного инструмента правки: дело не в режиме, хук по-прежнему срабатывает, просто matcher не совпал с фактически вызванным инструментом. И хук во frontmatter субагента может не сработать вовсе при идентичном хуке в общих настройках проекта.

Третье, и здесь интуиция обманывает надёжнее всего: `PreToolUse` — событие жизни агента, и человек, открывший отдельный терминал, для харнесса не существует. Формула «правила в коде — законы» верна строго для агента; для человека, действующего в обход агента, тот же хук — не закон и даже не просьба, он его просто не видит.

И четвёртое, тот же вопрос без человека, внутри субагента: хуки срабатывают и там, но зафиксированы случаи, где корректный «запретить» вынесен — а команда всё равно выполнилась. Сработал — не значит принудил.
