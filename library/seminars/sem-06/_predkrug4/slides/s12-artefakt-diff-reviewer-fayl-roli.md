# Файл роли — и строка короче всего остального

## Assertion

Файл роли `diff-reviewer.md` — не клонируемый артефакт занятия, а материал для устного разбора; строка `tools: Read, Grep, Glob` короче всего остального файла и делает больше всего.

## Visual

```markdown
---
name: diff-reviewer
description: Независимый ревьюер diff'ов. Видит только сам diff и критерии приёмки, не рассуждения
  автора. Используй перед мержем любого нетривиального изменения. НЕ для ревью архитектурных
  решений — это отдельная роль.
tools: Read, Grep, Glob
---

# diff-reviewer

Ты не правишь код сам — только находишь проблемы. Начни ответ строкой:
`VERDICT: PASS | BLOCK`

Затем: что проверено (конкретно — какие файлы прочитаны), находки (что не так, где, почему важно).
Пустой список находок — валидный PASS.
```

> Файл роли для разбора — не клонируемый артефакт занятия: снят с версии репозитория, которой больше не существует за пределами временной директории.

## Speaker notes

Вот файл роли целиком. Сразу — оговорка, частью рассказа, не сноской: склонировать его сейчас нельзя, файл снят с более ранней версии демо-репозитория, которой больше нет за пределами временной директории. Это файл для разбора — что в нём написано и почему, — не готовый к копированию артефакт.

Обратите внимание на строку `tools: Read, Grep, Glob`. Она короче всего остального файла и делает больше всего: без `Write` и `Edit` в списке инструмент правки у роли отсутствует физически, а не по договорённости. Описание — та же трёхчастная схема, что мы только что собрали сами: что делает, когда использовать, когда не использовать.

Тело роли короткое — два требования: начать ответ строкой вердикта и дать конкретный раздел «что проверено». Это не бюрократия, а единственное, что превращает утверждение в проверяемый факт.
