# Собранный файл: четыре строки, и права — вне файла

## Assertion

Итог разговора — четыре строки в файле: чем запускается сервер, что запускается, откуда берётся ключ. Вне файла, но не менее важно — какие права у этого ключа: один репозиторий, не вся учётная запись.

## Visual

```json
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": {
        "GITHUB_PERSONAL_ACCESS_TOKEN": "${GITHUB_PAT}"
      }
    }
  }
}
```

| Область | Физически | Приоритет при конфликте имён |
|---|---|---|
| `local` (личная) | `~/.claude.json` | 1 — выше всех пользовательских |
| `project` (общая, в репозитории) | `.mcp.json` в корне репозитория | 2 |
| `user` (общая личная) | `~/.claude.json` | 3 |

> При конфликте имени сервера побеждает вся запись приоритетной области целиком — поля не смешиваются. Дальше — сервер из плагина, коннектор, выше всех — политика организации.

## Speaker notes

Итог разговора — четыре строки в файле: чем запускается сервер, что запускается, откуда берётся ключ и — вне файла, но не менее важно — какие права у этого ключа: один репозиторий, не вся учётная запись.

Эта практика остаётся целевым решением раздела, не подтверждённым коммитом ни в этом проекте, ни в репозитории курса — слайд показывает разбираемый пример, не обещает «склонируй и повтори».

Если спросят про сам файл подробнее: он лежит в корне репозитория, видят его все, кто клонирует проект; личная и общая личная области живут в отдельном файле вне репозитория, туда секреты из кода не попадают просто потому, что файл физически не в дереве git.

Если спросят, что будет, если изменить область уже подключённого сервера: это та же запись, просто переписанная в другое место — сами права токена при этом не меняются, их меняют на стороне сервиса, где токен создавался.

Если спросят, почему именно этот список из трёх областей, а не произвольные: это ровно то, что физически умеет продукт — три жёстко заданных места, не произвольная настройка.

Если спросят про честный пробел ещё раз: этот конкретный файл — целевое решение, собранное из более раннего захвата демо-репозитория; в текущей ветке его нет, и тот же файл отсутствует в репозитории курса. Проверка этого кейса — на доказательной базе исследования, не на живом коммите; это касается и двух следующих кейсов этого блока — у них общий этот пробел.
