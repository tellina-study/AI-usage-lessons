## 2. Предложение A (основное) — один слайд, таблица решения

| Поле | Значение |
|---|---|
| `id` | `s-delivery-modes` |
| Позиция | в Разделе 4, **после `s24`, перед `s25b`** (то есть сразу за блоком §4.8 skills/subagents/MCP + безопасность) |
| `type` | `comparison_table` |
| `section` | `"Раздел 4. Агенты"` |
| `duration_min` | 2.5 |
| `chapter_ref` | `"§4.8b [for-slide-s-delivery-modes]"` |
| `assertion` (headline) | «Процедура одна — различаются гарантия и цена: кто решает применить и что платим постоянно» |
| `learning_goal` | Критерий выбора способа подачи процедуры через цену пропуска (§4.8b) |
| Мем / иллюстрация | **НЕТ.** Это сравнительный технический слайд — по правилу курса мем только на hook/judgment/контраст, не на сравнительных и технических слайдах |

**Содержание (минимум текста, таблица на 6 строк × 3 колонки — больше на слайд не влезет читаемо):**

| способ | кто решает применить | как молча ломается |
|---|---|---|
| always-on файл инструкций | модель, каждый запрос | раздувается → правила перестают соблюдаться |
| ссылочный файл «читай X» | модель, если решит открыть | не открывает — и отвечает уверенно |
| skill | модель, по строке описания | не триггерится / нет описания вообще |
| слэш-команда | человек, явно | человек забыл вызвать |
| хук | код, гарантированно | падает молча; гарантия работает и на атакующего |
| MCP-инструмент | модель выбирает из списка | много инструментов → выбор хуже |

Третья колонка — это и есть выполнение правила курса про провалы: каждая строка несёт режим отказа,
а не только возможность. Числовые базы (26.1% из 31 132 просканированных навыков; точность выбора
инструмента 43%→14%; +32-35% токенов за раздувание) — **в заметки докладчика, не на видимый слой**:
на слайде они не читаются, а в заметках служат ответом на вопрос из зала.

**Куда девать 2.5 минуты.** Дек уже идёт 103 мин при заявленных 100. Предлагаемый источник времени —
`s25b` («coding-агенты») уже стоит в `cut_order.to_75_min`, то есть владелец его и так считает
сжимаемым; альтернатива — не добавлять слайд вовсе (вариант C ниже). Решение за владельцем:
оркестратор не переписывает тайминг дека `status: final` самостоятельно.

**Если слайд принимается, его нужно добавить и в `cut_order`** — иначе при сжатии до 90/75 мин
непонятно, режется он или нет. Предложение: в `to_90_min` НЕ включать (таблица решения — это
операционный выход раздела), в `to_75_min` — включать последней строкой.

## 7. Связь с Семинаром 5 (issue #211) — предложение, семинар НЕ правится

Семинар 5 сейчас — `status: parked-raw-material`: `PARKING-NOTE.md` + 5 перенесённых разделов
`rework/section-1-khuk.md` … `section-5-protsess.md` (хук → скилл → MCP → субагент → процесс),
без своей вводной части, без `deck.yaml`, без рендера.

**Что даёт вердикт #217 этому семинару.** Лестница в его нынешнем виде читается как «каждая
следующая ступень — больше возможностей». Вердикт даёт другую несущую ось: **каждая ступень —
не "больше", а ДРУГОЙ ВИД ГАРАНТИИ**, и выбор между ступенями делается по цене пропуска, а не по
номеру ступени. Три конкретных способа это вплести:

1. **Вводная часть, которой у семинара нет** (пункт 1 его собственного списка «что НЕ сделано») —
   готовая постановка: берём ОДНУ процедуру из рабочего кейса и подаём её шестью способами,
   замеряя, срабатывает ли она без напоминания. Это не теория: эксперимент из `04-own-experiment.md`
   воспроизводим одной командой (`check.py`), студенты получают результат за один прогон, а не
   верят на слово. Ссылочный файл при этом не срабатывает молча — наглядно и неприятно, то есть
   ровно то, что запоминается.
2. **Одна и та же таблица решения на каждой ступени.** На ступенях 3-7 (`section-1`…`section-5`)
   один повторяющийся вопрос: «что эта ступень ГАРАНТИРУЕТ, чего не гарантировала предыдущая, и
   что мы за это платим постоянно». К концу занятия студент заполнил таблицу сам — и у семинара
   появляется сквозная ось вместо пяти независимых демонстраций.
3. **Ступень «хук» получает честную цену.** `section-1-khuk.md` стоит первой и выигрывает
   сравнение по надёжности — но CVE-2025-59536 (злонамеренный `.claude/settings.json` в
   клонированном репозитории срабатывает ДО диалога доверия) показывает обратную сторону той же
   гарантии: исполнение кодом работает и на атакующего. Это готовый on-point провал для ступени,
   у которой сейчас провала нет.

**Решение за владельцем.** Оркестратор семинар не трогает: `library/seminars/sem-05/` этой
операцией не изменён, предложение зафиксировано здесь, чтобы будущий производственный цикл
Семинара 5 его увидел, а не изобретал заново.
