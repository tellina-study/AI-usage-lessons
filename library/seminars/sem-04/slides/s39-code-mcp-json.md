# `.mcp.json`

## Assertion

.mcp.json живёт в корне репозитория и коммитится как код — область подключения ограничена конкретным репозиторием, не всей организацией сразу.

## Visual

Блок кода на всю ширину слайда, моноширинный шрифт, синтаксис-подсветка JSON:

```json
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": {
        "GITHUB_PERSONAL_ACCESS_TOKEN": "${GITHUB_PAT}"
      }
    }
  }
}
```

## Speaker notes

`.mcp.json` в корне репозитория — это project-scope конфигурация: она коммитится вместе с кодом и ревьюится точно так же, как любой другой файл в пул-реквесте, а не живёт молча в локальных настройках одной машины. Перед вами минимальный рабочий пример: один сервер `github`, запускается через `npx`, токен доступа берётся из переменной окружения `GITHUB_PAT`, а не прописан прямо в файле — секрет никогда не должен лежать в коммите.

За этим конфигом стоят три примитива протокола, и у каждого свой субъект решения — кто именно определяет, использовать его или нет. Инструменты, tools, — их вызов решает модель: она сама, по ходу диалога, решает, прочитать ли список issue или создать ли PR. Ресурсы, resources, — их подключение решает хост, то есть это происходит через явное `@`-упоминание, пользователь сам указывает, какой именно ресурс подключить к контексту. Подсказки, prompts, — их вызов решает человек напрямую, через `/`-команду, это заранее заготовленный шаблон запроса, а не то, что агент выбирает сам.

Подключать сервер стоит с минимальными правами — ограничивая область конкретным репозиторием signup-landing, а не всей организацией или всеми приватными репозиториями пользователя разом. Именно эта разница между «доступ к одному репозиторию» и «доступ ко всем репозиториям сразу» и станет ключевой в провале, который разберём чуть позже: там агент получил одновременный доступ и к публичному, и к приватным репозиториям через один и тот же сервер, и именно эта комбинация сделала утечку возможной.

После подключения проверка простая и повторяемая: `claude mcp list` должен показать сервер `github` со статусом подключён, а панель `/mcp` — реальный список доступных инструментов, а не ноль при заявленном подключении. Держите в голове, что статус подключения и реальная работоспособность сервера — не одно и то же; следующий слайд разберёт ровно этот разрыв на конкретном сервере этого же курса.
