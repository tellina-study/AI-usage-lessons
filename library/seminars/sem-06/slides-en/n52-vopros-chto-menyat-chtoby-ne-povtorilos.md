# Both tasks are needed. What gets changed here?

## Assertion

Has anyone had two runs fighting over one working folder: the branch turned out to be the wrong one, an edit got written over, and nobody did anything strange? Both tasks are needed, both sessions are needed, the directory is one. Choose what gets set up or changed here, and justify your choice against the four neighboring cards.

## Visual

> Has anyone had two runs fighting over one folder — the wrong branch, an edit written over, and nobody doing anything strange?

> **The tasks are independent, both sessions are needed at once, the directory is one. Pick a card — and justify it against the other four.**

`commit before every switch` · `work one at a time, in one session` · `subagents in the first session instead of a second session` · `a copy of the repository of its own for every session` · `divide by files and agree on it`

## Speaker notes

It is worth starting from a case of your own, because almost everyone here has one. Have you had two runs fighting over one working folder: the branch turned out to be the wrong one, an edit got written over, the build was built from the wrong thing — and nobody was doing anything strange at the time? If you have, it is worth keeping in mind how it ended for you.

The tasks do not depend on each other, both sessions are needed at once, their directory is one. Neither session in this story did anything strange: one started with a branch, the other carried on from what it had read. So the question worth asking is about the arrangement — what gets set up or changed here so that this does not happen again.

Five moves: commit before every switch; work one at a time, in one session; subagents in the first session instead of a second session; a copy of the repository of its own for every session; divide by files and agree on it. It is worth choosing together with a justification against the other four: each of the five has a case where it works and a limit past which it stops working.

There are five answers that get said to a question like this more often than others, and with each one it is useful to do one piece of work — ask what it does to the branch and what it does to the file.

"Commit before switching." It is named first, and it is a working move. The test question: what does it do to branches? It does let you recover what was lost — there is something to come back to. It does not cancel one branch per directory, which means it makes a story like the one examined recoverable without preventing it.

"One at a time." An honest answer, and it is worth defending directly: there will be no collisions at all — one job in the directory, one branch, one worker. The test question is about the cost: what happens when the second task cannot wait as long as the first one runs.

"Subagents instead of a second session." A productive confusion, and it leads straight into the middle of the case. Subagents really do replace a second session: the task does not have to be explained from scratch, the result comes back to where the work sits. The test question: which directory do these subagents work in?

"A copy of its own for every session." The test question, which rarely gets answered in full: what in that copy is its own and what is shared with the main one? The answer will be needed at the mechanics of the copy, and whether the copy pays off depends on it.

"Divide by files and agree on it." The test question: where does that agreement rest on the arrangement and where only on the memory of the participants?

The answer "let the workers sort it out themselves" is worth taking apart separately. They can sort it out by the state of the files, and the state does not record who made it — that much is already visible from the scene.

A sixth move that is not on the cards gets brought up often, and more often than anything else it is a queue on the shared file or a designated owner of the directory. Both will come in useful at the end of the case: they answer the question the five cards do not close.

And the last thing, if the answer seems the only one and self-evident. Check whether you have counted the working environment: what will have to be done before a build can be launched in the new copy. Confidence here usually rests on that part not having been counted.

One more observation about the set of cards itself. Four moves out of five are about discipline: commit on time, work one at a time, divide up the files, come to an agreement. Discipline is cancelable by one forgetful morning. The fifth move is about the arrangement: it changes what two workers physically see. The breakdown will start from that distinction, because it sorts all five.
