# What we're covering today

## Assertion

Four choices that keep coming back: AI or plain code, build-in or build-separate,
one-off call / RAG / agent, external API or local inference.

## Visual

A plain four-line list, no arrows and no procedure diagram between them: "AI or
plain code" / "Build it into an existing tool or build something separate" /
"One-off call, RAG, or agent" / "External API or local inference." Below it — a
compact, smaller-type list of the seven cases: supplier documents, personal data
in logs, a support assistant, product descriptions, meeting minutes, a chat
digest, sales calls.

## Speaker notes

Here's what we're training today — four types of choice that keep coming up in
engineering practice, again and again: whether you need AI here at all or plain
code is enough, whether to build the solution into what people already use or
make a separate product, what shape the model call should take — a one-off call,
a search over a knowledge base, or a multi-step agent — and finally, whether to
run it through an external cloud API or on your own infrastructure. We're not
turning this into a procedure with a checklist — instead we're going to work
through seven realistic situations: documents from suppliers, personal data in
logs, a support-desk assistant, product descriptions, meeting minutes, a digest
of work chats, and sales calls. Each one has its own choice and its own set of
facts. Look at each setup critically from the very start: what's missing that
you'd need in order to give an honest answer instead of guessing?
