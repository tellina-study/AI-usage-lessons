# sem-05 — материал на парковке (сырой перенос из Семинара 4 v3)

## Что это

Владелец курса раскалывает Семинар 4 «Сборка кодинг-агента» на два занятия (голосовое решение
2026-09-22, зафиксировано в `library/seminars/sem-04/REWORK-REQUIREMENTS-v4.md` §R4-0/§R4-3):

- **Новый, меньший Семинар 4** остаётся вводной частью + разбором двух тем (файл инструкций,
  память, по 3 кейса) — этим занимаются другие агенты параллельно, не эта папка.
- **Этот Семинар 5** — механически перенесённый материал ступеней 3-7 лестницы экипировки агента
  (хук → скилл → MCP → субагент → процесс) из v3 Семинара 4: план+методическая глава каждой
  ступени и все относящиеся слайды (s25-s72). Перенос **чисто механический** — содержание не
  дорабатывалось, не улучшалось и не адаптировалось под новый семинар.

## Что физически здесь лежит

- `rework/section-1-khuk.md` … `rework/section-5-protsess.md` — методические главы ступеней
  3-7, перенумерованные под новую последовательность разделов sem-05 (была раздел 3-7, стала
  раздел 1-5); нумерация «ступень N» (из лестницы Лекции 3) не менялась.
- `slides/s25-*.md` … `slides/s72-*.md` — 48 файлов слайдов как есть, имена НЕ перенумерованы
  (это сделает будущий производственный цикл при реальной сборке `deck.yaml`).
- `assets/captures/` — реальные захваченные материалы (терминал-снимки, diff'ы, деревья файлов,
  вердикт diff-reviewer), относящиеся к ступеням 3-7. Часть файлов (`22-tree-stage2.txt`,
  `27-tree-stage7.txt`, `README.md`, `TODO-capture.md`) — КОПИИ, не перемещены: они пересекают
  границу старого раздела 2/раздела 0 и всё ещё нужны `sem-04` тоже.
- `rendered/` — пустая, намеренно. Рендер (PPTX/PDF/снимки) будет делать будущий отдельный
  производственный цикл, не эта операция.

## Что НЕ сделано (явно, не молчаливый пропуск)

1. **Нет собственной вводной части.** В v3 ступени 3-7 начинались как продолжение сквозного
   диалога про `signup-landing`, начатого в разделе 0 (открытие) старого Семинара 4 — этого
   открытия здесь физически нет. Первый перенесённый раздел (`section-1-khuk.md`) начинается
   так, будто до него уже было открытие, карта экипировки, разделы про файл инструкций и память
   — в новом Семинаре 5 этого пока не существует.
2. **Ревью под новый формат не проводилось.** Ни один критик-агент (methodology-critic,
   fact-checker, consistency-checker и т.д.) не смотрел на этот материал как на самостоятельный
   семинар — весь прежний ревью-цикл был пройден для него как для ЧАСТИ семинара на 7 ступеней,
   а не как для отдельного занятия на 5.
3. **Нет актуального `deck.yaml`.** Старые per-slide метаданные (`duration_min`, `assertion`,
   `learning_goal`) для s25-s72 существовали в `sem-04/deck.yaml` и были оттуда удалены при
   разделении — они не потеряны (доступны в git-истории `sem-04/deck.yaml` до коммита переноса,
   раунд 4), но новый `deck.yaml` для sem-05 не создан — этой операцией специально, чтобы не
   выдумывать структуру нового занятия за оркестратора.
4. **Нет рендера.** `rendered/` пуста.
5. **Нумерация «Раздел N» частично противоречива внутри перенесённых файлов** — см. открытый
   вопрос №1 в каждом `rework/section-*.md`: ссылки на старый раздел 0/1/2 (открытие/файл
   инструкций/память старого Семинара 4) не резолвятся в sem-05, не переписаны молча.
