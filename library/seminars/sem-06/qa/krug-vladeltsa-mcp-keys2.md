# Круг правок владельца — кейс 2 блока MCP («подключён, а работы нет»)

## По каждому замечанию

**1. Разбор MCP, описание сервера.** Не относится к зоне — это блок 0/одностраничник, другие
сессии.

**2. Выбор API / удалённый MCP / свой сервер в первом кейсе.** Не относится к зоне — первый кейс
(n06–n16), другая сессия.

**3 и 5. Читаемость — кейсы и вопросы не читаемы / надо упрощать, конкретизировать, делать
нагляднее.**

- `n19` (вопрос): владелец назвал вопрос недостаточно подробным для чтения без устного
  пояснения. Добавлена тихая форма-подводка перед золотой рамкой вопроса — однострочный повтор
  сцены предыдущего слайда (сервер стоит две недели · агент отчитался · репозиторий пуст), без
  новых цифр. Приём уже используется в деке для той же цели (`n36`, `n46`) — не изобретён заново.
  Текст пяти карточек не менялся ни на знак, порядок сохранён.
- `n21` (самый плотный слайд зоны, три содержательных блока на одном экране — таблица из пяти
  статусов, доказательный вызов, таблица из двух тайм-аутов). Разделён на два слайда:
  `n21` — пять статусов + доказательный вызов; `n21a` (новый) — два тайм-аута, поданы как
  описание временной шкалы вместо второй таблицы (идея из задания: два значения на три порядка
  разные читаются на шкале за секунду, в таблице строкой — нет). Факты не менялись, только форма
  и распределение по экранам. Фигура шкалы (`mcp-n21a-taym-auty-shkala.png`) описана в
  `visual.primary`/`visual.figure` — рисует сессия сведения; до тех пор слайд читается по
  текстовым блокам в `## Visual`, проверено предпросмотром (ниже).
- `n20`: проверен — порядок строк таблицы разбора буквально совпадает с порядком карточек `n19`
  (`ничего — статус зелёный` → `перезапустить сессию` → `посмотреть статус подробнее` →
  `удалить и подключить заново` → `написать автору`). Не трогал, как и просили.

**4. Одностраничники по субагентам и MCP.** Не относится к зоне — другая сессия (одностраничник
для MCP описан в общем задании как отдельная работа, не в диапазоне `n17–n24`).

**6. Больше границ применимости.** `n24` нёс только две границы («достаточно периодической
проверки» / «флагу, который сервер не подтверждает, не доверять никогда»). Добавлена третья,
которую владелец явно назвал для этого кейса — где сам приём (доказательный вызов) перестаёт
быть ответом: если вызов систематически не проходит, а автор сервера не отвечает, вопрос
смещается туда же, где решался первый кейс блока — подключать ли сервер вообще. Граница собрана
из материала, уже введённого в этом же кейсе (карточка «написать автору сервера» на `n20`,
критерий «не нужно вообще» первого кейса) — новых фактов не добавлено. Формат оставлен
двухколоночным (как у границы первого кейса `n16`), а не превращён в грид-таблицу — третий пункт
лёг третьей строкой в правую колонку, без увеличения числа столбцов.

`n23` −0,25); разделение `n21` бюджет не меняет.

**Открытый вопрос к сведению/владельцу:** общее задание называло мою зону «8 слайдов, 10,75
минуты», а сумма `duration_min` из фронтматтера моих же файлов на момент старта давала 12,0

10,75 посчитаны другим методом (например, по словам в заметках, а не по `duration_min`), либо это
опечатка в общем задании. Я считал «было/стало» от фактических чисел в файлах на момент старта,
чтобы баланс «добавил — сократил» был проверяем; если сведение считает по другому методу, разница
между 10,75 и 12,0 (1,25 мин) не моя добавка — её не было в зоне до меня.

## Проверка

Собрал зону через `build_sem06.py --block n1` и `--block n2` (частичные сборки по id, не вся
дека) и `qa_preview.py` — просмотрел настоящие PNG `n17–n24a` (кроме `n22`, не трогал содержание;
`n17` не трогал тоже). Пятисекундная проверка прошла на каждом:
- `n19` — «статус зелёный третью неделю, результата ноль, что проверить» читается без сцены-соседа.
- `n21` — «пять статусов + один способ доказать работу», без тайм-аутов на этом экране.
- `n21a` — «два тайм-аута, разных на три порядка» — текстовые блоки читаются; схема появится при
  сборке сессией сведения.
- `n24` — «когда хватает проверки, когда нужен вызов, когда вопрос — подключать ли вообще» —
  три пункта видны сразу, без грид-таблицы.

Предупреждений о переполнении текста/наложении фигур в собранных слайдах — ноль (только ожидаемые
для частичной сборки по `id`: порядковый номер не по счёту и «ссылка в никуда» на слайды соседних
зон, не входящие в частичный блок, — это артефакт `--block`, не дефект).

## Что сокращено ради бюджета

- `n18`, `n23`: хронометраж снижен на 0,25 мин каждый без изменения содержания — оба рендерятся
  с заметным запасом белого поля (см. `rendered/snapshots/iter-18.png`, `iter-23.png` до правок),
  исходная оценка времени была щедрее, чем требует фактический объём текста на экране.
- `n21`: разгружен разделением на два слайда — это и есть снятие лишнего с одного экрана
  (замечание 3/5), не содержательное сокращение.
