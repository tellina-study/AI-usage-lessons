# Почему большое число подключённых инструментов удорожает контекст агента

**Date:** 2026-10-02 · **Issue:** #217-EXP

Каждый инструмент (tool, MCP server, skill) передаётся в system prompt агента как часть доступного API. Чем больше инструментов, тем больше места они занимают в контексте, тем меньше остаётся для реальной задачи и её история.

| утверждение | источник | тип |
|---|---|---|
| Каждый tool/MCP server описан JSON-схемой (параметры, тип, constraints) в системном промпте; это ~200-500 токенов на инструмент в среднем | по памяти, не проверено | механика |
| При N=50+ инструментах суммарное описание занимает 10-25k токенов только на перечисление и схемы | по памяти, не проверено | оценка |
| Контекстное окно LLM фиксировано (e.g., Claude 100k tokens); каждый потраченный токен на описание инструментов — это потерянный токен для истории задачи и примеров | Anthropic Claude API docs; general LLM context economics | механика |
| Агент с 15 инструментами может видеть больше истории (400-500 токенов); агент с 50+ инструментами теряет 5-10k токенов на их описания, уменьшая историческую глубину | по памяти, не проверено | вывод |
| Зависимость инструмента (если tool_A требует tool_B) — удорожает обоих; cascade требует явного управления | по памяти, не проверено | anti-pattern |

## Что НЕ доказано

- Точная формула токен-стоимости для tool-набора (зависит от модели, версии Claude, способа кодирования схемы)
- Пороговое число инструментов, где контекстная стоимость начинает заметно влиять на качество ответа
- Сравнение стоимости описания tool'а vs. стоимости tool-call при фактическом использовании (какая экономнее на практике)
