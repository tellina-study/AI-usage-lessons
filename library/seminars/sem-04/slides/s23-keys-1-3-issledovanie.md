# Вложенный файл грузится по факту, не по адресу

## Assertion

Вложенный файл грузится on-demand, только по факту чтения — не по факту нахождения в папке; контролируемое исследование не нашло пользы от разбиения, а практика показывает регулярные отказы вплоть до архитектурного предела.

## Visual

**Механизм** (официальная документация Claude Code): корневой и все родительские `CLAUDE.md` грузятся **при старте сессии автоматически**. Вложенные (дочерние) грузятся **on-demand** — только когда агент реально читает файл из этой поддиректории. «Логически зайти в папку» недостаточно: нужен факт tool-call на файл оттуда. `/context` — единственный надёжный способ проверить, что реально загружено.

## Speaker notes

«Механизм устроен конкретно, не расплывчато. Корневой файл и все родительские грузятся при старте сессии, всегда. Вложенный — только когда агент реально прочитал файл из этой папки, а не когда он просто "работает в ней". Это не гипотеза — это то, как написан загрузчик.

И вот эмпирика: самое близкое к нашему вопросу контролируемое исследование, тысяча шестьсот пятьдесят сессий, проверило ровно это — и не нашло значимого эффекта ни у одной структурной переменной, включая прямой аналог нашей ситуации, противоречие между уровнями. А отдельно — список реальных issue: Claude Code, Cursor, Codex, Copilot CLI. Везде одна и та же жалоба, вплоть до жёсткого архитектурного предела в одном из инструментов.»
