# Настоящий экран: дети и родитель, подстановка перед ответом

## Assertion

Левый узел режет документ на маленьких детей и хранит родителя нетронутым. Правый — непосредственно перед ответом меняет найденного маленького ребёнка на родителя.

## Visual

Левая панель («Нарезка иерархическая: дети + родитель») читает `payload.chunk_size_child` (по умолчанию 90) и вызывает ту же функцию резки по границам предложений, что Семинар 10 уже показывал для версии 1 этого занятия — только с вдвое меньшим целевым размером. Родитель — весь `payload.document`, без единого изменения.

Правая панель («Подстановка родителя») — шесть строк кода: берёт найденного top-1 ребёнка и родителя из предыдущих узлов и возвращает объект, где `context_for_answer` — это `parent_text` (весь документ), а не `top1_child.text` (найденный кусочек). Комментарий в самом коде называет это прямо: единица поиска и единица ответа — не один и тот же объект.

## Speaker notes

Эти два узла вместе реализуют первый из двух приёмов прошлого такта — развести единицу поиска и единицу ответа. Здесь видно, как именно это устроено в реальном узле.

Левая панель — узел «Нарезка иерархическая: дети + родитель». Первая строка читает параметр `chunk_size_child` из входных данных — по умолчанию девяносто, ровно половина заголовочного размера версии 1 из прошлого такта. Дальше вызывается та же функция резки по границам предложений, которую Семинар 10 уже показывал на своём экране для простой версии резки: её берут как есть, без переизобретения. Разница только в одном числе: девяносто вместо ста восьмидесяти. Родитель при этом не режется вовсе — это просто весь текст документа, без единого изменения, сохранённый рядом с маленькими детьми.

Правая панель — узел «Подстановка родителя», самый короткий код на этом холсте, и неслучайно: сам приём не требует сложной логики, только явного решения не путать две разные вещи. Код берёт результат поиска — найденного top-1 ребёнка — и родителя, который хранился рядом с самого начала, и формирует объект для следующего узла, где полем, которое пойдёт в промт модели, оказывается не текст найденного ребёнка, а текст всего родительского документа. Комментарий внутри самого кода называет это прямо: единица поиска, по которой шёл семантический поиск, и единица ответа, которую увидит модель, — здесь окончательно расходятся.

Это ровно тот момент цепочки, который чинит дефект версии 1: какой бы маленький кусочек ни «выиграл» поиск внутри правильного документа, после этого узла модель получает документ целиком, и выигрыш поиска внутри документа перестаёт быть фактором, который может сломать ответ. Как устроена вторая половина холста — узел эмбеддинга вопроса и узел семантической резки по разрыву смысла — следующим тактом.
