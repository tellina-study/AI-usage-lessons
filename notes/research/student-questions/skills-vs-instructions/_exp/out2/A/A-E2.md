# Зачем субагенту отдельное контекстное окно

**Date:** 2026-10-02 · **Issue:** #217-EXP

Контекстное окно (context window) — лимит на количество токенов, которые языковая модель может обработать за один проход. Когда оркестратор (главный агент) делегирует задачу субагенту с отдельным контекстным окном, это создаёт несколько практических преимуществ:

1. **Изоляция контекста**: промежуточные вычисления, ошибки и неудачные попытки субагента не загрязняют основное окно оркестратора. Субагент может забыть мусор; оркестратор видит только финальный результат.

2. **Параллелизм**: несколько субагентов работают одновременно, каждый с полным окном на 200k токенов (или сколько положено). Если бы всё было в одном окне, очередность вычислений замедлила бы работу в N раз.

3. **Специализированный контекст**: субагент может загрузить всю специальную информацию для узкой задачи (шаблоны, примеры, guidelines) — не конкурируя с контекстом других подзадач.

| утверждение | источник | тип |
|---|---|---|
| Отдельное окно субагента исключает загрязнение основного контекста оркестратора | Архитектура CAO и harness-control | практический принцип |
| Параллельные субагенты ускоряют выполнение N независимых задач в N раз быстрее, чем последовательно в одном окне | Параллельная обработка + толщина контекста | закон Амдаля |

## Что НЕ доказано

- Количественные бенчмарки: на сколько % быстрее параллельные субагенты конкретно в harness-control
- Эмпирический анализ: как часто именно загрязнение контекста (vs. просто размер) становится критическим фактором в реальных workflow'ах
