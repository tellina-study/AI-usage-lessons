# Чистое окно — не чистое от всего подряд

## Assertion

Роль по умолчанию наследует описания всех MCP-серверов родительской сессии целиком — даже тех, что её задаче не нужны. Фокус работает для репозитория, не сам по себе для MCP.

## Visual

> **«Subagents inherit every MCP tool definition from the parent session, which can fill their context window before the first turn. Disable MCP servers you are not using before spawning subagents.»** — документация харнесса об устранении ошибок.

Для нашего вопроса про лимит участников: если в родительской сессии подключены трекер задач и почтовый сервер из прошлого раздела занятия, роль, которой нужно просто прочитать сорок файлов кода, получает их описания в своё окно бесплатно — хотя ни трекер, ни почта к вопросу не относятся.

> **Фокус из прошлых двух слайдов — про содержимое репозитория. Для того, что подключено MCP-серверами, за этим нужно следить отдельно: тем же списком инструментов роли, который стоял пятым блоком на одностраничнике ступени.**

## Speaker notes

Окно роли по умолчанию не настолько чистое, каким выглядело два экрана назад. Собственный промпт и свежий контекст она получает — и вместе с ними, по умолчанию, описания всех MCP-серверов родительской сессии целиком, даже тех, что её задаче не нужны ни одним инструментом. Дословно из документации по устранению ошибок: субагенты наследуют каждое описание MCP-инструмента из родительской сессии, и это может заполнить их контекстное окно ещё до первого шага — отключайте серверы, которыми не пользуетесь, перед тем как заводить субагентов.

Для нашего вопроса про лимит участников: если в сессии подключены трекер задач и почта из прошлого блока занятия, роль, которой нужно прочитать сорок файлов кода, получает их описания в своё окно бесплатно.

Фокус работает для содержимого репозитория. За подключённым серверами следят отдельно — тем же списком прав, который стоял пятым блоком на одностраничнике.

Если спросят, почему это не противоречит прошлым слайдам: не противоречит, оба про один контракт. Этот называет то, что входит в контракт дополнительно и по умолчанию, помимо желания автора роли. Экономия контекста остаётся, просто считается с этой оговоркой.

Если спросят, сколько это стоит в окне: цифру зал уже видел в прошлом блоке занятия, там постоянная плата за подключённые серверы измерена в токенах и в доле окна. Здесь важно другое: эта плата вносится ещё раз, отдельно, в окно каждой заведённой роли.

Если спросят, можно ли подключить сервер только роли, не трогая сессию: можно, и это обратный приём той же механики. Роль умеет объявить нужный ей сервер у себя — он поднимается на её старте и отключается на её завершении, а окно родителя его описаний не видит вовсе. Для тяжёлого сервера, нужного одной задаче, это дешевле, чем держать его подключённым всю сессию.

Если спросят, относится ли то же к хукам и скиллам: механика у них своя, и сегодня мы её не разбираем. Здесь достаточно одного: отключение ненужных серверов — это осознанный ход перед заведением роли. Разовая уборка в начале дня его не заменяет, потому что сессия обрастает серверами по ходу работы.
