# Отчёт: конвейер сборки деки Семинара 6

Мандат этой сессии — **инструмент сборки, не содержание**. Контент слайдов не
придуман и не правлен; всё найденное в настоящих слайдах ниже — находки для
содержательных сессий, переданные как отчёт, не как правка.

## Что поставлено

`library/seminars/sem-06/rendered/`:

- **Кит из Семинара 5 — копия без изменений** (`deck_kit.py`, `slide_parts.py`,
  `metrics.py`, `check_tracks_pdf.py`, `check_text_overlap_pdf.py`, `notes_budget.py`)
  + **копия с точечной адаптацией** (`qa_preview.py`, `audit_sopostavleniya.py`,

  файлов, импорт `build_sem06`, словарь приёмов и имена разделов Семинара 6).
  Решение «копия, не вынос в `tools/seminar-build/`» обосновано в `RENDERER-NOTES.md`
  § «Решение по киту» — коротко: вынос требует правки импортов в `sem-05/rendered/`,
  а эта сессия не вправе писать в `sem-05/**` ни байта.
- **`build_sem06.py`** — новый сборщик по образцу `build_sem05.py` (не копия):
  границы разделов, словарь приёмов (`GENRE_FN`/`PATTERN_ROLE`), реестры (`TAGS`,
  `FIGS`, `BADGE_OVERRIDE`) переписаны под Семинар 6 и СВЕРЕНЫ с уже написанными

- **`smoke/`** — три временных слайда (по одному на `section_divider_macro`,
  `answer_breakdown_table` с таблицей 3×3, `code_artifact`) + `smoke_build.py`,
  независимый от настоящих `slides/`/`deck.yaml`. Не удалять — пригодятся как
  регрессионная проба конвейера.
- **`RENDERER-NOTES.md`** — как собирать, полный словарь приёмов, обязательные
  поля фронтматтера, три находки-бага, известные ограничения.

## Обязательные поля фронтматтера слайда (точный список)

```yaml
id: n06                    # = префикс имени файла
type: section_divider      # семантический жанр (SVODKA-SLAIDOV.md) — НЕ влияет на вёрстку
duration_min: 0.5          # минуты, дробные
assertion: "..."           # тезис-предложение
learning_goal: "..."       # методическое обоснование — не печатается на слайде
visual:
  pattern: section_divider_macro   # ОБЯЗАТЕЛЬНО — выбирает раскладку (см. словарь ниже)
  tag: "..."                       # ОБЯЗАТЕЛЬНО для приёма section_divider_macro
  figure: имя.png                  # опционально — фаза схем ещё не начата
  primary: "..."                   # опционально, не на слайде
  backup: "..."                    # опционально, не на слайде
```

Плюс структура тела `.md` (читает `slide_parts.sections()`): ровно один `# Заголовок`
(H1), `## Assertion`, `## Visual` (содержимое слайда), `## Speaker notes`.

**Критично — `type` и `visual.pattern` это РАЗНЫЕ поля.** `type` — из словаря
`SVODKA-SLAIDOV.md` (14 имён), информационный, не читается сборщиком напрямую.
`visual.pattern` — то, что реально выбирает раскладку, и словарь его значений
**почти буквально воспроизводит словарь Семинара 5**, не упрощённый список типов:

| `type` | фактический `visual.pattern` |
|---|---|
| `hero_cover` | `hero_cover` |
| `section_divider` | `section_divider_macro` |
| `reflection_question` (с карточками выбора) | `question_with_option_cards` |
| `reflection_question` (без карточек — n04, n62) | `reflection_question` |
| `recap_table` | `recap_table` |
| `criteria_boundary` | `criteria_checklist_and_boundary` |
| `research_evidence` | `evidence_table_with_gap` |
| `answer_breakdown` | `answer_breakdown_table` |
| `cobuilding` | `cobuilding_config_reveal` |
| `code_artifact` | `code_artifact` или `file_tree_snapshot` |
| `mechanics_map` | `mechanics_table` / `mechanics_with_figure` / `mechanics_debug_toolkit` |
| `failure_vignette` | `failure_vignette` / `failure_vignette_table` / `failure_vignette_with_figure` |
| `problem_scenario` | `problem_scenario` |
| `lecture_map` | `lecture_map` |
| `base_and_edge` | `base_and_edge` |

Любой другой (новый) `visual.pattern` НЕ ломает сборку — падает в раскладку по
умолчанию (заголовок + блоки по порядку источника), просто без специализированной
композиции. Семь приёмов из таблицы выше получили собственную раскладку в
`GENRE_FN`, остальные (включая три новых варианта сверх словаря Семинара 5)
работают через раскладку по умолчанию.

## Результат смоук-теста

Три временных слайда (`smoke/x01…x03.md`) собраны, сконвертированы в PDF и PNG,
проверены всеми сторожами:

| Слайд | Приём | Проверка |
|---|---|---|
| x01 | `section_divider_macro` | градиент, роадмап-пилюли, золотой тег, номер кейса — рендерится корректно |
| x02 | `answer_breakdown_table` | таблица 3×3 заведомо неравномерной длины ячеек на ширине ~1024px **не переполняется**, высота строки считается по самой длинной ячейке строки |
| x03 | `code_artifact` | тёмная карточка растёт под листинг целиком, ограждение `markdown` превращает `` `backticks` `` в жирный прогон, а не печатает их буквально |

Сторожа по смоук-артефакту:

```
check_tracks_pdf.py       — 0 находок (по настоящему PDF)
check_text_overlap_pdf.py — 0 находок (по настоящему PDF)
audit_sluzhebnoe.py       — 0 находок (прогнано напрямую через функции, т.к. нет deck.yaml для 3 заглушек)
notes_budget.py           — 3 находки: заметки заглушек не держат двухчастный контракт
                             (речь/справка) — ОЖИДАЕМО: это техническое описание теста,
                             не речь лектора, второй части («справка») там намеренно нет
audit_sopostavleniya.py   — 11 находок «не X, а Y» в ТЕКСТЕ ЗАГЛУШЕК (сам факт проверки
                             работает правильно; содержание заглушек не редактировалось
                             литературно — это техническая проза, не материал курса)
```

Оба warning-блока (notes_budget, audit_sopostavleniya) на смоук-слайдах — подтверждение,
что сторожа **живые и реагируют на настоящий текст**, а не отчёт о дефекте: смоук-тексты
никогда не предназначались быть речью лектора или литературно выправленным текстом.

## Бонус: полная сборка настоящей деки (63 слайда)

Во время этой сессии три параллельные сессии дописали все 63 слайда
(`slides/n01.md`…`n63.md`, без дыр, без дублей). Это позволило прогнать конвейер
не только на заглушках, но и на полном реальном материале — что и выявило три
настоящих бага сборщика (см. `RENDERER-NOTES.md` § «Что починено»), не видных
на статичном чтении кода:

1. `measure()` пересказана по памяти с лишней строкой `xml.getparent().remove(xml)`,
   которой нет в оригинале build_sem05.py и которая падает всегда (у python-pptx
   `slide._element` — корень отдельной XML-части, `.getparent()` вечно `None`).
2. Бутстрап с нуля: `main()` читал `deck.yaml` до того, как мог его создать —
   в Семинаре 5 не проявлялось (там манифест существовал с первого дня).
3. `deck["slides"]` не обновлялся после пересборки манифеста — цикл сборки шёл по
   старому (на бутстрапе пустому) списку; латентно присутствует и в build_sem05.py.

После починки: **python3 build_sem06.py → 63 слайда, 8 предупреждений, 0 падений.**

```
НЕТ ГЛИФА [n21]            — символ ⏸ отсутствует в моноширинном начертании (нужна замена символа)
ПЕРЕПОЛНЕНИЕ [n61 код]     — строка кода шире карточки (ручное пробельное выравнивание колонок)
РАЗМЕТКА [n63]             — курсив *…* в ячейке таблицы (вёрстка курсив внутри строки не умеет)
ССЫЛКА В НИКУДА: n03 → n65 — n65 не существует в деке Семинара 6 (видимо, хвост от sem-05/n65)
НЕТ СХЕМЫ ×4 (n01/n41/n51/n58) — объявлены файлы схем, файлов нет (фаза схем не начата — ожидаемо)
```

По настоящему PDF (`check_tracks_pdf.py`) — ещё 2 находки, которых по `.pptx` не видно:
`n11` и `n29` — фигура заходит на строку текста (18,4pt / 14,5pt). `check_text_overlap_pdf.py`
— 0. `audit_sluzhebnoe.py` — 0 (ни надзаголовков, ни тайминга на видимом слое, ни лесов).
`audit_sopostavleniya.py` — 0,4 «не X, а Y» на 1000 слов экрана, 0,7 на 1000 слов речи
(заметно ниже исторических чисел Семинара 5/Лекции 5 до их собственной правки).

**Эти находки переданы содержательным сессиям, сам контент не правился.** Артефакты
полной сборки (`sem-06.pptx`, `deck.yaml`, `snapshots/`) оставлены в репозитории как
рабочее доказательство конвейера; `.gitignore` исключает регенерируемые `snapshots/`
и `*.pdf`.

## Известные ограничения

- **Фаза схем (`make_figures*.py`) не начата.** `FIGS = {}` в `build_sem06.py`,
  `rendered/figures/` пуст. Четыре слайда уже объявили `visual.figure` — как только
  файлы появятся, подхватятся без единой правки кода.
- **`audit_sluzhebnoe.py` требует существующий `deck.yaml` рядом с `.pptx`** — не
  принимает список приёмов аргументом. Для деки без манифеста (как смоук-тест) нужно
  звать её функции напрямую из Python (пример — в `RENDERER-NOTES.md`).
- **`criteria_checklist_and_boundary` подтверждён только при полной сборке** (6 слайдов
  в настоящей деке), не отдельным смоук-слайдом — решено не дублировать: словарь уже
  проверен на живом материале.

## Что осталось сделать после того, как слайды устоятся

1. **Рисовалки схем (`make_figures_*.py`)** — отдельная фаза, вне мандата этой сессии.
   Минимум 4 схемы уже заявлены во фронтматтере (n01 hero, n41/n51/n58 субагент).
2. **Правка 8 находок полной сборки** (глиф, переполнение строки кода, курсив в ячейке,
   висячая ссылка n03→n65) — содержательным сессиям.
3. **Две находки `check_tracks_pdf.py`** (n11, n29 — фигура режет строку) — тоже
   содержательным сессиям; это НАСТОЯЩИЙ рендер, не геометрия из `.pptx`.
4. Донаполнение заметок докладчика по контракту `notes_budget.py` (двухчастный
   шов речь/справка) — почти на всех 63 слайдах справка вне нормы 180–270 слов;
   похоже, что фаза заметок пока писалась без примерки под этот бюджет.
