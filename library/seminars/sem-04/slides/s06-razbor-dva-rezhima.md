# Два типа решений, две разные цены ошибки

## Assertion

Оба режима рабочие — вопрос в том, к какому типу решения они применяются: специфичное для проекта ждёт сигнала, универсальная гигиена заводится сразу.

## Visual

Два блока рядом:

| Специфичное для проекта — ждать сигнала | Универсальная гигиена — заводить на день 0 |
|---|---|
| обзор репозитория | гейт готовности |
| вложенные файлы конвенций | трекинг задач и решений |
| сложная, многоуровневая память | |

Внизу — разграничение:

> «Лекция 3 говорила про тонкого агента — про отказ от структурной сложности: субагентов, скиллов, внешнего доступа. Там сигнал нужен. Универсальная гигиена — другая категория: здесь «жди боли» работает против вас.»

## Speaker notes

«Единого правильного режима нет — есть два типа решений с разной ценой ошибки.

Первый тип — специфичное для проекта. Понадобится ли это именно здесь, заранее неизвестно: ответ зависит от конкретного репозитория. Обзор структуры, вложенные файлы конвенций, многоуровневая память — сюда. Ждать реального сигнала здесь не лень, а нормальная инженерная практика: пока сигнала нет, записывать нечего.

Второй тип — универсальная гигиена. Завести дёшево, а цена отсутствия непредсказуема: неизвестно, в какой момент она понадобится и что к этому моменту будет потеряно. Гейт готовности, трекинг задач и решений — сюда. Сигнала здесь можно и не дождаться: недостача проявляется постфактум, а не одним явным событием.

Отдельно — чтобы не смешивать с Лекцией 3. Тезис про тонкого агента был про структурную сложность: субагенты, скиллы, внешний доступ. Он в силе и по-прежнему требует сигнала. Универсальная гигиена — другой класс решений.

Дальше в проекте нас ждут шесть развилок. К какому типу относится каждая — решаем по ходу, на месте.»
