# Один файл: план, лог хода, результаты

## Assertion

Файл задачи ссылается на журнал решений, а не дублирует его — и это осознанное упрощение паттерна, полностью раскрываемого в другом месте.

## Visual

Путь: `.tasks/active/signup-wizard.md`

```markdown
# Задача: разбить форму на пошаговый визард

## План
1. [x] Разметка трёх шагов (имя / email / подтверждение)
2. [x] Перенос текущей валидации без изменений
3. [ ] Состояние текущего шага (JS)
4. [ ] Кнопки «назад»/«далее»
5. [ ] Тесты на переключение шагов
6. [ ] Ручная проверка полного прохождения

## Лог хода
- 2026-09-20: шаги 1–2 закрыты. Договорились НЕ трогать email-валидацию — она уже
  обсуждалась в DECISIONS.md (2026-09-20), это отдельное решение, тут просто перенос.
- 2026-09-22: начат шаг 3, не закончен — контекст сжат в середине.

## Результаты (заполняется по завершении)
—
```

Подпись под примером: иллюстративный пример, не захваченный вживую — ждёт реальной многошаговой сессии владельца. Отдельная строка: упрощение до файла — масштабируется до папки на задачу, подробнее раскрыто за пределами этого занятия.

## Speaker notes

Один файл на задачу: план, лог хода, результаты. Пример на слайде — иллюстративный, не из захваченного репозитория, ждёт живой сессии. Обратить внимание на лог: там прямо написано, что в этой сессии договорились не трогать email-валидацию, потому что это уже отдельное решение из `DECISIONS.md` — файл задачи ссылается на журнал решений, а не дублирует его.

Явная оговорка: это упрощённая версия паттерна. В реальной практике это масштабируется до папки на задачу — отдельный план, отдельный лог, отдельная папка результатов, особенно когда задача не линейная. Для сегодняшнего занятия одного файла достаточно — не усложняем.

По завершении задачи файл переносится в архив задач или удаляется, если ценности после задачи не несёт, — архивирование, а не хранение навсегда: главное отличие от `DECISIONS.md`, который никогда не архивируется и не удаляется.
