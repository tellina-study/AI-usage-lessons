# Вычёркиваем права

## Assertion

Из всего, что даёт широкий персональный токен, нашему списку операций нужен один репозиторий и две операции.

## Visual

Слева — список операций, фиксируется по мере называния залом:

1. читать открытые issue;
2. писать комментарий к issue;
3. создавать черновик правки.

Справа — что даёт широкий персональный токен по умолчанию, со сквозным вычёркиванием:

- ~~**все репозитории пользователя, включая приватные**~~ (перечёркнуто заметнее прочих)
- ~~чтение **и запись**~~ → только нужное
- ~~управление настройками~~
- ~~удаление~~

Остаётся подсвеченным: **один репозиторий · чтение issue · создание черновика правки**.

Внизу — реплика на экране: «Запомните вид этого экрана».

## Speaker notes

Структура хода принципиальна: файл пишется последним. Если начать с файла, разговор неизбежно уйдёт в синтаксис, а весь смысл раздела — в двух решениях, которые принимаются до синтаксиса.

Ход первый быстрый: «что конкретно агент должен уметь?» Зал перечисляет, фасилитатор фиксирует три операции. Всё. Ничего про удаление, ничего про настройки репозитория, ничего про другие репозитории.

Ход второй — сердце раздела. На слайде список того, что даёт широкий персональный токен по умолчанию, и фасилитатор идёт по строкам, спрашивая про каждую: «наш список из трёх операций этого требует?»

Вычёркивание происходит на экране, строка за строкой. Это важно делать именно вычёркиванием, а не заменой списка: зал должен видеть объём того, что отдаётся по умолчанию, и объём того, что реально нужно, одновременно.

Остаётся один репозиторий и две операции.

И реплика, ради которой ход существует:

«Запомните, как выглядит этот экран сейчас. Через пять минут я покажу вам инцидент, который воспроизводится ровно тогда, когда верхняя строка не вычеркнута.»

Верхняя строка — «все репозитории пользователя, включая приватные». Её перечёркивание стоит сделать самым заметным на экране.
