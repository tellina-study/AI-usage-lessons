# The "file vs folder" criterion

## Assertion

One file per task is enough as long as the task is linear and one agent and one developer are running it — otherwise moving to a folder is justified.

## Visual

Checklist:

- The task is linear: the steps run in order, not in parallel.
- One agent is working (no subagents / parallel branches) and one developer.
- The progress log fits into a file of a reasonable size (hundreds of lines, not thousands) without becoming unreadable.
- There are few results and output artifacts — no need for a separate file for each.

Below — the bridge into section 3: "Let us draw a line under the memory section. Three cases — three different answers to the question 'what happens when a session ends'. The first and the third we set up right away, on day 0. The second is a reactive step. But all three are text that the agent reads and can take into account."

## Speaker notes

"If at least half of these points are false, moving to a folder per task is justified. That is already beyond today's session — it is covered in detail in Lecture 3.

Let us draw a line under the memory section. Three cases — three different answers to the question 'what happens when a session ends': a decision stays for good in a flat log; the decisions become too many and grow a structure around themselves; and the progress of one task lives exactly as long as the task does, in a separate file. The first and the third we set up right away, on day 0, because it is cheap. The second is a reactive step, because you cannot know in advance whether your particular decision log will grow to the volume that requires it.

But all three are text that the agent reads and can take into account. 'Can', precisely — not 'will'. Later in this session we will look at what happens when reading stops being enough."
