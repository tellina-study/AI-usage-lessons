# Четыре типа провалов на дискретном

## Тип 1: Чрезмерная автоматизация (replace, не augment)

**Кейс:** Tesla 2018. «Excessive automation a mistake».

**Где видно:** попытки заменить рабочих там, где variability — feature.

**Урок:** augment, не replace. Toyota Jidoka 2.0.

## Тип 2: Сдвиг распределения при смене продукта

**Кейс:** CV-инспекция, обученная на модели A, на модели B без дообучения.

**Где видно:** заводы с 5+ моделями; редкие конфигурации; новые поставщики.

**Урок:** план дообучения; baseline drift детектор; rules-based fallback.

## Тип 3: Scarce labels + class imbalance

**Кейс:** rare defect types (1 на 10000); cost разметки доминирует.

**Где видно:** все CV-проекты в дискретном. Boeing 737 door-plug — крайний случай где CV не видит закрытое.

**Урок:** physical signal amplification + rules ДО ML. Hybrid pipeline.

## Тип 4: Vendor self-claim без baseline

**Кейс:** Foxconn «80%»; Tata Steel «–20% downtime»; BMW AIQX without OEE breakdown.

**Где видно:** любая презентация вендора.

**Урок:** 3 вопроса (baseline / окно / вмешательства) + OEE-вопрос.

## Speaker notes

Резюме раздела 2 — failure-pattern matrix дискретного производства. Четыре типа провалов, которые мы только что разобрали. Запомните их таксономически — это поможет вам распознавать паттерны в новых кейсах.

Тип 1 — чрезмерная автоматизация. Попытка заменить человека там, где variability — это feature, не bug. Канонический кейс: Tesla 2018 с её demontированным конвейером Model 3 и роботом-fluffer. Где это видно у вас: любая попытка автоматизации без сохранения человека в петле для нештатных ситуаций. Урок: augment, не replace. Toyota Jidoka 2.0 — модель.

Тип 2 — сдвиг распределения при смене продукта. CV-инспекция, обученная на модели A, плохо работает на модели B. Где видно: заводы с 5 или более моделями, редкие конфигурации, смена поставщика, новый стандарт деталей. Урок: план дообучения с самого начала; baseline drift детектор; rules-based fallback на случай, когда CV-инспекция деградирует.

Тип 3 — scarce labels и class imbalance. Рарые типы дефектов, 1 на 10 тысяч деталей. Стоимость разметки доминирует. Самый крайний кейс — Boeing 737 door-plug, где CV не видит то, что закрыто обшивкой, и upstream-документация не зафиксировала, что болты не были поставлены. Урок: physical signal amplification — структурированный свет, рентген, тепловидение, поляризованный свет — потом rules-based для controlled situations, и только потом ML на остатке.

Тип 4 — vendor self-claim без baseline. «80 процентов работы делает AI», «снижение downtime на 25 процентов», «AIQX даёт прогнозирование без указания OEE-канала». Где видно: любая презентация вендора. Урок: три вопроса — baseline до AI, окно измерения, перечень вмешательств. Плюс четвёртый OEE-вопрос — какой компонент эффективности улучшается.

Запомните эти четыре типа. В §4 они станут конкретными критериями категорий «человек», «данные», «стоимость». Failure-matrix дискретного — это эмпирическая база для категорий рамки решения.
