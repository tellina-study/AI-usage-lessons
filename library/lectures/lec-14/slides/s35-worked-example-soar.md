# Разбор: «Вендор предлагает SOAR auto-block для phishing»

## Visible content

Sub: «Применяем 6 критериев пошагово. Что должно стать вашим первым ответом?»

6 чеков в сетке 2×3:
1. Нормативные требования? Email напрямую не под PCI-DSS / HIPAA. → ✓ ОК
2. Аудит-трейл (forensic)? Авто-блок может стирать следы для расследования. → ⚠ оговорка
3. Бюджет задержки? Email — асинхронный канал, задержка ОК. → ✓ ОК
4. Байес / частота FP? 100 тыс. email/день × 0,1% FP = 100 ложных блоков/день. → ✗ блок
5. Аппаратные / крипто-примитивы? Не применимо. → ✓ ОК
6. Малый масштаб? Корпоративный масштаб → не SMB. → ✓ ОК

Внизу — ВЕРДИКТ (gold-tint):
«Человек в контуре обязателен — авто-флаг, не авто-блок»
• AI помечает подозрительные email (авто-флаг) → аналитик проверяет (HITL)
• Авто-блок только для эталонных сигнатур malware (rule-based, не ML)
• 100 ложных блоков/день > стоимость аналитика на проверке — Байес решил это за вас

## Speaker notes

Worked example. Реальный сценарий: вендор приходит и предлагает SOAR auto-block для phishing-email. То есть SOAR (Security Orchestration, Automation, Response) платформа на ML автоматически блокирует email, который классифицировала как phishing.

Применяем шесть критериев пошагово.

Один. Compliance hardline. Email — не PCI-DSS напрямую (это карточные данные). Не HIPAA (это медицинские данные). Не SOX (финансовая отчётность). OK.

Два. Forensic chain. Тут caveat. Если auto-block удалил подозрительный email, у вас не остаётся artifact для расследования. Нужен audit trail — где-то лежит копия каждого blocked сообщения для forensic анализа. Дополнительный requirement, не блокирующий.

Три. Latency budget. Email — асинхронный канал. Десять секунд delay приемлемо. OK.

Четыре. Bayes math, false positive rate. Это критический check. Корпоративный inbox — сто тысяч email в день. Если ML-классификатор имеет false positive rate 0,1% — это сто ложных блоков в день. Сто легитимных писем не доставлено. Каждый день. Это блок. Не «незначительный шум», блок.

Пять. Crypto primitives. Не применимо. OK.

Шесть. Малый scope. Не SMB, корпоративный масштаб. OK.

Чек четыре failed. Один failed критерий — auto-block выключается.

Вердикт. HITL required. Auto-flag вместо auto-block. AI помечает подозрительные emails — аналитик быстро проверяет очередь. Это уровень «Решает», не «Действует».

Дополнительно: auto-block разрешён только для exact malware signatures (rule-based, не ML). То есть если файл с known malicious hash — блокируем без человека. Если поведенческий «подозрительный паттерн» — flag, не block.

Сто ложных блоков в день превышают стоимость аналитика на проверку очереди. Bayes решил это за вас. Это и есть рамка решения в действии.
