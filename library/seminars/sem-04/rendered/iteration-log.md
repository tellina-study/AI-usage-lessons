### Архитектура пересборки — block-transplant, не построчные правки

Вместо ручных правок 2601-строчного файла построчно, применена программная
пересборка (Python-скрипт `/tmp/assemble.py`, не коммитится — служебный инструмент
сессии): каждая функция `build_sXX`/общий helper old-файла распознана по regex
`^def \w+\(`/`^[A-Z_]+ = ` в топ-левел блоки с точными диапазонами строк, затем
собрана новая последовательность по списку `SEQ` из 76 записей (72 `build_sNN` +
4 переиспользуемых helper'а `two_basket_frame`/`cobuilding_map`/`scenario_top_text`/
`basket_row`, все — без изменений, на прежних относительных позициях) в трёх режимах:
- **verbatim** — блок копируется 1:1 (s01, s03, s07, s08, s09 — содержимое не
  менялось никогда, s08 менялся только в speaker notes, которые подгружаются
  автоматически через `load_notes(slide_id)` по glob `slides/{id}-*.md`, так что
  код-функция осталась той же строкой);
- **rename** — блок копируется с ровно одной подстановкой литерала `"sOLD"` →
  `"sNEW"` (это либо `load_notes("sOLD")`, либо, для 7 дивайдеров, второй позиционный
  аргумент `build_stage_divider(p, "sOLD", ...)` — обе формы сведены к одному
  regex-safe правилу с `assert count == 1` перед заменой, чтобы неверная подстановка
  падала явно, а не портила слайд молча);
- **new** — 18 функций написаны заново вручную (см. ниже) и подставлены как есть.

Скрипт содержит sanity-assert'ы: все 58 старых блоков, помеченных к переносу,
использованы **ровно один раз** (никакой блок не пропущен и не задвоен), новых
функций **ровно 18** и их имена совпадают с ожидаемым набором. Оба ассерта ловят
класс ошибки «забыл слайд» / «случайно скопировал не туда» на этапе сборки файла,
до первого рендера.
