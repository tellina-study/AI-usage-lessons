# Visible content

## Title bar
Дисциплина заранее — быстрый и предсказуемый результат; без неё отказ ожидаем, а не случаен

## Body
[Слева — AWS Kiro, успех дисциплины]

**AWS Kiro · life sciences (2026).** Production-ready агент для поиска терапевтических мишеней построен через spec-first workflow: спецификация → пошаговое исполнение по вехам → верификация против спеки.

**3 недели, 3 разработчика** — не растянутый цикл ad-hoc-промптинга.

*Опубликованный вендором кейс-стади, клиент анонимизирован — MEDIUM confidence, иллюстрация дисциплины, не обобщаемая статистика.*

[Справа — контраст, пропуск дисциплины]

**847 задокументированных внедрений AI-агентов** (один агрегированный обзор, методология выборки не раскрыта).

**76% провалились в течение 90 дней.** Корневая причина по источнику — **провал спецификации**, не неспособность модели.

*Методология выборки не раскрыта — LOW-MEDIUM confidence, используется только как иллюстрация направления тезиса, не как измеренный факт.*

[Снизу — SDD как термин]
Отрасль называет эту дисциплину **Spec-Driven Development (SDD)**: GitHub Spec Kit (~90 тыс. звёзд), к 2026 — минимум **8** крупных инструментов с собственным вариантом практики.

[Gold callout]
Дисциплина, применённая заранее, — не гарантия, а сдвиг вероятности: там, где спецификация намерения выстроена под понятный критерий, отказ становится исключением, а не статистически ожидаемым исходом.

## Speaker notes

Два примера рядом — не случайное сопоставление, а иллюстрация одного тезиса: результат зависит не от того, использовали AI или нет, а от того, применили ли дисциплину spec-driven заранее. Опубликованный AWS-кейс из области life sciences показывает команду, построившую готовый к продакшену агент для поиска терапевтических мишеней через spec-first воркфлоу — спецификация, пошаговое исполнение по вехам, верификация результата против спеки — и уложившуюся в три недели силами трёх разработчиков. Честная оговорка: это опубликованный вендором кейс-стади, а не независимо аудированное исследование, конкретный клиент анонимизирован — держим как MEDIUM-confidence иллюстрацию дисциплины, применённой осознанно, не как обобщаемый факт.

Для контраста — обратная сторона статистики, с той же осторожностью к источнику. Один агрегированный обзор называет 847 задокументированных внедрений AI-агентов и долю 76%, провалившихся в течение 90 дней; корневой причиной он называет не техническую неспособность модели, а провал спецификации — намерение организации не было специфицировано настолько точно, чтобы его вообще можно было проверить. Методология выборки источником не раскрыта — эту цифру нельзя цитировать как аудированную статистику, только как иллюстрацию направления тезиса. Пара кейсов вместе не совпадение: где дисциплину выстроили заранее под понятный критерий, результат предсказуем и быстр; где решение «применять AI» приняли без спецификации намерения, отказ — статистически ожидаемый исход. Отрасль называет эту дисциплину термином SDD (Spec-Driven Development) — GitHub Spec Kit и AWS Kiro задали мейнстримное значение, и к 2026 году минимум восемь крупных вендоров выпустили собственный вариант практики.
