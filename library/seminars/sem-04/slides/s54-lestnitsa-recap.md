# Лестница целиком, ещё раз

## Assertion

Семь ступеней — один и тот же принцип: добавляем по боли, не про запас.

## Visual

Таблица на всю ширину слайда, семь строк:

| Ступень | Что добавляем | Критерий «ещё рано» |
|---|---|---|
| 1. Файл инструкций | `CLAUDE.md`/`AGENTS.md` | Агент справляется, репозиторий маленький |
| 2. Память | `/memory` + `DECISIONS.md` | Хватило одной-двух сессий |
| 3. Хуки | `.claude/settings.json` | Проверка дешевле в CI |
| 4. Скиллы | `.claude/skills/<имя>/SKILL.md` | Нужно каждой сессии — это часть файла инструкций |
| 5. MCP | `.mcp.json` | Хватает обычной команды через Bash |
| 6. Субагенты | `.claude/agents/<имя>.md` | Шаги зависимы, нужен общий контекст |
| 7. Процесс | План + прожарка + `Tasks/<дата>_<slug>/` | Diff — одна фраза, откат дешевле проверки |

Слайд повторяет опорную таблицу раздела 0 без изменений — это тот же слайд, показанный второй раз.

## Speaker notes

Это та же таблица, что вы видели в самом начале занятия. Каждая её строка — раздел, который вы сегодня прошли на одном и том же сайте: лендинге с формой заявки на демо-урок. Файл инструкций появился, когда агент второй раз переспрашивал то, что ему уже объясняли. Память — когда то же самое приходилось объяснять второй раз в новой сессии. Хуки — когда правило было записано словами, но агент его нарушал. Скиллы — когда файл инструкций начал облагать налогом каждый запрос процедурой, нужной не всегда. MCP — когда понадобился живой, повторяющийся доступ к внешней системе. Субагенты — когда повторяющаяся роль перестала нуждаться в общем контексте с основной сессией. И процесс — когда работу агента начали принимать на слово, без проверки.

Ни одна ступень не была добавлена заранее, про запас — каждая появилась ровно тогда, когда стало больно без неё, и в каждой строке рядом есть критерий, который говорит, когда добавлять ещё рано. Это и есть основная идея занятия, если сжать её до одного принципа: конфигурация — не коллекция «на всякий случай», каждый блок платит за себя контекстом в каждом запросе, нужен он сейчас агенту или нет.

Дальше — ссылка на репозиторий, где все семь блоков собраны вместе, и один вопрос, который вы забираете с собой.

Стоит отдельно отметить: порядок ступеней в таблице — это порядок появления в сегодняшнем сценарии, а не жёсткая последовательность, обязательная для любого проекта. В вашем собственном репозитории боль может прийти не в этом порядке — например, MCP может понадобиться раньше скиллов, если внешняя система нужна с самого начала. Важен не порядок, а сам принцип: каждая ступень появляется по конкретному триггеру, который вы можете назвать словами, а не по ощущению «наверное, пригодится».
