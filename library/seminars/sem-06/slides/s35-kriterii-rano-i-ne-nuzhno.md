# Ещё рано — и не нужно вообще

## Assertion

Полный цикл вердикта не нужен, когда diff описывается одним предложением или откат дешевле проверки; и совсем не нужен там, где критерий формализуем исполняемой проверкой — или где файл задачи никто не читает.

## Visual

**«Ещё рано»:**
- diff можно описать одним предложением — план и отдельный цикл не нужны
- откат дешевле повторной проверки — барьер не окупается
- запись — факт, а не решение — дописывается напрямую в файл задачи, без цикла ветка → PR → ревью
- третий круг ревью на одном артефакте — сигнал чинить конструкцию, не продолжать ревью

**«Не нужно вообще»:**
- критерий формализуем без суждения человека — не текстовый вердикт, а исполняемая проверка: сборка проходит, файл существует, тест зелёный
- сам файл задачи, который никто не читает — вопрос: когда запись в нём в последний раз реально изменила чьё-то действие?

## Speaker notes

Когда этого не нужно в полном объёме. Diff описывается одним предложением — план и отдельный цикл не нужны. Откат дешевле повторной проверки — барьер не окупается. Факт дописывается напрямую в файл задачи, без цикла ветка-PR-ревью — это резервируется для решений. Третий круг ревью на одном артефакте — чините конструкцию, а не продолжайте ревью.

И два случая, где не нужно вообще. Первый: если критерий формализуем без суждения человека — не текстовый вердикт нужен, а исполняемая проверка. Сборка прошла, файл существует, тест зелёный — это гейт для CI, который срабатывает сам. Текстовый вердикт нужен там, где формализовать нечем — где решение требует суждения человека.

И второй, неудобный: сам файл задачи, который никто не читает. Спросите себя: когда в последний раз запись в файле задачи реально изменила чьё-то действие — а не была написана и забыта?
