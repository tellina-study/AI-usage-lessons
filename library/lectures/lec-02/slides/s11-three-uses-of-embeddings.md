## Speaker notes

Из того, что эмбеддинги дают численную меру семантической близости, естественно вырастают три практических применения. Это рамка, на которую опирается весь Раздел 3 курса — Лекция 3 про RAG, Семинар 3, Лекция 4 и далее.

Первое применение — **similarity**, поиск похожих. У вас есть документ и хранилище из тысяч похожих документов; нужно найти, на какие из них новый документ наиболее похож. Для каждого документа из хранилища предвычислены эмбеддинги; для нового документа эмбеддинг считается на лету; парные cosine similarity ранжируют хранилище по убыванию. Это базовый механизм поиска похожих тикетов в системе поддержки, похожих кейсов в юридической базе, похожих резюме в HR-системе.

Второе применение — **clustering**, кластеризация. У вас есть набор документов без явной разметки, и нужно автоматически разбить их на группы. Каждый документ переведён в эмбеддинг; алгоритм кластеризации — например, k-means, итеративный алгоритм, разбивающий точки на заданное число групп так, чтобы точки внутри группы были близки — находит группы в эмбеддинг-пространстве. На выходе получаются кластеры документов, объединённых по смыслу. Это используется для анализа жалоб клиентов («какие типы проблем встречаются»), для тематической группировки больших корпусов, для exploratory analysis новых данных.

Третье применение — **search**, семантический поиск. Это расширение similarity на сценарий «вопрос → база ответов». Пользователь задаёт вопрос в свободной форме; вопрос переводится в эмбеддинг; ищем близкие эмбеддинги в проиндексированной базе документов; возвращаем top-K. Это основа RAG (Retrieval-Augmented Generation), который мы разбираем в Лекции 3. На уровне эмбеддингов RAG — это просто семантический поиск с последующей передачей найденного как контекст в LLM.

Эти три применения часто комбинируются: корпоративная база знаний может одновременно использовать similarity для рекомендаций, clustering для автоматических разделов и search для интерактивного поиска. Под капотом — одни и те же эмбеддинги. Это объясняет, почему эмбеддинг-модель — это инфраструктурный выбор, а не «одна из фич»: один выбор обслуживает сразу несколько продуктовых функций.
