# Настоящий холст: одиннадцать узлов одного прогона

## Assertion

Документ и вопрос входят один раз, дальше холст делает и иерархическую резку, и семантическую — в одной последовательной цепочке, без выдуманной схемы.

## Visual

Документ + вопрос → Нарезка иерархическая: дети + родитель → Эмбеддинг вопроса и детей (text-embedding-3-small) → Поиск top-1 ребёнка (cosine) → Подстановка родителя → Ответ модели по родителю (gpt-4o-mini) → Разбор ответа → Нарезка семантическая: предложения → Эмбеддинг предложений (text-embedding-3-small) → Разрыв смысла и порог (gap_threshold) → Результат.

> Ни резка, ни поиск, ни подстановка родителя не вызывают модель — все три шага обычный код. Модель вызывается дважды: один раз для эмбеддинга (поиск и смысловой разрыв), один раз для самого ответа.

## Speaker notes

На экране — настоящий холст живого стенда, не рисованная схема. Одиннадцать узлов в одну линию: документ и вопрос входят один раз в начале, а дальше холст последовательно делает всё, что нужно для обоих приёмов предыдущего такта.

Сначала — иерархическая резка: документ режется на маленькие кусочки для поиска, вопрос и кусочки отправляются на эмбеддинг одним HTTP-запросом к модели `text-embedding-3-small`, код находит ближайший по смыслу кусочек через косинусное сходство, и следующий узел — «Подстановка родителя» — заменяет этот найденный мелкий кусочек на документ целиком, прежде чем передать текст модели `gpt-4o-mini` для ответа. Узел «Разбор ответа» достаёт готовый текст из ответа модели.

Дальше, в этом же прогоне, холст делает семантическую резку: документ режется на предложения, каждое из них отправляется на эмбеддинг тем же способом, код считает косинусный разрыв между соседними предложениями и режет кусок там, где этот разрыв превышает заданный порог. Экран результата в конце показывает оба исхода сразу: ответ модели по родительскому документу и то, на сколько кусков семантическая резка разбила тот же самый документ при заданном пороге.

Важная деталь устройства: обе резки идут одной последовательной цепочкой, а не двумя параллельными ветками холста. Причина не художественная — у формы с экраном результата в n8n только один канал ответа, и вторая параллельная ветка с собственным экраном результата на том же триггере оставляет прогон висеть в ожидании навсегда. Это не гипотетическая оговорка — ровно так холст и вёл себя на первой сборке этой сессии, пока цепочку не выстроили в одну линию.

Документ и вопрос на экране взяты из настоящего замера: это один из шестидесяти документов и один из семидесяти двух вопросов того самого замера, числа которого разбираются дальше. Какой ответ модель дала здесь и что получилось при живом вызове — следующими двумя тактами, с развёрнутыми панелями самих узлов.
