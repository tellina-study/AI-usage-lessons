# Механизм загрузки — и разбор

## Assertion

Вложенный файл грузится on-demand, только по факту чтения — не по факту нахождения в папке; контролируемое исследование не нашло пользы от разбиения, а практика показывает регулярные отказы вплоть до архитектурного предела.

## Visual

Механизм (офиц. документация Claude Code): корневой и все родительские `CLAUDE.md` грузятся при старте сессии автоматически. Вложенные грузятся on-demand — только когда агент реально читает файл оттуда. `/context` — единственный надёжный способ проверить, что реально загружено.

| Источник | Тезис | Сила |
|---|---|---|
| McMillan, arXiv:2605.10039 (1650 сессий Claude Code CLI) | Ни одна из 4 структурных переменных не дала значимого эффекта; для size/conflict — свидетельство ОТСУТСТВИЯ эффекта | Сильное и контринтуитивное |
| Claude Code #2571 | Вложенный CLAUDE.md не подхватывается автоматически, воспроизводимо; закрыт «not planned» | Прямое наблюдение |
| Claude Code #6972 | Документация вводит в заблуждение — пользователи ждут eager-загрузку | Прямое наблюдение |
| Cursor, форум | Сотрудник Cursor признал баг в nested-функциональности | Прямое, другой инструмент |
| Codex CLI #13288, #12115 | Ненадёжная подгрузка без явного --cd | Прямое, другой инструмент |
| **GitHub Copilot CLI #3051** | Не баг, а документированный структурный предел: discovery только вдоль прямого пути cwd→git-root | Самое жёсткое: архитектурное ограничение |

**Разбор пяти карточек зала:**

| Вариант | Где работает | Почему рано — и что вместо |
|---|---|---|
| «Доверюсь автозагрузке» | Никогда гарантированно | Вложенные файлы грузятся on-demand. Задокументированные отказы — системная категория |
| «Явно попрошу прочитать» | Работает, требует ручной дисциплины | Надёжнее автозагрузки, но перекладывает ответственность на человека |
| «Продублирую в корневой» | Работает всегда — корень грузится при старте | Снова presence paradox: продублированная строка стоит контекста везде |
| «Проверю через /context» | Единственный способ узнать факт | Диагностика, не решение |
| **«Объединю в один файл в корне»** | **Здесь и сейчас — репозиторий маленький** | **Целевой ответ.** Исследование не нашло значимого эффекта ни у одной структурной переменной |

## Speaker notes

«Механизм устроен конкретно, не расплывчато. Корневой файл и все родительские грузятся при старте сессии, всегда. Вложенный — только когда агент реально прочитал файл из этой папки, а не когда он просто "работает в ней". И вот эмпирика: самое близкое к нашему вопросу контролируемое исследование, тысяча шестьсот пятьдесят сессий, не нашло значимого эффекта ни у одной структурной переменной. А отдельно — список реальных issue: Claude Code, Cursor, Codex, Copilot CLI. Везде одна и та же жалоба, вплоть до жёсткого архитектурного предела в одном из инструментов.

Проверяем, кто угадал: "положу и доверюсь" — вот номер issue, где именно это не сработало, и мейнтейнеры закрыли его "not planned". Смотрите на два пункта одновременно: контролируемое исследование не нашло пользы даже там, где здравый смысл её обещал — а реальная практика показывает регулярные отказы, вплоть до архитектурного предела в одном инструменте. При таком репозитории, как наш, вывод простой — один файл в корне, пока он не стал реально неудобным. И даже тогда — не молчаливое разбиение, а проверенное: /context или прямое наблюдение.»
