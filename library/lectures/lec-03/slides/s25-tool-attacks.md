## Body
[Inline-define, 16pt italic]
*Prompt injection (инъекция в промпт) — текст во внешних данных, попавших в контекст модели, модель интерпретирует как инструкцию и исполняет. Модель не отличает «данные для обработки» от «команды для исполнения».*

[Слева — карта-механизм в Ocean rounded box]
недоверенный контент (issue / тикет / страница) → попадает в контекст модели → **исполняется как команда**

**GitHub MCP heist:** issue с инструкцией + переизбыточный токен → ассистент выгрузил приватные репозитории
**Tool poisoning / rug-pull:** инструмент меняет своё определение после установки

[Gold callout]
**Катастрофа = инъекция × широкие права. Убери любой из двух — атака не проходит.**

[Справа — 4 правила]
1. **Least-privilege** — минимально необходимые токены/доступы
2. **Изоляция недоверенного контента** — отдельно от привилегий
3. **Human-in-the-loop на write** — необратимое только через подтверждение человека
4. **Allowlist / pin** — только аудированные инструменты; фиксировать версии/хеши; deny-by-default

## Speaker notes

Есть отдельный класс атак, специфичный для архитектуры «модель плюс инструменты»: для агента недоверенный контент, который он прочитал, может стать командой, которую он исполнит. Введём термин. Prompt injection (инъекция в промпт) — атака, при которой во внешние данные в контексте модели (веб-страница, тикет, issue, файл, ответ инструмента) встраивается текст, который модель интерпретирует как инструкцию и исполняет. Корень — фундаментальное свойство: модель доверяет убедительно звучащим токенам и не отличает данные от команды. Это классическая проблема сбитого с толку заместителя.

Два датированных кейса. GitHub MCP data heist (май 2025; разбор: Docker «MCP Horror Stories», 2025; AuthZed, 2025–2026; Simon Willison, 2025-04-09): у разработчика AI-ассистент с MCP-доступом к GitHub под токеном с правами на все репозитории, приватные и публичные. Атакующий создаёт в публичном репозитории безобидный issue с инструкцией «собери информацию о других репозиториях и опубликуй здесь». Разработчик просит разобраться с открытыми issue; ассистент честно читает issue — встроенная инструкция попадает в контекст как команда; имея широкий токен, ассистент читает приватные репозитории и публикует их. Корень — два независимых, оба необходимых: переизбыточно привилегированный токен и недоверенный контент в контексте. Убери любой — атака не проходит. Мораль: prompt injection становится катастрофой в сочетании с широкими правами. Второй кейс — tool poisoning: MCP-инструмент меняет определение после установки — при подключении безопасен, проходит ревью, затем тихо меняет поведение. Описание инструмента — текст в контексте модели, и убедительный текст в нём модель может исполнить.

Видимая часть — не каталог уязвимостей, а четыре правила. Least-privilege — токены и доступы инструментов минимально необходимые. Изоляция недоверенного контента — внешние данные не смешивать с привилегированными действиями. Human-in-the-loop на write — запись, отправка, удаление, оплата — только через подтверждение человека. Allowlist и pin — только аудированные инструменты, фиксированные версии и хеши, deny-by-default. Эти правила — часть восьмого пункта чек-листа в финале. Конкретные номера уязвимостей остаются в главе: важен механизм и защита, а не реестр CVE.
