# Провал: агент вместо RAG

## Assertion

Агент вместо RAG — тот же результат дороже, медленнее, менее аудируемо.

## Speaker notes

Представим команду, которая для этой же задачи выбрала не RAG, а полноценного агента с циклом план→действие→проверка→повтор: агент сам решает, какие документы открыть, читает их по очереди, при необходимости перечитывает ещё раз, чтобы убедиться, и в конце формулирует ответ. Формально агент тоже может найти нужный пункт договора. В чём цена этого выбора?

Дайте себе 10-15 секунд подумать молча, затем — прямой вопрос классу, ждём минимум два ответа: по каким из четырёх критериев агент здесь хуже, чем RAG, при том же самом результате?

Ожидаемые направления ответа: шаги — агент добавляет многошаговый цикл там, где RAG делает один проход retrieval плюс один проход генерации; если агент делает, скажем, 5 шагов вместо 1-2 шагов RAG, риск накопления ошибки складывается мультипликативно — 0.99⁵ примерно 95% против примерно 99% у RAG-конвейера из 1-2 шагов, а на юридической задаче цена ошибки высокая. Стоимость — каждый шаг цикла это отдельный вызов модели; агент тратит кратно больше токенов, не получая взамен более точного результата, задача не требует динамического непредсказуемого маршрута, значит переплата не покупает ничего. Контроль — цикл агента даёт худшую аудируемость: сложнее восстановить, почему агент открыл именно эти документы и в этом порядке, чем в RAG, где шаг retrieval — один прозрачный проход поиска с понятным списком извлечённых фрагментов.

Вывод: задача «найти пункт в архиве по смыслу запроса» не является многошаговой по своей природе — это классический профиль retrieval, а не динамического планирования. Агент здесь не «мощнее» RAG, он просто дороже, медленнее и менее аудируем при том же результате. Это прямое приложение правила лестницы: подниматься на ступень выше нужно только при требовании, которого нижняя ступень не закрывает, а здесь такого требования нет.

Мост к Кейсу 2: в Кейсе 1 у задачи не было потребности в действиях — только в чтении и поиске. В Кейсе 2 появляется новый элемент: боту нужно не только читать, но иногда и писать — создавать тикеты. Это меняет расклад.
