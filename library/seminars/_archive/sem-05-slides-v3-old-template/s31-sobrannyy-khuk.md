# Хук целиком

## Assertion

Собранный хук — обычный файл проекта, который коммитится и работает в любом свежем клоне без шага установки.

## Visual

Слева — тело хука, с пометками, какой ответ зала за какой фрагмент отвечает:

```jsonc
{
  "hooks": {
    "PreToolUse": [                          // ← 1: до вызова
      {
        "matcher": "Bash",                   // ← 2: только команды оболочки
        "hooks": [
          {
            "type": "command",
            "command": "jq -r '.tool_input.command' | …
                        grep -qE '(^|[;&|]\\s*)git\\s+commit\\b'   // ← 3: команда из JSON
                        … git rev-parse --is-inside-work-tree … → \"ask\"  // ← 5
                        branch=$(git symbolic-ref --short HEAD)    // ← 4
                        … [ \"$branch\" = \"main\" ] → \"deny\" …",
            "timeout": 10
          }
        ]
      }
    ]
  }
}
```

Справа сверху — дерево ступени 3, `.claude/settings.json` выделен gold.

Справа снизу — четыре факта: это не git-хук, он версионируется и активен в свежем клоне · решение возвращается полем `allow`/`deny`/`ask` · **код возврата 2 блокирует безусловно, даже поверх `allow`** · списки хуков между уровнями настроек объединяются, а не перекрываются.

## Speaker notes

Собранный хук — это ровно те пять решений, которые зал только что принял, записанные в файл. Стоит показать соответствие явно: каждый фрагмент помечен номером вопроса.

Четыре факта механики, коротко.

Первое и главное: это не git-хук. Обычный `pre-commit` в `.git/hooks/` не версионируется — чтобы он заработал у коллеги, кто-то должен вручную скопировать файл в каждый новый клон. Хук агента живёт в обычном файле проекта, коммитится и активен в любом свежем клоне без шага установки. Разница не теоретическая: в задокументированном наблюдении ручной `pre-commit` простоял неустановленным тринадцать дней после запуска реального проекта, тогда как git-трекнутый хук разошёлся без единого разрыва.

Второе: решение возвращается структурой с полем решения о разрешении — `allow`, `deny` или `ask`. И отдельно: код возврата 2 блокирует безусловно, даже если тот же хук в том же ответе вернул `allow`. Код возврата побеждает содержимое ответа.

Третье: явный запрет в списке разрешений всегда побеждает разрешение, даже более узкое и точное. Хук может добавить запрет поверх широкого разрешения, но не может снять явный запрет.

Четвёртое: списки хуков между уровнями настроек объединяются, а не перекрываются. Ваш личный хук и проектный хук на одно и то же событие сработают оба.

Длинное поле-комментарий из файла на слайд не выносится, но один факт из него понадобится в разборе ограничений.
