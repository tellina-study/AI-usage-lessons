# Провал: правило было записано корректно

## Assertion

Правило, записанное корректно, всё равно может быть проигнорировано — записанного текста недостаточно, чтобы гарантировать соблюдение.

## Speaker notes

GitHub issue `anthropics/claude-code#42863`, закрыт как «not planned» в апреле 2026: агент дословно проигнорировал правило `CLAUDE.md`, требующее подтверждения перед доступом к файлам вне рабочей директории, — выполнил `msiexec /i` с записью в `C:\Program Files`, регистрацией служб и правкой реестра в системе, без единого запроса на подтверждение. Правило было написано корректно, по всем канонам, которые мы только что разобрали. Оно просто не сработало.

Второй слой — не другой инцидент, а углубление того же принципа. Личный кейс автора dev.to, заголовок дословно: «I Wrote 200 Lines of Rules for Claude Code. It Ignored Them All». Двести строк `CLAUDE.md`, плюс 258 файлов базы знаний — почти не были прочитаны, «write-only» документация. Детальные протоколы и «запрещённые фразы» не помогли ни разу. Вывод автора, дословно: «Rules in prompts are requests. Hooks in code are laws» — правила в промптах это просьбы, хуки в коде это законы. Это прямой мост к следующей ступени лестницы.

Важно не спутать вывод этого провала с отказом от файла инструкций вообще — `CLAUDE.md`, который мы только что собрали, реально закрыл конкретную боль: агент перестал переспрашивать команды сборки и теста. Вывод точнее: файл инструкций хорошо решает задачу «агент не знает» — он не решает задачу «агент знает, но всё равно нарушает». Для второй задачи в лестнице есть отдельная ступень, и она будет следующей.

Критерий «здесь не нужно» этой ступени стоит проговорить отдельно: крошечный репозиторий или одноразовый скрипт, где структура помещается в один экран и не требует нестандартных команд сборки, — файл добавляет только налог на контекст без компенсирующей выгоды.
