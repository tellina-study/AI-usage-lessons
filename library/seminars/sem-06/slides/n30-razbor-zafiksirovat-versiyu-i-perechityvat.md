# Фиксация версии и перечитывание — последовательность

## Assertion

Все пять вариантов разбираются по случаям и ограничениям. Зафиксировать версию и перечитывать её при сознательном обновлении — последовательность, не альтернатива.

## Visual

| Вариант | Где работает — конкретные случаи | Ограничения |
|---|---|---|
| ничего — одобрили один раз | сервер никогда не обновляется, описание не меняется | доверие — по имени сервера, не по тексту описания: изменение проходит незамеченным |
| сервер официальный — не обновляется тайно | снижает вероятность злого умысла издателя | не отменяет механики: легитимное обновление меняет текст тем же путём |
| запретить автообновление пакета | закрывает канал целиком, если источник зафиксирован | не задаёт версию — это следующий шаг, не альтернатива ему |
| зафиксировать версию сервера | даёт контролируемую точку: обновление — по вашему решению | не читает содержимое обновления — нужен отдельный шаг проверки |
| перечитывать описание при каждом обновлении | закрывает канал смены доверенного поведения | требует, чтобы обновление было замечено — без фиксации версии узнать нечем |

> **Из сочетания колонок:** зафиксировать версию и перечитывать её при сознательном обновлении — последовательность, не альтернатива. «Ничего» и «официальность — гарантия» оба не держат проверку: держит дисциплина, применённая к уже одобренному, не только к новому.

## Speaker notes

Ничего — одобрили один раз — работает, только если сервер никогда не обновляется и его описание никогда не меняется. Официальность — тоже не гарантия: легитимное обновление пакета меняет текст описания точно тем же путём, каким его сменил бы злоумышленник.

Запретить автообновление — закрывает канал, если команда подключения фиксирует источник, но сама по себе не говорит, какую версию фиксировать. Зафиксировать версию — даёт контролируемую точку: обновление происходит по вашему решению, не читает содержимое обновления. Перечитывать описание при каждом обновлении — закрывает именно канал изменения доверенного поведения, но требует, чтобы обновление вообще было замечено.

Вывод: зафиксировать версию и перечитывать её при сознательном обновлении — последовательность, не альтернатива одна другой.

Если спросят, почему большинство клиентов, включая наш, не перепроверяют описание при каждом вызове: доверие привязано к имени инструмента, не к текущему тексту его описания — так устроена архитектура протокола, не недосмотр одного продукта. Разберём это в механике дальше.

Если спросят, не слишком ли это трудоёмко — перечитывать описание при каждом обновлении: трудоёмко читать при каждом обновлении, не при каждом вызове — частота события намного ниже, чем кажется на слух вопроса.

Если спросят, зачем две меры сразу, если каждая работает по отдельности: фиксация версии без перечитывания оставляет вас уверенным в стабильности, которой вы не проверили; перечитывание без фиксации версии оставляет вас беззащитным перед обновлением, о котором вы не узнаете вовремя вовсе.
