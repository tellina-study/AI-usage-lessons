# Что делать с базами материалов нескольких курсов

## Assertion

Свести всё в один индекс без изменений · держать базы раздельно · свести в один индекс, но с фильтром по курсу в самом запросе.

## Visual

> **Что делать с базами материалов нескольких курсов учебного центра?**

`свести базы всех курсов в один общий индекс, ничего не меняя в поиске` · `держать для каждого курса отдельную, не связанную с другими базу` · `свести в один индекс, но добавить в запрос фильтр «искать только в материалах этого курса»`

## Speaker notes

Три действия, и у каждого собственная логика, которую стоит проговорить до голосования — без подсказки, какое из них правильное.

Первое — свести базы всех курсов в один общий индекс, ничего не меняя в самом поиске. Это версия 1, которую мы только что описали: один индекс вместо множества, тот же алгоритм поиска поверх него.

Второе — держать для каждого курса отдельную, никак не связанную с другими базу, ровно так, как было устроено на прошлом занятии. Каждый курс — свой маленький изолированный мир поиска.

Третье — тоже свести материалы в один физический индекс, но добавить в сам запрос дополнительное условие: искать только среди материалов того курса, с которого пришёл вопрос. Внешне это выглядит как компромисс между первыми двумя: один индекс, как в первом варианте, но с ограничением, как во втором.

Пятнадцать секунд на выбор. У каждого из трёх вариантов есть своя цена, и ни один из них не очевидно лучше остальных по умолчанию — иначе бы индустрия не изобретала третий вариант, если бы первый или второй закрывали вопрос полностью. Подумайте, что происходит с поиском, когда в базу, где раньше было восемь документов одной темы, добавляют сто документов совсем других тем, которые тем не менее употребляют часть той же лексики. Держите в голове: правильный ответ — это не обязательно тот вариант, который дешевле всего настроить сегодня.

Ещё одна подсказка для голосования, без протечки вердикта: подумайте, что физически происходит с составом кандидатов поиска в каждом из трёх случаев. В первом случае кандидатами для сравнения с вопросом становятся документы вообще всех курсов сразу — поиск не делает между ними никакой разницы заранее. Во втором случае кандидатами становятся только документы одного, заранее известного курса — и это известно наперёд, безо всякого разбора содержания самого вопроса. В третьем случае круг кандидатов тоже сужается — но не на этапе построения базы: сужение происходит прямо в момент запроса, по признаку того, с какого курса он пришёл. Это разница именно в том, КОГДА и НА ОСНОВАНИИ ЧЕГО сужается список того, с чем вообще будет сравниваться вопрос — и именно она решает, что произойдёт дальше.
