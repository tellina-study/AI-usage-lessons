# Структура замера: что и на чём проверяли

## Assertion

Один и тот же корпус прогнали через пять размеров куска для обеих версий резки — без единой модели на этом шаге.

## Visual

> **Корпус.** SberQuAD, 60 документов (не короче 500 символов — иначе резать не на что), 72 вопроса с разметкой ответа, проверенной напрямую по тексту.

> **Находка по пути.** У 22,0% строк исходного датасета (1 108 из 5 036) положение ответа не совпадало с текстом документа — такие строки исключены из замера целиком, без подгонки под удобный результат.

> **Пять групп — один и тот же размер куска для обеих версий:** 120 · 180 · 220 · 300 · 450 символов. 180 — заголовочное значение этого занятия.

Пример — реальный прогон демо-стенда: документ про кибернетику, 587 символов. Вопрос: «Из каких источников могут быть потоки информации в определении Гордона Паска?» Эталонный ответ — «из любых источников», позиции 528–547: буквальная подстрока документа на этом месте, её никто не придумывал.

> **Модели на этом шаге нет.** Ни резка по счёту символов, ни резка по границам предложений не вызывают ни LLM, ни эмбеддинг — оба узла «Нарезка» (следующий такт) обычный код. Модель появляется позже, на шаге эмбеддинга уже готового куска (Кейс 1), которого этот замер не трогает.

Результатов на этом кадре нет — что из этого вышло, дальше.

## Speaker notes

Прежде чем смотреть на результат, важно понять устройство самого замера — что именно прогнали и через что.

Корпус — шестьдесят документов из набора SberQuAD, стандартного набора вопросов и ответов на русском языке, и семьдесят два вопроса к этим документам. Документы отобраны не короче пятисот символов: более короткие резать на куски попросту не из чего, деление на части не даёт содержательной разницы.

По пути нашлась отдельная находка о качестве исходных данных. У двадцати двух процентов строк исходного датасета — у тысячи ста восьми строк из пяти тысяч тридцати шести — поле с позицией ответа не совпадало с реальным положением текста в документе: разметка оказалась сдвинута ещё на этапе подготовки датасета. Такие строки исключены из замера целиком — удобный результат тут никто не подгонял: если нельзя доверять разметке позиции, нельзя и честно посчитать, разорвал ли её разрез куска.

Пять групп замера — это пять размеров куска: сто двадцать, сто восемьдесят, двести двадцать, триста и четыреста пятьдесят символов. Сто восемьдесят — заголовочное значение, то, вокруг которого строится основной разбор; остальные четыре нужны, чтобы проверить, не случайность ли результат на одном конкретном числе. Внутри каждой группы прогоняются обе версии резки — по счёту символов и по границам предложений — на одном и том же наборе из шестидесяти документов и семидесяти двух вопросов.

Возьмём конкретный пример — настоящий прогон со стенда, его никто не придумывал. Документ про кибернетику, пятьсот восемьдесят семь символов. Вопрос: из каких источников могут быть потоки информации в определении Гордона Паска? Эталонный ответ — «из любых источников» — буквальная подстрока документа в позициях с пятьсот двадцать восьмой по пятьсот сорок седьмую; её не угадывали, она значится в самом тексте.

И последнее, важное для устройства теста: на этом шаге нет ни одной модели. Обе версии резки — обычный код, без обращения к LLM и без эмбеддинга; как это выглядит на реальном экране — через два такта. Модель появится позже, когда готовый кусок пойдёт на эмбеддинг, — и это уже другой, отдельный шаг, которого сегодняшний замер не трогает. Результатов на этом кадре намеренно нет: сначала устройство теста, потом его исход.
