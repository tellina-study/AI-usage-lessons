# Дважды не сработала интуиция

## Assertion

Решаем реактивно, по сигналу перегрузки файла инструкций; и интуиция ошиблась дважды — описание оказалось не деталью, а условием срабатывания, а одобрение скилла разовое при постоянных правах.

## Visual

> «Ступень 4 — скилл. На оси: решаем, реактивно — по сигналу, а не по плану.»
> «Сигнал прозвучал сам: файл инструкций уже платил за процедуру, нужную раз в десять сессий.»

| Интуиция говорила | Проверка показала |
|---|---|
| описание — деталь, важно содержание, допишу потом | выбор идёт по описанию: без него не сработает никакое содержание |
| в худшем случае скилл просто промолчит | скилл — исполняемый код: одобрение разовое, права постоянные |

- Всё, что добавляли до сих пор, жило внутри репозитория: файлы, которые агент читает сам.
- Следующая боль — первая, которую файлом внутри репозитория не закрыть.

## Speaker notes

«Ступень четыре — скилл. Куда её поставить на оси? Решаем, реактивно: файл инструкций уже платил налог за процедуру, которая нужна не всегда. Сигнал прозвучал сам, мы его не планировали.

А интуиция здесь ошибалась дважды. Первый раз: казалось, важно содержание, а описание — деталь, допишу потом. Проверка показала обратное: без точного описания-триггера скилл с любым содержанием не сработает, потому что модель выбирает по описанию.

Второй раз: казалось, в худшем случае скилл просто промолчит. Проверка показала, что это исполняемый код с правами, которые выдаются один раз и живут неопределённо долго. Обе ошибки одного рода: мы оценивали скилл по тому, что внутри файла, а решают его судьбу описание снаружи и права, с которыми он исполняется.

Посмотрите на дерево репозитория. Всё, что мы добавляли до сих пор, жило внутри проекта: файлы, которые агент читает сам. Следующая боль — первая, которую файлом внутри репозитория закрыть нельзя.»
