# Что реально приходит на вход

## Assertion

Хук получает полное описание вызова и вытаскивает из него одну строку распаковкой структуры — текстовый поиск сломался бы о соседнее поле и об экранирование внутри самой команды.

## Visual

- Самотест этого хука строит тот же набор полей и запускает тот же самый код хука, вытащенный из файла настроек, — не копию логики
- `permission_mode` приходит одним из шести значений; режим «вручную» из интерфейса приезжает сюда как `default`, а не как `manual`

## Speaker notes

Хук читает одно поле. А приходит ему существенно больше — вот полное описание вызова, слева.

Идентификатор сессии, рабочая директория, режим разрешений, имя события, имя инструмента, аргументы, идентификатор вызова. В реальном объекте есть ещё путь к транскрипту, каталог черновиков и показатель усилия — их я убрала, наш хук их не читает.

Он вытаскивает `tool_input.command` — ту самую строку, которую агент собирается выполнить. И делает это распаковкой структуры, а не поиском по тексту. Две причины, обе на схеме.

Первая: прямо рядом лежит `description` — тоже человеческий текст про ту же самую команду. Наивный поиск по всему вводу зацепит его и примет решение по чужой строке, а не по исполняемой.

Вторая тоньше. Внутри строки прячутся экранированные кавычки и переводы строк. Сообщение коммита из двух строк приедет сюда как экранированная последовательность — разбор через потоковый редактор на ней просто рассыплется. Распаковка сначала восстанавливает структуру и только потом отдаёт значение.

И замечание про самотест, к которому мы придём. Он не имитирует этот объект приблизительно: он строит тот же набор полей и запускает тот самый код хука, который сам вытащил из файла настроек. Не копию логики — настоящий код. Поэтому его вывод — свидетельство, а не иллюстрация.
