# Первая строка файла решает всё остальное

## Assertion

В контексте всегда лежит только первый уровень — имя и описание. Читаются они при одном условии: первая строка файла — три дефиса.

## Visual

| Поле | Спецификация Agent Skills | Ваш Claude Code |
|---|---|---|
| `name` | обязательно, до 64 символов | можно не писать: возьмёт имя каталога |
| `description` | обязательно, непустое, до 1024 символов | можно не писать: возьмёт первую непустую строку |

> **Фронтматтер читается при одном условии:** три дефиса стоят первой строкой файла. Не второй, не после пустой. Иначе разбор не запускается — и в дело идут подстановки из правой колонки.

## Speaker notes

Три уровня. Разбираемся, что из файла где оказывается.

Уровень первый — имя и описание. Они в контексте всегда, для каждого установленного скилла, сработал он сегодня или нет. И больше ничего: ни первой строки тела, ни списка файлов внутри каталога.

Уровень второй — тело файла. Попадает в переписку только после того, как модель решила, что описание совпало с запросом. Попало — дальше живёт как обычное сообщение и заново не перечитывается.

Уровень третий — вложения. Вспомогательный файл читается целиком, когда до него дошли. А код скрипта в контекст не попадает никогда — даже когда скрипт по-настоящему запускается: запускает его оболочка, а возвращается только то, что он напечатал.

Порядок величин, чтобы вы не боялись: тринадцать скиллов по сотне токенов — тысяча триста на весь перечень. Процент от окна в двести тысяч — около двух тысяч. Обрезка при таком масштабе не наступает. Два документа спорят о том, как считается этот бюджет; для вас разница нулевая, и я не стал делать вид, что разрешил спор.

**Теперь главное — чем первый уровень заполняется.** Среда открывает файл и смотрит на самую первую строку. Три дефиса — читает фронтматтер, берёт имя и описание из полей. Не три дефиса — разбор не запускается вовсе, и подставляются умолчания: имя от каталога, описание от первой непустой строки.

Вернитесь к нашему `build-deck`. Первая строка — заголовок. Значит, описанием стал заголовок. Снаружи похоже, будто система подставила имя вместо описания, — нет. Она взяла не ту строку. А совпала эта строка с именем только потому, что все двенадцать наших файлов открываются заголовком с именем скилла. Начни автор файл сразу с предложения — умолчание сработало бы осмысленно.

Тринадцатый, `pre-user-gate`, написан иначе: настоящий фронтматтер, явное имя, явное описание. Он же объясняет, почему остальные двенадцать вообще приносят пользу — их зовут по имени руками. Два разных канала, и одному из них описание не нужно вовсе.

*Честно и отдельной строкой: обрезается ли ведущая решётка заголовка при подстановке в перечень — я не нашёл подтверждения ни в одну сторону.*
