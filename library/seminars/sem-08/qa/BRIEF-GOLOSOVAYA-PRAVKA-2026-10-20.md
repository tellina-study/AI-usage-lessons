## Исследовательский вопрос по Кейсу 4 — ответ (WebSearch, не выдумка)

**Вопрос владельца:** имеет ли смысл сжимать картинку перед отправкой в модель для проверки
содержимого — даст ли это экономию или только ухудшит распознавание?

**Ответ по общедоступным источникам (2025-2026, multimodal LLM vision tokenization):**
умеренное сжатие ОБЫЧНО выгодно и не ухудшает качество заметно: пример из практики — изображение
4032×3024 полным разрешением даёт ~1500 токенов, то же изображение, уменьшенное до 720×540 при
JPEG quality 85, даёт ~300 токенов — 5-кратная экономия почти без потери точности для большинства
задач. Общая рекомендация для фото/документов — JPEG quality 75–85 при max width ~1024px.
**Но есть важная оговорка: задачи чтения текста на изображении (OCR-подобные) деградируют
заметнее всего при агрессивном сжатии** — если проверка карточки Telegram подразумевает, что
модель должна прочитать текст/цифры на картинке (не только общее содержание), сжимать нужно
аккуратно (не ниже ~1024px по большей стороне), а не агрессивно.
**Вывод для слайда:** умеренное сжатие (не агрессивное) — да, экономия без потери точности;
агрессивное — риск для текстовых элементов карточки. Указать на слайде/в заметках с пометкой
источника (не "я не знаю" — конкретный ответ с оговоркой).
