## 2. Формат

Все 27 файлов воспроизводят структуру эталонов Семинара 5 (`n06`, `n09`, `n10`, `n13`, `n14`):
фронтматтер (`id`, `type`, `duration_min`, `assertion`, `learning_goal`, `visual.pattern`,
`visual.tag` — только у трёх дивайдеров, `visual.primary`, `visual.backup`), затем `# заголовок`,
`## Assertion`, `## Visual`, `## Speaker notes`. Блок `**Справка.**` с отдельным `---`-разделителем
не используется: по проверке самого эталонного набора (`grep` по всем файлам `sem-05/slides/`) эту
форму несут только 6 файлов из 68 (вступительный блок занятия и один ранний вопрос) — основной,
устоявшийся формат ступеней прошлого занятия (`n06`–`n68`) держит «Если спросят…» прямо внутри
`## Speaker notes`, без отдельного заголовка. Выбран этот, более частый вариант.

Фигур (`visual.figure`) не заведено ни для одного из 27 слайдов — см. §4.

таблицей на светлом поле (см. эталоны `n13`, `n22`, `n24`, `n30` — все без `figure`). Три
`mechanics_map` этого блока (n14 — цена в токенах, n21 — статусы и тайм-ауты, n29 — доверие по
имени) и три `code_artifact` (n13, n22, n30) по насыщенности и структуре ближе к этим
табличным эталонам, чем к `n11` — отдельная схема устройства протокола не запрошена ни картой
слайдов, ни разделом-источником (`section-1-mcp*.md` ни в одном месте §A.1–A.3 не называет
фигуру для своих механик). Если на фазе визуального дизайна решение изменится — кандидаты:
«устройство MCP-подключения целиком» (аналог `khuki-n12`) для n14/n21/n29 объединённо.
