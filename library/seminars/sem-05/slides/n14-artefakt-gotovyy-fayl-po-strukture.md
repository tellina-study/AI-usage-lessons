# Собранный барьер: девять строк, у каждой своя работа

## Assertion

Собранный барьер — одна запись в файле настроек: объявление, четыре шага кода и два ответа.

## Visual

| Блок карты | Что стоит в файле | Что эта строка делает |
|---|---|---|
| **1** объявление | `"PreToolUse"` | событие: среда запускает проверку **до** того, как вызов исполнится |
| **1** объявление | `"matcher": "Bash"` | отбирает только вызовы команд оболочки; правки файлов идут мимо |
| **6** код | шаг 1 · `jq -r '.tool_input.command'` | достаёт из описания вызова (блок 3) саму команду одной строкой |
| **6** код | шаг 2 · `grep -qE` по этой строке | ищет в ней `git commit` — в начале строки или после разделителя команд |
| **6** код | шаг 3 · `git rev-parse --is-inside-work-tree` | спрашивает, репозиторий ли это вообще |
| **4** ответ | `"permissionDecision": "ask"` | репозитория нет: решение передаётся человеку, молча не пропускаем |
| **6** код | шаг 4 · `git symbolic-ref --short HEAD` | спрашивает имя текущей ветки; отвечает и на репозитории без коммитов |
| **4** ответ | `"permissionDecision": "deny"` | ветка `main` или `master`: вызов закрыт, причина уходит агенту |
| **1** объявление | `"timeout": 10` | сколько секунд среда ждёт ответа, прежде чем отменить проверку |

## Speaker notes

Тот же файл, что вы сейчас спроектировали. Слева — номер блока с карты устройства, в середине строка файла, справа — что она делает.

Объявление, блок один. Событие: проверка срабатывает до исполнения вызова. Матчер: только команды оболочки. Таймаут: десять секунд.

Дальше четыре шага кода, блок шесть. Первый достаёт из описания вызова саму команду — одной строкой, как агент её собирался выполнить. Второй ищет в этой строке `git commit`: в начале или после разделителя, чтобы коммит внутри составной команды тоже попался. Третий спрашивает, репозиторий ли это. Четвёртый спрашивает имя ветки.

Два ответа, блок четыре. Репозитория нет — передаём решение человеку. Ветка главная — закрываем вызов, и причина уходит агенту.

Каждая строка делает ровно одно. Ни одна из них не знает про остальные.

Если спросят, почему шаг четыре именно `symbolic-ref`: привычная `git rev-parse --abbrev-ref HEAD` на репозитории без коммитов падает с кодом сто двадцать восемь. `git symbolic-ref --short HEAD` на том же репозитории отдаёт имя ветки и ноль. Разница в том, что упавшая проверка ничего не блокирует и снаружи выглядит пройденной.

Если спросят, как выглядит выражение проверки целиком: `(^|[;&|]\s*)git\s+commit\b` — то есть `git commit` в начале строки либо после точки с запятой, амперсанда или вертикальной черты. На слайде оно приведено сокращённо.

Если спросят, где взять файл: `github.com/tellina-study/signup-landing-demo`, ветка `seminar-5-hook`. Файл под контролем версий, в свежем клоне барьер работает сам, ставить ничего не надо.

Если спросят про тексты причин: они сокращены, целиком оба показаны во втором кейсе — там разбирается, чем барьер говорит «нет».

Если спросят, почему таймаут десять, а не шестьсот по умолчанию: это третий кейс целиком. Коротко: срок умножается на число срабатываний.

Если спросят, почему проверка не в `.git/hooks`: этот файл едет с клоном, служебный каталог — нет. Разбирали на разборе вариантов.
