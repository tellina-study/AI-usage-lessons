# Три операции — и вычеркнутые права

## Assertion

Файл конфигурации пишется в конце: сначала называются три операции, которые агент должен уметь, а затем построчно вычёркиваются права широкого токена, которые эти три операции не используют.

## Visual

**Вопрос 1.** «Что конкретно агент должен делать?» Зал называет, фиксируется список:

- читать открытые issue
- писать комментарий к issue
- создавать черновик правки

Ничего про удаление, про настройки репозитория, про другие репозитории.

**Вопрос 2 — вычёркивание прав.** Что даёт широкий персональный токен по умолчанию:

- ~~все репозитории пользователя, включая приватные~~
- чтение и запись
- ~~управление настройками~~
- ~~удаление~~

По каждой строке — вопрос «нужно для нашего списка операций?» Остаётся: один репозиторий, чтение issue, создание черновика правки.

## Speaker notes

Файл пишется в конце разговора, а не в начале: начать с синтаксиса конфигурации — и разговор минует два решения, которые важнее синтаксиса.

Первый шаг быстрый. «Что конкретно агент должен уметь?» Зал перечисляет, фиксируется список: читать открытые задачи, писать комментарий, готовить черновик правки. Три операции, ничего больше — ни про удаление, ни про настройки репозитория, ни про другие репозитории. Специфичность списка здесь не формальность: каждая невычеркнутая операция станет отдельной строкой прав на следующем шаге, и развернуть эту связь обратно будет сложнее, чем сузить список заранее.

Второй шаг несёт основной вес этого разговора. На экране появляется список того, что даёт широкий персональный токен по умолчанию: все репозитории пользователя, включая приватные; чтение и запись; управление настройками; удаление. По каждой строке — один и тот же вопрос: «наш список из трёх операций этого требует?» Вычёркивание происходит прямо на экране, строка за строкой. Остаётся один репозиторий и две операции.

Запомните, как выглядит этот экран сейчас: через несколько слайдов вернёмся ровно к нему — с инцидентом, который воспроизводится ровно тогда, когда верхняя строка не вычеркнута. Принцип за этим простой: права выдаются под задачу, которая уже названа, а не под задачу, которая когда-нибудь может появиться, — расширить список легче, чем откатить уже выданные права.
