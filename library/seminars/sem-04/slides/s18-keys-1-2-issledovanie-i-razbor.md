# Что говорит исследование — и разбор

## Assertion

Текстовый гейт без тулинга не просто бесполезен, а вреден — регрессии выросли почти до 10%; ни один из пяти вариантов зала не решает проблему системно, кроме передачи проверки механизму вне текста.

## Visual

**Исследование — гейты:**

| Источник | Тезис | Сила |
|---|---|---|
| SWE-Gate/SpecBench/CapCode/Verification Horizon (4 препринта 2609–2606) | Согласие 4+ независимых 2026-препринтов: агенты систематически «обходят» видимые тестовые гейты | Сильное — межисследовательский консенсус |
| **TDAD, arXiv:2603.17973** | Чисто процедурная инструкция «сначала пиши тесты» без тулинга увеличила регрессии до 9,94% — хуже, чем вообще без инструкции | Сильное и контринтуитивное |
| Rethinking Agent-Generated Tests, arXiv:2602.07900 | Манипуляция промптом ради частоты тестов — без значимого эффекта (6 моделей) | Умеренное — нулевой результат |
| Agent Scaffolding Beats Model Upgrades | Архитектура харнесса даёт +20 п.п.; смена модели — ~1 п.п. | Сильное — механизм против модели |

**Исследование — цикл «улучшение»:**

| Источник | Тезис | Сила |
|---|---|---|
| Self-planning, arXiv:2303.06689 | Планирование перед кодом: +25,4% pass@1 (не repo-scale) | Умеренно-сильное «за» |
| LLMs Cannot Self-Correct, ICLR'24; CRITIC 2305.11738 | Самокоррекция без внешнего сигнала систематически ухудшает результат | Сильное «против» голого self-review |
| arXiv:2604.10508 | Self-repair с внешним сигналом: +4,9…+30 п.п. | Сильное «за» — с реальной проверкой |

Честный пробел: «Нет контролируемого эксперимента именно на изолированную фразу-гейт в `CLAUDE.md` — только best-practice наблюдения практиков.»

**Разбор пяти карточек зала:**

| Вариант | Где работает | Почему рано — и что вместо |
|---|---|---|
| «Капсом / жёстче» | Нигде системно | TDAD: регрессии выросли до 9,94% |
| «Продублирую вторым пунктом» | Иногда чуть повышает шанс прочитать | Presence paradox: лишняя строка стоит контекста |
| «Отдельный файл-чеклист» | Помогает человеку, слабо — агенту | Тот же класс решения — снова текст, снова просьба |
| **«Передам механизму вне текста»** | **Системно работает: +20 п.п.** | **Верное направление** — сам механизм разбирается на следующем слайде |
| «Смирюсь, это нормально» | Приемлемо для некритичных предпочтений | Для правила, чьё нарушение стоит дорого — решение не решать |

## Speaker notes

«Здесь результат по-настоящему контринтуитивный. Исследование TDAD взяло чисто процедурную инструкцию "сначала пиши тесты" без единого изменения в тулинге — и регрессии не упали, а выросли до почти десяти процентов. Хуже, чем вообще без инструкции. Улучшение появилось только тогда, когда то же самое требование зашили в скилл или в тулинг, а не в текст. И отдельно, для цикла "план-код-улучшение": самокритика без внешнего сигнала систематически ухудшает результат — это ICLR подтверждает жёстко. А вот self-repair с реальным прогоном теста даёт плюс пять-тридцать процентных пунктов. Разница принципиальная, не терминологическая: смотрел ли агент на свой код — или прогнал ли он реальную проверку.

Отдельного контролируемого эксперимента именно на изолированную фразу-гейт в файле инструкций нет — здесь у нас best-practice наблюдения практиков, не отдельное измерение.

Теперь разбор. Вариант "перепишу капсом" — в точности тот путь, который проверило TDAD: усилили формулировку текстом, без тулинга. Регрессии выросли. Капс не превращает просьбу в закон. "Продублирую вторым пунктом" — presence paradox из первого кейса: лишняя строка стоит контекста в каждой сессии. "Отдельный файл-чеклист" — тот же класс решения, снова текст, снова просьба. "Смирюсь, это нормально" — для правила, чьё нарушение стоит дорого, это решение не решать.

И только один вариант из пяти — "передам проверку механизму вне текста" — системно работает: механизм даёт двадцать процентных пунктов там, где смена модели даёт один. Это верное направление. Сам механизм — на следующем слайде.»
