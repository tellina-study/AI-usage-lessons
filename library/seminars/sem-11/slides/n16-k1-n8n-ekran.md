# Настоящий холст: HyDE-шаг перед эмбеддингом

## Assertion

Семь узлов: форма → сочинить гипотетический ответ → разбор → эмбеддинг этого ответа → поиск → ответ по найденному куску → результат.

## Visual

> Единственный новый узел в этой цепочке — «Сочинить гипотетический ответ (gpt-4o-mini)», вставленный ПЕРЕД эмбеддингом. Дальше холст продолжает ту же механику, что Кейс 1 Семинара 10: Simple Vector Store (cosine top-1) → Answer (RAG).

## Speaker notes

На экране — настоящий скрин живого холста стенда, снятый вживую: цепочка узлов, которую мы не рисовали от руки — её собрали через управляющий API n8n и сфотографировали так же, как студент увидел бы её своими глазами, открыв этот же сценарий в браузере.

Слева направо читается главный путь. Форма принимает вопрос и держит при себе корпус документов с уже посчитанными эмбеддингами — ровно тот же вход, что уже был у Кейса 1 Семинара 10. Дальше — единственный по-настоящему новый узел этого кейса: «Сочинить гипотетический ответ (gpt-4o-mini)», обычный HTTP Request к chat-эндпоинту OpenRouter с промтом, который просит модель написать короткий связный абзац, похожий на то, что могло бы лежать в базе. Узел «Разбор HyDE-документа» вытаскивает текст ответа из JSON. Дальше — «Embed HyDE-документ (text-embedding-3-small)»: та же операция эмбеддинга, что уже встречалась выше, только теперь она применяется к сочинённому тексту — вопрос в этой операции больше не участвует. «Simple Vector Store (cosine top-1 по HyDE)» — тот же код, что уже стоял в Кейсе 1 Семинара 10, с единственной разницей: вектор, который он сравнивает с корпусом, принадлежит уже не вопросу — он принадлежит HyDE-документу. «Answer (RAG) по найденному куску» формирует финальный ответ тем же способом, что и прежде — по найденному фрагменту; всю базу целиком он не читает.

Важная оговорка сказана прямо — её не прятали: отдельного живого скрина с видимым ветвлением на три переформулировки для multi-query в этой фазе не снято. Причина не в том, что это было недостижимо — переформулировки уже измерены числом на всех пятидесяти вопросах собственным Python-харнессом, который мы уже разобрали. Этот живой холст показывает механику добавления шага как класса — один дополнительный узел перед эмбеддингом, — и для этого достаточно линейной версии, HyDE; повторять тот же архитектурный урок вторым, более громоздким скрином не было смысла.

Что именно происходит внутри двух ключевых узлов — поиска и генерации — следующими двумя панелями.
