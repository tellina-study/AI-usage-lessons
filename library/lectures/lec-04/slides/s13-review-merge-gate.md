# Visible content

## Title bar
«Принять PR агента, не прочитав — потому что „тесты же зелёные“»

## Body
[Слева — антипаттерн в Ocean rounded box]

**Антипаттерн уровня C**
«merge по зелёным тестам без чтения» = уровень C, **де-факто деградировавший до D** без явного решения о повышении автономии.

Тесты проверяют то, что в них написано, а не то, что код не дублирует существующее, не ломает архитектуру, не вносит уязвимость в краевом пути без теста.

[Справа — GitClear 211M строк]
**Анализ 211 миллионов строк (2020–2024)**
- клоны: 8,3% → **12,3%**
- рефакторинг: 24,1% → **9,5%**
- churn (переписано за 2 нед): 5,5% → **7,9%**

→ AI оптимизирует **скорость порождения**, не качество *(gold)*

[Урок-плашка, низ]
**Альтернатива (не-AI):** обязательное человеческое ревью PR до слияния + метрики дублирования/churn в CI как gate. Решение о merge — это решение об ответственности за код, и оно **не делегируется** агенту по той же причине, по которой code review между людьми не отменяется доверием к коллеге.

## Speaker notes

Уровень C производит pull request — и появляется новый, специфический именно для этого уровня антипаттерн: принять PR агента, не прочитав его, потому что «тесты же зелёные» и «агент обычно справляется». Разберём, почему это конкретно опасно, на данных.

Исследование GitClear проанализировало двести одиннадцать миллионов строк изменённого кода за 2020–2024 годы — двадцать пять крупнейших open-source-проектов плюс приватные кодовые базы — и зафиксировало направленные сдвиги, совпавшие с массовым приходом AI-ассистентов. Доля скопированного кода выросла с восьми с небольшим до двенадцати с лишним процентов. Доля перемещённого, отрефакторенного кода упала с двадцати четырёх до девяти с половиной. Code churn — доля строк, переписанных в течение двух недель после коммита, прокси поспешного кода, — выросла с пяти с половиной до почти восьми процентов. Содержательный вывод: AI оптимизирует скорость порождения кода, но не его качество; при отсутствии человеческого gate растёт дублирование и падает рефакторинг — технический долг копится быстрее.

Урок и альтернатива. «Зелёные тесты» — необходимое, но не достаточное условие; тесты проверяют то, что в них написано, а не то, что код не дублирует существующее, не ломает архитектуру и не вносит уязвимость в краевом пути, для которого теста нет. Антипаттерн «merge по зелёным тестам без чтения» — это уровень C, де-факто деградировавший до уровня D без явного решения о повышении автономии. Правильная альтернатива конкретна и не-AI по своей природе: обязательное человеческое ревью pull request до слияния плюс метрики дублирования и churn в continuous integration как gate, а не как отчёт. Явный критерий: решение о слиянии в общую кодовую базу — это решение об ответственности за код, и оно не делегируется агенту по той же причине, по которой ревью между людьми не отменяется доверием к коллеге. AI удешевил производство pull request, но решение «за это отвечаем мы» осталось на человеке.
