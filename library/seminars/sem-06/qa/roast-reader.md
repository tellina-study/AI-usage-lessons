## 5. Шесть кейсов — слились или нет

Через две недели я уверенно развожу все шесть по тому, с чего каждый начинается:

1. **Данных нет в репозитории** — «issue вместо мессенджера», копипаст руками.
2. **Сервер подключён, работы нет** — «агент отвечает, что всё сделал», зелёная галочка.
3. **Одобрение не окончательно** — «сервер обновился сам», юникод-сокрытие, `postmark-mcp`.
4. **Роль переизобретается заново** — «правка готова, проверка расходится».
5. **Отчёт роли — утверждение** — «три PASS, один солгал».
6. **Вторая роль, промежуток** — «два честных PASS, между ними дыра».

Каждый кейс заканчивается своим критерием (`criteria_boundary`, n16/n24/n32/n43/n52/n59), и
критерии не повторяют друг друга дословно — это помогает не перепутать, какой кейс о чём. Ни
один из шести не читается взаимозаменяемо с другим ни по завязке (`problem_scenario`), ни по
выводу.
