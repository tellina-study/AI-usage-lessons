# Не та строка, а не имя вместо описания

## Assertion

Спецификация делает `name` и `description` обязательными, а Claude Code — рекомендательными; и когда фронтматтера нет вовсе, подставляется не имя вместо описания, а первая непустая строка файла — что и произошло в этом самом репозитории у двенадцати скиллов из тринадцати.

## Visual

| Поле | Дефолт при отсутствии |
|---|---|
| `name` | имя каталога скилла |
| `description` | первая непустая строка содержимого файла |
| `disable-model-invocation` | не задан — модель может вызвать скилл сама |
| `allowed-tools` / `disallowed-tools` | не задан — обычные права сессии |
| `paths` | не задан — автосрабатывание только по описанию |

Общая спецификация: `name` и `description` — обязательные поля. Документация Claude Code: все поля необязательны, рекомендован только `description`. Два разных контракта для двух разных путей распространения одного файла.

**Живой пример этого репозитория.** Условие, при котором фронтматтер вообще читается: открывающая `---` обязана быть первой строкой файла.

```
==> build-deck/SKILL.md <==
# build-deck
```

Двенадцать скиллов из тринадцати начинаются сразу с `# заголовок` — фронтматтера у них физически нет. Дефолты: имя — от каталога, описание — от первой непустой строки, которая у всех двенадцати оказывается markdown-заголовком, а не предложением-триггером. Один скилл (`pre-user-gate`) устроен иначе — настоящий фронтматтер с явными `name` и `description`.

> Непроверено: обрезается ли ведущий `#` при подстановке в листинг, или строка попадает в системный промпт буквально.

## Speaker notes

Второй вопрос механики — что вообще обязано быть в файле. Общая спецификация требует: имя и описание — обязательные поля, у описания жёсткий лимит в тысячу двадцать четыре символа, и оно обязано называть и что скилл делает, и когда его использовать. Документация вашего инструмента говорит прямо противоположное по тону: все поля необязательны, только описание рекомендовано. Это не смягчённый пересказ одного правила — это два разных контракта для двух разных путей распространения одного и того же файла.

И вот что происходит, если фронтматтера нет вовсе — не гипотеза, а факт вот этого самого учебного репозитория. Условие, при котором фронтматтер вообще читается, простое: открывающая строка из трёх дефисов обязана быть первой строкой файла. В этом проекте двенадцать скиллов из тринадцати начинаются прямо с заголовка — фронтматтера у них физически нет. В этом состоянии подставляются дефолты, не пустота: имя — от имени папки, описание — от первой непустой строки содержимого. У всех двенадцати первая непустая строка — это markdown-заголовок с именем скилла, а не предложение, которое реально годится как триггер и стоит строкой ниже.

Снаружи это выглядит как «описание равно имени» — понятная, но неточная формулировка. Причина другая: система не подставляет имя вместо описания, она берёт не ту строку — и совпадает с именем только потому, что все двенадцать файлов начинаются с заголовка, повторяющего имя папки. Один скилл в этом же репозитории устроен иначе: у него есть настоящий фронтматтер с явным именем и явным описанием — рабочий пример рядом с двенадцатью отрицательными, в одном и том же проекте. И он же отвечает на вопрос, почему двенадцать остальных хоть как-то работают: только явным вызовом по имени команды, не автоматическим срабатыванием по смыслу запроса — это два разных канала.

Честно, отдельной строкой: обрезается ли ведущая решётка заголовка при подстановке в системный промпт, или строка попадает туда буквально, с символом решётки, — подтверждения не нашлось.
