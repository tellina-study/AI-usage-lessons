# Процесс, контекстное окно, список инструментов

## Assertion

Отдельная роль — процесс со своим контекстным окном, вызываемый на одну задачу. Вызов по имени или по описанию решает маршрутизацию; задача и итог идут текстом; список инструментов решает, что роль может сделать физически.

## Speaker notes

Прежде чем выбирать, одна вещь, которая нужна во всех трёх разборах этой ступени. Отдельная роль — это процесс со своим контекстным окном, вызываемый на одну задачу. Вызывают его по имени явно, либо модель выбирает сама — по описанию роли, не по её названию. Задача приходит текстом, роль возвращает только итог: ни какие файлы она открыла, ни какие запросы сделала, родитель не видит. И последнее: список инструментов определяет, что роль может сделать физически. Если список не указан вовсе, роль получает все инструменты, доступные субагентам, без исключений.

Приём, о котором говорим, не привязан к одному инструменту: отдельная роль со своим контекстным окном есть у нескольких продуктов. Запись при этом у каждого своя: где-то это markdown с инструкцией телом файла, у одного — формат с отдельным полем для инструкции. Общей спецификации нет ни у одного.

Если спросят, зачем называть переносимость здесь, до разбора кейсов: чтобы не прозвучало как универсальный стандарт раньше времени — весь материал ступени привязан к конкретному продукту, и это стоит сказать сразу, не оговоркой потом.

Если спросят про исключение «форк»: есть режим, который наследует всё целиком — тот же промпт, те же права, всю историю; в нашей сцене мы им не пользуемся, но путать его с обычным вызовом не стоит.

Если спросят, кто решает, когда вызывать роль по имени, а когда дать модели выбрать самой: оба способа реальны — явный вызов снимает вопрос маршрутизации полностью, выбор моделью зависит от того, насколько точно описание роли называет задачу.
