# The Existing Process

## Assertion

Request → the model determines the topic and urgency → the knowledge base normalizes the values to a list → a row in the table → a notification to Olga. Out of this chain, one node changes today — where the answer goes.

## Visual

> The process you left last session with: the form takes in the request → the model determines the topic and urgency → the knowledge base normalizes the values to a list → the row goes to the table → Olga gets the notification.

| Where the process's answer used to go, until today | Where it goes starting today |
|---|---|
| a row in the request table, and a notification to the coordinator | a message to the person who reached out to the training center |

> A message sent to the client can't be fixed once they've read it — unlike a row in the table, it's no longer ours to change.

## Speaker notes

Today's input state is the exact same file last session ended with. The form takes in the request as free text. A separate model step pulls the topic, the urgency, and the contact out of that text. The knowledge base normalizes the values to a set list, and no cell is left empty after it. The row lands in the table, and the requester sees the results screen. Plus four decisions we worked through last time and that are already standing in this file: the coordinator notification is assembled by substitution into a ready-made form, a repeat request is checked at two levels, the refund-amount decision is made by a condition in code, and an image is checked for size before it's sent.

Out of these six nodes, exactly one changes today — the one that decides where the process's answer goes. The other five keep working unchanged: the model still pulls out the topic and the urgency the same way, the knowledge base still normalizes the values to a list the same way, the row still lands in the table the same way. We're recalling them not to fix anything in them, but to see exactly where today's boundary runs.

Now the second half of the bar on screen. Until today, the result of the process's work stayed inside: a row in the request table and a notification to the coordinator. Starting today, that same node has a new addressee — the message goes out to the person who reached out to the training center. That person has never seen the canvas, the execution log, or the knowledge base. They'll get a piece of text and read it as the training center's own answer — one that arrived quickly, in a confident tone, with no caveats.

And here's what happens to the cost of a mistake because of it. A row in the table can be reviewed and fixed — it stays with us, inside the company. A message that's already been sent can't be fixed: it's already with the client, they're relying on it, and if they come back to argue, they'll be arguing with the exact text we sent them. The same model node, the same model, the same settings — and a completely different cost for the exact same failure. Because of that difference, the whole of today we'll be asking every new step the same question, and we'll start asking it one screen from now.
