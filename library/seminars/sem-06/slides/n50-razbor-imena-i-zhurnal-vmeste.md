# Два хода работают только вместе

## Assertion

Четвёртая и третья карточки работают только вместе: названные файлы и команды делают сам итог проверяемым, а журнал вызовов показывает, что из названного произошло на самом деле внутри запуска.

## Visual

| Вариант | Где работает | Ограничения |
|---|---|---|
| ничего — итог уже есть | хватает для разовой проверки с низкой ценой ошибки | не добавляет видимости внутрь запуска |
| звать роль дважды, сравнивать | расхождение — сигнал проблемы | совпадение не добавляет видимости |
| назвать файлы и команды в «что проверено» | делает сам итог проверяемым | текст не доказывает, что действие произошло |
| смотреть журнал вызовов | единственный канал видимости внутрь запуска | не читают по умолчанию — отдельный шаг |
| отказаться от параллельных запусков | снимает именно этот сценарий | цена — время; видимость та же, по одному |

> **Вывод.** Четвёртая и третья карточки работают только вместе — по отдельности каждая слабее. Названные в итоге файлы и команды делают сам текст проверяемым; журнал вызовов показывает, что из названного произошло на самом деле внутри запуска. Отказ от параллельности снимает один конкретный сценарий; граница видимости, которая его создала, остаётся при любом порядке вызовов.

## Speaker notes

Ничего не менять — хватает для разовой проверки с низкой ценой ошибки, но ничего не добавляет к видимости внутрь запуска: на правке с высокой ценой ошибки видно только то, что роль решила написать. Звать роль дважды и сравнивать — расхождение между двумя ответами сигнализирует о проблеме, но совпадение не добавляет видимости: оба прогона могут одинаково не открыть нужный файл. Требовать названия конкретных файлов и команд в разделе «что проверено» — делает сам итог проверяемым, названное действие повторяется за секунды; текст всё равно не доказывает, что действие физически произошло внутри запуска. Смотреть журнал реальных вызовов — единственный канал, где видно, что произошло внутри запуска, помимо текста итога. Минус — журнал не читают по умолчанию, это отдельный шаг. Отказаться от параллельных запросов — снимает именно этот сценарий, сбой проявился при фан-ауте; цена — время, а последовательные запуски той же роли ограничены той же видимостью по одному.

Вывод. Четвёртая и третья карточки работают только вместе — по отдельности каждая слабее. Названные в итоге файлы и команды делают сам текст проверяемым; журнал вызовов показывает, что из названного произошло на самом деле внутри запуска.

Если спросят, почему пятая карточка не закрывает проблему целиком, хотя и снимает конкретный сценарий: потому что граница видимости, которая его создала, при этом остаётся — отказ от параллельности лечит симптом этого прогона, не саму границу между тем, что роль сделала, и тем, что она написала.

Если спросят про «журнал» подробнее: это тема следующего слайда, отвечать коротко — «у каждого запуска роли есть файл с записью её реальных вызовов, подробнее через слайд».
