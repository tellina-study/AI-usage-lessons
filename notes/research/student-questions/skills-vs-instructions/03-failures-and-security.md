## 1. Раздувание always-on инструкций (CLAUDE.md / AGENTS.md)

Механизм провала: CLAUDE.md/AGENTS.md грузится **целиком в каждую сессию** (в отличие от skill,
который грузится по решению модели). Это даёт гарантию присутствия, но плата — бюджет контекста
и, что важнее, **деградация соблюдения** при росте объёма.

### 1.1 — vendor-предупреждение: сам Anthropic пишет, что раздутый CLAUDE.md ломает соблюдение
- **Что случилось:** в официальной документации Claude Code есть прямая формулировка о вреде
  длинного файла.
- **Механизм (цитата, дословно):** «Keep it concise. For each line, ask: "Would removing this
  cause Claude to make mistakes?" If not, cut it. **Bloated CLAUDE.md files cause Claude to ignore
  your actual instructions!**» И отдельно, в разделе «Avoid common failure patterns»: «**The
  over-specified CLAUDE.md.** If your CLAUDE.md is too long, Claude ignores half of it because
  important rules get lost in the noise.» Там же — рецепт: «If Claude keeps skipping one
  instruction, add emphasis such as "IMPORTANT" to that line alone. If you emphasize many lines,
  none of them stands out.»
- **ВЫУЧЕННЫЙ УРОК:** always-on инструкция не масштабируется количеством правил — после
  некоторого объёма КАЖДОЕ правило (включая критичные) теряет вес; это не «добавь ещё одно
  правило», а операция прунинга.
- **Источник:** https://code.claude.com/docs/en/best-practices (раздел «Write an effective
  CLAUDE.md» и «Avoid common failure patterns», дата доступа 2026-10-02)
- **Тип:** vendor-предупреждение.

### 1.2 — народная практика: CLAUDE.md «забывается» после 2-5 промптов, issue закрыт без фикса
- **Что случилось:** пользователь (GAAOPS) завёл issue 2025-09-17 — Claude Code следует
  методологии из CLAUDE.md первые несколько промптов, затем откатывается к дефолтному поведению,
  трактуя правила как «advisory», а не «mandatory». Сама модель, отвечая в диалоге пользователю,
  признала: «My default mode always wins because it requires less cognitive effort and activates
  automatically.»
- **Механизм:** инструкция always-on конкурирует с весами модели по умолчанию; без явного
  детерминированного гейта (hook) ничто не форсирует соблюдение — это рекомендация, а не код.
- **ВЫУЧЕННЫЙ УРОК:** если правило должно исполняться «без исключений» — это задача для хука
  (детерминированного), а не для текста в CLAUDE.md (вероятностного), даже если текст помечен
  «MANDATORY».
- **Источник:** https://github.com/anthropics/claude-code/issues/7777 (filed 2025-09-17, закрыт
  как «not planned», без публичного ответа мейнтейнеров)
- **Тип:** народная практика (документированная жалоба, без формального research, issue закрыт без
  признания бага).

### 1.3 — народная практика: инъецированный disclaimer сам ослабляет приоритет файла
- **Что случилось:** в публичном обсуждении (Hacker News, тред про анонс поддержки AGENTS.md)
  пользователи обратили внимание, что Claude Code оборачивает CLAUDE.md/AGENTS.md в системную
  пометку.
- **Механизм (цитата, дословно):** текст-обёртка — «IMPORTANT: this context may or may not be
  relevant to your tasks. You should not respond to this context unless it is highly relevant to
  your task.» Комментатор отмечает, что это де-факто снижает обязательность файла по сравнению с
  более ранним поведением. **Это не гипотетика** — ровно эта же строка оборачивает CLAUDE.md в
  системном контексте и этой самой рабочей сессии (см. `<system-reminder>` в начале диалога).
- **ВЫУЧЕННЫЙ УРОК:** даже если пользователь физически положил правило в CLAUDE.md, система вокруг
  него может добавить мета-инструкцию «это необязательно релевантно» — слой между «файл записан» и
  «модель считает его обязательным» не прозрачен автору файла.
- **Источник:** https://news.ycombinator.com/item?id=49763844 (комментарий в треде об анонсе
  AGENTS.md-поддержки, 2025/2026)
- **Тип:** народная практика (наблюдение пользователя над системным поведением, не формальный
  research).

### 1.4 — народная практика: деградация пропорциональна «нерелевантной» доле файла
- **Что случилось:** в параллельном HN-треде пользователь формулирует эмпирическое правило: «The
  more information you have in the file that's not universally applicable to the tasks you have
  it working on, the more likely it is that Claude will ignore your instructions.» Иллюстрация —
  правило «обращайся ко мне как Mr Tinkleberry» перестаёт соблюдаться, когда файл разрастается
  посторонним контентом — это служит пользователю индикатором «модель перестала читать файл
  внимательно».
- **Механизм:** не просто длина, а ДОЛЯ нерелевантного для текущей задачи контента — универсальные
  правила (действуют всегда) держатся лучше, чем узкоспециализированные блоки, замешанные в общий
  файл.
- **ВЫУЧЕННЫЙ УРОК:** критерий «что оставить в always-on файле» — не «важно ли это когда-нибудь»,
  а «применимо ли это к БОЛЬШИНСТВУ задач»; специфичное — в skill/ссылочный файл, не в CLAUDE.md.
- **Источник:** https://news.ycombinator.com/item?id=46102048
- **Тип:** народная практика.

**Критерий «здесь always-on-файл не нужен»:** правило относится к <30% задач сессии, или требует
100%-ного исполнения без исключений (→ хук), или вступает в силу только по явному запросу
пользователя (→ slash-команда/skill).

## 2. Молчаливое неоткрытие ссылочного файла

Механизм провала системный, не баг конкретной версии: инструкция вида «подробности см. в
`docs/process.md`» или `@docs/process.md`-импорт **не гарантирует** вызов Read. Агент может
сгенерировать уверенный ответ, опираясь на название файла/память/общие знания о домене, не открыв
файл физически — и внешне это неотличимо от «прочитал и учёл».

### 2.1 — vendor-механизм: `@import` — синтаксис, не контракт на использование
- **Что случилось/факт:** документация Claude Code подтверждает механизм `@path/to/import` для
  CLAUDE.md и даёт отдельную команду проверки: `/context`, чтобы «confirm Claude loaded the file».
  Наличие отдельной diagnostic-команды для проверки факта загрузки — косвенное подтверждение, что
  загрузка не самоочевидна пользователю без явной проверки.
- **Механизм:** `@import` работает на уровне подготовки системного контекста (детерминированно
  вставляет содержимое при старте сессии) — это НЕ то же самое, что инструкция в тексте «прочитай
  файл X», которая зависит от решения модели вызвать Read posteriori. Два разных механизма легко
  спутать: «я написал @файл — значит, Claude всегда его видит» (верно для @import) vs «я написал
  "см. файл X" — значит, Claude его откроет» (НЕ гарантировано).
- **ВЫУЧЕННЫЙ УРОК:** если файл обязателен — использовать `@import` (загрузка синхронна с stat-ом
  сессии) или explicit `@`-референс в самом промпте; просьба «см. файл» текстом внутри другого
  документа — не гарантия, а шанс.
- **Источник:** https://code.claude.com/docs/en/best-practices (упоминание `@path/to/import` и
  `/context`), раздел «Write an effective CLAUDE.md»
- **Тип:** vendor-механизм (задокументированное поведение, не инцидент).

### 2.2 — Что НЕ найдено по этому пункту (честно)
Прямого формального измерения «какой процент ссылочных файлов агент не открывает при задаче,
ссылающейся на них» в публичных источниках на момент поиска (2026-10-02) **не найдено**. Механизм
вытекает из архитектуры (tool-calling — вероятностное решение модели, не принудительный шаг),
подтверждён косвенно через: (а) существование `/context` и `/doctor` как diagnostic-команд именно
для проверки, что файл реально загружен/учтён; (б) задокументированный смежный класс — агент
отвечает уверенно без выполнения заявленного шага верификации (issue #15136, п.3.2 ниже —
структурно тот же сбой: инструкция есть, вызов не произошёл). Детали — в «Что НЕ доказано».

**Критерий «здесь ссылочный файл не надёжен»:** если корректность задачи зависит от того, что
содержимое файла ТОЧНО попало в контекст (цифры, пороги, конкретные формулировки) — встраивать
содержимое напрямую (`@import`, инлайн в промпт) или заставлять агента процитировать прочитанное
перед тем, как продолжить, а не полагаться на одну отсылку «см. файл X».

## 3. Skill, который не триггернулся (и обратная проблема — ложный триггер)

Активация skill — это **решение модели**, принятое по тексту `description` в metadata, а не
детерминированный маппинг. Anthropic прямо пишет: «Claude applies them automatically when
relevant» — слово «relevant» здесь означает вероятностную оценку, не точное совпадение.

### 3.1 — vendor-рекомендация: description — это триггер для модели, а не документация для человека
- **Механизм (как это должно работать):** поле `description` (до 1024 символов) — единственное,
  что модель видит на этапе отбора skills ДО их полной загрузки. Рекомендация
  skill-creator-а Anthropic: описание должно быть «немного навязчивым» (pushy), потому что у
  модели «измеренная тенденция недо-триггерить» (under-trigger) skills — то есть дефолт системы —
  скорее пропустить релевантный skill, чем вызвать нерелевантный.
- **ВЫУЧЕННЫЙ УРОК:** хороший skill с невнятным description — это DEAD CODE: он физически есть в
  `.claude/skills/`, индексируется, но никогда не вызывается, и это не видно без тестирования
  конкретных формулировок запроса.
- **Источник:** синтез по документации Anthropic Skills (platform.claude.com/docs/en/agents-and-
  tools/agent-skills/overview) и руководству «The Complete Guide to Building Skills for Claude»
  (resources.anthropic.com/hubfs/The-Complete-Guide-to-Building-Skill-for-Claude.pdf)
- **Тип:** vendor-предупреждение/рекомендация.

### 3.2 — документированный баг: skill-триггеры вообще не доходят до модели
- **Что случилось:** issue в anthropics/claude-code — «skill triggers never reach the model»:
  frontmatter содержит триггеры, но Claude Code их не видит при формировании системного промпта.
- **Механизм:** это не «модель решила не вызывать» (п.3.1), а инфраструктурный баг — информация о
  skill не долетает до модели вообще, т.е. решение модели здесь нерелевантно, сбой на уровень ниже.
- **ВЫУЧЕННЫЙ УРОК:** «skill не сработал» — два разных класса причин (модель не выбрала vs
  инфраструктура не донесла до модели), и снаружи они неотличимы; диагностика требует проверки
  самого системного промпта, а не только переформулировки description.
- **Источник:** https://github.com/anthropics/claude-code/issues/35053 («Skill triggers ignored
  even with non-huge context»)
- **Тип:** документированный инцидент (открытый issue в репозитории вендора).

### 3.3 — документированный баг: скиллы не авто-активируются в спавненных субагентах
- **Что случилось:** skills, которые надёжно триггерятся в основной сессии, **не** авто-
  активируются в агентах, запущенных через Task tool (субагенты) — даже если промпт субагента
  текстуально совпадает с описанием триггера skill.
- **Механизм:** контекст субагента формируется отдельно от родительской сессии; наследование
  доступности skill не гарантировано тем же механизмом auto-invocation.
- **ВЫУЧЕННЫЙ УРОК:** архитектура «оркестратор делегирует субагентам» (ровно то, что требует
  Orchestration Rule этого курса) — зона повышенного риска «skill был, но не применился»; для
  субагента skill нужно вызывать явно текстом промпта, не полагаться на авто-триггер.
- **Источник:** https://github.com/anthropics/claude-code/issues/14016 («Skills don't auto-
  activate in spawned agents (via Task tool)»)
- **Тип:** документированный инцидент.

### 3.4 — документированный лимит: бюджет символов на список skills+команд — тихий дроп
- **Что случилось:** Claude Code ограничивает суммарный листинг skills+slash-команд в системном
  промпте **15 000 символов по умолчанию**; при превышении лишние по списку skills тихо выпадают
  без предупреждения. Задокументирован случай с **>116 загруженными skills**, когда часть описаний
  «тихо перестаёт загружаться», деля общий бюджет контекста.
- **Механизм:** это количественный, а не смысловой сбой — skill может иметь идеальный description
  и всё равно не триггернуться, потому что физически не попал в контекст модели.
- **ВЫУЧЕННЫЙ УРОК:** «добавь больше skills на все случаи жизни» имеет потолок — система молча
  теряет именно те skills, что добавлены позже/оказались в конце списка; симметрично проблеме MCP
  tool-overload (раздел 5).
- **Источник:** agregировано по anthropics/claude-code issues #12679, #15136, #10766; обзор —
  lazyskills.sh/troubleshooting/skills-not-triggering `[VFY-day-of — пороги могут меняться]`
- **Тип:** документированный инцидент + народная практика.

### 3.5 — обратная проблема: ложный/несвоевременный триггер при конкуренции многих skills
- **Что случилось:** при большом количестве установленных skills описания конкурируют за
  внимание модели на этапе отбора; возможны два симметричных сбоя — skill срабатывает на
  частично совпадающий, но не относящийся запрос («hijack»), либо не срабатывает вовсе, уступая
  более «агрессивному» описанию другого skill.
- **Механизм:** отбор skill — это, по сути, zero/few-shot классификация модели по тексту
  description; как любая такая классификация, она не идемпотентна при росте числа классов
  (skills) и схожести формулировок.
- **ВЫУЧЕННЫЙ УРОК:** рекомендация Anthropic писать «explicit exclusion clauses» в description
  («НЕ используй этот skill для Y») — это не стилистика, а прямая защита от hijack; тестирование
  skill обязано включать негативные примеры (запросы, похожие, но НЕ требующие этого skill), не
  только позитивные.
- **Источник:** синтез по https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview
  и материалам про написание description (generativeprogrammer.com/p/skill-authoring-patterns-
  from-anthropics)
- **Тип:** vendor-рекомендация (описывает известный класс проблемы, не единичный инцидент).

**Критерий «здесь skill не надёжен»:** если задача требует 100%-ного срабатывания на конкретный
явный пользовательский запрос («каждый раз когда я пишу X») — это slash-команда
(`disable-model-invocation: true` + явный `/name`), а не auto-skill; если задача критична и должна
исполняться независимо от формулировки — это задача для хука или явного вызова в CLAUDE.md/коде, а
не для вероятностного триггера.

## 4. Безопасность Agent Skills (skill как исполняемый недоверенный артефакт)

Ключевое отличие от раздела CLAUDE.md: skill может нести **исполняемый код** (bundled-скрипты,
`uv run`, PEP 723-зависимости) и подключается из внешних источников (маркетплейсы, git, плагины) —
то есть это полноценная supply-chain-поверхность, а не просто текст.

### 4.1 — security-research: эмпирическое исследование 42 447 skills на двух маркетплейсах
- **Что случилось:** исследование «Agent Skills in the Wild: An Empirical Study of Security
  Vulnerabilities at Scale» собрало 42 447 skills с skills.rest и skillsmp.com (декабрь 2025),
  после фильтрации качества осталось 31 132 уникальных skill с 3 574 исполняемыми скриптами.
  Построен инструмент SkillScan (статический анализ + LLM-классификация).
- **Механизм/результат:** **26.1%** проанализированных skills содержат хотя бы один из 14
  паттернов уязвимости по 4 категориям; **13.3%** — утечка данных, **11.8%** — повышение
  привилегий; **5.2%** показывают паттерны, указывающие на умышленную злонамеренность (не просто
  небрежность автора).
- **ВЫУЧЕННЫЙ УРОК:** «скачать skill с маркетплейса» статистически сопоставимо по риску с
  «установить непроверенный npm-пакет»; это не гипотетический риск «а что если», а измеренная доля
  на реальном корпусе.
- **Источник:** arXiv:2601.10338, «Agent Skills in the Wild: An Empirical Study of Security
  Vulnerabilities at Scale», 2026-01 — https://arxiv.org/pdf/2601.10338
- **Тип:** security-research (эмпирическое измерение на выборке, не единичный инцидент).

### 4.2 — security-research: от SKILL.md до shell-доступа «в три строки markdown» + демо ransomware
- **Что случилось:** независимые исследователи (coverage — SC World, со ссылкой на оригинальное
  исследование) модифицировали открытый GIF-skill, добавив helper-функцию, которая подтягивает
  внешний скрипт, разворачивающий ransomware-пейлоад (MedusaLocker); успешно выполнено в
  контролируемом тесте.
- **Механизм:** malicious Skill может направить Claude на вызов инструментов/исполнение кода
  способом, не соответствующим заявленному назначению skill — т.е. **декларируемая цель skill в
  description и реальное поведение кода могут не совпадать**, и ревью description не проверяет
  содержимое bundled-скриптов.
- **ВЫУЧЕННЫЙ УРОК:** ревью skill ТОЛЬКО по `description`/README — недостаточно; необходим аудит
  каждого файла, который skill подключает (скрипты, изображения, зависимости), именно это
  рекомендует сам Anthropic.
- **Источник:** https://www.scworld.com/news/claude-agent-skills-could-be-used-to-deploy-malware-
  researchers-say (контролируемая демонстрация, не wild-инцидент; попытка прямого фетча вернула
  403 — цитируется по заголовку/синтезу поисковой выдачи, **детали не независимо перепроверены
  полным текстом статьи**) `[VFY — доступ к полному тексту не подтверждён в этой сессии]`
- **Тип:** security-research (с пометкой: не удалось открыть первоисходный текст напрямую).

### 4.3 — security-research: отложенная supply-chain-атака через незафиксированные зависимости (PEP 723)
- **Что случилось:** threat-model от SafeDep (2026-01-23) демонстрирует конкретный PoC: skill
  публикует инструкцию `uv run scripts/helper.py <filename>`, скрипт объявляет зависимость без
  версии (PEP 723 inline metadata); на момент ревью зависимость безопасна, но код, который
  РЕАЛЬНО выполнится, определяется в момент запуска (`uv` подтягивает «последнюю доступную»
  версию), а не в момент ревью.
- **Механизм:** «the code that runs is determined at runtime, not at review time» — классический
  deferred dependency attack, перенесённый в контекст AI-skills; обходит ревью, которое смотрит
  только на момент установки.
- **ВЫУЧЕННЫЙ УРОК:** требование «я проверил код skill перед установкой» не защищает, если
  зависимости скрипта не закреплены по версии/хэшу — нужен pinning, а не разовый ревью.
- **Источник:** https://safedep.io/agent-skills-threat-model/, 2026-01-23, SafeDep Team
- **Тип:** security-research (контролируемый PoC, не задокументированный wild-инцидент).

### 4.4 — security-research: Unicode-инъекция в SKILL.md + реальные находки при аудите маркетплейса
- **Что случилось:** Cloud Security Alliance AI Safety Initiative (2026-05-06) описывает
  «SKILL.md agent context poisoning» и ссылается на аудит Snyk (февраль 2026): из 3 984
  просканированных skills **1 467** (36.82%) помечены как flawed, из них **76** — подтверждённые
  malicious-payload'ы (эксфильтрация credentials, замаскированное выполнение команд, маршрутизация
  данных на сервер атакующего, механизмы самораспространения). Отдельно продемонстрирована техника
  скрытия инструкций символами Unicode Tag (диапазон U+E0000–U+E007F) — невидимыми человеку,
  читаемыми моделью.
- **Механизм:** это НЕ баг платформы — модель делает ровно то, для чего спроектирована (следует
  инструкциям в контексте); проблема в том, что контент SKILL.md по умолчанию доверенный
  («misuse of intended agent behaviour», не exploit).
- **ВЫУЧЕННЫЙ УРОК:** «злонамеренный skill» — не экзотика лабораторных демо, а измеренная доля
  (36.82% flawed в выборке Snyk) на реальных опубликованных маркетплейс-skills; невидимые для
  человека Unicode-символы — тот же класс атаки, что в п.6.1 (Rules File Backdoor) — приём
  переносится между форматами (rules-файл → SKILL.md → любой markdown-артефакт, который грузится
  агентом).
- **Источник:** https://labs.cloudsecurityalliance.org/research/csa-research-note-skill-md-agent-
  context-poisoning-20260506/, 2026-05-06, Cloud Security Alliance
- **Тип:** security-research (цитирует данные независимого аудита Snyk).

### 4.5 — vendor-предупреждение: явная формулировка Anthropic о доверии
- **Что случилось:** в собственной документации Anthropic прямо пишет границу доверия.
- **Механизм (цитата):** «Use Skills only from trusted sources: those you created yourself or
  obtained from Anthropic.» Отдельно — рекомендация аудировать «SKILL.md, scripts, images, and
  other resources», искать «unexpected network calls, file access patterns, or operations that
  don't match the Skill's stated purpose», с предупреждением про skills, которые «fetch data from
  external URLs».
- **ВЫУЧЕННЫЙ УРОК:** вендор сам не считает «skill из маркетплейса» дефолтно безопасным — это
  прямо противоречит интуиции «раз есть официальный маркетплейс/каталог — значит, прошло модерацию
  уровня app-store».
- **Источник:** синтез по https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview
  (цитаты подтверждены множественными независимыми описаниями в security-research выше, включая
  Simon Willison — https://simonwillison.net/2025/Oct/16/claude-skills/)
- **Тип:** vendor-предупреждение.

**Критерий «здесь skill из внешнего источника не нужен»:** любая задача, где skill подключает
исполняемый код/сетевые вызовы, а источник skill — не «я сам» и не первоисточник Anthropic —
требует ручного построчного аудита (включая Unicode-sanitization) ПЕРЕД установкой, с pin
зависимостей; если это невозможно (нет времени/экспертизы на аудит) — писать свой минимальный
skill или решать задачу обычным кодом/MCP с ограниченными правами, а не доверять найденному skill.

## 5. Безопасность MCP (инструмент как внешний недоверенный процесс)

Классы атак ниже — системные для протокола, не баг одного сервера; часть уже зафиксирована в
исследовании Лекции 3 (CVE github MCP prompt-injection, mcp-remote CVE-2025-6514, MCP Inspector
CVE-2025-49596 — см. `notes/research/lecture-3/failures-and-limitations.md` #6-#9). Здесь —
дополнительные механизмы именно для сравнения «MCP vs skill vs хук».

### 5.1 — security-research: Tool Poisoning / «line jumping» — атака ДО вызова инструмента
- **Что случилось:** Invariant Labs первыми публично назвали класс атак Tool Poisoning Attack
  (апрель 2025); независимо Trail of Bits (2025-04-21) описали тот же механизм под именем «line
  jumping».
- **Механизм:** вредоносные инструкции встраиваются прямо в ОПИСАНИЕ инструмента на этапе
  регистрации (`tools/list`), а не в его код; инструкция исполняется, как только клиент
  подключается к серверу — то есть **до любого реального вызова инструмента пользователем**, в
  момент, когда описания загружаются в контекст модели. В PoC поддельное описание инструмента
  инструктирует модель предварять shell-команды чем-то вроде `chmod -R 0666 ~;`, делая домашний
  каталог доступным на запись всем. Приём эффективен из-за того, что payload ставится В НАЧАЛЕ
  описания — модели сильно обучены отдавать приоритет раннему контексту. Claude Desktop явно
  назван протестированным и уязвимым клиентом.
- **ВЫУЧЕННЫЙ УРОК:** «я не вызывал этот инструмент, значит, я в безопасности» — ложно для MCP;
  сам факт ПОДКЛЮЧЕНИЯ к серверу (до первого реального tool-call) — уже поверхность атаки.
- **Источник:** https://blog.trailofbits.com/2025/04/21/jumping-the-line-how-mcp-servers-can-
  attack-you-before-you-ever-use-them/, 2025-04-21
- **Тип:** security-research.

### 5.2 — security-research/документированный CVE: «Rug Pull» — сервер меняет поведение после апрува
- **Что случилось:** Check Point Research продемонстрировали CVE-2025-54136 («MCPoison») на
  Cursor IDE: атакующий коммитит безобидный `.cursor/rules/mcp.json` в общий репозиторий,
  разработчик апрувит конфигурацию один раз, атакующий ПОЗЖЕ меняет команду за тем же
  одобренным ключом конфигурации — Cursor не требует повторного апрува при изменении описания, и
  каждый следующий запуск тихо исполняет команду атакующего.
- **Механизм:** спецификация MCP не требует re-approval при изменении описания/реализации
  инструмента после первичного одобрения — асимметрия между «пользователь одобрил один раз» и
  «сервер может меняться многократно».
- **ВЫУЧЕННЫЙ УРОК:** одобрение MCP-инструмента — не «навсегда безопасно»; доверие к серверу
  обязано быть привязано к конкретной версии/хэшу его описания, а не к имени один раз увиденного
  инструмента.
- **Источник:** https://www.practical-devsecops.com/glossary/rug-pull-attack-in-mcp/ (излагает
  CVE-2025-54136, Check Point Research); дата события — 2025-07 `[VFY — точная дата диздклоза не
  подтверждена независимым прямым фетчем CVE-записи]`
- **Тип:** документированный инцидент (CVE присвоен) + security-research.

### 5.3 — security-research: confused deputy — сервер использует СВОЮ авторизацию по чужой команде
- **Что случилось/механизм:** MCP-серверы часто выступают посредниками между клиентом, LLM и
  downstream API — классическая проблема делегированной авторизации: атакующий через недоверенный
  вход заставляет MCP-сервер выполнить действие, используя права САМОГО сервера, которые шире, чем
  у обрабатываемых входных данных.
- **ВЫУЧЕННЫЙ УРОК:** широкий токен у MCP-сервера («чтобы всё работало») — бюджет доверия НЕ
  пользователя, а сервера; любой недоверенный вход, который сервер обрабатывает, может унаследовать
  этот бюджет.
- **Источник:** синтез по обзорам MCP-архитектуры 2026 (christian-schneider.net/blog/securing-mcp-
  defense-first-architecture/); отдельного CVE для этого КЛАССА (в отличие от конкретных случаев
  tool-poisoning/rug-pull выше) не найдено — архитектурная категория, не единичный инцидент.
- **Тип:** security-research (концептуальная категория, подтверждённая множественными разборами).

### 5.4 — измерение: рост числа инструментов → падение точности выбора (с базой)
- **Что случилось:** несколько независимых измерений деградации выбора инструмента при росте их
  числа в контексте (каждая цифра — со своей базой, не смешивать):
  - RAG-MCP (arXiv:2505.03275): точность выбора падает с **43.13%** (baseline — весь каталог тулз
    в промпте) до **13.62%** при росте каталога, когда retrieval-слоя нет; RAG-подход восстанавливает
    точность и сокращает токены промпта на >50% относительно baseline-прогона с полным списком тулз.
  - Отдельное измерение: фокусный набор из 4 тулз даёт ~95% верного выбора против ~71% на полном
    наборе из 46 MCP-тулз — разница 24 п.п., объясняемая именно разбуханием контекста описаниями
    (база — тот же бенчмарк-запрос, разное число доступных тулз).
  - Anthropic (внутреннее тестирование, по данным вторичных обзоров) — точность выбора «значимо
    деградирует» после **30-50** инструментов в контексте; с включённой функцией tool search
    Claude Opus 4 поднимается с 49% до 74% на MCP eval benchmark, Opus 4.5 — с 79.5% до 88.1% (база
    — тот же eval benchmark, с/без tool search).
- **ВЫУЧЕННЫЙ УРОК:** «подключить побольше MCP-серверов на все случаи» не бесплатно даже без
  злого умысла — деградация выбора тулзы начинается задолго до лимита контекстного окна по
  токенам, чисто от количества описаний-кандидатов.
- **Источник:** arXiv:2505.03275 («RAG-MCP: Mitigating Prompt Bloat in LLM Tool Selection via
  Retrieval-Augmented Generation»); https://platform.claude.com/docs/en/agents-and-tools/tool-use/
  tool-search-tool (числа Opus 4/4.5); вторичный обзор порога 30-50 — https://dev.to/rawveg/more-
  tools-made-ai-worse-po7 `[VFY-day-of — порог 30-50 из вторичного пересказа внутреннего гайда
  Anthropic, первичный документ с точной формулировкой не локализован в этой сессии]`
- **Тип:** security/performance-research (не инцидент — измерение деградации качества, смежная, но
  не security-уязвимость сама по себе; включено, т.к. прямо запрошено в брифе п.5).

**Критерий «здесь MCP не нужен»:** если нужна одна-две детерминированные операции без решения
модели «какой инструмент выбрать» — это обычный код/скрипт/хук, не MCP-сервер; если источник
MCP-сервера не аудирован и не закреплён по версии — not even один раз одобрить его на
привилегированные операции (файлы/секреты/запись).

## 6. Prompt injection через подгружаемый файл/контент (прямая связь с §4.8 Лекции 3)

Это тот же системный класс, что CamoLeak (CVE-2025-59145, CVSS 9.6, разобран в Лекции 3/4 — см.
`notes/research/lecture-4/failures-and-limitations.md` #7) и PocketOS (там же #3): **агент не
различает данные и команды** — текст, загруженный как «контент для анализа», интерпретируется как
инструкция, если он похож на инструкцию. Ниже — специфичный для нашей темы угол: это происходит
именно через файлы, которые инструкция/конвенция проекта просит прочитать (CLAUDE.md, README,
правила), т.е. ровно тот механизм, который делает ссылочные файлы и skills опасными, не только
«ненадёжными» (разделы 2 и 4).

### 6.1 — документированный инцидент: Rules File Backdoor (Pillar Security, 2025)
- **Что случилось:** Pillar Security (Ziv Karliner и команда) раскрыли технику для GitHub Copilot
  и Cursor — скрытые Unicode-символы (zero-width joiners, bidirectional text markers) внедряются в
  файлы конвенций (`.cursor/rules`, `.github/copilot-instructions.md`), невидимые человеку-
  рецензенту, но читаемые моделью. PoC: при запросе «Create a simple HTML only page» модель молча
  добавляла внешний `<script>`-тег, не упоминая это в чат-логе.
- **Механизм:** атакующий распространяет «полезный» rules-файл через форум/GitHub/cursor.directory
  — разработчик добавляет его в репозиторий, рассчитывая на пользу от стандартизации, и с этого
  момента КАЖДАЯ генерация кода в проекте несёт скрытую инструкцию.
- **Таймлайн:** раскрытие Cursor 2025-02-26 → ответ Cursor (ответственность на пользователе)
  2025-03-06/08 → раскрытие GitHub 2025-03-12 → GitHub добавил предупреждение о скрытом Unicode
  2025-05-01. **CVE не присвоен** ни одному вендору — оба назвали это проблемой конфигурации
  пользователя, не платформы.
- **ВЫУЧЕННЫЙ УРОК:** файл конвенций проекта (ровно тот же КЛАСС файла, что CLAUDE.md/AGENTS.md
  этого курса) — легитимная поверхность атаки, если он когда-либо был скопирован из внешнего
  источника; отказ вендора признать CVE означает, что защита — обязанность того, кто подключает
  правила в репозиторий, а не платформы.
- **Источник:** https://www.pillar.security/blog/new-vulnerability-in-github-copilot-and-cursor-
  how-hackers-can-weaponize-code-agents, 2025-03 (также освещено OECD.AI:
  https://oecd.ai/en/incidents/2025-03-18-06ed)
- **Тип:** документированный инцидент (раскрытие security-research, но с реальным вендор-ответом и
  PoC на продуктовых инструментах — не лабораторная абстракция).

### 6.2 — документированный CVE: вредоносный `.claude/settings.json` в клонированном репозитории
- **Что случилось:** Check Point Research — CVE-2025-59536, CVSS **8.7** — вредоносный
  `.claude/settings.json`, зафиксированный в репозитории, регистрирует hook с matcher'ом
  `SessionStart`/`startup`; при открытии проекта разработчиком Claude Code выполняет
  зарегистрированную команду **до того, как отрисовался диалог доверия/апрува**, с правами
  локального пользователя, открывшего проект. Параллельно — CVE-2026-21852 (эксфильтрация
  API-ключей через смежный механизм авто-регистрации MCP).
- **Механизм:** это прямой аналог Rules File Backdoor (6.1), но нацеленный не на «правила
  генерации кода», а на **сам конфигурационный слой агента** (settings.json, hooks) — то есть
  клонирование чужого репозитория = согласие исполнить его хуки до того, как увидел промпт
  согласия.
- **ВЫУЧЕННЫЙ УРОК:** хуки — заявленно «детерминированные и надёжные» (раздел 7), но именно
  поэтому они привлекательная цель: если хук можно подсунуть через репозиторий, детерминизм
  работает ПРОТИВ пользователя (гарантированно исполнится). Патч — Claude Code 1.0.111+, октябрь
  2025 `[VFY-day-of]`.
- **Источник:** https://blog.checkpoint.com/research/check-point-researchers-expose-critical-
  claude-code-flaws/ (разбор, 2026); CVE-2025-59536 присвоен, CVSS 8.7
- **Тип:** документированный инцидент (CVE, вендор признал и патчил, в отличие от 6.1).

### 6.3 — документированный класс: README/код репозитория как канал косвенной инъекции
- **Что случилось/механизм:** коммерческие security-разборы (Endor Labs, Cymulate, независимые
  разборы 2026 года) фиксируют воспроизводимый паттерн **AIShellJack**: атакующий кладёт malicious
  инструкцию в README, комментарий кода, или даже страницу документации/форум-ответ, который агент
  читает «по пути» (онбординг перед задачей); т.к. агент не различает «справочный текст» и
  «команда», скрытая инструкция в README исполняется как директива. Отдельно описан случай, когда
  payload доставляется через утилитарный модуль, исполняемый ПРИ ИМПОРТЕ — это уже обходит
  prompt-level детекцию инъекции, т.к. контроль передаётся через выполнение кода, а не текст
  промпта.
- **ВЫУЧЕННЫЙ УРОК:** README — не нейтральный «для человека» документ для агента в remote dev
  окружении с shell+network доступом (ровно конфигурация этого курса: subagents с Bash/Edit) —
  это такой же недоверенный вход, как issue/PR-комментарий в CamoLeak.
- **Источник:** https://www.endorlabs.com/learn/prompt-injection-against-coding-agents-the-attack-
  surface-nobody-owns; https://cymulate.com/blog/zero-click-rce-prompt-injection-ai-tools/ (оба —
  2026, обзорные аналитические материалы практиков, не первичный академический research; термин
  «AIShellJack» не независимо подтверждён третьим источником в этой сессии)
- **Тип:** security-research (вторичные индустриальные разборы, названный термин не
  кросс-подтверждён — помечено `[VFY]`).

**Критерий «здесь загружаемый файл небезопасен по умолчанию»:** любой файл конвенций/README/
правило, которое попало в проект НЕ от самого автора проекта (скопировано из форума, сгенерировано
третьей стороной, пришло с клонированным репозиторием) — требует явного построчного просмотра на
скрытые Unicode-символы и подозрительные директивы ПЕРЕД тем, как агент его прочитает в рамках
сессии с правами на запись/shell/сеть.

## 7. Хуки и slash-команды — собственные провалы

Хук и slash-команда — не «безопасные по конструкции» альтернативы вероятностным механизмам; у них
свои отказы, симметричные их главному преимуществу (детерминизм / явный триггер).

### 7.1 — документированный баг: хуки ломают поток, когда падают не так, как ожидалось
- **Что случилось:** в репозитории anthropics/claude-code — открытый feature-request #50287:
  «hooks currently fail silently in many ways: PATH issues, wrong exit codes, hanging processes,
  project-subdirectory load failures, and false-positive hook-error labels»; нет runtime-
  телеметрии, какой хук сработал, с каким exit-кодом, что он вывел в stderr.
- **Механизм (конкретные под-случаи, отдельные issues):**
  - exit code 2 (задумано как «форсировать продолжение агента») работает при установке хука в
    `.claude/hooks/`, но **не работает**, если хук установлен через plugin-систему (issue #10412);
  - при exit code 1 у WorktreeCreate-хука Claude Code **зависает бесконечно** вместо явной ошибки
    (issue #27963);
  - при exit code 0 с JSON на stdout вывод хука не всегда долетает до следующего turn модели —
    хук отработал верно, но Claude не видит вердикт (issue #70479);
  - «False Hook Error» — ложные метки ошибки хука обрывают многошаговую задачу до завершения,
    пользователь не может отличить реальный сбой от ложного (issue #34713).
- **ВЫУЧЕННЫЙ УРОК:** «детерминированный» ≠ «надёжно наблюдаемый» — хук гарантированно
  выполняется, но то, что он УСПЕШНО выполнился и его результат дошёл до модели — отдельная,
  негарантированная часть цепочки; детерминизм действия не переносится автоматически на
  детерминизм коммуникации результата агенту.
- **Источник:** https://github.com/anthropics/claude-code/issues/50287 (главный тикет, сводит
  остальные); #10412, #27963, #70479, #34713
- **Тип:** документированный инцидент (множественные открытые issues у вендора).

### 7.2 — документированный CVE: хук как канал RCE (пересечение с разделом 6.2)
См. 6.2 выше — CVE-2025-59536, hook `SessionStart` выполняется до диалога доверия. Это прямое
доказательство, что «хук = гарантия действия» — именно та гарантия, которую эксплуатирует
атакующий, когда хук приходит из чужого репозитория: детерминизм хука не различает «доверенный
автор» и «атакующий, подсунувший settings.json» — он одинаково надёжно выполнит код обоих.
- **ВЫУЧЕННЫЙ УРОК:** «надёжность = безопасность» — ложная эквивалентность; хук надёжен
  ИСПОЛНИТЬ, но не надёжен в различении, КТО его туда положил.
- **Тип:** документированный инцидент (та же пара CVE/источник, что в 6.2).

### 7.3 — народная практика: slash-команда не исполнится, если её забыли вызвать
- **Что случилось/механизм:** slash-команды, в отличие от skills, **требуют мануального вызова** —
  «Claude Code Skills auto-invoke based on context while slash commands require manual triggers…
  slash commands won't execute unless explicitly invoked by the user.» Отдельно задокументирован
  сценарий (issue #68402), где в сессиях удалённого запуска (web) slash-команда вообще не
  перехватывается клиентом и проходит как обычное сообщение модели — без UI команды и без её
  исполнения, с тихим примечанием «команда не сработала», но сам ход диалога продолжается, будто
  всё в порядке.
- **ВЫУЧЕННЫЙ УРОК:** цена детерминированности slash-команды — explicit trigger: если оператор/
  пользователь забыл написать `/review` перед тем, как посчитать задачу сделанной, никакой
  «автоматический скилл» это не подхватит молча (это и плюс — предсказуемость, и минус — зависимость
  от человеческой памяти). Это ЗЕРКАЛЬНАЯ проблема к п.3 (skill может сработать без вызова, но
  непредсказуемо; slash-команда сработает предсказуемо, но ТОЛЬКО если её вызвали).
- **Источник:** https://github.com/anthropics/claude-code/issues/68402; синтез по
  https://www.mindstudio.ai/blog/claude-code-skills-vs-slash-commands
- **Тип:** народная практика + документированный инцидент (конкретный issue про remote-сессии).

**Критерий «здесь хук не нужен»:** если действие не обязано происходить в 100% случаев без
исключений (т.е. достаточно «обычно», «по запросу») — оверхед хука (поддержка скрипта, отсутствие
наблюдаемости сбоев, пере-апрув при каждом изменении) не оправдан, используйте skill/CLAUDE.md.
**Критерий «здесь slash-команда не надёжна»:** если задача должна исполняться без человека,
помнящего вызвать команду — это задача для хука (событие) или skill (контекстный триггер), не для
`/command`.

## Что НЕ доказано (честный раздел)

- **«Skill стоит X токенов из бюджета Y»** — измеренной стоимости одного skill в токенах (кроме
  качественного «loads them on demand without bloating every conversation» из vendor-доков) не
  найдено. Лимит листинга (15 000 символов, п.3.4) — не то же самое, что токен-бюджет одного skill.
- **Процент случаев, когда агент не открывает ссылочный файл при инструкции «см. файл X»** — не
  найдено формального измерения (п.2.2); вывод сделан по аналогии с задокументированным соседним
  сбоем (инструкция есть — вызов инструмента не произошёл, issue #15136), не по прямому измерению.
- **Термин «AIShellJack»** (п.6.3) — встретился в нескольких вторичных разборах, но не
  кросс-подтверждён первичным источником; механизм README-инъекции при этом подтверждён независимо
  другими источниками — не проверено конкретно название.
- **Порог «30-50 MCP-инструментов», приписываемый «внутреннему гайду Anthropic»** (п.5.4) —
  цитируется вторичными блогами почти идентичной формулировкой, но первичный документ с этой
  фразой не открыт напрямую; числа Opus 4/4.5 (49%→74%, 79.5%→88.1%) — с официальной страницы
  tool-search и считаются подтверждёнными.
- **Scworld-статья о демо ransomware через GIF-skill (п.4.2)** — WebFetch вернул 403, детали
  пересказаны по сниппетам выдачи, не по полному тексту; механизм согласуется с независимо
  подтверждённым п.4.1/4.4, но именно этот кейс не верифицирован первичным текстом.
- **«Пользователи массово забывают slash-команды»** — только народная практика/единичные issues
  (п.7.3), не статистика; правдоподобно, но числовой базы нет.
- **«Раздувание CLAUDE.md → конкретный процент регресса задач»** — vendor утверждает механизм
  качественно («ignores half of it»), но измеренного процента не найдено.
