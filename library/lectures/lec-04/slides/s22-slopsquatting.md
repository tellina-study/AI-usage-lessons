# Visible content

## Title bar
«Выдуманный пакет как supply-chain атака»

## Body
[Inline-define, 16pt]
**slopsquatting** — атака на цепочку поставок: злоумышленник регистрирует имя пакета, которое LLM **стабильно галлюцинирует**, и публикует под ним malware. **supply-chain** — совокупность сторонних библиотек и каналов, из которых собран продукт.

[Слева — жизненный цикл атаки в Ocean rounded box, 4 шага]
1. собрать выдуманные имена пакетов из моделей
2. отфильтровать по **воспроизводимости** (43% — во всех 10 запросах)
3. зарегистрировать имя в npm/PyPI + опубликовать malware
4. ждать: разработчик/агент делает `pip install <имя>` — malware в момент установки

[Справа — данные]
- ~**20%** сгенерированных сэмплов рекомендуют несуществующие пакеты
- **58% воспроизводимо** (>1 запроса) — это и есть ось угрозы *(gold)*
- на уровне D установка может произойти **без единого человеческого взгляда**

[Альтернатива-плашка, низ]
**Не-AI барьер:** lockfile + хэш-пиннинг · allowlist реестров · проверка пакета **до** install (возраст, загрузки, репутация) · SCA-скан. Это прямой перенос урока Лекции 3 «когда не доверять выводу модели».

[Footer, 12pt italic light]
*Slopsquatting — термин Seth Larson (PSF, 2025); исследование 576 000 сэмплов. Проценты [VFY], направление стабильно.*

## Speaker notes

Детальный кейс и прямая связь с Лекцией 3 — «когда не доверять выводу модели». Введём термин. Slopsquatting — атака на цепочку поставок ПО, при которой злоумышленник заранее регистрирует имя пакета, которое LLM галлюцинирует, выдумывает как существующее, и публикует под этим именем вредоносный код; разработчик, скопировавший AI-совет «установить такой-то пакет», устанавливает malware. Название — от typosquatting, но эксплуатируется не опечатка человека, а галлюцинация модели. Введём и второй термин: supply-chain — цепочка поставок ПО, совокупность сторонних библиотек и каналов, из которых собран ваш продукт.

Данные. Из примерно пятисот семидесяти шести тысяч сгенерированных сэмплов кода около двадцати процентов рекомендовали несуществующие пакеты. Критично для атаки: сорок три процента галлюцинированных имён повторялись во всех десяти повторных запросах, пятьдесят восемь процентов — более чем в одном. То есть галлюцинация воспроизводима — атакующий может заранее узнать, какое имя модель выдумает стабильно, и зарегистрировать его.

Жизненный цикл атаки в четыре шага. Атакующий собирает несуществующие имена из моделей; фильтрует по воспроизводимости; регистрирует имена в публичном реестре с вредоносной нагрузкой; ждёт, пока разработчик или агент уровня C-D выполнит совет установить пакет — malware исполняется уже в момент установки, до любого ревью кода.

Урок и альтернатива. Подчеркну, почему именно воспроизводимость — ось всей угрозы, а не доля двадцать процентов: если бы модель каждый раз выдумывала разное имя, атакующему было бы нечего регистрировать заранее. Воспроизводимость переводит это из случайной ошибки в предсказуемую мишень. Урок: вывод LLM, ведущий к внешнему действию с побочным эффектом, нельзя исполнять на доверии — это прямой перенос «когда не доверять выводу» из Лекции 3, и он тем острее, чем выше уровень автономии. Правильная альтернатива не-AI: lockfile с хэш-пиннингом, allowlist доверенных реестров, проверка пакета до установки, SCA-скан, и базовое — не выполнять установку из AI-совета без верификации имени. Стоит задать себе вопрос: дали бы вы агенту автономно выполнить установку пакета из его же предложения — и почему нет?
