## 3. Реальная конфигурация узлов — без изменений с прошлой волны (повтор для удобства)

### Кейс «Уведомления»
- Версия 1, `chainLlm` («Compose notification (LLM)»): промпт — «Напиши короткое дружелюбное
  уведомление координатору учебного центра в Telegram о новой многотемной заявке. Имя заявителя:
  {{имя}}. Основная тема: {{тема}}. Также в заявке упомянуто: {{доп. темы}}. Пиши по-человечески,
  одно-два предложения.» Модель — `openai/gpt-4o-mini` (узел `Model (notification)`).
- Версия 2, `Set`/`Edit Fields` («Compose notification (template)»): выражение — `Новая заявка от
  {{ $('Request form').item.json['Имя'] }}: тема «{{ ... topic }}»{{ ... extra_topics ? ', также:
  ' + ... : '' }}.`
- Целевой пример текста (из постановки): «Новая заявка от Марии: тема «курс», также упомянуто:
  оплата. Контакт: +7 999 123-45-67.» Реальная находка — у Олега версия 1 вставила плейсхолдер
  «[Имя координатора]».

### Кейс «Проверка на повтор»
- `Set` («Normalize + hash»): `normalized_hash = text.toLowerCase().trim().replace(/\s+/g, ' ')`.
- `IF` («Exact duplicate in window?»): `normalized_hash` строго равен `recent_same_contact_hash`.
- `chainLlm` («Same question, reworded? (LLM)»): промпт — «Это новое сообщение: «{{новый текст}}».
  Недавнее сообщение того же контакта: «{{старый текст}}». Это тот же вопрос, просто
  сформулированный иначе? Ответь строго «да» или «нет».»
- Реальный тест переизмерен 2026-10-19 на новом наборе 20 пар (исходный набор не сохранился, см.
  SETKA фронтматтер): хэш 15/20, TF-IDF-косинус 13/20 (хуже хэша, не наравне), LLM-судья
  (gpt-4o-mini) 17/20. Четвёртая схема — jev (TypeSafe Decisions API) — измерена 2026-10-20 на том
  же наборе через production-workflow `stage-2-duptest.json` (id `gs5uhluV74yu045D`): **20/20**,
  лучший результат из четырёх, порог классификации 0,5. Прошлый диагноз «измерение заблокировано
  правом доступа credential» был ошибкой — реальная причина: credential не был привязан к узлу
  workflow (ошибка авторинга, не прав доступа), исправлено оркестратором 2026-10-20. Полный
  протокол — `stend/duplicate-check-results.json`. Числа финальные, не пересчитывать без нового
  измерения.

### Кейс «Одобрение возврата»
- `chainLlm` («Decide refund (model)»), модель `qwen/qwen-2.5-7b-instruct`: промпт — «Правило: не
  возвращай больше 3000 рублей автоматически, иначе эскалируй руководителю. Сумма запроса:
  {{сумма}} рублей. Ответь строго одним словом: «одобрить» или «эскалировать».»
- `IF` («Amount over threshold?»): извлечённая сумма (число) строго больше 3000.
- Результат: версия 1 — 3 ошибки из 51 (все на 3000₽); версия 2 — 0 из 51.
- Методология (см. SETKA часть 2): 50 сумм, кластер у границы (2900/2950/2990/2999/3000×3),
  4 шаблона фраз, плюс 1 ручной тест.

### Кейс «Карточка в Telegram»
- `Set` («Compose notification (template)»): то же выражение шаблона, что в «Уведомлениях».
- `HTTP Request` («Fetch card image»): файл по URL, формат ответа — файл.
- `Telegram` (`sendPhoto`, «Send card (Telegram photo)»): бинарные данные + `caption`.
- Реальная ошибка: `"Bad Request: file of size 12812355 bytes is too big for a photo; the maximum
  size is 10485760 bytes"` на файле 12 812 355 байт.
