# Протоколы встреч — разбор 1

## Assertion

Растущий и меняющийся архив, произвольный запрос — вот когда нужен RAG

## Visual

Иллюстрация растущего архива протоколов (множество документов за полгода)
с лупой поиска по запросу. Стрелка к блоку «релевантные фрагменты в
контекст модели».

## Speaker notes

Пока был один транскрипт одной встречи, который целиком помещается в
контекст модели, разовый вызов был правильным и достаточным ответом —
ни RAG, ни агент были бы не нужны и только усложнили бы дело без всякой
пользы. Но теперь база протоколов растёт со временем, постоянно
пополняется новыми встречами, и весь этот объём уже физически не влезает
в один запрос к модели. Значит, нужен поиск по этой растущей базе на
произвольный запрос пользователя — и это ровно то, для чего нужен RAG:
искать релевантные фрагменты протоколов по смыслу запроса, а не пытаться
каждый раз скармливать модели весь архив целиком. Обратите внимание — мы
не выбрали RAG заранее «на всякий случай», мы пришли к нему только когда
появилось конкретное требование, которое простой вариант закрыть уже не
мог.
