# Visible content

## Title bar
«Чек-лист "прежде чем дать задачу AI"»

## Body
[Слева — нумерованный чек-лист 8 пунктов в Ocean rounded box]

1. Можно ли решить **без AI** (детерминированно, верифицируемо)? → не добавляй AI
2. **Обратимо ли** последствие? Необратимое → hard human-gate, потолок вниз
3. Есть ли **тест-оракул** (машинно-проверяемый критерий)? Нет → ревью обязательно
4. **Кто ревьюит и кто мержит?** Merge — всегда человек (accountability)
5. Затронуты ли **секреты / недоверенный контент**? → least-privilege + изоляция + egress
6. Насколько **код знаком AI**? Незнакомый/критичный → доверие по Pro (~64%), строгий ревью
7. Цель — **артефакт или навык**? Навык → не делегировать генерацию, Learning-режим
8. **Конфигурация:** solo+AI или команда+AI — по обратимости/критичности/аудиту?

[Справа — 2 блока apply]

**Worked example (задача A):** «кодинг-агент C в приватном платёжном модуле, тесты неполные» → C **с** обязательным senior-ревью + hard-гейт на платежи, конфигурация команда+AI. Решающая ось — необратимость+критичность; ≥2 причины: критичность (платёж) + незнакомость без оракула. Условие смены: обратимый внутренний инструмент с полным покрытием → допустим D.

**Mini-apply (задача B):** «миграция формата конфигов в ~300 репо по фикс-правилу, мержит человек» — пройдите чек-лист **сами** за 2 минуты *(think-pair-share)*

[Gold callout, низ]
**Сначала попытка — потом сверка.** Сформулируйте ответ (уровень + ≥2 причины по осям + ≥1 условие смены + явное «где человек обязателен») **до** разбора. Полная отработка — Семинар 4.

## Speaker notes

Лестница, матрица и критерии сворачиваются в рабочий чек-лист — применяется к dev-задаче примерно за две минуты до того, как дать её AI. Каждый пункт — «когда не / где человек» из раздела как вопрос. Можно ли решить без AI, детерминированно? Обратимо ли последствие — необратимое требует жёсткого гейта. Есть ли тест-оракул — нет, значит, нельзя доверять фрагменту без человеческого ревью. Кто ревьюит и кто мержит — merge всегда человек. Затронуты ли секреты или недоверенный контент — least-privilege, изоляция, egress-контроль. Насколько код знаком AI — незнакомый и критичный, калибруйте доверие по Pro-цифре, не Verified. Цель — артефакт или навык: навык значит не делегировать генерацию. И конфигурация — solo или команда плюс AI по обратимости, критичности, аудиту.

Покажу образец рассуждения на задаче A: на уровне C попросить кодинг-агента реализовать фичу в приватном платёжном модуле с неполными тестами. Проход: не детерминированная, AI уместен в принципе; платёж — последствия критичны и частично необратимы, нужен жёсткий гейт; тесты неполные — нет надёжного оракула, нельзя доверять pull request без построчного senior-ревью; merge — senior, не агент; секреты есть — least-privilege; приватный код — доверие по Pro, около шестидесяти четырёх процентов; цель артефакт; критично плюс аудит — команда плюс AI. Вывод в формате success-критерия: уровень C с обязательным senior-ревью и жёстким гейтом, конфигурация команда плюс AI; решающая ось — необратимость и критичность; условие смены: будь это обратимый внутренний инструмент с полным покрытием на знакомом коде — допустим уровень D.

Теперь мини-применение. Задача B: рутинная миграция формата конфигов примерно в трёхстах репозиториях по фиксированному правилу; изменения в pull request, мержит человек. Пройдите чек-лист сами и сформулируйте по формату success-критерия: уровень A–D, не менее двух причин по осям, не менее одного условия смены выбора, явное «где человек обязателен». Важно: сначала попытка, потом сверка — иначе упражнение вырождается в узнавание готового. Полная отработка с разбором — на Семинаре 4.
