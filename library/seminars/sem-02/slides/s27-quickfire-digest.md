# Дайджест по чатам и почте

## Assertion

«Дайджест по чатам и почте — какая архитектура нужна?»

## Visual

Карточка: несколько иконок источников (чат, почта) → стрелка → иконка
сводного дайджеста. Справа — вопрос: «Какая архитектура здесь нужна?»

## Visual — цитата

«Обсуждали на планёрке — хотим еженедельный дайджест по рабочим чатам и
почте команды: что обсуждали, что решили за неделю, одним сообщением.
Нужен по пятницам к 17:00. Источников несколько: рабочий чат команды и
почта, у обоих есть API для выгрузки истории сообщений. Надо свести в
одно связное сообщение, а не склеить куски подряд. Кстати, отдельно
обсуждали, стоит ли переезжать на другой мессенджер, и параллельно
тестируем новое VPN-решение для удалёнщиков — но это не к дайджесту».

## Speaker notes

Зачитайте реплику целиком. Прямой сигнал, не выделен особо: нужен именно
еженедельный (по расписанию, не по запросу) дайджест по нескольким
конкретным источникам — рабочему чату и почте, — раз в неделю к пятнице
17:00, информацию нужно свести в одно связное сообщение. Косвенный сигнал
стоит вытащить: у обоих источников (чат и почта) уже есть API для выгрузки
истории — то есть техническая возможность собирать данные по расписанию
уже есть, вопрос только в том, какая архитектура обрабатывает собранное.
Переезд на мессенджер и тестирование VPN — шум-двойники: оба про
инфраструктуру коммуникации компании, но ни один не влияет на архитектуру
дайджеста. Вопрос в зал: какая архитектура здесь нужна — разовый вызов
модели, RAG, агент, или что-то ещё? Аргументируйте, не просто называйте
технологию — объясните, почему выбрали именно её, и что конкретно в
постановке навело вас именно на эту мысль. Кто готов? Аргументируйте свой
выбор. При разборе спросите: какие факты из реплики повлияли на ваш
выбор, а какие нет?
