Формулировки сведены из строк оси, сданных каждым разделом (`section-1-khuk.md` §A.15,

FAIL`, `section-1-khuk.md` §A.15/A.16, `section-7-vtoroy-barier.md` §A.5).

| Ступень | Предотвращаем / решаем | Интуиция говорила | Проверка показала |
|---|---|---|---|
| Хук | Решаем — правило уже нарушено | «Поставили хук — коммит в `main` закрыт» | Барьер обходится синтаксически пятью воспроизведёнными способами против ровно этого паттерна — и не видит человека, печатающего `git commit` в отдельном терминале |
| Скилл | Решаем — по сигналу перегрузки файла инструкций процедурой, нужной не всегда | «Содержание скилла — вот что важно, описание — деталь, можно дописать позже» | Без точного описания-триггера скилл не сработает вообще — модель выбирает по описанию, не по содержимому; разовое одобрение даёт постоянные права на исполнение кода |
| MCP | Смешанная: подключение — решаем, по сигналу; дисциплина минимальных прав — предотвращаем, день 0 | «Одобрил один раз, права выдал — вопрос решён; зелёный статус значит работает» | Права вычёркиваются, а не выдаются; одобрение не окончательно — 8 из 8 попыток сокрытия доставили инструкцию модели, 0 из 8 потребовали повторного одобрения; зелёный статус — утверждение о транспорте, не о работе |
| Субагент | Решаем — по сигналу повторения роли (одноразовая проверка целиком закрывается бесплатным встроенным делегированием) | «Чтобы поручить проверку отдельному агенту, нужно завести файл и настроить его» | Делегировать можно и без единой строки конфигурации — это уже бесплатно; заводить стоило не сам факт делегирования, а роль с урезанным набором инструментов, и оправдывает её повторение, не разовая проверка |
| Процесс | Предотвращаем, день 0 — план и запись по ходу дописываются сразу, без отдельного цикла ревью; полный цикл вердикта резервируется для решений, а не для каждой строки | «Агент, написавший "готово, тесты прошли", либо честно закончил, либо соврал» | Дело не в честности — самоотчёт структурно упускает большую часть реальных действий; гейт, который никто не обязан заполнять, не проваливают, его молча обходят, оставляя пустым |

**Синтез, который произносится вслух и не выносится отдельной строкой на слайд как афоризм, а идёт
частью той же реплики (assertion слайда):** у Семинара 4 та же ось раскладывалась 3:3; за эти два
занятия — один явный день-0 (процесс), одна смешанная (MCP), три по сигналу (хук, скилл,
субагент). Это не случайность и не слабость этой пары занятий: пять её ступеней — структурная
сложность, а правило лестницы (Лекция 3) требует для структурной сложности обоснования сигналом.
Именно поэтому в раскладке преобладает «по сигналу» — не потому что день-0-гигиены было мало, а
потому что три из пяти усилений и есть та самая структурная сложность, которую правило лестницы
просит обосновывать, а не заводить заранее. Тем ценнее две строки, которые в это правило не
попадают: процесс (день 0 целиком) и половина MCP (дисциплина прав, день 0 внутри смешанной
строки).

### A.3. sN-2 — три тезиса на вынос

**Заголовок:** «Если унести только три фразы».

Каждый тезис — на своей строке, каждая читается отдельно, без спешки; ни один не сворачивается в
афоризм без опоры. У первого и второго теперь есть по проверяемому усилению из материала этих двух
занятий — не новый кейс, а повторная сверка уже показанного.

1. **Правила в промпте — просьбы; правила в коде — законы.** Текстовый гейт ступени про процесс
   обходят молча, а хук ступени про барьер — нет, хотя и у него самого есть пять случаев, где он
   молчит. Это правило подтвердила не только собранная за два занятия статистика обходов, но и
   сама документация продукта, дважды и независимо: режим планирования — один и тот же механизм,
   в одной конфигурации сессии исполняемый барьер, в другой — просто напоминание, которое можно
   не заметить без единого запроса на подтверждение (`section-5-protsess.md` §A.7); а там, где
   барьер всё-таки сработал — хук родителя внутри субагента, — сработавший барьер ещё не значит
   барьер, который устоял: подтверждённых, до сих пор не разрешённых случаев, когда верное решение
   отклонить команду её всё равно не остановило, — два (`section-4-subagent-part1c.md` §A.10).
2. **«Поставил» ≠ «защищён», «подключён» ≠ «работает», «готово» ≠ «проверено».** Три формы одного
   и того же разрыва между отчётом системы о себе и фактом — первую из них зал уже видел на живом
   примере курса: исполняемый файл барьера в репозитории есть, а барьера нет, потому что ничто его
   не регистрирует.
3. **Права вычёркиваются, а не выдаются** — это верно и для сервера, подключённого по MCP, и для
   роли субагента.
