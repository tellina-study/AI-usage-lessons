# Разбор: где жить критерию «готово»

## Assertion

В файл инструкций идёт только невыводимое: критерий «готово», граница действий и способ проверки — и ничего, что агент допишет сам.

## Visual

Мелким шрифтом вверху — вопрос для контекста: «Куда записать критерий "готово"?»

Таблица разбора:

| Вариант | Где это работает | Почему здесь ещё рано — и что вместо |
|---|---|---|
| «Отвечу агенту в чате ещё раз» | Внутри одной сессии — полностью достаточно | Не переживает конец сессии: следующая начинается с пустого контекста. Вместо: записать туда, что читается само, без вашего участия |
| «Напишу в `README.md`» | README нужен людям, впервые открывшим репозиторий | README не подгружается в начало каждой сессии. Разные адресаты: README читает человек, если захочет; файл инструкций читает агент, хочет он того или нет |
| «Заведу файл инструкций с полным описанием архитектуры проекта» | Практически нигде: самый частый способ потратить контекст впустую | Агент выведет структуру кода сам за секунды. Раздел устареет при первом рефакторинге. Контролируемый эксперимент: такие файлы не дали измеримого прироста успеха, но подняли стоимость на 20–23% |
| «Допишу комментарий в `tests/form.spec.ts`» | Когда правило касается ровно этого файла | Агент откроет тест не в каждой задаче. Вместо: правило уровня проекта — в файл уровня проекта |
| «Пусть агент перепишет тест так, чтобы он проверял доставку» | **Правильный инженерный шаг — стоит сделать** | Но не закрывает задачу раздела: даже идеальный тест не скажет, чего делать нельзя. Не «вместо», а **вдобавок** |
| **«Заведу файл инструкций, но только с тем, чего агент не выведет из кода»** | **На этом шаге — именно то, что нужно** | **Не рано: сигнал сработал.** Перестаёт работать, когда файл начинает расти без обрезки |

## Speaker notes

Разбор идёт сразу после двух-трёх голосов зала, по шести позициям.

«Отвечу в чате» — внутри одной сессии достаточно, но следующая начинается с пустого контекста. «README.md» — README читает человек, если захочет; файл инструкций читает агент, хочет он того или нет. «Полное описание архитектуры в файле инструкций» — не иронизировать, это самый естественный импульс: «Разумно, если считать, что агент не понимает устройство проекта. Но он его понимает: он этот проект и собрал. А через месяц после рефакторинга этот раздел начнёт врать, причём уверенно.» «Комментарий в тесте» — правило уровня проекта должно жить в файле уровня проекта. «Пусть перепишет тест» — лучший из неправильных ответов, обесценивать нельзя: «Вы правы, и это надо сделать. Но представьте, что сделали: тест проверяет доставку. Объясните мне теперь этим же тестом, что деплоить на прод без спроса нельзя. Не получится.»

И целевой: файл инструкций, но только с тем, чего агент не выведет из кода.
