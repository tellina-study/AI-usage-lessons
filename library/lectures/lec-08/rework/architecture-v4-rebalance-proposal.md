# Лекция 8, архитектура v4 — ребаланс: распознавание, слитая «обвязка», сухие заметки

## 0. Решение одной строкой

Пять указаний владельца закрываются одним согласованным ребалансом: механика живого голосования
снимается при сохранении приёма «предсказание → вскрытие» (две пары кадров сливаются обратно,
−2 кадра); заметки лектора по всем кадрам ужимаются с ~46,8k до ~38k слов снятием рамочных
вступлений и отступлений (полная таблица §2); разделы 4+5+6 сливаются в один раздел «Счёт:
права, рынок и критерии отказа» (28 кадров → 16, 36,6 → ~23,5 мин), высвобожденный объём идёт
в Раздел 1 на новый блок «Как устроено распознавание» (6 кадров в Р1 + 2 payoff-кадра в Р2/Р3,
≈8,3 мин, факты проверены §4); storytelling-аудит даёт 16 правок заголовков/assertion (§5).
Итог: **71 кадр, ≈80,5 мин** против 76 кадров / 85,7 мин — люфт к 100-минутному слоту растёт
на ~5 мин и уходит в вопросы по ходу, слот не раздувается.

«полезно», «прежде чем», «не совпадение», «несмотря на то что») — колонка «что убрать»

Правила сжатия (бриф literary-editor): (а) рамки-вступления снимаются целиком, остаётся само
утверждение; (б) отступления-сравнения без новой информации снимаются; (в) НЕ трогать:
baseline/counterfactual-оговорки (мандат курса), оговорки честности («не присуждено»,
«причинность не признана»), сами числа и формы разборов; (г) методические самообоснования
(«почему этот приём работает») — под ноль.

## 4. Research-блок: распознающие модели — проверенные факты (п.4)

Проверено web-поиском 2026-10-26 из этой сессии (помечено ✓). Устоявшиеся ML-факты без
live-проверки помечены [станд.], спорные точности — [VFY].

**4.1 Дискриминативная vs генеративная задача [станд.]** Классификатор моделирует p(метка|вход),
генератор — распределение самого контента. Выход классификатора — вероятности по классам,
выход генератора — контент. Классическая опора: Ng, Jordan, «On Discriminative vs. Generative
Classifiers», NeurIPS 2001.

**4.2 На чём учат [станд. + официальные числа].** ImageNet-1k — 1,28 млн обучающих изображений,
1000 классов, разметка людьми (Russakovsky et al., arXiv:1409.0575). Loss — кросс-энтропия по
меткам; у LLM — та же кросс-энтропия, но по следующему токену (само-разметка из сырого текста),
у диффузии — ошибка предсказания шума. Урок для кадра R2: распознаватель требует ЧУЖОГО
ручного труда разметки — генератор учится на неразмеченном (пары «картинка—подпись» собраны,
не размечены) — это и есть экономическая разница двух классов.

**4.3 Общее с LLM: те же блоки, другая голова. ✓** ViT (Dosovitskiy et al., arXiv:2010.11929):
изображение → патчи → стандартный трансформер-энкодер; [CLS]-токен → линейная
classification head (подтверждено: huggingface docs, d2l.ai, Wikipedia «Vision transformer»,
доступ 2026-10-26); ViT-L с предобучением на JFT-300M — ~88% top-1 на ImageNet ✓. Та же
дихотомия в тексте: BERT (энкодер + classification head, arXiv:1810.04805) против GPT
(декодер-генератор) — блоки внимания одни, различие в задаче и голове. ResNet-50 — ~76%
top-1 [станд., He et al., arXiv:1512.03385] — как до-трансформерная опора, если нужна.

**4.4 Отличия в инференсе [станд.]** Классификация — один форвард-проход; диффузия — 20–50
проходов (research/05 §2); авторегрессия — проход на токен. Прямое следствие для кадра R1:
распознавание дёшево и мгновенно против генерации — то, что позволяет ставить его фильтром
внутрь конвейера (R4).

**4.5 Распознаватель внутри конвейера генерации.** CLIP-фильтрация LAION по косинусному
соответствию текста и картинки — уже в деке (s50, research/05) ✓. LAION-Aesthetics — отбор
финальной обучающей выборки SD «эстетическим предиктором» (laion.ai/blog/laion-aesthetics,
уже цитируется в s52) ✓. Safety-фильтр SD поверх выходов [VFY: формулировка по model card
CompVis/Stability — проверить при производстве].

**4.6 Детекторы дипфейков: провал обобщения. ✓** XceptionNet, обученный на FaceForensics++:
AUC 0,997 на своих данных → **0,48 на Celeb-DF** (arXiv:2204.04285); средний кросс-датасет
AUC по моделям ≈0,63; современные методы — 0,65–0,77 (подтверждено поиском 2026-10-26;
датасеты: FaceForensics++ arXiv:1901.08971, Celeb-DF arXiv:1909.12962). Причина — детектор
учится на артефактах конкретного генератора. Для кадра R5 использовать диапазон, не одно
число: «на своих данных 0,95+, на чужом генераторе — падение вплоть до уровня монетки».

**4.7 Детекторы против диффузии. ✓** Corvi et al., «On the detection of synthetic images
generated by diffusion models», ICASSP 2023, arXiv:2211.00680: детекторы, обученные на
GAN-изображениях, «work poorly» на диффузионных — новый класс генератора обнуляет детектор
предыдущего поколения. Опора старшего поколения: Wang et al., arXiv:1912.11035 («CNN-generated
images are surprisingly easy to spot… for now» — заголовок сам содержит оговорку «for now»,
которая и сбылась) [VFY: перечитать выводы при производстве].

**4.8 Текстовые детекторы. ✓** OpenAI AI Text Classifier: запущен в январе 2023, закрыт
20.07.2023 «из-за низкой точности» — TPR 26% на ИИ-тексте, FPR 9% на человеческом;
систематическое смещение против неносителей английского (openai.com/index/new-ai-classifier…,
подтверждено 2026-10-26). Для R6: автор лучшей на тот момент языковой модели не смог построить
её детектор — и честно это признал.

**4.9 Хрупкость к направленной атаке [станд.]** Adversarial examples: FGSM, «панда → гиббон
с уверенностью 99,3%» при невидимом глазу шуме (Goodfellow et al., arXiv:1412.6572). Кандидат
в заметки R5 (не отдельный кадр): распознаватель не просто плохо обобщается — он проигрывает
адаптивному противнику, что и делает «детекторную гонку» структурно проигрышной. Мост к Л14.

**4.10 Альтернатива: криптографическое происхождение. ✓** C2PA / Content Credentials —
подписанный манифест в файле в момент съёмки; Leica M11-P — первая серийная камера с C2PA,
октябрь 2023 (contentauthenticity.org, petapixel.com, подтверждено 2026-10-26); проверка —
валидация подписи, не суждение модели. Для R7: ответ на провал детекторов — не «детектор
получше», а другой класс инструмента: сдвиг с распознавания подделки на доказательство
подлинности. [VFY-day-of: статус внедрения C2PA у камер/платформ на дату чтения.]

при 23 мин; теперь больше. Почему предлагается считать рабочим: Р1 отвечает на два вопроса
стадии «кто это сделал» — «и чем сделал» (генерация) и «и кто это судит» (распознавание), оба
с под-дивайдерами, с возвратами к кейсам (R4→LAION/M4, R5→s06-найм) — и сам владелец просит
сместить вес именно сюда. Контроль тот же, что в v3: methodology-critic — вопрос «одна стадия
или три лекции»; запасная композиция — R-блок уезжает целиком в Р2 (распознавание — родная
механика стадии проверки; цена: рвётся симметрия s16 и мост R4→M4). Если и это «две лекции» —
R5/R6/R7 остаются, R1–R4 сворачиваются в два кадра (−2,4 мин глубины распознавания).

**Р-2. Детекторы против границы с Л14.** v3 прямо держала «детекторы не вводятся — территория
Л14»; указание №4 это отменяет, но Л14 ещё не переработана, и перенос границы может задвоить
материал при её производстве. Смягчение: граница сформулирована в §3.3 одним предложением
(«устройство и пределы — Л8; процедуры защиты — Л14»), s74 и дисклеймер главы переписываются,
решение фиксируется в decisions-owner.md. Остаточный риск низкий, но платит его Л14.

**Р-3. Слитый раздел против канона «строение раздела».** Канон требует открывать раздел
описанием стадии; слитый раздел покрывает две стадии (оплата прав, кадровый рынок) и сборку.
Разрешено так: M0 называет три масштаба счёта и перечисляет разборы по порядку; стадийное
заземление прав остаётся в M1 (классика лицензирования), рынка — строкой в M8 (из s57). Это
компромисс: заземление рынка худеет с кадра до строки. Если критика покажет «человек появился
ниоткуда» — возврат s57 отдельным кадром (+1,1 мин, люфт позволяет).

**Р-4. Сжатие заметок может срезать несущее.** Половина «воды» Л8 — это оговорки честности
(не присуждено, причинность не признана, честный пробел) и baseline-рамки, которые канон
ТРЕБУЕТ. Смягчение — правило (в) в §2 (явный no-cut список в брифе literary-editor) +
counter-check: после сжатия прогнать baseline-coverage sample по Pre-USER-GATE п.12.
Остаточный риск средний — ловится fact-checker'ом на диффе.

**Р-5. «Удивление без голосования» может не сработать в зале.** Слитые кадры M5 и s18/19
показывают вопрос и ответ одним экраном — глаз зала видит ответ раньше, чем лектор задал
вопрос. Принято осознанно: владелец снимает механику остановки, а для листающего деку
читателя один кадр самодостаточнее пары. Лектор может удерживать паузу голосом; если нужен
экранный саспенс без голосования — вариант Б: оставить пары кадров, сняв только инструкции
голосования (−0 кадров, +0,8 мин против плана). Решение за владельцем — вопрос №2.

**Р-6. Неоднозначности, разрешённые мной самостоятельно:** (а) «убрать вопросы к залу» прочитано
