# Первый инстинкт — описать структуру

## Assertion

Первый инстинкт — открыть пустой файл и начать с описания структуры репозитория; привычка сильная, но это ровно та фраза «так делают в хороших проектах», которую занятие проверяет впервые.

## Visual

Дерево на входе в кейс:

```
index.html
package.json
src/main.js
tests/form.spec.ts
# + spec.md, README.md (раздел 0) — здесь не показаны
```

Последняя строка — пометка (Fix 5, round-6 QA), не часть реального капчура: `spec.md`/`README.md`
уже существуют в репозитории с раздела 0, просто не входят в этот конкретный список
(product-слой, не конфигурация агента, которую разбирает кейс 1.1).

Справа — сценарий: разработчик открывает пустой `CLAUDE.md` для `signup-landing` и по привычке из прошлых проектов тянется первым делом написать «Repository overview»: из чего собран сайт, где лежит форма, какая структура папок.

Ниже, в gold-рамке — анекдот коллеги:

> «Он уже видел, чем это кончается: в одном из прошлых проектов раздел "Overview" пережил рефакторинг и два месяца спустя продолжал описывать структуру, которой больше не существовало — агент один раз отредактировал не тот файл, поверив описанию, а не факту.»

На этом слайде нет ни вопроса, ни карточек-вариантов — они на следующем слайде.

## Speaker notes

«Пустой репозиторий, форма и тест уже написаны, а CLAUDE.md — ни строки. Первый инстинкт многих из вас — открыть файл и начать с описания: что это за проект, как он устроен, где что лежит. Один разработчик так и сделал в прошлом проекте. Два месяца спустя, после рефакторинга, раздел "Overview" по-прежнему описывал структуру, которой уже не было — и агент один раз отредактировал не тот файл, поверив описанию вместо того, чтобы посмотреть в реальный код. Это тот самый "так делают в хороших проектах" из начала занятия. Сегодня проверяем его первый раз на практике.»
