# Наш собственный скилл сработать не может

## Assertion

Наш build-deck виден в перечне как «build-deck: build-deck»: описанием стала первая строка файла. Готовое описание лежит строкой ниже, и его никто не читает.

## Visual

> Что надо дописать в этот файл, чтобы скилл начал срабатывать сам? Назовите недостающие части, а не готовую формулировку.

```
.claude/skills/build-deck/SKILL.md          151 строка, добавлен 14 мая, ae6e30c3

  1  # build-deck
  2
  3  Build/rebuild a PowerPoint (PPTX) presentation for a lecture
  4  using the repo-first pipeline + visual loop + 3 QA agents.

в перечне доступных скиллов он виден так:    build-deck — build-deck

официальный список антипаттернов описания, дословно:
    description: Helps with documents      (помогает с документами)
    description: Processes data            (обрабатывает данные)
    description: Does stuff with files     (делает что-то с файлами)
```

## Speaker notes

Это наш скилл. Он собирает вот эту самую презентацию.

Посмотрите на строку первую и строку третью. В первой — заголовок. В третьей — нормальное человеческое описание: собирает презентацию лекции по такому-то конвейеру. Кто-то его написал. Написал хорошо. И оно не работает.

Потому что в перечне доступных скиллов этот файл виден вот так: «build-deck — build-deck». Имя вместо описания.

Если спросите, сломан ли он, — нет. Наберу `/build-deck` — отработает как часы. Не может он другого: сработать сам, по смыслу того, что я прошу. Модель выбирает нужный скилл из сотни установленных по описанию, и сопоставлять ей тут не с чем: слово «build-deck» не похоже ни на «собери презентацию», ни на «пересобери деку лекции».

Три формулировки внизу — из официального списка антипаттернов, дословно. Так пишут, когда торопятся. Наш случай честнее и обиднее: мы не поленились, мы написали описание. Мы положили его строкой ниже, чем надо.

Вопрос вам: какие части нужно дописать в этот файл. Не формулировку целиком — части.

*Два-три голоса, не комментирую. Собираем на следующем слайде.*
