# Когда каждый метод нужен, а когда — нет

## Assertion

Хэш — только на точный повтор файла; плитки — только на видимый объект; печатный текст на сканах не решается ни тем, ни другим.

## Visual

| Метод | Нужен | Не нужен |
|---|---|---|
| Перцептивный хэш | Тот же файл, возможно пересжатый или пересохранённый — дешевле и быстрее любой модели | Документ развёрнут, обрезан, снят под другим углом; вопрос упирается в смысл содержимого |
| Эмбеддинг целым кадром | Смысловая похожесть, неточный повтор | Точный повтор, поиск мелкой детали |
| Нарезка на плитки + эмбеддинг | Деталь — видимый объект или паттерн (логотип, текстура, предмет), который модель узнаёт по внешнему виду | Печатный текст на сканированном документе моделью общего назначения — нужен слой распознавания текста + текстовый поиск |
| Поиск по точному слову (обратный индекс) | Вопрос «есть ли документ с этой строкой» — дешевле и точнее любой модели | Вопрос про смысл содержимого — не про буквальное совпадение строки |

## Speaker notes

Граница прямой формой, собранная после собственного замера — не только по архитектурному разделению задач. Перцептивный хэш нужен, когда вопрос именно «тот же файл, может быть пересжатый или слегка пересохранённый», — он дешевле и быстрее любой модели. Он не нужен и не работает, когда документ развёрнут, обрезан или снят под другим углом, и тем более когда вопрос упирается в смысл содержимого, а совпадение самого файла уже не главное — там оправдан эмбеддинг, хотя и он не бесплатен ни по деньгам, ни по точности.

Дробление на плитки и поиск по вектору каждой плитки имеет смысл, когда искомая деталь — видимый объект или паттерн, который эмбеддинг-модель умеет узнавать по внешнему виду: логотип, характерная текстура, конкретный предмет на фотографии. Для задачи «найди мелкий печатный текст на отсканированном документе» векторный поиск на базе модели общего назначения — не тот инструмент независимо от размера плитки: нужен слой распознавания текста и текстовый поиск на результате распознавания, и это подтверждено третьей, контрольной веткой собственного замера этого кейса, не предположением по аналогии.

Третья строка добавлена находкой этого же замера: когда вопрос звучит «есть ли документ, где встречается вот эта строка», правильный инструмент — простой поиск по точному слову, обратный индекс, — он дешевле и точнее любой модели с вектором, и это измерено на порядок, не на доли процента. Он не годится, когда вопрос ставится про смысл содержимого — буквального совпадения строки там уже нет, нужен эмбеддинг.

Вместе три строки складываются в правило кейса целиком: сначала называется задача, которую на самом деле решают, и только потом под неё берётся инструмент. Ни одна нарезка, ни одна модель общего назначения не превращает инструмент, устроенный для одной задачи, в инструмент для другой.
