## Проход 1 — расхождения чисел

### Н1 (P0) — арифметическая ошибка внутри `09d`: доля США от мирового рынка не следует из собственных чисел файла

**Где:** `09d-obyomy-rezultaty-effekty.md:39-43`.

**Цитата:** «Рынок медизделий США оценивается в **$188,7 млрд (2024)**... Глобальный рынок медизделий
в том же 2024 году оценивается в **$528,9 млрд**; отсюда доля США — **чуть больше 40%**».

**Проверка:** 188,7 / 528,9 = **35,7%**, не «чуть больше 40%». Это не методологическая разница
между файлами — это арифметика, которая не следует из собственных входных чисел **внутри одного
файла**. Разница (35,7% против заявленных >40%) — 4,3 п.п., не округление.

**Рекомендация:** пересчитать и исправить формулировку на «~36%», либо если имелась в виду другая
пара чисел (встречающееся в индустрии общее место «США ≈40% мирового рынка медтеха» — возможно,
это и есть источник ошибки: автор смешал общеизвестный округлённый факт с собственным точным
расчётом) — назвать явно, какую пару чисел использовать, и держать её одной по всему файлу.
Это тем более важно, что именно эта цифра («40% мирового рынка») — готовый кандидат на слайд.

### Н2 (P1) — Россия: плотность МРТ на миллион населения — два разных числа без сверки

**Где:** `09c-mir-lidery.md:274` против `09d-obyomy-rezultaty-effekty.md:135`.

**Цитата 09c:** «среднероссийская обеспеченность МРТ — не более **4 аппаратов на млн населения**»
(источник — И. Тюрин, Минздрав, «исходная цифра **2016** года»).

**Цитата 09d:** «МРТ: **5,2 установки на млн населения** (≈750 аппаратов по стране)» — **год не
указан вовсе**.

**Вывод:** это одна и та же метрика (плотность МРТ на млн населения в РФ в целом, без
Москвы/СПб), два разных значения (4 vs 5,2, разница +30%), никакой перекрёстной ссылки между
файлами нет. 09c честно датирует свой источник (2016, устаревший), но 09d даёт более новое на вид
число без даты — непонятно, это более свежая оценка, другая методология подсчёта, или просто
другой агрегатор с той же или худшей надёжностью. КТ-плотность в обоих файлах сходится (13 на млн
— 09c со ссылкой на Тюрина/2016, 09d со ссылкой на Росстат/2017) — совпадение по счастливой
случайности двух независимо найденных, по-разному датированных источников, тоже не сведённых
явно друг с другом.

**Рекомендация:** датировать число 5,2/750 в `09d` (указать источник и год); если год более
поздний, чем 2016 — явно написать «более свежая оценка, заменяет цифру Тюрина»; если нет —
представить как диапазон 4–5,2 с оговоркой о разных источниках, а не как два несвязанных факта в
разных файлах.

### Н3 (P1) — Россия: доля отечественных изделий в госзакупках — третье число не свёдено с уже существующей таксономией долей

**Где:** `09b-dopusk-rossiya.md:440-443` + `09c-mir-lidery.md:84` против
`09d-obyomy-rezultaty-effekty.md:100-103`.

**Цитата 09b (и идентично 09c):** «в среднем по рынку закупок — около **28,5%** (Минпромторг,
общая оценка)».

**Цитата 09d:** «по закупкам медоборудования **2024 года** отечественная доля превысила **63%**
(зависит от того, считать ли расходники/простую технику или сложное оборудование)».

**Вывод:** `09b` §2.5 уже построил аккуратную таксономию из как минимум четырёх разных «долей
отечественного» (по штукам новых РУ, по деньгам на всём рынке, по госзакупкам в среднем 28,5%,
по первичному звену отдельно до 70%, по квотам КТ/МРТ отдельно). `09d` вводит **пятое** число
(>63% за 2024 год закупок медоборудования) с собственной оговоркой про корзину, но **не
ссылается** на уже существующую таксономию `09b` и не объясняет, в какую именно из уже названных
категорий оно попадает — выглядит как независимое, несведённое с остальными число, хотя по смыслу
могло бы просто уточнить один из уже названных диапазонов (например, совпадать с «первичное звено
→ 70% к 2026» или быть отдельной пятой корзиной).

**Рекомендация:** при следующей правке явно привязать число из `09d` к таксономии §2.5 `09b` —
либо показать, что это пятая корзина (и назвать её прямо), либо показать, что оно согласуется с
одной из уже названных.

## Проход 3 — доля strict-in по каждому файлу отдельно

### Методика

Файл делится на секции по `##`/`###` заголовкам; каждая секция вручную размечена as `in`
(полностью strict-in: документированный провал+урок, ИЛИ фундаментальное ограничение подхода,
ИЛИ явный критерий неприменимости, ИЛИ сравнение с лучшей альтернативой) или `out` (всё прочее,
включая смешанные/частично-bucket секции — "partial → out" по правилу брифа). Подсчёт слов —
Python `re.findall(r"[^\s]+", text)` — без `\b`/`\w` на кириллице (известный ложный-ноль баг
`grep -P`, см. `notes/mcp-limitations.md` [#225-1] и memory `cyrillic-search-pitfalls`).

**Методологическая оговорка:** секции делились на уровне `##`/`###`, не глубже. В одном месте
(`09b-dopusk-rossiya.md` §1.8, строки 261–302) внутри одной `###`-секции смешаны описание
классификации СаМД (out) и явный регуляторный спор «ИИ-софт автоматически класс 3» (~20 строк,
само по себе strict-in по критерию 3 — сравнение с международной практикой). По правилу
"partial → out" вся секция 1.8 посчитана out. Проверка на более грубой оценке (эти ~20 строк
отдельно) показывает, что это добавило бы части 1 `09b` не больше ~4% — ниже порога 30% в любом
случае, так что итоговый вердикт по части 1 не меняется от выбора глубины разбиения.

Для сопоставимости между файлами итоговые секции-«сводки»/рекапы в конце каждого файла
(`## Сводка в числах`, `## N утверждений под слайд`) **везде** посчитаны `out`, даже там, где
содержательно весь рекап состоит из strict-in-тематических строк (`09d-part2` §6) — это сделано
единообразно для всех 7 файлов, чтобы не давать части файлов "бонус" за повторное изложение уже
посчитанного материала в сжатом виде.

### Скрипт

```python
# -*- coding: utf-8 -*-
import re

BASE = "library/lectures/lec-07/rework/research/"

def wc(lines):
    text = "".join(lines)
    # простая пунктуация/пробел-токенизация, безопасна для кириллицы
    # (НЕ \b/\w — на кириллице в PCRE-режиме это считает по байтам и даёт ложный ноль)
    words = re.findall(r"[^\s]+", text, re.UNICODE)
    return len(words)

def load(fname):
    with open(BASE + fname, encoding="utf-8") as f:
        return f.readlines()

def analyze(fname, ranges):
    lines = load(fname)
    n = len(lines)
    total_in = total_words = covered = 0
    for (a, b, bucket, label) in ranges:
        chunk = lines[a-1:b]
        covered += (b - a + 1)
        w = wc(chunk)
        total_words += w
        if bucket == "in":
            total_in += w
    assert covered == n, f"{fname}: covered {covered} lines, file has {n}"
    pct = 100.0 * total_in / total_words if total_words else 0
    return total_words, total_in, pct

# FILES[fname] = [(line_start, line_end, "in"|"out", "метка секции"), ...]
# полная разметка по всем 7 файлам — см. /tmp/sogl/strict_in.py в сессии оркестратора;
# разметка воспроизводима по заголовкам ## / ### каждого файла (см. таблицу секций ниже)
```

сделана вручную по содержанию каждой секции, подсчёт слов — автоматический.

### Н8 (P0) — структурный: `09b` часть 1 не проходит требование ≥30% strict-in как отдельный артефакт

Бриф явно требует измерять долю **в каждом из семи файлов отдельно, не в сумме**. `09b-dopusk-rossiya.md`
