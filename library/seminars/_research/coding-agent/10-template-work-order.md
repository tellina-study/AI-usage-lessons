# Задание на доработку `base-project-template` — наряды на работу

## Как пользоваться этим документом

Документ разбит на два файла (лимит 600 строк на файл в этом курсе):

- **Этот файл** — вводный блок (репозиторий, правила, механика сборки, сдача работы, оценка
  объёма) + наряды 1–7 (правки самого шаблона).
- **`10-template-work-order-part2.md`** — наряд 8: учебная сборка, разбитая на подзадачи.

Каждый наряд самодостаточен — обоснование содержит конкретную цифру/дату/инцидент, не только
ссылку. Исполнитель этого задания имеет доступ к закрытому репозиторию курса
(`library/seminars/_research/coding-agent/`), где для каждого блока (память, хуки, MCP, скиллы,
субагенты, процесс, провалы) есть отдельный разбор — `01-instruction-files.md`,
`02-memory.md`, `03-hooks-permissions.md`, `04-failures-evidence.md`, `05-mcp.md`,
`06-process-roast-log.md`, `07-skills.md`, `08-subagents.md`. Внутренние ссылки на них в
обоснованиях ниже — рабочие, не тупиковые: перед тем как брать конкретный наряд, стоит открыть
файл, на который он ссылается, — там разбор глубже, чем помещается в одну строку обоснования.
Внешние проверяемые ссылки (CVE, arXiv, официальная документация) даны там, где добавляют вес
без раздувания текста — не как исчерпывающий библиографический список.

## Репозиторий, в котором идёт работа

### Что это за репозиторий

`workain/agent-harness-registry` — структурированный, пополняемый реестр «снаряжения» для
AI-агентов: атомарные **компоненты** (память, скиллы/инструменты, субагенты, доступ к внешним
системам через MCP, файлы инструкций) и собранные из них **бандлы**, плюс каталог **движков**
(Claude Code, Codex CLI, Aider…) и **бенчмарков**. Данные лежат в `data/**/*.yaml`, читаемый
артефакт — сгенерированный `GUIDE.md` (генератор — `scripts/generate.py`, `GUIDE.md` руками не
редактируется). У каждого компонента и бандла есть обязательный `deep_dive:` — файл с разбором
«когда использовать, как начать, какие грабли».

Внутри этого реестра — `templates/base-project-template/` — типовой стартовый набор файлов
для НОВОГО проекта, который заводит у себя agent-harness (`CLAUDE.md`, память, хуки, скиллы,
субагенты, дисциплина задач). Он существует в двух отрисованных вариантах:

- **`with-git/`** — для git-репозитория, с механическим хуком защиты ветки.
- **`without-git/`** — для проекта без git, без этого хука (копия хука без реального репозитория
  работала бы тихо и создавала ложное чувство защиты — хуже, чем явное отсутствие).

Оба варианта на 90%+ идентичны, поэтому вручную не дублируются: есть единый источник —
`common/` (всё общее целиком: `LESSONS.md`, `DECISIONS.md`, `knowledge/notes.md`,
`Tasks/README.md`, `.claude/{skills,agents,environment}/`) и `fragments/` (три куска
`CLAUDE.md`, из которых собирается по одному файлу на вариант). Скрипт
`render_templates.py` копирует `common/` в оба варианта и склеивает фрагменты в `CLAUDE.md`
каждого — подробнее в разделе «Как не сломать отрисовку» ниже.

### Правила репозитория, обязательные к соблюдению

- **Таксономия размещения файлов** (полностью — в корневом `README.md`, здесь — то, что
  затрагивает именно эти наряды): компонент — `data/components/<category>/<slug>.yaml` +
  `deep-dives/components/<category>/<slug>.md`, категория YAML и подпапка обязаны совпадать —
  генератор падает, если нет; бандл — `data/bundles/*.yaml` + `deep-dives/bundles/*.md`, без
  category-подпапки (это плоская, редкая категория по решению issue #32). `first_party: true`
  ставится только на то, что реально написано этой лабораторией (workain), не на чужой
  инструмент, даже отлично работающий.
- **Provenance rule (обязательное правило репозитория).** Каждое нагруженное утверждение в
  записи — либо цитата/пересказ реально открытого источника (в списке `provenance` записи), либо
  явная пометка `[unverified — <причина>]`. Маркетинговая формулировка проекта никогда не
  проходит как факт без проверки.
- **Дисциплина `Tasks/<slug>/`.** Каждый нетривиальный артефакт — новая запись, ранжирование,
  правка таксономии — получает `Tasks/<slug>/` с обязательным `log.md` (что делалось и почему, по
  ходу работы, не восстановлено по памяти после) и независимым `roast.md` (адверсариальная
  прожарка перед мержем — самоотчёт исполнителя никогда не достаточен). Формат папки —
  `<YYYYMMDD>_<slug>/` или `issue-NNN-<slug>/`. Папки не удаляются — это аудиторский след.
  Pre-commit хук репозитория (`scripts/pre-commit-checks.sh`) предупреждает, если `Tasks/<slug>/`
  тронута без `log.md`.
- **Ссылаться на то, что реально приземлилось, а не на самоотчёт.** ROAST — независимая
  прожарка: проверяет, что заявленное в `log.md` действительно существует на диске/в git, а не
  принимает формулировку «готово» на слово. Тот же принцип, что в наряде 8 ниже (ступень 7) —
  не декоративное требование только для этого задания, а правило самого репозитория.
- **Git-цикл.** Никогда не пушить прямо в `main`. Ветка `issue-NNN-description`, PR, доска
  `workain`-org (Project #3) — issue и PR добавляются на неё сразу. Никогда не мержить
  собственный PR и не прожаривать себя самостоятельно. Никогда не вызывать `gh pr merge`/
  `gh api .../pulls/<N>/merge` напрямую — только `scripts/safe-merge.sh <PR_NUMBER>` (он проверяет
  наличие PASS-вердикта независимой прожарки на файле для этого PR перед мержем). Это правило
  соблюдается независимо от того, стоит ли локально git-хук, который его же и проверяет — хук
  ловит только буквальный `gh` в команде, обходной путь через `curl` к тому же REST/GraphQL
  эндпоинту хуком не ловится, поэтому дисциплина, а не хук — гарантия.

### Как не сломать отрисовку

Любая правка внутри `common/` или `fragments/` обязана закончиться прогоном скрипта
`templates/base-project-template/render_templates.py` (сам скрипт — простой, без сетевых
обращений, единственная зависимость — стандартная библиотека):

```bash
python3 render_templates.py           # переписывает with-git/ и without-git/ из common/+fragments/
python3 render_templates.py --check   # только проверяет — код выхода 1 и список расхождений, если что-то разошлось
```

Механика: `render_claude_md(variant)` конкатенирует `fragments/claude-core-top.md` +
(`fragments/claude-with-git.md` либо `fragments/claude-without-git.md`) +
`fragments/claude-core-bottom.md` — результат построчно сравнивается с закоммиченным
`<variant>/CLAUDE.md`. Отдельно — каждый файл `common/**/*` побайтово сравнивается с одноимённым
файлом в обоих вариантах (`filecmp.cmp(..., shallow=False)`). Расхождение любого рода —
`DRIFT`, отсутствие файла в варианте — `MISSING`; любое из двух — код выхода 1.

**Правило для каждого наряда ниже:** правишь `common/` или `fragments/` — обязательно
`python3 render_templates.py` (без `--check`, чтобы переписать обе копии), затем
`python3 render_templates.py --check` — приёмка наряда не засчитывается без PASS этой команды.
Если наряд правит только один конкретный вариант напрямую (например, `with-git/README.md` —
такие файлы `render_templates.py` не генерирует и не проверяет), это отдельно оговорено в самом
наряде.

### Как сдавать работу

1. Ветка `issue-NNN-<короткое-описание>` от актуального `main`, `NNN` — номер issue в трекере
   `workain/agent-harness-registry` (issue заводится перед началом работы, если его ещё нет —
   правило репозитория «no work without an issue», унаследованное от PMO-слоя).
2. Коммитить рано и часто; пушить после каждой осмысленной единицы работы.
3. `Tasks/<slug>/log.md` — по ходу, не постфактум.
4. Независимая прожарка — `Tasks/<slug>/roast.md`, вердикт `PASS`/`BLOCK`. Каждый наряд ниже
   мержится отдельным PR (см. «Порядок выполнения») — не смешивать несколько нарядов в одном
   PR, это усложняет и прожарку, и ревью.
5. Критерий приёмки для каждого наряда — см. соответствующий раздел; для нарядов, трогающих
   `common/`/`fragments/`, обязательный компонент критерия — PASS `render_templates.py --check`.
6. PR открывается только после `log.md` + `roast.md` с вердиктом `PASS`; мерж — только через
   `scripts/safe-merge.sh <PR_NUMBER>`, не вручную.

## Наряд 1 — Добавить абзац безопасности в `claude-core-top.md`

**Приоритет:** P0

**Проблема.** `templates/base-project-template/fragments/claude-core-top.md`, раздел
«Safety / scope boundaries», сейчас содержит только общую заготовку-комментарий
(«fill in constraints an agent would not otherwise infer»). Ни слова про то, что
`.claude/settings.json` — исполняемый артефакт; ни про режимы разрешений
(`plan`/`acceptEdits`/`bypassPermissions`); ни про то, что принятое один раз доверие к папке
распространяется на хуки и блок `env` без отдельного подтверждения каждой команды.

**Обоснование.** Две разные уязвимости Claude Code, которые нельзя путать, — механизмы у них
противоположные:

- **`GHSA-ph6w-f82w-28w6`** (высокая, **без CVE** — `cve_id: null`, опубликовано 03.09.2025):
  предупреждение «Do you trust the files in this folder?» не документировало, что «Yes,
  proceed» разрешает Claude Code исполнять файлы этой папки **без дополнительного
  подтверждения**. То есть доверие дано — а отдельного подтверждения команды нет; механизм
  хуков сам по себе является поверхностью исполнения.
- **`CVE-2025-59536`** (CVSS v4.0 8.7 HIGH, `GHSA-4fgq-fpq9-mr3g`, опубликовано 03.10.2025,
  исправлено в версии 1.0.111): код из проекта исполнялся **до** того, как пользователь принял
  диалог доверия, — обход согласия, а не его чрезмерная широта. Разбор Check Point Research:
  `research.checkpoint.com/2026/rce-and-api-token-exfiltration-through-claude-code-project-files-cve-2025-59536`.

Коротко: первая — «доверие дано, а команда не подтверждена», вторая — «доверие ещё не дано».
Плюс CVE-2026-21852 (утечка API-ключа через `ANTHROPIC_BASE_URL` в чужом `settings.json`) —
конфигурационная CVE того же класса. Разбор построчно — `03-hooks-permissions.md`, §5.

Отдельно — деструктивные инциденты, которые останавливает именно
базовая позиция «не разрешать всё по умолчанию»: `rm -rf ~/` (Claude Code, декабрь 2025, сводка
Docker Blog — `docker.com/blog/coding-agent-horror-stories-the-rm-rf-incident`) и удаление
продакшен-БД Replit в обход явного, несколько раз повторённого code freeze (~1206 записей о
руководителях и ~1196 о компаниях уничтожены, ~4000 фейковых профилей сфабриковано; The
Register, 21.07.2025 — `theregister.com/2025/07/21/replit_saastr_vibe_coding_incident`);
источник для обоих — `04-failures-evidence.md`, таблица инцидентов.

**Что сделать.** 4–5 строк в `fragments/claude-core-top.md`, сразу после заголовка «Safety /
scope boundaries», внутри уже существующего блока (не новый файл): (1) `.claude/settings.json`
— исполняемый код, ревьюить диф на этот файл так же, как код, особенно из PR/форка;
(2) принятое доверие к папке распространяется на хуки и `env`-блок без отдельного
подтверждения каждой команды (`GHSA-ph6w-f82w-28w6`) — не открывать `claude` в непроверенном
клоне без `--setting-sources user` или предварительной проверки файла; (3) `bypassPermissions`
— только в одноразовом изолированном окружении без секретов и сети наружу; (4) `deny` в
`permissions` всегда побеждает `allow` — единственный надёжный способ гарантированно запретить
действие, не текст в CLAUDE.md. После правки прогнать
`python3 render_templates.py` (без `--check`, чтобы переписать обе копии), затем
`python3 render_templates.py --check` — должен быть PASS.

**Критерий приёмки.** `render_templates.py --check` → PASS для обоих вариантов; добавка ≤6
строк внутри существующей секции, не отдельный файл; ни один из `with-git/CLAUDE.md` /
`without-git/CLAUDE.md` не увеличился более чем на эти строки.

**Триггер.** Сквозной минимум с нулевой ступени — не привязан к конкретной ступени лестницы;
применяется с первого дня, а не «когда споткнулись».

**Риск переусложнения.** Полноценный `SECURITY.md` был бы избыточен — отдельный документ
требует поддержки и рискует замереть после bootstrap так же, как файл уроков без промоционного
цикла. Раздел внутри уже читаемого каждой сессией файла честнее лишнего файла, который никто не
откроет второй раз.

## Наряд 2 — Добавить памятку про MCP + строку в growth ladder

**Приоритет:** P0

**Проблема.** MCP не упомянут нигде в шаблоне — ни в скелете `CLAUDE.md`, ни в growth-ladder
таблице `deep-dives/.../design-and-usage.md` (5 строк, все про хуки/оркестрацию), ни даже в
разделе «What's deliberately NOT here» (`with-git/README.md`), который явно перечисляет
сознательно не сделанное (blueprint-бандл, ontology-слой, epic-register, delegated-merge-tier).
MCP в этот список не попал — значит, его отсутствие не решение, а пробел.

**Обоснование.** Детальный разбор — `05-mcp.md`. Ключевые инциденты: эксфильтрация приватных
репозиториев через GitHub MCP (26.05.2025, Invariant Labs —
`invariantlabs.ai/blog/mcp-github-vulnerability`, независимо подтверждено Simon Willison —
`simonwillison.net/2025/May/26/github-mcp-exploited`); межарендная утечка Asana MCP на 1000+
организаций (The Register, 18.06.2025 —
`theregister.com/security/2025/06/18/asana-mcp-server-back-online-after-plugging-a-data-leak-hole`);
демонстрация утечки БД через Supabase MCP по схеме «смертельного трио» (Simon Willison,
06.07.2025 — `simonwillison.net/2025/Jul/6/supabase-mcp-lethal-trifecta`, рамка трио —
`simonwillison.net/2025/Jun/16/the-lethal-trifecta`, 16.06.2025); CVE-2025-53109/53110 в
эталонном Filesystem MCP-сервере самого Anthropic (Cymulate, «EscapeRoute» —
`cymulate.com/blog/cve-2025-53109-53110-escaperoute-anthropic`). Цена без риска: связка из 5
серверов — 26 224 токена (13,1% от окна 200К) на каждый запрос
(`github.com/zhang-liz/mcp-token-benchmark`); прямое сравнение одного и того же действия —
1 365 токенов через CLI против 44 026 через MCP (источник — блог, не перепроверен независимо,
см. `05-mcp.md`, таблица источников, помечено как таковое).

**Что сделать.** Файл `common/.claude/mcp-notes.md` (короткая памятка, 5 пунктов, не гайд):
(1) MCP — не первый инструмент, за которым нужно тянуться: сначала проверить, не хватит ли
Bash-вызова существующей команды (`gh`/`psql`/`aws`); (2) конфигурация — `.mcp.json` в корне
при `project`-scope, ревьюится как код; (3) минимальный набор — отключать неиспользуемое,
каждый сервер — постоянные токены контекста и точка отказа; (4) проверка «lethal trifecta»
перед подключением: приватные данные + недоверенный внешний контент + канал наружу
одновременно → не подключать без разделения на сессии; (5) для HTTP-транспорта — только
OAuth-поток. Плюс одна строка в growth-ladder таблице `design-and-usage.md` (ось «Доступ к
внешним системам», триггер «обычной команды не хватает») и однострочный указатель в
`claude-core-bottom.md` § «Where things live», по аналогии со Skills/Subagents. После

## Наряд 5 — Добавить самотест хука защиты ветки

**Приоритет:** P1

**Проблема.** `with-git/.claude/settings.json` содержит рабочий `PreToolUse`-хук защиты ветки,
но рядом с ним нет исполняемого самотеста. Доказательство, что хук реально срабатывает, живёт
только в `design-and-usage.md` — документе, который студент, скопировавший `with-git/` в свой
проект, никогда не увидит. При этом сам шаблон уже формулирует правило, которое сейчас же и
нарушает — цитата из `claude-core-bottom.md`: «a gate is not installed because its file
exists — it is installed once observed firing against a real case. Ship each with a
self-test...».

**Обоснование.** Разбор — `03-hooks-permissions.md`, §5. Один невалидный matcher в
`settings.json` отключает все хуки файла без единого сообщения об ошибке (задокументировано
независимо через decision tree по issues репозитория `anthropics/claude-code`, Alex Dunlop,
2026); хук, не уложившийся в таймаут (30 с у `UserPromptSubmit`), не блокирует — он просто не
срабатывает, что неотличимо от «правило соблюдено». Дословно: «не сработавший гейт выглядит
точно как прошедший гейт». Подтверждающий пример того же класса риска —
`GHSA-ph6w-f82w-28w6` (наряд 1): пользователь видел диалог доверия и полагал, что защита есть,
а исполнение файлов папки после «Yes, proceed» отдельного подтверждения уже не требовало.
Разрыв между «защита выглядит включённой» и «защита срабатывает» в обоих случаях один и тот же.

**Что сделать.** Файл `with-git/.claude/hooks/selftest-branch-guard.sh` (variant-specific,
живёт прямо в `with-git/`, не в `common/` — как и сам `settings.json`), плюс пункт в Quick
start `with-git/README.md` сразу после шага `git init`. Содержание (5-6 шагов): (1) создать
временный git-репозиторий во `/tmp`, скопировать туда `.claude/settings.json`; (2) спровоцировать
блокировку — либо реальным коммитом на `main` через тот же хук-путь, либо прямым прогоном JSON
через хук-команду (`echo '{"tool_input":{"command":"git commit -m test"}}' | <hook-command>`);
(3) проверить, что `permissionDecision` равен `deny` с ожидаемым текстом; (4) прогнать тот же
тест на unborn HEAD (пустой репозиторий без коммитов) — ожидается **`deny`**, не `ask` и не
тихий пропуск: на неродившемся HEAD ветка уже известна, `git symbolic-ref --short HEAD`
возвращает `main` с кодом 0 (в отличие от `git rev-parse --abbrev-ref HEAD`, который падает с
кодом 128), поэтому защита обязана срабатывать здесь так же, как на обычном коммите в `main`;
(5) отдельным случаем — `ask`, когда каталог вообще **не** является git-репозиторием
(`git rev-parse --is-inside-work-tree` не проходит): хуку нечего проверять, и он обязан сказать
это вслух, а не промолчать; (6) явная инструкция повторять после любого обновления Claude Code
или правки `settings.json`.

Это не педантизм по поводу одного слова: тест, написанный по прежней букве наряда, провалился
бы против **правильного** хука, а «очевидная починка» такого провала — сломать хук. Сам хук
шаблона (`with-git/.claude/settings.json`) уже написан верно: `ask` в нём зарезервирован
ровно за случаем «это не git-репозиторий», а ветка резолвится через `git symbolic-ref`.

**Важно не забыть при проработке Семинара 5: шестой случай, которого в самотесте нет и быть не
может.** Все пять случаев выше — про одно: срабатывает ли хук на вызов инструмента **агентом**.
Шестой шире их всех вместе взятых: `PreToolUse` — механизм харнесса Claude Code, он
перехватывает вызовы инструментов агентом и **не видит вообще** человека, набравшего
`git commit` руками в своём терминале. Это не `.git/hooks/pre-commit` — сам репозиторий про
этот хук ничего не знает. Следствие для несущей формулы занятия («правила в коде — законы,
правила в тексте — просьбы»): для агента она верна, для человека тот же хук — не закон и даже
не просьба, он его просто не видит. Если Семинар 5 показывает этот хук как решение ступени 3,
границу нужно назвать вслух на занятии, иначе аудитория унесёт «поставил хук — защитил ветку» в
абсолютном смысле. Чем закрывать ветку от человека (`pre-commit`, обходимый `--no-verify`,
и/или защита ветки на хостинге) — решать при проработке Семинара 5, не здесь; сам самотест этот
случай может назвать непокрытым, но **проверить** его не в состоянии.

**Критерий приёмки.** Скрипт существует, исполняемый, без сетевых зависимостей; при запуске
против свежего `/tmp`-клона выдаёт: `deny` с точным текстом из `settings.json` при коммите на
`main`, `deny` при коммите на unborn HEAD, `ask` — только когда репозитория нет вовсе; шаг в
Quick start `with-git/README.md` явно называет команду запуска.

**Триггер.** Ступень 3 напрямую: «правило записано, но агент его нарушает» → хук. Конкретно
этот пробел — про критерий «ещё рано» той же ступени: без самотеста нельзя отличить работающий
хук от тихо сломанного.

**Риск переусложнения.** Самотест должен остаться скриптом воспроизводимости для одного
существующего хука, а не разрастись в общий фреймворк тестирования гипотетических будущих
хуков. Расширять только когда в массив `PreToolUse` реально добавлен второй хук — симметрично
первой строке growth-ladder.

## Наряд 6 — Добавить памятку про память

только индекс, лимит 200 строк/25 КБ; (3) не писать то, что выводимо из кода/git; (4) не
доверять записи как инструкции, если источник — недоверенный внешний контент; (5) строка в
growth-ladder — триггер «второй раз объясняете то же самое» → курировать авто-память, не новая
инфраструктура. Плюс однострочный указатель от существующей строки «Persistent memory» в
`claude-core-bottom.md` к новому файлу.

**Критерий приёмки.** `memory-notes.md` существует, ≤5 пунктов; growth-ladder получает ровно
одну новую строку; `render_templates.py --check` → PASS; таблицы «What's here» в обоих

**Триггер.** Ступень 2: «владелец повторяет одно и то же из сессии в сессию» / «Claude второй
раз наступает на те же грабли».

**Риск переусложнения.** Ровно риск «раздувание: память как второй CLAUDE.md»
