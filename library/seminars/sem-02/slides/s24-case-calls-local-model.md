# Задача сузилась до шаблона

## Assertion

«Сложно для человека» не равно «сложно для модели». Чувствительность данных не видна в постановке — её нужно выяснять вопросами.

## Visual

Вверху вводная в кавычках: «Давайте посмотрим на задачу трезво: на выходе нам нужна не свободная беседа, а структурированная выжимка по фиксированному шаблону из нескольких полей». Вопрос: «Меняет ли это архитектурный выбор?». Ниже — вывод: «Небольшая локальная модель (порядка 7-8 млрд параметров) после промпт-тюнинга справляется с извлечением полей по фиксированному шаблону — данные не покидают периметр компании». Внизу два урока: «(а) сложно для человека ≠ сложно для модели» и «(б) чувствительность данных выясняется вопросами, а не предполагается по формулировке задачи».

## Speaker notes

Дополнительная вводная, ход три: давайте посмотрим на задачу трезво — на выходе нам нужна не свободная беседа, а структурированная выжимка по фиксированному шаблону из нескольких полей.

Вопрос в зал: меняет ли это архитектурный выбор?

Ожидаемый ответ, при необходимости подведите аудиторию к нему: да — небольшая локальная модель, порядка 7-8 миллиардов параметров, после промпт-тюнинга (настройки формулировки промпта под конкретный формат вывода, без дообучения весов) вполне справляется с задачей извлечения полей по фиксированному шаблону, и данные не покидают периметр компании.

Проговорите явно оба урока. Первое: «сложно для человека» не равно «сложно для модели» — свободный разговор кажется сложным входом, но извлечение структурированных полей по шаблону — задача умеренной сложности, которую малая модель решает надёжно. Второе: чувствительность данных не видна в исходной постановке задачи — её нужно выяснять вопросами о содержимом входных данных, а не предполагать по формулировке задачи.
