# Visible content

## Title bar
Эталонный набор — спецификация, которую исполняет сборка, а не документ

## Body
[schema_matrix — строка набора / пороги / гейт / замыкание / граница]

**МЕХАНИЗМ**

Набор живёт в репозитории как версионируемый файл, а не как документ. Строка — четыре поля:

```
{"вход": "...", "ожидаемый_ответ_или_рубрика": "...",
 "класс_риска": "отказ_по_политике", "источник": "инцидент-2026-04-11"}
```

**Источник обязателен и обязательно реальный:** начинают с 5–10 настоящих промышленных примеров, а не выдуманных. Это то же требование «реальное прошлое, а не правдоподобное», что и в интервью, только применённое к тесту.

**ПОРОГИ — отдельно и числом, заранее, по классам риска**

| Класс риска | Порог |
|---|---|
| Рутинный запрос | не ниже 90% |
| Отказ по политике безопасности | 100%, без исключений |
| Ответ с юридическим последствием | **не через модель** — детерминированное правило поверх неё |

**ГЕЙТ И ЗАМЫКАНИЕ.** Прогон набора — команда в конвейере сборки, возвращающая ненулевой код при недоборе порога: гейт краснеет так же, как красный тест останавливает развёртывание. Каждый промышленный сбой добавляется в набор отдельной строкой с источником «инцидент» — один артефакт связывает запуск, измерение и эксплуатацию.

**АРТЕФАКТ**

```
evals/reference.jsonl     # строки набора
evals/thresholds.yaml     # пороги по классам риска
# + строка в гейте «продолжаем / закрываем»
# + строка в критерии готовности
```

**КРИТЕРИЙ**

Набор растёт после каждого инцидента — измеримо, по числу строк с источником «инцидент» · однажды пойманная регрессия не повторяется молча на следующем релизе.

[Gold callout — ГРАНИЦА: три режима отказа]
**Насыщение** — набор, который всегда зелёный, ничего не измеряет: это сломанный измеритель, а не гарантия. **Переобучение под набор** — как только прохождение становится целью команды, набор перестаёт быть мерой. **Успех хотя бы раз против успеха всегда** — гейт на среднем проходе не даёт постоянства при повторных запусках, и разница между двумя числами видна, если её посчитать, и незаметна, если нет. Плюс: зелёный набор закрытого формата «вопрос — ответ» не переносится на открытую генерацию произвольного текста. И один зелёный прогон доказательством не является: разброс между технически одинаковыми прогонами достигает 15 процентных пунктов, поэтому гейт прогоняют несколько раз на кейс, а порог ставят с учётом разброса, а не как точку.

[Опора на пройденное]
Лекция 4 — исполняемая спецификация и гейт прогона: тест, написанный до кода, переносится с кода на продукт без изменения конструкции.

[Бейдж-пауза]
**Вопрос залу: Ваш эталонный набор третий релиз подряд зелёный на 100%. Хорошая это новость или плохая — и какое действие отсюда следует?**

## Speaker notes

Эталонный набор и гейт оценок назывались обязательными элементами запуска трижды, ни разу не показанные изнутри. Вот механика, и это прямой перенос дисциплины теста, написанного до кода, с кода на продукт.

Набор живёт в репозитории как версионируемый файл. Каждая строка — четыре поля: вход, ожидаемый ответ или рубрика оценки, класс риска, источник примера. Источник обязателен, и он обязательно реальный: рекомендация — начинать с пяти-десяти настоящих промышленных примеров, а не выдуманных. Это то же требование реального прошлого вместо правдоподобного, которое мы уже применяли к интервью, только здесь оно применено к тесту.

Пороги записываются отдельно и числом, заранее, по классам риска. Рутинный запрос — не ниже девяноста процентов. Отказ по политике безопасности — сто процентов, без исключений. Ответ с юридическим последствием — вообще не через модель, а через детерминированное правило поверх неё. Обратите внимание на третью строку: это не строгий порог, это отказ от инструмента, и в таблице порогов он стоит осознанно.

Прогон набора — команда в конвейере сборки, возвращающая ненулевой код при недоборе порога. Гейт краснеет ровно так же, как красный тест останавливает развёртывание, и именно ради этого свойства тест называется детерминированным гейтом, а не рекомендацией. Петля замыкается тем, что каждый промышленный сбой добавляется в набор отдельной строкой с источником «инцидент»: один артефакт связывает сразу три фазы — запуск, измерение и эксплуатацию.

Сработало, если набор растёт после каждого инцидента — это измеримо, по числу строк с источником «инцидент», — и однажды пойманная регрессия больше не повторяется молча.

Граница — три именованных режима отказа, без них приём учит ложной уверенности. Насыщение: набор, который всегда зелёный, ничего не измеряет. Переобучение под набор: как только его прохождение становится целью, он перестаёт быть мерой. И разница между «успешен хотя бы раз» и «успешен всегда»: гейт на среднем проходе постоянства не даёт. Добавлю четвёртое: один зелёный прогон — не доказательство, потому что разброс между технически одинаковыми прогонами доходит до пятнадцати процентных пунктов.
