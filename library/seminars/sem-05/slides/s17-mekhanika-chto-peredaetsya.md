# Что реально приходит на вход

## Assertion

Хук получает на вход полное описание вызова, а вытаскивает из него одну строку через `jq` — не текстовым поиском, который сломался бы на экранированных кавычках внутри самой команды.

## Visual

```json
{
  "session_id": "abc123",
  "cwd": "/home/user/my-project",
  "permission_mode": "default",
  "hook_event_name": "PreToolUse",
  "tool_name": "Bash",
  "tool_input": {
    "command": "npm test",
    "description": "Run test suite",
    "timeout": 120000
  },
  "tool_use_id": "toolu_01ABC123..."
}
```

Полная схема даёт больше полей — идентификатор запроса, путь к транскрипту, каталог черновиков, показатель усилия модели. Хук ступени вытаскивает одно:

```
jq -r '.tool_input.command'
```

## Speaker notes

Хук читает одно поле — команду, а приходит ему на вход значительно больше. Полная нагрузка на слайде — то же самое, что реально строит самотест репозитория тем же кодом хука, который сам вытащил из файла настроек, не копией логики. Идентификатор сессии, путь к транскрипту, текущая директория, режим разрешений, имя события и инструмента — всё это тоже приходит, но хук курса из всего этого вытаскивает одно: `tool_input.command`. Не потому, что остальное не нужно никогда, а потому что задача этой ступени именно про одну команду.

Вытаскивает через `jq`, а не текстовым поиском по всему выводу. Наивный разбор либо зацепил бы постороннее поле вроде описания, либо потребовал бы написать собственный парсер поверх `sed`/`awk` — а JSON умеет прятать внутри строки экранированные кавычки и переводы строк: команда с многострочным сообщением коммита такой разбор просто сломает. `jq` сначала распаковывает структуру целиком и только потом отдаёт значение — по этой причине выбран именно он.

Самотест строит тот же набор общих полей тем же самым `HOOK_CMD`, который сам вытащил из `settings.json`, запуская настоящий код хука, а не копию его логики — это не имитация, а прогон реального кода, минус три поля, которые хук и так не читает.
