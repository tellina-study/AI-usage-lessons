# Воронка из четырёх выборов

## Assertion

Правильный ответ на каждый вопрос зависит от вводных, которых в первой формулировке задачи почти никогда нет.

## Visual

Вертикальная воронка — лестница из четырёх ступеней, каждая уже предыдущей (визуальное сужение сверху вниз). Верх: «Задача от заказчика». Ступень 1: «ИИ или обычный код?». Ступень 2: «Встроить в существующее приложение или делать своё?». Ступень 3: «Разовый вызов модели, RAG или агент?». Ступень 4: «Внешний API или локальный инференс?». Под воронкой отдельной строкой — тезис: «Правильный ответ зависит от вводных, которых нет в постановке — тренируем вопрос, который меняет ответ». Только текст воронки и тезис, без служебных иконок.

## Speaker notes

Вот схема, вокруг которой построено всё сегодняшнее занятие. Реальная задача проходит через четыре последовательных выбора. Первый — нужен ли здесь вообще ИИ, или задачу лучше и надёжнее решает обычный код. Второй — если ИИ нужен, встраиваем его в приложение, которым люди уже пользуются, или делаем отдельный продукт. Третий — если делаем своё, это разовый вызов модели, поиск по базе знаний, который называется RAG, или многошаговый агент с инструментами. И четвёртый — считает это внешний облачный API или модель, которая крутится у вас локально.

Ни один из этих четырёх выборов не решается «по умолчанию» и не решается один раз для всей компании — он решается заново для каждой задачи, по вводным, которые часто всплывают только после прямого вопроса заказчику. Заказчик не скажет вам сам, что среди входящих данных изредка встречаются паспортные данные, или что у используемой в компании системы нет открытого API. Это выясняется, только если вы спросите.

Поэтому главный навык, который тренирует сегодняшнее занятие — не запоминание этой схемы, а умение вовремя задать вопрос, который изменит ответ. Мы прогоним эту воронку на семи постановках, и почти в каждой ответ поменяется хотя бы раз по ходу разбора. Прежде чем двигаться дальше, нам нужен общий язык по двум архитектурам из шага 3 — RAG и агент — коротко: подробно они будут на Лекции 3.

### Self-check
1. Почему воронка не решается «один раз для всей компании», а заново для каждой задачи?
2. Какой из четырёх выборов, по-вашему, чаще всего пропускают инженеры, торопясь сразу к архитектуре?
