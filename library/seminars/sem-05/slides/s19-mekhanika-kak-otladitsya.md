# Как поверить барьеру не на слово

## Assertion

Есть только два принципиально разных тихих отказа, не десяток: сломанный целиком файл настроек виден сразу в интерактивной сессии, а опечатка в одной записи не видна нигде, кроме отладочного лога; три шага проверяют барьер целиком, не только половину.

## Visual

| Средство | Что показывает |
|---|---|
| `/hooks` | Список сконфигурированных хуков: событие, matcher, команда |
| `claude --debug-file <путь>` | Подробный лог выполнения хуков |
| `claude doctor` | Невалидные файлы настроек, отклонённые записи |
| `/status` | Какие файлы настроек реально загрузились |
| Ручная подача JSON на вход скрипту | Код возврата и вывод в обход Claude Code |

| Что сломано | В интерактивной сессии | В headless-прогоне |
|---|---|---|
| Весь файл настроек целиком | **Не тихо** — диалог ошибки сразу | Тихо — узнать только через `doctor` |
| Одна запись (опечатка, регистр, незаякоренный matcher) | **Тихо по-настоящему** — только `doctor`/debug-лог | То же |

Три шага проверки барьера:
1. Хук вообще виден в `/hooks`?
2. Заведомо блокируемый кейс даёт реакцию, а не веру.
3. Негативный контроль — хук пропускает то, что должен.

## Speaker notes

Пять инструментов, все — по нашему хуку: список конфигурации, подробный лог выполнения, диагностика невалидных настроек, список реально загруженных файлов, и просто ручная подача JSON в обход Claude Code вообще — код возврата и вывод смотрим изолированно.

Два разных тихих отказа, а не один — разница важна именно потому, что зал работает интерактивно. Сломан весь файл настроек целиком — в интерактивной сессии это не тихо: диалог ошибки виден сразу при старте, тихо это только в фоновом прогоне без интерфейса, узнать можно только постфактум. По-настоящему тихо — когда ошибка меньше и сидит в одной записи: опечатка в имени события, не тот регистр, незаякоренный шаблон. Тогда падает только эта запись, остальной файл работает как ни в чём не бывало, и сигнала нет нигде, кроме отладочного лога. То, что выглядит страшнее всего — сломанный файл целиком, — зал увидел бы сразу; по-настоящему тихое — то, что ничем себя не выдаёт.

Три шага проверки барьера — не гипотетическая процедура на будущее, а ровно то, чем построен самотест, который разберём дальше: виден ли хук вообще в списке конфигурации, даёт ли заведомый нарушитель реакцию, а не веру, и пропускает ли хук то, что должен пропускать, — без последнего шага, негативного контроля, проверена только половина барьера.
