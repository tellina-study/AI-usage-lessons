## 4. Бессилие, бедность, форма или решение — разбор по каждому недостающему приёму

Проверено по коду `tools/presentation-build/deckkit/*.py` и `tools/presentation-build/
analitika.py`, не по догадке. Определения: **инструмент** — нечем нарисовать физически (нет
примитива/библиотеки); **форма** — примитивы есть, но в каталоге (`scheme.KINDS`, типы слайда)
нет имени и раскладки для этого смысла; **материал** — нет данных/изображений; **решение** —
можем, но явное правило курса запрещает.

| Приём | Чего не хватает | Проверка |
|---|---|---|
| Донат / кольцо с числом в центре (I.7) | **Инструмент.** `prims.py` не содержит ни одной функции с `MSO_SHAPE.OVAL`/эллипсом; donut рисуется только внешним сервисом (QuickChart), а `analitika.py` сейчас оборачивает в переиспользуемую функцию ТОЛЬКО `"type": "bar"` и `"type": "line"` (`grep -n '"type":' analitika.py` → строки 215, 332, 388 — три места, все `bar`/`line`). QuickChart как бэкенд donut УМЕЕТ, у нас не обёрнуто | `analitika.py` строки 215/332/388 |
| Иконка как категория (III.15/III.16) | **Форма, не материал и не совсем инструмент.** Материал ЕСТЬ: `library/lectures/lec-07/assets/icons/lucide-*-blue.png` — 50+ готовых recolored PNG на диске, унаследованы от прошлого поколения сборщиков. Инструмент ЕСТЬ: `prims.add_image()` кладёт любой PNG на любые координаты — ничего не мешает физически. Чего нет — **формы**: ни один текущий тип кадра/схемы не говорит «клетка схемы = иконка + подпись», `scheme.KINDS` не знает такого режима клетки. `grep -rl "icons/" slides/*.md` = 0 — иконки есть на диске, их просто некуда вызвать | `prims.py` (есть `add_image`), `slides/*.md` (0 вызовов icons/) |
| Квадрант 2×2 со значением внутри клетки (`schema_quadrant`, README §4) | **Форма.** Примитивов хватает — два `rect()`/`ocean_box()` на оси, `text_box()` на подписи, `chip()`/маленький `rect()` как маркер точки позиционирования. Это не требует новой геометрии, которой нет (окружность не обязательна — маркер можно нарисовать маленьким квадратом). Чего нет — имени типа в `scheme.KINDS` и раскладки «две пересекающиеся оси + подписи зон внутри» | `scheme.py` KINDS: `dorozhki`/`lestnitsa`/`shkala`/`zero` — квадранта нет |
| Цикл / кольцевой процесс (`schema_cycle`, README §4) | **Инструмент.** Нужна либо дугообразная стрелка (в `prims.py` есть только `RIGHT_ARROW`/`LEFT_RIGHT_ARROW`/`DOWN_ARROW` — прямые блочные стрелки, `MSO_SHAPE` в принципе предлагает `CURVED_RIGHT_ARROW`/`CIRCULAR_ARROW`, но ни один не обёрнут функцией), либо расположение клеток по окружности (тригонометрия на координатах, тоже не реализована). README-formy.md сам называет это отдельно: «Кольцо… содержания нашлось на один кадр: `s67`» — и решение каталога было НЕ заводить форму ради одного кадра (правило «минимум два кадра по содержанию»). Правильно диагностировано как низкий приоритет, но причина пропуска — инструмент, не просто решение не делать | `README-formy.md` раздел «Чего в каталоге НЕТ и почему» |
| Слоистая архитектура (`schema_layered`, README §4) | **Форма.** Чистый стек прямоугольников, выровненных по нижней границе — ровно то, что `plates.py`/`rect()` уже умеют рисовать по одному вызову на слой. README-formy.md сам фиксирует: «Слои… содержания в деке не нашлось ни на один кадр» — здесь действительно материал/содержание, а не инструмент: пока в учебном материале нет многоуровневой архитектуры для показа, форма и не нужна. Честно: это единственный пункт таблицы, где отсутствие формы — не проблема, потому что нет контента под неё СЕЙЧАС | `README-formy.md`, тот же раздел |
| Диаграмма связей / граф с обратными рёбрами (`schema_architecture`, III правило о роли фото/иконки/схемы) | **Инструмент.** `prims.py` не умеет кривых и непрямых линий между двумя произвольными точками (только прямоугольник/скруглённый прямоугольник/три вида прямых блочных стрелок). Граф с перекрёстными и обратными связями физически нечем нарисовать внутри `deckkit`; нужен внешний рендерер (mermaid/D2) и встраивание результата как картинки — то же решение, что уже работает для QuickChart-чартов через `analitika.py`, просто для другого источника PNG | `prims.py` — нет функции кривой/произвольной линии |
| Small multiples — несколько одинаковых маленьких графиков рядом (Tufte, упомянут в блоке B §1, не адаптирован) | **Форма + лёгкий инструмент.** QuickChart технически рисует любое число отдельных PNG по отдельным URL — то есть «инструмент» в узком смысле уже есть (сделать 5 вызовов `stolbtsy()` вместо одного). Не хватает именно **формы**: раскладки «N одинаковых по размеру графиков в сетке» в `analitika.py`/`media.py` нет — `media.band_h`/`frames` кладёт рядом ФОТОГРАФИИ (функция уже написана для Лекции 6, см. ниже), но не чарты | `analitika.py` (нет grid-функции), `deckkit/media.py` (`frames`/`band_h` — есть для фото, не для чартов) |
| Два изображения рядом для «участников» (не из блока E, но смежно) | **Уже есть, недооценено.** `media.frames`/`media.band_h` — готовая функция с Лекции 6, переиспользована в `analitika` для режима `media_2` (issue #244, 2026-10-17). Это ближайшая база для small multiples — расширить с «2 фото» до «N чартов» технически дёшево, т.к. раскладка-сетка уже написана для другого типа содержимого | `tools/presentation-build/README.md` §4 `analitika` описание `media_2` |
| Величина как площадь/размер (вместо длины столбца) | **Решение, частично осознанное.** Курс цитирует в блоке B Cleveland & McGill (1984): позиция/длина читаются точнее площади/объёма, и `analitika.py` намеренно построен вокруг столбцов (длина), не вокруг площади. Это не пробел, а осмысленный выбор — площадь стоит держать ИСКЛЮЧЕНИЕМ (donut для состава целого, где площадь = доля читается привычно), не основным инструментом. Поэтому в очереди ниже эта форма стоит низко, а не нулём | `B-vizual-i-verstka.md` §1, строка Cleveland & McGill |
| Ось с засечками — визуальная голизна (не отсутствие приёма, а его исполнение) | **Форма, частично решение.** Сам приём (расстояние = смысл) УЖЕ применяется и УЖЕ приносит измеренную выгоду (README-formy.md: 26:1 отношение расстояний на `s49c`). Но исполнение — голая линия и три чёрточки без: подписи делений ВНУТРИ зоны (как требовал старый `schema_quadrant`), области под отрезком (заливка от нуля до засечки), контрастного фона под осью. Это инструмент НИЗКОЙ сложности — `rect()` с полупрозрачной заливкой под засечкой уже физически возможен, просто не вызывается в `axis.py` | `axis.py` (462 строки — рисует линию+засечки+подписи, НЕ рисует область/фон/иконку) |
| Схема рядами — визуальная голизна | **Форма + решение.** README-formy.md прямо фиксирует источник ограничения: «предел четыре клетки в ряду — из правила курса» (владелец, 2026-10-08, против длинных конвейеров) и «умолчание рядов не развёрнуто… стрелка — только явным ключом». То есть часть голизны (отсутствие цвета-по-роли, отсутствие иконки на клетке) — решение заказчика («не надо длинный пайплайн», и явный запрет умолчаний типа «стрелка сама по себе»), а часть (нет возможности раскрасить клетку по роли без явного `fill:` на каждой) — форма: `scheme.py` не принимает параметр «цвет клетки по роли» вообще | `README-formy.md` раздел «Предел четыре клетки» |
| Сырой скриншот без обработки (стр. 12, страница NHS England) | **Решение/дисциплина, не инструмент.** ImageMagick для duotone/recolor уже в стеке (design-superpowers.md §5, `tools/presentation-build/README.md` §2), просто не применён к ЭТОМУ конкретному скриншоту — не пробел каталога, а пропуск на одном кадре | `design-superpowers.md` §5 |

## 7. Очередь по отдаче

Критерий — на скольких кадрах из уже существующих дек форма применима ПРЯМО СЕЙЧАС, по грепу
фронтматтера и ключевых слов заголовков (не на глаз), делённое на цену внедрения. Счёт дан на
корпусе Лекции 7 (91 слайд, текущий — единственная дека, полностью переведённая на `deckkit` и
потому единственная, где поля `scheme:`/`blocks:`/`columns:`/`figure:` вообще что-то значат;
остальные 16 лекций используют старые самописные сборщики с другими полями фронтматтера —
см. честную оговорку §8).

| № | Форма/инструмент | Кадров-кандидатов (грубый счёт) | Цена | Отдача (кадров/час, грубо) |
|---|---|---|---|---|
| 1 | **Заливка зоны под осью** (усиление `kind: shkala`) | 4 кадра курса (`grep -rh "kind: shkala"` по всем `rework/deck/slides/*.md` = 4) — но это ОСЬ-КЕЙСТОУН каждой лекции (несущая мысль, не рядовой кадр) — вес кадра выше его числа | 3–5 ч | Низкий по числу, **высокий по значимости** — это ровно тот кадр, на который указал владелец пальцем |
| 2 | **Small multiples вместо перегруженного bar** | Минимум 2 прямых кандидата в Лекции 7 (`s12a` «Охват по странам», `s05` страновая статистика — оба сейчас один чарт на много серий); качественно похожих мест в будущих отраслевых лекциях (L7-L17 используют тот же паттерн «один showcase-чарт на много стран/случаев» по канону `stroenie-i-povestvovanie.md`) — минимум 1-2 на лекцию × 10 будущих лекций ≈ 15-20 | 8–12 ч | Высокая — малая цена (переиспользует готовую раскладку `media.band_h`), кандидатов много и будет больше |

| 4 | **Донат для состава целого** | 1-2 кадра в Лекции 7 (там, где сейчас строится bar для доли «57 из 57» — `s04`/`s05` зона состава массива) — умеренно, Cleveland&McGill оправданно держит это редким приёмом | 3–5 ч | Средняя — малая цена, но кандидатов УМЫШЛЕННО мало (не панацея, именно редкий акцент) |
| 5 | **Иконка-категория в таблице/схеме** | `tables.py` используется 5+ раз по курсу («Девять форм переезда», «Классический режим: годность снимка» и т.п. — таблицы с категориальными строками, где иконка-якорь ускорила бы навигацию); материал (50+ recolored PNG) уже на диске, простаивает | 6–10 ч | Средняя — материал бесплатный (уже есть), но раскладка требует аккуратной работы по пределу «не превратить в decoративный довесок» (блок E III.16 — иконка либо несёт категорию, либо декор) |

**Вывод очереди.** Дешевле и заметнее всего — не новая «форма» в инженерном смысле, а
**применение уже существующих примитивов шире их текущего использования**: залить зону под
несущей осью (пункт 1, самый дешёвый, самый заметный — это буквально кадр, который раскритиковал
владелец) и расширить `media.frames` на чарты вместо одного перегруженного bar (пункт 2, самая
высокая отдача по количеству). Диаграмма связей (пункт 3) — следующий по цене/пользе, потому что
устраняет форму, физически отсутствующую там, где содержание её уже требует (`s71`, `s16a`).
Квадрант — дороже всего и ждёт содержания, не наоборот; ставить его в начало очереди значило бы
строить форму под воображаемый кадр, а не под измеренную нужду, что сам блок E называет
диагностическим признаком decora­тивного решения (приём III.15: метафора/форма «потому что
хочется», а не потому что отображает структуру понятия).
