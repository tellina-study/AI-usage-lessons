## Speaker notes

This is the lecture's final slide, set aside for questions. The substantive part of all five sections is finished: we have gone the path from the central question — there is a task and access to a model, which architecture to choose and when the right answer is "not AI" — through the prompt and its limits, RAG, fine-tuning, API with agents and security, to the decision framework. The best time to ask a question is now, while the whole picture is fresh and held in mind as a whole.

A few directions along which questions arise most often, to give something to start from. First: the boundary between RAG and fine-tuning on a concrete task — if it is unclear what in your case is "knowledge" and what is "behavior," this is a typical and correct point for a question, because it is precisely here that people most often err in practice. Second: where the boundary "AI is not needed here at all" runs — how on a real task to tell a case requiring ordinary deterministic code from a case where AI is truly justified. Third: the security of the data chain and injections through tools — what of this applies to your current projects. And fourth, organizational: the assignment for Seminar 3 — "Architectural choice: chat, agent, RAG, API, three cases" — where you will apply the eight-step checklist; if something in the wording of the assignment is unclear, this is also a good question to ask now rather than a day before the seminar. The seminar is in a week; additional questions can be sent by email.
