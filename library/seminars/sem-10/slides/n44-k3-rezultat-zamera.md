# Что показал прогон на 500 документах и 50 вопросах

## Assertion

Поиск по смыслу выигрывает recall@1, объединение — recall@3 и средний ранг: ни один метод не выигрывает по всем метрикам сразу.

## Visual

> **Лучший результат по первому месту: поиск по смыслу находит верный документ сразу на 1-м месте в 43 вопросах из 50 (86%).**

| Метод | recall@1 | recall@3 | средний ранг верного (из 500) |
|---|---|---|---|
| Искать по словам | 0,74 | 0,80 | 9,9 |
| Искать по смыслу (вектор) | 0,86 | 0,92 | 2,0 |
| Искать обоими, объединить (гибрид, RRF) | 0,84 | 0,94 | 1,6 |

## Speaker notes

Пятьдесят вопросов прогнаны тремя методами без единого обращения к модели на шаге ранжирования — поиск по словам, поиск по смыслу и их объединение. Начнём со свода, разбор по каждому действию — следующим тактом.

По recall@1 — находится ли верный документ сразу на первом месте — лучший результат у поиска по смыслу: сорок три вопроса из пятидесяти, восемьдесят шесть процентов. Поиск по словам — худший: тридцать семь из пятидесяти, семьдесят четыре процента, и если документ не на первом месте, он в среднем лежит на девятой-десятой позиции из пятисот — специально отобранный лексический разрыв и путающие кластеры сбивают точное совпадение слов заметно. Объединение двух сигналов безусловным победителем не назвать: у него лучший recall@3 (девяносто четыре процента) и лучший средний ранг (1,6) среди всех трёх, но recall@1 ниже, чем у чистого вектора, — восемьдесят четыре процента против восьмидесяти шести.

На первый взгляд вывод напрашивается сам: раз поиск по смыслу выигрывает по главной метрике, он и есть лучший выбор, а объединение — просто более сложная версия того же самого с меньшим эффектом. Но эту интуицию стоит проверить честно — по тому, как каждый метод ведёт себя на разных типах вопросов. Смотреть только на агрегат целиком здесь недостаточно: усреднённое число по пятидесяти вопросам способно скрывать за собой несколько разных картин сразу.

Средний ранг тоже заслуживает отдельного взгляда: 9,9 у поиска по словам против 2,0 у поиска по смыслу — это не просто «хуже», это разница между «документ почти наверху» и «документ где-то в первой трети выдачи», когда он вообще не на первом месте. Для обратившегося это ощущается как разница между мгновенным ответом и ответом, до которого системе пришлось перебрать заметную часть базы.

Этот агрегат прячет кое-что важное: разбивку по типам вопросов — дальше.
