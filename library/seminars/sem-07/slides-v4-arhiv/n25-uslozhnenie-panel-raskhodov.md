# Дежурный открыл панель расходов

## Assertion

Шаг классификации за день обошёлся почти столько же, сколько шаг написания ответа.

## Visual

| | |
|---|---|
| писем за час в день релиза | 200 (обычный день — 20) |
| шаг «написать ответ» | целый абзац текста клиенту |
| шаг «определить категорию» | одно слово из четырёх |
| за день | два шага обошлись почти одинаково |

**Что делать с шагом определения категории?**

`оставить как есть` · `правила по словам` · `своя маленькая модель, обученная на эти четыре категории` · `вызов, который возвращает сразу значение, без текста вокруг`

## Speaker notes

В день релиза поток подскочил: двести писем в час вместо обычных двадцати. Вечером дежурный открывает панель расходов на внешние вызовы и видит картину, которая его удивляет.

Шаг, который пишет ответ клиенту, и шаг, который определяет категорию, обошлись почти одинаково. При этом первый производит целый абзац связного текста, а второй — одно слово из четырёх, причём список этих четырёх слов известен заранее и не меняется.

Стоит задержаться на том, почему так выходит, потому что причина не в тарифах поставщика. Генеративная модель по своему устройству отвечает текстом. Когда вы просите её определить категорию, она сначала объясняет себе выбор — «судя по тону и упоминанию возврата денег, это скорее всего жалоба» — и только в этом объяснении называет нужное слово. Дальше ваш код достаёт оттуда одно слово, а остальное выбрасывает. Платите вы за всё, включая выброшенное.

Решение, которое принимает зал. Четыре варианта. Оставить как есть — работает же. Вернуться к правилам по словам на этом конкретном шаге. Обучить свою маленькую модель специально на эти четыре категории. Или взять вызов, который устроен иначе и возвращает сразу значение, без текста вокруг.

Я намеренно описываю варианты тем, что они делают, без названий. Названия прозвучат на разборе, и будет понятнее, если сначала вы выберете по существу.
