# Описания — по требованию. Набор — под задачу

## Assertion

Четыре строки решения: у сервера в проектном файле нет флага принудительной загрузки описаний, отложенная загрузка в окружении не выключена, серверу передаются только нужные наборы инструментов, а свой набор серверов он держит в личной области.

## Visual

- `.mcp.json`: у сервера снят `alwaysLoad: true` — описания его инструментов приходят по требованию. Флаг оставляют одному инструменту, который нужен на каждом шаге, и записывают рядом, почему.
- Окружение проекта: `ENABLE_TOOL_SEARCH` не выставлен в `false`. Пороговое значение вида `auto:10` — компромисс: пока определения занимают меньше названной доли контекста, они грузятся сразу.
- Команда запуска сервера: только нужные наборы инструментов — `--toolsets repos,issues` вместо полного набора. Проверяйте флаги по текущей версии сервера: у официального сервера GitHub режим выдачи наборов по требованию был и снят в мае 2026.
- Личная область подключения: серверы под свою работу — там. Общий проектный файл остаётся командным, и чужие три сервера из него никто не выбрасывает.

> Проектный файл говорит, что подключено у всех. Личная область — что подключено у вас. Режим загрузки описаний решает, во что это обходится до первого вопроса.

## Speaker notes

Что он завёл в тот же день. Четыре строки, и первые две — проверка, не настройка.

В проектном файле у двух серверов снят флаг принудительной загрузки описаний: теперь их схемы приходят по требованию. Переменная, выключающая отложенную загрузку, в окружении не выставлена; у неё есть и пороговое значение — пока определения занимают меньше названной доли контекста, они грузятся сразу.

Третья строка — на стороне самого сервера: в команде запуска передаются только нужные наборы инструментов. Официальный сервер GitHub так и объясняет этот флаг — он снижает объём контекста. И сразу оговорка: флаги проверяйте по текущей версии. У того же сервера режим выдачи наборов по требованию существовал и был снят в мае прошлого года — поиск вам его ещё покажет.

Четвёртая, единственная, которая требует работы: серверы под свою работу он перенёс в личную область. Проектный файл остался командным, чужие серверы из него никто не выбросил.

В сцене было наоборот: флаг стоял, поставил его другой человек, а платил каждый, кто открывал сессию.

**Справка.**

Если спросят про снятый режим подробнее: у официального сервера GitHub были флаг и переменная окружения, включавшие выдачу наборов по запросу модели, плюс три служебных инструмента для этого. Удалены одним запросом на внесение правок в мае 2026: двадцать четыре файла, пятьдесят одна строка добавлена, девятьсот сорок две удалены. Причина, названная автором, — долг по поддержке и то, что режим работал только локально. Вывода «так делать не нужно» там нет.

Если спросят, зачем тогда об этом говорить: затем, что это обычная судьба флага. Поиск выдаёт страницу прежней версии, она читается как действующая инструкция, и проверить это можно одним способом — открыть описание текущей версии сервера.

Если спросят, где лежит личная область: в том же файле настроек пользователя, который мы разбирали, выбирая, куда положить ключ.

Если спросят, не проще ли держать всё в проектном файле: проще, пока наборы у всех совпадают. Как только работа разная, общий файл берёт с каждого плату за все работы сразу — это мы и увидели в сцене.

Если спросят, что записывать рядом с оставленным флагом: какой инструмент требует загрузки при старте и почему его схема нужна на каждом шаге. Исключение без причины через месяц неотличимо от случайной строки.
