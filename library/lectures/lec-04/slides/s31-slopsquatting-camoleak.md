# Visible content

## Title bar
Supply-chain — отдельный класс: воспроизводимая галлюцинация и структурный канал утечки

## Body
[Слева — slopsquatting, Ocean rounded box]

**Slopsquatting** — supply-chain-атака: LLM **воспроизводимо галлюцинирует** имя несуществующего пакета → злоумышленник **заранее регистрирует** его с malware → разработчик или агент C–D делает `install <выдуманное>`.

Ось угрозы — **воспроизводимость** галлюцинации (не случайность).

Числа: из **576 000** сэмплов ~**20%** рекомендовали несуществующие пакеты; **43%** галлюцинированных имён повторялись во всех 10 запросах. Термин ввёл Seth Larson (PSF, апрель 2025).

[Справа — CamoLeak]

**CamoLeak** — prompt injection в dev-агенте: скрытые в **невидимых markdown-комментариях** PR инструкции заставили GitHub Copilot Chat искать секреты (ключи AWS) и **эксфильтровать через GitHub image-proxy**.

**CVE-2025-59145, CVSS 9,6** (критический).

[Gold callout]
Урок: dev-агент с доступом к недоверенному контенту + секретам = **готовый канал эксфильтрации** (структурное свойство, не баг). **Не лечится «лучшей моделью» — только архитектурой:** lockfile с хэш-пиннингом, allowlist реестров, проверка пакета до установки, SCA-скан; least-privilege + изоляция + human-in-loop на write + egress-контроль.

## Speaker notes

Два кейса одного класса — supply-chain, цепочка поставок ПО, — и они показывают риск, которого раньше просто не было. Первый — slopsquatting, термин ввёл Seth Larson из Python Software Foundation в апреле две тысячи двадцать пятого. Механизм: LLM при генерации кода иногда рекомендует импортировать пакет, которого не существует, — галлюцинирует имя. Само по себе не страшно, install упадёт. Но ось угрозы — воспроизводимость: если модель галлюцинирует одно и то же имя стабильно, злоумышленник может это имя предсказать, заранее зарегистрировать в реестре пакетов с вредоносным содержимым и ждать. Разработчик или, что опаснее, автономный агент уровня C-D делает install выдуманного имени — и ставит malware.

Цифры стоит атрибутировать аккуратно: сам термин ввёл Seth Larson из PSF, а конкретные числа — из рецензируемого исследования Spracklen и соавторов на USENIX Security 2025: из пятисот семидесяти шести тысяч сгенерированных сэмплов около двадцати процентов рекомендовали несуществующие пакеты, и, главное, сорок три процента галлюцинированных имён повторялись во всех десяти запросах [1]. Это авторитетный источник именно для чисел — крупная академическая конференция по безопасности. Главное в цифрах — воспроизводимость: сорок три процента стабильных повторов означают, что имя предсказуемо, а значит эксплуатируемо.

Второй кейс — CamoLeak, материализация prompt injection из Лекции 3 прямо в инструменте разработчика. В pull request прятали инструкции в невидимых markdown-комментариях; GitHub Copilot Chat, читая PR, воспринимал их как команды, искал в окружении секреты, включая ключи AWS, и эксфильтровал их через image-proxy самого GitHub; уязвимость получила номер CVE-2025-59145 и оценку девять и шесть по CVSS — критический уровень [2]. Урок: dev-агент, у которого одновременно есть доступ к недоверенному контенту и к секретам, — готовый канал эксфильтрации, и это структурное свойство архитектуры, а не баг конкретной модели. Отсюда главное: это не лечится «возьмём модель поумнее» — только архитектурой. Против slopsquatting: lockfile с хэш-пиннингом, белый список реестров, проверка пакета до установки, SCA-скан. Против CamoLeak-класса: наименьшие привилегии, изоляция, человек в цикле на операциях записи и контроль исходящего трафика.
