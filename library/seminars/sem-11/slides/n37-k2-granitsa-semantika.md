# Семантическую резку не берут «потому что умнее»

## Assertion

Даже настроенный правильно порог семантической резки не заменяет иерархический приём: он улучшение над простой резкой, а иерархию ничем не заменяет.

## Visual

> **Семантическую резку не брать по умолчанию «потому что умнее».** Метод требует дорогой настройки порога под свой корпус, которую почти никто не делает, — и даже настроенный правильно (щадящий порог здесь) он не заменяет более простой и дешёвый иерархический приём.

> **Вторая строка оси занятия закрыта.** Казалось — резка по смысловым границам (приём прошлого занятия, по предложениям) достаточна, чтобы модель не путала соседние разделы документа. Оказалось — резка не рвёт фразу, но не удерживает иерархию; и не любое усложнение резки одинаково окупается: самый «умный» метод в этом замере проигрывает самому простому иерархическому приёму на любом из четырёх проверенных порогов.

## Speaker notes

Семантическая резка — самый концептуально привлекательный из трёх действий этого кейса: она единственная решает, где резать, глядя на само содержание текста, а не на заданное число или на уменьшенный размер. Именно поэтому её легко взять по умолчанию просто потому, что она звучит умнее. Этот замер показывает, почему так делать не стоит.

У метода один параметр — порог разрыва, — и от него зависит буквально всё остальное. Настройка этого порога требует отдельного прохода по своему корпусу: нужно посчитать распределение разрывов между соседними предложениями на своих документах и выбрать точку на этом распределении — не взять чужое число из чужого проекта. Это дорогая процедура, которую на практике почти никто не делает: предпочитают один раз подобранное «на глаз» значение. И даже если эта настройка сделана правильно — щадящий порог в этом замере оказался лучшим из четырёх проверенных, — метод всё равно не обгоняет иерархическую резку, которая вообще не требует эмбеддинга текста для самой резки. Семантическая резка в этом разборе остаётся улучшением над самой простой версией 1; иерархию она не замещает. Если выбор идёт между этими двумя приёмами, иерархия выигрывает дешевле.

Это и закрывает вторую строку оси сегодняшнего занятия, теперь на материале измеренного кейса. Казалось надёжным: резка по смысловым границам — та, что прошлое занятие уже проверило и одобрило, резка по предложениям, — достаточна, чтобы модель не путала соседние разделы документа. Оказалось иначе: резка не рвёт фразу внутри куска, но ничего не удерживает о том, из какой части документа этот кусок взят. И не любое усложнение резки одинаково окупается: иерархический приём, самый дешёвый по вычислениям из двух предложенных починок, даёт самый большой измеренный выигрыш, а семантическая резка, концептуально самая сложная, проигрывает ему на каждом из четырёх проверенных порогов.

Следующий кейс поднимает похожий вопрос на другом шаге цикла: не на резке документа — на самом поиске. Кто решает, с каким весом смешивать поиск по словам и поиск по смыслу, и когда это решение становится новой, скрытой точкой отказа.
