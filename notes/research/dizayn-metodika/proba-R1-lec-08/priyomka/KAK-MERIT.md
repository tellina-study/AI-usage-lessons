# Как мерить пол приёмки — рабочие команды

issue #307. Тринадцать показателей `07-PRIYOMKA.md` §1 снимаются ДВУМЯ программами, не
одной — ни одна не покрывает весь список.

## Команды

```bash
# zamer.py — плотность/слова/ступени-с-фильтром/изображение/акцент/ритм,
# одной линейкой по 13 эталонам + колодам курса (не про приёмку одной колоды к порогу)
cd tools/metodika-podachi/zamer
python3 zamer.py --path <lec>/rendered/<lec>.pptx --type pptx --name <lec> --razryad "наша колода"
cat sydoe-<lec>.json

# dobor_porogov.py — пять показателей, которых zamer.py не считает (и 1.3 полным методом)
cd notes/research/dizayn-metodika/proba-R1-lec-08/priyomka
python3 dobor_porogov.py                                   # по умолчанию ../rendered/proba-R1.{pptx,pdf}
python3 dobor_porogov.py --pptx <путь.pptx> --pdf <путь.pdf>
cat dobor-porogov.json
```

## Какой показатель чем снимается

| № | Показатель | Чем | Как |
|---|---|---|---|
| 1.1 | доля площади под текстом | `zamer.py` | медиана по кадрам, сетка 64×64 |
| 1.2 | слов на кадр | `zamer.py` | справочно, без порога |
| **1.3** | пол кегля, 15,0 пт / 100% | **оба, не одно число** | `zamer.py` даёт мягкий метод (ступень ≥1% веса, колонтитул исключён) — для сравнения эталонов; `dobor_porogov.py` даёт ПОЛНЫЙ прогон (каждый run, без фильтра/исключений) — это и есть число приёмки против порога владельца |
| 1.4 | число ступеней кегля | `zamer.py` | ступени после фильтра ≥1% |
| 1.5 | длина серии раскладок | `zamer.py` | кластеризация scipy, силуэт — глазами |
| 1.6 | доля кадров с крупным изображением | `zamer.py` | не порог, справочно |
| 1.7 | доля/метки акцента | `zamer.py` | HSV-скор заливок |
| **1.8** | контраст текст/фон | `dobor_porogov.py` → **`deckkit.contrast` импортом** | `rows_of(prs)`: фон по z-порядку собранного файла, формула WCAG §3.1 |
| **1.9** | заполненность слотов формы | **никто — человек** | сверка кадра с описанием формы (`02-KATALOG-FORM.md`) и нарядом (`03-RAZNARYADKA.md`); это «текст есть физически», не геометрия файла |
| **1.10** | форма ↔ утверждение | **никто — человек** | тег отказа формы + проверка за 5 секунд (`01-YAZYK-KADRA-part2.md` §5.2) — суждение о смысле, не измеримо по файлу |
| **1.11** | поле/безопасная зона | `dobor_porogov.py` | bbox критичных рамок (кегль ≥23 пт или нижняя десятая часть кадра) против 48/24 пт |
| **1.12** | длина строки | `dobor_porogov.py`, **по .pdf** | `fitz.get_text("dict")` — физическая строка после переноса; .pptx перенос не хранит |
| **1.13** | бюджет знаков на слот | `dobor_porogov.py` | ширина рамки / 9,0 × строки (строки — из PDF, сопоставлены по центру bbox; без PDF — оценка по числу абзацев, помечена явно) |

## Почему 1.9 и 1.10 машиной не снимаются

**1.9** — порог «100% обязательных слотов формы заполнены» сверяется с текстовым ОПИСАНИЕМ
слота у конкретной формы в каталоге (какой слот у формы №NN обязателен, что в нём должно
быть по смыслу) — у файла нет поля «это слот X формы Y», это знание разнарядки, не атрибут
фигуры. Геометрию (бюджет знаков слота) снимает 1.13 — но «слот заполнен содержательно» это
не измеряет.

**1.10** — оба порога сформулированы как условие смысла, не числа: тег отказа формы («нет
цели», «целое не названо») требует понять, ЧТО кадр утверждает, а проверка за пять секунд
(«подтверждает тезис, а не просто иллюстрирует тему») требует посмотреть на кадр и назвать
предмет → тезис → доказательство. `07-PRIYOMKA.md` сам называет это сверкой, не замером.

## Контраст — не переписан

`tools/presentation-build/deckkit/contrast.py` уже меряет ровно то, что нужно 1.8, и
пригоден как библиотека без состояния сборки (`rows_of`, `ratio`, `lum`, `background` —
чистые функции, зависят только от `python-pptx` + геометрии `theme.py`). `dobor_porogov.py`
импортирует его (`sys.path` на `tools/presentation-build`, `from deckkit import contrast`),
а не переписывает формулу второй раз.
