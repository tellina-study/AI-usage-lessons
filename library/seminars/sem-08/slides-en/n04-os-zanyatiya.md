# The session's axis: where the model decides, where code must

## Assertion

Four observations, each one looking like a working success today. What they turn out to be — we fill in as the session goes.

## Visual

| a repeat request about the same question came in — handled as new | |
| the prompt says "don't refund more than amount X" | |
| the image got assembled and sent to Telegram | |

> The right column won't close all at once at the end — one row at a time, right after the case that closes it. And each time, not by my telling it, but by what we see on screen.

## Speaker notes

Here is the axis the whole session stands on: four rows, and every single one of them looks, at first glance, like a perfectly normal, working result. Go ahead and read the left column. The message reached the coordinator. The request got processed without any fuss. The prompt has a rule about the refund amount written straight into it. The image made it all the way to Telegram. Each of these four phrases describes exactly the moment where it looks like the task has been solved and you can simply move on to the next thing.

The right column is empty, and that is not an oversight on our part — it is the actual plan for the session. Each of these four stories is hiding something that only shows up once you look more closely at it: an extra step sitting where none was actually needed, a repeat request that went unrecognized as a repeat, a probabilistic decision standing exactly where a hard condition was required instead, a data format that behaves nothing like ordinary text does. We are not going to name any of it right now — we are going to find it for ourselves and write it into the table as we break down each case in turn.

Four rows — and that is exactly the four cases of today's session: Notifications, Duplicate check, Refund approval, and Card in Telegram. At the end of each individual case there will be a moment where we come back to this very same table and write exactly one row into the right column — never an abstract conclusion handed to you, but a concrete observation drawn from a concrete run we have just watched together with our own eyes, on screen.

None of this means all four stories are broken from the very start. Quite the opposite, actually — every one of them looks completely functional on its surface, and that is the main trap built into this whole exercise: something that works is far too easy to mistake for something you can genuinely stand behind. The difference between those two states is precisely what this table measures, row by row, all the way through to the very end of the session, when we will finally see all four pairs sitting side by side and can compare them in a single glance.

Remember this table carefully — we will come back to it right after the very first case is done.
