# Что входит в окно роли, что из него выходит

## Assertion

Роль получает системный промпт, задачу, файлы инструкций и снимок репозитория на старте — но не историю переписки и не уже прочитанные родителем файлы. Обратно уходит только финальный текст.

## Visual

**Входит, на старте:** собственный системный промпт роли (тело её файла), формулировка задачи от вызывающей сессии — не исходная фраза из чата буквально, иерархия файлов инструкций всеми уровнями, снимок состояния репозитория в момент старта.

**Не входит физически, не по договорённости:** история переписки, файлы, которые уже прочитал родитель, автопамять основной сессии. Канала для этого нет: устройство харнесса само не передаёт это роли, дисциплина автора роли здесь ни при чём.

**Выходит обратно:** только финальный текст. Ни один промежуточный вызов инструмента — какой файл открыт, какой запрос сделан — родителю не виден.

## Speaker notes

Основа этого уже разобрана: роль — отдельный процесс со своим контекстным окном, и родитель получает от неё только итог, не действия. Сейчас — та же мысль подробнее, в обе стороны, потому что именно она объясняет прошлый слайд.

На входе роль получает собственный системный промпт — тело её файла, не системный промпт харнесса целиком, — формулировку задачи от вызывающей сессии, иерархию файлов инструкций всеми уровнями и снимок состояния репозитория на момент старта. Чего физически нет: истории переписки, уже прочитанных родителем файлов, автопамяти основной сессии — канала для этого попросту не существует, это свойство устройства харнесса. На выходе — только финальный текст: ни один промежуточный вызов инструмента родителю не виден.

Отсюда и сцена с сорока файлами: все сорок открываются именно в этом, отдельном окне, и ни один из них не попадает в окно родителя — туда попадает только итоговый вывод.

Если спросят, не то же ли самое это, что «роль возвращает только итог» из контракта: то же самое утверждение, развёрнутое в сторону входа — здесь видно не только то, что выходит из роли, но и то, что в неё входит; именно вход объясняет, почему окно родителя не распухает от содержимого сорока файлов, которые физически были прочитаны.
