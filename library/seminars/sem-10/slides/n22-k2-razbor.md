# Что делает каждое из четырёх действий

## Assertion

Все четыре способа дают на выходе один и тот же формат — список кусков. Какой из них ломает ответы чаще — следующие такты, не этот.

## Visual

| Действие | Как делает | Преимущество | Недостатки |
|---|---|---|---|
| Резать строго по счёту символов, без оглядки на текст | Документ рубится на части заданной длины без оглядки на текст внутри | Проще всего реализовать — один параметр, один механический проход по тексту | Разрез может прийтись ровно на середину фразы с ответом, независимо от выбранного размера куска; неочевидно заранее, какой размер «удобнее» без проверки |
| Резать по границам предложений | Разрез проходит только там, где заканчивается одно предложение и начинается следующее | Куски не рвут фразу посередине: разрез идёт по смысловой границе текста — счёт символов тут роли не играет | Чуть сложнее в реализации: нужен отдельный шаг, который понимает, где заканчивается предложение в конкретном языке — простого счёта символов здесь недостаточно; качество этого шага зависит от текста |
| Резать по границам слов | Документ делится на слова; кусок копится, пока не превысит целевой размер, разрез проходит только на границе между двумя соседними словами | Не рвёт слово пополам; реализовать проще, чем разбор границ предложений — достаточно знать, где кончается слово | Про границу предложения этот способ ничего не знает: разрез всё равно может пройти ровно посередине фразы, даже если ни одно слово не задето |
| Резать по счёту символов с перекрытием | Та же логика, что резать по счёту символов, но соседние куски перекрываются — часть символов конца одного куска повторяется в начале следующего | Часть ответов, разорванных на границе первого действия, попадает целиком в соседний перекрывающий кусок | Хранилище растёт из-за дублирования символов; перекрытие не гарантирует результат для ответа любой длины |

## Speaker notes

Четыре действия, и все реальны как инженерный выбор — этот такт объясняет, как каждое устроено; какое из них лучше на числах, увидим дальше.

Резать строго по счёту символов, не глядя на текст, — самое простое и самое дешёвое в реализации: один параметр, задающий длину куска, один механический проход по тексту. Плата за эту простоту — разрез не знает, где в тексте заканчивается мысль, и может пройти ровно посередине фразы с ответом на будущий вопрос, независимо от того, какой размер куска выбран. И заранее, не проверив, не скажешь, какой размер здесь удобнее: на глаз любой вариант выглядит разумно, потому что сам кусок при любом размере читается нормально.

Резать по границам предложений чуть сложнее: нужен отдельный шаг, который сначала понимает, где заканчивается одно предложение и начинается следующее, и только потом проводит разрез. Это зависимость, которую первое действие не несёт вовсе — качество разбивки на предложения зависит от конкретного языка и текста. Но плата возвращается тем, что разрез держится смысловой границы текста — счёт символов тут ни при чём, — и поэтому куски реже рвут фразу посередине.

Резать по границам слов — промежуточный вариант между первыми двумя действиями. Документ делится на отдельные слова, кусок копится, пока суммарная длина не подойдёт к целевому размеру, и разрез проходит строго на границе между двумя соседними словами. Слово никогда не рвётся пополам — в этом разница с первым действием, и реализовать это проще, чем разбор границ предложений: достаточно знать, где кончается слово. Знать, где кончается мысль, этот способ не умеет: разрез может пройти ровно посередине ответа, даже если ни одно слово при этом не задето.

Резать по счёту символов с перекрытием устроено так же, как первое действие, с одним добавлением: соседние куски частично повторяют один и тот же участок текста. Если разрез первого действия разрывает ответ на своей границе, у перекрывающего куска появляется шанс содержать тот же участок целиком — ценой того, что часть текста в хранилище хранится не один раз, а дважды, и без гарантии, что перекрытия заданного размера хватит для ответа любой длины.

Разорванная фраза выливается ниже по цепочке в конкретный сбой. Если разрез прошёл посередине фразы с ответом, поиск потом честно находит нужный кусок — и в этом куске лежит половина ответа. Модель получает обрывок и отвечает по обрывку: поиск формально сработал, ответ при этом неполный.

Снаружи, на уровне остальной цепочки, разницы между этими четырьмя действиями не видно вовсе: все четыре подают на следующий шаг один и тот же формат — список кусков текста, готовых к тому, чтобы посчитать для каждого эмбеддинг. Вся разница спрятана внутри одного узла — и именно поэтому её легко не заметить, пока не проверишь результат числом. Этим мы займёмся дальше.
