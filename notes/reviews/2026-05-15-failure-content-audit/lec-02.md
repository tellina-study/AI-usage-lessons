## 3. Оценка разрыва

Разрыва **нет** (порог достигнут везде). Запас, однако, тонкий у slides и speech. Чтобы перевести из «тонкий запас» в «уверенный ≥35% holistic» (рекомендуется для устойчивости к будущим правкам):

- **Speech:** +1 короткий failure-фрейм ~150–200 слов (≈1 мин) — например, явный документированный кейс «фабрикация ссылок» в s24 или s07. Доводит speech до ~36%.
- **Slides:** усилить s19/s20 явной формулировкой судебного критерия (1 строка «T>0 в проде для аудита = риск воспроизводимости») — переводит s19/s20 из partial в in, +~3 мин bucket → ~28% строгая / ~38% по активной речи.
- **Chapter:** не требуется (уже ~48%).

Это **рекомендация на усиление устойчивости**, НЕ требование для прохождения (артефакт уже проходит). Без правок verdict остаётся APPROVE-WITH-POLISH.

## 4. Research: документированные ограничения/провалы устройства LLM

| # | Ограничение/провал | Источник + дата | Урок и куда в Л2 ложится |
|---|---|---|---|
| 1 | Слепота к буквам / счёт символов (strawberry = `[st][raw][berry]`) | Xu et al., arXiv 2412.18626 (12/2024); arXiv 2410.19730 «Counting Ability & Tokenization» | Токенизация ломает посимвольные операции → внешний инструмент. **Уже в §1.3 / s07 — well covered.** |
| 2 | Арифметика/счёт цифр (split `1234567`) | Тот же кластер + общее tokenization-обоснование | Чистый LLM — плохой калькулятор → Code Interpreter. **Уже в §1.1 (кратко) — можно усилить отдельным кейсом** |
| 3 | Reversal curse: обучен «A is B» — не выводит «B is A» | Berglund et al., arXiv 2309.12288 (09/2023; ICLR) | LLM не симметрично «знает» факты — структурное, не fine-tuning. **НЕ покрыто. Кандидат в §5.2 / §2.x (1 абзац ~150 слов)** |
| 4 | Lost in the middle (U-кривая точности) | Liu et al., arXiv 2307.03172 (07/2023; TACL 2024, ~2576 цит.) | Важное — в начало/конец промпта, не середину. **Уже в §3.4 / s17 — well covered. Цифры в норме (chapter «30–40% середина», speech v1.1 исправлено на «50%»).** |
| 5 | Sycophancy (RLHF поощряет согласие с пользователем > истину) | Sharma et al. (Anthropic), arXiv 2310.13548 (10/2023) | Модель подстраивается под убеждения юзера → нельзя доверять подтверждению своей гипотезы. **НЕ покрыто. Сильный кандидат — §5.x или новый микро-блок (~150 слов)** |
| 6 | Hallucination / фабрикация ссылок (Mata v. Avianca; 712+ юр. дел) | Dahl et al., arXiv 2401.01301 (01/2024); arXiv 2510.06265 survey | LLM фабрикует правдоподобные источники → ground-truth факты = БД/RAG/верификация, не голый LLM. **НЕ покрыто явным кейсом. Высокий приоритет — §5.2 или §1.x** |
| 7 | Prompt injection / indirect injection | Greshake et al., arXiv 2302.12173 (02/2023; BlackHat'23); OWASP LLM01:2025 | Данные в контексте могут содержать инструкции → нельзя доверять необработанному внешнему тексту в промпте. **НЕ покрыто. Естественно ложится в §3.3/§5.5 как мост к Л3 (RAG), ~120 слов** |
| 8 | Knowledge cutoff / устаревание | Общеизвестное (model cards); связано с §4.4 stateless | LLM не знает событий после обучения → актуальные факты = web-tool/RAG. **Частично подразумевается (§5.5 «не может пойти наружу»), но без явного урока. Можно 1 строка в §4.4/§5.5** |
| 9 | Недетерминизм при T>0 (+ микро-вариативность при T=0) | Документировано в самой главе §4.2 + GPU-batching | Воспроизводимость production требует T=0 + осознания floating-point шума. **Уже в §4.2 — но подано ближе к дисклеймеру; усилить до явного критерия** |

**Кейсы «когда LLM НЕ нужен → альтернатива» (для проверки полноты §5.3):**

| Сценарий | Правильный инструмент | Покрытие в Л2 |
|---|---|---|
| Точный счёт/арифметика/посимвольно | Калькулятор / Python sandbox / regex | §1.3, §5.3 — **покрыто** |
| Ground-truth факты, цитаты, актуальные данные | БД / RAG / web-search + верификация | §2.4 (поиск) частично; **провал-кейс фабрикации НЕ показан явно — gap** |
| Детерминированная логика / правила / интерпретируемость для регулятора | Rule-based / decision tree / лог. регрессия | §5.3 ветка 2 — **покрыто** |
| Real-time <100мс, edge | Small NN / классический ML | §5.3 ветка 3 — **покрыто** |
| Узкая классификация, много размеченных данных | XGBoost / fine-tuned BERT | §5.3 ветка 1 — **покрыто** |

Вывод research: 4 из топ-9 failure-кейсов **не покрыты явно** (reversal curse, sycophancy, фабрикация ссылок как кейс, prompt injection). Они НЕ обязательны (порог уже взят), но добавление 1–2 из них усилит устойчивость speech/slides и закроет «знай границы»-миссию более полно. Особенно **фабрикация ссылок** — это каноничный, узнаваемый провал, идеально иллюстрирующий §5.2 «почему» и §2.4 (когда нужен ground-truth, а не LLM).

## 6. Топ-5 приоритетов

1. **[P1] Speech-устойчивость:** speech ~33% держится на длинном блоке s07 (462 сл.); +1 failure-фрейм ~150 слов в s24/речи для запаса до ~36%. Без правки артефакт всё ещё проходит, но запас хрупкий.
2. **[P1] §4.2/s19 «стохастичность» — дисклеймер, не суждение:** подача ближе к оговорке «это не баг»; не хватает явного production-критерия (T=0 обязателен для аудита/воспроизводимости). Усилить формулировку in-place — переводит §4.2 из partial в in, укрепляет Раздел 4 (единственный без full-in).
3. **[P2] Gap в «когда нужен ground-truth»:** §2.4 показывает поиск как механику, но каноничный провал-кейс фабрикации ссылок отсутствует — добавить в §5.2/s24 (research #6).
4. **[P2] Не покрыты 3 узнаваемых провала** (reversal curse, sycophancy, prompt injection) — не обязательны для порога, но добавление 1–2 повышает педагогическую полноту «знай границы».
5. **[P2] Slides по доле слайдов (19% от 36)** формально низко из-за 12 cover/divider/recap; по активной речи и по контентным слайдам (~29%) проходит. Зафиксировать в pre-gate, что метрика по slides считается по минутам активной речи, не по сырому числу слайдов.
