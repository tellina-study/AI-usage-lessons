# Visible content

## Title bar
Локальный инструментарий агента: чем закрыть пять его слепых каналов

## Body
[Карточка 1 — Данные · Testcontainers]
ЧТО ДЕЛАЕТ: поднимает настоящий Postgres / Kafka / Redis в Docker на временном порту — на машине агента.
БЕЗ НЕГО НЕВОЗМОЖНО: агент проверяет запрос против воображаемой схемы — тест либо не пишется, либо зелен на заглушке и красен в проде.

[Карточка 2 — Сеть · MSW]
ЧТО ДЕЛАЕТ: перехватывает HTTP внутри процесса: один обработчик и для модульных, и для сквозных тестов. Вне JS — WireMock (открытый код).
БЕЗ НЕГО НЕВОЗМОЖНО: агент либо бьёт по настоящему API — нестабильно, платно, с лимитами, — либо не тестирует сетевой код вовсе.

[Карточка 3 — Интерфейс · Playwright]
ЧТО ДЕЛАЕТ: даёт агенту браузер: не картинку, а дерево элементов страницы (accessibility) — кликает, заполняет формы, порождает тест.
БЕЗ НЕГО НЕВОЗМОЖНО: агент никогда не видит настоящий интерфейс — отладка фронтенда идёт вслепую и по сути бессмысленна.

[Карточка 4 — Свои проверки · skill-обёртка]
ЧТО ДЕЛАЕТ: упаковывает существующий в репозитории цикл «линтер → проверка типов → тесты» в один вызов.
БЕЗ НЕГО НЕВОЗМОЖНО: агент каждый раз угадывает команды проекта — и молча пропускает проверку, о которой не знал.

[Карточка 5 — Закрытый контур · pytest-generator]
ЧТО ДЕЛАЕТ: дообученная модель на 8 млрд параметров (~5 ГБ, есть версия для процессора) пишет скелеты тестов на машине.
БЕЗ НЕГО НЕВОЗМОЖНО: любая AI-генерация тестов = отправка исходного кода во внешний сервис: для закрытого контура это запрет.

[Шестая ячейка — критерий выбора]
Каждый инструмент закрывает ровно один канал, слепой для агента: данные, сеть, интерфейс, свои проверки, закрытый контур. Локальное, детерминированное и уже работающее — берите и оборачивайте; писать самому имеет смысл только обёртку вокруг своего же цикла проверок.

[Приглушённая строка снизу]
Честные ограничения: без настоящего примера ответа API мок MSW — догадка агента, а не контракт · AI-функции WireMock живут в платном WireMock Cloud, а не в локальном ядре с открытым кодом · pytest-generator — точность ≈77% заявлена вендором, независимо не проверена, распространённость низкая.

## Speaker notes

Пять каналов, в которых кодинг-агент без инструмента слеп, и чем каждый закрывается — локально, на машине разработчика, без выхода в облачный сервис.

Данные — Testcontainers: поднимает настоящий Postgres, Kafka или Redis в контейнере на временном порту и гасит его после прогона. Без него агент проверяет запрос против воображаемой схемы: интеграционный тест либо не пишется вовсе, либо оказывается зелёным на заглушке и красным в проде.

Сеть — MSW: перехватывает HTTP прямо внутри процесса, и один обработчик работает и в модульных, и в сквозных тестах; вне JS тот же класс задач закрывает WireMock с открытым кодом. Без него агент либо бьёт по настоящему API — нестабильно, платно, с лимитами, — либо не тестирует сетевой код вообще.

Интерфейс — Playwright: даёт агенту браузер и, что важнее, не картинку, а дерево элементов страницы, по которому он кликает, заполняет формы и порождает тест. Без него агент никогда не видит настоящий интерфейс — отладка фронтенда идёт вслепую и по сути бессмысленна. Это ровно та категория, которой не закрывают ни база данных, ни сетевые моки.

Свои проверки — обёртка-skill: уже существующий в репозитории цикл «линтер, проверка типов, тесты» упакован в один вызов. Без неё агент каждый раз угадывает команды проекта и молча пропускает проверку, о существовании которой не знал.

Закрытый контур — pytest-generator: дообученная модель на восемь миллиардов параметров пишет скелеты тестов прямо на машине. Без неё любая генерация тестов моделью означает отправку исходного кода во внешний сервис: для закрытого контура это запрет, а не неудобство.

Честные ограничения назовём тоже. Без настоящего примера ответа API мок — догадка агента, а не контракт. AI-функции WireMock живут в платном облаке, а не в локальном ядре. А заявленная точность pytest-generator около семидесяти семи процентов — вендорская, независимо не проверенная.
