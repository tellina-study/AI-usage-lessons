## 0. Новая рамка лекции

Целевая аудитория переформулирована: студенты — будущие инженеры, которые (а) когда-нибудь будут проектировать AI-системы и принимать архитектурные решения, но (б) **уже сейчас** ежедневно работают с агентами (coding-агенты, чаты). Формальная цель лекции (архитектурный выбор) остаётся, но **≥50% лекции** отдаётся под «анатомию агента» — не абстрактно, а на уровне реальных компонентов, которыми пользуются студенты, с прицелом на немедленную практическую пользу, не только на будущее архитектора.

**Источник:** `github.com/workain/agent-harness-registry` — публичный реестр "harness equipment" для AI-агентов. Проверен напрямую (README, GUIDE.md, research/, несколько deep-dives). Формат: каждый claim либо процитирован из проверенного источника, либо помечен `[unverified]`; есть механизм «tested (live-eval) vs catalogued» с честными вердиктами (tier + "the catch") — идеально ложится на требование курса про документированные провалы/ограничения.

**Категории реестра → блоки анатомии агента (мэппинг проверен):**
- **Memory** (11 записей, 9 live-tested) — от плоского файла до векторных/graph-баз (mem0, Cognee, Graphiti) — прямая линия к RAG из Раздела 2 («тот же вопрос масштаба знания, но для памяти агента, а не корпуса документов»)
- **Skills/tools** (26 записей) — переиспользуемые процедуры (Anthropic Agent Skills и др.)
- **Instructions-rules** (CLAUDE.md/AGENTS.md/Cursor Rules + hooks-gates) — «операционный слой» из брифа владельца
- **Subagents** (32 записи) — делегирование, роли
- **Access/MCP** (34 записи) — уже частично в деке (s20), расширяем реальными примерами
- **Engines** (11: Claude Code, Cursor, Aider, Codex CLI, Cline, Devin, Windsurf, Goose, **OpenHands** — вероятно то, что владелец на слух назвал «open claw», это open-source автономный coding-агент, MIT, — самый близкий кандидат из реестра, требует подтверждения у владельца при показе), SWE-agent, Gemini CLI) — реальный обзор coding-агентов, которым посвящён content gap из issue

**Ключевые находки для контента (готовые, процитированные, не выдуманные):**
1. **«Presence paradox»** (Gloaguen et al., arXiv:2602.11988, RCT): наличие файла-инструкции (CLAUDE.md-класс) само по себе **не даёт статистически значимого прироста task-success** — кроме случая, когда файл заполняет реальный пробел в документации. Сильный, некликбейтный failure/limitation-контент.
2. **Task-log эффект неоднозначен**: близкие ablation-исследования (ReasoningBank/SWE-MeM/Reflexion) сильные, но измеряют другое (машинная память в рамках одного бенчмарка, не человеко-читаемый журнал через недели). Отдельно — **"Honest Lying" (Dixit et al., arXiv:2605.29463)**: self-authored память может **закрепить неверное убеждение**. Реальный GitHub issue (`anthropics/claude-code#51735`) — записанная ошибка всё равно повторилась через 25 дней.
3. **Letta (Tier D, live-tested)**: агентная память **проигрывает простому плоскому файлу** по точности и на порядок медленнее; конкретные механизмы провала (капитуляция под давлением, «многословие топит факт», etc.) — отличный worked failure case.
4. **Anthropic Memory Tool (Tier B, live-tested)**: сильный результат, но **17% задач — потеря информации** через 3 разных механизма (отказ записать, out-of-scope отказ, тихая lossy-суммаризация), включая **невоспроизводимость** (одна и та же беседа — то сохранил, то нет).
5. **«Growth ladder»** (`base-project-template`, first-party): явная, обоснованная таблица «когда усложнять» (когда добавлять subagents, когда — memory backend, когда — MCP) — **прямое продолжение центрального правила лекции** («не усложняй без требования задачи»), только применённое к агентному инструментарию, а не к архитектуре целиком. Это и есть материал для нового финала.

## 4. Отклонение от стандартного каденса гейтов (явно, по прямому указанию)

Владелец прямым текстом попросил меньше промежуточных сверок: «прогони ревью, прожарь, и после этого уже приходи показывай». Стандартный pipeline CLAUDE.md предполагает 3 отдельных USER GATE (chapter/slides/final). **По этому конкретному заходу** — объединяю их в одну финальную сверку: chapter.md + slides + speech.md + все QA-отчёты предъявляются вместе, одним пакетом, после того как methodology-critic/fact-checker/presentation-critic/student-simulator/reader-simulator уже прогнаны и P0/P1 закрыты. Это разовое отклонение по прямой инструкции, не новая норма для остальных лекций.
