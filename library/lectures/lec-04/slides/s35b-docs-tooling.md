# Visible content

## Title bar
Инструментарий документации на практике: вход — код, выход — пересказ уже сказанного

## Body
[Слева — SaaS-вендорский слой, Ocean rounded box]

**Confluence AI (Atlassian Intelligence).** Три способности: **суммаризация** длинного треда в краткую выжимку; **генерация и трансформация** черновика из промпта; **Q&A-поиск** по базе знаний естественным языком (RAG-подобный паттерн поверх корпоративной базы).

**AWS Q Developer `/doc`.** Зрелая функция (анонс декабрь 2024): агент анализирует **кодовую базу**, а не пересказывает промпт. Может строить диаграммы инфраструктуры из IaC-файлов (Terraform/CDK) — прямая связь с уже введённым принципом архитектура-как-код. Замкнутый цикл: код изменился → предложен дифф в документации.

[Справа — code-first альтернатива, Ocean rounded box]

**Код-ориентированная альтернатива — сам кодинг-агент.** Установленный **skill** («Code Documentation Skill», «README Generator») анализирует структуру проекта, зависимости и код-паттерны, генерирует README/ADR/inline-комментарии.

*Честно: community-паттерн, не единый официальный skill из репозитория Anthropic. Онбординг-документация — хороший кандидат в skill по уже введённым эвристикам: повторяющаяся инструкция + нужен progressive disclosure.*

[Gold callout]
Вендор-специфичный слой (Confluence AI/Rovo, AWS Q `/doc`) — иллюстрация механики текущего 2026-стека, не рекомендация одного вендора: тот же паттерн доступен через установленный skill поверх уже используемого кодинг-агента, без привязки к SaaS.

## Speaker notes

Мы уже назвали вендоров документации — Confluence AI, AWS Q slash-doc, JetBrains, — но не механику. Разберём, что происходит внутри каждого, и code-first альтернативу, ближе к практике курса.

Confluence AI, общий AI-слой над продуктами Atlassian, даёт три способности. Суммаризация: длинный тред сворачивается в краткую выжимку. Генерация и трансформация контента: черновик страницы из промпта или переформулировка существующего текста в другом тоне. Q&A-поиск по базе знаний: вопрос на естественном языке вместо ключевых слов, ответ собирается из разрозненных страниц — тот же RAG-подобный паттерн поверх корпоративной базы, включая расшифровку внутреннего жаргона компании.

AWS Q Developer со слэш-командой doc — зрелая функция, анонсированная в декабре 2024 года, не свежий эксперимент. Агент анализирует кодовую базу и генерирует документацию из неё — вход именно код, а не пересказ промпта; уважает файл игнорирования git. Может создавать диаграммы инфраструктуры, если проект содержит файлы инфраструктуры как кода — прямая связь с уже введённым принципом архитектура-как-код: агент читает уже существующую инфраструктуру-как-код и выводит из неё диаграмму, а не выдумывает архитектуру по описанию. Может ревьюить новый код и предлагать обновления документации — замкнутый цикл «код изменился, доступен дифф в документации».

Код-ориентированная альтернатива: вместо SaaS ту же задачу решает кодинг-агент через установленный skill — этот паттерн уже встречался: skill вроде «Code Documentation Skill» анализирует структуру проекта и код-паттерны, генерирует README, ADR, inline-комментарии. Честная оговорка: это community-паттерн, не официальный skill из репозитория Anthropic — «паттерн существует» не значит «встроенная фича из коробки». Онбординг-документация — хороший кандидат в skill сразу по двум эвристикам: одну инструкцию копируют новому разработчику раз за разом, а материал нужен не на каждом шаге.

Устойчивый паттерн — сам факт, что документация как привнесённая сложность имеет вход, который уже существует: код, тред, решение, — и AI пересказывает сказанное, а не выдумывает намерение. Вендор-специфичный слой — иллюстрация текущего стека, не рекомендация: тот же паттерн доступен через skill поверх уже используемого агента, без SaaS.
