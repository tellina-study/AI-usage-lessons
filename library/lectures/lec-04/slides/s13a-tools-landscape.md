# Visible content

## Title bar
Три категории инструментов уровня B–C — по тому, ГДЕ живёт агент

## Body
[3 карточки в Ocean rounded box]

**Agentic IDE (агентная среда разработки)**
Desktop-редактор (часто форк VS Code) со встроенным агентом внутри интерфейса. Флагман — **Cursor**: Tab-автодополнение (A), Cmd-K (B), Composer/Agent Mode (C) — все три уровня в одном продукте.
→ визуальный контроль (diff, файловое дерево, терминал) ценой привязки к редактору.

**CLI-агент (агент командной строки)**
Работает из терминала без выделенного GUI, в связке с любым редактором. Canonical пример — **Claude Code**: по умолчанию уровень C, поднимается до D в режиме команд агентов.
→ гибкость в скриптовании и автоматизации (CI, hooks) ценой отсутствия визуального diff.

**Фреймворк для построения агентов**
Не готовый продукт, а библиотека/SDK для сборки собственного агента под нестандартную задачу. Упомянуто для полноты словаря — курс про пользователей готовых инструментов, не про их разработчиков.

[Teal callout]
**Категория важнее бренда** — тот же принцип, что и для уровня автономии: agentic IDE выигрывает при визуальном контроле над многофайловым diff в одном редакторе; CLI-агент — при автоматизации, встраивании в конвейер, headless-окружении (CI, удалённый сервер), параллельных сессиях.

[Gold callout]
**Агент vs субагент в коде:** основной агент делегирует узкий подшаг — например, «прочитай эти 15 файлов миграций и составь сводку схемы БД» — субагенту, чтобы не засорять свой контекст сырыми деталями и изолировать радиус поражения при работе с недоверенным содержимым (чужой PR). Независимые подшаги → субагент оправдан; зависимые, делящие контекст, — та же хрупкость мульти-агента, не апгрейд.

## Speaker notes

Зафиксируем словарь категорий инструментов уровня B–C. Рынок AI-инструментов для разработки делится на три категории по тому, где живёт агент, — это отдельная ось от лестницы автономности A→D: та отвечает «сколько AI решает сам», эта — «в каком окружении он это делает».

Agentic IDE — desktop-редактор, часто форк VS Code, со встроенным агентом внутри интерфейса. Флагман — Cursor: Tab-автодополнение, Cmd-K и Composer/Agent Mode — все три уровня автономии в одном продукте. Категория даёт визуальный контроль — diff перед принятием, файловое дерево, терминал — ценой привязки к конкретному редактору.

CLI-агент работает из терминала, без выделенного GUI, в связке с любым редактором. Canonical пример — Claude Code: по умолчанию уровень C, поднимается до D в режиме команд агентов. CLI-агенты обычно гибче в автоматизации — легко встроить в CI, в хук, — но без визуального diff-интерфейса.

Третья категория, фреймворк для построения агентов, — не продукт, а библиотека для сборки собственного агента. Упоминаем для полноты словаря: аудитория курса — пользователи готовых инструментов, не их разработчики.

Здесь работает тот же принцип, что мы применяли к уровню автономии: категория важнее бренда. Agentic IDE выигрывает там, где нужен визуальный контроль над многофайловым diff в одном редакторе; CLI-агент — там, где нужна автоматизация, встраивание в конвейер, headless-окружение или параллельные сессии.

Отдельно — «агент против субагента» применительно к коду. Основной агент может делегировать субагенту узкий подшаг — скажем, «прочитай эти пятнадцать файлов миграций и составь сводку схемы базы данных» — и получить сжатую выжимку, не засоряя собственный контекст. Субагент экономит контекст и изолирует радиус поражения при работе с недоверенным содержимым, например с чужим pull request. Независимые подшаги — субагент оправдан; зависимые, делящие контекст, — та же хрупкость мульти-агентной системы, не апгрейд.
