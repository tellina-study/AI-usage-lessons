# Восемь из восьми, три вызова в запасе, полторы недели тишины

## Assertion

Юникод-сокрытие доставило инструкцию модели в восьми случаях из восьми, без единого механизма повторного одобрения. Кампания ведёт себя безобидно ровно три вызова, прежде чем искать ключи доступа. Подмена уже одобренного пакета оставалась незамеченной около полутора недель.

## Visual

| Слой | Что произошло | База сравнения |
|---|---|---|
| 1 · контролируемый эксперимент (Rashidi, arXiv:2607.05744, 08.07.2026) | Юникод-сокрытие инструкции в описании инструмента доставило её модели в 8 из 8 попыток на трёх независимых серверных библиотеках; 0 из 8 вызвали механизм повторного одобрения; санитайзер по строковому совпадению дал 0 ложных срабатываний на 25 безобидных описаниях | 0 ложных срабатываний означает, что проблему нельзя списать на недокалиброванный фильтр — она в самой архитектуре доверия по имени |
| 2 · кампания на обход ручной проверки (Deadbugz) | Сервер, распространённый через 23 GitHub PR за 74 минуты, ведёт себя безобидно ровно 3 вызова инструментов — после чего переключается на поиск SSH-ключей и облачных credentials | порог в три вызова специально выше, чем глубина обычной ручной проверки перед доверием «попробовал — вроде работает» |
| 3 · реальный, тихий инцидент (`postmark-mcp`, сентябрь 2025) | Backdoor появился в обновлении пакета недели спустя после первого одобрения — около полутора недель (17–29.09.2025) скрытая BCC-копия каждого отправляемого письма уходила незамеченной, пока рассылку не заметили и пакет не сняли с npm | обновление пакета — обычное, ожидаемое действие; подмена вошла в его состав, отдельным заметным шагом она не стала |

> Фиксируйте версию сервера. Перечитывайте изменения при обновлении. Одобрение — не решённый вопрос навсегда.

## Speaker notes

Три факта, каждый острее предыдущего.

Контролируемый эксперимент, не анекдот: юникод-сокрытие инструкции в описании инструмента доставило её модели в восьми случаях из восьми, на трёх разных независимых серверных библиотеках. Ни разу это не вызвало какого-либо механизма повторного одобрения. При этом тот же фильтр по строковому совпадению не дал ни одного ложного срабатывания на контрольном наборе из двадцати пяти безобидных описаний — значит, причина лежит в самой архитектуре доверия по имени, не в недокалиброванном фильтре.

Кампания, спроектированная на обход ручной проверки: сервер, распространённый через двадцать три запроса на внесение правок за семьдесят четыре минуты с одного аккаунта, ведёт себя безобидно ровно три вызова — достаточно, чтобы пройти обычное «попробовал, вроде работает», — и лишь затем переключается на поиск ключей доступа.

И реальный, тихий инцидент: вредоносный пакет получил скрытую копию каждого отправляемого письма на адрес атакующего при обновлении уже одобренного инструмента — без единого взлома. Backdoor появился в обновлении пакета недели спустя после первого одобрения, и около полутора недель это уходило незамеченным, пока рассылку не заметили и пакет не сняли с npm.

Фиксируйте версию сервера. Перечитывайте изменения при обновлении. Одобрение — не решённый вопрос навсегда.

Если спросят про детали юникод-эксперимента: использован специальный диапазон символов, который терминал и редактор кода отображают как пустоту, но который целиком доходит до токенизатора модели — человек, читающий описание инструмента перед одобрением, физически не видит того, что видит модель.

Если спросят, почему порог именно три вызова у кампании с подменой: это специально выше, чем глубина обычной ручной проверки перед доверием — рассчитано на то, чтобы пройти типичный тест-прогон «попробовал — вроде нормально».

Если спросят про письма подробнее: подмена произошла через обновление самого пакета неделями позже первоначального одобрения, без заметного события — ни новое разрешение не запрашивалось, ни предупреждение не показывалось. Активный период скрытого копирования — около полутора недель, не дольше: пакет сняли с npm, когда рассылку заметили.
