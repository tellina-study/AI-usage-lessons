## Speaker notes

Две конкретные ситуации, в которых RL не подходит, и какие альтернативы доказательно лучше.

Первая — критичные по безопасности контуры. E-stop, interlock, emergency shutdown, аварийная остановка реактора. Почему RL не сертифицируется. Первое: нет audit trail в форме, которую принимает регулятор; RL-policy — это набор весов нейронной сети, не последовательность логических утверждений, которую можно проверить вручную. Второе: недетерминированный output несовместим с IEC 61508 SIL 2/3. Стандарт требует доказуемой вероятности отказа. Для SIL 2 это 10⁻⁶..10⁻⁷ отказов в час, для SIL 3 это 10⁻⁷..10⁻⁸. RL такие гарантии не даёт по definition. Третье: RL не покрывает edge cases — нейросеть учится на распределении тренировочных данных; новые ситуации обрабатываются непредсказуемо. Альтернатива: hardwired PLC плюс формальная верификация (TLA+, SPIN, Coq, SCADE) плюс IEC 61508 SIL 2/3.

Вторая — процесс с известной физикой. Если уравнения известны (Навье-Стокса для потоков, теплоперенос, химическая кинетика), MPC — Model Predictive Control, модельное предиктивное управление — даёт доказуемые гарантии устойчивости через теорию Ляпунова. Явная оптимизация на горизонте, учёт hard constraints, сертифицируется в фарма и нефтехим. RL даёт гибкость, MPC даёт гарантии. Для known physics — выбирайте MPC.
