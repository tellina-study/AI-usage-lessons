# Visible content

## Title bar
Та же механика — но здесь решение убить продукт, а не флаг переключить

## Body
[Flow: Feature flag → Canary → Staged rollout → Rollback + отдельная иконка «бизнес-решение»]

**Примитивы вы знаете из CI/CD** — новое здесь: чьё и по каким критериям решение они обслуживают

- MVP (Райс) = обучение, не отгрузка
- Stage-Gate go/kill (Купер) — «воронка, не туннель»; пороги провала записаны числом заранее

## Speaker notes

Feature flag, canary, rollback вам знакомы из повседневной инженерной практики — базовые определения вы, скорее всего, прочтёте по диагонали. Держите при этом одно продуктовое отличие, ради которого раздел вообще существует: здесь та же механика встроена в продуктовый go/kill-гейт, где решение убить проект — это бизнес-решение, а не только технический флаг «включить-выключить».

Единая логическая нить: каждая практика обменивает немного скорости запуска на ограниченный радиус поражения. Feature flag отделяет развёртывание от релиза. Canary — новая версия выкатывается на небольшую долю трафика первой. Staged rollout — обобщение canary: один, десять, двадцать пять, пятьдесят, сто процентов, с проверкой go/no-go на каждом шаге. Rollback — способность быстро вернуться к последнему рабочему состоянию.

MVP Эрика Райса определяется обучением, а не отгрузкой — быстрый способ пройти цикл построить-измерить-научиться. Stage-Gate Роберта Купера — пять стадий, каждой предшествует гейт go/kill/hold/recycle по заранее согласованным критериям; осознанная цель — принудить к дисциплинированным решениям об остановке рано, до капиталоёмких трат — «воронка, а не туннель». Go/no-go гейт готовности к запуску требует конкретно: фазы раскатки с критериями перехода, пороги провала, записанные числом заранее, план отката с назначенным человеком. Здесь снова всплывает наш сквозной приём — фальсифицируемая гипотеза, применённая к решению о релизе.
