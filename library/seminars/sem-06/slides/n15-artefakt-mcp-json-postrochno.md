# Собранный файл — и порядок при конфликте имён

## Assertion

Итог разговора — файл из четырёх строк существа: имя сервера, чем он запускается, что запускается, откуда берётся ключ. Вне файла, но не менее важно — какие права у этого ключа: один репозиторий, не вся учётная запись. А если то же имя сервера объявлено в двух областях конфигурации сразу — побеждает более личная область, а политика организации стоит выше всех шести.

## Visual

```json
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": { "GITHUB_PERSONAL_ACCESS_TOKEN": "${GITHUB_PAT}" }
    }
  }
}
```

- `mcpServers` — корень: все серверы этой области. `"github"` — имя сервера: под ним агент зовёт инструменты, `mcp__github__…`.
- `"command"` и `"args"` — чем запускается и что именно: пакет самого сервера.
- `"env"` — окружение процесса; `${GITHUB_PAT}` — подстановка, не сам секрет.

## Speaker notes

Итог разговора — файл из четырёх строк существа. Каждая отвечает на свой вопрос.

`mcpServers` — корень: список всех серверов, объявленных в этой области видимости. Один файл может держать несколько серверов, и каждый получает свою запись.

`"github"` — имя сервера. Под этим именем агент будет вызывать его инструменты: `mcp__github__…`. Имя выбираете вы, и оно попадает во все места, где на сервер ссылаются, — в правила разрешений, в списки инструментов, в вывод вызова. Переименовать его потом значит пройти по всем этим местам.

`"command"` — чем запускается: конкретная программа-лаунчер, здесь `npx`. `"args"` — что запускается: пакет самого сервера. Вместе эти две строки и есть та команда, которая исполнится при старте сессии.

`"env"` — переменные окружения для процесса. Значение здесь — подстановка `${GITHUB_PAT}`, сам секрет в файле не лежит текстом.

Права этого ключа в файл не входят вообще, и это стоит держать в голове, глядя на экран. Один репозиторий вместо всей учётной записи — решение, принятое на стороне сервиса, где токен создавался; из конфигурации его не видно и в ревью по этому файлу не поймать. Файл показывает, откуда берётся ключ, и ничего не говорит о том, что этим ключом можно сделать.

Про сам файл: он лежит в корне репозитория и виден всем, кто клонирует проект. Личная и общая личная области живут в отдельном файле вне репозитория — секреты из кода туда не попадают просто потому, что файл физически не в дереве git.

Эта команда запускает на вашей машине живой процесс. Если он упадёт посреди сессии, сам он не перезапустится — нужна новая сессия. Что при этом видно со стороны и почему зелёная отметка об этом молчит — на следующем экране.

Схема приоритета под файлом отвечает на вопрос, который возникает, когда одно и то же имя сервера объявлено дважды. Шесть ступеней, и на каждой подписан физический файл. Ступени `local` и `user` обе подписаны файлом `~/.claude.json` — то же устройство и та же причина, что на одностраничнике MCP: один физический файл, две записи внутри него. При конфликте имён это разные по весу записи, несмотря на общий файл.

Областей ровно три, и произвольной настройкой это число не является: три жёстко заданных места — ровно то, что умеет продукт. Изменить область уже подключённого сервера значит переписать ту же запись в другое место; права токена при этом остаются прежними, их меняют там, где токен создавался.

И честный пробел, который стоит назвать прямо. Этот файл — целевое решение раздела, собранное с более раннего захвата демонстрационного репозитория. Коммита с ним в текущей ветке нет, и в репозитории курса такого файла тоже нет. Разбор опирается на доказательную базу исследования, живого коммита за ним не стоит; то же касается двух следующих кейсов этого блока — у них этот пробел общий. Экран показывает разбираемый пример и не обещает «склонируй и повтори».
