# .mcp.json целиком

## Assertion

В файле подключения четыре строки существа, и одна из них — о том, откуда берётся ключ, а не какой он.

## Visual

Слева — файл целиком:

```json
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": {
        "GITHUB_PERSONAL_ACCESS_TOKEN": "${GITHUB_PAT}"
      }
    }
  }
}
```

Подписи: чем запускается · что запускается · **откуда берётся ключ** — подстановка из окружения, не значение в файле.

Отдельной плашкой **за пределами рамки файла**: какие права у этого ключа — **один репозиторий, а не вся учётная запись**. Стрелка к плашке с подписью «этого в файле нет, и это самое важное».

Справа — дерево ступени 5, `.mcp.json` выделен gold с пометкой «первый блок, который смотрит наружу».

## Speaker notes

Файл короткий, и это само по себе стоит отметить: вся сложность подключения снаружи файла, а не внутри него.

Четыре строки существа: чем запускается, что запускается, откуда берётся ключ и — вне файла, но не менее важное — какие права у этого ключа.

Последний пункт стоит показать визуально: плашка про права нарисована за пределами рамки файла, со стрелкой. Всё, что зал вычёркивал минуту назад, в этом файле не видно вообще. Именно поэтому просмотр `.mcp.json` в чужом pull request не отвечает на главный вопрос — он отвечает на второстепенный.

И одна фраза про то, зачем протокол вообще существует, если зал спросит: без общего стандарта каждую пару «клиент × внешняя система» приходится интегрировать отдельно — при M клиентах и N системах это до M×N кусков кода. Стандарт сводит задачу к M+N: разработчик системы один раз пишет сервер, разработчик клиента один раз встраивает клиент.

Дерево справа — пять блоков конфигурации. Четыре смотрят внутрь, пятый — наружу.
