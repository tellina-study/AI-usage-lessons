# Тот же перевод слова: 1 класс и 1 вызов против 3 классов и 4 вызовов

## Assertion

Одно и то же действие — перевод слова на другой язык. Прямым вызовом API это один класс и один вызов функции; через LangChain — три класса, четыре вызова и три новых понятия, которые к результату ничего не добавляют.

## Visual

```python
# прямой вызов API: класс OpenAI, вызов create — и это всё
client = OpenAI(api_key=KEY)
m = [{"role": "system", "content": "You are an expert translator"},
     {"role": "user", "content": f"Translate into {lang}: {text}"}]
resp = client.chat.completions.create(model=MODEL, messages=m)
result = resp.choices[0].message.content
```

```python
# через LangChain: 3 класса, 4 вызова, 3 новых понятия
prompt = ChatPromptTemplate.from_messages([      # класс 1, вызов 1
    ("system", "You are an expert translator"),
    ("user", "Translate into {language}: {text}")])
parser = StrOutputParser()                       # класс 2, вызов 2
chain = prompt | ChatOpenAI(model=MODEL) | parser    # класс 3, вызов 3
result = chain.invoke({"language": lang, "text": text})   # вызов 4
```

> Способа смотреть на состояние агента извне фреймворк не давал — реализацию пришлось сузить до того, что LangChain показывает наружу. **Решение Octomind: вынести фреймворк целиком**, оставив прямые вызовы модели и обычный код вокруг них — условия, циклы, обработку текста. **«We could just code»** — «мы могли просто написать код». Обсуждение на Hacker News, 20 июня 2024: **480 очков, 297 комментариев**.

## Speaker notes

Octomind — компания, чьи агенты на нескольких больших языковых моделях сами создают и исправляют сквозные (end-to-end) тесты на Playwright, популярном инструменте автоматизации браузера. LangChain стоял у них в промышленной работе больше двенадцати месяцев: взят в начале 2023 года, вынесен в 2024-м. В 2023-м выбор выглядел разумным — большой список готовых компонентов и прямое обещание довести разработчика «от идеи до работающего кода за полдня».

Пока требования команды совпадали с тем, под что фреймворк рассчитан, он помогал. Дальше понадобилось менять поведение системы на низком уровне, и команда полезла во внутренности LangChain: фреймворк намеренно скрывает эти детали, поэтому написать нужный низкоуровневый код часто оказывалось попросту невозможно.

Масштаб разницы виден на тривиальном примере из самого поста — перевод одного английского слова на итальянский. Прямым вызовом API это один класс и один вызов функции, остальное — обычный Python. Через LangChain то же самое — три класса и четыре вызова, и, что важнее, три новых понятия: шаблон промпта (чем промпт передаётся модели), парсер вывода (чем обрабатывается ответ) и «цепочка» — синтаксис LCEL, переопределяющий оператор `|` самого Python. К результату эти три понятия ничего не добавляют.

Вторая находка оказалась дороже первой и касалась наблюдаемости. Команде понадобилось менять набор доступных агенту инструментов на ходу, по бизнес-логике и по выводу модели, — а способа наблюдать состояние агента извне фреймворк не предоставляет. Реализацию пришлось сузить до того, что LangChain умеет показать наружу: систему построили под эту границу, и исходные требования остались за ней.

Решение — вынести фреймворк целиком, оставив прямые вызовы модели и обычный код вокруг них. Формулировка авторов короткая: «We could just code» — «мы могли просто написать код». В начале поста та же мысль другими словами: убрав фреймворк, команда перестала переводить свои требования на язык, который понимает LangChain.

Пост получил широкий резонанс: обсуждение на Hacker News 20 июня 2024 года собрало 480 очков и 297 комментариев. Там же публично и по существу ответил глава LangChain, а один из участников назвал `AgentExecutor` фреймворка «непрозрачным» — ровно то свойство, которое новый на тот момент LangGraph из той же экосистемы создавался заменить.
