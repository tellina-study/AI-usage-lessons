# Где должна проходить граница куска

## Assertion

Экономия на шаге разбора текста оплачивается долей ответов, разорванных между двумя кусками.

## Visual

> Граница куска должна совпадать с границей смысла внутри документа — счёт символов тут значения не имеет. Резка, которая режет документ «как придётся», экономит один шаг подготовки и платит за это тем, что часть ответов на будущие вопросы окажется разорвана между двумя кусками.

> **Это решение не нуждается в модели.** Все четыре версии резки — по счёту символов, по границам предложений, по границам слов и по счёту символов с перекрытием — чисто алгоритмические: место границы вычисляется кодом, без обращения к LLM.

## Speaker notes

Это слой архитектуры, сформулированный так, чтобы он оставался верным при смене инструмента. Об этом архитектурном решении важно сказать сразу: оно не нуждается в модели вовсе. Резка по счёту символов, резка по границам предложений, резка по границам слов и резка по счёту символов с перекрытием — всё это обычный код, который вычисляет границу куска по тексту напрямую, без обращения к LLM и без эмбеддинга. Это часть самого архитектурного решения; деталью реализации её не назвать: для этого шага правильный инструмент — алгоритм, и модель здесь ни при чём.

Идея простая: граница, по которой документ режется на куски хранилища, должна совпадать с границей смысла внутри этого документа — счёт символов тут значения не имеет. Резка, которая режет документ «как придётся» — по фиксированному числу символов, не глядя на текст, — экономит один шаг подготовки данных. Но мы только что увидели числом, чем эта экономия оплачивается: часть ответов на будущие вопросы клиентов окажется разорвана между двумя соседними кусками, и поиск впоследствии найдёт только половину нужного факта.

Это архитектурное наблюдение не привязано к конкретному инструменту резки текста и не привязано к конкретному языку — оно останется верным для любого документа, который режут на части перед тем, как положить в хранилище. Как это настраивается на реальном экране — следующий такт.

«Граница смысла» — вполне конкретная, измеримая вещь; абстрактным философским термином её назвать трудно: это граница между предложениями, между пунктами списка, между абзацами. Документ почти всегда уже содержит эту разметку — знаки препинания, переносы строк, нумерацию пунктов, — и задача резки по смыслу сводится к тому, чтобы уважать уже существующую структуру документа: никакого произвольного счёта символов сверху, никакого придуманного на ходу понимания текста.

Это объясняет, почему решение называется архитектурным: это больше, чем просто «более аккуратная настройка». Оно задаёт правило, применимое к любому документу учебного центра заранее, ещё до того, как известно, какой конкретно вопрос по нему зададут. Правило простое и проверяемое: разрез никогда не проходит внутри предложения. Всё остальное — конкретный размер куска, конкретный инструмент разбивки на предложения — это уже детали реализации одного этого принципа, самостоятельными решениями они не являются.
