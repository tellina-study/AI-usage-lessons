# Шесть источников — и один честный пробел

## Assertion

Шесть независимых источников сходятся на одном: доступ наружу расширяет площадь ошибки быстрее, чем растёт доверие к серверу, — а стоимость самой проверки перед подключением не измерил никто.

## Visual

| Источник | Что показал | Сила доказательства |
|---|---|---|
| Скан 7973 живых серверов, arXiv:2605.22333 | 40,55% отдают инструменты без проверки, кто обратился | Сильное: весь набор, не выборка |
| CVE-2026-61788, CVE-2026-61742 | флаг «только чтение» не включал режим; вход без проверки | Сильное для механизма; в дикой природе не замечено |
| Сокрытие инструкции, arXiv:2607.05744 | 8 из 8 доставлены модели, 0 из 8 спросили заново | Сильное: 3 реализации, 0 ложных на 25 описаниях |
| Цепочка поставки, OX Security | команда из конфигурации исполняется в любом случае | Умеренное: цифры масштаба — от вендора |
| Кампания августа 2026, Pillar Security | безобиден первые 3 вызова, затем меняет описания | Умеренное: жертва не названа |
| Замер «команда против сервера», Scalekit | 4–32× по токенам, 17× по деньгам | Умеренно-сильное: узкий круг задач |

- Чего нет ни в одном источнике: сколько времени занимает сама проверка сервера перед подключением.

## Speaker notes

Таблица упорядочена по силе доказательства, не по дате.

Три сильных — и сильны они по разным причинам. Сканирование почти восьми тысяч живых серверов: сорок процентов с половиной отдают инструменты вообще без проверки, кто к ним обратился. Это не выборка — это весь отсканированный набор. Две уязвимости сервера баз данных сильны для механизма: официально раскрыты, с разбором и заплаткой, хотя использования в дикой природе не подтверждено. Эксперимент с сокрытием инструкции воспроизводим: три независимые серверные библиотеки, и ни одно из восьми сокрытий не вызвало повторного вопроса пользователю.

Три оставшихся слабее, и это стоит сказать вслух. Разбор цепочки поставки и августовская кампания подтверждены по механизму, но агрегированные цифры там от самих исследователей, методика раскрыта не полностью. Замер расхода воспроизводим, но сделан на узком круге задач.

И честный пробел. Сколько времени занимает сама проверка перед подключением, не измерил никто. Поэтому критерий дальше будет построен на признаках, а не на цене процедуры — числа, которого нет, я подставлять не стану.
