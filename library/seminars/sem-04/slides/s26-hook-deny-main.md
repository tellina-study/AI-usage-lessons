# Хук в действии: `deny` на ветке main

## Assertion

На ветке main тот же самый коммит получает deny — исполняет среда, не завязано на согласие агента; это и есть наблюдаемое срабатывание, а не файл, существующий на всякий случай.

## Visual

Снимок терминала, моноширинный шрифт, дословно из капчура:

```
=== INPUT ===
{"tool_input":{"command":"git commit -m \"fix: second form field\""}}
=== current branch ===
main
=== HOOK OUTPUT (stdout) ===
{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":"BLOCKED: direct commit to main/master. Create a feature branch first."}}
=== exit code: 0 ===
```

## Speaker notes

Текущая ветка — `main`, проверено той же командой `git symbolic-ref --short HEAD`, которую мы только что разобрали построчно. Агент пытается закоммитить правку формы: `git commit -m "fix: second form field"`. Хук получает эту команду через stdin, видит `git commit` как отдельную команду, видит, что репозиторий реальный и ветка — `main`, и возвращает `permissionDecision: "deny"` с дословным текстом причины: «BLOCKED: direct commit to main/master. Create a feature branch first.» Коммит не создан.

Это ровно тот случай, о котором стоит сказать прямо, процитировав шаблон курса дословно: «a gate is not installed because its file exists — it is installed once observed firing against a real case». Слайд, который вы только что видели, — это и есть то самое наблюдаемое срабатывание, не гипотетическое описание того, что хук «должен» делать, а зафиксированный факт того, что он реально сделал на реальной попытке коммита.

Обратите внимание на важную деталь формата: `exit code: 0`. Хук не упал с ошибкой — он отработал штатно и сознательно вернул решение `deny` через JSON. Это отличает данный случай от «тихого несрабатывания», которое разберём в провале этого раздела: там хук либо вообще не запускается, либо падает по таймауту, и тогда никакого JSON-ответа не будет вовсе, а вызов пойдёт по обычному пути разрешений, как если бы хука не было.

Обратите внимание, что агент здесь не «согласился» с отказом и не понял, что был неправ, — согласие вообще не участвует в этой схеме. Разрешение решается на уровне среды выполнения, до того как модель вообще успевает сформулировать следующий шаг диалога. В этом и есть разница со ступенью 1: там правило работало, только пока агент решал ему следовать; здесь агент физически не может довести действие до конца, вне зависимости от того, что он «думает» по этому поводу.

Дальше — вопрос, который должен возникнуть сразу: что произойдёт, если агент сначала переключится на отдельную ветку? Ровно это мы сейчас и посмотрим — тот же самый коммит, другая ветка.
