# Тематические файлы со сквозными ссылками

## Assertion

Запись явно ссылается на связанную запись — то, чего в плоском append-only логе не было в принципе, не потому что забыли, а потому что формат не предполагает перекрёстных ссылок.

## Visual

Слева — структура:

```
memory/decisions/
  index.md          ← оглавление тем + список записей по каждой, со ссылками
  validation.md      ← все решения по валидации формы, в хронологии темы
  backend.md          ← решения о том, чего мы НЕ делаем
  deploy.md
```

Справа — пример записи внутри `validation.md`:

```markdown
## 2026-09-20 — не подключаем библиотеку валидации форм
Форма — два поля, хватает нативных required/pattern.
См. также: 2026-11-30 (антиспам) — это решение НЕ распространяется на защиту
от спама, там используется другой механизм, см. `validation.md#антиспам`.

## 2026-11-30 — антиспам через honeypot-поле, без капчи
Отменяет часть решения от 2026-09-20 для случая антиспама.
```

Подпись под примером: иллюстративный пример, не захваченный вживую — ждёт реальной сессии.

## Speaker notes

Устройство: тематические файлы плюс оглавление, и в самой записи — явная ссылка на связанную запись. Пример на слайде — не снятый кадр из демо-репозитория, честно назвать это залу: ждём живой сессии, чтобы захватить настоящий. Устройство от этого не меняется.

Ключевое отличие от предыдущего кейса — запись прямо говорит «см. также» и «отменяет часть решения от…»: то, чего в плоском append-only логе не было в принципе, потому что формат не предполагает перекрёстных ссылок.
