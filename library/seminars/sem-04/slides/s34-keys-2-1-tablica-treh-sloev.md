# Три слоя записи

## Assertion

Разница между слоями не в формате — оба markdown, — а в том, кто инициирует запись и кто её потом увидит.

## Visual

Таблица на весь слайд:

| | Файл инструкций | Авто-память | `DECISIONS.md` |
|---|---|---|---|
| Кто автор | вы, заранее | агент, по ходу | вы, в момент решения |
| Где живёт | в репозитории, git | вне репозитория, на этой машине | в репозитории, git |
| Что грузится | целиком, каждую сессию | индекс: первые 200 строк / 25 КБ | ничего автоматически |
| Проходит код-ревью | да | нет | да |
| Переживает смену машины | да | нет | да |
| Что туда идёт | стабильные правила и границы | предпочтения, подтверждённые подходы | решения и их «почему» |

Под таблицей — три строки: индекс памяти — только индекс · агент сам пропускает выводимое из кода · сжатие контекста переживают только файлы на диске.

## Speaker notes

Один критерий различения, одной фразой: разница не в формате — оба markdown, — а в том, кто инициирует запись и кто её потом увидит. Авто-память пишет агент, для себя, на этой машине, без ревью. Журнал решений пишете вы, для команды, в репозиторий, через ревью.

Три детали кратко: индекс памяти — только индекс, за двести строк содержимое физически не попадает в сессию; агент сам пропускает то, что выводимо из кода; сжатие контекста переживают только файлы на диске — то, что сказано лишь в разговоре, при сжатии может исчезнуть. Последняя деталь — прямой отклик на предыдущий раздел: «объясню в чате ещё раз» не работает даже внутри одной длинной сессии.
