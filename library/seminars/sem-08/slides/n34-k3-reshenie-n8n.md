# Настройка: IF-узел против текста правила

## Assertion

Один и тот же шаг цепочки настроен двумя разными способами. Слева — условие в коде, число сравнивается с числом. Справа — то же сравнение, но спрятанное внутри текста запроса к модели.

## Visual

> **Узел `IF` («Amount over threshold?»), версия 2.** Условие: извлечённая сумма (число) **строго больше 3000**. Ветка «да» → эскалировать руководителю. Ветка «нет» → одобрить. Сравнение — операция над числом, не текст, который нужно понять.

> **Для контраста — промпт версии 1, тот же шаг.** «Правило: не возвращай больше 3000 рублей автоматически, иначе эскалируй руководителю. Сумма запроса: {{сумма}} рублей. Ответь строго одним словом: «одобрить» или «эскалировать».» Здесь то же сравнение существует только как смысл внутри текста — у модели нет отдельной операции «сравнить числа», есть только одна операция «понять и ответить».

## Speaker notes

Вот настоящая настройка узла, который заменил решение модели в версии два — рядом с промптом версии один, который он заменил. Контраст виден сразу, и ради него стоило положить обе формулировки на один экран.

Слева — узел `IF`, названный по-русски для удобства, «Amount over threshold?» по смыслу. Условие внутри него одно: извлечённая сумма, уже число, а не текст, сравнивается с тремя тысячами строгим «больше». Если условие верно — заявка идёт по ветке «эскалировать». Если нет — по ветке «одобрить». Это операция сравнения чисел, и у неё нет пространства для интерпретации: либо число больше другого числа, либо нет.

Справа — промпт версии один, тот самый, что был на сцене. Обратите внимание, что в нём формально есть то же самое сравнение — «не больше 3000» — но оно существует только как часть смысла предложения, которое модель должна понять и применить. У модели нет отдельного шага «сравнить два числа»: есть один шаг «прочитать правило и сумму вместе и сформулировать ответ». И именно внутри этого одного шага три раза из пятидесяти одного правило и его трактовка расходились — ровно на границе, там, где текст можно прочитать двояко.

Это и есть разница между решением, принятым кодом, и решением, принятым текстовым пониманием, положенная рядом, без единого слова о том, какая версия лучше — она видна по самой форме настройки. Слева — число сравнивается с числом. Справа — число спрятано внутри фразы, которую нужно понять целиком, чтобы из неё извлечь тот же самый факт.

Сумма, которую сравнивает `IF`-узел, всё ещё извлечена моделью из свободного текста заявки на предыдущем шаге — этот шаг версия два не меняла. Меняется только то, что происходит после извлечения: было решение текстом, стало условие в коде.
