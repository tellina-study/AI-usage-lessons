# `AGENTS.md` — симлинк, не копия

## Assertion

AGENTS.md — симлинк на CLAUDE.md, не копия: один файл, один источник правды, читается любым движком.

## Visual

Терминальная карточка:

```
$ ln -s CLAUDE.md AGENTS.md
```

Рядом — дерево репозитория на этой ступени, дословно из демо-репозитория:

```
$ git ls-tree -r --name-only 04df4a3 | sort   # commit 04df4a3

AGENTS.md
CLAUDE.md
index.html
package.json
src/main.js
tests/form.spec.ts
```

## Speaker notes

Одна команда — `ln -s CLAUDE.md AGENTS.md` — и в репозитории появляется второй файл, `AGENTS.md`, который физически не хранит собственного содержимого: это символическая ссылка на тот же самый `CLAUDE.md`. Дерево коммита на этой ступени, снятое с реального демо-репозитория, показывает оба файла рядом — `AGENTS.md` и `CLAUDE.md` — как два самостоятельных имени, но одно содержимое.

Причина не в прихоти, а в том, что `CLAUDE.md` — не единственный формат такого файла в индустрии: `AGENTS.md` — открытый кросс-движковый стандарт, который читают другие агентные CLI, помимо Claude Code. Симлинк решает эту задачу без дублирования: правится один файл, `CLAUDE.md`, а второе имя автоматически показывает то же самое содержимое любому инструменту, который ищет именно `AGENTS.md`. Альтернатива — держать два независимых файла и вручную синхронизировать их при каждой правке — гарантированно разойдётся при первом же изменении, которое кто-то забудет продублировать.

В шаблоне курса, `base-project-template/with-git/`, `AGENTS.md` устроен ровно так же — не случайное совпадение, а прямое следствие того же принципа: один источник правды на весь проект, а не два файла, которые нужно держать синхронными руками.

Прежде чем перейти к провалу этой ступени, зафиксируем итог: репозиторий теперь содержит `CLAUDE.md` с реальными командами сборки и проверки, `AGENTS.md` как его зеркало для других движков, и это именно то состояние, на котором можно было бы остановиться, если бы правило само по себе гарантировало, что его соблюдают. Дальше — ровно об этом.
