# Что унести

## Assertion

Семь уроков, по одному на кейс — ничего нового, только компиляция

## Visual

Список из семи строк, каждая — кейс слева, урок справа:
«Документы поставщиков — два примера не выборка».
«Персоналка в логах — граница между regex и моделью внутри задачи».
«Помощник поддержки — организационное ограничение решает не хуже техники».
«Описания товаров — встроенность бьёт отдельный продукт».
«Протоколы встреч — архитектуру двигают требования, не мода».
«Дайджест — много источников ≠ RAG».
«Звонки продаж — сложно для человека ≠ сложно для модели, чувствительность выясняется вопросами».

## Speaker notes

Соберём то, что уже прозвучало сегодня — ничего нового, просто компиляция.
Документы поставщиков — два примера не выборка, нужно смотреть на полный
объём данных. Персоналка в логах — граница между регулярным выражением и
моделью проходит внутри одной задачи, не между задачами. Помощник
поддержки — организационное ограничение вроде закрытого API может решить
архитектуру не хуже технических требований. Описания товаров — кнопка в
существующем интерфейсе почти всегда бьёт отдельный продукт. Протоколы
встреч — архитектуру двигают конкретные новые требования, а не мода на
технологию, начинайте с простого. Дайджест — много источников данных не
значит, что нужен RAG. И звонки продаж — то, что кажется сложным
человеку, не обязательно сложно для модели, а чувствительность данных
выясняется только вопросами, не предположениями. Вот это и есть то, что
стоит унести с сегодняшнего занятия.
