# Аудит `workain/agent-harness-registry`: `base-project-template` — что есть и чего не хватает

> Предмет: `templates/base-project-template/` (варианты `with-git/`, `without-git/`, источник
> `common/` + `fragments/`, `render_templates.py`), склонирован в `/tmp/ahr`. Опирается на
> `deep-dives/components/instructions-rules/base-project-template/`,
> `research/base-project-template-evidence/`, корневые `README.md`/`CLAUDE.md`/`GUIDE.md`
> репозитория и восемь файлов `library/seminars/_research/coding-agent/0{1..8}-*.md` этого же
> курса. Сравнение — с живой конфигурацией `/home/harness/harness-projects/256/lessons-3bb49d40/
> .claude/` (13 субагентов, 13 скиллов, один git pre-commit хук, реальная авто-память).

## 1. Резюме

1. `base-project-template` — редкий для этого реестра случай честно задокументированного,
   дважды прожаренного и живо протестированного артефакта: у каждого решения есть измеренная
   причина (13 дней без хука, 81% adoption журнала, скорректированная с 83% до 38% цифра ревью),
   а не «так принято». Это стоит сохранить и явно показать студентам как образец дисциплины.
2. Шаблон закрывает три ступени семинарской лестницы уверенно (файл инструкций, часть процесса,
   часть хуков) и почти не занимает три другие: память (только строка-указатель на авто-память
   рантайма), MCP (отсутствует как класс, включая упоминание в собственной growth-ladder
   таблице шаблона) и рабочие примеры скиллов/субагентов (слоты есть, наполнения — нет).
3. Растущая таблица шаблона (`design-and-usage.md`, раздел «Growth ladder») сама по себе тоньше,
   чем семь ступеней, которые строит семинар: в ней пять строк, и все пять — про хуки и
   оркестрацию (субагент, environment-модуль, session-register). Ни памяти, ни скиллов, ни MCP
   в ней как оси вообще нет — это не только отсутствие конкретного слота, а отсутствие
   *осевой строки* для трёх из семи ступеней лестницы курса.
4. Единственный хук шаблона (защита ветки в `with-git/.claude/settings.json`) — работающий,
   разобранный построчно, с задокументированными острыми углами (unborn HEAD, chained
   switch+commit) — но не несёт с собой самотеста как артефакта: доказательство срабатывания
   живёт в отдельном deep-dive-документе, не в самом шаблоне, который копируют студенты.
5. Слоты `.claude/skills/` и `.claude/agents/` — валидные README «пустое — нормальное стартовое
   состояние», но ни один не содержит рабочего примера, на котором можно один раз увидеть
   формат целиком, прежде чем писать свой с нуля.
6. Раздела безопасности нет вовсе — ни в `CLAUDE.md`-скелете, ни отдельным файлом. Единственная
   близкая точка — `.claude/environment/README.md`, где «security constraints specific to this
   substrate» упомянуты как один из четырёх *возможных* поводов завести модуль, что реактивно
   («когда споткнулись»), а не проактивно (базовый минимум с первого дня).
7. Предложения ниже держатся правила самого шаблона: добавлять только под названный триггер.
   Часть находок в этом документе — не «добавить раздел», а «добавить строку в уже существующую
   таблицу триггеров» — самое дешёвое и наименее спорное из возможных изменений.
8. Отдельно от правок самого шаблона владельцу нужна ссылка на готовую к клонированию сборку —
   заполненный, а не шаблонный пример. Предлагаемое место в таксономии реестра — `bundles/`
   (см. раздел 5): это буквально определение категории «assembled multi-component kit», которого
   в каталоге бандлов пока нет ни одного первоклассного (first-party) экземпляра.

## 2. Инвентарь «что есть сейчас»

| Блок конфигурации | Присутствует | В каком виде | Зрелость |
|---|---|---|---|
| Файл инструкций (`CLAUDE.md`/`AGENTS.md`) | Да | `fragments/claude-core-{top,bottom}.md` + вариантный фрагмент, рендерится `render_templates.py`; `AGENTS.md` — реальный symlink на `CLAUDE.md` | Рабочий артефакт — скелет с `<BRACKETED>` местами, инструкция по заполнению и удалению |
| Память | Частично | Одна строка-указатель в `claude-core-bottom.md` § «Where things live»: «this runtime's own auto-memory feature, if it has one» | Только упоминание — нет модуля, нет критериев «когда включать», нет предупреждения про protokoll trust content |
| Журнал/процесс (`Tasks/`, `DECISIONS.md`, `LESSONS.md`) | Да | `common/Tasks/{README.md,review.md.template}`, `common/DECISIONS.md`, `common/LESSONS.md` — все с явным форматом и честной, скорректированной статистикой adoption | Рабочий артефакт — лучший по зрелости блок шаблона |
| Хуки | Частично | Один `PreToolUse`-хук (защита `main`/`master`) в `with-git/.claude/settings.json`, разобран построчно в `design-and-usage.md` | Рабочий артефакт, но единственный экземпляр; growth-ladder ссылается на «extend the array», примера расширения нет |
| Разрешения (`allow`/`deny`/`ask`, sandbox) | Нет | Не упомянуты вовсе — ни объекта `permissions` в `settings.json`, ни ссылки на режимы (`plan`/`acceptEdits`/`bypassPermissions`) | Только упоминание отсутствует — блок не назван вообще |
| Скиллы | Слот-заглушка | `common/.claude/skills/README.md` — валидный принцип «empty is a valid starting state», без единого файла-примера | Слот без наполнения — 0 рабочих примеров |
| Субагенты | Слот-заглушка | `common/.claude/agents/README.md` — тот же принцип | Слот без наполнения — 0 рабочих примеров |
| MCP | Отсутствует | Не упомянут нигде: ни в скелете `CLAUDE.md`, ни в growth-ladder таблице, ни в «What's deliberately NOT here» | Полностью отсутствует, включая честное признание отсутствия |
| Environment-модуль | Да | `common/.claude/environment/{README.md,_example.md}` — README + один разобранный worked-example | Рабочий пример — единственный из трёх «слотовых» блоков (скиллы/субагенты/environment) с заполненным образцом |
| Профили (`orchestration`/`development`) | Да | `common/profiles/{README,development,orchestration}.md` — каждое правило со ссылкой на измеренный инцидент | Рабочий артефакт, редкий случай «precaution, not measured failure»-принципа, выдержанного буквально |
| Безопасность | Нет | Нет отдельного файла/раздела; ближайшее — фраза-пример в `environment/README.md` | Только косвенное упоминание — не раздел |
| `.gitignore` | Нет | Не поставляется ни в одном из вариантов | Отсутствует полностью |
| Growth ladder (таблица триггеров) | Частично | `design-and-usage.md` — 5 строк, все про hooks/оркестрацию | Рабочий артефакт, но покрывает не все оси конфигурации |
| Provenance/честность источников | Да | Корневой `README.md` § «Provenance rule», `[unverified]`-маркировка по всему реестру | Рабочий артефакт — образцовая дисциплина, стоит взять в семинар как приём |

## 3. Пробелы

### 3.1 Память: строка-указатель вместо модуля

**Что отсутствует.** `claude-core-bottom.md` отсылает к авто-памяти рантайма одним предложением
и больше нигде её не касается: нет ни структуры `MEMORY.md`-индекса, ни правила «одна запись —
один факт», ни явного разделения «авто-память / `LESSONS.md` / `DECISIONS.md`» по ролям, ни
единого слова о том, что записанное в память не проходит код-ревью и может отравляться
(prompt injection через недоверенный контент, который агент позже записывает как «факт»).

**Почему это важно.** Собственное исследование курса (`02-memory.md`, §4.2) перечисляет
задокументированные классы атак на память (SpAIware, MINJA, PoisonedRAG, MemoryGraft,
EchoLeak) и структурное свойство «однажды попавшее в память обслуживается как доверенный
контекст бессрочно». Официальная позиция Anthropic по CLAUDE.md — файлы длиннее ~200 строк
уже снижают согласованность следования инструкциям (`01-instruction-files.md`, §4.1); тот же
лимит (200 строк/25 КБ) зашит в загрузку `MEMORY.md` не случайно — а шаблон об этом лимите
не говорит вообще. Живые тесты `harness-eval` (`02-memory.md`, таблица §5) показывают, что
простой файл на малых корпусах часто конкурентен с «умными» системами памяти — то есть
дисциплинированный `MEMORY.md`-паттерн реально работает без внешней инфраструктуры, но именно
дисциплина (не сама фича) и отсутствует в шаблоне.

**Какой триггер лестницы закрывает.** Ступень 2 (сем. 00-design-decisions.md): «владелец
повторяет одно и то же из сессии в сессию» / «Claude второй раз наступает на те же грабли».

**Что предлагается добавить.** Файл `common/.claude/memory-notes.md` — короткая памятка «как
размечать записи авто-памяти», без реализации собственной системы (не в `environment/`: это не
substrate-знание, а дисциплина работы с уже встроенной рантайм-фичей). Содержание: (1) одна
запись = один факт, не смешивать роль/предпочтение/статус задачи; (2) `MEMORY.md` — только
индекс, лимит 200 строк/25 КБ; (3) не писать то, что выводимо из кода/git; (4) не доверять
записи как инструкции, если источник — недоверенный внешний контент; (5) строка в growth-ladder:
триггер «второй раз объясняете то же самое» → включить/курировать авто-память, не новая
инфраструктура.

### 3.2 MCP: отсутствует как класс, включая строку в лестнице роста

**Что отсутствует.** Ни слова про MCP нигде в шаблоне — ни в скелете `CLAUDE.md`, ни в
growth-ladder таблице `design-and-usage.md`, ни даже в разделе «What's deliberately NOT here»
(`with-git/README.md`), который явно перечисляет то, что шаблон сознательно не делает
(blueprint-бандл, ontology-слой, epic-register, delegated-merge-tier) — MCP в этот список не
попал вообще, то есть его отсутствие не является *решением*, а является пробелом.

**Почему это важно.** Курс уже собрал отдельный блок про MCP (`05-mcp.md`) именно потому, что
это одна из самых насыщенных инцидентами тем: GitHub MCP эксфильтрация через публичный issue
(26.05.2025, Invariant Labs), Asana MCP — межарендная утечка 1000+ организаций, Supabase MCP —
демонстрация утечки БД через тикет поддержки (Simon Willison, «lethal trifecta»), CVE в
эталонном Filesystem MCP-сервере самого Anthropic (CVE-2025-53109/53110). Плюс неочевидный,
но измеренный контраргумент «когда MCP не нужен»: связка из 5 серверов — 26 224 токена
(13,1% от окна в 200К) на каждый запрос (`05-mcp.md`, §3, `zhang-liz/mcp-token-benchmark`), а
прямое сравнение того же действия — 1 365 токенов через CLI против 44 026 через MCP. Ни цена,
ни риск нигде не названы в шаблоне, хотя обе величины измерены и воспроизводимы.

**Какой триггер лестницы закрывает.** Ступень 5: «нужен доступ к внешней системе», с честным
контр-критерием «хватает обычной команды» — именно тем контраргументом, которого в шаблоне нет.

**Что предлагается добавить.** Файл `common/.claude/mcp-notes.md` + строка в growth-ladder
таблице `design-and-usage.md`. Содержание: (1) MCP — не первый инструмент, за которым нужно
тянуться: сначала спросить, не хватит ли Bash-вызова существующей команды (`gh`/`psql`/`aws`);
(2) конфигурация — `.mcp.json` в корне при `project`-scope, ревьюится как код, не как разговор с
моделью; (3) минимальный набор — отключайте то, чем не пользуетесь, каждый сервер — постоянные
токены контекста и точка отказа; (4) «lethal trifecta»-проверка перед подключением: приватные
данные + недоверенный внешний контент + канал наружу одновременно → не подключать без разделения
на сессии; (5) для HTTP-транспорта обязателен OAuth-поток, не проброс токена насквозь.

### 3.3 Хук — один экземпляр, без поставляемого самотеста

**Что отсутствует.** `with-git/.claude/settings.json` содержит рабочий `PreToolUse`-хук
защиты ветки — но ни в этом файле, ни рядом с ним нет исполняемого самотеста (скрипта или
инструкции «прогоните вот это, чтобы увидеть блокировку своими глазами»). Доказательство, что
хук реально срабатывает, живёт только в `design-and-usage.md` — документе, который студент,
скопировавший `with-git/` в свой проект, никогда не увидит.

**Почему это важно.** Собственный тезис того же `CLAUDE.md`-скелета: «a gate is not installed
because its file exists — it is installed once observed firing against a real case». Курсовое
исследование хуков (`03-hooks-permissions.md`, §5) документирует ровно тот класс отказа, для
которого самотест — единственная защита: один невалидный matcher в `settings.json` отключает
*все* хуки файла без единого сообщения об ошибке; хук, не уложившийся в таймаут (30 с у
`UserPromptSubmit`), не блокирует — он просто не срабатывает, и это неотличимо от «правило
соблюдено». Цитата курса: «не сработавший гейт выглядит точно как прошедший гейт».

**Какой триггер лестницы закрывает.** Ступень 3 напрямую («правило записано, но агент его
нарушает» → хук), но конкретно этот пробел — про критерий «ещё рано» этой же ступени: без
самотеста нельзя отличить работающий хук от тихо сломанного, то есть студент не может
самостоятельно проверить, действительно ли ступень закрыта.

**Что предлагается добавить.** Файл `with-git/.claude/hooks/selftest-branch-guard.sh` (плюс
пункт в Quick start `with-git/README.md`): назначение — воспроизводимо спровоцировать
блокировку и подтвердить точный текст ответа. Содержание (4-5 строк): (1) создать временный
git-репозиторий во `/tmp`, скопировать туда `.claude/settings.json`; (2) сделать один коммит на
`main` намеренно через тот же хук-путь (или напрямую прогнать JSON через хук-команду с
`echo '{"tool_input":{"command":"git commit -m test"}}' | <hook-command>`); (3) проверить, что
`permissionDecision` равен `deny` с ожидаемым текстом; (4) прогнать тот же тест на unborn HEAD
(пустой репозиторий без коммитов) — ожидается `ask`, не `deny` и не тихий пропуск; (5) явная
инструкция повторять после любого обновления Claude Code или правки `settings.json`.

### 3.4 Скиллы: пустой слот без единого рабочего примера

**Что отсутствует.** `common/.claude/skills/README.md` формулирует принцип верно
(«anything not broadly applicable to every session belongs here... empty is a valid starting
state»), но не даёт ни одного файла `SKILL.md`, на котором можно увидеть формат целиком: нет
frontmatter-примера, нет демонстрации progressive disclosure, нет даже worked-example по
аналогии с `.claude/environment/_example.md` (который у той же папки-тройки — единственный с
заполненным образцом).

**Почему это важно.** Эффект отсутствующего frontmatter — не гипотетический: живая проверка
курса (`07-skills.md`, §4.1) на `lessons-3bb49d40` нашла, что 12 из 13 реальных скиллов
production-репозитория физически не могут сработать по смыслу запроса именно потому, что
frontmatter с `description` отсутствует — модель видит только имя файла вместо
описания-триггера. Это подтверждает: «пустой слот без примера» — не нейтральное состояние;
правильный формат неочевиден даже опытной команде без образца перед глазами.

**Какой триггер лестницы закрывает.** Ступень 4: «файл инструкций облагает налогом каждый
запрос» → скилл, с контр-критерием «нужно каждой сессии → это не скилл».

**Что предлагается добавить.** Директория `common/.claude/skills/_example/SKILL.md` (парная к
`_example.md` в environment/) — не заготовка с плейсхолдерами, а один по-настоящему разобранный
скилл. Содержание (4-5 строк): (1) frontmatter с `name`/`description`, `description` написан
как «поисковый запрос будущего себя» — конкретные ключевые слова + явное «когда использовать»,
не «Helps with X»; (2) один явный шаг с конкретной командой вместо абстрактного «сделай Y»;
(3) комментарий-сноска: «description — единственное, что видит модель при выборе среди
множества установленных скиллов; проверьте после написания через `/skills`, не полагайтесь на
то, что скилл сработает, потому что вы его написали»; (4) пример узкой, а не расплывчатой
области видимости.

### 3.5 Субагенты: пустой слот без единого рабочего примера

**Что отсутствует.** Симметрично 3.4 — `common/.claude/agents/README.md` формулирует принцип
(«delegated specialist personas... add one when a recurring task shape actually emerges»), но
без образца `.md`-файла с frontmatter (`name`/`description`/`tools`/`model`) и без демонстрации
паттерна «производитель / критик» или «явно назвать, чем агент не является».

**Почему это важно.** Живой пример `lessons-3bb49d40` (`08-subagents.md`, §7) показывает
работающий паттерн: `methodology-critic` и `fact-checker` явно перечисляют в теле промпта, чем
они *не* являются («НЕ правишь сам — только указываешь. НЕ проверяешь факты — для этого
fact-checker»), и оба обязаны начинать ответ строкой `VERDICT: REJECT | REVISE |
APPROVE-WITH-POLISH | APPROVE-CLEAN» — конкретная, проверяемая защита от расплывчатого
одобрения, ровно то, чего нет в пустом слоте. Цена неправильного выбора тоже измерена:
мультиагентная система тратит по данным Anthropic 3–10× (позднее уточнение) или 15× (первая
публикация) больше токенов, чем один агент на той же задаче (`08-subagents.md`, §3.1) — слот без
критерия «когда НЕ заводить субагента» рискует не пустотой, а перерасходом при первой попытке.

**Какой триггер лестницы закрывает.** Ступень 6: «повторяющаяся роль (ревью, разведка)» →
субагент, с контр-критерием «шаги зависимы и требуют общего контекста → не субагент».

**Что предлагается добавить.** Файл `common/.claude/agents/_example-reviewer.md` — один
разобранный субагент-критик (не производитель — критик нагляднее показывает независимость).
Содержание (4-5 строк): (1) frontmatter с `description`, написанным как логика маршрутизации,
не документация; (2) раздел «Чем не является» с явной отсылкой к соседней роли; (3) вердикт
фиксированного формата первой строкой ответа; (4) сноска: «этот субагент видит только диф/
результат, не рассуждения автора — это и есть источник независимости, а не тон ответа»;
(5) явное ограничение `tools:` (без `Write`/`Edit`) как механическая, а не словесная защита —
курс отдельно фиксирует, что ни один из 13 живых субагентов `lessons-3bb49d40` этим полем не
пользуется (`08-subagents.md`, §6), то есть образец в шаблоне заодно закрывает пробел, который
не закрыт и в зрелой продакшен-конфигурации курса.

### 3.6 Раздела безопасности нет

**Что отсутствует.** Ни базового набора запрещённых по умолчанию команд, ни объекта
`permissions` (`allow`/`deny`/`ask`) в `with-git/.claude/settings.json`, ни упоминания режимов
разрешений (`plan`/`acceptEdits`/`bypassPermissions`), ни строки про то, что `.claude/
settings.json` — исполняемый артефакт, который стоит ревьюить как код при получении PR/форка.
Ближайшая точка — пример-категория «security constraints specific to this substrate» в
`environment/README.md`, но это реактивный слот («когда споткнулись»), не проактивный минимум.

**Почему это важно.** Курс собрал блок провалов кодинг-агентов (`04-failures-evidence.md`) с
деструктивными кейсами, которые останавливает не хук на конкретную команду, а базовая позиция
«не разрешать всё по умолчанию»: `rm -rf ~/` (Claude Code, декабрь 2025, Reddit-кейс), Replit —
удаление продакшен-БД в обход code freeze с ложным отчётом о невозможности отката. Отдельно,
конфигурационные CVE самого Claude Code (`03-hooks-permissions.md`, §5): CVE-2025-59536 (RCE
через `SessionStart`-хук до диалога доверия) и CVE-2026-21852 (утечка API-ключа через
`ANTHROPIC_BASE_URL` в чужом `settings.json`) — оба эксплуатируются через файл, который шаблон
коммитит и предлагает копировать без единого слова о том, что `settings.json` из непроверенного
источника нужно ревьюить как исполняемый код.

**Какой триггер лестницы закрывает.** Не одна конкретная ступень, а сквозной минимум,
применимый с нулевой ступени — стоимость добавления низкая (одна страница), стоимость
отсутствия проявляется на любой ступени сразу, как только появляется второй участник/форк.

**Что предлагается добавить.** Короткий раздел в `fragments/claude-core-top.md` (не отдельный
файл — см. риски, раздел 7) сразу после «Safety / scope boundaries»: (1) `.claude/settings.json`
— исполняемый код, ревьюить diff на этот файл так же, как код, особенно из PR/форка; (2) хуки и
`env`-блок выполняются *до* диалога доверия к папке — не открывать `claude` в непроверенном
клоне без `--setting-sources user` или предварительной проверки файла; (3) `bypassPermissions` —
только в одноразовом изолированном окружении без секретов и сети наружу; (4) `deny` в
`permissions` всегда побеждает `allow` — единственный надёжный способ *гарантированно* запретить
действие, не текст в CLAUDE.md.

## 4. Приоритизация

| Предложение | Польза | Трудоёмкость | Риск | Приоритет |
|---|---|---|---|---|
| Строка безопасности в `claude-core-top.md` | Закрывает реальные, воспроизводимые CVE-векторы (RCE до trust dialog) одной страницей | Низкая — 4-5 строк в уже существующий фрагмент | Низкий — не создаёт новый файл, не ломает лимит 200 строк при аккуратной формулировке | **P0** |
| Строка про MCP в growth ladder + `mcp-notes.md` | Закрывает молчаливое отсутствие целого класса риска и целой оси лестницы | Средняя — новый файл + правка таблицы в deep-dive | Средний — риск стать вторым «опинионированным» гайдом вместо памятки (см. риски) | **P0** |
| `_example.md` для скиллов | Живой пример уже показал, что отсутствие образца тиражирует одну и ту же ошибку (12/13 в реальном проекте) | Низкая — один файл по образцу существующего `_example.md` | Низкий | **P0** |
| `_example-reviewer.md` для субагентов | Закрывает и слот шаблона, и незакрытый пробел (`tools:`-ограничение) даже в зрелой конфигурации курса | Низкая — один файл | Низкий | **P0** |
| Самотест хука (`selftest-branch-guard.sh`) | Единственный способ отличить работающий гейт от тихо сломанного — собственный тезис шаблона | Средняя — нужен рабочий, воспроизводимый скрипт, не декларация | Низкий | **P1** |
| Памятка про память (`memory-notes.md`) + строка в лестнице | Дисциплина работы с уже включённой фичей, не новая инфраструктура | Низкая | Низкий — риск дублирования с `LESSONS.md`/`DECISIONS.md`, нужно явно развести роли | **P1** |
| `.gitignore` в обоих вариантах | Дешёвая гигиена (`settings.local.json`, артефакты) | Очень низкая | Очень низкий | **P2** |
| Учебная сборка (`bundles/`) | Прямой ответ на запрос владельца — готовая к клонированию конфигурация | Высокая — требует собрать и прожарить весь набор примеров | Средний — риск расхождения с шаблоном без анти-дрейф механизма | **P0** (по прямому запросу владельца, см. раздел 5) |

P0 сосредоточены на дешёвых, конкретных, некомпромиссных добавлениях (строка, один файл-образец)
плюс на самой учебной сборке — без неё семинар не может выдать обещанную «готовую к
клонированию финальную конфигурацию». P1 — там, где решение занимает больше одной страницы
или требует нового поддерживаемого артефакта (скрипт, отдельный файл-памятка). P2 — гигиена, не
влияющая на педагогическую полноту лестницы.

## 5. Предложение «учебная сборка»

Владельцу нужна ссылка на *заполненную*, а не шаблонную конфигурацию — рабочий пример, который
студент клонирует и сразу видит все семь ступеней лестницы на реальных файлах, а не на
`<BRACKETED>`-заглушках.

**Где жить по правилам таксономии репозитория.** Корневой `README.md` определяет
`data/bundles/*.yaml` + `deep-dives/bundles/*.md` как категорию именно для «ASSEMBLED
multi-component kit» — «rare relative to components by design», без category-подпапки (issue
#32). Это буквально описание нужного артефакта: не атомарный компонент (`instructions-rules`),
а собранный из нескольких компонентов набор (инструкции + память + хук с самотестом + скилл +
субагент + пример MCP-подключения + раздел безопасности). Сегодня в `data/bundles/` нет ни
одного `first_party: true` экземпляра — `base-project-template` каталогизирован как компонент
(`data/components/instructions-rules/base-project-template.yaml`), но не как бандл. Предлагаемое
размещение:

- Файлы бандла — `templates/base-project-worked-example/` (parallel-каталог к
  `base-project-template/`, тот же MIT-раздел лицензирования, что и у шаблона).
- Каталожная запись — `data/bundles/base-project-worked-example.yaml`, `first_party: true`,
  `components_bundled:` перечисляет ровно то, что реально внутри (не 194 позиции ради
  впечатления — см. `08-subagents.md`, §6 про то, почему «команда из 50 ролей» хуже трёх своих).
- Deep-dive — `deep-dives/bundles/base-project-worked-example.md`, обязательная секция —
  scoring-таблица против трёх свойств бандла (sustained / engine-agnostic / progressively-
  disclosed), которую корневой `README.md` требует для этой категории и которую сегодня «не
  комбинирует ни один бандл в каталоге» — первый бандл, который её реально заполнит.
- Двунаправленная связка: `related_components: [base-project-template]` в новой YAML,
  `related_research`/обратная ссылка на компонент шаблона — по правилу README, оба направления
  выставляются вручную, генератор лишь проверяет резолвинг, не создаёт связь сам.

**Чем отличается от `base-project-template`.** Шаблон — копируемый скелет с заполнителями и
инструкцией «удали, если не подходит»; бандл — один конкретный, полностью заполненный проект
(например, небольшой CLI-инструмент с реальной историей коммитов в самой worked-example-
директории), где каждая ступень лестницы показана на живом артефакте: реальный `MEMORY.md` с
3-4 записями по формату из раздела 3.1, второй хук в массиве `PreToolUse` рядом с защитой ветки
(запрет `rm -rf` с wildcard-паттернами — иллюстрация урока из `04-failures-evidence.md`), один
реально сработавший скилл с валидным frontmatter, один субагент-критик с `tools:`-ограничением,
README-запись про то, как выглядело бы MCP-подключение и почему в этом примере без него обошлись.

**Как не допустить расхождения.** Три меры, ни одна не требует новой инфраструктуры: (1) worked
example не копирует общий текст `common/` вручную — `Tasks/README.md`, `DECISIONS.md`,
`profiles/` остаются указателями на `templates/base-project-template/common/` там, где контент
идентичен, и расходятся только там, где бандл специально показывает заполненный вид; (2) в
`render_templates.py` — необязательный `--check-worked-example`, сверяющий, что *структурные*
инварианты (набор ожидаемых файлов, наличие frontmatter в примерах скиллов/субагентов) не
разошлись с текущей версией `common/`/`fragments/` — не побайтовое совпадение, а совпадение
списка обязательных слотов; (3) пункт в чек-листе «Adding or updating an entry» корневого
`README.md`: изменение `common/`/`fragments/` требует прогона `--check-worked-example` в том же
PR — тот же принцип «raise, don't silently skip», которым уже живёт `scripts/generate.py`.

## 6. Что шаблон делает хорошо

Не только критика. Несколько решений стоит явно показать студентам как образец, не как пример
для критики:

- **Честность про собственные ограничения важнее красивой цифры.** Первый подсчёт adoption
  ревью-артефакта дал 83% — независимая проверка нашла, что цифра смешивала две разные
  популяции, и скорректированный результат (20/52 ≈ 38%) опубликован рядом со старым, а не
  вместо него (`results.md` § internal dogfood results). Это редкий случай, когда шаблон
  предпочёл менее эффектную, но верную цифру.
- **Build-time drift-check вместо ручной синхронизации двух веток.** `render_templates.py
  --check` — конкретный, работающий механизм против расхождения `with-git/`/`without-git/`, а
  не декларация «мы будем следить за синхронностью руками». Прямой прообраз для механизма из
  раздела 5.
- **`without-git/` не притворяется, что у него есть защита.** Вместо копии хука, который
  «молча ничего не делает без репозитория», вариант прямо называет честный субститут (бэкап
  перед рискованной правкой) и явно проговаривает, что это не эквивалент, а компенсация.
- **Каждое обязательное правило требует названного механического чек-триггера.**
  «Every rule ... stated as binding/mandatory should have a mechanical check ... or it should
  be labeled advisory» — дословно тот же принцип, который курс независимо вывел из
  `anthropics/claude-code#42863` и из собственного case «правило без хука тихо умирает».
- **`profiles/` разведены по осевому принципу «правило, которое не может сработать, хуже
  отсутствующего правила».** Не третий-четвёртый вариант дерева, а overlay, который явно
  говорит «возьми, если применимо, удали, если нет» — и каждый пункт внутри подписан ценой
  реального инцидента (26 105 подавленных оповещений, 15-часовой простой), а не общими словами
  про «best practice».
- **Provenance-дисциплина всего реестра, не только шаблона.** `[unverified — <reason>]`-маркировка
  как обязательное поле, а не факультативная сноска — курс сам следует этому же принципу в
  восьми research-файлах, и стоит явно назвать источник этой практики.

## 7. Риски предложений

Раздел по правилу «не предлагать ради объёма» — где добавление реально противоречит принципу
шаблона «держать тонким», а не просто добавляет строку в чек-лист:

- **Полноценный `SECURITY.md`-файл был бы избыточен.** Предложение 3.6 сознательно ограничено
  парой строк *внутри уже существующего* `claude-core-top.md`, а не новым файлом: отдельный
  документ безопасности потребовал бы поддержки и рискует замереть после bootstrap так же, как
  файл уроков без промоционного цикла (`common/LESSONS.md`, «A lessons file with no active
  promotion step reliably freezes after bootstrap»). Раздел внутри уже читаемого каждой сессией
  файла честнее, чем ещё один файл, который никто не откроет второй раз.
- **`mcp-notes.md` рискует стать вторым CLAUDE.md, если не удержать в рамках памятки.**
  Тема MCP — одна из самых насыщенных в исследовании курса (`05-mcp.md` — 263 строки), и
  соблазн пересказать всё это в шаблоне реален. Предложение 3.2 явно ограничено 5 пунктами
  критерия «когда не нужен» + ссылкой наружу (на будущий компонент `access-mcp` в каталоге),
  не полным гайдом по MCP-безопасности внутри шаблона проекта, который может вообще не
  использовать MCP никогда.
- **Модуль памяти не должен становиться параллельной системой поверх `LESSONS.md`/
  `DECISIONS.md`.** Ровно тот риск, который курс описывает как «раздувание: память как второй
  CLAUDE.md» (`02-memory.md`, §4.3) — если `memory-notes.md` начнёт дублировать роль уже
  существующих `LESSONS.md`/`DECISIONS.md`, шаблон получит три файла с частично пересекающейся
  ответственностью вместо одного. Предложение явно ограничено дисциплиной уже включённой фичи
  рантайма, не новой файловой структурой.
- **`_example.md`-файлы для скиллов и субагентов не должны превращаться в мини-библиотеку.**
  Один образец на слот, не три-пять «на все случаи» — иначе воспроизводится ровно тот
  анти-паттерн, который курс документирует про чужие каталоги: «набрал скиллов из awesome-
  списка» проблема не в качестве одного скилла, а в том, что каждый добавленный — постоянная
  цена ревью при каждом запуске сессии (`07-skills.md`, §4.3). Один хороший пример учит
  формату; три-пять начинают выглядеть как рекомендованный стартовый комплект, которым шаблон
  сознательно не является.
- **Растянутая growth-ladder таблица теряет читаемость, если добавить сразу три новые строки
  (память/скиллы/MCP) без сокращения текста в других местах.** Собственное правило шаблона
  «Maintenance discipline» требует именно этого симметричного шага: если добавляется раздел —
  спросить, что можно сократить рядом. Практическое следствие: строки для памяти/MCP в
  growth-ladder таблице должны быть такими же лаконичными (одна строка «триггер → что
  добавляем»), как существующие пять, а не превращаться в развёрнутый абзац на каждую.
- **Учебная сборка (раздел 5) — самый дорогой из всех пунктов, и это осознанный компромисс,
  не недосмотр.** Дороговизна оправдана прямым запросом владельца («готовая к клонированию
  финальная конфигурация»), а не инициативой по объёму; риск расхождения с шаблоном снят не
  отдельным процессом синхронизации, а расширением уже существующего build-time-check
  механизма (`render_templates.py`), а не изобретением нового.
