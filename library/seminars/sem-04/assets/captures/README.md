это явно помечено в самом файле.

**Важно про числа.** Число строк в `CLAUDE.md` и состав дерева берутся из репозитория командой, а
не со слайда. Если репозиторий изменится, первым правится захват, потом слайд — не наоборот.

Деревья снимаются через `git ls-tree -r --name-only <SHA> | LC_ALL=C sort`, а не `find`/`tree`
(`tree` в окружении нет: `tree: command not found`). `LC_ALL=C` фиксирует порядок сортировки —
без него точечные файлы (`.gitignore`) встают в разное место в разных локалях. Каждый файл
заканчивается комментарием «что здесь видно и чего здесь намеренно нет».

## Провенанс слайдов, у которых захвата нет

Не всякая оговорка `visual.backup` опирается на файл в этой папке — часть слайдов ссылается на
коммит напрямую, потому что команда в тексте оговорки и есть способ проверки:

- **s27** (кейс 1.3) — дерево снято с `ffbb258`: три файла в `tests/`, объект страницы,
  `submitForm()` с одним повтором. Захвата под него нет намеренно: дерево `ffbb258` отличается от
  `21-tree-stage1.txt` только подросшим `tests/`, а команда приведена прямо в оговорке слайда.
- **s34** — иллюстративная сортировка карточек; в репозитории зафиксирована только та карточка,
  что стала записью (`94c5378`).
- **s43**, **s39**, **s52** — содержимое иллюстративное, это сказано на самих слайдах.
