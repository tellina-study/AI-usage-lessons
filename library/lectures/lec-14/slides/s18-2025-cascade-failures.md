# Октябрь–ноябрь 2025: три каскада за 30 дней

## Visible content

3 карточки:
• Cloudflare (18.11.2025, 5ч 38мин — основной трафик восстановлен ~3ч 10мин):
  - Изменение database permission в ClickHouse
  - Дубли в feature file → превышен лимит 200 фич
  - Memory limits в proxy fleet → крах Bot Management
  - ChatGPT, X, Spotify, тысячи SaaS — недоступны
  Урок: «Не DNS. Конфиг распространился автоматически и сломал core traffic.»

• AWS DynamoDB (20.10.2025, ~15 часов):
  - Детерминированная race condition в DNS-автоматике
  - Гонка Planner ↔ Enactor в us-east-1
  - AWS post-mortem НЕ называет AI причиной
  - Эффект: RDS, Lambda, EC2, кэши в us-east-1
  Урок: «Это классический сбой автоматизации, не AI. Не путать с Amazon Kiro Dec 2025.»

• Azure Front Door (29.10.2025, ~8 часов):
  - Канарейка не сработала
  - Сигналы канарейки шли через тот же сломанный слой
  - Microsoft 365 + Xbox + Azure сервисы — деградация
  - Пост-мортем: «слепое пятно мониторинга»
  Урок: «Канарейка без независимого канала наблюдения — фиктивная канарейка.»

> ⚠ Разграничение: **AWS 20.10.2025 — это DNS race condition, НЕ AI** (post-mortem AWS не атрибутирует AI). Отдельный AI-инцидент Amazon Kiro в декабре 2025 (по отчёту Financial Times) — другое событие, не путать.

## Speaker notes

Октябрь и ноябрь 2025 — за тридцать дней три крупных каскадных сбоя. Это не случайность, это закономерность. Все три — на уровне «Действует» лестницы автономии.

Cloudflare восемнадцатого ноября. Стартовало с изменения database permission в ClickHouse — внутреннее изменение, не клиентское. Запрос для построения feature file Bot Management начал возвращать дубликаты строк. Из-за дублей feature file превысил жёсткий лимит 200 фич. Прокси-флот наткнулся на memory limits, Bot Management начал крашиться. И поскольку Cloudflare обслуживает огромную часть мирового HTTP-трафика — каскад. ChatGPT, X, Spotify, тысячи SaaS-сервисов — все недоступны или деградированы. Полное восстановление пять часов тридцать восемь минут, основной трафик восстановлен примерно через три часа десять минут.

Важно: это НЕ DNS-сбой, как часто пишут в популярной прессе. Это конфиг-каскад через Bot Management. Постмортем Cloudflare: классическая «config — не code» mentality, автоматический деплой обращался с конфигом как с кодом, но без той же дисциплины тестирования.

AWS DynamoDB двадцатого октября. Детерминированная race condition в DNS-автоматике DynamoDB — гонка между компонентами Planner и Enactor в регионе us-east-1. Это самый «load-bearing» регион AWS — половина SaaS-индустрии зависит от него. Важно: AWS post-mortem НЕ называет AI причиной. Это классический сбой автоматизации, не AI-assisted deployment. AI-attribution относится к ОТДЕЛЬНОМУ инциденту — Amazon Kiro в декабре 2025 года, по FT-отчёту на leaked internal documents. Не путайте эти два события.

Azure Front Door двадцать девятого октября. Самый поучительный пример. Microsoft развернул изменение через канареечный деплой — то есть на маленький процент трафика сначала. Сигналы канарейки выглядели нормально. Раскатали на сто процентов — и упало. Причина: сигналы canary шли через тот же сломанный слой, который тестировался. То есть канарейка была фиктивной. Постмортем: «слепое пятно мониторинга». Восемь часов восстановления. Microsoft 365, Xbox, Azure сервисы — деградация.

Главный урок: на уровне «Действует» канареечный деплой работает только когда сигналы независимо наблюдаются — через отдельный канал, через отдельный data plane. Иначе это театр канарейки.
