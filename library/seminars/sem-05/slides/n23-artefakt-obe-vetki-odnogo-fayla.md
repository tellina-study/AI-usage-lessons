# Обе ветки одного файла

## Assertion

Один хук закрывает две клетки сразу: на защищённой ветке он запрещает, а там, где репозитория нет, спрашивает — и причина отказа видна агенту только при запрете.

## Visual

```json
// ветка 1 — репозитория нет вовсе
if ! git rev-parse --is-inside-work-tree; then
  "permissionDecision": "ask",
  "permissionDecisionReason":
     "WARNING: branch-protection gate inactive —
      this is not a git repository yet …"

// ветка 2 — мы на защищённой ветке
if [ "$branch" = "main" ] || [ "$branch" = "master" ]; then
  "permissionDecision": "deny",
  "permissionDecisionReason":
     "BLOCKED: direct commit to main/master.
      Create a feature branch first."
```

| Поле решения | Что делает |
|---|---|
| `"deny"` | вызов не происходит |
| `"ask"` | спрашивает человека, **даже** в режиме без диалогов |
| `"allow"` | пропускает без вопроса |
| поля нет вовсе | решения нет — обычный порядок разрешений, а **не** «разрешено» |

> Если хуков несколько и ответили они по-разному, приоритет такой: **`deny` > `defer` > `ask` > `allow`**.
> Причина при `deny` видна **агенту**. При `allow` и `ask` — **человеку, но не агенту**. Значит, текст отказа — единственный способ объяснить агенту, что он сделал не так.

## Speaker notes

Один файл, два решения. Не два хука — один, потому что ситуации разные.

Первая ветка: репозитория нет вовсе. Решение — спросить. Мы это разбирали: тихо разрешить здесь означало бы изобразить защиту, которой нет.

Вторая: мы на защищённой ветке. Решение — запретить, с текстом причины.

Таблица полей. Три решения плюс важная четвёртая строка: если поля нет совсем — это не «разрешено». Это «решения нет, идите обычным порядком разрешений». Разница видна тогда, когда рядом стоит правило, которое и так бы спросило.

Обратите внимание на вторую строку: «спросить» работает даже в режиме без диалогов подтверждения. Тот самый режим из нашей сцены — он не отменяет вопрос от хука.

Приоритет, если хуков несколько и ответили они по-разному: запрет сильнее всего, разрешение слабее всего. Личный и проектный хук сработают оба, и запрет одного перебьёт разрешение другого.

И последняя строка, самая практичная. При запрете причина видна агенту — он её прочитает. При разрешении и вопросе причина видна только человеку. Отсюда прямое следствие: текст отказа — это не украшение и не журнал, это единственный канал, которым вы объясняете агенту, что он сделал не так. Писать `BLOCKED` без объяснения — значит потратить единственный доступный канал впустую.
