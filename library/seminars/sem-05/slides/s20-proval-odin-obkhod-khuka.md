# Девять прошли, пять промолчали

## Assertion

Самотест ровно этого хука печатает 9 PASS и 5 LIMIT: пять форм одной и той же команды проходят мимо барьера молча — не из-за небрежности паттерна, а потому что оболочка раскрывает слова уже после того, как хук принял решение.

## Visual

**Реальный прогон `.claude/hooks/selftest-branch-guard.sh`: 9 PASS / 5 LIMIT / 0 FAIL.**

| Форма команды | Должна давать `deny` | Что происходит |
|---|---|---|
| `git commit -m "..."` на `main` (эталон) | ✓ | Срабатывает |
| Дефолтная ветка названа не `main`/`master` (напр. `trunk`) | ✓ | Проходит молча |
| `git -C <path> commit -m "..."` | ✓ | Проходит молча |
| `/usr/bin/git commit -m "..."` | ✓ | Проходит молча |
| `env git commit -m "..."` | ✓ | Проходит молча |
| `git commit` на второй строке многострочной команды | ✓ | Проходит молча |

Почему не лечится расширением списка: оболочка раскрывает слова и алиасы **после** того, как хук уже принял решение по тексту.

Вывод: хук на `Bash` — фильтр на синтаксис одной команды в нераскрытой текстовой форме, не на намерение и не на финальную исполняемую форму.

## Speaker notes

У этого хука есть самотест, он лежит в том же репозитории. Реальный прогон: девять проверок прошли, ни одной провальной — и сам скрипт напечатал пять случаев, где ворота молчат. Дефолтная ветка названа не `main`/`master`. Путь перед `git`. Обёртка `env`. Флаг рабочей директории. Команда не в первой строке. Сработала только та форма, что уже показана как эталон. Остальные пять прошли молча.

Два дополнительных случая молчания зафиксированы тем же файлом самотеста: хук, превысивший заданный тайм-аут, не блокирует — он просто не успевает; отсутствующий в системе `jq` даёт тот же тихий отказ, что и намеренный обход.

И это не потому, что паттерн написан небрежно, — это потому, что задача написать паттерн, ловящий все формы одной команды, структурно невыполнима. Оболочка раскрывает слова и алиасы непосредственно перед выполнением — то есть уже после того, как хук принял решение по тексту. Хук физически не может увидеть финальную развёрнутую форму команды раньше, чем она выполнится. Тот же класс grep-хука защиты ветки независимо воспроизведён внешним адверсариальным тестом на другом проекте — четырьмя разными формами одной команды, не как гипотеза, а как подтверждающий, второй по счёту прогон.

Практический вывод — не паника: не гоняться за каждой новой найденной формой обхода, это гонка с отрицательным исходом — пространство синтаксических форм одной shell-команды больше, чем можно перечислить. Вместо неё — платформенный барьер, не зависящий от текста вообще, и узкий хук, ограниченный перечислимым списком заведомых попыток отключить защиту: флаг, пропускающий проверки при коммите, манипуляция путём к каталогу хуков, переменные окружения хук-менеджеров. Такой список можно довести до полноты — в отличие от синтаксиса git.

Для слайда это значит одно: хук на `Bash` — фильтр на синтаксис одной команды в её нераскрытой текстовой форме, а не на намерение и не на финальную исполняемую форму той же команды. Для действительно чувствительного действия одного текстового фильтра недостаточно — нужен слой, не зависящий от текста вообще.
