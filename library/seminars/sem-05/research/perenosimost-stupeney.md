# Переносимость пяти ступеней

Все проверки — **1 октября 2026**. Везде, где ниже стоит «не нашёл» или «не проверял», это
означает именно это, а не «вероятно нет». Первоисточники — документация поставщиков и тексты
спецификаций; вторичные обзоры помечены отдельно и ни одно утверждение на них не держится.

## 1. Короткий ответ владельцу

Надежда оправдана **не полностью, но сильнее, чем выглядит из предварительного ответа**.
Картина смешанная, и ломается она не по линии «один открытый против четырёх вендорских»,
а по линии **что именно стандартизовано**:

| Ступень | Приём | Реализация | Открытая спецификация |
|---|---|---|---|
| **MCP** | общий | общая | **да** — Linux Foundation, ревизия `2026-07-28` |
| **Скилл** | общий | **общая** | **да** — Agent Skills, `agentskills.io` |
| **Процесс** | общий | механизма нет вовсе | не нужна (обычные файлы); для входного файла — `AGENTS.md`, Linux Foundation |
| **Хук** | общий | **расходится**, но три поставщика читают наш формат | **нет** |
| **Субагент** | общий | **расходится** (markdown против TOML) | **нет** |

**Переносимы по-настоящему три ступени из пяти, не одна.** Две остаются вендорскими —
и у одного популярного агента (Aider) трёх из пяти механизмов нет вообще ни в каком виде.

## 2. Проверка предварительного ответа: где он верен, где нет

Предварительный ответ: «MCP открыт; процесс переносится полностью; хук, скилл и субагент —
приём общий, реализация вендорская».

- **MCP — верно**, и даже сильнее, чем сказано (§3.3).
- **Процесс — верно** (§3.5), с одной поправкой: у «входного файла инструкций» переносимость
  тоже стала стандартом, `AGENTS.md`, и в нашем демо-репозитории он уже есть симлинком.
- **Хук — верно по сути, но заметно пессимистично** (§3.1). Спецификации действительно нет.
  Но **Cursor, Codex CLI и GitHub Copilot читают имя события `PreToolUse` и формат ответа
  Claude Code**, причём Cursor читает прямо файл `.claude/settings.json`. Это не стандарт,
  это сходимость вокруг реализации одного поставщика — и для зала это другой по смыслу ответ.
- **Субагент — верно** (§3.4). Формат расходится принципиально: markdown + YAML у одних,
  TOML у Codex.
- **Скилл — неверно.** Это главная поправка. **Скилл — открытый стандарт с 18 декабря
  2025 года**, спецификация опубликована отдельно от Anthropic, её читают более сорока
  агентов, и **ровно наш файл работает в них без переписывания** (§3.2). Утверждать на
  занятии, что скилл вендорский, было бы ошибкой.

Итог: ошибка предварительного ответа — одна, и она в сторону недооценки.

## 3. Разбор по ступеням

### 3.1. Хук

**Приём или реализация.** Приём общий: «среда сама запускает команду в заданный момент».
Он есть у Claude Code, Cursor, Codex CLI, GitHub Copilot, Gemini CLI, Windsurf (Cascade),
Cline. У **Aider его нет совсем**. Реализация у каждого своя.

**Открытая спецификация — нет.** Ближайший кандидат, **Agent Plugins 1.0.0** (бывший
Open Plugins; вендор-нейтральный, технический комитет из Amazon, Cursor, Microsoft, OpenAI,
Vercel), стандартизует **только скиллы и серверы MCP**. Хуков в нём нет
([agent-plugins.org](https://agent-plugins.org/), проверено 2026-10-01). Вторичные обзоры
называют хуки планом будущих версий — на сайте самого стандарта такого списка я не нашёл.

**Чем привязано — по четырём осям:**

| Ось | Claude Code | Cursor | Codex CLI | Copilot | Gemini CLI | Windsurf/Cascade | Cline |
|---|---|---|---|---|---|---|---|
| Файл | `.claude/settings.json` | `.cursor/hooks.json` **+ читает `.claude/settings.json`** | `.codex/hooks.json` или `[hooks]` в `config.toml` | `.github/hooks/*.json`, `.github/copilot/settings.json` | `.gemini/settings.json` | `.devin/hooks.json`, `~/.codeium/windsurf/hooks.json` | **исполняемый файл** `.clinerules/hooks/PreToolUse` |
| Имя события | `PreToolUse` | `preToolUse` (и принимает `PreToolUse`) | `PreToolUse` | `preToolUse` **и `PreToolUse`** | `BeforeTool` | `pre_run_command` | `PreToolUse` |
| Вход | `tool_input.command` | `tool_input.command` | `tool_input` | `tool_input` (snake_case-режим) | `tool_input` | **`tool_info.command_line`** | не проверял |
| Ответ | `hookSpecificOutput.permissionDecision` = `allow`/`deny`/`ask`/`defer` | `permission` = `allow`/`deny`/`ask`, **и принимает `hookSpecificOutput`** | `hookSpecificOutput.permissionDecision` | `permissionDecision` = `allow`/`deny`/`ask` | **`{"decision":"deny","reason":…}`** | **только код выхода 2** | не проверял |
| Таймаут | секунды | секунды | секунды, по умолчанию 600 | есть, **истёкший таймаут = пропустить** | **миллисекунды**, по умолчанию 60000 | в документации **нет поля таймаута** | не проверял |

**Три поставщика читают наш формат, и это зафиксировано в их документации:**

- **Cursor**: «Cursor supports loading hooks from third-party tools like Claude Code»;
  читает `.claude/settings.local.json`, `.claude/settings.json`, `~/.claude/settings.json`;
  переводит `PreToolUse → preToolUse`, имя инструмента `Bash → Shell`; принимает вложенный
  ответ `hookSpecificOutput`; код выхода 2 сделан совпадающим «for compatibility».
  **Не поддержано:** события `Notification` и `PermissionRequest`, инструмент `Glob`.
- **Codex CLI**: имена событий совпадают с Claude Code дословно (`PreToolUse`,
  `PostToolUse`, `SessionStart`, `SubagentStart`, …), `matcher` применяется к `tool_name`,
  инструмент оболочки называется `Bash`, ответ — `hookSpecificOutput.permissionDecision`.
  **Совместимость при этом нигде не заявлена** — совпадение есть, обещания нет.
- **GitHub Copilot**: «Hooks configured with the PascalCase event name `PreToolUse` — as used
  in Claude Code plugins and the Open Plugins format — apply Claude's matcher semantics».
  Есть snake_case-режим входа (`tool_name`, `tool_input`).

**Два расходятся принципиально:** Gemini CLI (другое имя события, другой формат ответа,
таймаут в миллисекундах) и Windsurf/Cascade (другое имя события, другое поле входа,
**нет объекта решения вовсе** — запретить можно только кодом выхода).

**Cline расходится по способу объявления:** хук — это исполняемый файл, **имя которого и есть
имя события**, в `.clinerules/hooks/`. Файла настроек нет, **матчера нет**: хук срабатывает на
каждый вызов инструмента. Ограничить частоту нечем — её приходится отсекать внутри скрипта.

**У Aider механизма нет.** В полном перечне параметров конфигурации
([aider.chat/docs/config/options.html](https://aider.chat/docs/config/options.html), проверено
2026-10-01) **не встречается ни одного** из слов `hook`, `mcp`, `skill`, `subagent`, `agent`.
Есть только `--lint-cmd`, `--auto-lint`, `--test-cmd`, `--auto-test`, `--lint`, `--test`.

### 3.2. Скилл — здесь предварительный ответ неверен

**Приём и реализация общие.** **Agent Skills — открытый стандарт**, спецификация
на [agentskills.io](https://agentskills.io) (проверено 2026-10-01): «The Agent Skills format
was originally developed by Anthropic, released as an open standard, and has been adopted by a
growing number of agent products. The standard is open to contributions from the broader
ecosystem». Разработка идёт в отдельном репозитории `github.com/agentskills/agentskills`,
там же эталонная проверялка `skills-ref validate`.

**Что именно стандартизовано:** каталог с файлом `SKILL.md`; обязательны ровно два поля
фронтматтера — `name` (≤64 знака, строчные, дефисы, совпадает с именем каталога) и
`description` (≤1024 знака); необязательны `license`, `compatibility`, `metadata`,
`allowed-tools`. Трёхуровневая загрузка (**progressive disclosure**: метаданные при старте →
тело при активации → файлы по требованию) записана **в самой спецификации**, а не в
документации одного продукта.

**Кто читает.** Витрина клиентов стандарта перечисляет среди прочих Claude Code, Cursor,
GitHub Copilot, VS Code, ChatGPT и Codex, Gemini CLI, OpenCode, OpenHands, Goose, Roo Code,
JetBrains Junie, Amp, Kiro, Factory, Warp-класса инструменты, Snowflake Cortex Code,
Databricks Genie Code, Laravel Boost, Spring AI — более сорока записей.

**Единственная реальная привязка — каталог, где агент его ищет.** Спецификация стандартизует
устройство скилла, но **не место установки**. По факту сложилось так:

| Агент | Где ищет |
|---|---|
| Claude Code | `.claude/skills/`, `~/.claude/skills/`, `<подкаталог>/.claude/skills/`, `<плагин>/skills/`. Каталоги вида `.agents/` **не читает** |
| Cursor | `.agents/skills/`, `.cursor/skills/`, `~/.agents/skills/`, `~/.cursor/skills/`, **и для совместимости** `.claude/skills/`, `.codex/skills/`, `~/.claude/skills/`, `~/.codex/skills/` |
| Codex | `.codex/skills/<имя>/SKILL.md` в проекте или в домашнем каталоге |
| OpenCode | шесть каталогов, включая `.claude/skills/` и `.agents/skills/` (по вторичному источнику, первоисточник не проверял) |

То есть **перенос скилла — это `cp -r`, а не переписывание**. Файл не меняется.

**Где Claude Code выходит за стандарт — и это важно для нашего артефакта.** Документация
Claude Code говорит прямо: «Claude Code accepts every field in the table above. Outside Claude
Code, you can use only the fields in the Agent Skills spec». Сверх стандарта он принимает
`when_to_use`, `argument-hint`, `arguments`, `disable-model-invocation`, `user-invocable`,
`disallowed-tools`, `model`, `effort`, `context: fork`, `agent`, `background`, `hooks`,
`paths`, `shell`. **Скилл, использующий любое из них, перестаёт быть переносимым**, причём
при выгрузке в claude.ai лишнее поле даёт жёсткую ошибку, а не игнорируется.

**Наш артефакт** (`n41`, `n49`–`n52`): во фронтматтере ровно `name` и `description`
(`n41` так и говорит — «две строки фронтматтера, имя и описание»). **Это точно стандарт,
без расширений.** Переносится целиком.

### 3.3. MCP — единственный, у кого есть и спецификация, и нейтральный владелец

**Открытый протокол.** Текущая ревизия — **`2026-07-28`**; авторитетный источник требований —
схема TypeScript в `github.com/modelcontextprotocol/specification`. Протокол на JSON-RPC 2.0;
роли — host / client / server; сервер отдаёт **Resources, Prompts, Tools**, клиент может
отдавать **Elicitation**. Ключевые слова требований — по BCP 14 / RFC 2119, то есть это
написано как спецификация, а не как руководство.

**Кто принял.** **9 декабря 2025** Anthropic передала MCP в **Agentic AI Foundation**,
направленный фонд **Linux Foundation**: «Anthropic is donating MCP to the Agentic AI
Foundation, a directed fund under the Linux Foundation»; фонд основан Anthropic, Block и
OpenAI при поддержке Google, Microsoft, AWS, Cloudflare и Bloomberg; вместе с MCP
основополагающими проектами стали **goose** (Block) и **AGENTS.md** (OpenAI). Заявлено:
«vendor-neutrality and long-term independence under the same neutral stewardship that supports
Kubernetes, PyTorch, and Node.js», и «The Linux Foundation … will not dictate the technical
direction of MCP».

**Кто реализовал на стороне клиента.** Документация протокола называет Claude, ChatGPT,
Visual Studio Code, Cursor, MCPJam «and many others». Косвенно, но надёжно: у Cursor есть
событие `beforeMCPExecution`, у Windsurf — `pre_mcp_tool_use`, у Gemini CLI вход хука несёт
`mcp_context`, у Claude Code есть события `Elicitation`, у Codex и Gemini CLI субагенты
принимают поле `mcpServers`. То есть MCP встроен в сами механизмы этих продуктов, а не
прикручен сбоку.

**Исключение, которое стоит назвать вслух:** **у Aider нативной поддержки MCP нет**.
В перечне параметров слова `mcp` нет (проверено по первоисточнику, см. §3.1). Вторичные
обзоры добавляют, что пул-реквесты на MCP были закрыты без слияния, а обходы существуют
только как сторонние мосты — **этого я по первоисточнику не проверял**.

### 3.4. Субагент

**Приём общий, реализация расходится, спецификации нет.** Приём есть у Claude Code, Cursor,
Codex CLI, Gemini CLI, GitHub Copilot (события `subagentStart`/`subagentStop`), Qwen Code.
У **Aider его нет**: это однопоточный редактор файлов с автокоммитом.

| Агент | Где | Формат | Обязательные поля |
|---|---|---|---|
| Claude Code | `.claude/agents/`, `~/.claude/agents/`, `<плагин>/agents/` | markdown + YAML | `name`, `description` |
| Cursor | `.cursor/agents/`, **`.claude/agents/`**, **`.codex/agents/`** (и те же в `~`) | markdown + YAML | `name`, `description` |
| Gemini CLI | `.gemini/agents/*.md`, `~/.gemini/agents/*.md` | markdown + YAML | `name`, `description` |
| Codex CLI | `.codex/agents/`, `~/.codex/agents/` | **TOML** | `name`, `description`, `developer_instructions` |

**Документация Claude Code по субагентам не ссылается ни на одну открытую спецификацию**
(проверено 2026-10-01). Документация Cursor — тоже: она читает каталог `.claude/agents/`,
но это соглашение об имени каталога, а не стандарт.

**Расхождение глубже, чем имена полей.** Markdown-агенты несут системный промпт телом файла;
у Codex это поле `developer_instructions` внутри TOML. Переписывать придётся сам файл, а не
только его расположение. Плюс набор необязательных полей у Claude Code (их около двадцати:
`permissionMode`, `maxTurns`, `isolation: worktree`, `memory`, `effort`, `hooks`, …) не имеет
соответствий у остальных даже близко.

### 3.5. Процесс

**Переносится целиком, и это единственная ступень, где переносить нечего — потому что
механизма нет.** План, запись по ходу и проверка перед сдачей — обычные файлы в репозитории.
Агент читает их потому, что ему так сказано, а не потому, что среда что-то для этого
поддерживает. Ни формата, ни места, ни имён событий, ни формата ответа здесь не существует.

**Один элемент процесса всё-таки имеет формат — входной файл инструкций.** И у него тоже
есть открытый ответ: **`AGENTS.md`** — «a simple, open format for guiding coding agents»,
сейчас **«stewarded by the Agentic AI Foundation under the Linux Foundation»**, заявлено
60 000+ проектов и 24+ поддерживающих инструмента, включая Codex, Copilot, VS Code, Cursor,
**Aider**, Junie, Jules, Devin ([agents.md](https://agents.md), проверено 2026-10-01).
Формат — «just standard Markdown. Use any headings you like».

**Claude Code читает `AGENTS.md`** начиная с v2.1.277: по умолчанию — только если в рабочем
каталоге и выше нет ни `CLAUDE.md`, ни `.claude/CLAUDE.md`, ни `CLAUDE.local.md`. Режим
переключается настройкой **Project instructions** (`claude-md-or-agents-md` по умолчанию,
`claude-md-and-agents-md`, `claude-md`, `managed-only`). Полезная тонкость: **`.claude/rules/`
и `~/.claude/CLAUDE.md` в этот зачёт не входят** и грузятся рядом с `AGENTS.md`.

**В нашем демо-репозитории это уже сделано правильно.** `n02` показывает строку
`CLAUDE.md   AGENTS.md (симлинк на CLAUDE.md)` — то есть входной файл уже лежит под
кросс-вендорным именем. Это стоит сказать залу вслух: один символический файл, и входной
слой репозитория перестаёт зависеть от агента.

## 4. Что из демо-репозитория переживёт смену агента

Разбор по `n65` (что появилось за занятие) и `n02` (что было на входе).

| Артефакт | Переживёт | Что придётся сделать |
|---|---|---|
| `CLAUDE.md` (20 → 40 строк) | **да** | ничего: это текст |
| `AGENTS.md` (симлинк) | **да** | ничего; у Windows-клонов симлинк может стать текстовым файлом — тогда вместо него импорт |
| `src/`, тесты, спецификация, журнал решений | **да** | ничего |
| План / журнал / чек-лист (ступень «процесс») | **да** | ничего |
| `.claude/skills/deploy/SKILL.md` | **да** | `cp -r` в каталог, который читает целевой агент. Фронтматтер (`name` + `description`) уже стандартный |
| Самотест хука (скрипт в репозитории) | **да, кроме одной части** | Логика проверки переносится; **зашитые образцы описания вызова** привязаны к формату входа Claude Code и у Gemini/Windsurf станут неверными — а тест при этом продолжит проходить (`n15` честно пишет это в шапке) |
| `.claude/settings.json` — объявление хука | **частично** | Cursor — предположительно без правок; Codex и Copilot — перенос файла; Gemini и Windsurf — переписать объявление и ответ; Cline — переделать в исполняемый файл с именем события; Aider — механизма нет |
| Тело скрипта хука (`jq` → `grep` → два вызова `git`) | **да, почти везде** | Поле входа `tool_input.command` совпадает у Claude Code, Cursor, Codex, Copilot, Gemini CLI. У Windsurf — `tool_info.command_line` |
| Команды проверки (`/hooks`, `claude doctor`, `claude --debug-file`, `claude plugin validate`) | **нет** | Вендорские целиком. Ближайшая переносимая замена для скилла — `skills-ref validate` из эталонной библиотеки стандарта |

## 5. Проверяемый пример переноса: наш барьер ветки

Исходник (`n14`, ветка `seminar-5-hook`, коммит 9803643): запись в `.claude/settings.json` —
событие `PreToolUse`, `"matcher": "Bash"`, `"timeout": 10`; скрипт из четырёх шагов
(`jq -r '.tool_input.command'` → `grep -qE '(^|[;&|]\s*)git\s+commit\b'` →
`git rev-parse --is-inside-work-tree` → `git symbolic-ref --short HEAD`); два ответа —
`permissionDecision: "ask"` (репозитория нет) и `"deny"` (ветка главная).

### Cursor — по документации **ноль правок**

Cursor читает `.claude/settings.json` сам, переводит `PreToolUse → preToolUse` и
`Bash → Shell`, принимает ответ в форме `hookSpecificOutput`, код выхода 2 совпадает
намеренно. Собственный вход Cursor для `preToolUse` несёт `tool_name` и
`tool_input.command` — ровно то, что достаёт наш `jq`.

**Честный пробел:** документация Cursor **не описывает, какой именно вход получает
импортированный хук Claude Code**. Совпадение формата я вывел из описания его собственного
события, а не из прямого утверждения. **Живой проверки одной сессией я не делал.**
Так это и надо говорить залу: «по документации — ноль правок, проверяется одной сессией».

### Codex CLI — перенос файла, скрипт не меняется

Имя события, семантика матчера (по `tool_name`), имя инструмента `Bash`, поле входа
`tool_input`, ответ `hookSpecificOutput.permissionDecision`, таймаут в секундах, блокировка
кодом 2 — совпадают. Работы: перенести блок в `.codex/hooks.json` (или в таблицу `[hooks]`
в `config.toml`) и включить `features.hooks`. **Тело скрипта — 0 строк правок.**

### GitHub Copilot — перенос файла, и одна ловушка, которой у нас нет

PascalCase `PreToolUse` принимается с «Claude's matcher semantics», вход доступен в
snake_case (`tool_name`, `tool_input`), ответ `permissionDecision` = `allow`/`deny`/`ask`.
Работы: положить в `.github/hooks/*.json`. **Но:** «Timeouts are fail-open for every event,
including `preToolUse`». То есть истёкший таймаут **пропускает вызов**. Наш третий кейс
(таймаут × число срабатываний) здесь бьёт сильнее, а не слабее.

### Gemini CLI — переписать обёртку, логику сохранить

Переписать: имя события `PreToolUse → BeforeTool`; файл → `.gemini/settings.json`; имя
инструмента в матчере `Bash → run_shell_command`; ответ `hookSpecificOutput.permissionDecision`
→ `{"decision":"deny","reason":…}`. Сохранить: `tool_input.command` (имя поля то же), `grep`,
оба вызова `git`. Объём — **около шести строк объявления и ответа, тело без изменений.**

**Ловушка, которая стоит слайда сама по себе:** таймаут здесь **в миллисекундах**. Наше
`"timeout": 10` перенесётся синтаксически безупречно и станет **10 миллисекунд** — барьер
будет молча отваливаться по сроку, то есть пропускать. Это ровно тот отказ, который занятие
уже разбирает, но добытый не ошибкой автора, а переносом.

### Windsurf / Cascade — переписать и потерять одно решение из пяти

Переписать: событие → `pre_run_command`; файл → `.devin/hooks.json`; поле входа
`tool_input.command → tool_info.command_line`; ответ — **только код выхода 2**.
**Потеря по существу:** объекта решения нет, значит нет и состояния `ask`. Наше решение
«что делать, когда проверка не может ответить» (`n13`, ответ `ask` при отсутствии
репозитория) **здесь выразить нечем** — остаётся выбор между «запретить» и «пропустить».

### Cline — переделать способ объявления, матчер потерять

Хук — исполняемый файл с именем `PreToolUse` в `.clinerules/hooks/`, без файла настроек.
**Матчера нет**, значит хук сработает на каждый вызов инструмента, а не только на команды
оболочки. Урок третьего кейса — «сужать матчер, а не ускорять прогон» — **механизма здесь
не имеет**: отсекать придётся первой строкой самого скрипта.

### Aider — механизма нет вовсе, и это самый сильный ответ

Ни хуков, ни MCP, ни субагентов, ни скиллов: в полном перечне параметров нет ни одного из
этих слов. **Решение то же — «коммит в главную ветку закрыт» — а механизма нет, значит
держать придётся иначе:**

- `git` pre-commit hook в `.git/hooks` — работает против любого агента и против человека,
  **но не едет с клоном**. Это ровно та развилка, которую `n14` уже разбирает в заметке
  («почему проверка не в `.git/hooks`: этот файл едет с клоном, служебный каталог — нет»);
- защита ветки на стороне площадки — срабатывает, даже когда барьер промолчал. Ровно то,
  что `n24a` называет «вторым барьером, который от клетки не зависит»;
- `--auto-test` с проверкой ветки в тестовой команде — слабее, срабатывает после правки.

**Это вывод, а не пробел.** Отсутствие механизма не отменяет решения — оно переносит его
на другой уровень, и уровень этот оказывается надёжнее исходного.

## 6. Формулировка самой разницы — один абзац вслух

> Из пяти усилений переносятся по-разному, и граница проходит не там, где кажется.
> Переносится **решение**: что считать нарушением, в какой момент вмешиваться, что вынести
> в отдельный файл, какие права урезать. Это рассуждение целиком ваше, оно не принадлежит
> ни одному инструменту, и при переходе на другой агент вы не теряете ни одного вывода
> этого занятия. Не переносится **запись решения**: как называется событие, в каком файле
> и в какой папке оно объявлено, в каком виде хук отвечает «нет», в каких единицах задан
> срок ожидания. У скилла и у доступа наружу эту запись уже договорились делать одинаково —
> есть опубликованный формат, и один и тот же файл читают десятки инструментов. У хука и
> у субагента такого договора нет: приём есть у всех, а записывается он у каждого по-своему.
> Практический вывод один: **то, что вы сегодня решили, вы перенесёте; то, что вы сегодня
> напечатали, местами придётся напечатать заново.** И есть случай хуже: у инструмента может
> не быть механизма вовсе — тогда решение остаётся в силе, а держать его приходится другим
> уровнем, и часто более надёжным.

## 7. Готовые формулировки для `n03`

Третья колонка к таблице определений. Заголовок: **«Переносится ли»**. Регистр тот же —
одна строка, выделен ключевой термин, точка в конце.

| Усиление | Что это | **Переносится ли** |
|---|---|---|
| Хук | Команда, которую **среда запускает сама** в заданный момент работы агента. | **Приём** — у всех. **Запись** — у каждого своя; у отдельных агентов механизма нет. |
| Скилл | Процедура в **отдельном файле**; агент открывает её сам. | **Открытый формат** — тот же файл читают десятки агентов. |
| MCP | **Model Context Protocol** — подключение к внешней системе; через него агент достаёт данные, которых в репозитории нет. | **Открытый протокол** — у него нейтральный владелец и общая спецификация. |
| Субагент | Отдельная роль с **урезанными правами**; её запускают на одну задачу и получают обратно только итог. | **Приём** — у всех. **Формат объявления** — у каждого свой. |
| Процесс | **Порядок работы, записанный файлами**: план, запись по ходу, проверка перед сдачей. | **Переносится целиком** — это обычные файлы, механизма не требует. |

Если третья колонка не влезает — те же пять строк как второе предложение в колонке «Что это»:

- **Хук.** Приём — у всех; запись события и ответа — у каждого своя.
- **Скилл.** Формат опубликован: тот же файл читают десятки агентов.
- **MCP.** Протокол опубликован, владелец нейтральный.
- **Субагент.** Приём — у всех; формат объявления — у каждого свой.
- **Процесс.** Переносится целиком: это обычные файлы.

## 8. Где объяснять и чего это стоит

**Дека: 89,75 мин по сумме `duration_min` (70 слайдов), слот 90. Запас — 0,25 мин.**

**Рекомендация — разнести на два места, не на одно.**

1. **Пометка — на `n03`,** как владелец и просил: «явно указать в определениях».
   Третья колонка из §7. **Цена: +0,25 мин** (таблица выше, читается дольше) — ровно
   остаток запаса, слайд не добавляется, новых источников не требует.
   Здесь только **факт**, без объяснения: на этом слайде зал ещё не видел ни одного
   механизма, и объяснять разницу «приём против записи» ему пока нечем.

2. **Объяснение — в закрытии, на `n64`,** а не отдельным слайдом. Причина: `n64` **уже**
   содержит таблицу тех же пяти ступеней в том же порядке, и это ровно то место, где зал
   спрашивает «а если я завтра на другом инструменте». Пятую колонку туда добавлять нельзя
   — там уже четыре. Вместо этого: **одна видимая строка под таблицей** («Переносится
   решение, а не запись: что вы решили — перенесёте, что напечатали — местами напечатаете
   заново») **плюс абзац §6 в заметках**. **Цена: +0,5 мин.**

   **Итого 0,75 мин при запасе 0,25 — искать 0,5 мин.** По `CUT-ORDER.md` первый в очереди —
   вопрос к залу «Назовите скилл, который вы бы модели не доверили выбирать» (1,5 мин);
   снимать его целиком ради 0,5 мин не нужно, достаточно сократить. **Решение владельца.**

3. **Отдельный слайд нужен только под разобранный пример переноса** (§5) — тот, где видно
   «в Gemini `10` станет десятью миллисекундами» и «у Aider механизма нет, держим защитой
   ветки». Это хороший материал, и он работает именно как слайд, а не как реплика.
   **Цена: 1,5 мин + 0,25 на `n03` = 1,75 мин.** Тогда из `CUT-ORDER.md` снимается пункт 1
   целиком (1,5 мин) и пункт 3 (0,5 мин) — и запас уходит в нуль.
   **Я бы это предложил, но не стал бы ставить без слова владельца:** занятие и так
   кончается на «что стало проверяемым», а перенос — утверждение, которое сегодня
   ничем не проверяется, и `n67` прямо говорит, что такое за результат не выдаётся.

## 10. Устроено принципиально иначе у другого поставщика — материал, не слайд

Решать владельцу; я ничего не предлагаю ставить.

1. **Таймаут в миллисекундах у Gemini CLI.** Перенос `"timeout": 10` даёт синтаксически
   верный и мёртвый барьер. Отказ того же класса, что уже разбирается в третьем кейсе, но
   причина — перенос, а не ошибка автора.
2. **У Windsurf нет состояния «спросить».** Запретить можно только кодом выхода. Решение
   `n13` «что делать, когда проверка не может ответить» там невыразимо: выбор сужается до
   «запретить» и «пропустить». Хороший разбор того, как отсутствие канала ответа съедает
   проектное решение.
3. **У Cline нет матчера.** Имя файла — это имя события, и хук срабатывает на каждый вызов.
   Урок «сужать матчер, а не ускорять прогон» теряет механизм; цена уезжает внутрь скрипта.
4. **У Copilot истёкший таймаут пропускает вызов,** и это написано прямо: «Timeouts are
   fail-open for every event, including `preToolUse`». Прямое продолжение `n24a`
   («молча становится разрешением»), но на этот раз по решению поставщика, а не по оплошности.
5. **У Codex субагент — TOML, а не markdown.** Единственный, кто выпал из сложившегося
   «markdown + YAML». Наглядно показывает разницу между «сложилось» и «договорились».

## 11. Честные пробелы — чего я не нашёл или не проверял

- **Живая проверка переноса в Cursor не делалась.** Вывод «ноль правок» получен из
  документации (отображение событий + отображение имён инструментов + приём
  `hookSpecificOutput`), **не из запуска**. Вход, который получает импортированный хук
  Claude Code, Cursor нигде не описывает.
- **Вход и ответ хука Cline не проверял** — есть список восьми событий и способ объявления,
  формата полей не нашёл.
- **«Хуки и субагенты в плане будущих версий Agent Plugins»** — утверждение вторичных
  обзоров. На `agent-plugins.org` такого перечня не нашёл; подтверждено только то, что
  в 1.0.0 их нет.
- **Закрытие Continue после покупки Cursor (июнь 2026)** — вторичный источник. По
  первоисточнику не проверял и ни на чём это не держу. Хуки у Continue, по вторичным
  данным, были (17 событий) — тоже не проверял.
- **Закрытые без слияния пул-реквесты MCP у Aider** — вторичный источник. По первоисточнику
  проверено только отсутствие параметра `mcp` в полном перечне параметров.
- **Шесть каталогов скиллов у OpenCode** — вторичный источник.
- **Числа «более сорока агентов» и «24+ инструмента»** — подсчёт по витринам клиентов на
  `agentskills.io` и `agents.md`; это заявления владельцев форматов, а не независимый аудит.
