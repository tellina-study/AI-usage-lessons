# AI or plain code?

## Assertion

The first choice: when a task is solved by code, and when only a model will do

## Visual

Large title naming the choice on a neutral background + a background illustration
(designer to choose) + a single comment line with no spoiler.

## Speaker notes

The first question today: when a task is worth solving with plain code, and when
you genuinely can't do without a model. Engineers often decide this by feel, by a
gut sense of how complex the task looks, rather than by any concrete signal they
could put into words. And the cost of getting it wrong is real in both
directions. Putting AI where plain code would have been enough means ending up
with a solution that's more expensive and less predictable than it needs to be:
code either runs correctly or fails loudly with an error, while a model can
quietly produce plausible-looking nonsense and never warn anyone about it.
Putting plain code where a model is actually needed means signing up for
perpetual patching: every new variation in the input breaks the rigid logic, and
someone has to keep fixing it over and over. There's no single recipe of "always
pick X" — there are signals inside the task itself that are worth learning to
notice. Let's move to the setup.
