# Откуда хук знает команду и ветку

## Assertion

Привычная команда получения текущей ветки падает в свежем репозитории — а падающая проверка не блокирует, она просто не срабатывает.

## Visual

Слева — два вопроса и две новые строки конфигурации:

3. «Откуда хук узнает, какая именно команда сейчас выполнится?» → `jq -r '.tool_input.command'` плюс поиск `git commit` как отдельной команды, а не подстроки.
4. «Как узнать, на какой мы ветке?» → `git symbolic-ref --short HEAD`

Справа — реальный захваченный вывод:

```
$ git init -q -b main
$ git symbolic-ref --short HEAD
main
(exit code: 0)

$ git rev-parse --abbrev-ref HEAD
fatal: ambiguous argument 'HEAD': unknown revision or path not in the working tree.
HEAD
(exit code: 128)
```

Команда `git rev-parse --abbrev-ref HEAD`, которую называет зал, перечёркивается после показа вывода.

## Speaker notes

Третий вопрос зал обычно не берёт, и это нормально: здесь фасилитатор даёт механику, а не проверяет знание. Ответ механический — движок передаёт хуку описание предстоящего вызова в виде JSON через стандартный ввод. Стоит показать одну строку с разбором и сказать, что это общий приём: любой хук начинается с распаковки описания события, а не с разбора произвольного текста. Отдельно — что ищем `git commit` как отдельную команду, а не подстроку.

Четвёртый вопрос — первый настоящий сюрприз раздела. Зал называет привычную команду получения текущей ветки, и фасилитатор показывает реальный захваченный вывод: в свежем репозитории без единого коммита она падает с ошибкой и кодом 128, а `git symbolic-ref --short HEAD` корректно возвращает `main` с кодом 0.

«Смотрите, что бы произошло. Мы написали проверку ветки. Она падает. Падение проверки — это не блокировка: это просто отсутствие блокировки. Внешне — ничего. Абсолютно то же самое "ничего", которое вы видите, когда проверка прошла успешно и всё в порядке.»

Эту фразу стоит произнести медленно: она тот же принцип, который через пару минут вернётся в разборе молчаливого отказа, и зал должен услышать его дважды — один раз на конкретной команде, второй раз как правило.

Если времени не хватает, именно третий вопрос даётся одной фразой вместо диалога. Четвёртый сокращать не стоит: он держится на реальном выводе, а не на рассуждении.
