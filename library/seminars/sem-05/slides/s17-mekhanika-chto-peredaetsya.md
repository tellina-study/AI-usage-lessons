# Что реально приходит на вход

## Assertion

Хук получает на вход полное описание вызова, а вытаскивает из него одну строку через `jq` — не текстовым поиском, который сломался бы на экранированных кавычках внутри самой команды.

## Visual

```json
{
  "session_id": "abc123",
  "cwd": "/home/user/my-project",
  "permission_mode": "default",
  "hook_event_name": "PreToolUse",
  "tool_name": "Bash",
  "tool_input": {
    "command": "npm test",
    "description": "Run test suite",
    "timeout": 120000
  },
  "tool_use_id": "toolu_01ABC123..."
}
```

Полная схема даёт больше полей — идентификатор запроса, путь к транскрипту, каталог черновиков, показатель усилия модели. Хук ступени вытаскивает одно:

```
jq -r '.tool_input.command'
```

## Speaker notes

Хук читает одно поле — команду. А приходит ему на вход куда больше. Вот полная нагрузка — то же самое, что самотест репозитория строит по-настоящему через `jq`, тем же кодом хука, который сам вытащил из файла настроек, не копией логики.

Идентификатор сессии, путь к транскрипту, текущая директория, режим разрешений, имя события, имя инструмента, сами аргументы вызова — команда, описание, таймаут — и идентификатор конкретного вызова. Хук ступени вытаскивает одну строку: `tool_input.command`. Не потому, что остальное не нужно никогда, а потому, что задача этой ступени — про одну команду, не про весь контекст вызова.

И вытаскивает её через `jq`, а не текстовым поиском по всему выводу. Наивный текстовый разбор либо зацепил бы постороннее поле вроде описания, либо потребовал бы написать собственный JSON-парсер поверх `sed`/`awk` — а JSON умеет прятать внутри строки экранированные кавычки и переводы строк: команда с многострочным сообщением коммита такой разбор просто сломает. `jq` сначала распаковывает структуру целиком и только потом отдаёт значение — по этой причине выбран он, а не текстовый поиск.

Самотест из репозитория не имитирует эту схему приблизительно — он строит тот же набор общих полей тем же самым `HOOK_CMD`, который сам вытащил из `settings.json`, запуская настоящий код хука, а не копию его логики. Отличается он только отсутствием трёх полей, которые хук курса и так не читает: идентификатора запроса, каталога черновиков, показателя усилия модели. Это не упрощение ради удобства — это буквально то же самое, что видит хук в реальной сессии, минус то, что ему не нужно. Тот же принцип пригодится на следующем слайде: то, что хук не читает, для его логики попросту не существует — ни поле stdin, ни, как выяснится дальше, действие, которое вообще не проходит через инструмент харнесса.
