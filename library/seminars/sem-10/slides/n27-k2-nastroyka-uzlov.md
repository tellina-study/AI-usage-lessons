# Настоящий экран: как устроены два узла нарезки

## Assertion

Слева — цикл по числу символов; справа — деление по границам предложений и накопление до целевого размера. Один и тот же тип узла, разный код внутри.

## Visual

Нарезка фиксированным размером (слева) читает `payload.chunk_size` (по умолчанию 180), затем в цикле `while (i < text.length)` режет строку кусками по этому числу символов подряд, не глядя на содержимое — после каждого куска сдвигается на `size` символов и повторяет.

Нарезка по границам предложений (справа) сначала делит текст на предложения регулярным выражением (граница — после точки, восклицательного или вопросительного знака), затем накапливает предложения в один кусок, пока суммарная длина не превысит `target` символов, — кусок обрывается только на границе предложения, никогда внутри него.

Оба узла — обычный код (Code-узел, язык JavaScript, режим «Run Once for All Items»), без единого обращения к модели.

## Speaker notes

На прошлом экране было видно, что оба узла нарезки — просто код. Здесь — что именно этот код делает, развёрнуто, строка за строкой, так же, как это видит инженер, открывший узел на реальном стенде.

Левая панель — узел «Нарезка фиксированным размером». Первая строка кода читает параметр `chunk_size` из входных данных, и если его не передали, подставляет значение по умолчанию — сто восемьдесят, то самое заголовочное значение, вокруг которого строился основной разбор. Дальше — одна функция, `chunkFixed`: цикл, который идёт по тексту слева направо и на каждом шаге отрезает кусок ровно заданной длины, вообще не читая, что в этом куске написано. Дойдя до конца текста, цикл останавливается. Это ровно тот код, который даёт девять разорванных ответов из семидесяти двух на заголовочном размере.

Правая панель — узел «Нарезка по границам предложений». Здесь первая строка кода разбивает весь текст на предложения через регулярное выражение, которое ищет точку, восклицательный или вопросительный знак с пробелом после них. Дальше код идёт по этим предложениям по одному и складывает их в текущий кусок, пока суммарная длина не превысит целевое значение — и только тогда закрывает кусок и начинает новый, причём закрывает его строго на границе между двумя предложениями, а не где придётся. Это ровно тот код, который даёт один разорванный ответ из семидесяти двух на том же заголовочном размере.

Стоит обратить внимание на то, что отличается и что нет. Оба узла — один и тот же тип: обычный программный код внутри n8n, режим выполнения «один раз для всех входных данных», язык JavaScript. Разница — только в самой логике функции внутри: двенадцать строк, которые режут по числу, против почти двадцати строк, которые режут по смыслу предложений. Это не новый узел и не новая настройка интерфейса — это другая программа, написанная на месте прежней, и именно эта разница в коде, а не в интерфейсе, отвечает за разницу в числе разорванных ответов.
