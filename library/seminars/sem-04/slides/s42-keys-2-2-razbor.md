# Разбор: как реорганизовать журнал

## Assertion

Разбить на отдельные файлы (по одному на решение) со сквозными ссылками — целевой ответ, но не бесплатный: структура сама создаёт новую нагрузку.

## Visual

Мелким шрифтом вверху — вопрос для контекста: «Как реорганизовать разросшийся журнал решений?»

| Вариант | Где это работает | Почему здесь ещё рано — и что вместо |
|---|---|---|
| «Оставить как есть, просто грепать» | Пока записей десятки и они укладываются в контекст целиком | Деградация плоской памяти со временем задокументирована (~72 ч, −14 п.п.); наш файл уже перерос эту границу |
| **«Разбить на отдельные файлы (по одному на решение) со сквозными ссылками»** | **Именно этот случай** | **Целевой ответ, но не бесплатный** — структура сама создаёт новую нагрузку |
| «Поставлю графовую/векторную систему памяти» | На больших многопользовательских корпусах с семантическим поиском | Контрпример прямо про наш масштаб: файловое хранилище обошло graph-based систему на LoCoMo |
| «Один общий SUMMARY.md, переписываемый целиком» | Для совсем маленького проекта | Переписывание целиком убивает append-only гарантию |
| «Агент сам найдёт через поиск» | Для фактов, выводимых из кода | Решения — не факты кода. «Сам найдёт» — то же заблуждение, что «сам запомнит» |

Нижняя плашка, gold: целевой ответ — разбить на отдельные файлы (по одному на решение) со сквозными ссылками, со списком реальных издержек, а не как безусловный апгрейд.

## Speaker notes

«"Оставить как есть, просто грепать" — приемлемо, пока записей десятки; но мы только что видели: плоская память деградирует со временем, и наш файл уже перерос эту границу. «Поставлю графовую систему памяти» — у нас же по сути граф решений. Целевой ответ всё равно другой: отдельные файлы, по одному на решение, со сквозными ссылками, а не графовая система. Бенчмарк Letta показал: простое файловое хранилище обошло графовую Mem0. Структура — не гарантированный выигрыш, она выигрывает здесь потому, что решает конкретную проблему — потерянную связь между решениями, — а не потому что «структурированное всегда лучше плоского».

«Один общий SUMMARY.md» — переписывание целиком убивает саму гарантию append-only. «Агент сам найдёт через поиск» — то же заблуждение, что «сам запомнит» из прошлого кейса: решения — не факты кода.»
