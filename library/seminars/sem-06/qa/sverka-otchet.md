производят новый файл). Расхождений не найдено — в отличие от Семинара 5, где на этом стыке
расходились пять строк из шести.

**2. Определения ступеней — там, где звучат дважды.** Сошлось. MCP определяется один раз
(`section-1-mcp.md` §A.1.3), субагент — один раз (`section-2-subagent.md` §A.0/А.1 база); ни одно

## Расхождения пункта 17 — три находки, все закрыты

### 17-1. `axis_placement` — снято из обоих блоков

**Решение: снято, не возвращено.** В произведённой деке Семинара 5 типа `axis_placement` нет
вовсе (0 из 68 слайдов) — круг 4 свёл синтез «предотвращаем/решаем» для всех пяти ступеней в
один `recap_table` на закрытии. MCP-раздел это проверил и свои слайды такого типа не писал;
субагент — написал три (`n46`/`n56`/`n64` по старой нумерации, 0,5 мин каждый). При сшивке три
слайда субагента сняты, их текст («строка оси», закрывающая каждый кейс) не потерян — фраза
перенесена в конец речи соответствующего слайда-критерия как естественный переход (тем же
приёмом, что уже использует MCP), а содержимое использовано как источник для ячеек «MCP»/
«Субагент» таблицы оси блока 3. Освобождено 1,5 минуты, ушло в резерв блока.

**Основание против возврата типа в MCP.** Обоснования для нового 16-го типа не нашлось: синтез
оси — работа блока 3 по архитектуре занятия (`ARCHITECTURE.md` §4), дублирование этой работы в
каждом блоке создавало бы декларацию вместо перехода, а тип тянет за собой раскладку в
рендерере без видимой пользы. Решение не возвращать — финальное на этом этапе; владелец может
пересмотреть на ГЕЙТЕ A, если считает трёхкратную декларацию оси педагогически нужной.

### 17-2. `mechanics` → `mechanics_map`

**Закрыто.** Переименовано во всех местах: субагент `n40`/`n48`/`n57` (финальная нумерация,
пров. `n43`/`n52`/`n62`), MCP `n13`/`n20`/`n28` (у MCP было записано неформальными метками
«механика (доп.)» и «`cobuilding` / механика» — тоже приведено к `mechanics_map`, это
дополнительная находка сверх прямого указания пункта 17-2, сделанная при той же проверке).
Содержание слайдов не менялось — правка затрагивает только поле типа.

### 17-3. Хронометраж субагента — верная сумма 36,25, не 35,75

**Закрыто пересчётом.** Автор раздела сообщил 35,75 минуты. Независимый построчный пересчёт при
сшивке — сложение всех 30 строк исходной таблицы (включая три слайда оси), по кейсам отдельно:
кейс 1 (12 строк, с осевым слайдом) — 14,25; кейс 2 (10 строк) — 11,5; кейс 3 (8 строк) — 10,5.
Сумма: 14,25 + 11,5 + 10,5 = **36,25**, не 35,75 — авторская сумма не сходилась с построчным
итогом собственной же таблицы. Принято число **36,25** как верное до снятия трёх слайдов оси,
**34,75** после (36,25 − 1,5). Таблица, фронтматтер (`duration_min`) и доля strict-in раздела
приведены к этому числу во всех местах одновременно — счёт теперь сходится у таблицы,
фронтматтера и `SVODKA-SLAIDOV.md`.
