# Пять каналов — и что у них с гарантией

## Assertion

«Куда положить» — это вопрос «дойдёт ли текст до агента и сколько он стоит»; у пяти каналов пять разных ответов, и три инструмента из четырёх независимо сошлись на одном механизме — объявленном шаблоне путей.

## Visual

| Канал | Когда доходит до агента | Гарантия | Цена контекста |
|---|---|---|---|
| Корневой файл инструкций и его `@`-импорты | при старте каждой сессии | есть | платится всегда, в том числе в сессиях, где не нужен |
| Правило с объявленным шаблоном путей | когда агент работает с файлом, подходящим под шаблон | условная — но триггер объявлен явно, и файл лежит там, куда инструмент смотрит всегда | ноль до срабатывания |
| Комментарий рядом с кодом | когда агент открыл этот файл | следует из механизма: правишь функцию — значит, прочитал файл | ноль сверх того, что и так читалось |
| **Вложенный файл инструкций в подпапке** | когда агент прочитал файл из этой папки — если инструмент так умеет | **нет ни в одном из четырёх инструментов** | ноль до срабатывания |
| Отдельный документ без указателя на него | если агент догадается туда пойти | нет | ноль — и ноль доставки |

Дословно из документации: файлы в подкаталогах «вместо загрузки при запуске включаются, когда Claude читает файлы в этих подкаталогах»; импорт `@`-путём «разворачивается и грузится в контекст при запуске»; правило с шаблоном «срабатывает, когда Claude читает файлы, подходящие под шаблон, а не на каждом вызове инструмента». Проверить, что реально загружено, можно только `/context`.

## Speaker notes

«Вопрос "куда положить" — это на самом деле вопрос "дойдёт ли текст до агента и сколько он стоит". Ответ механический, и он разный у пяти каналов.

Корневой файл и все каталоги выше грузятся при старте сессии: доходит всегда, платим всегда. Импорт через собачку разворачивается тоже при старте — организует файл, контекст не экономит, мы это считали в прошлом кейсе. Комментарий в коде доходит тогда, когда агент открыл файл, — а он его открыл, если правит функцию. Вложенный файл в подпапке доходит только когда агент прочитал что-то из этой папки, и то если инструмент вообще так умеет.

Дальше — факт, ради которого этот кейс существует. Три инструмента независимо друг от друга сделали один и тот же механизм: правило с объявленным шаблоном путей, лежащее в одном общем каталоге правил. У Claude Code это поле `paths`, у Cursor — `globs`, у VS Code — `applyTo`. Формулировка везде одна: правило подключается, когда агент работает с файлом, подходящим под шаблон. Триггер объявлен явно, и файл лежит там, куда инструмент смотрит всегда, — не надо надеяться, что он забредёт в подпапку.

А "просто положи файл в папку" у тех же четырёх инструментов: закрыт как "not planned", признан багом сотрудником, помечен экспериментальным и выключен по умолчанию, не реализован вовсе. Четыре инструмента, четыре разных отказа.

Обещание, на которое все опираются, даёт не инструмент, а стандарт `agents.md`: агенты автоматически читают ближайший файл в дереве каталогов. Это описание типичного поведения, а не требование. Обещание не выполняется, потому что его никто и не давал.»
