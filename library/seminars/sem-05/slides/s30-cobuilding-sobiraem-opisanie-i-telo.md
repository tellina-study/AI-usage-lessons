# Три части описания и пять шагов тела

## Assertion

Описание собирается из трёх частей в реальную формулировку из демо-репозитория, а тело — пять шагов, которые зал уже называл в сценарии проблемы.

## Visual

Собранное описание:

> «Деплоит лендинг signup-landing на прод — сборка, smoke-тест формы, публикация, проверка прод-URL. Используй, когда пользователь просит задеплоить, выкатить или опубликовать сайт — не для обычных правок кода без деплоя.»

Приём для запоминания: **описание — это поисковый запрос вашего будущего «я», забывшего детали через полгода.**

Тело — пять шагов:

1. Собрать
2. Прогнать smoke-тест формы
3. Опубликовать
4. Открыть прод-URL, вручную отправить заявку
5. Записать в журнал задачи, что задеплоено и когда *(новый шаг)*

## Speaker notes

Собираем из трёх частей — и вот реальное описание из демо-репозитория: деплоит лендинг signup-landing на прод, используй, когда просят задеплоить, выкатить или опубликовать сайт, не для обычных правок кода без деплоя. Приём для запоминания: описание — это поисковый запрос вашего будущего «я», забывшего детали через полгода, — не «утилита для деплоя», а слова, которые реально прозвучат в запросе. Тело — минуту назад вы уже назвали все пять шагов, в сценарии проблемы. Единственный новый — последний, запись в журнал задачи: он вернётся на ступени про процесс.
