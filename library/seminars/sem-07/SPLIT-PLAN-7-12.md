# Семинары 7–12 — процессы и автоматизации на базе LLM

Документ фиксирует общий каркас дуги из шести занятий, прежде чем каждое получит свой
`ARCHITECTURE.md`. Семинар 7 первый в дуге и держит этот файл в своей папке; С8–С12
наследуют его §2–§5 так же, как С6 наследовал ось С4/С5.

## 0. Что это снимает

Слот С7–С12 имел три разных предыдущих плана. Ни один не отменён молча — называю явно:

1. **Канон `course-plan-seminars.md`** — С7 «Проверка фактов AI на финансовых данных»
   (парный к старой финансовой Л5), С8–С11 — отраслевые кейсы (генеративный дизайн,
   медицина, автономность, агропилот), С12 — РК2. Этот канон уже не действовал фактически
   с момента, когда С4–С6 ушли в дугу «сборка кодинг-агента» — С7–С12 продолжают то же
   расхождение канона с производством, не вводят его впервые.
2. **`sem-06/SPLIT-PLAN-6-7.md`** планировал С7 как «Порядок, который нечем нарушить» —
   прямое продолжение сквозного демо-репозитория С4–С6 (журнал, гейт, второй барьер,
   перенос на свой репозиторий). **Снято владельцем 2026-10-11.** Документ остаётся как
   историческая запись деления С5/С6 — не читать как план С7.
3. **Issue #191 п.2** требовал re-scope С7 под AI-PDLC (парный к новой Л5) с кейсами
   Zillow/Air Canada/Klarna из архивной finance-Л5. **Снято тем же решением** — С7 больше
   не парный к Л5 1:1, это первое занятие шестисеминарной дуги, привязанной к Л3. Zillow и
   Air Canada не выброшены — переиспользованы ниже (это и предвидел issue #191 п.4: «валидный
   reuse, не случайный дубль»), но под рамкой workflow-паттернов, не PDLC-цикла.

## 2. Ось: лестница сложности процесса

Decision frame Л3 §4.3 («остановись на первом да»), развёрнутый в лестницу — тот же приём,
что С4 («какой блок добавить первым и когда ещё рано»), только про узел процесса.

| Строка | Что | Закрывает |
|---|---|---|
| 0 | Хватит одного вызова (+RAG) — ничего не строим | С7 |
| 1 | Workflow · цепочка (prompt chaining) | С7 |
| 2 | Workflow · маршрут (routing), включая decision-модель вместо LLM | С7 |
| 3 | Workflow · параллель (parallelization) | С8 |
| 4 | Workflow · эталон-переделка (evaluator-optimizer), RAG как ингредиент генерации | С8 |
| 5 | Workflow · дирижёр-исполнители (orchestrator-workers) | С9 |
| 6 | Один агент (в т.ч. вложенный внутри маршрута workflow) | С10 |
| 7 | Мульти-агент (оркестрованный vs «рой») | С11 |
| 8 | Выключить — откат к ручному процессу лучше любой из строк выше | С11→С12 |

Движение: С7 закрывает три нижних строки разом (вход в тему, зал свежий); С8–С10 закрывают
по одной-две строки, каждая новый тип узла; С11 переворачивает вопрос («а когда НЕ») —
сознательный сбой ритма (правило П4, `tools/seminar-production/README.md` §4.2); С12 не
добавляет строк, работает со всей лестницей сразу.

**Нарратив по неделям** (заимствован у Udemy «AI Builder», 40,5k студентов, 4.8 — три
недели курса называются Automate → Accelerate → Amplify): С7–С8 = Автоматизируй, С9–С10 =
Ускоряй, С11–С12 = Проверь. Внешний, запоминаемый скелет дуги поверх внутренней лестницы.

## 3. Сквозной технический кейс (спина) — почему это не «из пальца»

Один домен — **обработка входящей почты/тикетов поддержки** — растёт на каждой ступени как
кейс A (механика, не провал). Это не придуманная компания: это ровно тот домен, который
**независимо выбрали 4 из 7 найденных реальных курсов** как точку входа:

- Nate Herk (бесплатный n8n-курс, 8ч27м, самый растаскиваемый по Class Central) — Customer
  Support workflow, переиспользующий setup RAG-кейса.
- freeCodeCamp — Customer Support RAG Agent, и первый проект всей серии — Email AI Agent.
- Udemy, 50 500 студентов — WhatsApp-саппорт-агент как первый урок.
- n8n Academy (официальная) — чатбот поддержки с памятью как капстоун трёхмодульного курса.

Рост спины по ступеням: chain+gate (С7-1) → routing+decision-модель (С7-2) → параллельные
проверки (С8-1) → RAG+SQL-эвалюатор (С8-2, лаба в духе DeepLearning.AI *Agentic AI* Reflection
pattern) → фото в тикете (С9-1) → генерация визуального ответа (С9-2) → бот в Telegram/WhatsApp
(С10-1, канал — из хука Udemy-курса на 50k студентов) → вложенный агент = тот самый агент
с урезанными правами, собранный на С4–С6 (С10-2) → мульти-агентный эксперимент на своём же
пайплайне (С11-1) → письмо как вектор prompt injection на своём же пайплайне (С11-2).
