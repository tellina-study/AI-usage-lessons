# `CLAUDE.md`

## Assertion

CLAUDE.md содержит только то, что агент не выведет сам из кода — реальные команды сборки и теста этого сайта.

## Visual

Блок кода на всю ширину слайда, моноширинный шрифт, дословно из демо-репозитория:

```markdown
# CLAUDE.md

signup-landing: статический лендинг с формой заявки на демо-урок. Готово = `npm run build`
завершается кодом 0, `npx playwright test` зелёный, форма реально отправляет заявку на проде.

## Safety / scope boundaries

- Никогда не запускать деплой на прод без явного запроса.

## Build, test, verify

- Build: `npm run build`
- Test: `npx playwright test`
- Run locally: `npm run dev`
- To verify a change actually works (not just compiles): открыть `dist/index.html` после сборки,
  вручную отправить форму с заполненными и с пустыми полями.
```

## Speaker notes

Вот как это решение выглядит на нашем собственном сайте — не абстрактный пример из документации, а реальный `CLAUDE.md` из демо-репозитория, дословно. Файл появляется после `git init`: без реального git-репозитория позже честно не сработает хук из следующего раздела, поэтому инициализация репозитория — обязательный первый шаг этой же ступени.

Смотрите на то, чего в файле нет, столько же внимательно, сколько на то, что в нём есть. Нет описания структуры кода — агент выведет её сам за секунды, читая файлы. Нет истории решений — для этого следующая ступень, память. Есть ровно три вещи: одна строка о том, что такое этот проект и что значит «готово»; одна строка ограничения — никогда не деплоить на прод без явного запроса, это готовит почву для скилла в одном из следующих разделов, процедура деплоя туда и переедет; и раздел `Build, test, verify` с настоящими командами именно этого сайта — `npm run build`, `npx playwright test`, `npm run dev`, и отдельная строка про то, как проверить, что изменение реально работает, а не просто компилируется.

Официальная таблица include/exclude, на которую опирается это решение, сводится к одному правилу: включать bash-команды, которые агент не угадает, нестандартный стиль кода, инструкции тестирования, репозиторный этикет, архитектурные решения, обязательные переменные окружения и неочевидные грабли — исключать всё, что агент и так выведет из кода, стандартные языковые конвенции, подробную API-документацию, часто меняющуюся информацию и самоочевидные советы вроде «пишите чистый код». Наш файл проходит этот фильтр построчно: каждая строка — то, чего иначе агенту неоткуда узнать.

Агент читает этот файл в начале каждой сессии — как памятка на столе нового сотрудника, которую читают, хочет он того или нет. Это база, которую стоит унести с этого слайда. Дальше — как этот же файл становится видимым ещё и для других агентов, не только Claude Code.
