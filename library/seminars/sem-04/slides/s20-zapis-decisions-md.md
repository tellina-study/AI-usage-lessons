# DECISIONS.md: журнал «почему»

## Assertion

Журнал решений — append-only лог «почему», а не второй файл инструкций.

## Visual

Слева — файл целиком:

```markdown
# Decisions

Append-only log of why, in date order.

## 2026-09-20 — не подключаем библиотеку валидации форм
Форма — два поля (имя, email), хватает нативных `required`/`pattern` в `index.html`.
Сторонняя библиотека — лишняя зависимость и лишние килобайты в сборке ради этого объёма.
```

Строка «Append-only log of why, in date order» подсвечена.

Справа сверху — дерево ступени 2, строка `DECISIONS.md` выделена gold:

```
AGENTS.md
CLAUDE.md
DECISIONS.md
index.html
package.json
src/main.js
tests/form.spec.ts
```

Справа снизу — узкая плашка: diff создания файла, семь добавленных строк.

## Speaker notes

Это реальный файл реального демо-репозитория, а не пример, сочинённый для слайда, — и это стоит произнести вслух.

Обратить внимание на две вещи. Первая: подзаголовок «append-only log of why» — файл дополняется, а не переписывается, и записывается в него обоснование, а не событие. Вторая: сама запись состоит из даты, одной строки решения и двух строк причины. Больше ничего.

Формат намеренно скромный. Если запись начинает разрастаться до абзаца, значит в неё пытаются положить то, что должно лежать в файле инструкций (стабильное правило) или в истории изменений (что именно сделано).

Дерево справа показывает всё состояние репозитория после второй ступени: продукт-код, файл инструкций с симлинком и один новый файл. Два блока конфигурации из семи.

И параллельно — авто-память, второй механизм этой ступени, который в дерево не попадает, потому что живёт вне репозитория. Команда «запомни: не подключаем стороннюю библиотеку валидации, форма из двух полей, хватает нативного HTML5» создаёт тематический файл именно там. Как эти два механизма отличаются — на следующем слайде.
