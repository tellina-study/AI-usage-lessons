# Сценарий 2 — ночной скрипт багов

## Assertion

Ночной скрипт: баг-репорты → критичность → очереди Jira.

## Visual

Верхняя широкая Ocean rounded box карточка: иконка `git-branch`, курсивный текст сценария («Скрипт запускается каждую ночь по расписанию. Сам скачивает новые баг-репорты, классифицирует каждый по критичности через AI и автоматически раскладывает по очередям в Jira. Никто не наблюдает за процессом»).

Ниже — две маленькие карточки бок о бок с Q1 и Q2 текстом. Ниже — квадрант 2×2 слева (ячейка «Приложение» выделена gold) + gold callout справа с обоснованием «Q1 нет (работает автономно) · Q2 да (сама вызывает API Jira) — реже всего разбираемый угол».

## Speaker notes

Прогоняем через чек-лист. Q1 — нет: работает автономно, по расписанию, без диалога с пользователем. Q2 — да: самостоятельно вызывает API Jira, читает репорты, пишет результат. Правильный ответ — приложение в режиме автоматизации, правый нижний угол квадранта. Это наименее очевидный и реже всего разбираемый на конкретных примерах угол — часть аудитории могла проголосовать «агент», потому что видит многошаговую автономную работу с инструментами.

Ключевое различие для разбора вслух: у агента есть диалог с пользователем на уровне постановки цели и корректировки (Q1 да); здесь пользователь никак не взаимодействует с системой в моменте исполнения — только настраивает её один раз заранее. Даём этому сценарию не меньше времени на обсуждение, чем следующим двум — это не менее важная, а просто менее интуитивная точка чек-листа.
