# Зачем субагенту отдельное контекстное окно

**Date:** 2026-10-02 · **Issue:** #217-EXP

Субагент в архитектуре Claude Code — это независимый сеанс со своим собственным контекстным буфером, отделённым от родительской сессии. Это разделение критично.

| утверждение | источник | тип |
|---|---|---|
| Отдельный контекст изолирует память субагента от информационного шума родителя | harness-control CLAUDE.md § Sibling discovery | principle |
| Чистая история сообщений упрощает отладку: логи читаются как самостоятельный нарратив, без «контекста из части 2 родителя» | harness-control #1004 design | observation |
| Риск галлюцинации снижается, когда агент не видит весь контекст управления и планирования родителя | Anthropic agent design practices | principle |
| Параллельные субагенты масштабируются без перегрузки родительского буфера | harness-control orchestration rules | principle |

**Практический смысл:** когда оркестратор запускает 5 субагентов на разные части задачи, каждый работает в изоляции. Родитель не отправляет им весь свой контекст — только задачу. Результат: каждый субагент быстро сходится на своей подзадаче, не отвлекаясь на информацию из соседних задач.

**Альтернатива (неправильно):** один большой буфер на всех. Тогда каждый субагент видит всё: план родителя, результаты соседей, debug-логи. Контекст становится шумным; вероятность неправильного вывода растёт.

## Что НЕ доказано

- Оптимальный размер контекстного окна для типовой подзадачи.
- Минимальный информационный набор, который субагент обязательно должен получить от родителя (только задача или также часть аргументов?).
- Влияние изоляции на end-to-end latency: экономия на context-switching vs добавленная сетевая задержка.
