# Slash-команда vs хук в агентном харнесе: основные различия

**Date:** 2026-10-02 · **Issue:** #217-EXP

## Различие в инициации

**Slash-команда** (skill) — явный, синхронный вызов пользователем через `/skill-name` в командной строке. Возвращает результат немедленно в текущую сессию. Пользователь полностью контролирует время и контекст запуска. Механика: ввод → выполнение → вывод.

**Хук** (hook) — асинхронный автоматический триггер, связанный с событием или условием. Конфигурируется один раз в `settings.json` по выражению вида `before X` или `after Y` (где X/Y — действия, фазы, временные точки). Выполняется фоном при достижении условия, без явного участия пользователя.

Ключевое различие: slash-команда — это одноразовое действие по требованию, а хук — это установленная система автоматизации. Хук проще всего понимать как задачу в планировщике (`cron`), которая срабатывает по расписанию условий, а не по явному вызову.

## Особенности реализации

| утверждение | источник | тип |
|---|---|---|
| Slash-команды спавнят одноразовый subagent через `handoff`/`assign` | CLAUDE.md § Handoff vs. assign; harness-control#1004 | архитектурный факт |
| Хуки конфигурируются в `.claude/settings.json` и выполняются harness-control оркестратором | CLAUDE.md § update-config skill | конфигурационный факт |
| Slash-команда возвращает результат в сессию пользователя синхронно | memory `confident-tone-no-apologies` + CAO-MCP docs | API-контракт |
| Хук может запустить новый session или задачу фоном асинхронно | по памяти, не проверено | архитектурное предположение |

## Что НЕ доказано

- Отказоустойчивость хуков при отказе harness-control оркестратора
- Максимальная задержка между условием и срабатыванием хука
- Поддержка вложенных хуков (хук внутри хука)
- Какой хук имеет приоритет, если несколько срабатывают одновременно
