# Ветка, которую не видно, и вопрос вместо тишины

## Assertion

Определять ветку — не через `rev-parse`, который падает на пустом репозитории, а через `symbolic-ref`; а на «это вообще не git-репозиторий» хук возвращает не тишину и не блокировку, а явный вопрос.

## Visual

**Вопрос 4.** «Как узнать, на какой мы ветке?» Зал называет `git rev-parse --abbrev-ref HEAD`.

```
$ git init -q -b main
$ git symbolic-ref --short HEAD
main
(exit code: 0)

$ git rev-parse --abbrev-ref HEAD
fatal: ambiguous argument 'HEAD': unknown revision or path not in the working tree.
(exit code: 128)
```

Фиксируется: `git symbolic-ref --short HEAD`.

**Вопрос 5, кульминация.** «А если это вообще ещё не git-репозиторий?»

`разрешить молча` · `заблокировать` · **`спросить`**

Реальный вывод хука на «спросить»:
```
permissionDecision: "ask"
"WARNING: branch-protection gate inactive — this is not a git repository yet…"
```

> «Гейт, чей отказ молчалив, не считается установленным, пока его не заставили отказать громко.»

## Speaker notes

Четвёртый вопрос — первый настоящий сюрприз. Как узнать, на какой мы ветке? Обычно называют `git rev-parse --abbrev-ref HEAD`. Смотрите, что происходит на свежем репозитории без единого коммита: инициализировали репозиторий, `symbolic-ref --short HEAD` корректно вернул ветку с кодом ноль, а `rev-parse --abbrev-ref HEAD` упал с кодом сто двадцать восемь — «неоднозначный аргумент HEAD». Падение проверки — это не блокировка, это просто отсутствие блокировки. Внешне — ничего. Абсолютно то же самое «ничего», которое видно, когда проверка прошла успешно и всё в порядке. Фиксируем `symbolic-ref`, не `rev-parse`.

Пятый вопрос — кульминация всего шага, и режется последним при нехватке времени, потому что без него теряется главный принцип этой ступени. А если это вообще ещё не git-репозиторий? Три варианта: разрешить молча, заблокировать, спросить. Пусть каждая сторона скажет пару слов, прежде чем открыть ответ.

«Разрешить молча» — проверять действительно нечего, но тогда файл барьера лежит в репозитории, а барьера нет, и снаружи эти два состояния неразличимы. «Заблокировать» — честно, но парализует работу в ситуации, которая не является нарушением. Автор этого хука выбрал третий вариант — не потому, что он компромиссный, а потому, что он единственный не создаёт иллюзии.

Вот реальный вывод хука в этой ситуации: решение «ask», явное предупреждение, что защита ветки сейчас неактивна. Потому что если бы хук просто промолчал, файл барьера лежал бы в репозитории, барьера бы не было, а внешне это было бы неотличимо от работающей защиты.

Принцип, ради которого задавался этот вопрос, стоит закрепить дословно: гейт, чей отказ молчалив, не считается установленным, пока его не заставили отказать громко. Он вернётся ещё раз, почти без изменений, когда будем разбирать второй слой провала — там окажется, что «отказать громко» не всегда в силах самого хука.
