## Видимый текст слайда

**Рабочее поле, в котором диффузионная модель производит все вычисления, — против готовой картинки 1024×1024: больше, равно или в разы меньше?** В разы меньше.

**Автоэнкодер (VAE) сжимает картинку в латентное поле:** 512×512×3 пикселей (786 432 числа) → латент 64×64×4 (16 384 числа).

**×8 по стороне. ×48 по числу обрабатываемых чисел** — точная арифметика, не оценка «около».

**Латент — не «сжатый JPEG»**, а пространство признаков: соседние точки похожи по смыслу, не по байтам файла.

## Заметки лектора

Следующий шаг устройства — не в каких единицах модель видит вход, а в каком по размеру поле она физически работает. Рабочее поле, в котором диффузионная модель генерации изображений производит все свои вычисления, — больше, равно или в разы меньше, чем готовая картинка размером 1024 на 1024 пикселя, которую видит пользователь на выходе? Интуиция инженера, не занимавшегося этим специально, скорее предположит «примерно того же порядка». Ответ — противоположный интуиции, причём с точностью, а не приблизительно: в разы меньше.

Перед тем как изображение попадает в генеративную модель, отдельная сеть — автоэнкодер, в этом семействе моделей называемая VAE, variational autoencoder, — сжимает его в латентное пространство: не архивный сжатый файл вроде JPEG, а внутреннее, абстрактное представление, в котором модель и производит всю реальную работу диффузии. Для стандартной конфигурации моделей семейства Stable Diffusion эта арифметика известна точно: картинка 512×512 пикселей с тремя цветовыми каналами — 786 432 отдельных числа — превращается в латентное поле размером 64×64 с четырьмя каналами, 16 384 числа. Пространственно это сжатие в восемь раз по каждой стороне (512 делится на 64); по общему числу скаляров, с которыми модель реально работает на каждом шаге, — в сорок восемь раз (786 432, разделённое на 16 384, даёт ровно 48,0 — это точная арифметика, не оценка «около»). Оба числа — «в восемь раз по стороне» и «в сорок восемь раз по количеству обрабатываемых чисел» — это два честных среза одной и той же экономии, а не два противоречащих друг другу утверждения: квадрат сжимается по стороне в восемь раз, а по площади — в шестьдесят четыре раза, но число каналов при этом растёт — с трёх цветовых каналов RGB до четырёх каналов латентного представления, — и этот рост частично компенсирует сжатие по площади, снижая итоговый множитель с шестидесяти четырёх до сорока восьми.

Нюанс, без которого этот механизм легко принять за трюк архивации: латентное поле — не «JPEG навыворот» и не упрощённая, зернистая версия картинки. Это пространство признаков, в котором близкие по координатам точки соответствуют картинкам, похожим по смыслу содержания — два портрета с похожим выражением лица, два пейзажа с похожим освещением, — а не похожим по сырым байтам файла: две визуально похожие картинки, сохранённые в разных форматах, могут лежать в этом пространстве далеко друг от друга, если их смысловое содержание устроено по-разному. Именно поэтому модель, работающая в латентном поле, может плавно интерполировать между двумя смыслово близкими состояниями — то, что она и делает на каждом шаге диффузии дальше, — тогда как плавная интерполяция между двумя сырыми JPEG-файлами дала бы просто визуальный шум.

Ось этого шага работает буквально: меньшее по размеру рабочее поле означает меньше вычислений на каждый из десятков шагов генерации, а меньше вычислений на шаг — это и есть секунда генерации, которая обходится в доли цента вместо дней ручного труда. Следующий кадр замыкает эту арифметику на число, которое keystone этой лекции предъявила без объяснения с самого начала.
