# Visible content

## Title bar
LLM здесь не источник истины, а интерфейс к источнику истины.

## Body
[Слева — Ocean rounded box, критерий «когда LLM НЕ источник истины»]

- **Аргумент 1 — механизм галлюцинации:** LLM генерирует правдоподобное продолжение, не извлекает проверенный факт. «Правдоподобно» ≠ «верно».
- **Аргумент 2 — цена ошибки юридическая:** неверная ставка/условие = нарушение + ущерб клиенту, отвечает организация.
- **Аргумент 3 — что сломается:** свободная генерация о регулируемых фактах = масштабируемый генератор правдоподобной дезинформации с юр. ответственностью банка.

[teal callout — альтернатива]
Для фиксированных фактов (ставка, тариф, право) — **детерминированная выборка** (lookup / grounded RAG), LLM формулирует найденное, но не выдумывает число. Любой обязывающий банк факт обязан быть grounded и проверяем.

[Справа — Ocean rounded box, 5 классов ошибок]
1. **галлюцинация факта** — число без источника → сверить с первоисточником
2. **устаревшие данные** — цифра без даты → проверить актуальность
3. **прокси-bias в выводе** — «не использовали признак» → аудит исходов
4. **обман метрикой** — «99,X%» без базы → FP/FN раздельно в деньгах
5. **подмена базы** — громкая доля без «доля чего от чего» → запросить базу

[Аналогия-плашка]
grounding: студент сначала открывает справочник на нужной странице, читает точное значение, потом формулирует — а не угадывает уверенным тоном.

[Gold callout, низ]
На лекции: **распознать класс + назвать принцип** (Understand). Самостоятельная проверка 5 заявлений по первоисточникам — Семинар 5 (Apply).

## Speaker notes

Здесь — сквозной паттерн всей лекции: проверка фактов. Сформулируем его как развёрнутый критерий, когда языковая модель не источник истины, тремя аргументами и альтернативой. Тезис: в финансах ответ модели о числах, ставках, условиях, правах клиента обязан опираться на проверяемый первоисточник и быть проверяемым; модель здесь не источник истины, а интерфейс к источнику истины.

Первый аргумент — механизм галлюцинации: модель генерирует правдоподобное продолжение текста, а не извлекает проверенный факт; правдоподобно не равно верно. Спросите про точную ставку по конкретному вкладу — модель может выдать уверенно звучащее, но неверное число, потому что её задача — связность, а не истинность. Второй аргумент — цена ошибки в финансах юридическая: неверно названная ставка или условие — это потенциальное нарушение и прямой ущерб клиенту, за который отвечает организация. Третий — что сломается: если позволить модели свободно генерировать ответы о регулируемых фактах, вы получаете масштабируемый генератор правдоподобной дезинформации с юридической ответственностью банка за каждый ответ. Альтернатива и критерий: для фиксированных фактов ответ строится детерминированной выборкой из системы или документа, модель формулирует найденное человеческим языком, но не выдумывает само число.

Чтобы «распознать класс ошибки» был операциональным навыком, разложим типичные классы. Класс первый — галлюцинация факта: конкретное число без ссылки на источник, принцип — сверить с первоисточником. Класс второй — устаревшие данные: цифра в волатильной области без даты, принцип — проверить актуальность. Класс третий — смещение через прокси в выводе о группе людей, принцип — помнить, что нужен аудит исходов. Класс четвёртый — обман метрикой: точность без базы и цены ошибки, принцип — спросить ложноположительные и ложноотрицательные раздельно и в деньгах. Класс пятый — подмена базы: громкая доля без точной формулировки, ровно как «голосовые более девяноста процентов». Аналогия для grounding: модель без опоры на источник — как студент, который не помнит цифру, но уверенно её произносит; модель с grounding сначала открывает справочник, читает точное значение и только потом формулирует. На лекции от вас требуется распознать класс и назвать принцип; самостоятельная проверка по первоисточникам — это Семинар 5.
