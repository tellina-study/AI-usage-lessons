## P1 — находки

### P1-1. Две таблицы разбора вернулись к форме, которую круг 2 явно отменил

`n30` («Фиксация версии и перечитывание — последовательность») и `n58` («Пять вариантов, у
каждого свой случай и своя цена») используют заголовки колонок **ВАРИАНТ · ГДЕ РАБОТАЕТ —
КОНКРЕТНЫЕ СЛУЧАИ · ЧТО НЕ ДЕЛАЕТ / ОГРАНИЧЕНИЕ** — это дословно старая трёхколоночная форма
«вариант · где работает · ограничения», которую `ZADANIE-KRUG-2-VLADELTSA.md` А5 отменяет
прямым текстом: «Это отменяет прежнее требование трёх колонок «вариант · где работает ·
ограничения»». Остальные четыре `answer_breakdown`-таблицы деки (`n11`, `n21`, `n40`, `n48`,
`n51`) используют правильную форму — СПОСОБ/ВАРИАНТ · **ЧТО ДЕЛАЕТ** · ЧТО НЕ ДЕЛАЕТ /
ОГРАНИЧЕНИЕ. Два из шести разборов (треть) не прошли это требование — проверено построчно по
каждому из шести `answer_breakdown` слайдов деки, других расхождений нет.

### P1-2. n41 дублирует содержимое, которое круг 3 прямо запретил выносить отдельным слайдом

`ZADANIE-KRUG-3-SUBAGENT.md`, раздел «Что остаётся базой, а не кейсом»: «Что роль видит и чего
не видит, что возвращает и чего не возвращает» — это механика. Её место в базе ступени и в
одностраничнике «Роль целиком, одним экраном»… **Отдельным кейсом она больше не стоит**».
`n41` («Что входит в окно роли, что из него выходит») — именно такой отдельный слайд: он
дословно пересказывает то же содержимое, что уже есть на `n36` (база: «Задача приходит текстом,
роль возвращает родителю только итог») и на `n37` (одностраничник, блоки 3 «ЧТО НА ВХОД» и 4

только финальный текст на выходе — список фактов идентичен, только в прозе вместо карточек).
Между n37 и n41 — три слайда дистанции в одном и том же кейсе. Это прямое расхождение с
письменным решением круга 3, а не просто третье повторение одной мысли.

### P1-3. Золотой акцент отсутствует на 6 слайдах — нарушение «≥1× на слайд»

Проверено программно по пикселям (`#F0AB00` ± допуск) на полноразмерных PNG, не на глаз:
`n03`, `n05`, `n25`, `n32`, `n59`, `n65` не содержат золотого цвета нигде на полотне.
`CLAUDE.md` фиксирует золото как обязательный акцент без исключений («Gold `#F0AB00` highlight
≥1×/слайд»). Паттерн тот же, что был в прежней версии (P1-4 старого отчёта): все шесть —
таблицы-рекапы или research-таблицы с тёмно-синей/бирюзовой рамкой без единого жёлтого
элемента (`n03`/`n65` — ось ступеней, `n05` — карта блоков, `n25` — таблица провала, `n32` —
карточка с фактом, `n59` — таблица источников). Находка не нова, но и не почищена за два круга
правок — либо задокументировать исключение для типа «таблица-рекап/источники», либо добавить
минимальный золотой акцент.

## P2 — находки

1. **`n01` и `n04` дублируют цитату вопроса занятия почти дословно** — ровно та же находка, что
   в прежнем отчёте (P2-1 там), не исправлена: обложка несёт полную цитату в золотой коробке,
   `n04` — тот же текст через четыре слайда. Петля на троих (n01 → n04 → n67) всё ещё начинается
   с двух почти идентичных предъявлений подряд.
2. **`n14` ведёт два разных дела, названо в заголовке только одно.** Заголовок «Собранный файл:
   что значит каждая строка» точно описывает верхние две трети слайда (код `.mcp.json` + разбор
   строк). Нижняя треть — отдельная тема: приоритет шести областей при совпадении имени сервера,
   включая новые для слайда уровни (политика организации, плагин, коннектор), которых не было на
   `n13`. У блока есть собственный подзаголовок, поэтому пятисекундный тест проходит частично —
   но заголовок слайда по-прежнему покрывает не весь экран.
3. **Четыре слайда подряд в одной графической форме** (`n41`–`n44`: акцентная полоса + абзац
   жирного текста, без единого визуального элемента между ними, если не считать мелкую карточку
   на `n44`) — тот же механизм низкой динамики, что старый отчёт отмечал мягче (P2-5 там, 6 тёмных
   пауз из 63). Внутри кейса 1 субагента это создаёт заметный провал плотности визуала перед
   кейсом параллелизма.
4. **Асимметрия двухколоночных `criteria_boundary`-карточек.** `n26` — одна строка слева против
   трёх справа; `n34` — одна строка слева против четырёх справа. Контент оправдан (реже
   достаточно одной причины), но визуально читается как незаполненная половина экрана.
5. **`n54` выпадает по форме из своего же типа.** Остальные четыре `criteria_boundary`
   (`n17`, `n26`, `n34`, `n63`) используют пару лёгких карточек «когда нужно / когда не нужно».
   `n54` — четыре отдельных абзаца подряд без карточек, самый текстоёмкий слайд блока
   (отраслевой разворот + критерий + база правила в одном месте). Контент плотный и обоснованный,
   но не повторяет собственную грамматику деки — кандидат на репетицию вслух на предмет укладки
   во время.
6. **Кегль одностраничников n08/n37 на грани порога, не с запасом.** Измерено по эмбеддед-картинке:
   n08 — полотно 2400 px на 12,23″ (196 px/дюйм), самый мелкий текст (`NOTE=21px`) даёт **7,71 pt**
   — выше порога деки 7,5 pt, но на 0,21 pt, около 3%. n37 — полотно 1600 px на той же ширине
   (130,8 px/дюйм), самый мелкий текст (16 px) даёт **8,80 pt** — запас больше, но всё ещё не
   «крупно». Формально оба прошли — после двух предыдущих попыток, обе ниже порога (5,9 pt и
   7,16 pt по заметкам в самом коде). На проекторе стоит перепроверить вживую, а не доверять
   только расчёту.

Держится, проверено по всем опорным точкам. Обложка (`n01`) и `n04` формулируют её дословно:

## Что хорошо и ломать нельзя

- **Красный цвет убран полностью** — не только визуально (все пять прежних мест: n14/n15/n37/n51/
  n53 по новой нумерации), но и в генерирующем коде: `RED` в `fig_toolkit.py` существует, но
  функция `xmark()`, которая его использует, нигде не вызывается — мёртвый код, не риск
  регрессии при следующей правке.
- **Чёрные/тёмные блоки кода убраны везде** — все код-артефакты (n08, n14, n24, n32, n61) на
  светлой подложке с тёмным моноширинным текстом, ни одного «терминала».
- **Теги дивайдеров сняты** — все 6 дивайдеров (n06, n18, n27, n35, n45, n55) без приписок
  «N подключений, M провалов»; прогресс-пилюли (золото=активный, бирюза=пройден, тёмно-синий/
  серый=впереди) несут состояние без единой цифры минут.
- **Итоги разделов говорят прямо «когда нужно / когда не нужен»** — все шесть `criteria_boundary`
  (n17, n26, n34, n43-мостик, n63, n64) формулируют критерий напрямую, без «ещё рано».
- **Вопрос вызова API исправлен** (`n11`): текст теперь верно говорит, что агент вызывает API
  сам, без отдельного кода интеграции — старая ошибка снята.
- **Нереалистичные варианты разбора кейса 2 заменены** (`n20`): четыре рабочих варианта вместо
  «удалить сервер / перезапустить / написать автору».
- **А9 (токены) исполнено**: `n15` разводит постоянную плату и цену вызова, даёт сопоставление по
  способам доступа с двумя независимыми источниками (vendor + второе исследование в деньгах).
- **Самоизобличение курса сохранено и усилено**: `n62`/`n63` — реальный баг каталога ролей
  (`tools: All tools` не резолвится), `n64` — сравнение с официальными примерами Anthropic
  (code-reviewer/debugger).
- **Заметки докладчика богатые и честные**: 7 случайных слайдов — 150–450 слов, структура
  «Справка/Если спросят», разбор вероятных реплик зала, ни одного «Лектору», ни одного описания
  раскладки.
- **Запрещённый видимый слой чист**: 0 упоминаний тайминга в минутах, 0 методических
  комментариев, 0 номеров занятия вне обложки, 0 scaffolding-маркеров — проверено грепом по
  всему тексту всех 68 слайдов, не выборочно.
- **«Честный пробел» — устойчивая узнаваемая форма** (n42, n52, n59) — пунктирная серая рамка,
  курсив, не смешивается с другими блоками.
