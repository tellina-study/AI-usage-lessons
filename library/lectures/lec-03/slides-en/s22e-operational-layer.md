# Visible content

## Title bar
«The operational layer: instructions and a log are not a panacea»

## Body
[Three results]
- **Presence paradox** *(Gloaguen et al., 2026, RCT)* — the mere presence of an instruction file gives **no** significant gain in success; it helps only in a **documentation gap**
- **Honest Lying** *(Dixit et al., 2026)* — self-authored memory can **entrench** a wrong belief rather than correct it
- **claude-code#51735** — a record of a past error **did not prevent** its repeat 25 days later

[Gold callout, bottom]
The operational layer is a tool with measured effects, **not a vaccine against an agent's errors**. The same pattern as a role in the prompt: "add X — it gets better" is not confirmed by measurement.

## Speaker notes

The second harness slot is the operational layer: the project's instruction files and a task log into which the agent writes its own progress on multi-step work. An instruction file here is a generalized name for a class of convention files where a team records how to build the project, how to test, which patterns to keep to. The intuition is clear: if you write the agent a detailed instruction and keep a log of what was done, quality should rise. Controlled studies show that the intuition diverges noticeably from the measured effect. The first study, the presence paradox[1], is a randomized experiment with three arms: no file, a file generated by the model, a file written by a developer. The key conclusion: the mere presence of a file gave no statistically significant gain in task success, while cost and the number of steps tended to rise. The single exception is meaningful: generated files helped precisely in repositories where there was no other documentation — that is, a file works when it fills a real information gap, rather than duplicating what the model would infer from the code anyway.

The second study, Honest Lying, is about self-authored memory: the agent itself writes notes about its conclusions and errors. It turned out that such memory can not help correction but entrench a wrong belief — if the agent early on wrongly recorded the cause of a failure, subsequent attempts rely on it instead of rechecking. The third is a real case, claude-code#51735[2]: a past error was acknowledged in writing in the log, and this did not prevent its repeat twenty-five days later. The synthesis for an engineer: the operational layer is not a magical vaccine against errors and not a ritual by default, but a tool with measured, sometimes modest and counterintuitive effects. The same pattern as a role in the prompt: the common "add X — it gets better" is not confirmed by measurement, and doing X is worth it only where there is a concrete basis.
