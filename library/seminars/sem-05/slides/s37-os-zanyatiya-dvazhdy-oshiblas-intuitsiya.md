# Дважды не сработала интуиция

## Assertion

Решаем — реактивно, по сигналу перегрузки файла инструкций; и интуиция ошиблась дважды: описание — не деталь, а условие срабатывания, а одобрение скилла — разовое, права — постоянные.

## Visual

**Ось занятия:**

> Решаем — реактивно: файл инструкций уже платит налог за процедуру, которая нужна не всегда, сигнал уже прозвучал. Интуиция говорила: содержание скилла — вот что имеет значение, описание — необязательная деталь, можно дописать позже. Проверка показала: без точного описания-триггера скилл с любым качественным содержанием не сработает вообще. И интуиция подводит не единственный раз: разовое одобрение скилла превращается в постоянные права на исполнение кода.

**Мостик:** всё, что добавлялось до сих пор, жило внутри репозитория — файлы, которые агент читает сам. Следующая боль — первая, которую нельзя закрыть файлом внутри репозитория.

## Speaker notes

Ступень четыре — скилл. На оси: решаем, реактивно — файл инструкций уже платит налог за процедуру, которая нужна не всегда, сигнал уже прозвучал.

Интуиция здесь ошибалась дважды. Первый раз казалось: важно содержание скилла, описание — деталь, можно дописать потом. Проверка показала обратное: без точного описания-триггера скилл с любым содержанием не сработает вообще, модель выбирает по описанию, а не по факту того, что внутри. Второй раз казалось: скилл в худшем случае просто ошибётся или промолчит. Проверка показала — это исполняемый код с правами, которые выдаются один раз и живут неопределённо долго.

Посмотрите на дерево репозитория: продуктовый слой, файл инструкций, барьер на коммит, и теперь — процедура, что грузится по требованию. Всё, что добавляли до сих пор, жило внутри проекта. Следующая боль — первая, которую нельзя закрыть файлом внутри репозитория. Ступень пятая.
