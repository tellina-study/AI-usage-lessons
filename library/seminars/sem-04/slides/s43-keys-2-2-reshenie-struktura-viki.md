# Одно решение — один файл, ссылку пишет инструмент

## Assertion

Практика ADR («Architecture Decision Record», запись об архитектурном решении): одно решение — один нумерованный файл, а связь между решениями — строка в разделе `Status`, которую инструмент проставляет сразу в обе стороны.

## Visual

Слева — каталог решений:

```
doc/adr/
  0001-record-architecture-decisions.md
  ...
  0031-storonnie-vidzhety-ne-dobavlyaem.md
  ...
  0187-antispam-honeypot-bez-kapchi.md
  README.md   ← оглавление, его печатает `adr generate toc`

  0031 — та же запись, что в кейсе 2.1:
  она переехала сюда из DECISIONS.md
```

Справа — ноябрьская запись целиком, по шаблону:

```markdown
# 187. Антиспам — honeypot-поле, без капчи

Date: 2026-11-28

## Status

Accepted

Amends [31. Сторонние виджеты в форму не добавляем]
       (0031-storonnie-vidzhety-ne-dobavlyaem.md)

## Context
На форму пошёл спам. Капча — сторонний виджет, запрещённый
решением 31, и она роняет конверсию формы.

## Decision
Скрытое honeypot-поле. Сторонние виджеты по-прежнему не добавляем.

## Consequences
Третьих сторон в форме нет, конверсия не страдает.
Примитивных ботов отсекает, целевой спам — нет.
```

Полоса внизу, в gold-рамке:

> `adr new -l "31:Amends:Amended by" …` — и в файле 31 появилась встречная строка `Amended by [187. Антиспам — honeypot-поле, без капчи](0187-antispam-honeypot-bez-kapchi.md)`. Обе ссылки написал инструмент, а не автор записи.

Подпись-источник: «Практика Architecture Decision Record — Майкл Найгард, 2011; шаблон, разделы и команды — `adr-tools`. Technology Radar Thoughtworks: кольцо Adopt с 2016 года. Сила доказательства: задокументированная и широко применяемая практика **для людей**; контролируемого измерения «ADR помогают кодинг-агенту» нет. Содержимое записей — иллюстративное.»

## Speaker notes

«Структуру здесь не изобретали — взяли готовую. Записи об архитектурных решениях, ADR, описаны Майклом Найгардом в 2011 году, и у практики есть эталонный набор команд — `adr-tools`. Устройство ровно такое, как на слайде.

Одно решение — один файл: четырёхзначный номер по порядку плюс название через дефисы. Внутри — заголовок с номером, дата и четыре раздела: `Status` (статус), `Context` (что вынудило решать), `Decision` (что решили), `Consequences` (что станет проще, а что сложнее).

Главное для нашего случая — раздел `Status`: кроме статуса там лежат ссылки на другие решения. В ноябрьской записи стоит `Amends` — «уточняет» — и ссылка на сентябрьскую; в сентябрьской инструмент дописал встречную строку `Amended by`. Это и есть то, чего в плоском логе не было: агенту, открывшему сентябрьское решение, больше не нужно дочитывать файл до конца — ссылка на ноябрьское уточнение стоит прямо в нём.

Ключевое слово — «инструмент дописал»: ссылку в обе стороны ставит команда, а не дисциплина автора. Флаг `-s` означает «отменяет» и переводит старую запись из `Accepted` в «отменено записью такой-то»; флаг `-l` просто связывает, статуса не трогая. У нас второй случай — ноябрьское решение не отменяет сентябрьское, а уточняет его для одного вопроса. Оглавление тоже не ручное: `adr generate toc` печатает список всех записей со ссылками, его кладут в `README.md`.

Честно про силу доказательства: это практика для людей. Она задокументирована с 2011 года и широко применяется — в работе 2026 года из открытых репозиториев набрали больше четырёх с половиной тысяч ADR из семисот пятидесяти проектов. Но контролируемого измерения «ADR помогают кодинг-агенту» нет ни одного. Содержимое наших двух записей — иллюстративное. Снимок демо-репозитория существует — каталог `doc/adr/`, коммит `3b4b289`, — но он про другую сцену: записей там три, встречной пары `Amends` / `Amended by` между ними нет, а сам `adr-tools` не устанавливался, поэтому оглавление там написано руками. Структура, разделы и формат строки связи — из шаблона и исходников `adr-tools`, не выдуманы.»
