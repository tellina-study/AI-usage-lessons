# Настоящие панели: один фильтр — вся разница

## Assertion

Левый узел считает косинусное сходство по всем документам индекса. Правый — делает ровно то же самое, но одной строкой раньше отфильтровывает документы чужого курса из списка кандидатов.

## Visual

> `const scopedDocs = d.docs.filter(doc => doc.course_id === d.course_id);` — эта единственная строка (и замена `docs` на `scopedDocs` в сортировке по сходству ниже) отличает код «со скоупингом» от кода «без скоупинга» слева. Функция `cos()`, подсчёт сходства и выбор top-1 — буквально тот же код в обоих узлах.

## Speaker notes

Это настоящие панели параметров обоих code-узлов, развёрнутые полностью, не сжатый предпросмотр — то же устройство экрана, что уже показывали узлы с кодом в предыдущих кейсах этого и прошлого занятия.

Слева — узел «Поиск без скоупинга». Он разбирает JSON из формы, достаёт эмбеддинг вопроса и эмбеддинги обоих документов из ответа модели, считает косинусное сходство вопроса с каждым документом функцией `cos()` и выбирает тот, у которого сходство выше, — без единого условия на то, какому курсу документ принадлежит.

Справа — узел «Поиск со скоупингом». Код начинается с того же входного объекта, что оставил предыдущий узел, и первым делом, до всякого сравнения по смыслу, отфильтровывает список документов: остаются только те, чей `course_id` совпадает с курсом, с которого пришёл вопрос. Дальше — та же самая функция `cos()`, тот же самый перебор и выбор ближайшего, но уже по суженному списку. Строка фильтра стоит явным комментарием в коде: «единственное отличие от узла «без скоупинга»: фильтр по course_id применён ДО ранжирования — чужой курс даже не входит в кандидатов».

Это и есть буквальное, не метафорическое подтверждение архитектурного тезиса предыдущего такта. Решение не вводит новый узел с ветвлением логики и не меняет модель эмбеддинга или формулу сходства ни на йоту — оно добавляет ОДИН дополнительный шаг фильтрации перед тем же самым сравнением, которое уже было. В терминах реального n8n-хранилища (не самодельного code-узла, который здесь используется для прозрачности вычислений) это выглядело бы ещё проще — как одно дополнительное поле `Metadata Filter` на узле хранилища — не отдельный узел вовсе. Здесь это показано явным кодом ровно для того, чтобы разница была видна буквально, построчно — не спрятана внутри готового компонента. Что показывает этот фильтр на реальном прогоне — следующим тактом.
