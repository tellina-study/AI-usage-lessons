# Не каждая процедура просит скилла

## Assertion

Процедура просит скилла не всегда: там, где она нужна каждой сессии, одноразова или где правило нельзя нарушить ни разу, — ещё рано; а набор скиллов «про запас» не рано, а измеримо вредно.

## Visual

| Здесь ещё рано | Здесь не нужно вообще |
|---|---|
| нужна каждой сессии — тело грузится почти всегда, а сверху добавлен шаг угадывания → строка в файле инструкций | скилл из непроверенного реестра — установка чужого кода с постоянными правами → обойтись своим файлом |
| процедура одноразовая — дешевле один раз попросить обычным запросом → запрос; оформлять по факту повторения | скилл вместо описания проекта — знание о структуре выводимо за секунды → README |
| правило нельзя нарушить ни разу — скилл остаётся знанием, которое агент может не учесть → хук | набор «про запас» — падает точность выбора, а не цена контекста → ставить по факту нужды |
| нужен отдельный бюджет контекста — скилл делит то же окно → субагент, ступень 6 | |

- −21% успеха при 202 скиллах — те же задачи и тот же агент; падает точность выбора, цена контекста остаётся маленькой.
- Мерка прежняя: считаем загрузки, которые ничего не вернули, а не строки файла.

## Speaker notes

**Слева — четыре ситуации, где скилл правильная вещь, но ещё рано.**

Нужна каждой сессии: тело всё равно грузится почти всегда, выигрыша нет, а шаг угадывания «совпадёт описание или нет» добавился. Честнее строка в файле инструкций.

Одноразовая: дешевле один раз подробно попросить. Официальная рекомендация прямая — сначала пройти задачу без скилла и только по факту повторения решать, что оформлять.

Нельзя нарушить ни разу — это хук: скилл остаётся знанием, которое агент может и проигнорировать.

Нужен изолированный бюджет контекста — это субагент. Скилл делит то же окно: он решает «не грузить, пока не нужно», а не «слишком много в одном окне».

**Справа — три, где скилл не нужен вовсе.** Чужой реестр мы только что разбирали. Описание проекта выводится за секунды и живёт в README.

И последнее, самое неочевидное: желание поставить набор заранее — не нейтральная привычка. При двухстах скиллах падение успешности доходит до двадцати одного процента, на тех же задачах и том же агенте. Падает точность выбора, а не цена контекста — она остаётся маленькой. Количество установленных скиллов не сигнал качества, это сигнал будущей проблемы выбора.

Мерку стоит повторить вслух, она же была на разборе: считаем загрузки, которые ничего не вернули, а не строки.
