## Корпус и вопросы — буквально корпус Кейса 2 Семинара 10, не пересобран

60 документов SberQuAD (`validation`, длина ≥500 символов, `seed=7`, тот же offset-фильтр,

## Шесть версий резки — последовательная итерация, не параллельный A/B

| Версия | Что делает |
|---|---|
| v1 | Baseline Семинара 10 — резка по границам предложений, `chunk_structural`, target=180 символов (буквально та же функция, что `case2_chunking.py`/`case2_e2e_measure.py` С10) |
| v2 | Иерархическая / parent-document: дети — `chunk_structural`, target=90 (половина v1); родитель — весь документ целиком (в этом корпусе у документа нет третьего уровня иерархии — упрощение названо прямо в разделе главы) |
| v3a | Семантический чанкинг, порог = 90-й процентиль разрыва эмбеддингов соседних предложений по всему корпусу (щадящий — режет редко) |
| v3b | Семантический чанкинг, порог = 40-й процентиль (умеренно агрессивный) |
| v3c | Семантический чанкинг, порог = 10-й процентиль (сверхагрессивный) |
| v3d | Семантический чанкинг, порог ниже минимального разрыва корпуса — режет на каждой границе предложения без исключения (вырожденный предел той же оси, не новая ось) |

Все шесть версий измерены в ОДНОМ прогоне (не смешиваются числа из разных сессий замера), K=1:
эмбеддинг вопроса → поиск top-1 кусочка по косинусному сходству среди кусочков ВСЕХ 60
документов (не только «своего») → для v2 подмена найденного ребёнка на родителя (весь документ)
перед передачей модели → `gpt-4o-mini` отвечает по этому одному кусочку/документу → строгая
проверка вхождения эталонного ответа (`harness2.contains_answer`, та же функция, что Кейс 1/2
С10).

`notes/decisions.md` №33 про общий риск параллельного `stend/`, сама путаница с номером прогона
— отдельный урок, не внесённый туда отдельной записью, т.к. относится к этой же сессии, не к
инфраструктуре). Полный разбор, honest-вывод по неровности точности на агрессивных порогах и
сопоставление с цифрой брифа (Vectara/arXiv 2410.13070) — в разделе главы
(`library/seminars/sem-11/rework/section-2-prodvinutyi-chankirovaniye.md`), не повторяется
здесь. Короткая сводка: иерархия (v2) даёт самый большой и самый дёшево устроенный выигрыш
(+13,9 п.п. точности к v1, без единого вызова эмбеддинга сверх уже нужного для поиска);
семантический чанкинг (v3a–v3d) обгоняет v1 на всех четырёх проверенных порогах (от +2,8 до
+8,3 п.п.), но ни на одном не обгоняет v2 — направление брифа («умнее не значит лучше»)
подтверждено этим фактом, а не числом: прямого пересечения «семантика хуже v1» на этом корпусе
не найдено, и это сказано прямо, не подогнано. Структурная метрика (доля целых ответов) падает
монотонно с учащением резки; итоговая точность ответа идёт в целом в ту же сторону, но не по
прямой линии (минимум на p40, не на самом агрессивном пороге) — разбор этой неровности, тоже
честно названной, а не сглаженной, — в разделе главы.

## Объём реальных вызовов

Финальный прогон (с v3d): **432 вызова `gpt-4o-mini`** (6 версий × 72 вопроса, K=1) + **23
batch-вызова `openai/text-embedding-3-small`** (вопросы, 330 эмбеддингов предложений для
вычисления разрывов, плюс эмбеддинг пулов кусков v1/v2-дети/v3a/v3b/v3c/v3d) — все через
`s10-raw-openrouter`. Полный прогон (concurrency до 12 параллельных LLM-вызовов) — **112,1 с**
wall-time. Суммарная стоимость эмбеддингов — **$0,0025**; стоимость LLM-вызовов — в пределах
`avg_cost_usd × n` на каждую версию в `case2-results.json` → `summary` (порядка $0,0003–0,0007
на версию, 72 вопроса).

**Execution id (сэмпл, полный список — `case2-results.json` → `details[].exec_id`):**
первый вызов финального прогона — `10649`, последний — `11095` (432 последовательных
execution-id вебхука `s10-raw-openrouter` на этом прогоне, диапазон подряд — признак того, что
между стартом и финишем прогона никто другой этот же вебхук не дёргал).
