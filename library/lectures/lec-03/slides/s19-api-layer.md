## Body
[3 равные карточки в Ocean rounded box, по одному тезису]

**Structured output**
модель обязана вернуть ответ строго по схеме (JSON), а не свободный текст
→ выход = **валидные данные, не текст для парсинга** → модель *встраиваемая*

**Function calling** *(вызов функций / инструментов)*
модель возвращает «вызови инструмент X с аргументами Y»; **исполняет ваш код, не модель**
→ модель *активная* в системе

**Prompt caching**
переиспользовать вычисленное состояние неизменного префикса
→ не переплачивать за повторяемую часть → модель *экономически жизнеспособная*

## Speaker notes

Чтобы AI стал частью системы, нужны три механизма. Разберём каждый на уровне одного тезиса; полный разбор, граница ответственности и приватностное следствие остаются в главе и дополнительных материалах.

Первый — structured output, структурированный вывод. Режим, в котором модель обязана вернуть ответ строго по заданной схеме, например JSON, а не свободный текст. Технически схема компилируется в ограничение на сэмплинг: на каждом шаге допустимы только токены, не нарушающие схему, поэтому модель не может выдать структурно невалидный ответ. Это превращает выход из текста, который надо парсить регулярками, в данные, гарантированно валидные по форме. То есть structured output делает модель встраиваемой. Тонкость: гарантируется валидность формы, но не содержания — поле может быть фактически неверным.

Второй — function calling, вызов функций или инструментов. Модели описывают набор доступных инструментов, и модель вместо ответа текстом может вернуть запрос «вызови инструмент X с аргументами Y». Дальше внешняя система, ваш код, а не модель, исполняет вызов, и результат возвращается модели в контекст. Принципиально: модель не исполняет ничего сама — она формулирует намерение; исполнение и его границы на стороне вашего кода. Это делает модель активной и будет ключевым для безопасности дальше в разделе.

Третий — prompt caching, кэширование префикса. Переиспользование уже вычисленного внутреннего состояния модели для неизменной начальной части промпта, чтобы не пересчитывать её каждый раз. Кэшируется состояние префикса, а не текст ответа: модель по-прежнему генерирует ответ заново. Это делает модель экономически жизнеспособной при объёме, и именно кэширование делает full-context для малого стабильного корпуса реальным конкурентом RAG. Соберём: structured output — встраиваемость, function calling — активность, prompt caching — экономическая жизнеспособность. Но ни один из трёх не делает модель надёжнее или аудируемее: они расширяют то, что модель может делать, не меняя её недетерминированной природы. Переход на этот слой не отменяет правило лестницы, а лишь даёт техническую возможность подняться выше — решение по-прежнему за инженером и требует требования задачи.
