# Тридцать три события, одно в работе

## Assertion

Хук использует одно из тридцати трёх событий жизненного цикла агента — и срабатывает не тогда, когда модель решила вызвать инструмент, а после того, как она уже сформировала его аргументы.

## Visual

| Группа | События |
|---|---|
| Сессия целиком | SessionStart, SessionEnd, Setup |
| Каждый ход | UserPromptSubmit, UserPromptExpansion, Stop, StopFailure |
| **Вызовы инструментов** | **PreToolUse**, PostToolUse, PostToolUseFailure, PermissionRequest, PermissionDenied, PostToolBatch |
| Уведомления/интерфейс | Notification, MessageDisplay |
| Команда агентов | SubagentStart, SubagentStop, TaskCreated, TaskCompleted, TeammateIdle |
| Файлы/окружение/worktree | FileChanged, CwdChanged, DirectoryAdded, WorktreeCreate, WorktreeRemove |
| Конфигурация | ConfigChange, InstructionsLoaded, PreCompact, PostCompact |
| Модель | PreModelSwitch, PostModelSwitch |
| MCP-элиситация | Elicitation, ElicitationResult |

Ядро для агента-кодера: `PreToolUse` (до вызова) · `PostToolUse` (после) · `Stop` (перед завершением) · `SessionStart` (начало сессии).

`PreToolUse` срабатывает после того, как модель уже сформировала аргументы вызова, и до того, как харнесс начал сам вызов обрабатывать.

Три факта: хуки разных уровней настроек складываются, а не перекрываются; явный `deny` в правах побеждает всё, включая хук, вернувший `allow`; `PreToolUse` срабатывает в любом режиме разрешений, включая `bypassPermissions`.

## Speaker notes

Барьер уже стоит, все три кадра уже видели. Прежде чем разбирать, где он не срабатывает, — несколько слов о том, что вообще значит «сработать».

В Claude Code тридцать три события жизненного цикла агента — не «больше тридцати», ровно тридцать три, число пересчитано дважды по официальной документации: первый проход дал ошибочные тридцать четыре, сумма по группам не сошлась со списком, второй, построчный, дал тридцать три, и это совпало. Хук ступени использует одно из тридцати трёх. Ядро, с которого стоит начинать в любом реальном проекте, — четыре события: `PreToolUse`, который только что собран, `PostToolUse` для реакции после — линт, форматирование, `Stop` — проверка перед тем, как агент объявит себя закончившим, и `SessionStart` — подгрузить контекст в начале сессии. Остальные двадцать девять — не про сборку агента-кодера: элиситация MCP-сервера, автоматизация git worktree, мультимодельные пайплайны, командный режим с несколькими агентами.

Важная деталь про `PreToolUse` конкретно. Хук срабатывает после того, как модель уже сформировала конкретные аргументы вызова — для нашего хука это готовая строка bash-команды, — и до того, как харнесс начал сам вызов обрабатывать. Не «до того, как модель решила»: модель уже решила и уже написала команду. Хук фильтрует один вызов в изоляции — не видит, что будет после, и не видит другие вызовы той же пачки, если Claude Code выполняет несколько инструментов параллельно.

Острая кромка `git switch … && git commit …`, уже записанная правилом в `CLAUDE.md`, — прямое следствие этой же точки: хук получает вызов целиком одной строкой, но состояние ветки читает в момент своего запуска, до того как составная команда реально выполнится.

И последнее на сейчас: если есть и личный хук в домашней папке, и проектный на то же событие — сработают оба, списки складываются, а не перекрываются. Явный запрет в правах побеждает всё, включая хук, который сказал «разрешаю». Хук с кодом возврата два побеждает разрешение в правах, но не запрет. И хуки на `PreToolUse` срабатывают в любом режиме разрешений, включая режим без запросов подтверждения, — сам режим факт срабатывания не отключает. Это пригодится через несколько минут, когда будем разбирать провалы.
