# Обошли, промолчал, или просто не увидел

## Assertion

Хук может отказать тихо даже написанный правильно, может приехать с чужим репозиторием уже скомпрометированным, и в любом случае не видит человека, который набрал команду в обход агента — сработал не значит принудил.

## Visual

**1. Конфигурация — чужой исполняемый код.** Задокументированная уязвимость подделки служебного файла git worktree заставляет харнесс считать папку доверенной и выполнить хуки из чужого `settings.json` **без диалога доверия вообще** (CVSS 7,7–8,8).

**2. Тихий отказ — по силе тишины:**
- Сломан весь файл целиком → в интерактивной сессии **не тихо**, диалог виден сразу
- Опечатка в одной записи (имя события, регистр, matcher) → тихо всегда, только через `doctor`
- Таймаут → тихое разрешение
- Узкий matcher (`Edit|Write`) при вызове `Bash` вместо правки → не режим виноват, а ширина условия
- Хук во frontmatter субагента может не сработать вовсе при идентичном хуке в общих настройках

**3. Человек и субагент.** `PreToolUse` — событие жизни **агента**; человек в отдельном терминале для харнесса не существует. Хуки уровня настроек срабатывают и внутри субагента — но зафиксированы два независимых случая, где `deny` вынесен, а команда всё равно выполнилась.

> «Когда гейт не срабатывает, не происходит ничего — а именно так выглядит и успешно пройденный гейт.»

## Speaker notes

Первое: конфигурация — это исполняемый код, который приезжает вместе с чужим репозиторием. Задокументированная уязвимость подделывает служебный файл git worktree так, что харнесс решает: папка уже доверена, — и выполняет хуки из чужого файла настроек без единого показа диалога доверия. Разница с более ранней версией той же проблемы принципиальна: там диалог хотя бы появлялся на экране, просто хуки успевали отработать раньше. Здесь диалог не появляется вовсе.

Второе: хук может отказать тихо, даже если написан правильно, — и тут стоит различать две категории тишины, а не одну. Сломан весь файл настроек — здесь, в интерактивной сессии, тишины вообще нет: диалог ошибки настроек виден сразу, тихо это только в фоновом прогоне без интерфейса. По-настоящему тихо — когда ошибка меньше и сидит в одной записи: опечатка в имени события, не тот регистр в `matcher`. Тогда падает только эта запись, остальной файл работает как ни в чём не бывало, и сигнала нет нигде, кроме `claude doctor`.

К этой, по-настоящему тихой категории — ещё две находки. Первая: у части моделей режим без запросов подтверждения повышает шанс, что агент вызовет команду оболочки вместо выделенного инструмента правки — и хук, привязанный именно к этим инструментам, такой вызов не увидит. Но `PreToolUse` при этом срабатывает в любом режиме разрешений без исключения — дело не в режиме, а в том, какой инструмент агент фактически вызвал: matcher не совпал, хук не отключился. Вторая: хук, объявленный в настройках отдельного субагента, может не сработать вовсе, хотя идентичный хук в общих настройках проекта — срабатывает. Запомните формулировку: когда гейт не срабатывает, не происходит ничего — а именно так выглядит и успешно пройденный гейт.

Третье — и это стоит сказать медленно, потому что интуиция здесь обманывает надёжнее всего. `PreToolUse` — событие в жизни агента. Харнесс генерирует его перед тем, как модель вызывает инструмент. Человек, который откроет отдельный терминал и наберёт `git commit` руками, не вызывает никакого инструмента харнесса — для харнесса этого действия попросту не существует. Формула «правила в коде — законы» остаётся верной строго для агента. Для человека, действующего в обход агента, тот же самый хук — не закон и даже не просьба: он его просто не видит.

И четвёртое, тот же вопрос ещё раз, но уже без человека — внутри субагента. Задокументировано прямо: хуки уровня настроек срабатывают и на вызовы инструментов внутри субагента. Но «срабатывает» не равно «принуждает»: есть два независимых, до сих пор не разрешённых сообщения, где хук внутри субагента корректно вынес решение «запретить» — а команда всё равно выполнилась. Тот же тезис, ещё один слой: сработал — не значит принудил.
