# Требования кейса D к корпусу фотографий (кейс B)

Опыт D: один и тот же набор текстовых запросов прогоняется тремя способами поиска —
по словам описаний, по смыслу описаний (текстовый эмбеддинг), по эмбеддингам самих
картинок — плюс гибрид. Метрика — доля запросов, где верная фотография найдена первой
(recall@1), отдельно по классам запросов. Отсюда каждое требование ниже.

## 1. Объём

**30–60 фотографий.** Нижняя граница 30 — шаг метрики 1/30 сопоставим с прежними
замерами занятия (все четыре стояли на 30 единицах), и случайное угадывание (1/30 ≈ 0,03)
достаточно далеко от рабочих чисел. Верхняя 60 — локальный прогон эмбеддингов на CPU
(~2 с/картинка) держит без боли. Больше не нужно.

## 2. Трудные негативы — главное требование

**Не меньше 6 групп по ≥3 фотографии «похожие, но не те»**: один тип сцены или объекта,
разные экземпляры/ракурсы/дни (одна и та же аудитория в разные дни; три разных
огнетушителя; несколько стендов с объявлениями). Корпус из 30 попарно непохожих
фотографий даст recall@1 ≈ 1 у всех трёх методов — сравнивать будет нечего
(это же требование уже названо в PEREDELKA §6 последней фразой).

## 3. Запросы с известным правильным ответом

**Три класса, по 12–15 запросов в классе** (итого 36–45), у каждого запроса — ровно одна
верная фотография, и эта единственность проверена по разметке до прогона (аналог
`case3_ceiling_check` прежнего замера):

1. **«Слово из описания»** — формулировка, которая почти наверняка совпадёт со словами
   сгенерированного описания (проверяется после генерации описаний в B; запросы этого
   класса можно финализировать только тогда).
2. **«То же другими словами»** — смысл тот же, лексика другая (синоним, парафраз,
   обобщение: «место для тушения пожара» против «огнетушитель» в описании).
3. **«Деталь на фотографии»** — деталь, видимая на фото, но которую типовое описание
   скорее всего не упоминает (мелкий предмет на заднем плане, надпись, число предметов).
   Этот класс — единственный, где картиночный эмбеддинг может обыграть оба поиска по
   описаниям; без него опыт D не отвечает на вопрос владельца.

На каждый запрос — **список трудных негативов** (id фотографий из той же группы §2,
которые подходят под запрос «почти»). Запросы и ответы фиксируются до прогона, не
подбираются по результатам.

## 4. Разметка на фотографию

- id файла;
- **что видно** — список предметов/надписей/признаков руками (5–10 строк): из него
  строятся запросы классов 2–3 и по нему проверяется единственность ответа;
- id группы похожих (§2) либо «вне групп».

## 5. Язык

Описания и запросы — по-русски (язык кейса B). **На каждый запрос — английский перевод
в той же разметке.** Причина: текстовая башня открытых картиночных моделей (SigLIP/CLIP)
обучена на английском; картиночная ветка D ищет по английской форме запроса, и этот
перевод — измеряемая часть её цены. Свой прогон проверки русский-против-английского на
стенде я делаю сам и числа пришлю отдельно — требование к корпусу от этого не меняется.

## 6. Что кейс B передаёт кейсу D

- **Сами описания каждой фотографии** — в той форме (или формах), которую B выберет
  (свободное описание / заполненные поля), файлом с привязкой к id;
- **имя модели и промт**, которыми описания сделаны (канон С5 — числа D будут стоять
  на этих описаниях).

Без описаний B кейс D не может искать «по описаниям из предыдущих примеров» — это
зависимость порядка производства: замер D идёт после того, как B сгенерировал описания.

## 7. Контрольная точка на документах A

Тот же опыт на другом материале (PEREDELKA §6). От корпуса A нужно:

- **≥10 запросов** с единственным известным ответом: половина — буквальная строка из
  документа (стол словарного поиска), половина — смысловой вопрос без буквального
  совпадения;
- распознанный текст документов (его кейс A и так производит) с привязкой к id.

Ожидание, которое D проверит: на документах порядок методов из прежнего замера
(словарный ≫ эмбеддинги) либо удержится, либо перевернётся — оба исхода произносятся.

## 8. Люди и права — СНЯТО решением владельца 2026-11-24

Прежняя редакция («фотографии без узнаваемых людей; для опыта D люди не нужны вовсе»)
снята: владелец велел брать готовые размеченные наборы **с людьми** («у меня фотографий
готовых нет, попробуй найти какие-то готовые размеченные датасеты с людьми»). Пункты
1–7 не меняются. Следствие для дизайна опыта — запросы класса 3в строятся на предметах
и обстановке, не на приметах человека — решено и записано в `kejs-D-poisk.md` §4.

## Дополнения оркестратора 2026-11-24 (приняты)

- Разметку «что видно» (§4) пишет **человек, до и без чтения модельных описаний** —
  иначе опыт показывает согласие модели с собой. Хозяин — планировщик корпусов.
- Порядок закреплён: описания кейса B — вход замера D; замер D не стартует, пока B не
  выдал описания, имя модели и промт.
- Принятые корпуса: контроль A — FUNSD (199 форм, разметка поле→значение); источник
  фотографий B — вероятно Open Images V7 (готовых подписей к снимку нет — истина
  запросов остаётся нашей разметкой, на подписи набора дизайн не опирается).
