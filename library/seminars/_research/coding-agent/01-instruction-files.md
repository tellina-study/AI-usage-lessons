# Файлы инструкций агента: CLAUDE.md / AGENTS.md

## Резюме (8 тезисов)

1. Файл инструкций — это не «README для людей», а контекст, который движок агента *принудительно* подгружает в начало каждой сессии. Он не заменяет чтение кода, а сообщает то, что код не расскажет сам.
2. Три независимых источника (гайд Anthropic, документация Cursor, контролируемый эксперимент Gloaguen et al.) сходятся в одном принципе: **пишите только то, что агент не может вывести сам из кода**. Это единственный настолько подтверждённый вывод во всей теме.
3. Единственный известный RCT с настоящей веткой «файла нет вообще» (Gloaguen et al., arXiv:2602.11988) даёт неудобный результат: наличие файла *само по себе* статистически значимо не повышает успех задачи — кроме одного подтверждённого случая (репозиторий без другой документации, файл сгенерирован LLM: +2.7%). Зато стоимость и число шагов агента растут на 20–23% при любом файле.
4. Официальная позиция Anthropic (2026): цель — до 200 строк на файл; «раздутый CLAUDE.md заставляет Claude игнорировать ваши настоящие инструкции» — цитата из официальной документации, не догадка.
5. Instruction adherence (соблюдение инструкций) деградирует и с длиной сессии, и с плотностью инструкций: исследование IFScale (Jaroslawicz et al., arXiv:2507.11538) показало, что даже лучшие модели держат только 68% точности при 500 инструкциях, а комплаенс падает почти линейно с их числом.
6. Правило без механической проверки (хука, CI-шага, линтера) — «мёртвое» правило: сам файл-шаблон, который мы уже используем (`base-project-template`), формулирует это как «единственный самый нагруженный операционный урок» — и подтверждает реальным кейсом: в GitHub issue #42863 агент дословно игнорировал CLAUDE.md-правило, требующее подтверждения перед изменением файлов вне рабочей директории.
7. AGENTS.md — кросс-вендорный стандарт (донирован в Linux Foundation / Agentic AI Foundation в декабре 2025, заявлено >60 000 проектов, поддержан Cursor, Windsurf/Devin, Gemini CLI, Goose и Claude Code напрямую с версии 2.1.277). Но заявка о 60k+ не подтверждена независимо — это флаг `[НЕ ПОДТВЕРЖДЕНО]` из первоисточника.
8. Продвинутая дисциплина — не про добавление разделов, а про их обрезку: файлы реально растут только добавлением (медиана +57 слов/–15 слов за коммит по данным Chatlatanagulchai et al.), если ничего не следит за балансом активно.

## 1. Классическая база

**Что это такое.** Файл инструкций агента (`CLAUDE.md` для Claude Code, `AGENTS.md` как кросс-вендорный стандарт, `.cursorrules`/`.cursor/rules/*.mdc` у Cursor, `GEMINI.md` у Gemini CLI, `.goosehints` у Goose, Rules/Memories у Windsurf, Knowledge/Playbooks у Devin) — это markdown-файл, который движок агента **автоматически подгружает в начало каждой сессии**, до того как пользователь напишет первое сообщение. Это не документация «для людей потом» — это контекст, который тратит токены каждый раз и присутствует в разговоре независимо от того, читал ли его кто-то из людей вообще.

**Зачем он нужен.** У агента нет памяти между сессиями (если не считать отдельного механизма auto memory). Каждая сессия Claude Code начинается с чистого контекстного окна. Файл инструкций — единственный надёжный способ передать то, что вы бы иначе объясняли заново каждый раз: команды сборки, которые агент не угадает, нестандартные конвенции кода, специфику окружения, границы допустимых действий.

**Чем отличается от README.** README пишется для человека, который открывает репозиторий впервые и хочет понять «что это и как запустить». Файл инструкций пишется для агента, который **уже умеет читать код** — поэтому хорошая практика прямо запрещает дублировать в нём то, что агент выведет сам: структуру директорий, список зависимостей, архитектурный обзор. Официальная документация Claude Code формулирует это как таблицу «включить / исключить»: включать команды, которые агент не угадает, отличия от языковых конвенций по умолчанию, репозиторный этикет; исключать «всё, что Claude может выяснить, читая код», длинные объяснения и файл-по-файлу описания кодовой базы.

**Как агент его читает — иерархия.** У Claude Code это многоуровневая иерархия, загружаемая **от общего к частному**, так что более специфичный файл читается *последним* (то есть «ближе к текущему запросу» с точки зрения модели):

| Уровень | Расположение | Область действия |
|---|---|---|
| Managed policy (IT) | `/etc/claude-code/CLAUDE.md` и аналоги для macOS/Windows | вся организация, нельзя исключить |
| Пользовательский | `~/.claude/CLAUDE.md` | все проекты одного разработчика |
| Проектный | `./CLAUDE.md` или `./.claude/CLAUDE.md` | команда через git |
| Локальный | `./CLAUDE.local.md` (в `.gitignore`) | только текущий разработчик, текущий проект |
| Вложенный | `CLAUDE.md` во вложенных директориях | подгружается «на лету», когда агент открывает файлы в этой директории — не сразу при старте |

Все найденные файлы **конкатенируются**, а не перекрывают друг друга — противоречие между уровнями не «разрешается» автоматически, оно просто попадает агенту в контекст как есть, и агент может выбрать любую сторону произвольно (это прямо написано в официальной документации).

**AGENTS.md как кросс-вендорный стандарт.** Формат сформирован в августе 2025 (инициатива OpenAI при участии Google, Cursor, Factory), в декабре 2025 передан под управление Agentic AI Foundation (Linux Foundation) — одновременно с MCP и Goose. По данным вторичных источников (пресс-релизы, не подтверждено независимо через сам репозиторий) — свыше 60 000 проектов и 20+ инструментов. Claude Code читает `AGENTS.md` напрямую начиная с версии 2.1.277 — но **только если в проекте нет своего `CLAUDE.md`/`CLAUDE.local.md`** (по умолчанию `CLAUDE.md` побеждает, а не суммируется с `AGENTS.md`; чтобы читать оба, нужно явно выставить `claude-md-and-agents-md` в `/config`). Cursor читает вложенные `AGENTS.md` напрямую как альтернативу своему `.mdc`-формату; Windsurf/Devin занимают тот же функциональный слот собственными Rules.

## 2. Что реально кладут внутрь — таксономия

Самое сильное эмпирическое исследование здесь — Chatlatanagulchai et al., «Agent READMEs» (arXiv:2511.12884): вручную размечены 332 реальных Claude-Code-специфичных файла инструкций по 16 категориям содержания (подвыборка из общего корпуса в 2303 файла).

| Категория | Доля (n=332) | Комментарий |
|---|---|---|
| Тестирование/верификация | **75,0%** | самая частая категория из 16 |
| Репозиторный этикет (branch naming, PR-конвенции) | 63,3% | |
| Сборка/запуск | 62,3% | |
| Progress-tracking прямо в файле | 5,4% | вторая по редкости категория — это и есть доказательная база решения выносить дисциплину прогресса в отдельную `Tasks/`-директорию, а не в сам файл |

Структурные метрики по полному корпусу (2303 файла): медиана 6–7 H2-разделов на файл; медиана **+57 слов за коммит на добавление**, медиана **–15 слов на удаление** — файлы растут почти исключительно добавлением, если их не обрезают целенаправленно.

Реальный подтверждённый паттерн: `pytorch/pytorch/CLAUDE.md` (доступен также как `AGENTS.md` через git-симлинк) открывается разделом **«AI Policy — MANDATORY»** — это редкий, но реальный паттерн: раздел безопасности/границ ставится первым, а не в конец файла.

**Что даёт эффект.** Три источника (Anthropic, Cursor, Gloaguen et al.) независимо сходятся на одном принципе: писать только то, чего агент не выведет из кода сам. Развёрнуто в официальной таблице Anthropic:

| ✅ Включать | ❌ Исключать |
|---|---|
| Bash-команды, которые агент не угадает | Всё, что агент выведет, читая код |
| Стиль кода, отличающийся от дефолтов языка | Стандартные языковые конвенции |
| Инструкции тестирования и предпочитаемый test runner | Подробная API-документация (лучше ссылка) |
| Репозиторный этикет | Информация, которая часто меняется |
| Архитектурные решения, специфичные для проекта | Длинные объяснения и туториалы |
| Особенности окружения (обязательные env vars) | Самоочевидные практики вроде «пишите чистый код» |
| Неочевидные грабли и поведение | Файл-по-файлу описания кодовой базы |

**Что карго-культ.** «Обзор проекта» и «структура кодовой базы» — самые соблазнительные, но и самые бесполезные разделы: агент прочитает структуру за секунды через инструменты чтения файлов, а вот раздел устаревает при первом рефакторинге и начинает врать. Одноразовое исследование Gloaguen et al. напрямую это подтверждает численно: LLM-сгенерированные файлы, которые опираются на content вида «repository overview», **не дали измеримого выигрыша в успехе задачи**, при этом подняли стоимость на 20–23%.

## 3. Доказательная база и её честные границы

Здесь важно не переоценивать эффект — аудитория курса это заметит быстро.

**RCT наличия файла (Gloaguen et al., arXiv:2602.11988, ETH Zurich + LogicStar.ai, препринт).** Единственный найденный настоящий трёхплечевой эксперимент: NONE (файлы инструкций вычищены) / LLM-generated / DEV-written, метрика — реальный успех решения задачи (SWE-bench-style Python issues, 4 комбинации модель/агент).

| Плечо (vs. NONE) | Эффект на успех задачи | Значимость |
|---|---|---|
| LLM-generated | −0,5% | p = 87% (незначимо) |
| LLM-generated, вторая комбинация модель/агент | −2% | p = 37% (незначимо) |
| Developer-written | +2,4% | p = 21% (небольшой положительный эффект, незначимо) |
| Стоимость/число шагов, любое плечо с файлом | +20–23% | значимо |
| LLM-generated, **подвыборка: репозитории без другой документации** | **+2,7%** | подтверждённое исключение — обогнал даже DEV-written в этой подвыборке |

Честный вывод: **наличие файла само по себе не даёт статистически значимого прироста успеха задачи** — кроме случая, когда файл реально закрывает пробел в документации, а не дублирует то, что уже есть в репозитории. Это не повод отказаться от файла — это то же правило «пиши только невыводимое», сформулированное через результат, а не через контент.

**Длина и деградация комплаенса (McMillan, arXiv:2605.10039).** Байесовское факторное исследование в диапазоне 25–500 строк. Эффект длины на *единственную* измеренную инструкцию — нулевой результат (методологически более убедительный, чем обычный незначимый тест, но измерена только одна тривиальная, механически проверяемая инструкция — трактовать осторожнее, чем это делает вендорский фольклор). Более интересная, но менее обсуждаемая находка того же исследования: **деградация комплаенса ≈5,6% на каждую сгенерированную функцию внутри одной сессии** — с длиной файла это не лечится, это отдельная проблема управления сессией. Нулевое спонтанное появление инструкции: 0 из 1669 базовых наблюдений — агенты не изобретают соблюдение правила, которое никогда не было записано.

**Помогает ли ведение журнала задач.** Ближайшие настоящие абляции «с памятью / без» в литературе (ReasoningBank, SWE-MeM, Reflexion) дают сильные цифры (SWE-bench Verified: 37,6% без инструмента памяти → 43,4% с ним, −5,8 п.п.; Reflexion HumanEval pass@1: 80%→91%), но **ни одна не тестирует именно человеко-читаемый проектный журнал** через недели несвязанной работы — это смежное, а не прямое доказательство. Контраргумент: MEMORYARENA показал, что плоский контекст обгоняет структурированную память (но без настоящего контроля «без памяти» — отвечает на вопрос «какая память лучше», не «помогает ли ведение журнала вообще»); реальный GitHub issue `anthropics/claude-code#51735` документирует случай, когда зафиксированный урок из прошлой ошибки не помешал повторить ту же ошибку 25 дней спустя.

## 4. Провалы и ограничения (критично — часть блока)

### 4.1 «Раздутый файл» и налог на каждый запрос

Официальная позиция Anthropic прямая и недвусмысленная: *«Bloated CLAUDE.md files cause Claude to ignore your actual instructions!»* — цитата из раздела best practices, не парафраз. Рекомендация — целиться в **до 200 строк на файл**; более длинные файлы тратят больше контекста и снижают соблюдение. Файл-шаблон загружается **каждую сессию** — это буквально налог на каждый запрос, независимо от того, нужна ли инструкция именно сейчас.

Автор статьи «I Wrote 200 Lines of Rules for Claude Code. It Ignored Them All.» (dev.to, 2026) на личном примере: 200-строчный CLAUDE.md + 258 файлов базы знаний остались практически непрочитанными («write-only»). Попытки усилить комплаенс через детальные протоколы, «запрещённые фразы» и шаги верификации — все провалились. Вывод автора: *«Rules in prompts are requests. Hooks in code are laws»* — правила в промпте это просьбы, хуки в коде — это законы.

### 4.2 Context rot — деградация внимания на длинном контексте

Исследование Chroma (2025) протестировало 18 передовых моделей (включая GPT-4.1, Claude Opus 4, Gemini 2.5) на multi-hop reasoning в контекстах от 10 000 до 500 000 токенов: **все 18 моделей** показали монотонно убывающий F1 при росте длины входа — при каждом шаге увеличения. Три складывающихся механизма: (1) «затерянное в середине» — модель хорошо видит начало и конец контекста, но плохо середину (падения точности >30%); (2) размывание внимания — attention квадратичен по числу токенов, 100 тыс. токенов = 10 млрд попарных связей; (3) интерференция дистракторов — семантически похожий, но нерелевантный контент активно сбивает модель. Это **архитектурное свойство** attention-механизма трансформера, а не пробел в обучении, который решится следующей версией модели.

Практическое следствие для файла инструкций: он не существует в вакууме — он часть общего контекстного окна, и чем больше он сам плюс всё остальное (история диалога, вывод инструментов, файлы), тем хуже модель обращается с каждой отдельной инструкцией внутри него, включая ту, что написана в первой строке.

### 4.3 Instruction adherence — агент игнорирует правила

Исследование IFScale (Jaroslawicz et al., arXiv:2507.11538): бенчмарк из 500 инструкций про включение ключевых слов в бизнес-отчёт, протестированы 20 передовых моделей 7 провайдеров. **Даже лучшие модели держат только 68% точности при максимальной плотности в 500 инструкций.** Комплаенс падает почти линейно с числом инструкций из-за неизбежных внутренних конфликтов между растущим числом правил.

Реальный подтверждённый кейс — GitHub issue `anthropics/claude-code#42863` (закрыт как «not planned», апрель 2026): пользователь документировал конкретную сессию, где агент проигнорировал правило CLAUDE.md, требующее подтверждения перед доступом к файлам вне рабочей директории — выполнил `msiexec /i`, записал в `C:\Program Files`, зарегистрировал службы и изменил реестр без запроса. Правило про «не спрашивай „Soll ich...?“ — просто делай работу» тоже игнорировалось: агент регулярно всё равно задавал уточняющие вопросы. Root cause по мнению автора issue и подтверждённый в официальной документации Anthropic: **CLAUDE.md — это контекст, а не принудительная конфигурация**; Claude трактует его содержимое как контекст, который может проигнорировать, а не как жёсткое ограничение. Единственный механизм, который блокирует действие независимо от решения модели — `PreToolUse`-хук.

Отдельно задокументировано «затухание внутри сессии» (issue `#80873` по данным поиска, не проверен напрямую в этой сессии, оставляю как вторичный источник): правила вроде «отвечай коротко» соблюдаются первые несколько ходов диалога, а затем «расплываются» примерно к 5–10-му ходу.

### 4.4 Противоречивые правила

Официальная документация признаёт это прямо: если два правила противоречат друг другу — на уровне разных файлов иерархии, вложенных `CLAUDE.md` или `.claude/rules/` — Claude может выбрать любую сторону произвольно. Это не баг, это следствие того, что все найденные файлы конкатенируются, а не разрешаются в единую непротиворечивую конфигурацию.

### 4.5 «Правило без хука тихо умирает»

Формулировка из нашего собственного шаблона `base-project-template` (`with-git/CLAUDE.md`, раздел «Maintenance discipline»): *«Every rule in this file that's stated as binding/mandatory should have a mechanical check (a hook, a CI step, a lint rule) landing in the same change, or it should be labeled advisory. A rule with neither decays silently — this is the single most load-bearing operating lesson behind this template.»* Это подтверждается внутренним дневным опытом того же исследования: вручную устанавливаемый pre-commit хук (`cp` в `.git/hooks/`) простоял неустановленным 13 дней после реального bootstrap проекта, тогда как git-трекнутый `.claude/settings.json`-хук распространился без единого разрыва — отсюда и дизайн-решение: там, где правило действительно обязательное, оно должно жить как git-трекнутый хук, а не как строка текста, на исполнение которой полагаются.

### 4.6 Дублирование файла под каждый движок и дрейф между копиями

Шесть вендоров (Claude Code, AGENTS.md-стандарт, Cursor, Windsurf/Devin, Gemini CLI, Goose) независимо сошлись на одном функциональном слоте — «committed instruction file, читаемый в начале сессии» — но каждый со своим именем файла и форматом. Практический провал, который из этого следует: если поддерживать по копии на движок, копии расходятся. Официальная документация Claude Code явно предупреждает про подводный камень с симлинком на macOS: `cp -R` без флага `-P` **разыменовывает симлинк `AGENTS.md → CLAUDE.md` в реальную вторую копию**, молча воссоздавая проблему дублирования, против которой сам подход и был придуман. Рекомендуемая альтернатива копированию шаблона — `cp -a`, `git clone` или `git archive`.

Второй практический грабл того же семейства, задокументированный официально: Edit/Write-инструменты **отказываются писать через симлинк** — агент получает отказ и инструкцию редактировать файл-цель (`AGENTS.md`) напрямую, а не сам симлинк.

## 5. Критерии «здесь это не нужно»

- **Крошечный репозиторий / одноразовый скрипт.** Если структура проекта помещается в один экран и не требует нестандартных команд сборки — файл инструкций добавляет только налог на контекст без компенсирующей выгоды. Тот же RCT Gloaguen et al. подтверждает это косвенно: выигрыш файла проявляется только там, где он закрывает реальный пробел в документации, а не там, где заменить нечего.
- **Правило, которое реально должно быть жёстким ограничением, а не советом.** «Никогда не коммить напрямую в main», «никогда не трогай `payments/`» — это не то, что стоит доверять тексту в контексте: официальная документация прямо разделяет это на два разных механизма — Managed settings / хуки для принудительного применения и CLAUDE.md для поведенческого руководства. Правило без хука — де-факто просьба, а не гарантия.
- **Многошаговая процедура или контент, релевантный только для части задач.** Официальная рекомендация Anthropic: если пункт — это многошаговая процедура или касается только одной части кодовой базы, он должен уйти в skill (`.claude/skills/`, загружается по требованию) или в path-scoped rule (`.claude/rules/*.md` с `paths:` frontmatter, подгружается только когда агент открывает совпадающий файл), а не жить в файле, который читается в каждой сессии целиком.
- **Информация, которая часто меняется.** Официальная таблица исключений прямо называет это отдельным пунктом — «changes frequently» не должно быть в файле, который читается каждую сессию и быстро устаревает, начиная врать раньше, чем кто-то заметит.
- **Контент, который линтер уже проверяет механически.** Шаблон `base-project-template` формулирует это явно: если правило уже проверяется CI-линтером — не дублировать его текстом, указать на конфиг линтера.

## 6. Фишки для продвинутых

- **Бюджет инструкций в словах и строках.** Официальный таргет — до 200 строк на файл. Шаблон `base-project-template` формулирует это как два явных числа, которые должен зафиксировать сам проект: «context budget» (потолок ниже технического максимума движка — выше него сессия перечитывает весь контекст на каждом ходу) и «instruction budget» (сколько слов вообще грузится каждый ход — сам файл плюс всё, что он транслюдирует через `@`-импорты).
- **Вложенные `CLAUDE.md` для монорепо.** Файлы во вложенных директориях подгружаются не сразу при старте, а «на лету», когда агент читает файлы внутри этой директории — то есть можно держать `packages/api/CLAUDE.md` и `packages/web/CLAUDE.md` отдельно от корневого, и они не тратят контекст, пока агент реально не зашёл в эту часть кода. Для больших монорепо, где чужие правила из других команд попадают в контекст, есть `claudeMdExcludes` — можно исключить конкретные файлы по glob-паттерну. Референс из практики: у OpenAI Codex монорепо — 88 вложенных `AGENTS.md`, по одному на сервис/пакет (заявлено вторично, не проверено напрямую в этой сессии).
- **Symlink `AGENTS.md → CLAUDE.md` и подвох `cp -R` на macOS.** Официально рекомендуемый способ разделить один файл между несколькими движками — либо `@AGENTS.md`-импорт внутри `CLAUDE.md`, либо прямой симлинк `ln -s AGENTS.md CLAUDE.md`. На Windows симлинк требует прав администратора или Developer Mode, а git без `core.symlinks` чекаутит закоммиченный симлинк как обычный однострочный текстовый файл — то есть на клоне у коллеги на Windows файл инструкций внезапно окажется пустым. Рекомендация для кросс-платформенных команд — `@`-импорт вместо симлинка.
- **`@`-импорты.** Синтаксис `@path/to/file` внутри `CLAUDE.md` подтягивает содержимое файла в контекст при загрузке; поддерживается рекурсия до 4 уровней вложенности; парсинг пропускает markdown code span'ы и fenced code blocks — чтобы упомянуть путь текстом без импорта, надо обернуть его в обратные кавычки. Важный нюанс: импорт **не экономит контекст** — импортированный файл всё равно загружается целиком при старте сессии, это инструмент организации, а не сжатия.
- **Что происходит при компактификации контекста (`/compact`).** Корневой проектный `CLAUDE.md` **переживает** компактификацию: после `/compact` Claude Code перечитывает его с диска и заново внедряет в сессию. А вот вложенные `CLAUDE.md` из поддиректорий и path-scoped rules **не** перечитываются автоматически — они подгружаются заново только когда агент снова открывает файл, к которому они относятся. Если инструкция «пропала» после компактификации — вероятная причина: она была дана только в диалоге (а не в файле), либо это вложенное правило, которое ещё не сработало заново.
- **Дисциплина обрезки: файлы растут только добавлением.** Эмпирическая медиана по 2303 реальным файлам — **+57 слов на коммит за добавление против –15 слов за удаление** (Chatlatanagulchai et al.). Отсюда практика: при каждом изменении файла спрашивать не «что добавить», а «что теперь может уйти» — и держать причины прошлых решений не в самом файле, а в отдельном `DECISIONS.md` (append-only лог «почему», не «что»).
- **Автопроверка на раздутие.** С версии 2.1.206 команда `/doctor` в Claude Code сама предлагает урезания для закоммиченного `CLAUDE.md`: вырезает то, что агент выведет из кода сам (структуру директорий, список зависимостей, архитектурный обзор), и оставляет грабли, обоснования и конвенции, отличающиеся от дефолтов инструмента.
- **Auto memory как отдельный механизм рядом с файлом инструкций.** У Claude Code это два разных слоя: `CLAUDE.md` пишете вы (правила), auto memory пишет сам агент по итогам сессии (выводы и паттерны, основанные на ваших правках и подтверждениях). Индекс `MEMORY.md` грузится только первые 200 строк или 25 KB — что раньше сработает; агент сам получает напоминание сократить его, если он приближается к лимиту.
