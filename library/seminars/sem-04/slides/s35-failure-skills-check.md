# Провал: 12 из 13 скиллов курса без description

## Assertion

12 из 13 скиллов этого же курса не имеют фронтматтера с description — они физически не могут сработать по смыслу запроса.

## Visual

Таблица, перенесённая дословно из реальной проверки `head -5 .claude/skills/*/SKILL.md` по 13 директориям курса: колонка «Скилл» (build-deck, catalog-docs, compile-wiki, diagram-refresh, extract-links, impact-check, issue-from-change, pre-user-gate, publish-article, query-kb, reflect, sync-library, update-lecture), колонка «Есть фронтматтер» и колонка «Есть description» — «нет» везде, кроме строки pre-user-gate, где оба «да». Итоговая строка внизу, крупным шрифтом: «1 из 13 скиллов имеют YAML-фронтматтер с description».

## Speaker notes

Это не гипотетический пример — это проверка на материале того самого курса, в рамках которого идёт этот семинар. Тринадцать скиллов реально лежат в репозитории проекта. Команда простая: `head -5 .claude/skills/*/SKILL.md`, вывести первые пять строк каждого файла SKILL.md. Результат: у двенадцати из тринадцати файл начинается сразу с заголовка `# имя-скилла` — никакого фронтматтера, никакого description вообще. Единственное исключение — `pre-user-gate`, у которого есть YAML-блок с полями `name` и `description`, и именно description объясняет одновременно что делает скилл и когда он нужен: предгейтовый самоконтроль перед показом результата пользователю.

Практическое следствие прямое: двенадцать скиллов без description физически не могут сработать по смыслу запроса — модель их просто не увидит как релевантные, потому что нечему совпадать с задачей. Единственный способ их вызвать — явная команда через слэш, то есть человек должен заранее помнить имя скилла и вручную его позвать. Это ровно тот антипаттерн, который раздел называет по имени: скилл существует, но не работает так, как задуман, потому что первый, наименее затратный по токенам уровень — метаданные — не заполнен.

Второй слой провала — глубже, не про отсутствие триггера, а про то, что даже сработавший скилл может навредить. Исследование skill-induced failures, arXiv 2608.11888, нашло 307 подтверждённых случаев вреда от скиллов: 125 функциональных провалов, из которых 68,8 процента, это 86 из 125, — Task-Implementation Fault: кажущийся релевантным скилл заставляет агента реализовать требуемое поле, расчёт или формат вывода неправильно или пропустить его вовсе. Плюс 182 случая раздутия стоимости — до плюс 451 процента токенов на задачу на бенчмарке SWE-Skills-Bench. Скилл — не бесплатная страховка, а ещё один источник ошибки, который нужно проверять так же внимательно, как и любой другой код.
