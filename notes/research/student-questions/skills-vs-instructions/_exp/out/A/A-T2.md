# Почему подключённые инструменты удорожают контекст агента

**Date:** 2026-10-02 · **Issue:** #217-EXP

Каждый инструмент — это не просто ссылка, а **описание на естественном языке**: сигнатура, типы параметров, примеры вызовов, ограничения, side effects. При 50 инструментах этот "вспомогательный груз" может занять 15–25k токенов — чистый overhead, не относящийся к самой задаче.

Три механизма удорожания:

| утверждение | источник | тип |
|---|---|---|
| Каждый инструмент требует описания параметров и примеров; 50 инструментов ≈ 15k токенов | по памяти, теория контекстных окон LLM | механика |
| При фиксированном окне (128k) 15k на инструменты = 12% прямо на overhead | Claude context window scaling | расчёт |
| Агент с 50 инструментами хуже выбирает между ними (нужно прочитать всё описание); шум сигнал-носитель | общая теория выбора | гипотеза |

Агент вынужден «носить с собой» весь каталог в окне, даже если в текущей задаче нужны только 3–5. Решение: динамический отбор инструментов по контексту задачи (как `tool_use_budget` в Claude API) или явное фильтрование по intent.

## Что НЕ доказано

- Точное распределение когнитивной нагрузки ("выбор между 50 vs выбор между 5") — есть гипотеза, нет эмпирики.
- Как именно растёт ошибочность инструментов с числом доступных (монотонно? логарифмически?).
- Оптимальное число инструментов для заданного размера окна и задачи.
