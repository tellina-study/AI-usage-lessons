# Карта слайдов — Семинар 10

Таблица собрана из файлов слайдов, а не из плана: номер, блок, тип, заголовок экрана и минуты
взяты из фронтматтера и первой строки каждого файла. Границы блоков и кейсов — из
`rendered/deck-config.yaml` этого занятия (`razmetka`, `case_idx`).

Нумерация сквозная; буквенные хвосты в ней есть — `n72a` и `n76a`–`n76d`. Они оставлены
сознательно: сплошная перенумерация правит ссылки на номера кадров в служебных полях соседних
блоков, а эти блоки правит параллельная сессия. Четвёртое занятие дуги (`sem-07/KONTSEPTSIYA-7-12.md`
§6): четвёртая ступень лестницы доверия к модели — «знание вне промта». С9 решил, может ли
процесс отвечать человеку сам; С10 меняет ставку дальше — база знаний, на которую процесс
опирается, больше не помещается в один вызов модели. Вопрос занятия («откуда процесс берёт
факты и почему считает их верными?») задаётся на n03 и получает ответ дословно второй раз на n81.

Формат ведения — тот же, что у С7-С9: на занятии ведущий ничего не редактирует в узлах n8n
вживую, только прогоняет уже готовые процессы. Слой 2 всех четырёх кейсов — настоящий скрин
живого холста стенда и настоящие снимки развёрнутых панелей узлов, снятые Playwright через
обход `~/.cache/page-shot-libs/x` (ограничение [#233-8] снято 2026-10-20, подтверждено на
этом занятии третий семинар подряд). Схемами нарисована только постановка задачи — сплошным
то, что уже собрано, пунктиром то, что в этом кейсе предстоит сделать (канон С1,
`tools/seminar-production/forma-keysa-s-zamerom.md`).

Четыре кейса стоят на собственных прогонах живого стенда: SberQuAD (открытый датасет
вопросов-ответов по статьям Википедии с эталонной разметкой) для Кейсов 1-3, CORD (открытый
датасет реальных чеков) для Кейса 4. Корпус Кейсов 1 и 3 пересобран 2026-11-01 по замечанию
владельца «текущий замер слишком лёгкий» (200→500 документов, путающие кластеры, классификация
вопросов кодом) — ось обоих кейсов развернулась или ужесточилась по факту этого доп. прохода, не
по ожиданию исходного плана. Кейс 4 переписан правкой issue #311 под один несущий разбор —
прямое сравнение картинок одной моделью, с классическим отпечатком контрастной линией рядом.
Рабочая модель найдена отбором: каталог эмбеддингов провайдера отдаёт 40 моделей, картинку
принимают 9, простую проверку «два разных входа дают разный выход» прошли 8, margin-тест был
поставлен 5 из них, прошли 2, в работу взята 1. На снимке под углом она держит recall@1 = 0,967
(29 из 30) против 0,233 у отпечатка; границы входа измерены по трём осям (сжатие, размер,
размытие), и на мелком или смазанном входе бесплатный отпечаток обгоняет её в 5,6–7,3 раза.
Два отрицательных результата показаны как есть, со своими числами: первая же найденная модель
отвечала без ошибки и возвращала одинаковый вектор для разных чеков, а слияние рангов,
выигравшее в Кейсе 3 на тексте, на картинках потеряло 11 сканов из 30. Полный протокол всех
прогонов — в `stend/raw/`.

Четыре строки оси занятия открываются пустыми на n03 и закрываются по ходу занятия — по одной на
кейс, предметной парой «выглядит надёжным / чем оказывается», не абстрактной радостью.
