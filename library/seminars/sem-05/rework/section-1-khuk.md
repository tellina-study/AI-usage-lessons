**Честный пробел.** Прямой численной базы для утверждения «правило файла инструкций
нарушается в стольких-то процентах случаев» не нашлось: контролируемый эксперимент на 1650
сессиях Claude Code (arXiv `2605.10039`) измеряет другое — затухание соблюдения на ~5,6% шансов
за каждую следующую функцию сессии, не исходную долю нарушений; смежное исследование конфликта
правил (arXiv `2605.27784`, 64,6% нарушений хотя бы одного из пары) — про столкновение **двух**
правил, не про одно однозначное правило вроде «не коммить в main». Обе цифры на этот слайд не
идут — это разные постановки задачи, а не более точная версия одного и того же числа.

### A.5. Разбор карточек

| Вариант | Где это работает | Почему здесь ещё рано — и что вместо |
|---|---|---|
| «Перепишу правило капсом» | Нигде механически: эмфаза не создаёт барьера | Это исходит из допущения, что агент правило **не заметил**. `#42863` — случай, где замечать было нечего: правило было прочитано и всё равно проигнорировано. Капс не превращает просьбу в закон — он делает её просьбой заглавными буквами |
| «Проверять руками после каждого коммита» | Пока хватает дисциплины и коммитов немного | Не масштабируется и отменяет смысл автоматизации: сторожем становится человек, который взял агента, чтобы не сторожить. Сторожем должна быть среда |
| «Защита ветки на сервере» | Работает, и это нужный слой: даже если локально прошло, на сервер не уедет | Не рано, но и не достаточно: обратной связи в момент действия нет — локальный коммит уже создан, о нарушении узнают при попытке отправки. Не «вместо», а вдобавок |
| **«Хук, который среда исполняет сама»** | Здесь — целевой ответ: исполняет среда, согласия агента не требуется | Не рано: правило уже нарушено, сигнал сработал. Ломается тихо при невалидном условии срабатывания или таймауте — это отдельный слой провала, §A.9–§A.10 |
| «Забрать у агента доступ к git» | Когда все коммиты делаются руками — осознанный выбор | Снимает риск вместе с пользой: это отказ от задачи автоматизации, а не её решение. Вместо — отнять одно движение, а не инструмент целиком |

Формулировка из `#42863`, которую стоит закрепить дословно: **правила в промпте — это просьбы;
правила в коде — это законы.** Дальше в разделе собирается закон.

### A.6. Совместное формирование хука: пять вопросов — пять строк

Хук не показывается готовым JSON-блоком с разбором постфактум — он собирается пятью вопросами
к залу; после каждого ответа на слайде проявляется соответствующая часть конфигурации.

**Вопрос 1. «Проверять до или после вызова?»** Целевой ответ — до. Фиксируется: событие
`PreToolUse`, срабатывает перед вызовом инструмента и может его не пропустить.

**Вопрос 2. «Вешаем на все инструменты или на один?»** Целевой ответ — на один, на выполнение
команд оболочки. Фиксируется: `"matcher": "Bash"`. Шире условие срабатывания — больше ложных
срабатываний и выше цена ошибки в самой логике хука, плюс латентность на каждый вызов.

**Вопрос 3. «Откуда хук узнаёт, какая именно команда сейчас выполнится?»** Здесь зал обычно не
угадывает — ответ механический: движок передаёт хуку описание предстоящего вызова в виде JSON
через стандартный ввод. Фиксируется: `jq -r '.tool_input.command'` плюс поиск `git commit` как
отдельной команды, а не подстроки.

**Вопрос 4. «Как узнать, на какой мы ветке?»** Зал называет привычное
`git rev-parse --abbrev-ref HEAD`. Здесь — реальный контрпример, воспроизведённый лично
25.09.2026 (`assets/captures/03-symbolic-ref-vs-rev-parse-unborn-head.txt`):

```
$ git init -q -b main
$ git symbolic-ref --short HEAD
main
(exit code: 0)

$ git rev-parse --abbrev-ref HEAD
fatal: ambiguous argument 'HEAD': unknown revision or path not in the working tree.
(exit code: 128)
```

На чистом `git init` без единого коммита `rev-parse --abbrev-ref` падает; `symbolic-ref --short`
корректно возвращает ветку. Фиксируется `symbolic-ref`. Падающая проверка не блокирует — она
просто не срабатывает, а не сработавший барьер выглядит точно так же, как сработавший и
пропустивший.

**Вопрос 5, кульминация шага. «А если это вообще ещё не git-репозиторий? Что должен вернуть
хук?»** Три варианта: `разрешить молча` · `заблокировать` · `спросить человека`.

- «Разрешить молча» — проверять действительно нечего, но тогда файл барьера лежит в
  репозитории, а барьера нет, и снаружи эти два состояния неразличимы.
- «Заблокировать» — честно, но парализует работу в ситуации, которая не является нарушением.
- **«Спросить»** — целевой ответ: хук возвращает решение «спросить» с явным предупреждением,
  что защита ветки сейчас неактивна.

Принцип, ради которого задавался вопрос: **гейт, чей отказ молчалив, не считается
установленным, пока его не заставили отказать громко.**

### A.7. Конкретное решение: что добавляется в репозиторий

`.claude/settings.json` в `signup-landing/` — реальный рабочий файл
(`assets/captures/29-code-settings.json.txt`), который действительно исполнялся:

```jsonc
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "jq -r '.tool_input.command' | { read -r cmd; if echo \"$cmd\" | grep -qE '(^|[;&|]\\s*)git\\s+commit\\b'; then if ! git rev-parse --is-inside-work-tree >/dev/null 2>&1; then echo '{\"hookSpecificOutput\":{…\"permissionDecision\":\"ask\"…}}'; exit 0; fi; branch=$(git symbolic-ref --short HEAD 2>/dev/null); if [ \"$branch\" = \"main\" ] || [ \"$branch\" = \"master\" ]; then echo '{\"hookSpecificOutput\":{…\"permissionDecision\":\"deny\"…}}'; exit 0; fi; fi; }",
            "timeout": 10
          }
        ]
      }
    ]
  }
}
```

Рядом с самим хуком в репозитории лежит его самотест, `.claude/hooks/selftest-branch-guard.sh`
(используется на слайде провала, §A.8), и в `CLAUDE.md` дописан второй за этот раздел раздел —
`## Хук защиты ветки`. Ниже — не пересказ, а дословная цитата (ветка `seminar-5-hook`, коммит
`9803643`, строки 28–39):

> `.claude/settings.json` — `PreToolUse`-хук, отклоняющий коммит прямо в `main`/`master`.
> Лежит в git, поэтому живёт в любом свежем клоне сам, без шага установки.
> `.claude/hooks/selftest-branch-guard.sh` проверяет, что он срабатывает, и печатает пять
> случаев, где он молчит. Правка `settings.json` — перезапуск самотеста.
>
> Это не гейт, а хук: гейт — строка текста, которую агент читает и может учесть; хук
> выполняется и отказывает. Правила в промпте — просьбы, правила в коде — законы.
>
> Кого он НЕ останавливает: человека в терминале. Это хук Claude Code, он срабатывает на
> вызовах инструментов агента; git-хук при этом не устанавливается, и `git commit` на `main`
> из обычной оболочки проходит. Шестой случай вдобавок к пяти, которые печатает самотест.

Формула «правила в промпте — просьбы, правила в коде — законы», которую зал уже слышал в §A.5
из `#42863`, — не совпадение и не повтор ради красоты: в этом репозитории она записана как
собственное объяснение самого хука, а не только как вывод занятия.

Файл `CLAUDE.md` дошёл до сорока строк, пяти разделов — это и есть состояние на выходе ступени
3, сверенное напрямую по ветке `seminar-5-hook` (`ARCHITECTURE.md` §2а). Дерево после этого
раздела — состояние из §A.1 плюс `.claude/settings.json` и
`.claude/hooks/selftest-branch-guard.sh`.

**Четыре реальных срабатывания подряд — все захвачены, ни одно не нарисовано:**

| Ситуация | Что вернул хук | Файл |
|---|---|---|
| Ветка `main`, попытка коммита | `deny`, дословно: «BLOCKED: direct commit to main/master. Create a feature branch first.» | `06-hook-deny-main.txt` |
| После `git switch -c fix-form-field`, тот же коммит | пустой вывод — не блокирует | `07-hook-allow-feature-branch.txt` |
| Тот же коммит реально выполнен | `[fix-form-field a666b27] fix: second form field`, файл закоммичен | `08-hook-commit-lands-on-feature-branch.txt` |
| Каталог без `git init` | `ask` с предупреждением «branch-protection gate inactive…» | `09-hook-ask-no-repo.txt` |

Третья строка здесь принципиальна: она показывает, что «разрешил» — не абстракция, коммит
действительно лёг. Без неё зал видит только запрет и не видит, что барьер узкий.

**Механика, которую стоит назвать вслух.** Хук — не git-хук: `.git/hooks/pre-commit` не
версионируется и требует ручной установки в каждом клоне; `.claude/settings.json` коммитится в
git и активен в любом свежем клоне без шага установки. Решение возвращается полем
`permissionDecision` (`allow`/`deny`/`ask`); отдельно — код возврата `2` блокирует безусловно,
даже если тот же хук вернул `allow` в JSON. Явный запрет в `permissions` всегда побеждает более
узкое разрешение. Списки хуков между уровнями настроек объединяются, а не перекрываются: личный
и проектный хук на одно событие сработают оба.

Таймаут по умолчанию для `PreToolUse` на `Bash` — 600 секунд; в собранном файле —
`"timeout": 10`. Автор хука сознательно урезал дефолт в 60 раз — деталь важна для §A.9: медленный
хук не становится строже, он тихо отключается по таймауту.

### A.8. Провал, слой 1 — обход именно этого хука

**Здесь — не гипотетический пример, а реальный прогон самотеста ровно этого хука, снятый из
опубликованной ветки; студент может склонировать репозиторий и повторить этот же прогон сам.**

`.claude/hooks/selftest-branch-guard.sh` лежит в том же репозитории, что и сам хук (ветка
`seminar-5-hook`, коммит `9803643`). Его реальный прогон —
`assets/captures/35-selftest-branch-guard-run.txt` (27.09.2026): **9 PASS / 5 LIMIT / 0 FAIL**.
Скрипт не просто проходит проверки — он сам печатает пять случаев, где ворота молчат:

| Форма / условие | Что должно произойти | Что происходит |
|---|---|---|
| `git commit -m "..."` на `main` (эталон) | `deny` | Срабатывает — это то, что показано в §A.7 |
| Дефолтная ветка названа не `main`/`master` (например, `trunk`) | `deny` | Проходит молча: сравнение веток жёстко на два имени |
| `git -C <path> commit -m "..."` | `deny` | Проходит молча: регэксп ловит только соседние слова `git` и `commit` |
| `/usr/bin/git commit -m "..."` | `deny` | Проходит молча: абсолютный путь — не буквальное слово `git` |
| `env git commit -m "..."` | `deny` | Проходит молча: любая команда-обёртка перед именем прячет коммит от регэкспа |
| `git commit` на второй строке многострочной команды | `deny` | Проходит молча: хук читает только первую строку stdin |

**База сравнения.** Хук написан, чтобы блокировать «прямой коммит в main/master» — одно
действие, любой синтаксис. Самотест воспроизводит эталонную форму и пять вариаций рядом:
сработала только эталонная, пять прошли молча — не потому что паттерн написан небрежно, а
потому что задача написать паттерн, ловящий **все** формы одной команды, структурно
невыполнима (см. ниже).

**Два дополнительных случая молчания**, зафиксированных тем же файлом самотеста со ссылкой на
официальную документацию: хук, превысивший заданный тайм-аут, не блокирует вызов — он просто не
успевает; отсутствующий в системе `jq` даёт тот же тихий отказ, что и намеренный обход.

**Почему это не лечится расширением списка.** `dubbl-a/house-rules#58` — структурное объяснение,
не догадка: POSIX-оболочка раскрывает слова и алиасы непосредственно **перед** выполнением
команды, то есть уже после того, как хук на `PreToolUse` увидел текст и принял по нему решение.
Хук не может увидеть финальную развёрнутую форму команды раньше, чем она исполнится. Расширять
паттерн на каждый новый найденный обход — это гонка с отрицательным ROI: пространство
синтаксических форм одной shell-команды больше, чем можно перечислить. Тот же класс grep-хука
защиты ветки независимо воспроизведён внешним адверсариальным тестом
(`workain/agent-harness-registry#65`, 20.09.2026) — подтверждающее, не основное свидетельство
этого слайда.

**Вывод для слайда.** Хук на `Bash` — фильтр на синтаксис одной команды в её нераскрытой
текстовой форме, а не на намерение и не на финальную исполняемую форму той же команды.
Для действительно чувствительного действия одного текстового фильтра недостаточно — нужен слой,
не зависящий от текста вообще (платформенный ruleset, git-хук, работающий уже после раскрытия
состояния).

### A.9. Провал, слой 2 — тихий отказ, конфигурация как код, слепое пятно к человеку

Три разных вопроса, три коротких пункта — не сливать в один: у каждого свой ответ и свой урок.

**«А что, если хук написал не я?»** `CVE-2026-40068` (CVSS 7.7 по вторичному источнику —
SentinelOne Vulnerability Database, не по первичной записи Anthropic; версии 2.1.63–2.1.83,
патч в 2.1.84): подделанный `.git/commondir` в git worktree заставляет харнесс решить, что папка
уже доверена, и выполнить хуки из чужого `.claude/settings.json` **без единого показа диалога
доверия вообще**. Это глубже базовой `CVE-2025-59536` (диалог доверия там хотя бы появлялся —
хуки успевали отработать раньше, чем он прогружался на экран); здесь диалог не появляется
вообще, потому что состояние доверия подделано заранее.

**«А что, если хук написал я, но он не сработал?»** К пяти известным причинам тихого отказа
(невалидный matcher гасит все хуки файла; удалённый или неисполняемый скрипт; несовпадение
регистра или незаякоренный шаблон; вызовы субагента не триггерят хуки родителя; таймаут — тихое
разрешение) добавляются две новых, подтверждённых после 20.09.2026: режим `bypassPermissions` на
части моделей подталкивает агента использовать `Bash` вместо `Edit`/`Write` — хук с
`matcher: Edit|Write` физически не видит вызов (`#92271`, эффект модельно-зависим); хук,
объявленный во frontmatter субагента, может не сработать вовсе, хотя идентичный хук в
`settings.json` для того же субагента срабатывает (`#95650`). Формулировка, которую стоит
оставить дословно: **«когда гейт не срабатывает, не происходит ничего — а именно так выглядит и
успешно пройденный гейт».**

**«А что, если хук сработал правильно — и всё равно ничего не защитил?»** `PreToolUse` — событие
жизненного цикла **агента**: харнесс генерирует его перед тем, как модель вызывает инструмент.
Человек, открывший отдельный терминал и набравший `git commit` руками, не вызывает никакой
инструмент харнесса — для харнесса этого действия попросту не существует. Формула «правила в
коде — законы» остаётся верной строго для агента; для человека, действующего в обход агента, тот
же самый хук — не закон и не просьба, он его просто не видит. Источник — не внешняя публикация,
а собственное наблюдение курса по итогам внешнего ревью Семинара 4 (`owner-questions.md`, п.5).
Тот же вывод независимо записан в самом репозитории — раздел `## Хук защиты ветки` в `CLAUDE.md`
(§A.7) называет это «шестым случаем вдобавок к пяти, которые печатает самотест»: наблюдение
курса и собственное описание артефакта совпадают буквально, а не только по смыслу.

### A.10. Критерии «здесь ещё рано» и «здесь не нужно вообще»

**«Здесь ещё рано»:**

- Проверку дешевле сделать один раз в сборке или линтере на pull request, чем гонять на каждом
  вызове интерактивной сессии.
- Хук становится тормозом раньше, чем это заметят как ошибку: практические измерения независимых
  проектов дают порядок величины от ~30 мс (простой bash-хук) до ~440 мс (хук с проверкой
  процессов через `ps`) на один вызов — те же хуки, с разницей ровно в проверку `ps`; в одном
  задокументированном случае p95 2,5 с на хук дал ~20 с суммарного ожидания за десять вызовов
  того же проекта до и после диагностики. Разрастание хуков не выдаёт сообщения — продуктивность
  снижается молча.
- Правило по сути не механизируемо (суждение, не синтаксис) — оставлять рекомендательным и
  проверять человеком или критиком.
- Соло-разработчик с низким радиусом поражения — риск ещё не стал реальным.

**«Здесь не нужно вообще»:**

- **Полное текстовое перечисление всех синтаксических форм одной shell-команды — не нужно как
  стратегия, оно структурно недостижимо** (см. §A.8): пространство форм больше, чем можно
  перечислить, потому что раскрытие слов и алиасов происходит уже после того, как хук принял
  решение. Вместо: платформенный ruleset как потолок (не зависит от текста локальной команды
  вообще) плюс узкий `PreToolUse`-хук, ограниченный **перечислимым** списком заведомых попыток
  отключить защиту (`--no-verify`, манипуляция `core.hooksPath`, переменные окружения
  хук-менеджеров) — такой список можно довести до полноты, в отличие от синтаксиса git.
- Если единственная причина ставить локальный хук — «прод не должен пострадать» без какого-либо
  технического разделения окружений, хук не решает эту задачу: он защищает ветку `main` в git, а
  не производственную систему. Нужен отдельный барьер уровня доступа/окружения — это уже другая
  тема, не эта ступень.

### A.11. Строка в ось занятия

**Решаем (правило уже нарушено).** Интуиция говорила: «поставили хук — коммит в main закрыт».
