# Восемь конфигураций: по одной, парами, все три

## Assertion

Три защиты, восемь способов их включить — от «ничего нет» до «все три вместе», и у каждого способа свой холст на стенде.

## Visual

> **Дизайн замера.** Каждая защита проверяется по отдельности (`p`, `r`, `c`), затем все три пары (`pr`, `pc`, `rc`), затем все три вместе (`prc`) — плюс базовая линия без единой защиты (`0`) для сравнения. Восемь конфигураций на одном и том же корпусе из 64 заявок — **512 решений**.

| Ступень | Конфигурации |
|---|---|
| без защиты | `0` |
| одна защита | `p` — промт · `r` — механика · `c` — классификатор |
| пара защит | `pr` · `pc` · `rc` |
| все три | `prc` |

> **Каждая конфигурация — отдельный холст на стенде**, не переключатель внутри одного процесса. Холст без узла механической проверки — честное изображение конфигурации «без механики», а не декорация.

> **Прежде чем смотреть результат — ставка.** Из трёх защит, разобранных на прошлом кадре, какая в одиночку остановит больше атак? Ответ — на следующем кадре, числом.

## Speaker notes

Дизайн замера — двойной, именно так его и формулировал владелец курса: каждую защиту проверить по отдельности, затем все их сочетания по двое, затем все три вместе. Восемь конфигураций получаются прямым перечислением: базовая линия без единой защиты, три защиты поодиночке, три возможные пары и одна тройка.

Базовая линия без защит в прямой просьбе не звучала — она добавлена, потому что без неё остальные семь конфигураций не с чем сравнивать. Число без базы не читается, и здесь база — это и есть «что происходит вообще без всякой защиты».

Восемь конфигураций — это восемь отдельных холстов на стенде, каждый со своим набором узлов. У конфигурации без механической проверки узла механики на холсте физически нет: холст собран без него. Такой подход честнее переключателя: переключатель может стоять в неверном положении незаметно, а отсутствующий узел виден сразу.

На каждую из восьми конфигураций прогоняется весь корпус — все 64 заявки. Восемь умножить на шестьдесят четыре даёт пятьсот двенадцать решений. Это число уже можно назвать — оно о размере плана, не об исходе: сколько решений мы собираемся получить, а не что в них оказалось.

Стоит сказать и о том, чего в этом плане нет. Отдельных повторов каждой заявки внутри одной конфигурации не предусмотрено — каждая заявка прогоняется через каждую конфигурацию ровно один раз. Это осознанный выбор ради охвата: лучше разобрать 64 разных формулировки один раз, чем десять формулировок десять раз каждую. Устойчивость самого ответа — отдельный вопрос, и ниже по ходу разбора он тоже получит свою проверку, причём по не самой очевидной причине.

Прежде чем смотреть на то, что получилось, — ставка. Три защиты мы уже разобрали: усиление промта, механическая проверка, классификатор на входе. Как думаете, какая из них в одиночку остановит больше атак? Держите свой ответ в голове — на следующем кадре сверим его с числом.
