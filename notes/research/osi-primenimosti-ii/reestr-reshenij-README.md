# Реестр решений (`reestr-reshenij.csv`)

Канонический, однократно нормализованный CSV-регистр всех реальных кейсов, размеченных по трём
основным осям применимости ИИ (неопределённость, скорость обратной связи, сложность метода) и
дополнительной Оси 4 (гейт/обратимость + внешний vs технический драйвер провала), накопленных в
ходе исследования issue #349. Цель файла — чтобы любой будущий кросс-кейсовый анализ (корреляции
между осями, доля провалов по индустрии, доля `unclear` и т.п.) читал **один файл**, а не
перепарсивал 24 markdown-таблицы заново.

## Происхождение (provenance)

Собран 2026-11-18 путём совместного чтения 24 файлов:

- `notes/research/osi-primenimosti-ii/razmetka/lec-NN.md` (NN = 04..15) — первичная разметка по
  Осям 1–3 + Успех + Confidence + Источник, по одной строке на кейс.
- `notes/research/osi-primenimosti-ii/razmetka/lec-NN-os4.md` (NN = 04..15) — вторичный проход по
  тем же кейсам (сопоставление по названию/`source_locator`), добавляющий Ось 4 (Гейт,
  Blast radius, Внешний драйвер).

Три лекции (08, 11, 14) в `lec-NN.md` разбиты на суб-таблицы по разделам материала — это сохранено
в `source_locator` префиксом (см. ниже), а не потеряно при сведении в одну таблицу.

Проверка полноты: сумма строк таблиц во всех 12 файлах `lec-NN.md` = **421**, и ровно 421 строка
оказалась в итоговом CSV (см. «Проверка количества» ниже) — без потерянных и без задвоенных
кейсов.

## Колонки и канонический словарь значений

Нормализация выполнена одним проходом, одним «разметчиком» (эта сессия), чтобы не повторить
нестабильность между независимыми проходами извлечения, зафиксированную в предыдущем синтезе
(`07-os4-gejt-i-vneshnij-shum.md`). **Любое расширение реестра в будущем обязано использовать
значения из этого словаря буквально** — не варианты, не синонимы.

| Колонка | Тип | Допустимые значения |
|---|---|---|
| `id` | строка | `L{NN}-{3-значный порядковый}`, напр. `L04-001` — сквозной в пределах лекции, в порядке появления кейса в `lec-NN.md` |
| `lecture_num` | число | 4–15 |
| `industry` | enum | `sdlc, product-lifecycle, cad-cam, medical-decision, trust-recognition, frontier-space, agriculture, manufacturing, digital-twins, logistics, telecom-cybersecurity, scientific-research` (строго по номеру лекции 04→15) |
| `case_name` | строка | название кейса как оно дано в `lec-NN.md`, без markdown-разметки (`**`, нумерации) |
| `axis1_level` | enum | `low, moderate, high, extreme, unclear` |
| `axis1_mechanism` | enum | `U1, U2, U3, U4, none, unclear` — `none` = успешный кейс ИЛИ провал, не отнесённый источником ни к одному механизму неопределённости |
| `axis2_bucket` | enum | `seconds-minutes, hours-days, weeks-months, season-years, unclear` |
| `axis2_mechanism` | enum | `F-A, F-B, F-C, none, unclear` |
| `axis3_class` | enum | `rule-based, classical-ml, deep-learning, foundation-model, agentic-llm, sensor-fusion, hybrid, unclear` |
| `axis4_gate` | enum | `yes, no, not-applicable, unclear` |
| `axis4_blast_radius` | enum | `low, medium, high, catastrophic, unclear` |
| `external_driver` | enum | `yes, no, mixed, not-applicable, unclear` — `not-applicable` = чистый успех без обсуждённого контрфактического провала (эквивалент исходной записи «n/a (успех)») |
| `outcome` | enum | `success, partial, failure, undetermined` |
| `confidence` | enum | `high, medium, low` |
| `source_file` | строка | имя файла `lec-NN.md` (только имя, не полный путь) |
| `source_locator` | строка | точная строка-идентификатор кейса из `lec-NN.md`, для грепа; для лекций с суб-таблицами (08, 11, 14) — с префиксом метки суб-таблицы (см. ниже) |

### Правило нормализации хеджей (compound/hedged значений)

Когда исходная ячейка содержала составной или оговорённый текст (например, «высокая, но граница
с умеренная», «medium-low», «низкая-умеренная»), в CSV записано **первое/ведущее** значение из
текста. Это заведомо лоссовая компрессия — нюанс оговорки теряется в CSV, но не теряется
навсегда: `source_locator` + `source_file` всегда указывают на исходную ячейку с полным текстом
оговорки. Реестр создан для быстрой фильтрации, не для замены первоисточника.

### Суб-таблицы (08, 11, 14) — префиксы `source_locator`

- **Лекция 08** (trust-recognition): `section1:` (Раздел 0–1, продакшн/исполнение) ·
  `hiring:` (найм под чужой личностью) · `editorial:` (редакционный контроль) ·
  `release:` (релиз и приём аудиторией) · `rights:` (счёт: права/рынок/критерии отказа).
- **Лекция 11** (manufacturing): `discrete:` (дискретное производство) ·
  `process:` (процессное производство).
- **Лекция 14** (telecom-cybersecurity): `telecom:` · `aiops:` · `cybersecurity:`.

Формат: `"{метка}: {case_name}"`, например `"discrete: Tesla 2018 (конвейер + «fluffer» + сборка батарей)"`.

## Доля `unclear` по колонкам (из 421 строк)

| Колонка | `unclear` | % |
|---|---|---|
| `axis4_blast_radius` | 81 | 19% |
| `axis2_bucket` | 76 | 18% |
| `axis1_level` | 49 | 12% |
| `axis4_gate` | 46 | 11% |
| `axis3_class` | 42 | 10% |
| `axis2_mechanism` | 17 | 4% |
| `axis1_mechanism` | 10 | 2% |
| `external_driver` | 8 | 2% |
| `industry`, `outcome`, `confidence` | 0 | 0% |

**Это не шум измерения — это честный сигнал о тонкости первоисточника.** Высокая доля `unclear`
у `axis4_blast_radius`/`axis2_bucket`/`axis1_level` сосредоточена там, где исходная разметка сама
пишет «неопределённо», «недостаточно данных», «неприменимо к задаче вовсе» (институциональные/
юридические/геополитические кейсы — Suez Ever Given, FTC v. Deere, GE Predix, Foxconn Wisconsin,
AIRI/Sber/Yandex, РСХБ, и т. п.) или кейсы-заглушки («короткие упоминания», «3 упоминания
раздела 3» в Лекции 9). `axis1_mechanism`/`external_driver` почти всегда заполнены, потому что
`none`/`no` — валидный, информативный ответ для подавляющего большинства успешных кейсов, а не
признание пробела.

## Унаследованные ограничения источника (обязательно учитывать при анализе)

Ниже — предупреждения из исходного исследования, которые теряются, если читать только CSV без
контекста `razmetka/*.md`:

1. **Single-rater, hypothesis-aware labeling.** Все 24 файла размечены одним и тем же
   исследовательским циклом, знающим гипотезу «оси предсказывают исход» заранее — это не
   blind-независимая разметка несколькими кодировщиками. Межкодировочная надёжность не измерена.
2. **Extraction instability между проходами.** Прежний синтез-агент (`07-os4-gejt-i-vneshnij-shum.md`)
   обнаружил, что два независимых прохода извлечения категориальных значений из одних и тех же
   свободнотекстовых ячеек дают заметно разные проценты. Этот CSV — попытка сделать эту
   нестабильность необратимой (зафиксировать одну нормализацию навсегда), но сама природа
   исходных ячеек (свободный текст с оговорками) не изменилась — расхождения с будущей повторной
   разметкой возможны и ожидаемы на пограничных кейсах.
3. **Case-selection bias исходного материала лекций.** Несколько `lec-NN.md` явно отмечают (Лекция
   9 — «подвержена смещению в сторону публикуемых успехов», Лекция 5, 8, 10, 13 — конкретные
   кейсы коммерческой/само-отчётной природы без независимого аудита). Присутствие кейса в этом
   реестре не означает, что он представляет типичное распределение исходов в индустрии — только
   что он документирован и обсуждён в материале курса.
4. **Исключение Лекции 15 (гейт/Ось-1 конфляция).** `lec-15-os4.md` явно и однозначно
   констатирует: это единственная из 12 лекций, где `axis4_gate` **не является** независимой от
   `axis1_level` переменной — для научно-исследовательского домена «есть ли независимая
   проверочная истина для под-задачи» и «есть ли гейт перед тем, как поверить результату» — по
   сути один и тот же вопрос, заданный дважды (пример: AlphaFold в целом `axis4_gate=yes`/
   `axis1_level=high`, AlphaFold-на-IDP `axis4_gate=no`/`axis1_level=extreme` — внутри одного
   метода). На всех остальных 11 лекциях `lec-NN-os4.md` явно демонстрирует и подчёркивает
   независимость Оси 4 от Осей 1–2 (см. наблюдения каждого файла) — считать Ось 4 ортогональной
   осям 1–2 *по умолчанию на всём корпусе* будет статистической ошибкой именно из-за строк
   Лекции 15 (27 строк, `lecture_num=15`); любой корреляционный анализ Ось4×Ось1 обязан либо
   явно выделить Лекцию 15, либо явно процитировать этот абзац.
5. **Suez Ever Given, UPS ORION, G-FOLD, AutoNav/GESTALT, NASA IPEx, Пульсоксиметр, Babylon,
   Мелитополь, FANUC AI Servo и другие — не ИИ-кейсы или кейсы с противоречивым статусом
   «ИИ-природы».** Это сделано намеренно: каждый такой `lec-NN.md` явно включает их как
   структурный контрпример («провал без ИИ», «успех классики там, где ожидали ИИ»,
   «security/governance-провал, а не провал ML-задачи»). Фильтруя реестр по `axis3_class`, не
   удаляйте их бездумно — они часть доказательной базы тезиса курса, не шум.
6. **Baseline/counterfactual для измеримых заявлений — не в этом файле.** Реестр хранит
   `outcome`/`confidence` как итоговую оценку, но НЕ хранит сами числа (ROI, %, $) — за ними нужно
   идти в `source_file`/`source_locator` → исходную ячейку таблицы в `razmetka/lec-NN.md`.

## Как обновлять реестр дальше

- **Новый кейс в существующей лекции:** добавить строку с id на следующем свободном порядковом
  номере этой лекции (например, следующий после `L10-054` — `L10-055`), не переиспользовать номера.
- **Новая лекция:** использовать новый `industry` из этого же словаря, если домен уже покрыт
  существующим значением; никогда не вводить новое значение `industry` без правки и этого README,
  и явного обоснования в коммите.
- **Любое новое значение категории, которое "не лезет" в существующий словарь:** использовать
  литерал `unclear`, никогда не изобретать новый enum-значение молча — расширение словаря — явное,
  документированное решение, не побочный эффект одной строки данных.
