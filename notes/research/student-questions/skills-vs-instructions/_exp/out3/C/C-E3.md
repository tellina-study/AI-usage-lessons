# Почему проверка кодом надёжнее просьбы к модели

**Date:** 2026-10-02 · **Issue:** #217-EXP

## Утверждения

| утверждение | источник | тип |
|---|---|---|
| Проверка кодом (unit tests, assertions) даёт детерминированный результат — один и тот же код при одинаковом входе вернёт одинаковый выход всегда | Свойство вычислимости: компьютерные программы исполняют фиксированную последовательность операций | Фундаментальное свойство |
| Просьба к LLM-модели вариативна: один и тот же prompt при одинаковых параметрах (temperature, top_k) может дать разные ответы из-за внутренней стохастичности генерации | Природа трансформер-сэмплинга: автор.регрессионная генерация с вероятностным выбором токенов | Механизм |
| Код проверяет конкретное поведение (возврат значения, побочные эффекты, исключения); модель выдаёт текст, требующий интерпретации человеком | Разница в типах выходов: deterministic binary (pass/fail) vs. probabilistic natural language | Архитектурное различие |
| При критическом функционале (safety, correctness, compliance) код — необходимое условие; модель — дополнение, но не замена | Специфика критических систем: требуют гарантий, а не вероятностей | Практика |

## Что НЕ доказано

- Нет ли LLM-систем с особыми гарантиями детерминизма (на практике все современные модели вероятностны).
- Невычислимо ли в коде случаи, где естественная вариативность моделей — преимущество (например, творческое письмо; здесь недоказано, что вариативность моделей превосходит контролируемый sampling).
- Не покрывают ли нейросетевые верификаторы (learned verifiers) часть функционала традиционной проверки кодом (частично верно, но верификаторы тоже вероятностны).
