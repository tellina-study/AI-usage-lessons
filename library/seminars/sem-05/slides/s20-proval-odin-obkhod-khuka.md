# Девять прошли, пять промолчали

## Assertion

Самотест ровно этого хука печатает 9 PASS и 5 LIMIT: пять форм одной и той же команды проходят мимо барьера молча — не из-за небрежности паттерна, а потому что оболочка раскрывает слова уже после того, как хук принял решение.

## Visual

**Реальный прогон `.claude/hooks/selftest-branch-guard.sh`: 9 PASS / 5 LIMIT / 0 FAIL.**

| Форма команды | Должна давать `deny` | Что происходит |
|---|---|---|
| `git commit -m "..."` на `main` (эталон) | ✓ | Срабатывает |
| Дефолтная ветка названа не `main`/`master` (напр. `trunk`) | ✓ | Проходит молча |
| `git -C <path> commit -m "..."` | ✓ | Проходит молча |
| `/usr/bin/git commit -m "..."` | ✓ | Проходит молча |
| `env git commit -m "..."` | ✓ | Проходит молча |
| `git commit` на второй строке многострочной команды | ✓ | Проходит молча |

Почему не лечится расширением списка: оболочка раскрывает слова и алиасы **после** того, как хук уже принял решение по тексту.

Вывод: хук на `Bash` — фильтр на синтаксис одной команды в нераскрытой текстовой форме, не на намерение и не на финальную исполняемую форму.

## Speaker notes

У этого хука есть самотест в том же репозитории. Реальный прогон: девять проверок прошли, ни одной провальной — и сам скрипт печатает пять случаев, где ворота молчат: дефолтная ветка названа иначе, путь перед командой, обёртка-префикс, флаг рабочей директории, команда не в первой строке. Сработала только эталонная форма из таблицы, остальные пять прошли мимо барьера. Два дополнительных случая молчания фиксирует тот же файл: хук, превысивший тайм-аут, не блокирует — он просто не успевает; отсутствующий `jq` даёт тот же тихий отказ, что и намеренный обход.

Дело не в небрежности паттерна — задача поймать все формы одной команды структурно невыполнима: оболочка раскрывает слова и алиасы непосредственно перед выполнением, то есть уже после того, как хук принял решение по тексту. Хук физически не может увидеть финальную развёрнутую форму команды раньше, чем она выполнится. Тот же класс обхода независимо воспроизведён внешним адверсариальным тестом на другом проекте — не как гипотеза, а как второй, подтверждающий прогон.

Практический вывод — не паника: не гоняться за каждой новой найденной формой обхода, это гонка с отрицательным исходом, потому что пространство синтаксических форм одной команды больше, чем можно перечислить. Вместо неё — платформенный барьер, не зависящий от текста вообще, и узкий хук, ограниченный перечислимым списком заведомых попыток отключить защиту. Такой список можно довести до полноты — в отличие от синтаксиса git.
