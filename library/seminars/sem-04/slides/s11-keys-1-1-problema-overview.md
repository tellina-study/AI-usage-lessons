# Почти пустой CLAUDE.md

## Assertion

Прототип собран, следующая сессия будет завтра — в `CLAUDE.md` уже есть строка гейта готовности, остальное пусто, а стандартный первый раздел такого файла называется «Repository overview».

## Visual

Состояние репозитория:

```
README.md
spec.md
DECISIONS.md
index.html
package.json
src/main.js
tests/form.spec.ts
CLAUDE.md        ← заведён, есть строка гейта, остальное пусто
AGENTS.md        → симлинк на CLAUDE.md, заведён на дне 0
```

Справа — сценарий:

> Прототип работает, задач по нему ещё на несколько дней. Разработчик заводит `CLAUDE.md`, чтобы агент в следующих сессиях работал с проектом одинаково, и открывает файл — там одна строка, гейт готовности, остальное пусто.
>
> Первый раздел, с которого такой файл обычно начинается, — «Repository overview»: из чего собран сайт, где лежит форма, какая структура папок. Так устроено большинство файлов инструкций, которые можно открыть в публичных репозиториях.

На этом слайде нет ни вопроса, ни карточек-вариантов.

## Speaker notes

«Прототип собран, но работа не закончена: впереди ещё несколько дней задач по этому же репозиторию, и каждая — новая сессия агента с нуля. Разработчик заводит `CLAUDE.md` — файл, который грузится в начало каждой сессии, — и открывает файл: там одна строка, гейт готовности, остальное пусто.

Откроете почти любой публичный репозиторий с таким файлом — он начинается с раздела «Repository overview»: что это за проект, как устроен, где что лежит. Это сложившаяся конвенция, и вопрос первой развилки ровно про неё: что из этого имеет смысл записать здесь, в этом репозитории, на этом шаге.»
