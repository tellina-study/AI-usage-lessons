# Формат записи повествования. §0–§2

## §0. Что уже есть и где — и что остаётся не покрытым

Повествование лекции и семинара уже описано каноном, и пересказывать его здесь — нарушение
прямого требования этой работы. Перечень того, что уже есть, со ссылками:

| Что уже решено | Где | Что именно |
|---|---|---|
| Из чего лекция сделана | `stroenie-i-povestvovanie.md` §1 | ось (две половины), вопрос лекции, keystone — три решения до первого слайда |
| Хребет и состав разделов | там же §2 | путь одного предмета, таблица разделов, швы, карта вечера |
| Устройство раздела | там же §3 | пять шагов (а)–(д) общего описания + что работает/не работает + разборы + цена + вывод |
| Устройство разбора | там же §4 | пять шагов формы (Scania), три графы второго шага, три условия отбора примера |
| Счёт разборов | там же §5 + образец `REESTR-RAZBOROV.md` | знаменатель — суждение, перечисляется построчно, не вписывается |
| Сквозная линия | там же §6 + образец `REESTR-PRIPISOK-DEKI.md` | число-рефрен, где пересчитывается, что подводится на закрытии |
| Словари | там же §7 | предъявляются до жаргона |
| Своё свидетельство | там же §8 | разряд, оговорка «это свидетельство, не измеренный кейс» |
| Минутный счёт | там же §9 | 0,75 мин/кадр, порядок резки считается заранее |
| Заметки | там же §10 | 500–800 слов, публикуемый текст |
| Грамматика кейса (семинар) | `seminar-production/README.md` §3 | такты, карточки без протечек, четырёхколоночный разбор |
| Сторителлинг (семинар) | там же §4 | семь болезней, шесть правил, арка через занятия |

**Что из этого следует для объёма этого документа.** Всё перечисленное — **что** должно быть в
повествовании и **каким** оно должно быть по качеству. Канон ни разу не отвечает на вопрос, **в
каком виде** это записывается так, чтобы запись можно было (1) проверить построчно, не
перечитывая главу целиком, (2) передать другой сессии без потери решений, (3) превести в кадр
без того, чтобы автор кадра на глаз придумывал тезис и форму заново. `03-RAZNARYADKA.md` §1.2
прямо называет эту дыру с другой стороны: «форма кадра из каталога 31» и «что кадр утверждает»
плану сейчас **не достаются ни от чего** — автор кадра решает оба поля сам, в момент рисования.
Этот документ — ответ на вопрос «чем заполнить эту дыру», написанный со стороны повествования,
а не со стороны кадра.

Ниже — не новые правила, а **единицы и поля**: что записывается, какое имя у единицы берётся
из канона, какое поле на какой вопрос отвечает и что в нём обязательно, а что можно оставить
пустым с названной причиной.

## §1. Единицы

Единицы называются словами канона. Своего слова не введено ни одного — там, где задание просило
«узел», термин заменён на **раздел** и **разбор**: оба слова уже несут ровно ту функцию, которую
задание называет «узлом» (повторяющаяся содержательная единица лекции и её внутренняя доказательная
единица), и вводить третье имя для того же понятия значило бы повторить ошибку, которую канон сам
называет антипаттерном — «мы вводим термин, которого нет в речи» (`seminar-production/README.md`
§8.1, тот же принцип, что применён здесь к документам курса, а не к речи ведущего).

| Единица | Слово канона | Повторяется? | Что она есть |
|---|---|---|---|
| Занятие | **лекция** / **семинар** | один раз | весь вечер целиком |
| Ось + вопрос + keystone | **ось**, **вопрос лекции**, **keystone** | фиксируются один раз, до первого раздела | три решения, без которых раздел не пишется (`stroenie-i-povestvovanie.md` §1) |
| Раздел | **раздел** | столько, сколько стадий держит хребет | стадия предмета, 5 внутренних шагов |
| Разбор | **разбор** | 3 подробных + до 6 упоминаний на раздел | доказательная единица внутри шага 3 раздела |
| Переход между разделами | **шов** | на каждой границе разделов | то, что несёт взгляд назад или вперёд (`stroenie-i-povestvovanie.md` §2) |
| Переход между занятиями | **шов** (то же слово — `seminar-production/README.md` §2: «шов переносится дословно») | на границе с предыдущим/следующим занятием курса | долг, обещанный соседним занятием, или обещанный этим занятием соседнему |
| Сквозная линия | **сквозная линия** («красная линия») | одна на занятие, пронизывает все разделы | наблюдение, которое пересчитывается и получает число на закрытии (`stroenie-i-povestvovanie.md` §6) |
| Закрытие | **закрытие** | один раз, в конце | раздел особого вида: заработанное утверждение + число + долг вперёд |

Единицы образуют не дерево, а цепочку с двумя пронизывающими линиями:

```
занятие
 ├─ ось · вопрос лекции · keystone      (фиксируются один раз)
 ├─ раздел 1 ─ шов ─ раздел 2 ─ шов ─ … ─ раздел N ─ шов ─ закрытие
 │     └─ разбор, разбор, разбор …            (3+6 на раздел, canon §3)
 ├─ сквозная линия                      (пронизывает все разделы, число на закрытии)
 └─ шов с соседними занятиями           (долг назад и долг вперёд, по курсу)
```

Единица «разбор» не обязана жить только внутри шага 3 раздела, но **записывается** она там:
канон прямо допускает, что шаги 1–2 разбора стоят в одном параграфе, а шаги 3–4 в следующем
(`REESTR-RAZBOROV.md`, правило «что включено») — запись в этом случае держит один разбор одной
строкой, с обоими адресами в поле «адрес», а не раздваивает его на две строки реестра.

## §2. Поля записи

Таблицы ниже — поля каждой единицы. Колонка «вопрос» называет, на что отвечает поле, а не что
в нём написать: формулировка содержания остаётся за автором, канон (вторая колонка таблицы §0)
и жанровые правила (`02-KATALOG-FORM.md`, `07-PRIYOMKA.md`) эту формулировку уже регулируют.
«Обяз.» — поле без записанного значения значит, что раздел/разбор не готов к показу, и запись
обязана содержать либо значение, либо явный отказ с причиной (как это уже устроено в
`REESTR-RAZBOROV.md` для графы (в) и у отказа присвоить форму словаря).

### 2.1. Поля ЗАНЯТИЯ

| Поле | Обяз. | Вопрос, на который отвечает |
|---|---|---|
| `title` / `rpd_title` | да | какой пункт РПД этот вечер закрывает |
| `supersedes` | нет | какую прежнюю версию эта заменяет и чем та была плоха — без этого поля правка выглядит произволом, а не ответом на названный дефект |
| `ось: наследуемая половина` | да | что из предыдущего занятия применяется, не заявляется новым |
| `ось: своя половина` | да | единственная заявка этого занятия на новое |
| `ось: чем это НЕ является` | да | абзац «переименование» — какие формулировки курса стоят рядом и чем заявка от них отличается (`stroenie-i-povestvovanie.md` §1.1) |
| `ось: адреса` | да | по каким именованным адресам ось прошивается по разделам (у Лекции 7 — внимание · навык · подпись · арбитраж) |
| `вопрос лекции` | да | один вопрос, формулировка дословная, с местом первого и второго произнесения |
| `keystone: адрес` | да | какой кадр предъявляет ось до первого погружения |
| `keystone: состав` | да | ряд 1 (измеренная тройка) · ряд 2 (перенос) · строка вывода — если ряда нет, это называется явно, не молчанием |
| `словарь: имя + число форм` | да | какой словарь занятие заводит или наследует |
| `словарь: адрес первого ПОЛНОГО предъявления` | да | где словарь показан целиком, до первого употребления термина |
| `сквозная линия: имя` | да | какое наблюдение пронизывает все разделы |
| `сквозная линия: число-рефрен` | да | какое число повторяется и чем измеряется линия |
| `слот / темп / порядок резки` | да (для производства) | ссылка на `stroenie-i-povestvovanie.md` §9, не пересказ |
| `шов назад: долг от предыдущего занятия` | да | что соседнее занятие уже произнесло залу как обязательство этого занятия |
| `шов вперёд: долг следующим занятиям` | да | что это занятие обещает и кому именно (номер лекции, параграф) |
| `утверждение занятия целиком` | да, пишется последним | какую одну фразу занятие заработало — не тезис плана, а то, что материал подтвердил |

### 2.2. Поля РАЗДЕЛА (повторяются на каждый раздел хребта)

| Поле | Обяз. | Вопрос |
|---|---|---|
| `термин отрасли` | да | как стадия называется в самой отрасли, не разговорным ярлыком |
| `(а) что это за стадия` | да | именованное определение |
| `(б) что на стадии получают и решают` | да | какие данные о человеке, какой вопрос на них решают |
| `(в) как данные получают` | да | перечень способов — обязателен на кадре, не в заметках |
| `(г) какое решение и почему здесь по порядку` | да | что за решением следует, почему стадия стоит на этом месте хребта |
| `(д) как решают без ИИ` | да | классические режимы по именам |
| `разборы` | да, список | что подтверждает раздел (3 подробных, перечислить) |
| `упоминания` | нет (до 6) | что добавляет по касанию, каждое с числом |
| `что работает / что не работает` | да, обе половины | что ИИ меняет на стадии, обе стороны |
| `адрес оси` | да | какой из именованных адресов платежа этот раздел прошивает и на каком разборе именно |
| `цена: дало / потребовало / в сумме` | да | чем раздел платит за то, что раздел даёт — в сопоставимых единицах |
| `вывод раздела` | да | польза, граница, что едет дальше по циклу |
| `вопрос залу` | да | формулировка дословная + канал (вслух/чат) + допустимый короткий ответ + где вскрывается ответ |
| `сбой ритма` | нет | если раздел ломает общую форму сознательно — чем именно и зачем |
| `шов назад` | да | что последняя фраза предыдущего раздела оставила этому разделу |
| `шов вперёд` | да | что последняя фраза этого раздела отдаёт следующему — и какому именно, если не непосредственно следующему |

### 2.3. Поля РАЗБОРА (внутри шага «разборы» раздела)

| Поле | Обяз. | Вопрос |
|---|---|---|
| `имя` | да | короткое имя, под которым разбор называется в дивайдере и в реестре |
| `адрес в деке` / `адрес в главе` | да | где проверить построчно (пример устройства — `REESTR-RAZBOROV.md`) |
| `условия отбора` | да, три | изменение вызвано ИИ · предмет отраслевой · дихотомия измерена |
| `цена обеих ошибок` | да | единица, названная до всякой точности |
| `графа второго шага (а/б/в)` | да | посчитаны оба режима в одной единице / второй назван без числа / второго не существует |
| `чем вердикт обоснован` | да | цитата или пересказ абзаца, из которого графа выведена |
| `модель против режимов` | да | выигрыш от нуля не принимается |
| `устройство: вход/выход/обучение/имя изделия` | да | не только в поле источника — на кадре |
| `форма переезда` | да | имя из словаря девяти форм либо названный отказ с причиной |
| `адрес оси` | да | какой конкретно платёж этот разбор подтверждает |
| `дало / потребовало / в сумме` | да | парой, в сопоставимых единицах |
| `приписка` | нет | если разбор несёт сквозную линию — графа 1/2/3 (кому принадлежит результат) |

### 2.4. Поля ШВА

| Поле | Обяз. | Вопрос |
|---|---|---|
| `откуда` / `куда` | да | между какими двумя единицами (раздел-раздел либо занятие-занятие) |
| `род` | да | внутренний (между разделами) или межзанятийный (с соседней лекцией/семинаром) |
| `несёт взгляд назад или вперёд` | да | да/нет + цитата строки, которая это делает |
| `называет разборы следующего раздела по порядку` (для внутреннего шва на дивайдер) | да | совпадает ли дивайдер дословно с заголовками кадров (`trebovaniya-k-soderzhaniyu-forma.md` §5.16) |

### 2.5. Поля СКВОЗНОЙ ЛИНИИ

| Поле | Обяз. | Вопрос |
|---|---|---|
| `имя` | да | какое наблюдение названо сквозным |
| `адреса пересчёта` | да, список | на каких кадрах линия касается зала по ходу вечера |
| `число-рефрен` | да | чем линия измеряется, какое число повторяется |
| `адрес подведения на закрытии` | да | где число произносится итогом |
| `что из линии НЕ доехало до экрана` | да, если есть | называется прямо, не замалчивается — это тоже часть записи линии |

### 2.6. Поля ЗАКРЫТИЯ

| Поле | Обяз. | Вопрос |
|---|---|---|
| `заработанное утверждение` | да | чем закрытие ОТВЕЧАЕТ на вопрос лекции поимённо, не recap |
| `число` | да | число сквозной линии, произнесённое на этом кадре |
| `долг вперёд, в проверяемой форме` | да | что следующие занятия вправе требовать как уже доказанное |
| `посадка` | нет, рекомендовано | явный выход на Q&A, один вопрос от лектора, если зал молчит |
