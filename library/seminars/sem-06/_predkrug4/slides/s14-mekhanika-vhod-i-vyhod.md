# Что приходит на вход — и что уходит обратно

## Assertion

Роль получает свой системный промпт, задачу от вызывающей сессии, иерархию файлов инструкций и снимок git status — но не переписку родителя; возвращает только финальный итог, ни одного промежуточного вызова инструмента.

## Visual

**Приходит на вход:**
- свой системный промпт (тело файла роли) + базовые детали окружения
- task-сообщение, сформулированное вызывающей сессией
- иерархия `CLAUDE.md` целиком, теми же уровнями
- снимок `git status` на момент старта
- опционально — предзагруженные скиллы, если перечислены явно

**Физически не доходит:** переписка родителя, его стиль вывода, автопамять, уже прочитанные им файлы.

**Исключение — режим `fork`:** наследует всё целиком, изолирует только результат.

**Возвращается обратно:** только финальный текст, статус, модель, счётчики вызовов — ни одного промежуточного вызова инструмента.

## Speaker notes

Мы только что видели файл роли и строку `tools:`. Прежде чем идти дальше — что стоит за этим механически, не приблизительно.

На старте роль получает свой системный промпт — тело собственного файла — плюс базовые детали окружения: субагент не знает, как устроен харнесс, который его вызвал. Дальше — задачу, сформулированную вызывающей сессией, не вашу исходную реплику буквально. Дальше — иерархию файлов инструкций, всеми уровнями, что видит и основная сессия. И снимок состояния репозитория на момент старта.

Чего при этом физически нет: истории переписки, стиля вывода, автопамяти, уже прочитанных файлов — не потому что харнесс это прячет, а потому что канала для этого нет вообще.

Одно исключение одной строкой: форк наследует всё целиком, изолируется в нём только результат, не вход. А что возвращается обратно — только итог: родитель не видит, какие файлы ревьюер открыл по пути, только финальный текст ответа.
