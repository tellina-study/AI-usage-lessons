> Дата: 2026-05-17. Назначение: операционализировать сквозной тезис владельца — **«разная задача → разный тип ИИ; LLM ≠ универсальный молоток»**. Аудитория ВПЕРВЫЕ видит эти понятия → объяснять с нуля, без жаргона, через задачу→инструмент→где ломается.

## Сквозной тезис (ядро LO1, директива владельца)

Студент после Л1–Л4 склонен думать «ИИ = ChatGPT/LLM». Л5 ломает это: в финансах/ритейле **большинство ценности даёт НЕ LLM**, а классические/специализированные типы ИИ. Сторителлинг ведёт: **задача → подбор правильного типа ИИ → где этот тип ломается (failure) → критерий применимости**.

Педагогический приём: один «единый паттерн карточки типа ИИ» (как лестница A→D в Л4), применяется к каждому из 6 типов:
**[Какая задача] → [Какой тип ИИ и почему именно он] → [Реальный пример РФ/мир] → [Где ломается / когда НЕ этот тип] → [Альтернатива]**

## 6 типов ИИ под задачи финансов/ритейла (вводятся с нуля)

### Тип 1. Прогнозирование временных рядов (time-series forecasting)
- **Задача:** спрос на товар, продажи, cash-flow, отток клиентов, нагрузка колл-центра.
- **Тип ИИ:** классическая статистика / ML на табличных рядах (ARIMA-семейство, градиентный бустинг на признаках, специализированные модели). **НЕ LLM** — у LLM нет понятия численного ряда и сезонности; это не текстовая задача.
- **Пример:** X5 прогноз спроса (точность >70%, −2% списаний), Магнит F&R (см. 02-adoption).
- **Где ломается:** distribution shift (Zillow — режим рынка сменился), редкие события, промо-каннибализация. → 01-failures #A.
- **Альтернатива/критерий:** узкий доверительный сегмент + human-gate на капитальных решениях + live error-monitoring.
- **Glossary:** *time-series forecasting / прогнозирование временных рядов*.

### Тип 2. Поиск аномалий / fraud detection (anomaly detection)
- **Задача:** фрод в реальном времени, AML (отмывание), нетипичные транзакции.
- **Тип ИИ:** anomaly detection (модель «нормы» → отклонение), часто unsupervised/semi-supervised + правила. Не генеративный.
- **Пример:** Stripe Radar, JPMorgan, Visa (02-adoption). РФ: anomaly detection в банках по опросу ЦБ.
- **Где ломается:** false positives (заблокированный клиент), дрейф паттернов фрода, дисбаланс классов; «accuracy 99.9%» обманчива. → 01-failures #D. Матрица ошибок — мост к Л7 §2.2 (НЕ переобъяснять).
- **Альтернатива/критерий:** cost-sensitive метрики (FP/FN раздельно в деньгах), мягкий challenge вместо глухого отказа на крупных, human-in-the-loop на необратимом; rules-engine для жёстких регуляторных правил (AML-пороги).
- **Glossary:** *anomaly detection / поиск аномалий*, *false positive / false negative* (мост к Л7, краткое напоминание-формулировка), *AML*.

### Тип 3. Классический ML для скоринга (НЕ нейросеть/LLM — и почему)
- **Задача:** кредитный скоринг, оценка кредитоспособности.
- **Тип ИИ:** градиентный бустинг / логистическая регрессия / scorecard. **Почему НЕ нейросеть/LLM:** (1) нужна объяснимость (reason codes — регуляторное требование, ECOA/Reg B аналоги), (2) табличные данные, не текст, (3) интерпретируемость и аудит важнее +1% точности, (4) bias-тестирование. Мост к ML-vs-LLM-дереву Л2.
- **Пример:** Сбер 100% решений ИИ, до 5000 параметров (02-adoption); Apple Card/Goldman (01-failures #B).
- **Где ломается:** прокси-предвзятость, необъяснимость, «алгоритм так решил». → 01-failures #B + Obermeyer-параллель. **[USER GATE 0 2026-05-17 override]** Л7 идёт ПОСЛЕ Л5 → НЕ «мост назад, не дубль»: механизм прокси-bias **вводится в Л5 с нуля компактно** (2-3 фразы), Obermeyer = **forward-pointer на Л7 §4.3** (НЕ §3 — §3 = drug discovery; P1-2 fix). См. plan-v2-final §1.2 / §USER GATE 0 / s18.
- **Альтернатива/критерий:** интерпретируемые модели + SHAP, fair-lending аудит, human-андеррайтер на пограничных/оспоренных, обязательный appeal path.
- **Glossary:** *scoring / кредитный скоринг*.

### Тип 4. LLM (голосовые ассистенты, поддержка, паттерн fact-checking)
- **Задача:** клиентская поддержка, голосовой ассистент, объяснение, помощь сотруднику.
- **Тип ИИ:** LLM (то, что студент уже знает из Л1–Л3) — здесь показываем ГРАНИЦЫ применимости в финансах.
- **Пример:** Т-Банк голос/чат-бот (02-adoption); Klarna (01-failures #F); Air Canada callback (01-failures #E).
- **Где ломается:** галлюцинация условий/ставок/прав клиента → регуляторный риск + ущерб; полная замена людей → падение CSAT (Klarna).
- **Паттерн лекции — fact-checking (РПД-аспект):** ответ LLM о регулируемых фактах обязан быть grounded в первоисточнике и проверяем; LLM = интерфейс, источник истины = детерминированный lookup/документ. Это первый опыт fact-checking на реальных данных (РПД) — пара = Семинар 5 («проверка 5 заявлений о AI в банках РФ по первоисточникам»).
- **Критерий «здесь не генеративный LLM»:** фиксированная политика/тариф/право → детерминированная выборка, не свободная генерация; гарантированный путь к человеку.
- **Glossary:** (LLM/галлюцинация — из Л1, не заново) — мост-напоминание.

### Тип 5. Рекомендательные системы (collaborative vs content-based vs hybrid)
- **Задача:** «что ещё купить/посмотреть», персонализация ленты/выдачи.
- **Объяснить разницу НА ПАЛЬЦАХ (с нуля, ядро для аудитории):**
  - **Collaborative filtering** — «люди, похожие на тебя по поведению, покупали Y» (используем матрицу пользователь×товар; не знаем, ЧТО за товар). Плюс: ловит неожиданное. Минус: cold-start (новый товар/юзер), popularity bias.
  - **Content-based** — «этот товар похож по признакам на то, что ты уже любил» (используем атрибуты товара). Плюс: нет cold-start для товара. Минус: замыкает в нишу (over-specialization).
  - **Hybrid** — комбинация (большинство реальных систем): collaborative + content + контекст.
- **Пример:** Amazon ~35% (классическая оценка), Netflix ~75% просмотров; Ozon/WB ML-рекомендации (02-adoption — формулировать аккуратно, без переноса US-цифр на РФ).
- **Где ломается:** filter bubble, прокси≠цель (оптимизируем клики, не благополучие), dark patterns. → 01-failures #G.
- **Альтернатива/критерий:** diversity/serendipity-инъекция, explainable recs; решение о ценовой/контентной политике — человек + регуляторная рамка.
- **Glossary:** *collaborative filtering*, *content-based filtering*, *hybrid recommender*, *filter bubble*.

### Тип 6. Компьютерное зрение (CV) в ритейле
- **Задача:** полки/планограммы, кассы без кассира, OCR чеков/документов, KYC-сверка лица (liveness/face-match) при онбординге, аналитика очередей.
- **Тип ИИ:** CV (свёрточные/детекционные модели) — НЕ LLM, НЕ табличный ML; вводится как отдельный класс (студент видел «компьютерное зрение» в Л2 как тип, здесь — отраслевое применение).
- **Пример:** Amazon Just Walk Out (01-failures + 02-adoption — закрытие 04.2024, скрытые 1000+ людей в Индии); OCR чеков, KYC face-match при удалённом онбординге.
- **Где ломается / урок:** «автономия» CV-кассы оказалась дороже и потребовала скрытого человеческого труда → урок «оцени hidden human cost / TCO и edge-cases ДО автоматизации»; KYC-распознавание лица — приватность + ФЗ-152 (биометрия = чувствительные данные).
- **Glossary:** *KYC*. (CV — мост к Л2.)

## Dynamic pricing (сквозная, в Р5 рядом с recsys)
- **Задача/тип:** оптимизация цены (ML/RL/правила) под спрос/конкурента/контекст.
- **Пример/провал:** Wendy's backlash 02.2024 (01-failures #G).
- **Критерий:** восприятие справедливости и регуляторика — ограничения, не оптимизируемые переменные; ценовая дискриминация = репутационный/правовой риск > маржинальный выигрыш.
- **Glossary:** *dynamic pricing*.

## Безопасность (сквозная тема курса, обязательна)
- Финансовые данные + PII + биометрия (KYC) = чувствительные. **ФЗ-152** «О персональных данных»: что нельзя обрабатывать в облаке без оснований; локализация ПДн граждан РФ; биометрия — отдельный режим.
- Критерий: регулируемые/биометрические/финданные → on-prem или контролируемое облако с правовым основанием; не отправлять PII в публичный LLM (callback к сквозной теме Л1).
- Где rules-engine/детерминизм бьёт ML: жёсткие регуляторные пороги (AML-лимиты, обязательные проверки) — это закон, не вероятность; детерминированная сверка надёжнее и аудируема.
