# n37: «имена инструментов и инструкция сервера» вместо «описание каждого инструмента целиком»

Продолжение `qa/razvedenie-protivorechiy.md` §8 п.1, которая развела противоречие на `n09`, `n16`,
`n31`, `n32`, но оставила `n37` нетронутым (задание той сессии прямо исключило слайд). Эта сессия
закрывает единственное оставшееся место.

## 1. Что подтвердил источник

Повторного чтения первоисточника не потребовалось — `razvedenie-protivorechiy.md` §1 уже
зафиксировал его двумя независимыми проходами (`curl` markdown и HTML-версии
`code.claude.com/docs/en/mcp.md`, 2026-10-07) плюс третьим проходом сентябрьского исследования:
по умолчанию в контекст при старте ложатся «tool names and server instructions» — имена
инструментов и инструкция сервера о себе, не полные схемы. Отсрочку снимают `alwaysLoad: true` у
отдельного сервера и `ENABLE_TOOL_SEARCH=false` (и ещё два случая, на слайды не попадающие).

Прочитан заново только локальный контекст самого блока — зеркало `n16`
(`slides/n16-postoyannaya-plata-odinakova.md`), на которое `n37` прямо ссылается («Это та самая
постоянная плата, которую предыдущий блок занятия измерил в токенах»). После вчерашней правки
`n16` называет постоянную плату так: «это **имена всех инструментов** каждого подключённого
сервера и короткая инструкция сервера о себе». Раз `n37` называет свою третью строку «той же»
платой, формулировка обязана включать оба пункта — имена **и** инструкцию, не только имена.

## 2. Какая формулировка выбрана и почему

Предложение предыдущей сессии («имена всех инструментов, по всем серверам») проверки не прошло
по одному пункту: оно называет только имена, без инструкции сервера, хотя сама же строка слайда
ссылается на `n16` как на источник той же цифры — а `n16` измеряет оба пункта вместе. Назвать
только половину того, что ссылка называет полностью, — не ошибка факта, но потеря точности на
стыке.

Выбрано:

| Поле строки 3 (`SRC`, `rendered/make_figures_subagent.py`) | Было | Стало |
|---|---|---|
| `what` (крупная, жирная) | «описание каждого инструмента» | «имена инструментов и инструкция сервера» |
| `gloss` (мелкая, под ней) | «целиком, по всем серверам, до первого вашего вопроса» | «по всем серверам, до первого вашего вопроса» |

Формулировка `what` дословно повторяет связку, которой уже пользуются `n09` («…в контекст из
этого ответа ложатся только имена инструментов и инструкция сервера о себе…») и `n16` («имена
инструментов каждого сервера и инструкция о нём висят в контексте всегда»). Условия «по
умолчанию» на `n37` не добавлено — по той же причине, по которой его нет на видимом слое `n16`
(§4 `razvedenie-protivorechiy.md`): «имена и инструкция — в контексте» верно при **любом** режиме,
это нижняя граница, а не утверждение о режиме; отсрочка к ней лишь добавляет полные схемы, не
отменяет сам факт. `gloss` сохранил «по всем серверам, до первого вашего вопроса» без изменений
по существу — это и есть то, что блок обязан удержать по заданию («контекст занят ещё до первого
вопроса человека»), и это утверждение источник не оспаривает ни в каком режиме.

Отдельно взвешен вариант «имена инструментов и инструкция сервера» целиком в `what` при коротком
`gloss` против варианта «имена всех инструментов» в `what` с инструкцией, перенесённой в `gloss`.
Выбран первый: `n16`/`n09` называют имена и инструкцию парой, одним дыханием, и разносить их по
двум полям строки развело бы то, что источник называет вместе. Пиксельный запас позволял оба
варианта (677 px при лимите 820 для `what`, 592–1001 px при лимите 1852 для `gloss`) — выбор
сделан по смыслу, не по месту.

Правка внесена в трёх зеркалах одной фразы — рисовалка, заметки слайда, глава:

- `library/seminars/sem-06/rendered/make_figures_subagent.py:408-409` (`SRC`, третья строка кортежа)
- `library/seminars/sem-06/slides/n37-baza-agent-rol-i-kontekst-kazhdogo.md` (Speaker notes, тот же абзац)
- `library/seminars/sem-06/rework/section-2-subagent-part1b.md` (§B, зеркало `n37`, тот же абзац)

В `make_figures_subagent.py` и в frontmatter `backup` слайда `n37` добавлена короткая запись о
причине правки — по образцу, каким вчера был отмечен `n16`.

## 3. Есть ли четвёртое такое место

Грепом по всей деке (`rendered/*.py`, `slides/*.md`, `rework/*.md`) на точные подстроки
«описание каждого инструмента», «целиком» рядом с составом контекста, «при старте», «при запуске»,
«до вашего первого/первого вашего вопроса» — **буквального повтора старой формулировки `n37` нигде
больше нет**. Единственное другое совпадение с «описание каждого инструмента» — `n32`
(`slides/n32-mehanika-chto-lezhit-v-kontekste-do-pervogo-voprosa.md`, видимый слой и заметки):
«клиент обрезает и **описание каждого инструмента**, и инструкцию каждого сервера по 2 048
символов». Это не состав-при-старте, а предел длины (`CLAUDE_CODE_MAX_MCP_DESCRIPTION_LENGTH`),
верный независимо от режима — источник подтверждает его тем же предложением документации
(«Claude Code truncates each tool description and each server's instructions at 2,048 characters
by default»). Трогать нечего.

Один пограничный случай найден и разобран отдельно, не как то же самое противоречие:

**`n29`** (`slides/n29-stsena-chetyre-servera-ponadobilsya-odin.md`, сцена кейса 3 блока MCP),
пункт «Из чего набрано» — «Он посмотрел, что лежит в контексте до его первого вопроса: системная
часть, файлы инструкций проекта, **описания инструментов четырёх серверов**». Взятая отдельно,
эта строка читается как тот же overclaim: «описания» (не «имена») для всех четырёх серверов
безусловно. Но строка не стоит отдельно — следующий же пункт сцены называет механизм: «У двух
серверов стоит `alwaysLoad: true` — отложенная загрузка описаний для них отменена, все их
инструменты описываются при старте». Это ровно условие, которого не хватало старому `n37`:
полные описания у ДВУХ из четырёх серверов, по названной причине, не у всех по умолчанию. Разница
с `n37`-до-правки принципиальная: `n37` утверждал «целиком» без всякого условия нигде на экране;
`n29` называет условие в соседнем пункте того же блока. Это делает `n29` не противоречием
источнику, а неточной формулировкой предварительного шага внутри сцены (герой сперва смотрит
обобщённо, потом находит причину) — слабое место стиля, не факта. Сцена, как и кейс, который она
несёт, вне границ этого задания («точечная правка», «содержание кейсов не трогай»); правка не
внесена, но разница с `n37` и причина, по которой `n29` не в счёт четвёртого места, записаны здесь
для следующего круга.

**Вывод: четвёртого места, повторяющего факт-ошибку `n37`, нет.** `n29` — отдельное наблюдение,
не это противоречие, и оставлено автору сцены.

## 5. Итог

- **Источник подтвердил:** по умолчанию в контекст ложатся имена инструментов и инструкция
  сервера, не полные схемы; это нижняя граница, верная при любом режиме.
- **Выбранная формулировка `n37`:** «имена инструментов и инструкция сервера» / «по всем серверам,
  до первого вашего вопроса» — дословно та же пара понятий, что на `n09` и `n16`, без лишнего
  «по умолчанию» по той же причине, что и на видимом слое `n16`.
- **Четвёртое место:** не найдено. Один пограничный случай (`n29`) разобран и признан иным —
  условие у него названо в соседней строке той же сцены, правка не внесена (вне границ задания).
- **Сторожа:** все пять пройдены; два предупреждения («ОТВЕТ РЯДОМ С ВОПРОСОМ [n64]», «РЕЖЕТ
  [n28]») — известные, не касаются правленных слайдов, присутствовали и до этой сессии.
