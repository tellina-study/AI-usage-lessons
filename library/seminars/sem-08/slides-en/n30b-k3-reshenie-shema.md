# Version 2: the same path, one point changes

## Assertion

The action table already named the number: version 1 errs nine times out of a hundred and one, and all nine are in the same place — in how the "approve or escalate" decision gets made. Version 2 changes exactly that place, and nothing else.

## Visual

> **Version 1 (was).** Free-text form → model extracts the amount → **the same model decides from the rule text** → result.

> **Version 2 (became — a direct answer to the experiment's finding).** The same form → model extracts the amount → **`IF` node compares the number to the threshold** → result.

> The chain hasn't been rebuilt. The difference is confined to exactly one node — the very one where the decision used to be made. Everything else — the form, extracting the amount, routing the request further — stayed the same.

## Speaker notes

In the action table we just stated the number: version one, the one that's been running for a month, errs nine times out of a hundred and one. And not at some random point in the chain — at exactly one point, where the "approve" or "escalate" decision gets made. Before going further and breaking that number down, it's worth showing what we actually did with this finding. Version two is not a new chain built from scratch — it's version one with exactly that one node replaced.

Look at the diagram. The top band is version one, the one that ran for a month. A free-text form, the model pulls the amount out of it, and the same model — in the same call — decides whether to approve the amount or escalate it, by reading the text of the rule. This last action, deciding from the rule's text, is exactly the point where all nine errors happened.

The bottom band is version two. It doesn't appear alongside version one in parallel, nor does it replace it from the very start — it appears specifically as an answer to what the experiment showed. The form is the same, extracting the amount is the same — the model still has to pull a number out of the free-text request, because we haven't changed the form yet. But further down the chain, where the model used to decide from the rule's text, there is now an `IF` node: it compares the already-extracted number with the threshold as a condition in code, not as a text call.

Notice that this is not drawn as two equal, parallel processes that we supposedly built at the same time and compared. Version two came after version one, and because of a problem found in it — that is the correct way to tell the story of a decision change, and it matches exactly what actually happened: a month in production, an experiment, a finding, and only then a node replaced.

Next we'll break down how well this actually works — not just the headline number, but exactly how the test on a hundred and one requests was built, and exactly which phrasings tripped up version one again and again. That's the next beat.
