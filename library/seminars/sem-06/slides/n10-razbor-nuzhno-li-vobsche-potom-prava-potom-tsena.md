# Пять способов, у каждого своя область

## Assertion

У каждого из пяти способов — случаи, где он работает, и ограничения. Для регулярного доступа нескольких сессий к общему трекеру два способа отпадают сразу, а между оставшимися двумя законными — осознанный выбор, не формальность.

## Visual

| Вариант | Где работает — конкретные случаи | Ограничения |
|---|---|---|
| вызвать API напрямую | единичный эндпойнт: вы сами пишете запрос и разбор ответа | нет стандартного обнаружения инструментов моделью — каждый новый сервис это отдельный код интеграции, который пишете и поддерживаете сами |
| подключить чужой сервер — удалённо | сервис, который кто-то хостит и обновляет сам; не требует постоянного процесса на вашей машине | официальность не гарантирует, что сервер делает то, что заявляет: автор сервера сам может быть уверен в неверном |
| подключить чужой сервер — локально | пакет исполняется у вас, конфигурация — строка в репозитории, видимая всей команде в ревью | машина держит ещё один постоянно работающий процесс; команда запуска без зафиксированной версии подтягивает последнюю при каждом старте |
| написать свой сервер | нужен нестандартный набор операций или прав, которого готовый сервер не даёт | отдельная разработка и поддержка протокола — второй проект рядом с основным, не разовая настройка |
| обойтись разовой командой | разовое действие в одной сессии команда закрывает без сервера | перестаёт хватать, когда доступ нужен регулярно, из нескольких сессий, с сохранением состояния |

> **Из сочетания колонок:** для нашего случая — регулярный доступ нескольких сессий к общему трекеру — разовая команда и свой сервер отпадают сразу: первая не масштабируется на такую частоту, второй избыточен, раз готовый сервер уже существует. Прямой API остаётся вариантом только для единичного действия, не для повторяющейся задачи. Между «удалённо» и «локально» выбора без ответа нет — оба законны: свежий официальный пример для этого же сервиса подключается удалённо, а решение этого занятия — локальный процесс, потому что тогда конфигурация становится кодом в репозитории, видимым в ревью всей команде.

## Speaker notes

Разбираю все пять. У каждого — где работает и что ограничивает, вывод — из сочетания.

Прямой вызов API работает для одного эндпойнта, который вы готовы обслуживать сами, — но тогда модель не видит стандартного списка возможностей, каждый новый сервис это отдельный код. Чужой сервер удалённо снимает с вас процесс на машине, но официальность не гарантирует заявленное поведение. Чужой сервер локально делает конфигурацию кодом в репозитории — ценой ещё одного процесса, который крутится у вас, и риска тихого обновления пакета. Свой сервер оправдан, только когда готового для нужного сервиса просто нет. Разовая команда закрывает единичное действие и всё.

Вывод: для регулярного доступа нескольких сессий к общему трекеру — разовая команда и свой сервер отпадают сразу, прямой API — не для этой частоты. Между «удалённо» и «локально» — оба законны, выбор этого занятия — локальный, и дальше мы его собираем.

Если спросят про «удалённо» подробнее: свежий официальный пример подключения именно к этому сервису — удалённый http-сервис, не локальный процесс, как в примере, на который опирается этот кейс. Это не делает решение занятия неверным — локальный способ остаётся официально поддерживаемым, — но стоит знать: официальный путь для одного и того же поставщика может со временем смениться с одного способа на другой.

Если спросят про официальность подробнее: у одного MCP-сервера для баз данных флаг «только чтение» не делал соединение реально ограниченным — разберём это в провале этого кейса.

Если спросят, почему «просто довериться официальности» не вынесено отдельной карточкой: это отношение к уже выбранному серверу, не отдельный способ доступа — та же мысль выражена здесь ограничением строки «удалённо».
