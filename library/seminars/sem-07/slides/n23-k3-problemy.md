# Нюансы, которые есть везде

## Assertion

Повтор — это решение с ценой, и платят ею чаще всего не там, где ждут.

## Visual

| Нюанс | Чем проявляется |
|---|---|
| **повтор на неидемпотентной операции** | «отправить письмо» при таймауте уходит дважды: ответ потерялся, а действие прошло |
| **повтор на каждом слое** | слои множат друг друга, и чужой сервис получает лавину вместо запроса |
| задержка без разброса | все клиенты повторяют синхронно и добивают сервис, который начал вставать |
| бюджет повторов | в n8n число попыток приводится к 2–5, пауза к 0–5000 мс — что бы вы ни ввели |
| ключ идемпотентности | идентификатор прогона для этого не годится: он общий для элементов и новый при ручном повторе. Ключ выводят из данных |

> Три попытки на каждом из пяти слоёв дают **243-кратную** нагрузку на нижний. Поэтому повторяют **в одном месте стека** — не всюду, где есть галочка.

## Speaker notes

Пять нюансов, и первые три — из инженерной практики больших распределённых систем, не из нашего оркестратора. Они применимы всюду.

Первое: повтор безопасен только на идемпотентной операции. Идемпотентная — та, которую можно выполнить дважды с тем же результатом. Чтение идемпотентно всегда. «Отправить письмо», «создать заказ», «списать деньги» — нет. И вот ловушка. Таймаут означает ровно одно: «ответ не пришёл». Про то, произошло ли действие, он не говорит ничего — письмо могло уйти, деньги могли списаться, а потеряться мог только ответ. Повтор тогда сделает это второй раз. Поэтому на операциях с последствиями нужен ключ идемпотентности, по которому принимающая сторона узнаёт повтор.

Второе — число, которое стоит запомнить. Если повтор включён на каждом слое, слои множат друг друга: три попытки на каждом из пяти слоёв дают двести сорок три обращения вместо одного. Это пример из инженерной библиотеки Amazon, и вывод оттуда же: повторять надо в одном месте стека. У нас в оркестраторе галочка «повторить» есть на каждом узле, и соблазн поставить её всюду прямой.

Третье: задержка без разброса. Если все клиенты повторяют через ровно две секунды, они повторяют синхронно — и добивают сервис, который только начал вставать. Нужен случайный разброс. В простых оркестраторах его обычно нет, и это повод не ставить повтор на горячий путь без размышления.

Четвёртое — наша конкретика, но знать стоит: сколько бы попыток вы ни ввели, в n8n их будет от двух до пяти, а пауза — не больше пяти секунд. Приводится в коде, молча. Нужен длинный повтор — строится отдельно, узлом ожидания.

Пятое. Для ключа идемпотентности естественно взять идентификатор прогона, потому что он под рукой. Нельзя: он один на весь прогон, то есть у пяти заявок он одинаковый, а при ручном повторе из журнала — наоборот, новый у той же заявки. Ключ выводят из самих данных: время прихода плюс контакт, например.
