# Visible content

## Title bar
Presence paradox: наличие файла само по себе — не гарантия пользы

## Body
[Слева — RCT null result, Ocean rounded box]

**Gloaguen et al., arXiv:2602.11988, 2026**
Контролируемое сравнение: NONE / LLM-generated / developer-written steering-файл. Две постановки — SWE-bench-задачи (LLM-generated vs отсутствие) и реальные repo-issue (developer-written vs отсутствие).

**Результат:** само наличие файла не даёт статистически значимого прироста успешности задач, а стоимость и число шагов агента при его наличии, как правило, **растут**.

Единственное задокументированное исключение — LLM-сгенерированные файлы в репозиториях, где не было другой документации вообще.

[Справа — Honest Lying-риск + git-конвенции]

**Honest Lying: риск self-authored правки** *(Dixit, Kamal, Oates, arXiv:2605.29463, 2026)*
Если агенту разрешено самому править свой steering-файл («запиши, что понял по итогам сессии») — это то же уязвимое место, что self-authored память в целом: заметки могут не исправлять неверное убеждение, а **закреплять** его через повторные попытки. Ошибочная запись «X не работает по причине Y» на раннем шаге наследуется следующей сессией как данность, без перепроверки.

**Git-конвенции как контракт** (машинно-читаемое, не свободный текст):
- Conventional Commits (`type(scope): описание`) — парсится автоматически → changelog, semver, фильтр истории
- Именование веток (`feature/`, `fix/`, префикс задачи) → автосвязь с трекером
- Структурированные секции PR (Summary / Test Plan / Breaking Changes) — заполняются по шаблону, не «своими словами»

[Gold callout — максимальная видимость]
**Когда steering-файл НЕ нужен.** Если нет конкретного, называемого информационного пробела, который файл закрывает — писать его ритуально не даёт измеренной пользы, а стоит дороже нуля (лишний контекст на каждый запуск, лишние шаги, по данным presence-paradox-RCT). Если агент правит свой steering-файл без человеческого ревью правки — риск закрепления ошибки реален и задокументирован, не гипотетичен. Альтернатива: писать файл только под названный пробел, ревьюить изменения как обычный код.

## Speaker notes

Сам факт наличия файла-инструкции не гарантирует пользы — это presence paradox. Контролируемое сравнение по трём условиям — файла нет, файл сгенерирован моделью, файл написан разработчиком — в рамках двух постановок эксперимента показало: наличие файла не даёт статистически значимого прироста успешности задач, а стоимость и число шагов агента, как правило, растут. Единственное исключение — LLM-сгенерированные файлы в репозиториях без другой документации вообще.

Написание steering-файла — не самоцель. Файл работает, только если закрывает реальный информационный пробел, которого агенту иначе взять неоткуда. Файл, дублирующий то, что модель и так выведет из кода, не бесполезен нейтрально — он стоит дороже нуля: лишний контекст на каждый запуск, лишние шаги, не принося измеримой пользы.

Есть и второй риск. Если агенту разрешено самому править свой steering-файл — «запиши, что понял по итогам сессии», — это то же уязвимое место, что self-authored память в целом. Исследование Honest Lying показало: такие заметки могут не исправлять неверное убеждение, а закреплять его через повторные попытки — ошибочная запись на раннем шаге наследуется следующей сессией как данность, без перепроверки.

Отдельный слой — как агент коммитит и оформляет pull request, как машинно-читаемое правило, не свободный текст. Conventional Commits — тип, область, описание из фиксированного набора значений — позволяет автоматически сгенерировать changelog, определить semver, отфильтровать историю. Именование веток с префиксом задачи связывает ветку с трекером. Структурированные секции PR — Summary, Test Plan, Breaking Changes — заполняются по шаблону, превращая описание в машинно-проверяемый чек-лист.

Критерий, когда файл не нужен: нет названного информационного пробела — писать ритуально не даёт пользы. Агент правит файл без человеческого ревью — риск закрепления ошибки реален. Альтернатива: писать только под названный пробел, ревьюить изменения как обычный код.
