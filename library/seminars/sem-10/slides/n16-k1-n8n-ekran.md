# Настоящий холст: векторное хранилище в n8n

## Assertion

Узел хранилища называется Simple Vector Store — штатное имя, не «In-Memory», как его иногда ошибочно называют.

## Visual

> И шаг эмбеддинга, и финальный вызов модели собраны обычным узлом HTTP Request с предустановленным типом учётных данных — отдельного штатного узла «эмбеддинг через OpenRouter» в каталоге n8n нет.

> **Прогон на этом холсте.** Вопрос: «При каком давлении удалось получить кристаллы гелия?» · найден документ про кристаллы гелия у Камерлинг-Оннеса, сходство 0,590, первое место среди десяти документов · ответ модели: «При давлении выше 35 атм.»

## Speaker notes

На экране — настоящий скрин живого холста стенда, тот самый интерфейс, в котором собирали процесс и на прошлом занятии: снятый вживую кадр n8n, без рисования и без схемы.

Слева направо читается главный путь. Форма принимает вопрос и держит при себе корпус документов с уже посчитанными векторами. Дальше узел «Embed query (OpenRouter)» считает эмбеддинг этого вопроса тем же способом, что и при подготовке корпуса, — подпись под узлом на холсте прямо показывает, куда уходит запрос: `POST: https://openrouter.ai/...`. Следующий узел — хранилище, и называется оно Simple Vector Store: это штатное имя ноды в n8n. «In-Memory» — название, которое иногда используют по ошибке, но его на этом холсте нет. Внутри узла — код поиска: косинусное сходство эмбеддинга вопроса с эмбеддингом каждого документа, топ-1 кандидат. Дальше — узел ответа, Answer (RAG), к которому снизу подвешен отдельный круглый узел модели: в этом интерфейсе модель — внешняя сущность, подключённая к узлу снаружи, поэтому на холсте она и нарисована отдельно.

Обе модели, которые здесь на самом деле работают, названы текстом, потому что на самом холсте видно только обобщённое имя узла — какая именно модель внутри, с кадра не прочитать: эмбеддинг считает `text-embedding-3-small`, ответ формирует `gpt-4o-mini`, оба вызова — без каких-либо специально заданных настроек, с параметрами по умолчанию.

На этом холсте нет отдельного штатного узла «эмбеддинг через OpenRouter». У версии n8n, которая стоит на стенде, такого готового узла нет — провайдер OpenRouter не входит в список готовых интеграций для шага эмбеддинга. Поэтому и шаг эмбеддинга, и финальный вызов модели собраны одинаково: обычным узлом HTTP Request с предустановленным типом учётных данных. Это не обходной путь и не недоделка — это то, как сегодня в n8n реально собирается шаг, которого нет в каталоге готовых узлов: параметры настраиваются прямо в теле HTTP-запроса — адрес, модель, промт, — а сами учётные данные подставляет n8n на своей стороне, без ручного обращения с ключом.

Прогон на этом кадре — демонстрационный, на отдельном маленьком корпусе из десяти документов: основной замер на четырёх размерах базы мы уже видели числом, повторять его здесь незачем. Вопрос «При каком давлении удалось получить кристаллы гелия?» прошёл через эту цепочку целиком: эмбеддинг вопроса нашёл нужный документ с оценкой сходства 0,590 среди десяти кандидатов, и модель ответила верно, процитировав условие из найденного куска — «при давлении выше 35 атм». Как устроены оба узла изнутри — настоящие панели настройки, следующими двумя кадрами.
