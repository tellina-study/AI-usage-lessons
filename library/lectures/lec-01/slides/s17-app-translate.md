## Speaker notes

Приложение — полноценный продукт для конечного пользователя, в котором AI — лишь один из внутренних компонентов. Пользователь не пишет промпты; он нажимает кнопки, заполняет формы, говорит голосом.

**Базовая характеристика — AI как функция, а не продукт.** Приложение решает доменную задачу (перевод текста, навигация, проверка грамматики, написание кода), AI обеспечивает функциональность. У хорошего приложения детерминированный UX — то же действие даёт ту же реакцию, даже если AI-выход внутренне варьируется. Приложение добавляет вокруг AI guardrails, fallbacks, кэширование, ревью ошибок.

**Канонические примеры**:
- **Google Translate** — нейронная машинная трансляция; на 2026 — 1B+ users monthly, ~1T слов в месяц **across Translate, Search, Lens, Circle to Search** (caveat от P2-fact-2 ревизии — не только Translate сам по себе; источник Google Blog апрель 2026).
- **Grammarly** — NLP-модели + LLM; пользователь видит подчёркивания.
- **Notion AI** — GPT-4/Claude; кнопки «summarize», «improve writing».
- **GitHub Copilot** — особый случай (один бренд, два разных продукта).

**GitHub Copilot — критическое разграничение** (P2-16 ревизия):
- **Inline-suggestion** (Tab-completion) = **приложение** поверх модели: нажимаете Tab, получаете предложение, нет планирования, нет tool use; UX детерминированный.
- **Workspace** (планирует многошаговую задачу, открывает файлы, редактирует, коммитит) = **агент**: есть планирование, есть tool-calls, цикл act/observe.

Граница «приложение vs агент» проходит **не по бренду, а по архитектуре конкретного продуктового сценария**: есть ли планирование и tool use.

**Кейс перевода**: раз в неделю, маленький объём — не нужна standalone-модель (объём не оправдывает), не нужен чат (UX перевода в чате громоздкий), не нужен агент (задача однашаговая). Готовое приложение — оптимально. **Переплачивать сложностью — анти-паттерн.**

В целом, большинство студентов уже ежедневно пользуются AI через приложения, не отдавая себе отчёт: голосовой набор, разблокировка лица, поиск по фото, рекомендации в Spotify, маршруты в Яндекс.Картах, спам-фильтры. Понимание разницы между моделью и приложением помогает оценить, на что вы фактически опираетесь.
