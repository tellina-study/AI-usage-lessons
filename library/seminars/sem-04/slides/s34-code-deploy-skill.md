# `.claude/skills/deploy/SKILL.md`

## Assertion

deploy/SKILL.md — конкретная процедура именно этого сайта, а не абстрактный шаблон, и description называет и что делает, и когда использовать.

## Visual

Блок кода на всю ширину слайда, моноширинный шрифт, синтаксис-подсветка markdown/yaml для фронтматтера:

```markdown
---
name: deploy
description: Деплоит лендинг signup-landing на прод — сборка, smoke-тест формы, публикация,
  проверка прод-URL. Используй, когда пользователь просит задеплоить, выкатить или опубликовать
  сайт — не для обычных правок кода без деплоя.
---

# deploy

1. Собрать: `npm run build` (код выхода должен быть 0).
2. Прогнать smoke-тест формы: `npx playwright test` (должен быть зелёным).
3. Опубликовать: `wrangler pages deploy dist --project-name signup-landing`.
4. Открыть прод-URL, вручную отправить форму с валидными данными — заявка должна дойти.
5. Записать в `Tasks/<date>_<slug>/log.md`, что задеплоено, когда и какой командой.
```

## Speaker notes

Вот как выглядит рабочий скилл целиком, не абстрактный пример из документации, а именно тот deploy, который реально появится в signup-landing на этой ступени. Обратите внимание на description — в нём ровно два смысловых блока, и оба обязательны. Первый: что делает скилл — «деплоит лендинг signup-landing на прод: сборка, smoke-тест формы, публикация, проверка прод-URL». Второй: когда его использовать — «когда пользователь просит задеплоить, выкатить или опубликовать сайт», и отдельно явно сказано, когда не использовать — «не для обычных правок кода без деплоя». Это разграничение работает в обе стороны: description должен срабатывать на нужных запросах и молчать на ненужных.

Тело скилла — пять шагов, пронумерованных и конкретных, каждый с точной командой: собрать через `npm run build`, прогнать smoke-тест формы через `npx playwright test`, опубликовать через `wrangler pages deploy`, вручную проверить прод-URL, и обязательно записать факт деплоя в `log.md` — тот же журнал, который появится в разделе про процесс и станет проверяемым следом того, что деплой действительно случился, а не просто был заявлен в чате.

Сравните это с официальным антипримером формулировки description, который прямо запрещён чек-листом: «Helps with documents» или «Processes data». Такая формулировка не называет ни что конкретно делает скилл, ни когда его открывать — а модель выбирает скилл именно по description среди потенциально сотни установленных. Расплывчатая формулировка гарантирует, что скилл просто не сработает тогда, когда нужен, и будет срабатывать невпопад, когда не нужен.

Рецепт применения короткий: создать файл с таким содержимым, вырезать процедуру деплоя из CLAUDE.md, не дублируя её в двух местах одновременно, и проверить срабатывание в обе стороны — в новой сессии попросить «задеплой сайт на прод», убедиться, что скилл открылся сам, без явного слэш-вызова; затем в другой новой сессии попросить починить мелкий баг в вёрстке и убедиться, что скилл на этот раз не открылся. Если открылся — description слишком широкий, его нужно сузить.
