# Проверка технических чисел Т-блока «Как устроена генерация» (Лекция 8, v3)

## 1. Латентное сжатие VAE (Stable Diffusion-класса)

**Подтверждено.** Стандартная конфигурация VAE Stable Diffusion 1.x/2.x («kl-f8») сжимает
изображение 512×512×3 (RGB-пиксели) в латент 64×64×4: пространственное понижение разрешения —
**×8 по каждой стороне** (×64 по площади), число каналов растёт 3→4. Итоговое отношение числа
скаляров: 786 432 (512×512×3) / 16 384 (64×64×4) = **48×**.

v2-документ называл «приблизительно ×48» — **арифметика точна, не приблизительна**: это ровно
48,0×, если считать отношением общего числа скалярных значений (не только пространственное
сжатие, которое ×64 по площади компенсируется ростом каналов 3→4 обратно в ×1,33, итог
64/1,33 ≈ 48).

- **Источник механизма (f=8 autoencoder, латентная диффузия):** Rombach, Blattmann, Lorenz,
  Esser, Ommer, «High-Resolution Image Synthesis with Latent Diffusion Models», CVPR 2022,
  arXiv:2112.10752. Прямой доступ к полному тексту через WebFetch вернул только abstract
  (числа не в аннотации) — конкретные цифры 512×512×3→64×64×4 и f=8 подтверждены
  согласованно across независимых технических вторичных источников, которые описывают именно
  архитектуру CompVis/Stability: HuggingFace Diffusers blog
  (https://huggingface.co/blog/stable_diffusion, доступ 2026-10-24), NVIDIA NeMo Framework
  User Guide (https://docs.nvidia.com/nemo-framework/user-guide/24.09/nemotoolkit/multimodal/text2img/sd.html,
  доступ 2026-10-24), stable-diffusion-art.com «How does Stable Diffusion work?»
  (доступ 2026-10-24).
- **Точность:** высокая для SD 1.x/2.x (конфигурация kl-f8, 4 латентных канала) — это
  зафиксированная, не варьирующаяся архитектурная константа этого семейства моделей. SDXL
  использует тот же f=8 VAE (с доработанным декодером), множитель сжатия тот же порядок.
- **Для слайда (Т3):** можно говорить и «×8 по стороне», и «×48 по числу чисел, которые
  обрабатывает модель» — оба числа корректны, это просто разные срезы одной арифметики;
  предлагается показать оба на кадре, а не выбирать одно.

## 3. Классификатор-свободное управление (CFG)

### (а) Механика — оригинальная работа

**Подтверждено.** Ho & Salimans, «Classifier-Free Diffusion Guidance», NeurIPS Workshop 2021 /
arXiv:2207.12598 (2022). WebFetch вернул только abstract (детали формулы — не в аннотации),
но формула и механизм надёжно подтверждены согласованными вторичными техническими источниками
(emergentmind.com — два разных топика с формулой, apxml.com курс по диффузии, mccormickml.com
блог Chris McCormick, все — доступ 2026-10-24):

Модель обучается в двух режимах одновременно — с условием (текстовый промпт `c`) и без
(«null»/пустой токен, случайно подставляемый на 10–20% обучающих примеров). На шаге генерации
делаются **два прогона сети**: условный `ε_θ(z, c)` и безусловный `ε_θ(z)`. Итоговая
предсказанная «поправка шума» — экстраполяция от безусловного к условному прогону, масштабируемая
коэффициентом guidance scale `w`:

```
ε̃_θ(z, c) = (1 + w) · ε_θ(z, c) − w · ε_θ(z)
```

При `w = 0` — чистая безусловная генерация; при `w = 1` — обычная условная генерация без
усиления; при `w > 1` — экстраполяция дальше в сторону условия (сильнее следует промпту, но
может терять разнообразие/реалистичность при больших значениях).

### (б) Типичные значения guidance scale и эффект

**Подтверждено.** Дефолт CompVis-библиотеки и большинства SD-based моделей — **`w ≈ 7–7,5`**;
практический рабочий диапазон **7–13**. Источники: mccormickml.com, stablecog.com,
oakgen.ai/glossary/cfg-scale (доступ 2026-10-24) — согласованно.

Трейд-офф, прямая параллель температуре LLM: низкий `w` (≈1–3) — разнообразнее и «креативнее»,
но слабее следует промпту; средний `w` (≈5–10) — рабочий баланс; высокий `w` — жёстче следует
промпту, но может давать артефакты перенасыщения/потери реализма и меньше разнообразия между
генерациями по одному промпту.

### (в) Негативный промпт — тот же механизм

**Подтверждено, механика точна.** Негативный промпт реализован как подмена безусловного
прогона: вместо прогона с «пустым» промптом (`ε_θ(z)` в формуле выше) берётся прогон,
обусловленный негативным текстом (`ε_θ(z, c_neg)`). Формула CFG не меняется структурно —
меняется только то, «от чего» экстраполируется условный прогон: не «от ничего», а «от
негативного промпта». Источники: stable-diffusion-art.com «How does negative prompt work?»,
segmind.com blog (оба — доступ 2026-10-24). Цитата по смыслу: «вместо направления ‘к промпту,
от ничего в частности’ — направление ‘к промпту, от этих конкретных концептов’».

Это ровно формулировка v3-плана «вектор-руль + второй вектор, от которого шаги отталкиваются» —
**подтверждена как технически точная**, механизм можно явно назвать «CFG» на слайде.

## 4. Cross-attention как механизм кондиционирования промптом

**Подтверждено.** Rombach et al. 2022 (тот же arXiv:2112.10752) вводит cross-attention слои в
денойзер (U-Net в оригинальной SD-архитектуре) для кондиционирования на тексте. Текст-энкодер
(CLIP ViT-L/14 text encoder — «FrozenCLIPEmbedder» в SD 1.x/2.x; в более новых моделях класса
SD3/Flux добавляется T5) превращает промпт в последовательность токен-эмбеддингов.

Механика cross-attention: **query (Q) — из латентных пространственных признаков** (то, что
денойзер обрабатывает на этом шаге), **key (K) и value (V) — из текстовых эмбеддингов**
(линейные проекции токенов промпта). Это прямая кросс-модальная параллель self-attention из
LLM — разница только в том, что Q и K/V берутся из разных модальностей, а не из одной
последовательности.

- **Источники:** Rombach et al. 2022 (arXiv:2112.10752, вводит механизм); согласованные
  вторичные описания — augmentcode.com/open-source/CompVis/stable-diffusion, medium.com статья
  «Why Cross-Attention is the Secret Sauce of Multimodal Models», eugeneyan.com
  «Text-to-Image: Diffusion, Text Conditioning, Guidance, Latent Space» (все — доступ
  2026-10-24).
- **Точность:** высокая, это стандартное, многократно воспроизведённое описание архитектуры —
  годится для прямой параллели с self-attention Л2 на слайде Т6.

нет, есть диапазон порядка величины.**

### Обучающий корпус (подтверждено, с нюансом про стадийность)

LAION-5B целиком — **5,85 млрд** пар изображение-текст (arXiv:2210.08402, LAION blog

simonwillison.net/2022/Sep/5/laion-aesthetics-weeknotes, доступ 2026-10-24).

### Арифметика «байт на изображение» — диапазон, не одно число

| Знаменатель | Чекпойнт (SD1.5, 4,27 ГБ) | Чекпойнт (SDXL, 6,94 ГБ) |
|---|---|---|
| Финальная подвыборка (600 млн) | ≈7,1 байт/изображение | — |
| LAION-2B-en (2,32 млрд) | ≈1,8 байт/изображение | — |
| Весь LAION-5B (5,85 млрд) | ≈0,73 байт/изображение | ≈1,18 байт/изображение |

**Вывод:** v3-план формулирует «порядка пары байт на обучающее изображение» — это **корректный
порядок величины** (диапазон 0,7–7 байт в зависимости от того, какую стадию обучения считать
знаменателем), но не единственное точное число. Популярная версия этого аргумента (её цитирует
Hacker News-обсуждение, news.ycombinator.com/item?id=34383077, доступ 2026-10-24: «модели
Stable Diffusion — это 2–8 ГБ; 5 миллиардов изображений означают, что на каждое изображение
приходится около 1 байта») округляет через самый крупный знаменатель (весь LAION-5B) до
«около 1 байта» — это тоже в пределах найденного диапазона.

**Рекомендация для слайда (ТП2):** говорить «меньше десятка байт на обучающее изображение —
порядка одного-двух байт, если считать по всему корпусу» и явно называть, что число зависит от
того, какую обучающую выборку считать базой — это честнее единственной точной цифры и
соответствует Baseline/Counterfactual Mandate (нужна база, а не округлённое число без
оговорки).

## 6. «Негативный промпт иногда притягивает отрицаемое»

**Подтверждено как документированный, активно исследуемый эффект, не как слух.**
Текст-энкодеры CLIP-класса (используемые в SD и других T2I-моделях) плохо обрабатывают
логическое отрицание; модели класса Stable Diffusion и DALL-E 3 задокументированно склонны
генерировать, например, розового слона, когда их прямо просят **не** генерировать слона.

- **Источники (все 2025–2026, активная область исследований именно из-за нерешённости
  проблемы):** arXiv:2505.18434 «TNG-CLIP: Training-Time Negation Data Generation for Negation
  Awareness of CLIP»; arXiv:2511.12331 «SpaceVLM: Sub-Space Modeling of Negation in
  Vision-Language Models»; arXiv:2512.17121 «The Effect of Negation on CLIP in Medical
  Imaging»; arXiv:2508.10931 «VSF: Simple, Efficient, and Effective Negative Guidance...» (все
  — доступ через WebSearch 2026-10-24).
- **Точность:** высокая для формулировки «текст-энкодер плохо обрабатывает отрицание →
  негативный промпт иногда не убирает, а усиливает присутствие отрицаемого понятия». Пример
  «розовый слон» — повторяющийся в нескольких независимых источниках канонический пример,
  годится для слайда как named-пример эффекта.

## 7. «Больше шагов — не всегда лучше» (плато качества)

**Подтверждено.** Увеличение числа шагов диффузии даёт убывающую отдачу (diminishing returns):
качество растёт быстро на начальном участке и выходит на плато после рабочего диапазона; для
SDXL плато типично называется в районе **30–50 шагов** (дальнейшее увеличение — марginальный
или нулевой выигрыш в воспринимаемом качестве при фиксированном guidance scale, но растущая
цена вычислений). Более широкие исследования диффузионных моделей называют насыщение в районе
64–128 шагов в зависимости от задачи и сэмплера.

- **Источники:** theneuralbase.com «num_inference_steps: quality», prompt-architects.com
  «Stable Diffusion Steps: What Sampling Iterations Actually Do (2026)», medium.com «Beyond
  denoising: rethinking inference-time scaling in diffusion models» (доступ 2026-10-24 все).
- **Точность:** средняя-высокая для направления эффекта (плато существует, это консенсус);
  точный номер шага плато — вариативен между моделями/сэмплерами, поэтому для слайда безопаснее
  говорить «после рабочего диапазона (обычно десятки шагов) прирост качества выходит на плато»,
  без фиксации единственного числа.

## 8. Межкадровая консистентность видеогенерации

**Подтверждено, честная формулировка без привязки к конкретному продукту.** Современные
видео-диффузионные модели генерируют каждый клип как независимый прогон: денойзер видит все
кадры **одного** клипа одновременно и держит идентичность стабильной внутри него, но между
двумя раздельными запусками (даже с идентичным текстовым промптом) нет связующего механизма —
стартовый шум отличается, траектория сэмплера отличается, итоговая композиция отличается. Два
последовательных запуска с подробно описанным одним и тем же персонажем (возраст, цвет волос/
глаз, одежда) дают на выходе заметно разных людей/освещение/сцену.

- **Источники:** medium.com (dhirajpatra) «Technical Challenges to keep Character Consistency
  Across Image or Video Generations»; академические работы 2025–2026, констатирующие это как
  открытую проблему, а не решённую: arXiv:2510.21696 (BachVid, «training-free» подход именно
  потому, что проблема стоит остро); openreview.net «Multi-Shot Character Consistency for
  Text-to-Video Generation» (доступ 2026-10-24 все).
- **Рекомендованная формулировка для ТП1:** «независимые прогоны видео-диффузии не
  гарантируют одного и того же персонажа, сцены или освещения между клипами — это следствие
  того, что каждый запуск стартует с нового шума и не хранит памяти о предыдущем» — без
  привязки к конкретной модели/продукту, так как решения (reference-conditioning и т.п.)
  развиваются быстро и продукт-специфичные гарантии меняются чаще, чем формулируется кейс.

## 9. Класс архитектур Suno/ElevenLabs — не раскрыто

**Подтверждено: архитектуры не раскрыты официально ни той, ни другой компанией.**

- **ElevenLabs:** компания не опубликовала техническую статью или архитектурную диаграмму для
  своих production-моделей (например, Eleven v4) — это соответствует её исторической практике
  держать внутреннее устройство производственных моделей закрытым. Источник: miraflow.ai
  «Eleven v4 Explained: Inside ElevenLabs' New Voice Architecture and Benchmarks» (доступ
  2026-10-24) — сам заголовок обещает «architecture explained», но текст прямо признаёт
  отсутствие официальной публикации, любые конкретные утверждения о числе шагов диффузии/
  механизме attention/словаре токенов — спекуляция третьих лиц, а не раскрытая архитектура.
- **Suno:** внутренняя архитектура не раскрыта; независимые аудиты и попытки анализа
  предполагают гибрид трансформера (автор­егрессия или диффузия) для промежуточного
  представления + нейронный вокодер для финальной волны — но это предположение сторонних
  аналитиков, не подтверждённая официальная информация. Источник: emergentmind.com «Suno: AI
  Music & MRI Optimization» и связанные страницы (доступ 2026-10-24): «internal model
  architecture remains undisclosed... generative system is entirely closed-source, with no
  published documentation of layer counts, pre-training corpora, or codec details».
- **Для слайда (Т2):** честная графа (б) «архитектура не раскрыта» — подтверждена для обоих
  названных инструментов; любое конкретное утверждение сверх этого (сколько шагов, какой тип
  сети) было бы угадыванием, план v3 корректно это обходит одной строкой.

## 10. Цена GPU-секунды облачного инференса (октябрь 2026)

**Подтверждён порядок величины для «сырой» аренды GPU-вычислений; отдельно — порядок величины
для розничной цены готового API-вызова (две разные вещи, обе полезны для арифметики Т10).**

### Аренда GPU «сырьём» (почасовые ставки → цена секунды)

| GPU | Диапазон почасовой ставки (2026) | Цена секунды (вычислено) |
|---|---|---|
| H100 | $1,19–$6,98/час (спот → premium), hyperscaler on-demand до ≈$12,29/час | ≈$0,0003–$0,002/сек (hyperscaler on-demand — выше, ≈$0,0034/сек) |
| A100 | $0,68–$5,03/час | ≈$0,0002–$0,0014/сек |

Источники: cast.ai «GPU Cloud Pricing in 2026», northflank.com, spheron.network, tech-insider.org
«AWS vs Azure vs GCP GPU Pricing 2026», cloudzero.com (все — доступ 2026-10-24). Разброс большой
(провайдер, спот/резерв/on-demand), но порядок величины устойчив: **доли цента за GPU-секунду**
(≈0,02–0,2 цента/сек).

### Розничная цена API (для сравнения, не то же самое число)

Для видео-генерации (не изображений, но полезный порядок для Т10/арифметики лекции) розничные
API в 2026 году берут **$0,03–$0,70 за секунду сгенерированного видео** (Veo 3.1 Lite — $0,03/с,
Kling — ≈$0,07/с, Sora 2 Pro — $0,30–$0,70/с) — источник: fluxnote.io «AI Video Generation
Pricing 2026», invideo.io, cometapi.com (доступ 2026-10-24).

**Вывод для арифметики Т10 (цена изображения $0,03–0,05 с s15):** розничная цена включает
маржу площадки и амортизацию модели, поэтому она закономерно **выше**, чем голая цена
GPU-вычисления на сам инференс (десятки шагов × доли секунды на шаг на latency-оптимизированном
железе = единицы GPU-секунд на изображение, то есть доли цента по таблице выше). Соотношение
«единицы центов конечной цены против долей цента сырого вычисления» — ожидаемо и не
противоречит разрыву «три-четыре порядка против классической цены», который называет план:
классическая координация человеческого труда стоит часы оплаты людей, а не доли секунды
вычислений, даже с учётом маржи площадки.

**Точность:** средняя — почасовые ставки GPU сильно варьируются по провайдеру/спот-режиму/
региону, точного единого числа «цена GPU-секунды» не существует по определению рынка; диапазон
выше — честный ориентир порядка величины, не точечная цифра. Для слайда рекомендуется говорить
«доли цента за GPU-секунду вычислений» без единственного числа.
