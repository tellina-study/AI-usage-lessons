# Стенд Семинара 7 — четыре стадии учебного процесса

Стенд: n8n 2.42.7, поднят владельцем 2026-10-12. Четыре файла здесь — **один процесс на
четырёх стадиях**, по кейсам занятия, плюс файл для студента.

| Файл | Кейс | Что в нём |
|---|---|---|
| `stage-1.json` | 1 | форма → извлечение → справочник → строка → экран результата |
| `stage-2.json` | 2 | то же плюс пометка о других темах заявки |
| `stage-3.json` | 3 | у извлечения повтор (3 попытки) и вторая ветка со своим экраном |
| `stage-4.json` | 4 | та же стадия 3 — на ней показывается черновик против Publish |
| `student.json` | выход | то, что уносит студент: стадия 4 со снятыми привязками к этому стенду |

**Три требования владельца, от которых зависит устройство** (2026-10-12): результат виден
сразу, без переключений (экран результата узлом формы); идентификаторы по-английски;
задача решается полностью — тема и срочность заполнены всегда и из справочника. Подробности
в докстринге `sborka.py`.

Все четыре выложены на стенд, опубликованы и **прогнаны настоящими отправками формы**.
Что именно подтвердил каждый прогон — в `../SETKA-KEYSOV-S7.md`, раздел «Состояние стенда».

## Как пересобрать и выложить

Файлы — **производное** от `sborka.py` (правило §8.5: производное пересобирается, а не
правится руками). Правят генератор.

```bash
source ~/.n8n-lab.env      # ключ стенда живёт ВНЕ репозитория
python3 sborka.py          # только перезаписать json рядом
python3 sborka.py --push   # перезаписать и выложить на стенд
```

Выкладка идёт по имени сценария: если сценарий с таким именем на стенде есть — он
обновляется, иначе создаётся. После выкладки нужен **Publish**, иначе боевые прогоны пойдут
по прежней версии — ровно то, про что кейс 4:

```bash
curl -fsS -X POST -H "X-N8N-API-KEY: $N8N_API_KEY" \
  "$N8N_API_URL/workflows/<id>/publish" -d '{}'
```

## Как прогнать стадию

Управляющий API **не умеет запускать сценарий** — у него нет такого метода. Запуск идёт
через настоящий триггер, то есть отправкой формы:

**Поля на проводе зовутся `field-N` по порядку, а не по подписям.** Подписи («Имя»,
«Контакт», «Что нужно») видит человек в браузере, и под ними же данные приходят в выход
узла; отправка по именам подписей молча даёт `null` во всех полях. Замерено: такой прогон
прошёл со статусом «успех» и записал строку из трёх `null`. Про сдвиг нумерации — ниже.

## Ловушка со сдвигом полей формы

Во вводной на форме первым стоит **блок разметки** (`fieldType: html`) — объяснение, что
произойдёт с текстом. Он не поле ввода, но **в нумерации на проводе он участвует**: настоящие
поля зовутся `field-1`, `field-2`, `field-3`, а не `field-0..2`.

Замерено: после добавления этого блока прогон стал падать с `Text for item 0 is not defined`,
потому что отправка шла по прежним именам. Код ответа формы при этом 200.

```bash
curl -X POST -F 'field-1=Пётр' -F 'field-2=petr@example.com' \
  -F 'field-3=Нужен курс по аналитике, перезвоните сегодня.' \
  https://n8n.lessons.tellian.io/form/s7-stage-1
```

Добавили или убрали ЛЮБОЕ поле формы, включая разметку — нумерация сдвинулась.

записана со `status = not_parsed`, **а статус прогона — `success`**.

## Прогон с экраном результата висит в `waiting`

Узел завершения формы — это узел ожидания: прогон получает статус **`waiting`** и остаётся в
нём, пока браузер не запросит страницу результата. На занятии это незаметно (окно у ведущего
открыто и забирает её сразу), но при проверке через API «не `success`» здесь **не** значит
«не сработало» — смотреть надо `runData`, а не статус.

Побочное: блок разметки на форме отдаёт в выход триггера ключ с пустым именем (`"": null`).
Ни на что не влияет, но в списке полей он виден.
