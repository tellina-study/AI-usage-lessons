# The "too early" criterion and the bridge to task memory

## Assertion

A handful of links per record and one or two people editing the memory — the structure is enough; a full-blown memory system requires measurements at your own scale, not general advice.

## Visual

The checklist:

- A record has a handful of links, not dozens: you can see them in the `Status` section.
- You find the record you need by number, by file name or with a plain grep, not by semantic proximity.
- One or two participants edit the memory at the same time.
- Nobody has asked to "find decisions semantically similar to…".

Below — the bridge: "A change of axis: everything in this case and the previous one is about decisions that live forever. What happens to the memory of a single task while it is not finished yet?"

## Speaker notes

"If a record has a handful of links rather than dozens, one or two people edit the memory, and nobody has asked to 'find decisions semantically similar to this one' — what we have just built is enough for you. A full-blown memory system is the next step, and it requires measurements at your own scale, not general advice: we have just seen that 'smarter' does not mean 'better' without a check.

Now the change of axis. Everything we discussed in this section is about decisions that live forever. But what happens to the memory of a single task while it is not finished yet? The next case is about exactly that."
