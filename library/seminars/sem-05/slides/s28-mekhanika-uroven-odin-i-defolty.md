# За первый уровень платят всегда — а пишут его редко

## Assertion

Из трёх уровней загрузки в контексте всегда лежит только первый — имя и описание; спецификация делает оба поля обязательными, Claude Code — рекомендательными, и когда фронтматтера нет вовсе, описанием становится не имя, а первая непустая строка файла.

## Visual

| Поле | Спецификация Agent Skills | Claude Code |
|---|---|---|
| name | обязательно; до 64 символов | необязательно; дефолт — имя каталога |
| description | обязательно, непустое; до 1024 символов | необязательно; дефолт — первая непустая строка файла |
| прочие поля | — | необязательны; неопознанное молча игнорируется |

> Цену уровня 1 два документа описывают по-разному: спецификация — ≈100 токенов на скилл, Claude Code — бюджет ≈1% окна с обрезкой реже всего вызывавшихся. Подтверждения, что это одно правило, не нашлось.

## Speaker notes

**Три уровня — про то, что уже в контексте, что попадёт позже и что не попадёт никогда.**

Уровень первый: имя и описание. В системном промпте всегда, для каждого установленного скилла, сработал он в этой сессии или нет. И больше ничего: ни первой строки тела, ни списка файлов внутри.

Уровень второй: тело. Попадает в переписку только после того, как модель решила, что описание совпало с запросом, — и дальше живёт там как обычное сообщение, на следующих ходах повторно не перечитывается.

Уровень третий: вложения. Вспомогательный файл читается целиком, когда до него дошли. А код скрипта в контекст не попадает вовсе — даже когда скрипт реально исполняется: исполняется он через оболочку, а возвращается только то, что он напечатал. Вот буквальный смысл фразы «ноль, пока не открыто».

**Про цену первого уровня — расхождение, а не одно число.** Спецификация: около ста токенов на скилл. Документация инструмента это число не повторяет — она описывает бюджет: весь перечень имён и описаний размером до процента контекстного окна, а при переполнении обрезку описаний, начиная с тех скиллов, что реже всего вызывались. Отдельно — потолок на одну запись, полторы тысячи символов с небольшим. Для практики разница невелика: оба согласны, что дёшево, пока не выбран. Но второй точнее говорит, кого урезают первым, — как раз те скиллы, что ещё ни разу не срабатывали.

Порядок величин с доски: тринадцать скиллов по сотне — тысяча триста токенов на весь перечень; процент от окна в двести тысяч — около двух тысяч. Обрезка при таком масштабе не наступает.

**Теперь чем этот первый уровень заполняется.** Спецификация требует: имя и описание обязательны, у описания жёсткий лимит, и оно обязано называть и что скилл делает, и когда его использовать. Документация вашего инструмента говорит противоположное по тону: все поля необязательны, рекомендовано только описание. Это не смягчённый пересказ одного правила — это два контракта для двух путей распространения одного файла. Что сходит с рук локально, не пройдёт валидацию при выгрузке в общий каталог.

Условие, при котором фронтматтер вообще читается: открывающая строка из трёх дефисов обязана быть первой строкой файла. Иначе парсер не запускается, а весь файл считается содержимым. В этом состоянии подставляются дефолты, а не пустота: имя — от имени каталога, описание — от первой непустой строки.

**Самопроверка курса, и она неудобная.** В этом репозитории двенадцать скиллов из тринадцати начинаются прямо с заголовка — фронтматтера у них физически нет. Команда на схеме, проверяется за секунду. И у всех двенадцати первая непустая строка — это заголовок с именем скилла, а не нормальное предложение строкой ниже, которое реально годилось бы как триггер.

Снаружи это выглядит как «описание равно имени» — понятно, но неточно. Система не подставляет имя вместо описания: она берёт не ту строку, и совпадает эта строка с именем только потому, что все двенадцать файлов по одной конвенции открываются заголовком. Начни автор файл сразу с предложения — дефолт сработал бы содержательно.

Тринадцатый устроен иначе: настоящий фронтматтер с явным именем и описанием. Он же отвечает, почему остальные двенадцать хоть как-то работают — только явным вызовом по имени, не автоматическим срабатыванием по смыслу. Два разных канала, и один описания не требует вовсе.

Честно отдельной строкой: обрезается ли ведущая решётка заголовка при подстановке в перечень — подтверждения не нашлось.
