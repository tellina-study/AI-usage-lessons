## Speaker notes

Здесь, как в разборе режимов агента в третьей лекции, нет единственно правильного ответа. Вопрос не «как правильно логировать задачи агента», а какой паттерн соразмерен вашей команде, длительности задачи и нужде в аудит-следе.

Сначала закроем источник путаницы: логирование задач — не то же самое, что встроенный live-трекинг прогресса внутри одной сессии. У Claude Code есть TodoWrite и его преемник — TaskCreate/TaskUpdate/TaskGet/TaskList, — создающий видимый список подзадач текущей сессии. Легаси TodoWrite полностью session-scoped: состояние живёт только в контекстном окне. Преемник пишет JSON-файлы, но привязан к session-id — после новой сессии агент читает пустую папку, для пользователя часто неотличимо от потери состояния. Задача встроенного механизма другая: live-прогресс внутри сессии, не персистентность постфактум.

Три файловых паттерна различаются гранулярностью. Первый — отдельная папка с набором файлов на задачу: план, заметки, отчёт. Сильная сторона — детальный аудит-след, сохраняет промежуточные шаги мышления; окупается на сложной, долгоживущей задаче. Второй — единый общий лог, один файл на весь проект, куда каждая задача дописывается append-only; у нашего курса честный пример — notes/decisions.md, ENFORCED. Сильная сторона — непрерывная хронология; слабая — частые git-конфликты при параллельной работе. Третий — плоская папка с одним файлом на задачу; пример — Backlog.md, где принцип гранулярности сформулирован дословно: «каждая задача равна одному контекстному окну равна одному pull request».

Читать это нужно как критерий, не как перечень: solo-разработчик с короткими задачами тянется к единому логу; команда с долгими сложными задачами — к папке с файлами; команда с задачами размером с один PR — к плоской папке. Критерий составной — кто работает, как долго живёт задача, зачем аудит-след, — а не выбор по умолчанию. И честная связь с «Honest Lying» из третьей лекции: любой из трёх паттернов, если лог пишет и читает исключительно сам агент без верификации человеком, наследует риск закрепления ошибки.
