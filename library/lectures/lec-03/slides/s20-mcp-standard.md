# Visible content

## Title bar
«MCP — стандарт подключения инструментов»

## Body
[Inline-define, 16pt italic]
*MCP (Model Context Protocol) — открытый стандарт: единый способ подключать инструменты, данные и контекст к LLM-приложениям. «USB-C для инструментов LLM».*

[Слева — экономия в Ocean rounded box]
**N×M** несовместимых интеграций (каждая пара модель↔инструмент — своя) → **N+M** через MCP
*(инструмент один раз = MCP-сервер; модель один раз = MCP-клиент)*

Мини-таймлайн принятия: Anthropic 11/2024 → OpenAI 03/2025 → Google 04/2025 → независимый фонд

[Справа — плашка-предупреждение]
**Стандартизация подключения ≠ безопасность подключаемого — и усугубляет проблему доверия.** Каждый подключённый инструмент:
- код в вашем окружении / доступ к данным
- описание попадает в контекст модели — носитель *prompt injection* (инъекция в промпт — внешний текст, который модель исполнит как команду; разбор — s25)
- ещё одна граница доверия и retention-политика

[Gold callout, низ]
**Удобство подключения — не аргумент за подключение. Аргумент — требование задачи и приемлемость новой границы доверия.**

[Footer, 12pt italic]
*Принятие/масштаб экосистемы MCP — перепроверить ко дню лекции.*

## Speaker notes

Function calling решает «как модель формулирует вызов инструмента». Остаётся вопрос «как инструмент подключается» — и до конца 2024 года каждый вендор решал его по-своему, что давало комбинаторный взрыв несовместимых интеграций. MCP, Model Context Protocol, — открытый стандарт, описывающий единый способ подключать инструменты, данные и контекст к LLM-приложениям. Прижившаяся метафора: MCP — это USB-C для инструментов LLM, один разъём вместо набора несовместимых.

Что стандартизует MCP: способ, которым клиент обнаруживает доступные инструменты у сервера, узнаёт их описания и схемы аргументов, вызывает их и получает результаты. До MCP каждая пара «модель и инструмент» требовала своей интеграции; при N моделях и M инструментах это N умножить на M. MCP сводит это к N плюс M: каждый инструмент один раз становится MCP-сервером, каждая модель — MCP-клиентом. Хронология принятия показывает, что это де-факто стандарт: MCP открыт Anthropic в ноябре 2024, принят OpenAI в марте 2025, поддержан Google в апреле 2025, затем передан независимому фонду. Практический смысл для инженера: подключение инструмента — теперь стандартизованная операция, а не разовая интеграция.

Но именно здесь — критический инженерный поворот, который легко пропустить за удобством. Стандартизация подключения не означает безопасность подключаемого и более того — усугубляет проблему доверия. Ровно та лёгкость, с которой MCP подключает внешний инструмент, означает, что каждый подключённый инструмент — это, во-первых, код, который вы запускаете в своём окружении или которому даёте доступ к данным; во-вторых, описание, которое попадает в контекст модели и может быть носителем инъекции; в-третьих, ещё одна граница доверия и ещё одна политика хранения в цепочке. «Подключить за минуту» и «доверять тому, что подключил» — разные вопросы; MCP решил первый и тем сделал второй острее. Зафиксируем принцип, к которому вернёмся в разговоре про атаки: удобство подключения — не аргумент за подключение; аргумент — требование задачи и приемлемость новой границы доверия.
