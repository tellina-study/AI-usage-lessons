# Выбор 4. Внешний API или локальный инференс?

## Assertion

Выбор 4. Внешний API или локальный инференс?

## Visual

Divider: крупная фоновая цифра «4». Заголовок «Внешний API или локальный инференс?» и фраза-фрейм: «чувствительность данных не видна в постановке — она выясняется вопросами». Воронка-мини с подсветкой ступени 4 gold.

## Speaker notes

Четвёртый и последний выбор воронки — считает это внешний облачный API, или модель, которая крутится у вас локально. Сегодняшний кейс — трёхходовка про саммаризацию звонков продаж, где ответ меняется дважды по ходу разбора, и два случая из практики: компания, столкнувшаяся с утечкой через внешний чат-бот, и примеры небольших моделей, которые в проде работают локально прямо сейчас.

Цель раздела — показать, что чувствительность данных не видна в исходной постановке задачи и выясняется только вопросами, и что «сложно для человека» не равно «сложно для модели» — для финальной, суженной задачи маленькая локальная модель может оказаться достаточной.

Начнём с постановки: записи звонков менеджеров по продажам.

Обратите внимание — это последний из четырёх выборов, но по значимости он не менее важен, чем первые три: даже если архитектура выбрана верно, неправильный ответ на вопрос «где считать» может создать компании прямой юридический и репутационный риск. Именно поэтому кейс сегодня устроен как трёхходовка — интуиция на старте разумна, но каждая следующая вводная меняет расчёт.
