# Чистое окно — не чистое от всего подряд

## Assertion

Роль по умолчанию наследует описания всех MCP-серверов родительской сессии целиком — даже тех, что её задаче не нужны. Фокус работает для репозитория, не сам по себе для MCP.

## Visual

> **«Subagents inherit every MCP tool definition from the parent session, which can fill their context window before the first turn. Disable MCP servers you are not using before spawning subagents.»** — документация харнесса об устранении ошибок.

Для нашего вопроса про лимит участников: если в родительской сессии подключены трекер задач и почтовый сервер из прошлого раздела занятия, роль, которой нужно просто прочитать сорок файлов кода, получает их описания в своё окно бесплатно — хотя ни трекер, ни почта к вопросу не относятся.

> **Фокус из прошлых двух слайдов — про содержимое репозитория. Для того, что подключено MCP-серверами, за этим нужно следить отдельно: тем же списком инструментов роли, который стоял пятым блоком на одностраничнике ступени.**

## Speaker notes

Окно роли по умолчанию не настолько чистое, насколько выглядело на прошлых двух слайдах. Роль получает собственный системный промпт и свежий контекст, но вместе с ним — по умолчанию — она наследует описания всех MCP-серверов, подключённых в родительской сессии, целиком, даже тех, что её задаче не нужны ни одним инструментом. Дословно из документации по устранению ошибок: субагенты наследуют каждое описание MCP-инструмента из родительской сессии, и это может заполнить их контекстное окно ещё до первого шага — отключайте те серверы, которые не используете, перед тем как заводить субагентов.

Для нашего вопроса про лимит участников это значит: если в родительской сессии подключены трекер задач и почтовый сервер из прошлого раздела занятия, роль, которой нужно просто прочитать сорок файлов кода, получает их описания в своё окно бесплатно, хотя ни трекер, ни почта к вопросу не относятся.

Фокус, который даёт делегирование, работает для содержимого репозитория. Он не работает сам по себе для того, что подключено MCP-серверами — за этим нужно следить отдельно, тем же списком инструментов роли, который стоял пятым блоком на одностраничнике ступени — а собирать его руками будем в третьем кейсе.

Если спросят, почему это не противоречит прошлому слайду: не противоречит — оба слайда об одном контракте, этот называет ровно то, что в контракт входит дополнительно и по умолчанию, не по желанию автора роли.
