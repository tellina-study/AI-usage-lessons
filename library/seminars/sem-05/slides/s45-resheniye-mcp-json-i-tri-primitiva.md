# .mcp.json — и три примитива протокола

## Assertion

Итог разговора — четыре содержательные строки в `.mcp.json`: чем запускается сервер, что запускается, откуда берётся ключ и какие у него права; а протокол различает инструмент, ресурс и подсказку по тому, кто решает их применить.

## Visual

```json
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": {
        "GITHUB_PERSONAL_ACCESS_TOKEN": "${GITHUB_PAT}"
      }
    }
  }
}
```

Дерево — прибавка к прежнему: `.claude/skills/deploy/SKILL.md` (ступень скилла) + `.mcp.json` (эта ступень).

| Примитив | Кто инициирует | Как выглядит на практике |
|---|---|---|
| Инструменты | модель — сама решает вызвать | «прочитать открытые issue», «создать черновик правки» |
| Ресурсы | приложение — по явному упоминанию | пользователь вставляет ссылку на конкретный объект |
| Подсказки | человек — явной командой | пользователь выбирает готовый сценарий из меню |

## Speaker notes

Итог разговора — четыре строки существа: чем запускается сервер, что запускается, откуда берётся ключ — подстановкой из окружения, не значением в файле, — и, вне файла, но не менее важно, какие права у этого ключа: один репозиторий, а не вся учётная запись. Каждая из этих четырёх строк — прямой ответ на один из вопросов совместного формирования: сервер, ключ и права здесь не абстракция, а решения, которые только что были приняты вслух.

Стоит дать одну мысль про устройство протокола точно, она пригодится дальше. Различие между тем, что сервер отдаёт агенту, — не в содержимом, а в том, кто решает это использовать. Инструмент вызывает сама модель, когда решает, что он нужен. Ресурс подставляет приложение, только когда пользователь явно на него указал. Подсказку выбирает человек командой из меню.

Если вы проектируете свой сервер и хотите, чтобы агент сам решал воспользоваться возможностью, — это обязан быть инструмент. Оформите то же самое ресурсом — и агент до него по собственной инициативе не дотянется. Дальше — не про сам файл, а про то, как это физически исполняется: три следующих слайда разбирают механику ровно этого решения.
