# Разбор: что сделать иначе

## Assertion

Дисциплина синхронной записи в уже существующий файл на задачу — целевой ответ; файл задачи это не то же самое, что журнал решений.

## Visual

Мелким шрифтом вверху — вопрос для контекста: «Файл задачи ввёл в заблуждение — что сделать иначе?»

| Вариант | Где это работает | Почему рано — и что вместо |
|---|---|---|
| «Не сжимать, не закрывать сессию» | Для задачи, целиком укладывающейся в одну короткую сессию | Контекстное окно конечно; на многошаговой задаче рано или поздно случится сжатие |
| «Записать план в DECISIONS.md» | Никогда — не тот слой памяти | DECISIONS.md — про решения, которые остаются в силе навсегда; статус одной задачи туда не относится |
| **«Дисциплинированно дописывать лог хода сразу»** | **Ровно наш случай** | **Целевой ответ.** Файл не нужно создавать — нужно писать в него в момент |
| «Папка на задачу с файлом под каждый шаг» | Параллельные подзадачи, несколько субагентов | Оверинжиниринг для одной линейной задачи здесь и сейчас |
| «Попросить "продолжи с того места"» | Внутри одной непрерывной сессии, до сжатия | После сжатия буквально нечего продолжать сверх записанного в файле |

Нижняя плашка, gold: целевой ответ — дисциплина синхронной записи в уже существующий файл на задачу, с явной оговоркой об упрощении.

## Speaker notes

«Обратите внимание — файл задачи это не то же самое, что журнал решений. DECISIONS.md — про то, что остаётся в силе навсегда, для всех будущих задач. Ход этой конкретной задачи — не решение проекта, это статус: что сделано, что дальше, что мелкое мы успели по ходу решить. Когда задача закончится, всё это можно выбросить. Совсем другой тип памяти, не следующая ступень той же лестницы.

Целевой ответ — не «завести файл» (он уже есть), а дисциплина синхронной записи: файл был, практика была, не хватило одного — вписать мелкую договорённость в лог в момент, когда она прозвучала, а не «как будет время». Именно эта секунда дисциплины и есть решение этого кейса.»
