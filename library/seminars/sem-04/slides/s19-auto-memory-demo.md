# Авто-память рантайма: `запомни` → файл → загружен снова

## Assertion

Авто-память рантайма живёт вне репозитория и грузится в каждую новую сессию сама — команда «запомни» создаёт файл, который переживает конец разговора.

## Visual

Плейсхолдер (TODO-capture #5), ждёт досъёмки: левая часть — фрагмент диалога, дословно: «запомни: не подключаем стороннюю библиотеку валидации форм — форма из двух полей, хватает нативного HTML5»; под ним снимок терминала команды `/memory` со списком файлов, среди которых виден новый `feedback_native-form-validation.md`. Правая часть — плейсхолдер (TODO-capture #6): снимок `/context`, выполненного в новой, отдельно открытой сессии того же репозитория, где строка `MEMORY.md` присутствует в перечне загруженного контекста. Оба плейсхолдера подписаны «ждёт реальной интерактивной сессии» — не рисованная имитация терминала.

## Speaker notes

Первый из двух параллельных механизмов памяти — авто-память рантайма, включена по умолчанию с версии Claude Code ≥2.1.59, и она живёт не в репозитории сайта, а вне его, в `~/.claude/projects/<project>/memory/`. Устроена она из двух слоёв: индекс `MEMORY.md`, первые 200 строк или 25 КБ которого загружаются в каждую сессию автоматически, и тематические файлы по типам — `user`, `feedback`, `project`, `reference`.

Для нашего сценария команда «запомни, что мы не подключаем библиотеку валидации форм, обходимся нативным HTML5» создаёт отдельный файл `feedback_native-form-validation.md` — не потому что вы явно указали путь, а потому что агент сам классифицировал факт как обратную связь о принятом решении. Проверить это можно командой `/memory`: она выводит список всех файлов памяти этого проекта, и новый файл должен появиться в этом списке сразу после того, как вы попросили что-то запомнить.

Но самого факта существования файла недостаточно, чтобы доверять механизму — файл на диске и факт, реально загруженный в контекст следующей сессии, не одно и то же. Поэтому вторая часть проверки — открыть новую сессию того же репозитория и выполнить `/context`: только если `MEMORY.md` виден среди перечисленного загруженного контекста, а не только в файловой системе, можно быть уверенным, что механизм действительно работает, а не просто существует файлом.

Держите в голове важную границу этого механизма: он быстрый, непрерывный и полностью машинно-локальный. Он не проходит код-ревью и не синхронизируется между машинами — если вы работаете за вторым компьютером или другой участник продолжает эту же задачу, файл памяти с первой машины ему не виден. Именно эта граница и подводит к второму механизму — `DECISIONS.md`, который живёт внутри самого репозитория и версионируется через git.
