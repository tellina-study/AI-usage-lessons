# Три файла, а не три ключа одного файла

## Assertion

Область видимости конфигурации — физически разные файлы, и при совпадении имени сервера побеждает вся запись приоритетной области целиком, а не смесь полей; поле `command` — не описание, а команда, которую реально запустят.

## Visual

| Область | Файл | Кто видит |
|---|---|---|
| `local` (по умолчанию) | личная конфигурация, запись проекта | только вы, только этот проект |
| `project` | `.mcp.json` в корне репозитория | все, кто клонирует репозиторий |
| `user` | личная конфигурация, верхний ключ | только вы, все ваши проекты |

Приоритет при конфликте имени: `local` → `project` → `user` → сервер из плагина → коннектор → организационная политика.

При совпадении имени побеждает **вся запись** приоритетной области целиком — не гибрид полей из разных источников.

Транспорт `stdio`: поле `command` — не декларация, а команда, которую реально запустят при старте сессии, без проверки пакета заранее. Для сравнения: `http` — рекомендованный способ для удалённых серверов; `sse` официально помечен устаревшим.

## Speaker notes

Область видимости, которую мы только что выбрали, — не украшение конфигурации, а физически разные файлы. `local` — по умолчанию, личная запись, видна только вам и только в этом проекте. `project` — `.mcp.json` в корне репозитория, тот самый файл, который мы только что решили коммитить: его видит каждый, кто клонирует репозиторий. `user` — тоже личная конфигурация, но верхнеуровневый ключ, видна только вам, но во всех ваших проектах сразу.

Здесь стоит проговорить механику конфликта, потому что интуиция обычно ошибается в одну и ту же сторону. Если сервер с одним именем описан в двух областях сразу, побеждает не смесь двух записей — побеждает вся запись более приоритетной области целиком. Если в личной конфигурации у сервера `github` не указан ключ, а в проектной указан, и они совпали по имени, — при конфликте вы получите личную запись целиком, включая отсутствие ключа, а не гибрид «адрес из одной записи, ключ из другой». Порядок приоритета: личная область выше проектной, проектная выше общей личной, дальше — сервер из плагина, затем коннектор, и выше всех — организационная политика, если она есть.

Второе — про транспорт, тот самый `stdio`, который мы только что записали в файл. Поле `command` — это не описание того, что сервер умеет. Это команда, которую реально запустят при старте сессии, без предварительной проверки пакета. И отсюда механически следует то, что мы уже решили несколько минут назад про ключ: если `command` и `env` — это буквально то, что исполняется на машине, то ключ, вписанный прямо в текст команды, стал бы частью исполняемой строки. Ключ в переменной окружения — не стилистическое предпочтение, а прямое следствие того, что конфигурация здесь исполняемая, а не декларативная. Для сравнения: `http` — рекомендованный способ для удалённых серверов, а `sse` официально помечен устаревшим.
