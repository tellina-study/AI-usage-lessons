# `DECISIONS.md`: одна запись — одна причина

## Assertion

DECISIONS.md — командный, версионируемый лог «почему», видимый всем через git; авто-память — не замена ему, а отдельный, быстрый, машинно-локальный слой.

## Visual

Блок кода на всю ширину слайда, моноширинный шрифт, diff-подсветка, дословно из капчура:

```diff
diff --git a/DECISIONS.md b/DECISIONS.md
new file mode 100644
index 0000000..1f479f9
--- /dev/null
+++ b/DECISIONS.md
@@ -0,0 +1,7 @@
+# Decisions
+
+Append-only log of why, in date order.
+
+## 2026-09-20 — не подключаем библиотеку валидации форм
+Форма — два поля (имя, email), хватает нативных `required`/`pattern` в `index.html`.
+Сторонняя библиотека — лишняя зависимость и лишние килобайты в сборке ради этого объёма.
```

## Speaker notes

Второй механизм — `DECISIONS.md`, git-трекнутый, append-only лог «почему» прямо в репозитории сайта. Перед вами реальный diff: новый файл с семью строками, заголовок, одна вводная строка про формат («append-only log of why, in date order»), и первая содержательная запись. Формат записи фиксированный: заголовок `## YYYY-MM-DD — <решение одной строкой>`, затем одно-три предложения причины. В нашем случае: форма — два поля, хватает нативных `required` и `pattern` в `index.html`, сторонняя библиотека — лишняя зависимость и лишние килобайты в сборке ради этого объёма.

Разница ролей между `DECISIONS.md` и авто-памятью, которую мы только что видели, принципиальна, и её стоит проговорить явно. Авто-память — быстрый, непрерывный, машинно-локальный слой: она создаётся одной фразой «запомни», не проходит код-ревью и не синхронизируется между машинами. `DECISIONS.md` — противоположность по всем трём признакам: запись делается один раз осознанно, коммитится и ревьюится точно так же, как любой другой файл в пул-реквесте, и видна всем участникам через git, а не только тому, кто был за этой конкретной машиной в момент разговора.

Третий, ранее существовавший файл — `CLAUDE.md` — в эту пару не входит, и важно не смешивать все три. `CLAUDE.md` — статичные правила, которые вы пишете заранее и которые должны оставаться стабильными: команды сборки, структура репозитория. `DECISIONS.md` — растущий журнал причин, которые накапливаются по ходу работы. Если начать дописывать решения прямо в `CLAUDE.md`, файл довольно быстро — при повторении такого паттерна на десятки решений — перевалит за условные 200 строк и начнёт работать против себя, ровно та проблема, которую раздел 1 уже показал на процедуре деплоя.

Практический рецепт: скопировать шаблон `DECISIONS.md` из `/tmp/ahr/templates/base-project-template/with-git/DECISIONS.md`, дописать запись по этому формату и закоммитить файл — обычным коммитом, без специального ритуала.
