## P1 — находки дизайн-прожарки

### P1-1. n13 — лестница приоритета противоречила сама себе

Источник (`sem-05/research/mechanics-5-mcp.md` §1.3, дословно из документации «Scope hierarchy
and precedence»): порядок от высшего к низшему — `local → project → user → сервер из плагина →
коннектор`; отдельно, поверх всех пяти, стоит политика организации, которая побеждает даже
`local`. Старая лестница несла `local` на САМОЙ НИЖНЕЙ ступени (6) с подписью «ПОБЕЖДАЕТ при
конфликте» — прямое противоречие ступени 1 («выше всех»).

**Починено:** `make_figures_mcp.py`, `RUNGS` — `local` переставлена на ступень 2 (сразу под
золотой org-policy), остальные четыре — `project → user → плагин → коннектор`, по источнику.
Подпись ступени 1 уточнена: «если есть — выше всех, даже local». Теперь лестница читается без
противоречия сверху вниз.

Второе дело слайда (два дела на одном экране, заголовок называл только одно) — починено тем же
патчем: в `build_sem06.py` `g_content` код `.mcp.json` (то, что называет заголовок) теперь
рисуется ПЕРВЫМ, лестница (компаньон-механика) — ВТОРЫМ (новый `FIG_AFTER_BLOCKS = {"n13"}`).
Новый слайд не добавлялся, тайминг не менялся.

### P1-3. n32 — коробка «вопрос залу» под мостик-утверждение

`n32` — единственный из шести `criteria_checklist_and_boundary`-слайдов (n16/n24/n32/n43/n52/
n59), чей мостик-абзац после таблицы заканчивается знаком вопроса («...в каждой сессии её
приходится объяснять заново?»). `quote_role()` ловит это ПЕРВЫМ правилом («тело заканчивается
на `?`» → роль `question`) раньше, чем успевает сработать правило по приёму
(`criteria_checklist_and_boundary → formula`), и рисует авторский мостик в следующий блок той
же золотой кремовой рамкой, что и настоящие вопросы залу (n04/n09/n19/n27/n36/n46/n55/n62) — хотя
за n32 идёт не карточка-ответ, а дивайдер (n33). Проверено: у остальных пяти слайдов того же
приёма мостик не кончается вопросом, роль `formula` подбирается автоматически верно — патч
точечный, только для n32.

**Починено:** `build_sem06.py` `g_criteria` — новый `CRITERIA_QUOTE_ROLE_FORCE = {"n32":
"formula"}`, передаётся в `block_drawer(..., role=...)`. Текст не менялся ни на символ — только
форма: теперь абзац с акцентной полосой, без золотой рамки-вопроса, тот же приём, что у n16/n24.
Подтверждено на свежем рендере.

*Известный побочный эффект, не дефект:* `audit_grammar.py` (отдельный скрипт сверки форм,
читает `quote_role()` напрямую, без рендер-уровневого форса) по-прежнему печатает для n32 форму
«вопрос» — это классификация ИСХОДНОГО текста для аудита содержания, не то, что видно на
слайде; тот же механизм уже используется для золота на n02/n60/n61/n63 (P1-4) и там тоже не
совпадает буквально со строкой аудита. Если захочется свести аудит и рендер к одному источнику
истины — отдельная, не визуальная задача.

### P1-4. Золото ≥1× — добавлено на n02, n60, n61, n63

Причина отсутствия: единственная цитата этих слайдов классифицировалась как «тихая реплика»
(`quote_role` → `speech`, тиловая полоса), хотя по собственному `visual.primary` этих слайдов
это «единственная подпись слайда» — то есть работа ИТОГА (`formula`, золотая планка), не
реплики. В `build_sem06.py` добавлен `GOLD_QUOTE_SIDS = {"n02": "all", "n60": "all",
"n61": "all", "n63": "last"}` — для n63 золотой становится только ПОСЛЕДНЯЯ из двух цитат
(короткая строка оси «Четыре строки из пяти…», рефрен с n60), первая (длинная рефлексия)
остаётся тихой репликой. Подтверждено на свежем рендере: золото видно на всех четырёх.

## Находки студента и технические огрехи

- **n26 — `npx   - y`.** Причина — не markdown-разбор (он уже отдавал один пробел), а баг
  LibreOffice: подстановка Consolas рисует дефис, открывающий моноширинный прогон, С ЛИШНЕЙ
  шириной глифа — воспроизведено изолированно вне рендерера (временные `test_mono*.pptx`,
  не коммитились) и локализовано: триггер — дефис ПЕРВЫМ символом мон. прогона, а не пробел
  внутри прогона (прежняя теория). Чинится без замены шрифта: `metrics.py` `_mono_words` теперь
  не отдаёт моноширинный прогон кускам, начинающимся с `-` (`-y`, `-a`, `-l`...) — такой кусок
  рисуется обычным шрифтом. Проверено на n26 и попутно на всех остальных `-флаг`-паттернах
  деки (n02 `git branch -a`/`wc -l`, n63 `wc -l`) — тот же класс дефекта, та же починка.
- **Висячая `»` на n04/n62** — проверено на свежем рендере, уже чисто (прошлая сессия).
- **n34, n45, n54 — сплошной абзац вместо списка.** Причина — разборщик `slide_parts.py`
  узнавал только `-`/`*`-буллиты, не нумерованные `1. 2. 3.`; нумерованные строки схлопывались
  через `flush()` в один жирный абзац без переносов. Починено: `blocks()` теперь распознаёт
  `\d+\.` наравне с `-`/`*`, рисует той же формой `K.numbered_list`, что и n07/n18 (дот-маркер,
  не цифра — тот же визуальный язык, что у всех остальных списков деки). Подтверждено на
  свежем рендере: все три теперь читаются буллитами.
- **n19 → n20 — порядок карточек/строк не совпадал.** `n20.md` `visual.primary` сам обещает
  «порядок строк совпадает с порядком карточек вопроса» — обещание было нарушено (строка
  «посмотреть подробнее» стояла последней вместо третьей). Починено перестановкой строки
  таблицы (только порядок, текст ячеек не менялся) + синхронным порядком абзацев в speaker
  notes.
- **n58 — правая карточка выглядела как готовая граница, а на деле не написана.**
  Reader-прожарка (п.1): источник (`section-2-subagent-part1c.md` n62 «Речь») прямо говорит —
  «тестировщику нужна симметричная строка… ещё не написана», это открытая задача, не готовый
  текст. Одинаковый сплошной стиль `«НЕ для:»` на обоих боксах стирал разницу. Починено:
  левый бокс (диф-ревьюер) остаётся сплошным, с готовым текстом источника; правый
  (тестировщик) стал ПУНКТИРНЫМ, той же грамматикой, что «честный пробел» деки, с меткой
  «пока не написано:» — текст не выдуман, дословно по источнику («своя граница — симметричная
  диф-ревьюеру, по-доменному, не абстрактно»).
- **n01 — двусмысленный замок.** Закрытый на вид замок стоял на золотых карточках «сегодня»,
  серые соседи «закрыты» были без замка вовсе — обратная по знаку ассоциация. Снят (не
  заменён): подпись несёт смысл сама, без значка.

## Визуальный цикл

Каждый тронутый слайд — минимум 3 прохода «собрать → PDF → PNG → посмотреть → поправить»:
1) первый рендер деки «как есть» (до правок) — зафиксировал реальное состояние, отличное от
   того, что было в снимках прошлой сессии (старые снимки были частично устаревшими);
2) после правки всех `make_figures_*.py` + `build_sem06.py` + `slide_parts.py`/`metrics.py` —
   полный ребилд, нашёл, что PNG-фигуры не регенерировались автоматически (это отдельный
   скрипт на каждый `make_figures_*.py`), перегенерировал;
3) после обнаружения клиппинга текста в пунктирном боксе n58 (строка касалась нижней рамки) —
   увеличена высота бокса, перегенерировано и перепроверено отдельно.

Снимки — `rendered/snapshots/iter-01.png … iter-63.png`, старые при каждом ребилде удалялись
(`rm -f snapshots/iter-*.png`) перед новым `pdftoppm`, так что в каталоге всегда ровно один,
самый свежий набор.
