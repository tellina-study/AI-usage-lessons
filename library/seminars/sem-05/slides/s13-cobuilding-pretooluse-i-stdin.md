# Три вопроса — три фрагмента конфигурации

## Assertion

Первые три решения хука: проверка до вызова, условие — только команды оболочки, источник знания о команде — JSON на стандартном вводе.

## Visual

**Вопрос 1.** «Проверять до вызова инструмента или после?» → до. Фиксируется:
```
"PreToolUse"
```

**Вопрос 2.** «Вешаем условие на все инструменты или на один?» → на один, на команды оболочки. Фиксируется:
```
"matcher": "Bash"
```

**Вопрос 3.** «Откуда хук узнаёт, какая команда сейчас выполнится?» → движок передаёт описание вызова в виде JSON через стандартный ввод. Фиксируется:
```
jq -r '.tool_input.command'
```

## Speaker notes

Первые два вопроса — почти разминка. «До вызова инструмента проверяем или после?» — зал отвечает почти всегда верно: до. Фиксируем `PreToolUse` — событие, которое срабатывает перед вызовом инструмента и может его не пропустить.

«На все инструменты вешаем условие или на один?» — на один, на выполнение команд оболочки. Фиксируем `"matcher": "Bash"`. Чем шире условие срабатывания, тем больше ложных срабатываний и тем выше цена ошибки в самой логике проверки, плюс латентность на каждый вызов — к этому вопрос ещё вернётся, когда будем разбирать провалы и границы применимости.

Третий вопрос зал обычно не берёт, и это нормально: «Откуда хук вообще узнаёт, какая команда сейчас выполнится?» Механика здесь не угадывается интуицией, она просто устроена определённым образом: движок передаёт хуку описание предстоящего вызова целиком, в виде JSON, через стандартный ввод. Хук вытаскивает из него одну строку — саму команду — через `jq`. Это общий приём, не специфика конкретно этого хука: любой хук на `PreToolUse` начинается с распаковки описания события, а не с разбора произвольного текста, который к нему как-то попал.

Три фрагмента уже на экране: `PreToolUse`, `matcher: Bash`, `jq -r '.tool_input.command'`. Конфигурация ещё не готова — ей не хватает главного: что именно делать с полученной командой и что возвращать в ответ. Это следующий слайд, два оставшихся вопроса, и один из них с настоящим сюрпризом — привычная команда для определения текущей ветки здесь не работает так, как ожидается.
