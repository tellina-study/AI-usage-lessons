# Где должен проходить разрез документа

## Assertion

Четыре способа провести границу куска — по счёту символов, по словам, по предложениям, по счёту символов с перекрытием.

## Visual

> **Где должен проходить разрез документа?**

`резать строго по счёту символов, без оглядки на текст` · `резать по границам предложений` · `резать по границам слов` · `резать по счёту символов с перекрытием`

## Speaker notes

Четыре действия, и все реальны как инженерный выбор. Резать строго по счёту символов — самое простое и самое дешёвое в реализации: один параметр, механический проход по тексту без оглядки на содержимое. Резать по границам предложений — чуть сложнее: нужно сначала понять, где заканчивается одно предложение и начинается следующее, и только потом проводить разрез. Резать по границам слов — промежуточный вариант: разрез держится границы слова, но ничего не знает о границе предложения. Резать по счёту символов с перекрытием устроено так же, как первое действие, с одной добавкой: соседние куски частично повторяют один и тот же участок текста.

Прикиньте: документ разрезан на куски по сто восемьдесят символов. Какова вероятность, что этот разрез случайно разорвёт прямо посередине фразу с ответом на будущий вопрос?

Пятнадцать секунд на выбор. Разбор того, как устроено каждое действие, — следующим экраном; проверка на настоящих документах, с заранее известным правильным ответом, — дальше, на структуре замера и на самом результате.

Все четыре действия дают на выходе один и тот же формат — список кусков текста, готовых к тому, чтобы посчитать для каждого эмбеддинг и положить в хранилище. Снаружи, на уровне остальной цепочки, разницы не видно вовсе: все четыре версии подают на следующий шаг ровно такие же по форме куски. Вся разница спрятана внутри одного узла, и именно поэтому её легко не заметить, пока не проверишь результат числом.

И именно поэтому голосование здесь не праздное упражнение. Если бы разница между версиями была видна невооружённым глазом на любом примере — скажем, если бы версия 1 производила явно сломанный, нечитаемый текст, — выбор был бы очевиден без всякого замера. Но все четыре способа производят куски, которые выглядят совершенно нормально, если просто открыть и прочитать их глазами. Проблема обнаруживается только тогда, когда конкретный вопрос попадает ровно на границу разреза, а это заранее не видно ни по одному куску в отдельности.
