# Что делает каждое из трёх действий

## Assertion

Объединённый индекс без фильтра — дешевле всего сегодня и дороже всего при первом же добавлении непохожей, но лексически пересекающейся темы; раздельные базы платят за надёжность тем, что не видят общих для всех курсов материалов; фильтр по курсу даёт надёжность раздельных баз почти без их цены.

## Visual

| Действие | Как делает | Преимущество | Недостатки |
|---|---|---|---|
| Свести всё в один индекс, поиск не трогать | Косинусный top-1 по объединённому пулу всех курсов, без различения темы | Один индекс, одна точка поддержки, не нужен роутинг запроса по курсам | **recall@1 падает с 1,000 до 0,875 уже на 100 добавленных документах чужой темы** — а если эти документы похожи по смыслу на вопрос не случайно, то же падение происходит **в 5 раз быстрее**, на 20 добавленных документах |
| Держать отдельную базу на каждый курс | N независимых индексов, вопрос всегда идёт в «свой» | recall@1 = 1,000 на любом размере — чужая тема физически не существует в индексе своего курса | Материал, общий сразу для нескольких курсов (правило пересдачи, правило безопасности центра), либо дублируется N раз, либо не находится вовсе — пользователь должен заранее знать, в какую базу идти |
| Свести в один индекс + фильтр «только материалы этого курса» в запросе | Тот же единый индекс физически, но поиск ограничен по метаданным (курс/домен) ДО ранжирования, не после | Тот же результат, что у раздельных баз (recall@1 = 1,000, запас не утекает от чужой темы вовсе), без цены N отдельных индексов | Фильтр верен ровно настолько, насколько верна разметка «какой документ к какому курсу относится» — при ошибке разметки протечка возможна |

## Speaker notes

Первое действие — слить всё в один индекс и не трогать поиск — выглядит самым дешёвым сегодня и оказывается самым дорогим при первом столкновении с реальностью. Косинусный поиск сравнивает вопрос со всеми документами объединённого пула без различения, какому курсу какой документ принадлежит. Собственный замер этого раздела показывает: recall@1 держится на единице, пока в базу не попадёт около сотни документов других тем — а если их выбор направленный, по смысловой близости к вопросу, тот же обгон происходит уже при двадцати добавленных документах, в пять раз быстрее. Чем «умнее» выбор того, что добавляется в базу, тем раньше наступает проблема — и это касается не только злонамеренного отбора: обычный органический рост контента со временем смещается в сторону более релевантных, то есть более похожих материалов.

Второе действие — прямая противоположность: разнести курсы по разным, никак не связанным базам. Чужая тема в индексе своего курса физически отсутствует, поэтому recall@1 держится на единице на любом размере — этому варианту нечему размывать поиск. Цена здесь не видна на стенде, но реальна в жизни учебного центра: как только появляется материал, актуальный сразу для нескольких курсов — общее для всех правило пересдачи, общее правило безопасности, — раздельные базы либо дублируют его в каждой из N баз, либо не находят вовсе, и пользователь должен заранее знать, в какую базу идти, то есть именно то, от чего должен избавлять поиск по смыслу.

Третье действие объединяет сильные стороны первых двух почти без их слабостей. Физически это один индекс, не N отдельных хранилищ — дешевле в поддержке, чем вариант с раздельными базами. Но перед тем, как кандидаты сравниваются по смыслу с вопросом, применяется фильтр по домену — курсу, с которого пришёл вопрос, — и документы чужих курсов даже не попадают в список кандидатов. Результат арифметически совпадает с вариантом раздельных баз: recall@1 = 1,000, запас не утекает от чужой темы вовсе. Цена этого варианта лежит в честности самой разметки, не в производительности: фильтр верен ровно настолько, насколько верна метка «какой документ к какому курсу относится» — и собственный замер этого раздела нашёл случай, где эта разметка протекла. Что это за случай и как устроен замер, который дал эти числа, — следующими тактами.
