## Speaker notes

Мы закончили первый раздел: уровни A и B, автодополнение и мелкие задачи через чат. Общее у них то, что человек видит каждый фрагмент кода — на уровне A в момент написания, на уровне B при ревью после генерации. Поднимаемся на следующую ступень лестницы автономности.

Уровень C — кодинг-агент. Это AI-система, которая получает крупную задачу — «реализуй фичу», «почини этот класс багов», «отрефактори модуль» — и самостоятельно планирует подзадачи, правит несколько файлов, запускает тесты и линтеры, читает их вывод, итерирует по результатам, и в конце предъявляет человеку готовый pull request. Человек ставит задачу на входе и принимает решение о ревью и слиянии на выходе; всё между — автономно. Качественное отличие от уровня B — автономная итерация: на B человек решает после каждого фрагмента, на C он видит только итог.

В этом разделе мы разберём три вещи. Первое: как кодинг-агент устроен и почему это ровно цикл агента из Лекции 3, применённый к коду. Второе: главный инженерный факт уровня C — разрыв между тем, как агент работает на знакомом публичном коде и на честном незнакомом, через бенчмарк SWE-bench. И третье, где центральный вопрос вернётся ребром во второй раз: специфический для этого уровня антипаттерн — принять pull request агента, не прочитав его, — и почему решение о слиянии не делегируется.
