# Почему много подключённых инструментов удорожает контекст агента

**Date:** 2026-10-02 · **Issue:** #217-EXP

Каждый инструмент (tool, skill, MCP-сервер) описывается в системном промпте через его JSON-схему: имя, описание, параметры, типы, примеры использования. Все эти описания загружаются в контекст **ЦЕЛИКОМ** до того, как агент вообще начнёт работать — независимо от того, использует ли он инструмент в реальности.

Один инструмент занимает примерно 150–500 токенов (в зависимости от сложности). 20 инструментов — это уже 3–10k токенов контекста, потраченных только на их описания. В режиме, где агент читает файлы и исследует (но не создаёт), эти описания зря "занимают место".

Проблема усугубляется комбинаторно:
- **Усложнение промпта.** Системный промпт становится огромнее → агент медленнее парсит собственные действия и принимает решения.
- **Шум при планировании.** Видя все доступные инструменты, агент может выбирать неоптимальные пути (call tool A когда tool B дешевле).
- **Cost per request.** При fixed budget (например, 100k токенов контекста на сессию), инструменты "едят" часть, оставляя меньше места для документов/истории.
- **Холодный старт.** Если агент запущен только читать, но ему загрузили все 50+ инструментов — это бессмысленный overhead.

| утверждение | источник | тип |
|---|---|---|
| Каждый MCP tool занимает 150–500 токенов в JSON-схеме | По памяти, не проверено | оценка |
| 20 инструментов = 3–10k контекст-токенов overhead | По памяти (правило большого пальца) | расчёт |
| Все инструменты загружаются в контекст до первого использования | Ant Claude SDK docs, mode typical | факт |
| Шум при выборе инструмента ↔ удорожает решение | Гипотеза на основе LLM поведения | предположение |

## Что НЕ доказано

- Точные цифры: насколько именно замедляется вывод при N инструментах (зависит от их сложности и модели).
- Оптимальное число инструментов для типичного агента (может быть 5–15, но не проверено).
- Есть ли в пакетах инструментов (например, harness-control MCP) способ lazy-load описания в контекст (по памяти — нет, но возможно есть более свежие подходы).
